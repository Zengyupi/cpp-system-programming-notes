## 一、简历核心原则

### 1.1 简历的本质

简历不是"个人经历的流水账"，而是**"你能为雇主创造什么价值"的广告**。HR 和技术面试官平均花 **15~30 秒**筛选一份简历，必须在最短时间内传递核心信息：
- 你是谁（教育背景、工作年限）；
- 你会什么（技术栈、核心能力）；
- 你做过什么（项目经历、量化成果）；
- 你能带来什么（与岗位的匹配度）。

### 1.2 五条铁律

| 原则 | 说明 |
| --- | --- |
| **一页纸** | 应届生/3 年以内经验严格一页，资深可两页，绝不超过两页 |
| **量化成果** | 用数字说话："优化性能"→"QPS 从 2000 提升到 8000，延迟降低 60%" |
| **匹配岗位** | 针对 JD 调整技术关键词和项目顺序，一份简历投所有岗位是大忌 |
| **真实可查** | 不夸大、不虚构，面试深挖会露馅；可以包装但不能造假 |
| **无废话** | 删除"熟练使用 Office""性格开朗"等无关信息，每一行都要有信息量 |

## 二、简历结构设计

### 2.1 标准结构（按优先级排序）

```text
1. 个人信息（姓名、电话、邮箱、GitHub/博客链接、所在地）
2. 教育背景（学校、专业、学历、时间、GPA/排名（好的话写））
3. 专业技能（技术栈分类罗列，关键词匹配 JD）
4. 项目经历（核心，2~4 个，STAR 法则描述）
5. 工作经历（公司、职位、时间，如有）
6. 竞赛/证书/开源贡献（加分项，可选）
```

### 2.2 各部分要点

**个人信息**：
- 必写：姓名、电话、邮箱（用专业邮箱，别用非主流昵称）；
- 选写：GitHub 链接（有优质项目必写）、技术博客、个人网站、期望城市；
- 不写：身份证号、政治面貌、身高体重、照片（除非岗位要求）。

**教育背景**：
- 格式：`学校 | 专业 | 学历 | 入学-毕业`；
- GPA 3.5/4.0 以上或排名前 20% 才写，否则不写；
- 相关课程只写与岗位强相关的 3~5 门，别列全部成绩单。

**专业技能**：
- 分类呈现：编程语言、框架/库、操作系统/工具、领域知识；
- 用"熟悉/掌握/了解"分级，别全写"精通"（面试官会往死里问）；
- 关键词对齐 JD：JD 写"epoll、Reactor"，你简历就出现这些词；
- 示例：
  ```text
  编程语言：C++17（熟练）、Python（熟悉）、Shell（熟悉）
  网络编程：TCP/IP、epoll、Reactor、自研协议栈、SocketCAN
  操作系统：Linux 系统编程、多线程、内存管理、交叉编译
  中间件/数据库：Redis、MySQL、Nginx、消息队列
  工具：Git、CMake、GDB、Valgrind、perf、Docker
  ```

## 三、项目经历：STAR 法则与量化表达

### 3.1 STAR 法则

项目描述是简历的灵魂，用 **STAR 法则**组织每一段：

| 要素 | 说明 | 写什么 |
| --- | --- | --- |
| **S（Situation 背景）** | 项目在什么场景下，解决什么问题 | 一句话说清项目定位和规模 |
| **T（Task 任务）** | 你负责什么，面临什么挑战 | 你的具体职责和技术难点 |
| **A（Action 行动）** | 你做了什么，用了什么技术 | 具体技术方案、架构设计、优化手段 |
| **R（Result 结果）** | 取得了什么成果 | **必须量化**：性能、效率、稳定性、业务指标 |

### 3.2 项目描述模板

```text
项目名称 | 角色 | 时间
技术栈：C++17、Linux、epoll、Redis、MySQL
项目简介：一句话说明项目是什么、服务什么场景、规模多大。
核心工作：
• 【背景+任务】针对 XXX 问题，负责 XXX 模块的设计与开发。
• 【行动】采用 XXX 架构，使用 XXX 技术解决了 XXX 难点（具体怎么解决的）。
• 【行动】优化 XXX 流程，通过 XXX 手段将 XXX 指标提升/降低了 XXX。
• 【结果】系统支撑 XXX 并发/数据量，可用性达到 XXX，线上零故障运行 XXX 天。
```

### 3.3 量化成果的方法

不会量化？从这些维度找数字：

| 维度 | 示例 |
| --- | --- |
| 性能 | QPS 从 2000→8000；延迟 P99 从 200ms→30ms；吞吐量提升 4 倍 |
| 效率 | 开发周期缩短 30%；部署时间从 30min→2min；构建时间减少 50% |
| 稳定性 | 可用性 99.99%；崩溃率从 0.5%→0.01%；故障恢复时间 10min→1min |
| 规模 | 支撑 100 万日活；管理 500+ 设备；处理 10TB/天数据 |
| 成本 | 服务器成本降低 40%；带宽节省 30%；人力效率提升 50% |
| 质量 | 代码覆盖率从 40%→80%；Bug 率下降 60%；通过 XXX 安全审计 |

> 技巧：如果没有精确数字，用"约""量级"表述，如"支撑万级并发""延迟降低约一个数量级"，但不能完全没有数字。

### 3.4 项目示例（工业网关方向）

```text
工业协议采集网关 | 核心开发 | 2024.03 - 2025.06
技术栈：C++17、Linux ARM、epoll、Modbus/IEC104、SQLite、SocketCAN
项目简介：面向工业现场的多协议数据采集网关，支持 Modbus RTU/TCP、IEC104、
CAN 等协议接入，将设备数据上送云平台，部署于 500+ 工业现场。
核心工作：
• 设计并实现基于 Reactor 模型的多协议接入框架，统一协议解析接口，
  新增协议从 2 周缩短到 3 天。
• 手写 IEC104 协议栈，处理 ASDU 解析、超时重传、连接管理，
  单网关稳定接入 200+ 设备，数据采集延迟 < 100ms。
• 实现本地数据缓存与断点续传，网络中断时缓存 7 天数据，
  恢复后自动补传，数据零丢失。
• 优化内存管理，采用对象池+环形缓冲，长时间运行内存占用稳定，
  网关连续运行 180 天无内存泄漏、无重启。
```

### 3.5 项目选择策略

- 选 **2~4 个**最有含金量的项目，宁缺毋滥；
- 第一个项目放与目标岗位最匹配的；
- 每个项目都要能在面试中讲 10 分钟以上（架构、难点、方案、权衡）；
- 课程设计/玩具项目如果没有技术深度，不如不放；
- 如果项目涉及公司机密，脱敏处理（用"某大型互联网公司""日活百万级"代替具体名称）。

## 四、不同经验阶段的简历策略

### 4.1 应届生/实习

- 教育背景放前面（学校是重要筛选条件）；
- 项目经历是核心，突出技术深度和学习能力；
- 竞赛、开源贡献、GitHub 是加分项；
- 没有实习经历就用课程项目+个人项目补足，但要做出深度（别只写"实现了一个聊天系统"，要写清楚架构和难点）。

### 4.2 1~3 年经验

- 项目经历放教育背景前面；
- 突出"独立负责过什么""解决过什么技术难题"；
- 技术栈从"学过"转向"在生产环境用过"；
- 开始体现业务理解和工程能力（不只是写代码，还有稳定性、性能、协作）。

### 4.3 3~5 年经验

- 突出"主导过什么""带过什么""架构设计能力"；
- 体现技术选型决策和权衡能力；
- 有跨团队协作、技术分享、Code Review 经验加分；
- 项目描述侧重"系统设计"和"业务影响"，而非"写了什么代码"。

## 五、面试中的项目表达

### 5.1 项目讲解框架（3 分钟版）

面试官说"介绍一下你做过的项目"，按这个结构讲：

```text
1. 一句话定位（30秒）：这是个什么项目，解决什么问题，规模多大
2. 整体架构（1分钟）：画个架构图/说清模块划分和数据流
3. 你的职责（30秒）：你负责哪块，在团队中的角色
4. 核心难点+解决方案（1分钟）：1~2个最有技术深度的难点，怎么分析、怎么解决
5. 成果（30秒）：量化结果，对业务的影响
```

### 5.2 技术深挖的应对

面试官会针对项目中的技术点深挖，准备时每个项目问自己：

- 为什么选这个技术方案？有没有考虑过替代方案？权衡是什么？
- 这个模块如果流量翻 10 倍，会有什么瓶颈？怎么扩展？
- 线上出过什么问题？怎么排查和解决的？
- 如果重新做，你会怎么改进？
- 这个数据结构/算法为什么选它？时间空间复杂度是多少？

### 5.3 常见项目面试题

| 问题 | 考察点 | 回答思路 |
| --- | --- | --- |
| "项目中最大的技术挑战是什么？" | 解决问题能力 | 选真实难点，讲清分析过程→方案→结果，别选太简单的 |
| "为什么用 X 不用 Y？" | 技术选型判断力 | 从需求出发，对比优劣，讲权衡 |
| "这个系统怎么保证高可用？" | 系统设计能力 | 冗余、降级、限流、熔断、监控、故障恢复 |
| "性能优化怎么做的？" | 性能调优能力 | 先测量（perf/火焰图）→定位瓶颈→针对性优化→量化验证 |
| "如果让你重新设计，会改什么？" | 反思和成长 | 诚实说 1~2 个可改进点，体现技术判断力 |

## 六、简历常见错误

| 错误 | 后果 | 改正 |
| --- | --- | --- |
| 技术栈全写"精通" | 面试官往死里问，答不上来扣分 | 用"熟练/掌握/了解"分级，诚实 |
| 项目只写"参与了XXX系统开发" | 看不出你做了什么 | 用 STAR，写清具体行动和成果 |
| 没有量化成果 | 没有说服力 | 从性能/效率/稳定性/规模/成本找数字 |
| 一份简历投所有岗位 | 匹配度低 | 针对 JD 调整关键词和项目顺序 |
| 简历超过两页 | HR 没耐心看 | 精简，一页纸原则 |
| 写"熟练使用 Office""性格开朗" | 占空间无信息量 | 删除，只写与岗位相关的 |
| 项目描述像产品说明书 | 看不出技术深度 | 突出技术方案、架构、难点、优化 |
| 时间线有断层 | 引起怀疑 | 如实说明（考研、Gap、自由职业） |
| 错别字/格式混乱 | 不专业 | 反复检查，PDF 格式投递 |
| GitHub 是空的但写了链接 | 减分 | 要么不放，要么放有实质内容的 |

## 七、投递与跟进

### 7.1 投递渠道优先级

1. **内推**（成功率最高，找学长/同事/社区朋友）；
2. **官网/官方招聘公众号**（直接投递，避免第三方平台信息丢失）；
3. **Boss 直聘/拉勾**（沟通直接，适合中小公司）；
4. **猎头**（适合中高端岗位）；
5. **校招宣讲会/双选会**（应届生）。

### 7.2 投递策略

- 分批投递：先投 5~10 家"练手"公司，根据面试反馈调整简历和话术，再投目标公司；
- 记录投递表格：公司、岗位、投递时间、进度、反馈、面试题；
- 不要同时面太多家（精力分散），也不要只投一家（风险高），保持 3~5 家在流程中。

## 八、快速参考卡片

```text
简历原则：一页纸 | 量化成果 | 匹配JD | 真实可查 | 无废话
结构：个人信息→教育→技能→项目(核心)→工作→加分项
STAR：S背景→T任务→A行动→R结果(必须量化)
量化维度：性能(QPS/延迟) | 效率(时间) | 稳定性(可用性) | 规模(并发/数据) | 成本 | 质量
项目讲解：定位(30s)→架构(1min)→职责(30s)→难点方案(1min)→成果(30s)
深挖准备：为什么选这个 | 流量10倍怎么办 | 出过什么问题 | 重新做怎么改
常见错误：全写精通 | 无量化 | 一份投所有 | 超两页 | 无技术深度
投递：内推>官网>Boss>猎头；分批投递，练手后投目标公司
```

## 九、延伸阅读与工具

- **简历模板**：LaTeX 模板（Overleaf）、冷熊简历、超级简历（注意去广告水印）；
- **PDF 生成**：Word/WPS 导出 PDF，确保格式不乱；
- **GitHub 美化**：README 写清楚项目架构、技术选型、运行方式，比简历更有说服力；
- **技术博客**：掘金、知乎、个人博客，写项目复盘和技术总结，面试加分；
- **模拟面试**：找朋友互相面试，录音回听，改进表达逻辑和语速。
