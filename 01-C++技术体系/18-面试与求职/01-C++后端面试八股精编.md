## 一、C++ 语言基础

### 1. 指针和引用的区别？

| 维度 | 指针 | 引用 |
| --- | --- | --- |
| 本质 | 变量，存地址 | 别名，不占独立内存 |
| 可为空 | 可以（nullptr） | 必须初始化，不可为空 |
| 可重新指向 | 可以 | 不可，绑定后不可改 |
| 多级 | 支持多级指针（`**p`） | 不支持多级引用 |
| sizeof | 指针大小（4/8字节） | 引用对象的大小 |
| 自增 | 指针地址移动 | 引用对象值+1 |

答题要点：引用是"更安全的指针"，函数参数传递优先用引用避免拷贝；指针更灵活但需判空。

### 2. new/delete 和 malloc/free 的区别？

| 维度 | new/delete | malloc/free |
| --- | --- | --- |
| 所属 | C++ 运算符 | C 标准库函数 |
| 构造/析构 | 调用构造/析构函数 | 只分配/释放内存 |
| 返回类型 | 具体类型指针 | void* 需强转 |
| 分配失败 | 抛 bad_alloc 异常 | 返回 NULL |
| 可重载 | 可以重载 operator new | 不可重载 |
| 数组 | new[] / delete[] 配对 | 手动计算大小 |

**高频坑**：`new[]` 必须配 `delete[]`，否则只调用第一个元素的析构函数，内存泄漏。

### 3. 虚函数实现机制？

- 每个有虚函数的类有一张**虚函数表（vtable）**，存虚函数地址；
- 对象内存布局首项是**虚指针（vptr）**，指向 vtable；
- 运行时通过 vptr→vtable→函数地址实现**动态绑定（晚绑定）**；
- 构造函数中调用虚函数是静态绑定（此时派生类部分未构造）；
- 虚函数成本：一次间接跳转 + 可能破坏内联，热路径慎用。

### 4. 智能指针：unique_ptr / shared_ptr / weak_ptr

| 类型 | 所有权 | 线程安全 | 适用 |
| --- | --- | --- | --- |
| unique_ptr | 独占，不可拷贝，可移动 | 管理的对象非线程安全 | 工厂返回、局部资源 |
| shared_ptr | 共享，引用计数 | 控制块线程安全，对象非 | 共享所有权 |
| weak_ptr | 不拥有，观察 shared_ptr | — | 打破循环引用、缓存 |

- **循环引用**：A 持有 B 的 shared_ptr，B 持有 A 的 shared_ptr → 计数永不为 0 → 内存泄漏；用 weak_ptr 打破。
- **shared_ptr 开销**：控制块（引用计数+弱计数+删除器+分配器），两次动态分配（可用 make_shared 合并为一次）。
- **enable_shared_from_this**：类成员函数需要返回自身的 shared_ptr 时继承它，直接 `shared_ptr<T>(this)` 会重复释放。

### 5. 左值、右值、移动语义、完美转发

- **左值**：有名字、可取地址；**右值**：临时对象、字面量，不可取地址；
- **移动语义**：`std::move` 把左值转为右值引用，触发移动构造/赋值，**转移资源所有权而非拷贝**（如 vector 的 buffer 指针直接移交）；
- **完美转发**：`std::forward<T>(arg)` 保持参数的值类别（左值/右值），用于模板函数透传参数；
- **移动后对象状态**：合法但未指定（通常为空），不要使用移动后的对象，除非重新赋值。

### 6. RAII 是什么？

Resource Acquisition Is Initialization：资源获取即初始化。用对象生命周期管理资源（内存、文件句柄、锁、socket），构造时获取，析构时释放。
- 典型应用：智能指针、`lock_guard`、`ifstream`、`unique_fd`；
- 解决异常安全：函数中途抛异常，局部对象析构自动释放资源。

### 7. 多态有哪些？

- **静态多态（编译期）**：函数重载、模板、CRTP；
- **动态多态（运行期）**：虚函数 + 继承；
- **宏多态**：`#define MAX(a,b) ((a)>(b)?(a):(b))`（不推荐）。

### 8. const 关键字的用法

- `const int* p`：指向常量的指针，值不可改，指针可改；
- `int* const p`：常量指针，指针不可改，值可改；
- `const int* const p`：都不可改；
- 成员函数后加 `const`：不修改成员变量（mutable 除外），可被 const 对象调用；
- `constexpr`：编译期常量，比 const 更强。

## 二、内存管理

### 1. 内存分区

| 区域 | 存什么 | 管理 |
| --- | --- | --- |
| 栈（Stack） | 局部变量、函数参数、返回地址 | 编译器自动，大小有限（通常 1~8MB） |
| 堆（Heap） | new/malloc 动态分配 | 手动管理，容量大但有碎片 |
| 全局/静态区 | 全局变量、static 变量 | 程序生命周期 |
| 常量区 | 字符串字面量、const 全局 | 只读 |
| 代码区 | 二进制指令 | 只读 |

### 2. 内存对齐

- 结构体成员按自身大小对齐，整体大小为最大成员的整数倍；
- 目的：CPU 一次读取完整数据，避免跨缓存行/跨页；
- `#pragma pack(n)` 可改变对齐（网络协议结构体常用 pack(1)）；
- 空类大小为 1 字节（占位）。

### 3. 内存泄漏排查

- 工具：Valgrind（Linux）、CRT 调试堆（Windows `_CrtDumpMemoryLeaks`）、AddressSanitizer（ASan，编译加 `-fsanitize=address`）；
- 代码层面：统一用智能指针，RAII，避免裸 new；
- 排查步骤：复现 → ASan 定位分配栈 → 确认未释放路径 → 修复。

### 4. 栈溢出原因与排查

- 原因：递归过深、大数组局部变量、深调用链；
- 排查：`ulimit -s` 查看栈大小，core dump 看调用栈，ASan 可检测；
- 解决：改递归为迭代、大对象放堆、增大栈限制（`ulimit -s unlimited`，生产慎用）。

## 三、并发编程

### 1. 进程和线程的区别？

| 维度 | 进程 | 线程 |
| --- | --- | --- |
| 资源 | 独立地址空间、文件描述符 | 共享进程资源，有独立栈和寄存器 |
| 切换开销 | 大（页表、TLB 刷新） | 小 |
| 通信 | IPC（管道/共享内存/消息队列） | 共享内存，需同步 |
| 稳定性 | 一个崩溃不影响其他 | 一个崩溃整个进程挂 |
| 创建 | fork/Clone | pthread_create/std::thread |

### 2. 互斥锁、自旋锁、读写锁、条件变量

| 原语 | 特点 | 适用 |
| --- | --- | --- |
| 互斥锁 mutex | 拿不到就睡眠，上下文切换 | 锁持有时间长 |
| 自旋锁 spinlock | 拿不到忙等，不睡眠 | 锁持有时间极短（<几次调度） |
| 读写锁 rwlock | 读共享、写独占 | 读多写少 |
| 条件变量 condition_variable | 等待/通知机制，配合 mutex | 生产者消费者、事件等待 |

- **虚假唤醒**：条件变量 wait 可能被意外唤醒，必须用 while 循环重新判断条件；
- **死锁四个必要条件**：互斥、占有且等待、不可剥夺、循环等待；破坏任一即可预防。

### 3. 线程同步方式有哪些？

互斥锁、自旋锁、读写锁、条件变量、信号量（semaphore）、屏障（barrier）、原子操作（atomic）、Future/Promise。

### 4. 什么是线程安全？

多线程并发访问时结果正确。实现方式：
- 无共享（线程局部存储 thread_local）；
- 不可变（const 数据）；
- 互斥（锁）；
- 原子操作（无锁）。

### 5. CAS 与 ABA 问题

- CAS（Compare-And-Swap）：原子操作，比较内存值是否等于预期，是则更新为新值，返回是否成功；
- 无锁数据结构基于 CAS 实现；
- **ABA 问题**：值从 A→B→A，CAS 误以为没变；解决：加版本号（如 `AtomicStampedReference`）或使用计数。

## 四、网络编程

### 1. TCP 三次握手、四次挥手

**三次握手**：
```text
Client → SYN(seq=x) → Server
Server → SYN(seq=y)+ACK(x+1) → Client
Client → ACK(y+1) → Server（连接建立）
```
为什么三次？两次无法确认客户端接收能力；四次多余（服务端 SYN+ACK 可合并）。

**四次挥手**：
```text
Client → FIN → Server（客户端无数据发了）
Server → ACK → Client（确认，此时服务端可能还有数据发）
Server → FIN → Client（服务端也发完了）
Client → ACK → Server（等待 2MSL 后关闭）
```
为什么 TIME_WAIT？①确保最后 ACK 到达；②让旧连接报文在网络中消失。主动关闭方进入 TIME_WAIT。

### 2. TCP 如何保证可靠传输？

- 序列号 + 确认应答（ACK）；
- 超时重传（RTO）；
- 滑动窗口（流量控制）；
- 拥塞控制（慢开始、拥塞避免、快重传、快恢复）；
- 校验和。

### 3. select / poll / epoll 区别

| 维度 | select | poll | epoll |
| --- | --- | --- | --- |
| 数据结构 | fd_set 位图（1024 限制） | pollfd 数组（无上限） | 红黑树+就绪链表 |
| 拷贝 | 每次调用拷贝全部 fd | 同 select | 注册时拷贝一次 |
| 复杂度 | O(n) 遍历 | O(n) 遍历 | O(1) 就绪通知 |
| 触发模式 | LT | LT | LT/ET |
| 性能 | 连接多但活跃少时差 | 同 select | 高并发最优 |

- **ET（边缘触发）**：只在状态变化时通知一次，必须非阻塞 + 循环读到 EAGAIN；
- **LT（水平触发）**：有数据就通知，简单但可能重复通知。

### 4. Reactor 和 Proactor

- **Reactor（同步非阻塞）**：事件循环监听 fd 就绪，就绪后用户线程自己执行读写（epoll + 非阻塞 IO）；
- **Proactor（异步 IO）**：内核完成读写后通知用户，Windows IOCP 是典型，Linux 用 io_uring 模拟；
- 主流 C++ 网络库（muduo、libevent）是 Reactor 模型。

### 5. HTTP 和 HTTPS 区别

| 维度 | HTTP | HTTPS |
| --- | --- | --- |
| 端口 | 80 | 443 |
| 加密 | 明文 | TLS/SSL 加密 |
| 证书 | 无 | CA 证书 |
| 性能 | 快 | 握手开销，可会话复用 |
| 安全性 | 易被窃听篡改 | 机密性、完整性、身份认证 |

TLS 握手：客户端 Hello → 服务端证书+公钥 → 客户端验证证书 → 协商会话密钥（非对称加密）→ 对称加密通信。

## 五、设计模式

### 1. 单例模式

- 饿汉式：静态变量初始化即创建，线程安全，但可能浪费；
- 懒汉式：第一次使用时创建，需双重检查锁（DCL）或 `std::call_once`；
- **C++11 最佳实践**：局部静态变量（Meyers Singleton），编译器保证线程安全初始化：
```cpp
Singleton& getInstance() {
    static Singleton instance;
    return instance;
}
```

### 2. 观察者模式

一对多依赖，主题状态变化时通知所有观察者。C++ 可用 `std::function` + `vector` 实现，或信号槽（boost::signals2、Qt）。

### 3. 工厂模式

- 简单工厂：一个工厂根据参数创建不同产品；
- 工厂方法：每个产品有对应工厂，符合开闭原则；
- 抽象工厂：创建一族相关产品。

### 4. 策略模式

封装一系列可互换算法，运行时切换。替代大量 if-else/switch，用 `std::unordered_map<string, function>` 注册策略。

### 5. 常用设计模式速查

| 模式 | 场景 |
| --- | --- |
| 单例 | 全局唯一资源（配置、日志、连接池） |
| 工厂 | 对象创建解耦 |
| 观察者 | 事件通知、发布订阅 |
| 策略 | 算法可切换 |
| 装饰器 | 动态增强功能（IO 流） |
| 适配器 | 接口不兼容转换 |
| 模板方法 | 算法骨架固定，步骤子类实现 |
| 代理 | 控制访问（远程代理、虚拟代理、保护代理） |

## 六、数据库

### 1. 索引类型与原理

- B+ 树索引：MySQL InnoDB 默认，范围查询友好，叶子节点链表；
- 哈希索引：O(1) 点查，不支持范围；
- 聚簇索引：叶子存整行数据（主键）；二级索引：叶子存主键值，需回表；
- 覆盖索引：查询列都在索引中，无需回表；
- 最左前缀：联合索引 (a,b,c) 可服务 a、a,b、a,b,c 查询。

### 2. 事务 ACID

- 原子性（Atomicity）：undo log 回滚；
- 一致性（Consistency）：最终目的，其他三者保证；
- 隔离性（Isolation）：锁 + MVCC；
- 持久性（Durability）：redo log + WAL。

### 3. 事务隔离级别

| 级别 | 脏读 | 不可重复读 | 幻读 |
| --- | --- | --- | --- |
| 读未提交 | 可能 | 可能 | 可能 |
| 读已提交 RC | 避免 | 可能 | 可能 |
| 可重复读 RR（MySQL 默认） | 避免 | 避免 | 基本避免（Next-Key Lock） |
| 串行化 | 避免 | 避免 | 避免 |

### 4. Redis 数据结构与适用场景

| 类型 | 底层 | 场景 |
| --- | --- | --- |
| String | SDS | 缓存、计数器、分布式锁 |
| List | 双向链表/压缩列表 | 消息队列、最新列表 |
| Hash | 哈希表/压缩列表 | 对象存储 |
| Set | 哈希表 | 标签、共同好友、去重 |
| ZSet | 跳表+哈希 | 排行榜、延迟队列 |

### 5. Redis 持久化

- RDB：快照，二进制，恢复快，可能丢数据；
- AOF：追加日志，数据安全，文件大，恢复慢；
- 混合持久化（4.0+）：RDB 头 + AOF 尾，兼顾速度和安全。

## 七、操作系统

### 1. 进程间通信（IPC）

管道（匿名/命名）、消息队列、共享内存（最快）、信号量、信号、Socket（跨网络）。

### 2. 死锁预防与避免

- 预防：破坏四个必要条件之一（如资源有序分配破坏循环等待）；
- 避免：银行家算法，分配前检查是否安全；
- 检测与恢复：允许死锁，定期检测，终止进程或剥夺资源。

### 3. 虚拟内存

- 每个进程有独立虚拟地址空间，通过页表映射到物理内存；
- 缺页中断：访问未加载页时，OS 从磁盘加载；
- 页面置换算法：FIFO、LRU（最近最少使用）、Clock；
- 好处：隔离进程、允许内存超额、简化内存管理。

### 4. 零拷贝

传统 read+write 有 4 次拷贝 4 次上下文切换；零拷贝技术：
- mmap：文件映射到内存，减少一次拷贝；
- sendfile：内核内直接传输，不经用户态；
- splice：管道中转，真正零拷贝；
- io_uring：异步批量 IO，减少系统调用。

## 八、项目相关高频问题

### 1. 介绍一下你的项目

用 STAR 法则：
- **S（Situation）**：项目背景，解决什么问题；
- **T（Task）**：你的职责和任务；
- **A（Action）**：具体做了什么，用了什么技术，遇到什么挑战怎么解决；
- **R（Result）**：量化结果（性能提升 X%、延迟降低 Yms、支撑 Z 并发）。

### 2. 项目中遇到的最大挑战？

准备 2~3 个真实技术挑战：
- 性能优化：定位瓶颈（perf/火焰图）→ 优化手段 → 量化收益；
- 并发问题：死锁/竞态 → 排查过程 → 解决方案；
- 架构设计：扩展性/高可用 → 设计权衡。

### 3. 为什么用这个技术选型？

从需求出发：性能要求、团队熟悉度、生态、可维护性、成本。不要只说"因为它流行"，要讲权衡。

## 十、面试准备建议

1. **八股是基础不是全部**：面试官更看重项目深度和解决问题的能力，八股答完要能结合项目展开。
2. **每个知识点准备三层**：是什么 → 为什么 → 项目中怎么用的/踩过什么坑。
3. **手写代码必考**：链表反转、LRU、线程安全单例、生产者消费者、字符串处理，提前练熟。
4. **系统设计题**：准备 1~2 个常见场景（短链接、消息队列、秒杀），从需求→架构→细节→扩展逐步展开。
5. **反问环节**：问团队技术栈、项目挑战、成长空间，体现对岗位的兴趣。

## 十一、面试常见误区

1. **背八股不结合项目**：答完"虚函数原理"就停，面试官追问"你项目里哪用了、踩过什么坑"答不上来；每个知识点都要能落到项目。
2. **只说结论不说权衡**：被问"为什么用 Redis"只答"快"，讲不清持久化选型、集群方案与缓存一致性代价。
3. **手写代码不处理边界**：链表反转/二分查找漏空指针、越界、溢出；先口头讲思路再写，写完主动自测。
4. **夸大项目贡献**：把团队成果说成个人成果，追问细节穿帮；如实讲分工，突出自己负责的部分与量化收益。
5. **否定前公司/前同事**：谈离职原因只客观陈述，不抱怨不负面。
6. **技术选型回答"都行/不知道"**：被问"为什么选 MySQL 不用 MongoDB"要能对比场景，体现判断力。
7. **不会装会**：没接触过的技术如实说"了解原理、没实战"，并说明学习思路，比硬扯更得分。
8. **忽视基础只背高频题**：new/delete、指针引用、智能指针这些基础题答不准比答不出冷门题更扣分。
