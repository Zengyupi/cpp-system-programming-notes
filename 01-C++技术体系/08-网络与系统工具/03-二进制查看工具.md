## 0. 30 秒上手

```bash
hexdump -C file.bin            # 最常用：偏移 + 十六进制字节 + ASCII，记住这一条就够入门
xxd file.bin                   # 另一种等价观感，且能 -r 逆向还原、-i 生成 C 数组
od -Ax -tx1z -v file.bin       # POSIX 标准工具的等价写法，脚本可移植性最好
```

## 1. hexdump 基本调用

```bash
hexdump [选项] 文件
cat xxx | hexdump -C           # 也可从标准输入读
```

> 一句话记忆：**日常 99% 直接用 `hexdump -C`**（canonical 标准格式）。裸 `hexdump` 默认按 16 位"字"且遵循本机小端序显示，字节顺序会被交换，是最常见的坑（见第 3 节）。

### 核心选项

| 选项 | 作用 |
| --- | --- |
| `-C` | **最常用**：偏移 + 单字节十六进制 + `\|...\|` 包裹的 ASCII |
| `-c` / `-b` | 单字节按字符 / 单字节按八进制显示 |
| `-x` / `-o` / `-d` | 两字节一组：十六进制 / 八进制 / 无符号十进制（受字节序影响） |
| `-n N` | 只显示前 N 字节 |
| `-s N` | 跳过前 N 字节（支持 `0x` 十六进制、`k/m` 单位） |
| `-v` | **不折叠**重复行；默认连续相同行用一个 `*` 代替 |
| `-e '格式串'` | 自定义输出格式（高级，见第 6 节，**注意字节序陷阱**） |

## 2. `-C` 输出逐列解读（必懂）

样本为 `Hello, hexdump!\nABCDEFGHIJKLMNOP\n` 加 6 个二进制字节 `00 01 02 03 ff fe`：

```bash
$ hexdump -C sample.bin
00000000  48 65 6c 6c 6f 2c 20 68  65 78 64 75 6d 70 21 0a  |Hello, hexdump!.|
00000010  41 42 43 44 45 46 47 48  49 4a 4b 4c 4d 4e 4f 50  |ABCDEFGHIJKLMNOP|
00000020  0a 00 01 02 03 ff fe                              |.......|
00000027
```

| 列 | 含义 |
| --- | --- |
| `00000000` | **行首偏移**（十六进制），即本行首字节距文件头的字节数；`0x10=16`、`0x20=32` |
| `48 65 6c ...` | 每行最多 16 字节十六进制；第 8、9 字节间有额外空格，分成左右各 8 字节便于对齐 |
| `\|Hello...\|` | 同 16 字节的 ASCII 映射；可打印字符原样显示，不可打印/非 ASCII 一律显示 `.` |
| 末尾 `00000027` | 文件总字节数（0x27 = 39），不对应任何一行 |

> 右侧 ASCII 列是排查文本协议、找字符串的关键：dump 报文/内存时一眼看出哪里是可读 payload、哪里是二进制控制字段。

## 3. 两个最容易踩的坑

### 3.1 裸 hexdump 会按小端交换字节

```bash
$ hexdump sample.bin | head -2          # 没有 -C
0000000 6548 6c6c 2c6f 6820 7865 7564 706d 0a21
0000020 4241 4443 4645 4847 4a49 4c4b 4e4d 504f
```

- 默认按 **2 字节一个"字"**显示，并按**本机小端序**组合：`H e`（0x48 0x65）拼成 16 位数 0x6548 显示成 `6548`；`A B` 显示成 `4241`。
- 偏移也变成 7 位八进制风格（`0000020` = 十进制 16，别当成十进制 20）。
- **要看真实字节顺序务必 `-C`（或 `-c`/`-b` 单字节模式）**。

### 3.2 连续相同行被折叠成 `*`

```bash
$ python3 -c "open('rep.bin','wb').write(b'A'*48)"
$ hexdump -C rep.bin                    # 48 个 0x41，只显示首行 + *
00000000  41 41 41 41 41 41 41 41  41 41 41 41 41 41 41 41  |AAAAAAAAAAAAAAAA|
*
00000030
$ hexdump -C -v rep.bin | head -3       # -v 逐行完整展开
00000000  41 41 41 41 41 41 41 41  41 41 41 41 41 41 41 41  |AAAAAAAAAAAAAAAA|
00000010  41 41 41 41 41 41 41 41  41 41 41 41 41 41 41 41  |AAAAAAAAAAAAAAAA|
```

> dump 一片被清零（全 0）的 Flash/内存时满屏只剩一个 `*`，不是工具坏了；要逐行看加 `-v`。

## 4. 定位与截取：`-s` 跳过、`-n` 长度

```bash
hexdump -C -n 16 sample.bin                 # 只看前 16 字节
hexdump -C -s 16 sample.bin                 # 跳过前 16 字节，从 0x10 开始
hexdump -C -s 0x100 -n 64 file.bin          # 从 0x100 起开一个 64(0x40) 字节的窗口
hexdump -C -s 1k -n 256 file.bin            # 跳过 1KiB 再看 256 字节
```

## 5. 三工具横向对比

| 工具 | 默认格式 | 特长 | 适用 |
| --- | --- | --- | --- |
| `hexdump -C` | 偏移+字节hex+ASCII | 通用查看、`-e` 可编程化 | Linux 日常 |
| `xxd` | 偏移+两字节组hex+ASCII | **`-r` 还原二进制、`-i` 生成 C 数组**、配合 vim 改二进制 | vim 生态 |
| `od` | 八进制 | POSIX 标准、**可指定 `--endian` 解析多字节** | 脚本/可移植 |

### xxd 实跑与常用选项

```bash
$ xxd sample.bin | head -3
00000000: 4865 6c6c 6f2c 2068 6578 6475 6d70 210a  Hello, hexdump!.
00000010: 4142 4344 4546 4748 494a 4b4c 4d4e 4f50  ABCDEFGHIJKLMNOP
00000020: 0a00 0102 03ff fe                        .......
```

| 选项 | 作用 | 示例 |
| --- | --- | --- |
| `-i` | 输出成 **C 语言数组**（嵌入式直接拷进代码） | `xxd -i font.bin > font.h` |
| `-r` | **逆向**：把 hex 文本还原为二进制 | `xxd -r dump.txt out.bin` |
| `-b` | 按二进制位(0/1)显示 | `xxd -b file` |
| `-g N` | 每 N 字节分组（默认 2，`-g1` 等同 -C 观感） | `xxd -g1 file` |
| `-s/-l` | 跳过 / 长度（对应 hexdump 的 -s/-n） | `xxd -s16 -l32 file` |
| `-c N` | 每行 N 字节（默认 16） | `xxd -c 8 file` |

```text
# 嵌入式：把字库/图片转成 C 数组头文件
xxd -i font.bin > font_table.h
# 输出：unsigned char font_bin[] = { 0x.., ... }; unsigned int font_bin_len = ...;

# 可逆编辑二进制：vim -b file → :%!xxd 改成十六进制 → :%!xxd -r 转回 → :wq
```

### od 速览（解析多字节整数更靠谱）

```bash
od -Ax -tx1z -v file.bin           # 十六进制偏移 + 单字节hex + ASCII + 不折叠，等价 hexdump -C
od -An -tx1 file.bin               # 不要偏移，只输出 hex 字节流（脚本提取用）
od -An -tu2 --endian=big file.bin  # 按【大端】uint16 解释 —— 网络协议分析首选
od -An -tu4 --endian=little file.bin  # 按小端 uint32 解释
```

## 6. hexdump 自定义格式 `-e`（进阶，含字节序陷阱）

格式串语法：`'重复次数/每单元字节数 格式符'`，常用格式符：

| 格式符 | 含义 |
| --- | --- |
| `%02x` | 1 字节两位十六进制 |
| `%d` `%u` `%o` | 有符号 / 无符号十进制 / 八进制 |
| `%_p` | 按 ASCII 显示（同 -C 右侧） |
| `%08_ax` | 十六进制偏移 |
| `"\n"` `"\t"` | 字面换行/制表 |

```bash
# 每行 16 字节十六进制 + ASCII（手写版 -C）
hexdump -e '"%08_ax  " 16/1 "%02x " " |%_p|\n"' sample.bin
```

> **字节序陷阱（实测）**：`-e` 的多字节单元（`/2` `/4`）**仍按本机小端组合，且 hexdump 无法指定大端**。对一个大端 Modbus 帧（开头两字节是 `00 01`）：
>
> ```bash
> $ hexdump -e '6/2 "%04x " "\n"' mb.bin
> 0100 0000 0600 0301 0000 0a00      # 错！00 01 被小端拼成 0100
> $ od -An -tx2 --endian=big mb.bin
>  0001 0000 0006 0103 0000 000a     # 对：这才是网络大端的真实字段
> ```
>
> 结论：**分析网络/串口大端协议，多字节字段用 `od --endian=big`，或用 `-C` 看单字节自己按大端拼**，不要直接信 hexdump 的 `/2`、`/4` 数值。

## 7. 实战场景

### 7.1 文件魔数（magic number）：扩展名会骗人，头字节不会

```bash
hexdump -C -n 16 unknown.bin
```

| 文件 | 头部魔数（偏移 0 起） |
| --- | --- |
| ELF 可执行/目标文件 | `7f 45 4c 46`（`.ELF`） |
| PNG | `89 50 4e 47 0d 0a 1a 0a` |
| JPEG | `ff d8 ff` … 结尾 `ff d9` |
| GIF | `47 49 46 38`（GIF8） |
| PDF | `25 50 44 46`（%PDF） |
| ZIP/jar/apk | `50 4b 03 04`（PK..） |
| gzip | `1f 8b` |
| PCAP 抓包 | `d4 c3 b2 a1`（小端）/ `a1 b2 c3 d4`（大端） |
| Java class | `ca fe ba be` |

### 7.2 端到端解析一个 Modbus TCP 帧（通讯开发高频）

"读保持寄存器"请求（功能码 0x03）：事务标识 0x0001、协议 0x0000、长度 6、单元标识 1、起始地址 0、数量 10。

```bash
$ printf '\x00\x01\x00\x00\x00\x06\x01\x03\x00\x00\x00\x0a' > mb.bin
$ hexdump -C mb.bin
00000000  00 01 00 00 00 06 01 03  00 00 00 0a              |............|
0000000c
```

逐字段按**大端**切开（MBAP 头 7 字节 + PDU）：

| 偏移 | 字节 | 字段 | 值 |
| --- | --- | --- | --- |
| 0-1 | `00 01` | 事务标识 Transaction ID | 1（应答原样回填，用于匹配请求） |
| 2-3 | `00 00` | 协议标识 Protocol ID | 0 = Modbus |
| 4-5 | `00 06` | 后续字节长度 Length | 6 |
| 6 | `01` | 单元标识 Unit ID | 从站 1 |
| 7 | `03` | 功能码 | 03 读保持寄存器 |
| 8-9 | `00 00` | 起始地址 | 0 |
| 10-11 | `00 0a` | 寄存器数量 | 10 |

> 用这张表对照 hexdump 的原始字节，是定位"字节序反了、长度字段算错、功能码/地址偏移错位"最快的方法。多字节字段记得按大端（`00 01`=1，不是 0x0100）。

### 7.3 核对大小端与结构体内存布局（嵌入式高频）

```cpp
#include <stdint.h>
struct Frame { uint16_t addr; uint16_t func; uint32_t val; };
struct Frame f = {0x0001, 0x0003, 0x11223344};   // write 到 frame.bin
```

```bash
$ hexdump -C frame.bin
00000000  01 00 03 00 44 33 22 11                           |....D3"!|
# 小端机器：uint16 0x0001 存成 01 00；uint32 0x11223344 存成 44 33 22 11
# 而网络/串口多为大端，线上应是 00 01 00 03 11 22 33 44 —— 发出去前必须 htons/htonl
```

> 直接 hexdump 序列化后的字节流，验证 `htons/htonl`、结构体 padding 是否符合协议；编译器插入的对齐填充字节（常为 `00` 或栈残留）也一目了然。

### 7.4 配合管道 / 抓包 / 字符串

```bash
cat raw.packet | hexdump -C -v
tcpdump -r cap.pcap -XX port 502 | less          # tcpdump -XX 直接带 hex，配合《02-tcpdump网络抓包.md》
strings -a -t x firmware.bin | grep -i modbus    # 从二进制提取可打印串并给偏移
hexdump -C a.bin > a.hex; hexdump -C b.bin > b.hex; diff a.hex b.hex   # 直观逐字节 diff
```

## 8. 快速参考卡片

```text
日常查看：        hexdump -C file
只看前 N 字节：    hexdump -C -n 64 file
开窗口：          hexdump -C -s 0x20 -n 32 file
展开重复行：       hexdump -C -v file
单字节字符/八进制： hexdump -c / hexdump -b file
转 C 数组：        xxd -i file > out.h
hex 还原二进制：   xxd -r dump.txt out.bin
大端解析多字节：    od -An -tu2 --endian=big file   # 不要用 hexdump /2（会按小端）
等价 POSIX 写法：  od -Ax -tx1z -v file
看魔数：          hexdump -C -n 16 file
```

## 9. 常见问题与坑

1. **裸 `hexdump` 字节顺序是反的**：默认两字节小端拼字（`H e`→`6548`），看真实字节一定 `-C`。
2. **`hexdump -e '/2、/4'` 不能指定大端**：x86/ARM 默认小端，网络大端协议改用 `od --endian=big` 或 `-C` 自拼。
3. **`*` 不是出错**：连续相同行被折叠，加 `-v` 展开；清零 Flash/内存时最常见。
4. **裸 hexdump 偏移是 7 位八进制风格**：`0000020` 是十进制 16，别当成十进制 20；`-C` 是十六进制。
5. **ASCII 列的 `.` 有两种来源**：真点号 0x2e 与"不可打印"都显示 `.`，要回中间 hex 列区分。
6. **别手改 `-C` 文本再另存当二进制**：带偏移和 ASCII，不可逆；要可逆编辑用 `xxd/xxd -r` 或 `vim -b`。
7. **大文件别整盘 dump**：先 `-n` 看头、`-s` 定位，或管道接 `less`。
8. **结构体 dump 出来对不上协议**：多半是对齐 padding 或大小端没转，用 `__attribute__((packed))` + 显式序列化后 hexdump 复核。
