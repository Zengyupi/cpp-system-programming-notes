## 1. 概述

### 1.1 池化思想

| 要点 | 说明 |
|---|---|
| 预分配 | 启动/首次使用时一次性创建一批资源，而非用到再建 |
| 复用 | 用完不销毁，归还池中等待下一个使用者 |
| 收益 1 | 消除高频"创建-销毁"开销（线程创建毫秒级、连接创建毫秒级） |
| 收益 2 | 内存池把碎片"格式化"为定长块，减少 malloc 元数据与碎片 |
| 收益 3 | 削峰限流：池容量即并发上限，天然背压，防止把下游打垮 |

### 1.2 三大池总览

| 池 | 复用对象 | 解决的开销 | 典型场景 |
|---|---|---|---|
| 线程池 | 工作线程 | 线程创建/销毁、无限扩线程导致调度崩溃 | 突发任务削峰、并行计算、日志落盘 |
| 内存池 | 定长内存块 | malloc 元数据开销、brk/mmap 混合、多线程 arena 锁竞争 | 高频小块分配：请求对象、节点、报文 |
| 连接池 | DB 连接 | TCP 三次握手 + MySQL 认证握手 | Web 后端每次请求查库 |

## 2. 线程池【高频】

### 2.1 使用场景与组成

| 场景 | 说明 |
|---|---|
| 突发任务削峰 | 短时间海量小任务排队消化，线程数恒定不雪崩 |
| 限制并发资源 | 最多 N 个线程同时访问下游（DB/磁盘），天然背压 |
| 并行计算 | fork-join 型任务拆分执行 |

组成图（生产者-消费者骨架）：

```text
 提交线程(多个)                        管理者线程(周期巡检)
     | submit()                          | 扩容/回收/收割退出线程
     v                                   v
+--------------------------------------------+
| mutex + 条件变量 not_empty / not_full      |
| +-----------+   +------------------------+ |
| | 任务队列   |-->| 工作线程组              | |
| | (有界容量) |<--| w1 w2 ... wN           | |
| +-----------+   +------------------------+ |
+--------------------------------------------+
  生产者: 队满则等 not_full (背压/拒绝)
  消费者: 队空则等 not_empty; 扩展线程空闲超时退出
```

### 2.2 任务回调与条件等待

- 任务载体：`std::function<void()>` 打包任意可调用对象（成员函数用 lambda/`std::bind` 适配）
- 等待-通知：`condition_variable` + 谓词等待（`wait(lock, pred)`）防虚假唤醒，基础见 `../04-并发与多线程编程/01-并发编程与线程同步.md`
- 惊群优化【高频】：用**两个条件变量**——`not_empty`（消费者等）与 `not_full`（生产者等），唤醒各自 `notify_one`，避免单一条件变量上生产者消费者互相无效唤醒

### 2.3 动态伸缩策略表

| 参数 | 语义 | 典型值 |
|---|---|---|
| core_threads | 核心线程数，常驻不回收 | CPU 核数（计算型）~ 2×核数（IO 型） |
| max_threads | 线程总数上限 | 观察下游承受力定 |
| idle_timeout | 扩展线程空闲多久退出 | 5~60s |
| queue_capacity | 任务队列容量（有界） | 有限值（背压），不是无界 |
| 拒绝策略 | 队满 + 线程满时的行为 | 抛异常 / 调用者执行 / 丢弃 / 丢弃最旧 |

### 2.4 手撕生产级线程池（C++11 完整代码）【核心】

```cpp
// thread_pool.h  生产级线程池: future 支持 + 优雅停止 + 动态伸缩
#pragma once
#include <atomic>
#include <condition_variable>
#include <functional>
#include <future>
#include <map>
#include <memory>
#include <mutex>
#include <queue>
#include <set>
#include <stdexcept>
#include <thread>
#include <type_traits>
#include <vector>

class ThreadPool {
public:
    ThreadPool(size_t core, size_t max, size_t queue_cap, int idle_secs = 10)
        : core_(core), max_(max), cap_(queue_cap), idle_secs_(idle_secs) {
        for (size_t i = 0; i < core_; ++i) add_worker(false);  // 核心线程
        manager_ = std::thread([this] { manager_loop(); });   // 管理者线程
    }
    ~ThreadPool() { shutdown(); }
    ThreadPool(const ThreadPool&) = delete;
    ThreadPool& operator=(const ThreadPool&) = delete;

    // 提交任务: 返回 future, 异常经 future 传播给调用者
    template <class F, class... Args>
    auto submit(F&& f, Args&&... args)
        -> std::future<std::invoke_result_t<F, Args...>> {
        using R = std::invoke_result_t<F, Args...>;
        // packaged_task 只能移动, std::function 要求可拷贝 → 套 shared_ptr
        auto task = std::make_shared<std::packaged_task<R()>>(
            std::bind(std::forward<F>(f), std::forward<Args>(args)...));
        std::future<R> fut = task->get_future();
        {
            std::unique_lock<std::mutex> lock(mtx_);
            if (stop_) throw std::runtime_error("submit on stopped pool");
            if (!not_full_.wait_for(lock, std::chrono::seconds(1),
                    [this] { return tasks_.size() < cap_; }))
                throw std::runtime_error("queue full, task rejected"); // 拒绝策略
            tasks_.emplace([task] { (*task)(); });
        }
        not_empty_.notify_one();
        return fut;
    }

    void shutdown() {                    // 优雅停止: 排干队列后退出
        {
            std::unique_lock<std::mutex> lock(mtx_);
            if (stop_) return;
            stop_ = true;
        }
        not_empty_.notify_all();
        not_full_.notify_all();
        if (manager_.joinable()) manager_.join();
        std::vector<std::thread> joining;
        {
            std::unique_lock<std::mutex> lock(mtx_);
            for (auto& [id, t] : threads_)
                if (t.joinable()) joining.push_back(std::move(t));
            threads_.clear();
        }
        for (auto& t : joining) t.join();
    }

private:
    void add_worker(bool extra) {
        std::thread t([this] { worker_loop(); });
        std::thread::id id = t.get_id();
        std::unique_lock<std::mutex> lock(mtx_);
        threads_.emplace(id, std::move(t));
        if (extra) extra_ids_.insert(id);
    }

    void worker_loop() {
        bool extra = false;
        {
            std::unique_lock<std::mutex> lock(mtx_);
            extra = extra_ids_.count(std::this_thread::get_id()) > 0;
        }
        for (;;) {
            std::function<void()> task;
            {
                std::unique_lock<std::mutex> lock(mtx_);
                if (extra) {   // 扩展线程: 空闲超时可被回收
                    bool got = not_empty_.wait_for(lock,
                        std::chrono::seconds(idle_secs_),
                        [this] { return stop_ || !tasks_.empty(); });
                    if (!got) {                       // 超时且无任务 → 自我退出
                        retire_self();                // 注意: 此处仍持有外层锁
                        return;
                    }
                } else {        // 核心线程: 一直等
                    not_empty_.wait(lock, [this] { return stop_ || !tasks_.empty(); });
                }
                if (tasks_.empty()) {                // 虚假唤醒/刚被唤醒
                    if (stop_) return;               // 停机路径: 交给 shutdown join
                    continue;
                }
                task = std::move(tasks_.front());
                tasks_.pop();
            }
            not_full_.notify_one();                  // 腾出一个队列空位
            task();  // 异常已被 packaged_task 捕获存入 future, 不会击穿线程
        }
    }

    void retire_self() {   // 运行期自我回收(线程无法 join 自己→detach)
        std::thread::id me = std::this_thread::get_id();
        threads_.at(me).detach();        // 脱管; 线程体随即 return 结束
        retiring_.insert(me);            // 登记, 由 manager 从 map 清除
        extra_ids_.erase(me);
    }

    void manager_loop() {         // 周期巡检: 扩容 + 回收
        while (!stop_) {
            std::this_thread::sleep_for(std::chrono::seconds(2));
            std::unique_lock<std::mutex> lock(mtx_);
            // 1) 任务积压且未达上限 → 加一个扩展线程
            if (!tasks_.empty() && threads_.size() < max_)
                add_worker(true);
            // 2) 尝试收割已退出线程(登记过的)
            std::vector<std::thread::id> done(retiring_.begin(), retiring_.end());
            for (auto id : done) {
                auto it = threads_.find(id);
                if (it != threads_.end()) { threads_.erase(it); retiring_.erase(id); }
            }
        }
    }

    std::queue<std::function<void()>> tasks_;
    std::map<std::thread::id, std::thread> threads_;  // id → 线程对象
    std::set<std::thread::id> extra_ids_;             // 扩展线程集合
    std::set<std::thread::id> retiring_;              // 已退出待收割
    std::mutex mtx_;
    std::condition_variable not_empty_, not_full_;
    size_t core_, max_, cap_;
    int idle_secs_;
    bool stop_ = false;
    std::thread manager_;
};
```

使用示例与异常传播说明：

```cpp
ThreadPool pool(4, 8, 1000);
auto f1 = pool.submit([](int a, int b) { return a + b; }, 1, 2);   // f1.get()==3
auto f2 = pool.submit([] { throw std::runtime_error("boom"); });
try { f2.get(); }                       // 异常在 future.get() 处重新抛出
catch (const std::exception& e) { /* e.what()=="boom" */ }
```

| 设计点 | 说明 |
|---|---|
| submit 返回 future | packaged_task 把返回值/异常封进 future；任务抛异常不会杀死 worker |
| 双条件变量 | not_empty / not_full 分离，唤醒精准 |
| 优雅停止 | stop 后不接新任务（submit 抛异常），worker 把剩余任务做完才退出 |
| 扩展线程回收 | 自我超时退出 + manager 收割，核心线程永不退出 |

| 维度 | 教学版（见 ../04-并发与多线程编程/01-并发编程与线程同步.md） | 本篇生产级 |

## 3. 内存池【高频】

### 3.1 为什么需要

| 痛点 | 说明 |
|---|---|
| malloc 元数据开销 | 每次分配带 chunk header、位图等管理数据，8B 的请求实际耗 16B+ |
| brk/mmap 混合 | glibc：小块走 brk 堆顶，大块走 mmap；混合使用产生地址空间碎片 |
| 小块高频分配碎片 | 请求对象/链表节点生命周期交错，堆被切成不连续小块 |
| 多线程锁竞争 | glibc 多 arena 缓解但仍有竞争；高频分配时锁是热点 |

### 3.2 小块与大块分配

```text
定长 free list (小块):
  大块内存(一次 new) 按固定 size 切割, 空闲节点串成链
     +------+------+------+------+
     | node | node | node | node |   chunk (chunk_blocks * BlockSize)
     +--+---+--+---+--+---+--+---+
        |      |      |      |
        v      v      v      v
  free_head -> node -> node -> node -> NULL
  alloc:   取头节点, 头指针后移            O(1)
  free:    节点头插回链表                  O(1)

大块分配: size > 阈值 → 直接 malloc, 归还时也走系统 free
```

### 3.3 手撕定长内存池（C++ 完整代码）【核心】

```cpp
// fixed_mem_pool.h  定长内存池: free list 实现
#pragma once
#include <cstddef>
#include <mutex>
#include <new>
#include <vector>

template <size_t BlockSize>
class FixedMemPool {
public:
    explicit FixedMemPool(size_t blocks_per_chunk = 1024)
        : chunk_blocks_(blocks_per_chunk) {
        static_assert(BlockSize >= sizeof(void*),
                      "BlockSize 必须能容纳空闲链表指针");
        static_assert(BlockSize % alignof(void*) == 0,
                      "BlockSize 需按指针宽度对齐");
        alloc_chunk();                       // 启动即备好一个 chunk
    }
    ~FixedMemPool() {
        for (void* c : chunks_) ::operator delete(c);   // 整池归还系统
    }
    FixedMemPool(const FixedMemPool&) = delete;
    FixedMemPool& operator=(const FixedMemPool&) = delete;

    void* allocate() {                       // 对应 new
        {
            std::lock_guard<std::mutex> g(mtx_);
            if (free_head_) {                // 快路径: O(1) 摘头节点
                void* p = free_head_;
                free_head_ = free_head_->next;
                return p;
            }
        }
        refill();                            // 慢路径: 换新 chunk
        return allocate();
    }

    void deallocate(void* p) noexcept {      // 对应 delete
        if (!p) return;
        Node* n = static_cast<Node*>(p);     // 归还 = 头插
        std::lock_guard<std::mutex> g(mtx_);
        n->next = free_head_;
        free_head_ = n;
    }

    static FixedMemPool& instance() {        // 每种 size 一个全局池(可选)
        static FixedMemPool pool;
        return pool;
    }

private:
    union Node {                             // 空闲节点: 内存与链指针复用
        Node* next;
        unsigned char pad[BlockSize];
    };

    void alloc_chunk() {                     // 需在持锁状态下调用
        size_t bytes = chunk_blocks_ * BlockSize;
        unsigned char* mem =
            static_cast<unsigned char*>(::operator new(bytes));
        chunks_.push_back(mem);
        for (size_t i = 0; i < chunk_blocks_; ++i) {   // 切块并串链
            Node* n = reinterpret_cast<Node*>(mem + i * BlockSize);
            n->next = free_head_;
            free_head_ = n;
        }
    }

    void refill() {
        std::lock_guard<std::mutex> g(mtx_);
        if (free_head_) return;              // 双检: 别的线程刚补过
        alloc_chunk();
    }

    Node* free_head_ = nullptr;
    std::vector<void*> chunks_;              // 记录大块, 析构统一释放
    size_t chunk_blocks_;
    std::mutex mtx_;                         // 线程安全封装(见下文说明)
};
```

| 要点 | 说明 |
|---|---|
| union Node | 空闲时当链表指针用，分配出去当数据用，零额外元数据 |
| O(1) 分配/释放 | 摘头/头插，无 best-fit 搜索 |
| chunk 双检 | refill 加锁后先再查一次 free_head，防多个线程同时补块 |
| 线程安全 | 这里用一把 mutex 保平安；高并发应改**每线程池**（thread_local 实例）或按核分池，竞争立即消失 |
| 多级 size class | tcmalloc 一句话：按 8/16/32...字节级数分池 + 每线程 cache + 中央回收，见 `../01-C++语言核心/04-内存管理与智能指针.md` |

### 3.4 nginx 内存池剖析

nginx 的 `ngx_pool_t` 证明"池"可以和"生命周期"绑定——一个 HTTP 请求一个池，请求结束整池销毁，全程不做单个 free。

```text
ngx_pool_t
+----------------------------------------------+
| d: last ──►|end   (当前小块的 bump 分配指针)   |
|    max:  小块阈值(默认 pagesize-1)             |
|    current: 从这块开始找(跳过失败块)           |
| large ──────────────────────────────┐         |
| cleanup ───────────────┐            |         |
+------------------------│------------│---------+
   小块链 p->d.next       │            │
 +-------------+          │            │
 | ngx_pool_t  |→next     │            │
 +-------------+          v            v
                ngx_pool_cleanup_t   ngx_pool_large_t
                {handler,data,next}  {next, alloc(指向malloc的大块)}
                如 close(fd)/释放外部资源
```

| 机制 | 说明 |
|---|---|
| 小块 | `ngx_palloc(size ≤ max)`：在当前块从 `d.last` 向 `d.end` 做 bump 分配，按 `NGX_ALIGNMENT`（源码定义为 `sizeof(unsigned long)`，64 位平台 8 字节；不少资料误写 16，以源码为准）对齐；本块放不下则 `d.next` 链入新块 |
| 大块 | `size > max`：单独 malloc，挂到 large 链头部（插头 O(1)） |
| pfree | 只对大块有效：large 链上找到节点 free；小块**不支持单独释放** |
| destroy | 先遍历 cleanup 链执行注册回调（关 fd、释放外部句柄），再 free 大块链，再 free 所有小块 |
| cleanup | `ngx_pool_cleanup_add` 注册"析构动作"，弥补池内对象没有单独析构的问题 |

为什么适合请求生命周期：请求内所有分配几乎同生共死 → 整池销毁 O(块数)，免掉上万次 free；碎片与元数据开销双双消失。反面：池存活很久且对象错峰释放的业务（如缓存）就不合适——这正是"定长池 + free list"和"tcmalloc 多级"要解决的问题。

## 4. MySQL 连接池【高频】

### 4.1 性能影响的两个因素

| 因素 | 说明 | 量级 |
|---|---|---|
| TCP 三次握手 | 建连接 1.5 RTT + 内核资源 | 局域网 0.1~1ms |
| MySQL 认证握手 | challenge-response：服务端发盐 → 客户端哈希回传 → 服务端验证，多一次往返 + 密码学计算 | 再 1 RTT + 计算 |

单次新建连接毫秒级看似不慢，但 QPS 1 万的服务每秒就多付出 10 秒级 CPU/等待；且高并发建连会冲击 MySQL 的连接数上限（`max_connections`）与线程创建。结论：**连接必须池化**。

### 4.2 池参数设计表

| 参数 | 语义 | 经验值 |
|---|---|---|
| init_size | 启动时预建 | 常态并发的 1/2，预热避免冷启动抖动 |
| max_size | 连接总数上限 | DB 能承受 + 业务并发上限的交点，压测定 |
| min_idle | 最小空闲（低于则补建） | init_size |
| borrow_timeout | 借出等待超时 | 100ms~1s，快速失败 |
| max_lifetime | 连接最大存活 | 小于 DB 的 wait_timeout（如 3600s），防半死连接 |
| heartbeat | 空闲心跳周期 | 30s~5min，`mysql_ping` 保活 |

### 4.3 归还与超时策略

| 策略 | 实现 |
|---|---|
| RAII 归还 | Guard 对象析构自动 release——异常路径也不漏 |
| 借出计时 | 借出时记 last_borrow；后台巡检发现超时未还 → 告警；强制回收需谨慎（使用中连接被回收会崩） |
| 失活重建 | 借出/归还时 `mysql_ping` 失败 → 关闭、total--，等待方继续等池补建 |

### 4.4 同步与异步两种机理

```text
同步池:
  业务线程 ──getConnection──► [空闲队列空] ──cond_wait──┐
  业务线程 ◄──release── notify ◄──────────────────────┘
  特点: 简单; 但线程在等待期间被挂起占住

异步池:
  业务线程 ──submit(sql, callback)──► 请求队列 ──┐
                                                v
                                    worker线程: 取请求→持连接执行
                                                │ 完成后
  业务线程 ◄───── callback(结果) ◄───────────────┘
  特点: 业务线程不阻塞; 回调交付由框架事件循环承接
```

### 4.5 手撕 MySQL 连接池（完整代码）【核心】

```cpp
// mysql_pool.h  同步连接池: RAII 归还 + 心跳保活 + 单例 (C++11)
#pragma once
#include <mysql/mysql.h>
#include <atomic>
#include <chrono>
#include <condition_variable>
#include <cstring>
#include <deque>
#include <mutex>
#include <string>
#include <thread>
#include <unordered_map>

class MySQLPool {
public:
    struct Config {
        std::string host = "127.0.0.1";
        unsigned int port = 3306;
        std::string user = "root", passwd, db;
        int init_size = 4, max_size = 16;
        int borrow_timeout_ms = 500;     // 借出超时
        int heartbeat_s = 30;            // 心跳周期
    };

    static MySQLPool& instance() { static MySQLPool p; return p; }

    bool init(const Config& c) {
        cfg_ = c;
        std::unique_lock<std::mutex> lock(mtx_);
        for (int i = 0; i < cfg_.init_size; ++i) {
            MYSQL* conn = create_conn();
            if (!conn) return false;
            idle_.push_back(conn);
            total_++;
        }
        running_ = true;
        hb_ = std::thread([this] { heartbeat_loop(); });
        return true;
    }

    MYSQL* acquire() {                  // 借出: 空闲→新建→等待
        std::unique_lock<std::mutex> lock(mtx_);
        auto deadline = std::chrono::steady_clock::now() +
                        std::chrono::milliseconds(cfg_.borrow_timeout_ms);
        for (;;) {
            while (!idle_.empty()) {
                MYSQL* conn = idle_.front(); idle_.pop_front();
                if (mysql_ping(conn) == 0) return conn;   // 验活后借出
                mysql_close(conn); total_--;              // 死连接销毁
            }
            if (total_ < cfg_.max_size) {                 // 未达上限: 补建
                total_++;                                 // 先占坑防超建
                lock.unlock();
                MYSQL* conn = create_conn();
                lock.lock();
                if (!conn) { total_--; cv_.notify_one(); return nullptr; }
                return conn;
            }
            if (cv_.wait_until(lock, deadline) == std::cv_status::timeout)
                return nullptr;           // 借出超时: 上层降级/告警
        }
    }

    void release(MYSQL* conn) {          // 归还: 失活则销毁
        if (!conn) return;
        std::unique_lock<std::mutex> lock(mtx_);
        if (mysql_ping(conn) != 0) {
            mysql_close(conn); total_--;
            return;
        }
        idle_.push_back(conn);
        cv_.notify_one();
    }

    void shutdown() {
        running_ = false;
        if (hb_.joinable()) hb_.join();
        std::unique_lock<std::mutex> lock(mtx_);
        for (MYSQL* c : idle_) { mysql_close(c); total_--; }
        idle_.clear();
    }

private:
    MYSQL* create_conn() {
        MYSQL* c = mysql_init(nullptr);
        bool reconnect = true;                    // 断线自动重连(仍需 ping 触发)
        mysql_options(c, MYSQL_OPT_RECONNECT, &reconnect);
        mysql_options(c, MYSQL_SET_CHARSET_NAME, "utf8mb4");
        if (!mysql_real_connect(c, cfg_.host.c_str(), cfg_.user.c_str(),
                cfg_.passwd.c_str(), cfg_.db.c_str(), cfg_.port, nullptr, 0)) {
            mysql_close(c);
            return nullptr;
        }
        return c;
    }

    void heartbeat_loop() {                        // 心跳: 空闲连接保活
        while (running_) {
            std::this_thread::sleep_for(
                std::chrono::seconds(cfg_.heartbeat_s));
            std::deque<MYSQL*> targets;
            {
                std::unique_lock<std::mutex> lock(mtx_);
                targets = idle_;                   // 拷贝名单, 锁外执行
            }
            for (MYSQL* c : targets) mysql_ping(c);// 网络IO在锁外, 不阻塞借还
        }
    }

    Config cfg_;
    std::mutex mtx_;
    std::condition_variable cv_;
    std::deque<MYSQL*> idle_;                      // 空闲连接队列
    int total_ = 0;                                // 空闲+借出总数
    std::atomic<bool> running_{false};
    std::thread hb_;
};

// RAII Guard: 借出即绑定, 出作用域自动归还
class MySQLConnGuard {
public:
    explicit MySQLConnGuard() : conn_(MySQLPool::instance().acquire()) {}
    ~MySQLConnGuard() { if (conn_) MySQLPool::instance().release(conn_); }
    MYSQL* operator->() const { return conn_; }
    MYSQL* get() const { return conn_; }
    explicit operator bool() const { return conn_ != nullptr; }
    MySQLConnGuard(const MySQLConnGuard&) = delete;
    MySQLConnGuard& operator=(const MySQLConnGuard&) = delete;
private:
    MYSQL* conn_;
};
```

```cpp
// 使用示例
void query_user(long id) {
    MySQLConnGuard g;                       // 借出
    if (!g) { /* 借出超时: 降级/返回繁忙 */ return; }
    char sql[128];
    snprintf(sql, sizeof(sql), "SELECT name FROM user WHERE id=%ld", id);
    if (mysql_query(g.get(), sql) == 0) {
        MYSQL_RES* res = mysql_store_result(g.get());
        // ... 取行
        mysql_free_result(res);
    }
}                                          // 析构自动归还
```

与数据库中间件（如 ProxySQL/MyCat）连接池的关系一句话：中间件把"连接池"做在代理层，后端对应用透明，适合多语言/无法改客户端的架构；自建池性能最好但仅限本进程。

## 5. 通用设计准则

| 准则 | 说明 |
|---|---|
| 参数可配置化 | 池大小/超时全部走配置文件 + 热加载，拒绝写死 |
| 预热 | 启动时建满 init_size（连接池连 DB、内存池建首 chunk），避免首请求毛刺 |
| 监控指标 | 见下表；没有监控的池等于盲飞 |
| 背压与拒绝 | 有界队列 + 明确拒绝策略，宁可拒绝不可雪崩 |

监控指标表：

| 指标 | 含义 | 告警建议 |
|---|---|---|
| 池水位 | 空闲/总数/借出 | 空闲长期为 0 → 扩容或降级 |
| 等待队列长度 | 等待借出的请求数 | 突增 → 下游变慢前兆 |
| 等待耗时 P99 | acquire 耗时 | > 借出超时一半即关注 |
| 泄漏计数 | 借出后超时未归还 | > 0 即报警，定位代码路径 |
| 拒绝计数 | 拒绝策略触发次数 | 突增 → 容量不足或上游洪峰 |

## 7. 常见问题与坑

| 坑 | 现象 | 正解 |
|---|---|---|
| 任务抛异常未捕获 | std::terminate，整个进程崩 | 用 packaged_task 让异常进 future；或 worker 里 try-catch 兜底日志 |
| 线程池里再 submit 等待结果 | 死锁：外层任务占住 worker 等 future，内层任务排不上 | 禁止池内同步等待同池任务；改异步链式（then）或独立池 |
| 队列无界 | 任务堆积吃光内存后 OOM | 有界 + 拒绝策略 |
| submit 返回值丢弃 | 任务异常被吞、无法感知失败 | 至少 get() 一次或 log future 状态；重要任务必须持 future |
| 内存池线程安全误用 | 一边宣称无锁一边多线程 alloc | 默认加锁；或明确 thread_local 分池；接口文档写清并发契约 |
| 内存池当万能 malloc | 大对象也走定长池，浪费严重 | 超阈值直落系统 malloc，池只管小块 |
| 池对象析构顺序错误 | 池先于使用它的线程/请求销毁，use-after-free | 全局池单例 + atexit 顺序，或显式 shutdown 在依赖停止后 |
| 连接池雪崩（DB 重启） | 全部连接失活，瞬间重建风暴压垮刚恢复的 DB | 失活连接按小批重建 + acquire 指数退避；重建加并发闸门 |
| 忘记归还 | 池慢慢耗尽，借出超时 | 只通过 RAII Guard 拿连接，禁裸 acquire |
| 归还后继续使用 | 数据写进已借给别人的连接 | 归还即交出所有权；Guard 后不得再持裸 MYSQL* |
| 池大小拍脑袋 | 过小排队、过大压垮 DB | 从 2×核数起步压测，观察水位与 DB 负载调 |
| max_lifetime > wait_timeout | 拿到被 DB 单方面掐死的连接 | lifetime 必须小于 DB 的 wait_timeout，配合 ping |
| 心跳在锁内执行 | ping 阻塞期间整个池无法借还 | 心跳锁内取名单、锁外执行 |
| 依赖 MYSQL_OPT_RECONNECT 万能 | 事务中途断线重连造成状态混乱 | 重连只保底；事务失败显式回滚重试 |
