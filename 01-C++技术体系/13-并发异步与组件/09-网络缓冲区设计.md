## 1. 为什么需要缓冲区

### 1.1 收发速度不匹配

TCP 是字节流协议，发送方和接收方的处理速度不可能完全一致：

```text
发送方 1Gbps 突发数据 → 内核 send buffer → 网络 → 内核 recv buffer → 应用层
                                                          │
                                              应用处理慢（业务逻辑/磁盘IO）
                                              → 数据堆积在 recv buffer
                                              → 需要应用层缓冲区暂存
```

**没有应用层缓冲区的问题**：
- 应用一次 `recv()` 没读完，剩余数据留在内核缓冲区，下次 epoll 再通知
- 但 ET（边缘触发）模式下只通知一次，没读完就再也不会通知 → 数据卡住
- 应用层缓冲区 = 把内核数据一次性读到用户态，慢慢处理

### 1.2 半包与粘包

TCP 是**字节流**，没有消息边界。应用层发送 3 条消息，TCP 可能：

```text
发送：[msg1][msg2][msg3]
接收可能：
  [msg1ms][g2msg3]      ← 粘包（多条合并）+ 半包（msg1 被截断）
  [msg1][msg2msg3]      ← 粘包
  [msg1msg2][ms][g3]    ← 多次 recv，每次边界不定
```

**缓冲区的作用**：暂存不完整的数据，等凑齐一条完整消息再交给业务层。

## 2. RingBuffer（环形缓冲区）【核心】

### 2.1 读写指针与环形逻辑

RingBuffer 用一块连续内存 + 两个指针（读指针 r、写指针 w）实现循环使用：

```text
初始状态（空）：
  [ ][ ][ ][ ][ ][ ][ ][ ]
   r
   w

写入 3 字节后：
  [A][B][C][ ][ ][ ][ ][ ]
   r        w

读取 2 字节后：
  [ ][ ][C][ ][ ][ ][ ][ ]
         r  w

写满到末尾后回绕（写指针到末尾回到开头）：
  [F][G][C][D][E][ ][ ][ ]
         w  r
  （r 在中间，w 回绕到开头，形成"环"）
```

**关键约定**：
- `w == r` 表示空（不是满）
- `(w + 1) % size == r` 表示满（牺牲一个格子区分空和满）
- 读指针只能追写指针，不能超过

### 2.2 取模 vs 位与

环形回绕需要取模运算。取模 `%` 是除法指令，较慢。**当 size 是 2 的幂时，可用位与 `&` 替代**：

```cpp
// size = 1024 (2^10)
w = (w + n) % size;   // 取模：除法指令，~20 cycles
w = (w + n) & (size - 1);  // 位与：1 cycle，等价于取模
```

**设计原则**：RingBuffer 大小始终取 2 的幂（64/256/1024/4096/...），用位与替代取模。

### 2.3 空间计算

```cpp
// 可读数据量
size_t readable() const {
    return (w_ >= r_) ? (w_ - r_) : (size_ - r_ + w_);
}

// 可写空间量（牺牲 1 字节）
size_t writable() const {
    return (w_ >= r_) ? (size_ - w_ + r_ - 1) : (r_ - w_ - 1);
}

// 写指针到末尾的连续空间（可能需要分两段写）
size_t writable_contiguous() const {
    return (w_ >= r_) ? (size_ - w_ - (r_ == 0 ? 1 : 0)) : (r_ - w_ - 1);
}
```

**写入时可能需要分两段**：写指针到末尾空间不够时，先写满末尾，再从开头继续写。

### 2.4 生产者消费者模型

RingBuffer 天然适合**单生产者单消费者**模型：
- 生产者（网络 IO 线程）只移动写指针
- 消费者（业务处理线程）只移动读指针
- 两者不共享变量（w 只生产者改，r 只消费者改），无需锁

```text
IO 线程（生产者）              业务线程（消费者）
  recv() → 写入 RingBuffer       从 RingBuffer 读 → 解析消息
  移动 w_                         移动 r_
```

多生产者/多消费者需加锁或用无锁环形缓冲区（CAS 更新指针）。

## 3. ChainBuffer（链式缓冲区）

### 3.1 ngx_chain_t 风格设计

ChainBuffer 由多个独立的 buffer 节点串联成链表，每个节点有自己的 pos/last 指针：

```text
chain → [buf1: pos/last, next] → [buf2: pos/last, next] → [buf3: pos/last, next] → NULL
```

```cpp
struct ChainBuffer {
    char*      pos;    // 读指针
    char*      last;   // 写指针（有效数据末尾）
    char*      start;  // buffer 起始
    char*      end;    // buffer 末尾
    ChainBuffer* next;
};
```

### 3.2 多 buf 串联与零拷贝

ChainBuffer 的核心优势：**不需要连续内存**。

```text
RingBuffer 问题：需要一块连续大内存，扩容时要重新分配+拷贝
ChainBuffer：需要更多空间时，new 一个 buf 挂到链表末尾，零拷贝

发送大文件时：
  chain → [文件头 buf(内存)] → [文件内容 buf(指向 mmap 内存)] → [文件尾 buf(内存)]
  三个 buf 物理上不连续，但逻辑上是一条完整消息
  writev 一次调用全部发送，用户态零拷贝
```

### 3.3 writev 分散写

`writev`（集中写）可以一次系统调用发送多个不连续的 buffer：

```cpp
#include <sys/uio.h>

ssize_t writev(int fd, const struct iovec *iov, int iovcnt);

// 使用：把 chain 中每个 buf 转成 iovec，一次发送
struct iovec iov[1024];
int cnt = 0;
for (ChainBuffer* c = chain; c && cnt < 1024; c = c->next) {
    iov[cnt].iov_base = c->pos;
    iov[cnt].iov_len = c->last - c->pos;
    cnt++;
}
ssize_t n = writev(fd, iov, cnt);
```

对比：RingBuffer 发送需要先把数据拼到连续内存（memcpy），再 send；ChainBuffer 直接 writev，省一次拷贝。

## 4. FixedBuffer（固定大小缓冲）

FixedBuffer 是大小固定的简单缓冲区，通常作为 ChainBuffer 的节点或协议解析的临时缓冲。

```cpp
template<size_t SIZE>
class FixedBuffer {
    char data_[SIZE];
    size_t len_ = 0;
public:
    void append(const char* d, size_t n) {
        memcpy(data_ + len_, d, n);
        len_ += n;
    }
    void clear() { len_ = 0; }
    const char* data() const { return data_; }
    size_t size() const { return len_; }
};
```

**适用场景**：
- 协议头解析（固定 4/8/16 字节）
- 小消息暂存
- ChainBuffer 的单个节点
- 栈上临时缓冲（避免堆分配）

## 5. 发送缓冲区与接收缓冲区设计

### 5.1 接收缓冲区（recv buffer）

```text
epoll EPOLLIN 触发 → recv() 读到 RingBuffer → 尝试解析完整消息
                                         → 完整：回调业务层
                                         → 不完整：等下次 recv 凑齐
```

**ET 模式下必须一次读到 EAGAIN**：

```cpp
void on_readable(int fd, RingBuffer& buf) {
    for (;;) {
        // 直接读到 RingBuffer 的可写区域
        size_t space = buf.writable_contiguous();
        ssize_t n = ::recv(fd, buf.write_ptr(), space, 0);
        if (n > 0) {
            buf.advance_write(n);
            // 尝试解析消息
            while (buf.has_complete_message()) {
                Message msg = buf.read_message();
                dispatch(msg);
            }
        } else if (n == 0) {
            close_connection(fd);  // 对端关闭
            return;
        } else {
            if (errno == EAGAIN || errno == EWOULDBLOCK) break;  // 读完了
            if (errno == EINTR) continue;
            close_connection(fd);  // 错误
            return;
        }
    }
}
```

### 5.2 发送缓冲区（send buffer）

```text
业务层 send(msg) → 写入 ChainBuffer → 注册 EPOLLOUT
epoll EPOLLOUT 触发 → writev 发送 → 全部发完则注销 EPOLLOUT
```

**为什么需要发送缓冲区**：
- 内核 send buffer 可能满（对端接收慢），`send()` 返回 EAGAIN
- 数据不能丢，需暂存在应用层发送缓冲区
- 等 fd 可写时（EPOLLOUT）再继续发送

```cpp
void send_message(int fd, const Message& msg, ChainBuffer*& send_chain) {
    // 序列化到 ChainBuffer（零拷贝：直接挂 buf）
    append_to_chain(send_chain, msg);
    // 注册可写事件
    epoll_modify(fd, EPOLLIN | EPOLLOUT);
}

void on_writable(int fd, ChainBuffer*& send_chain) {
    // writev 发送所有 buf
    ssize_t n = writev_chain(fd, send_chain);
    if (n > 0) {
        advance_chain(send_chain, n);  // 移动 pos，释放已发完的 buf
        if (chain_empty(send_chain)) {
            epoll_modify(fd, EPOLLIN);  // 发完了，注销 EPOLLOUT
        }
    } else if (n < 0 && errno != EAGAIN) {
        close_connection(fd);
    }
}
```

## 6. 半包粘包解决方案【高频】

### 6.1 定长消息

每条消息固定大小，最简单但不灵活：

```cpp
const size_t MSG_SIZE = 64;
while (buf.readable() >= MSG_SIZE) {
    char msg[MSG_SIZE];
    buf.read(msg, MSG_SIZE);
    handle(msg);
}
```

适用：心跳包、固定格式状态上报。

### 6.2 分隔符

用特殊字符（如 `\n`、`\r\n`、`\0`）分隔消息：

```cpp
// 查找分隔符
const char* data = buf.read_ptr();
size_t len = buf.readable();
for (size_t i = 0; i < len; ++i) {
    if (data[i] == '\n') {
        // 找到一条完整消息 [0, i]
        handle_message(data, i);
        buf.advance_read(i + 1);  // 跳过分隔符
        break;
    }
}
```

适用：文本协议（HTTP/1.1 header、Redis RESP、IRC）。
缺点：需扫描缓冲区找分隔符 O(n)；消息内容不能含分隔符（需转义）。

### 6.3 长度字段（TLV）

最常用的方案：消息头包含长度字段，先读固定长度的头，再按长度读 body。

```text
消息格式（TLV：Type-Length-Value）：
+----------+----------+------------------+
|  type(2) | length(4)|    value(N)      |
+----------+----------+------------------+
  固定 6 字节头         length 指定 body 长度
```

```cpp
void try_parse(RingBuffer& buf) {
    // 1. 先读 6 字节头
    if (buf.readable() < 6) return;  // 半包：头都没齐
    uint16_t type = read_u16(buf.read_ptr());
    uint32_t body_len = read_u32(buf.read_ptr() + 2);

    // 2. 检查 body 是否齐
    if (buf.readable() < 6 + body_len) return;  // 半包：body 没齐

    // 3. 完整消息，处理
    handle_message(type, buf.read_ptr() + 6, body_len);
    buf.advance_read(6 + body_len);

    // 4. 继续解析下一条（粘包：缓冲区可能有多条）
    try_parse(buf);  // 递归或循环
}
```

**TLV 变体**：
- 只有 Length（无 Type）：最简单的长度前缀
- Type + Length + Value：标准 TLV
- Magic + Version + Length + Body：带魔数和版本的协议头（更健壮）

## 7. 缓冲区动态扩容与水位线

**RingBuffer 扩容**：
- 写满时分配 2 倍大小的新内存
- 将旧数据拷贝到新 buffer（注意处理回绕情况）
- 释放旧内存

```cpp
void RingBuffer::expand() {
    size_t new_size = size_ * 2;  // 2 倍扩容
    char* new_buf = new char[new_size];
    // 拷贝旧数据（处理回绕：分两段拷贝）
    size_t readable = this->readable();
    if (w_ >= r_) {
        memcpy(new_buf, data_ + r_, w_ - r_);
    } else {
        size_t first = size_ - r_;
        memcpy(new_buf, data_ + r_, first);
        memcpy(new_buf + first, data_, w_);
    }
    delete[] data_;
    data_ = new_buf;
    size_ = new_size;
    r_ = 0;
    w_ = readable;
}
```

**水位线（watermark）**：
- 低水位线：接收缓冲区数据量低于此值时，重新注册 EPOLLIN（之前因为缓冲区满暂停读取）
- 高水位线：接收缓冲区数据量超过此值时，注销 EPOLLIN（背压，停止读取，让内核缓冲区积压，TCP 窗口收缩通知对端降速）

```cpp
const size_t HIGH_WATERMARK = 64 * 1024;  // 64KB
const size_t LOW_WATERMARK  = 16 * 1024;  // 16KB

void on_readable(...) {
    recv_into_buffer();
    if (buf.readable() > HIGH_WATERMARK) {
        epoll_modify(fd, EPOLLOUT);  // 暂停读，背压
    }
}

void on_message_processed(...) {
    if (buf.readable() < LOW_WATERMARK) {
        epoll_modify(fd, EPOLLIN | EPOLLOUT);  // 恢复读
    }
}
```

## 8. 手撕实现：RingBuffer C++ 完整代码【核心】

```cpp
// ring_buffer.h —— 单线程 RingBuffer（2 的幂大小，位与回绕）
#pragma once
#include <cstdint>
#include <cstring>
#include <algorithm>
#include <stdexcept>

class RingBuffer {
public:
    explicit RingBuffer(size_t capacity = 4096) {
        // 向上取整到 2 的幂
        size_ = 1;
        while (size_ < capacity + 1) size_ <<= 1;  // +1 因为牺牲 1 字节
        data_ = new char[size_];
        r_ = w_ = 0;
    }

    ~RingBuffer() { delete[] data_; }

    RingBuffer(const RingBuffer&) = delete;
    RingBuffer& operator=(const RingBuffer&) = delete;

    // 可读字节数
    size_t readable() const {
        return (w_ >= r_) ? (w_ - r_) : (size_ - r_ + w_);
    }

    // 可写字节数（牺牲 1 字节区分空满）
    size_t writable() const {
        return size_ - readable() - 1;
    }

    // 写指针位置（供 recv 直接写入）
    char* write_ptr() { return data_ + w_; }

    // 读指针位置（供业务直接读取）
    const char* read_ptr() const { return data_ + r_; }

    // 写指针到末尾的连续可写空间
    size_t writable_contiguous() const {
        if (w_ >= r_) {
            // w 在 r 后面：可写到末尾，但不能写到 r 的前一格
            return (r_ == 0) ? (size_ - w_ - 1) : (size_ - w_);
        } else {
            // w 在 r 前面：只能写到 r 的前一格
            return r_ - w_ - 1;
        }
    }

    // 读指针到末尾的连续可读空间
    size_t readable_contiguous() const {
        return (w_ >= r_) ? (w_ - r_) : (size_ - r_);
    }

    // 推进写指针（recv 返回后调用）
    void advance_write(size_t n) {
        if (n > writable()) throw std::overflow_error("RingBuffer write overflow");
        w_ = (w_ + n) & (size_ - 1);
    }

    // 推进读指针（业务消费后调用）
    void advance_read(size_t n) {
        if (n > readable()) throw std::underflow_error("RingBuffer read underflow");
        r_ = (r_ + n) & (size_ - 1);
    }

    // 写入数据（自动处理回绕，分两段拷贝）
    size_t write(const char* src, size_t n) {
        size_t actual = std::min(n, writable());
        if (actual == 0) return 0;
        size_t first = std::min(actual, writable_contiguous());
        memcpy(data_ + w_, src, first);
        if (first < actual) {
            // 回绕：第二段从开头写
            memcpy(data_, src + first, actual - first);
        }
        w_ = (w_ + actual) & (size_ - 1);
        return actual;
    }

    // 读取数据（自动处理回绕）
    size_t read(char* dst, size_t n) {
        size_t actual = std::min(n, readable());
        if (actual == 0) return 0;
        size_t first = std::min(actual, readable_contiguous());
        memcpy(dst, data_ + r_, first);
        if (first < actual) {
            memcpy(dst + first, data_, actual - first);
        }
        r_ = (r_ + actual) & (size_ - 1);
        return actual;
    }

    // 查看（不推进读指针）
    size_t peek(char* dst, size_t n) const {
        size_t actual = std::min(n, readable());
        size_t first = std::min(actual, readable_contiguous());
        memcpy(dst, data_ + r_, first);
        if (first < actual) {
            memcpy(dst + first, data_, actual - first);
        }
        return actual;
    }

    void clear() { r_ = w_ = 0; }

    bool empty() const { return r_ == w_; }

    // 扩容到 2 倍
    void expand() {
        size_t new_size = size_ * 2;
        char* new_data = new char[new_size];
        size_t rd = readable();
        if (w_ >= r_) {
            memcpy(new_data, data_ + r_, w_ - r_);
        } else {
            size_t first = size_ - r_;
            memcpy(new_data, data_ + r_, first);
            memcpy(new_data + first, data_, w_);
        }
        delete[] data_;
        data_ = new_data;
        size_ = new_size;
        r_ = 0;
        w_ = rd;
    }

private:
    char*  data_;
    size_t size_;   // 2 的幂
    size_t r_;      // 读指针
    size_t w_;      // 写指针
};
```

## 9. ChainBuffer 设计与实现要点

```cpp
// chain_buffer.h —— 链式缓冲区（ngx_chain_t 风格）
#pragma once
#include <cstdint>
#include <cstring>
#include <sys/uio.h>
#include <vector>

struct BufNode {
    char*    pos;    // 读指针
    char*    last;   // 有效数据末尾
    char*    start;  // buffer 起始
    char*    end;    // buffer 末尾
    BufNode* next;

    size_t size() const { return end - start; }
    size_t readable() const { return last - pos; }
    size_t writable() const { return end - last; }
};

class ChainBuffer {
public:
    explicit ChainBuffer(size_t node_size = 4096) : node_size_(node_size) {}

    ~ChainBuffer() {
        BufNode* cur = head_;
        while (cur) { BufNode* next = cur->next; delete[] cur->start; delete cur; cur = next; }
    }

    // 追加数据（需要时分配新节点）
    void append(const char* data, size_t len) {
        size_t offset = 0;
        while (offset < len) {
            BufNode* tail = get_tail();
            if (!tail || tail->writable() == 0) {
                tail = alloc_node();
                if (!head_) head_ = tail;
                else get_tail_prev()->next = tail;
            }
            size_t n = std::min(len - offset, tail->writable());
            memcpy(tail->last, data + offset, n);
            tail->last += n;
            offset += n;
        }
    }

    // 转成 iovec 数组（供 writev）
    int to_iovec(struct iovec* iov, int max_cnt) const {
        int cnt = 0;
        for (BufNode* cur = head_; cur && cnt < max_cnt; cur = cur->next) {
            if (cur->readable() > 0) {
                iov[cnt].iov_base = cur->pos;
                iov[cnt].iov_len = cur->readable();
                cnt++;
            }
        }
        return cnt;
    }

    // 消费已发送的 n 字节（移动 pos，释放空节点）
    void consume(size_t n) {
        while (n > 0 && head_) {
            size_t rd = head_->readable();
            if (n >= rd) {
                n -= rd;
                BufNode* old = head_;
                head_ = head_->next;
                delete[] old->start;
                delete old;
            } else {
                head_->pos += n;
                n = 0;
            }
        }
    }

    size_t readable() const {
        size_t total = 0;
        for (BufNode* cur = head_; cur; cur = cur->next) total += cur->readable();
        return total;
    }

    bool empty() const { return head_ == nullptr; }

private:
    BufNode* alloc_node() {
        BufNode* node = new BufNode;
        node->start = new char[node_size_];
        node->pos = node->last = node->start;
        node->end = node->start + node_size_;
        node->next = nullptr;
        return node;
    }

    BufNode* get_tail() {
        BufNode* cur = head_;
        while (cur && cur->next) cur = cur->next;
        return cur;
    }
    BufNode* get_tail_prev() {
        BufNode* cur = head_;
        while (cur && cur->next && cur->next->next) cur = cur->next;
        return cur;
    }

    BufNode* head_ = nullptr;
    size_t node_size_;
};
```

**ChainBuffer vs RingBuffer 选型**：

| 维度 | RingBuffer | ChainBuffer |
|---|---|---|
| 内存连续性 | 连续（需大块内存） | 不连续（多小块） |
| 扩容 | 需拷贝（O(n)） | O(1) 挂新节点 |
| 发送 | 需拼连续内存或分两次 send | writev 一次发送 |
| 零拷贝 | 有限 | 好（mmap/sendfile 可直接挂 buf） |
| 实现复杂度 | 简单 | 中等 |
| 适用 | 接收缓冲区 | 发送缓冲区、大文件 |

**推荐**：接收用 RingBuffer（连续内存便于解析），发送用 ChainBuffer（writev 零拷贝）。

## 10. 与 Reactor send_cb/recv_cb 的集成

```text
Reactor 连接结构：
  struct Connection {
      int fd;
      RingBuffer  recv_buf;   // 接收缓冲区
      ChainBuffer send_buf;   // 发送缓冲区
      MessageCallback on_message;
  };

事件循环：
  EPOLLIN  → recv_cb(conn)
              → recv 到 recv_buf
              → 解析完整消息 → on_message(msg)
              → 高水位检查（暂停读）

  EPOLLOUT → send_cb(conn)
              → writev(send_buf)
              → consume 已发送数据
              → 发完则注销 EPOLLOUT

业务层 send(conn, msg)：
  → 序列化到 send_buf
  → 注册 EPOLLOUT
```

```cpp
// recv_cb 完整逻辑
void recv_cb(Connection* conn) {
    for (;;) {
        size_t space = conn->recv_buf.writable_contiguous();
        if (space == 0) {
            conn->recv_buf.expand();  // 扩容
            continue;
        }
        ssize_t n = ::recv(conn->fd, conn->recv_buf.write_ptr(), space, 0);
        if (n > 0) {
            conn->recv_buf.advance_write(n);
            // 解析消息（TLV）
            while (try_parse_message(conn)) {}
            // 高水位背压
            if (conn->recv_buf.readable() > HIGH_WATERMARK) {
                epoll_mod(conn->fd, EPOLLOUT);  // 暂停 EPOLLIN
            }
        } else if (n == 0) {
            close_conn(conn);
            return;
        } else {
            if (errno == EAGAIN) break;
            if (errno == EINTR) continue;
            close_conn(conn);
            return;
        }
    }
}

// send_cb 完整逻辑
void send_cb(Connection* conn) {
    struct iovec iov[1024];
    int cnt = conn->send_buf.to_iovec(iov, 1024);
    if (cnt == 0) {
        epoll_mod(conn->fd, EPOLLIN);  // 无数据，注销 EPOLLOUT
        return;
    }
    ssize_t n = ::writev(conn->fd, iov, cnt);
    if (n > 0) {
        conn->send_buf.consume(n);
        if (conn->send_buf.empty()) {
            epoll_mod(conn->fd, EPOLLIN);  // 发完，注销 EPOLLOUT
        }
    } else if (n < 0 && errno != EAGAIN && errno != EINTR) {
        close_conn(conn);
    }
}
```

## 11. 快速参考卡片

### 缓冲区选型表

| 场景 | 推荐 | 原因 |
|---|---|---|
| 接收缓冲区 | RingBuffer | 连续内存，便于协议解析，读指针顺序消费 |
| 发送缓冲区 | ChainBuffer | writev 分散写，零拷贝，扩容 O(1) |
| 协议头临时存储 | FixedBuffer | 栈上分配，固定大小，无堆开销 |
| 大文件发送 | ChainBuffer + mmap | mmap 内存直接挂 buf，sendfile/writev 零拷贝 |
| 单生产者单消费者 | RingBuffer（无锁） | w/r 指针分离，无需同步 |
| 多生产者多消费者 | 无锁 RingBuffer（CAS）或加锁 ChainBuffer | 需原子操作更新指针 |
| 高性能日志 | RingBuffer（单写者） | 日志线程单写，刷盘线程单读 |

### 常见坑

1. **ET 模式下没读到 EAGAIN**：边缘触发只通知一次，一次 recv 没读完，剩余数据永远等不到通知。必须循环 recv 直到 EAGAIN。
2. **RingBuffer 满了还写**：`writable()==0` 时 recv 仍调用，数据覆盖未读数据。检查 writable，满了则 expand 或暂停读（背压）。
3. **半包处理遗漏**：只解析一条消息就返回，缓冲区可能还有第二条（粘包）。解析必须循环/递归，直到没有完整消息。
4. **长度字段未做校验**：恶意客户端发 length=2GB，导致缓冲区疯狂扩容或 OOM。限制最大消息长度（如 16MB），超限断开连接。
5. **发送缓冲区内存泄漏**：writev 部分发送后只移动 pos 不释放空节点，节点累积。consume 时释放已读完的节点。
6. **EPOLLOUT 未及时注销**：发送缓冲区空了仍监听 EPOLLOUT，epoll 每次都返回可写（水平触发），CPU 100%。发完立即注销 EPOLLOUT。
7. **RingBuffer 大小不是 2 的幂**：用了 `& (size-1)` 但 size 不是 2 的幂，位与结果不等于取模，指针越界。构造时强制取整到 2 的幂。
8. **writev 的 iov 数量超限**：UIO_MAXIOV 通常 1024，chain 节点超过 1024 时 writev 返回 EINVAL。分批发送或限制节点数。
9. **recv 返回 0 当错误处理**：n==0 是对端正常关闭（FIN），不是错误。优雅关闭，发送缓冲区数据发完再关。
10. **缓冲区扩容时指针未重置**：expand 后 r_/w_ 要重新计算（r_=0, w_=readable()），否则指向已释放的旧内存。
11. **分隔符协议中消息体含分隔符**：未做转义，提前截断消息。用长度字段（TLV）替代分隔符，或对内容做转义。
12. **背压只暂停读不通知对端**：注销 EPOLLIN 后内核 recv buffer 满，TCP 窗口自动收缩，对端 send 会被限流——这是正确的背压，无需额外操作。
