## 1. 定时器使用场景

| 场景 | 说明 | 典型超时时间 |
|---|---|---|
| **连接超时** | TCP 连接建立超时、TLS 握手超时 | 3~10s |
| **读写超时** | 对端长时间不发数据，半开连接检测 | 30~120s |
| **心跳检测** | 定期发心跳包，超时未收到则判定对端宕机 | 5~30s |
| **请求超时** | RPC/HTTP 请求超时，避免线程永久挂起 | 1~30s |
| **定时任务** | 定期清理过期缓存、统计上报、日志切割 | 秒~小时级 |
| **重试退避** | 失败后延迟重试（指数退避） | 100ms~数分钟 |
| **会话过期** | 用户登录态、Token 过期 | 分钟~小时级 |
| **延迟队列** | 订单 30 分钟未支付自动取消 | 分钟级 |

**高性能服务器的核心需求**：数万连接每个都有超时定时器，定时器数量大（10w+），插入/删除/到期检查必须高效。

## 2. 三种数据结构对比【高频】

### 2.1 红黑树

- 有序平衡二叉树，key 为到期时间戳
- 最近到期节点 = 最左节点
- 插入/删除 O(logN)，取最近 O(1)（维护最左指针或直接取 min）

```text
红黑树定时器（key=到期时间ms）：
        [5000]
       /      \
   [3000]    [8000]
   /    \        \
[1000] [4000]  [12000]
最左节点 1000 = 最近到期
```

### 2.2 最小堆

- 完全二叉树，堆顶为最小到期时间
- 插入 O(logN)（上浮），取最近 O(1)，删除堆顶 O(logN)（下沉）
- **删除任意节点困难**：需先找到位置 O(N)，或用"惰性删除"（标记失效，到期时跳过）

```text
最小堆（数组表示，父≤子）：
        [1000]
       /      \
   [3000]    [2000]
   /    \
[5000] [4000]
堆顶 1000 = 最近到期
```

### 2.3 时间轮

- 一个环形数组，每个槽位挂一个定时器链表
- 指针按固定 tick 转动，指向的槽位中所有定时器到期
- 插入/删除 O(1)（直接定位槽位），到期检查 O(1)（只处理当前槽）

```text
时间轮（8 槽，tick=1s）：
  slot[0] → [timer A(1s)] → [timer B(9s, 圈数=1)]
  slot[1] → [timer C(2s)]
  slot[2] → null
  ...
  指针每秒前进一格，当前槽的定时器全部到期
```

### 2.4 复杂度对比总表

| 操作 | 红黑树 | 最小堆 | 时间轮 |
|---|---|---|---|
| 插入 | O(logN) | O(logN) | **O(1)** |
| 删除（已知节点） | O(logN) | O(N) 或 O(logN) 惰性 | **O(1)** |
| 取最近到期 | O(1) | O(1) | O(1) |
| 到期检查（批量） | O(logN) 逐个取 | O(logN) 逐个取 | **O(1)** 当前槽 |
| 空间 | O(N) | O(N) | O(N + 槽位数) |
| 精度 | 精确 | 精确 | 受 tick 限制（±tick） |
| 适用 | N 中等、需精确 | N 小、实现简单 | **N 极大、高并发** |

**选型结论**：
- 定时器数量 < 1w：最小堆足够（实现简单）
- 定时器数量 1w~10w：红黑树（精确、平衡）
- 定时器数量 10w+：时间轮（O(1) 操作，高并发首选）

## 3. 红黑树定时器

### 3.1 ngx_rbtree_t 用法

Nginx 定时器使用红黑树 `ngx_event_timer_rbtree`，key 为到期时间（毫秒）。

```c
// 事件结构体内嵌红黑树节点
typedef struct ngx_event_s {
    // ...
    ngx_rbtree_node_t  timer;  // 红黑树节点，key = 到期时间
    // ...
    ngx_event_handler_pt  handler;  // 超时回调
} ngx_event_t;

// 添加定时器：key = 当前时间 + 超时
ngx_event_t *ev;
ev->timer.key = ngx_current_msec + timeout_ms;
ngx_rbtree_insert(&ngx_event_timer_rbtree, &ev->timer);

// 删除定时器
ngx_rbtree_delete(&ngx_event_timer_rbtree, &ev->timer);

// 取最近到期（最左节点）
ngx_rbtree_node_t *node = ngx_rbtree_min(
    ngx_event_timer_rbtree.root, ngx_event_timer_rbtree.sentinel);
```

### 3.2 Nginx 定时器实现

```c
// 定时器到期处理（ngx_event_timer.c 简化）
void ngx_event_expire_timers(void) {
    ngx_event_t *ev;
    ngx_rbtree_node_t *node;
    for (;;) {
        node = ngx_rbtree_min(ngx_event_timer_rbtree.root, sentinel);
        if (node == sentinel) break;  // 无定时器
        ev = (ngx_event_t *) ((char *) node - offsetof(ngx_event_t, timer));
        if (node->key > ngx_current_msec) break;  // 未到期
        ngx_rbtree_delete(&ngx_event_timer_rbtree, &ev->timer);
        ev->timer_set = 0;
        ev->timedout = 1;
        ev->handler(ev);  // 执行超时回调
    }
}

// epoll_wait 超时时间 = 最近定时器到期时间 - 当前时间
ngx_msec_t ngx_event_find_timer(void) {
    ngx_rbtree_node_t *node = ngx_rbtree_min(root, sentinel);
    if (node == sentinel) return NGX_TIMER_INFINITE;
    ngx_msec_t timer = node->key - ngx_current_msec;
    return (ngx_msec_t) (timer > 0 ? timer : 0);
}
```

## 4. 最小堆定时器

### 4.1 priority_queue 实现

C++ STL `priority_queue` 默认是最大堆，需用 `greater` 变最小堆。

```cpp
struct Timer {
    uint64_t expire;       // 到期时间（ms）
    int      fd;           // 关联的连接 fd
    bool     canceled;     // 惰性删除标记
    std::function<void()> callback;
};

struct TimerCmp {
    bool operator()(const Timer* a, const Timer* b) const {
        return a->expire > b->expire;  // 小顶堆
    }
};

class HeapTimer {
    std::priority_queue<Timer*, std::vector<Timer*>, TimerCmp> heap_;
public:
    void add(Timer* t) { heap_.push(t); }

    void tick(uint64_t now) {
        while (!heap_.empty()) {
            Timer* t = heap_.top();
            if (t->canceled) {        // 惰性删除：已取消的跳过
                heap_.pop();
                delete t;
                continue;
            }
            if (t->expire > now) break;  // 未到期
            heap_.pop();
            t->callback();
            delete t;
        }
    }

    uint64_t next_timeout() {
        while (!heap_.empty() && heap_.top()->canceled) {
            Timer* t = heap_.top(); heap_.pop(); delete t;
        }
        return heap_.empty() ? UINT64_MAX : heap_.top()->expire;
    }
};
```

### 4.2 上浮与下沉

最小堆的核心操作（数组存储，索引从 1 开始，父 i/2，子 2i/2i+1）：

```text
插入（上浮 swim）：
  新元素放末尾 → 与父比较，比父小则交换 → 直到根或父更小

删除堆顶（下沉 sink）：
  末尾元素移到堆顶 → 与较小的子比较，比子大则交换 → 直到叶子或子更大
```

**惰性删除**：STL priority_queue 不支持删除任意元素，用 `canceled` 标记，到期检查时跳过并释放。缺点：已取消的定时器占堆空间，大量取消时堆膨胀。

## 5. 时间轮定时器【核心】

### 5.1 单轮时间轮

```text
单轮时间轮（tick=1s，8 槽）：
  槽位 = (当前槽 + 超时秒数) % 8
  问题：超时 > 8s 的定时器会被错误地提前触发

  解决：每个定时器记录"圈数"，指针转到该槽时圈数-1，圈数=0才到期
```

单轮+圈数方案简单，但超时范围大时圈数大，到期检查需遍历整个槽链表减圈数（O(槽内元素数)）。

### 5.2 多轮时间轮（层级时间轮）

类似时钟的秒针/分针/时针，多层时间轮：

```text
层级时间轮（Linux kernel timer wheel 思想）：
  第1层：256 槽，tick=1ms    → 覆盖 0~255ms
  第2层：64 槽，  tick=256ms → 覆盖 256ms~16s
  第3层：64 槽，  tick=16s   → 覆盖 16s~1024s
  第4层：64 槽，  tick=1024s → 覆盖 1024s~65536s

  高层定时器在"降级"时移到低层：
  第2层槽0的定时器到期时，重新计算到第1层的精确槽位
```

**降级（cascade）**：高层指针转到某槽时，该槽所有定时器重新计算并插入低层。这样插入 O(1)，到期检查均摊 O(1)。

### 5.3 Netty HashedWheelTimer 原理

Netty 的 `HashedWheelTimer` 是单轮时间轮的工业级实现：

```text
结构：
  - wheel: 数组，默认 512 槽
  - tickDuration: 默认 100ms
  - worker 线程：每 tickDuration 推进一格，处理当前槽
  - 每个槽是一个链表，节点包含 deadline（绝对到期时间）

添加定时器：
  1. 计算 deadline = now + timeout
  2. 计算需要多少 tick 才到期：ticks = (deadline - now) / tickDuration
  3. 槽位 = (当前槽 + ticks) % wheel.length
  4. 记录 remainingRounds = ticks / wheel.length（圈数）
  5. 插入对应槽的链表

到期处理：
  遍历当前槽链表，每个节点 remainingRounds--，为 0 则执行回调
```

**关键特性**：
- 后台单线程驱动，不依赖事件循环
- 精度 = tickDuration（默认 100ms，可配 1ms）
- 新添加的定时器至少等一个 tick 才会被检查
- O(1) 插入删除，适合海量定时任务

## 6. 定时器触发机制

### 6.1 epoll_wait 超时驱动

Reactor 模式下最常用：epoll_wait 的超时时间设为最近定时器到期时间。

```cpp
// 事件循环
while (running_) {
    uint64_t next = timer_->next_timeout();
    int timeout = (next == UINT64_MAX) ? -1 :
                  (next > now() ? (int)(next - now()) : 0);
    int n = epoll_wait(epfd_, events_, MAX_EVENTS, timeout);
    // 处理 IO 事件...
    timer_->tick(now());  // 处理到期定时器
}
```

**优点**：无需额外线程，与事件循环一体化
**缺点**：IO 事件密集时 epoll_wait 频繁返回，定时器检查也频繁（但 tick 只处理到期的，开销小）

### 6.2 单独线程驱动

一个独立线程循环检查定时器到期（Netty 模式）：

```cpp
void TimerThread::run() {
    while (running_) {
        uint64_t now = current_ms();
        wheel_->tick(now);
        std::this_thread::sleep_for(std::chrono::milliseconds(tick_));
    }
}
```

**优点**：与 IO 线程解耦，定时器精度不受 IO 影响
**缺点**：多一个线程，回调在定时器线程执行需注意线程安全（回调中投递到 IO 线程）

### 6.3 信号驱动

用 `timerfd_create` + `setitimer` 产生定时信号，信号处理函数中检查定时器。

```cpp
int tfd = timerfd_create(CLOCK_MONOTONIC, TFD_NONBLOCK | TFD_CLOEXEC);
struct itimerspec its = { .it_interval = {1, 0}, .it_value = {1, 0} };
timerfd_settime(tfd, 0, &its, nullptr);
// 将 tfd 加入 epoll，每次可读表示一个 tick 到了
```

**优点**：内核级定时器，精度高
**缺点**：信号处理函数中不能做复杂操作；timerfd 更优雅（可纳入 epoll）

## 7. 手撕实现：C++ 时间轮定时器【核心】

以下为单轮时间轮 + 圈数的完整 C++17 实现，tick 由外部事件循环驱动（epoll_wait 超时模式）。

```cpp
// timer_wheel.h
#pragma once
#include <cstdint>
#include <functional>
#include <list>
#include <vector>
#include <chrono>
#include <mutex>

class TimerWheel {
public:
    using Callback = std::function<void()>;
    using TimerId = uint64_t;

    explicit TimerWheel(uint32_t slot_count = 512, uint32_t tick_ms = 10)
        : slots_(slot_count), tick_ms_(tick_ms), current_slot_(0), next_id_(1) {}

    // 添加定时器，返回 ID（用于取消）
    TimerId add(uint32_t timeout_ms, Callback cb) {
        std::lock_guard<std::mutex> lock(mtx_);
        uint64_t ticks = timeout_ms / tick_ms_;
        if (ticks == 0) ticks = 1;  // 至少等一个 tick
        uint32_t slot = (current_slot_ + ticks) % slots_.size();
        uint32_t rounds = static_cast<uint32_t>(ticks / slots_.size());
        TimerId id = next_id_++;
        slots_[slot].push_back({id, rounds, std::move(cb)});
        return id;
    }

    // 取消定时器（惰性删除：标记失效）
    bool cancel(TimerId id) {
        std::lock_guard<std::mutex> lock(mtx_);
        canceled_.insert(id);
        return true;
    }

    // 推进一个 tick，处理当前槽的到期定时器
    void tick() {
        std::list<Entry> expired;
        {
            std::lock_guard<std::mutex> lock(mtx_);
            auto& slot = slots_[current_slot_];
            for (auto it = slot.begin(); it != slot.end(); ) {
                if (canceled_.erase(it->id)) {  // 已取消，移除
                    it = slot.erase(it);
                    continue;
                }
                if (it->rounds > 0) {
                    it->rounds--;
                    ++it;
                } else {
                    expired.push_back(std::move(*it));
                    it = slot.erase(it);
                }
            }
            current_slot_ = (current_slot_ + 1) % slots_.size();
        }
        // 锁外执行回调，避免死锁
        for (auto& e : expired) {
            e.callback();
        }
    }

    // 距离最近到期的毫秒数（用于 epoll_wait 超时）
    uint32_t next_timeout_ms() {
        std::lock_guard<std::mutex> lock(mtx_);
        for (uint32_t i = 0; i < slots_.size(); ++i) {
            uint32_t slot = (current_slot_ + i) % slots_.size();
            for (auto& e : slots_[slot]) {
                if (canceled_.count(e.id)) continue;
                // rounds=0 且在当前或后续槽
                uint64_t wait_ticks = i + e.rounds * slots_.size();
                return static_cast<uint32_t>(wait_ticks * tick_ms_);
            }
        }
        return UINT32_MAX;  // 无定时器
    }

private:
    struct Entry {
        TimerId  id;
        uint32_t rounds;     // 还需转几圈
        Callback callback;
    };

    std::vector<std::list<Entry>> slots_;
    uint32_t tick_ms_;
    uint32_t current_slot_;
    TimerId  next_id_;
    std::unordered_set<TimerId> canceled_;  // 惰性删除集合
    std::mutex mtx_;
};
```

**与 Reactor 集成**：

```cpp
// 事件循环中使用
TimerWheel wheel(512, 10);  // 512 槽，10ms tick

// 添加连接读超时
wheel.add(5000, [fd]() {
    close_connection(fd);  // 5 秒未读到数据则关闭
});

// 事件循环
while (running) {
    uint32_t timeout = wheel.next_timeout_ms();
    int n = epoll_wait(epfd, events, MAX_EVENTS,
                       timeout == UINT32_MAX ? -1 : (int)timeout);
    for (int i = 0; i < n; ++i) {
        // 处理 IO 事件...
    }
    wheel.tick();  // 推进定时器（epoll_wait 返回后调用）
}
```

**多线程安全说明**：
- `add`/`cancel`/`tick`/`next_timeout_ms` 都加了互斥锁
- 回调在锁外执行，避免回调中再次调用 `add`/`cancel` 导致死锁
- 若在多线程 Reactor 中使用，每个线程独立一个 TimerWheel（无共享），或用无锁队列投递 add 请求

**优化方向**：
1. `next_timeout_ms` 当前是 O(槽位数) 扫描，可维护一个"最近到期"变量在 add 时更新
2. `canceled_` 用 unordered_set，大量取消时内存增长，可在 tick 时清理
3. 超大规模用层级时间轮替代单轮+圈数

## 8. 与 Nginx/Redis/skynet 定时器方案对照

| 项目 | 数据结构 | 触发机制 | 特点 |
|---|---|---|---|
| **Nginx** | 红黑树（ngx_rbtree_t） | epoll_wait 超时 | key=到期ms，最左节点=最近到期，worker 独立定时器 |
| **Redis** | 无序链表 + 跳表（redisDb） | 时间事件循环（aeProcessEvents） | 普通过期 key 用惰性删除+定期抽样；时间事件用链表（因为数量少） |
| **skynet** | 最小堆（4 叉堆） | 线程循环 skynet_updatetime | 4 叉堆缓存友好，timer 线程更新时间，工作线程检查 |
| **Netty** | 单轮时间轮（HashedWheelTimer） | 独立 worker 线程 | 512 槽，100ms tick，O(1) 插入，工业级实现 |
| **Linux kernel** | 层级时间轮（hrtimer 红黑树 + timer wheel） | 时钟中断 | hrtimer 高精度用红黑树；普通 timer 用层级时间轮 |
| **Go** | 四叉堆（runtime.timer） | 调度器循环 | 每个 P 一个 timer 堆，调度时检查 |

**Nginx 红黑树 vs 时间轮**：
- Nginx 选择红黑树：worker 连接数通常几千~几万，红黑树 O(logN) 足够，且精度精确
- 时间轮精度受 tick 限制（±10ms），Nginx 对超时精度要求高（如 proxy_read_timeout）
- 时间轮适合海量短生命周期定时器（如心跳，10w+），Nginx 场景定时器数量相对可控

## 9. 快速参考卡片

### 三种方案复杂度对比表

| 操作 | 红黑树 | 最小堆 | 时间轮 |
|---|---|---|---|
| 插入 | O(logN) | O(logN) | O(1) |
| 删除（已知） | O(logN) | O(N) / 惰性 | O(1) |
| 取最近 | O(1) | O(1) | O(1) |
| 批量到期 | O(k logN) | O(k logN) | O(k) |
| 精度 | 精确 | 精确 | ±tick |
| 实现复杂度 | 中 | 低 | 中 |
| 推荐场景 | 中规模、精确 | 小规模 | 大规模、高并发 |

### 选型决策

```text
定时器数量 < 1万 → 最小堆（priority_queue + 惰性删除）
定时器数量 1万~10万 → 红黑树（std::set / ngx_rbtree_t）
定时器数量 > 10万 → 时间轮（HashedWheelTimer 风格）
需要毫秒级精确超时 → 红黑树
心跳/连接超时（可容忍 ±10ms）→ 时间轮
与 Reactor 事件循环集成 → epoll_wait 超时驱动
独立定时任务调度 → 单独线程驱动
```

### 常见坑

1. **定时器回调中执行阻塞操作**：回调在事件循环线程执行，阻塞会导致所有 IO 和定时器停滞。回调中只做非阻塞操作或投递任务到线程池。
2. **取消定时器后回调仍执行**：取消和到期之间存在竞态（已标记取消但 tick 已取走）。用版本号/ID 校验，回调中检查连接是否仍有效。
3. **epoll_wait 超时设为 0 导致忙等**：无定时器且无 IO 时 timeout=-1（无限等待），不要设 0。
4. **时间轮 tick 太大精度丢失**：tick=100ms 时，10ms 超时实际 0~100ms 后才触发。对精度敏感的场景 tick 设 1~10ms。
5. **最小堆惰性删除导致内存泄漏**：大量 add+cancel 后堆中积累失效节点。定期清理（每次 tick 时 pop 掉堆顶的 canceled 节点）。
6. **定时器溢出**：32 位毫秒时间戳 49 天后溢出。用 uint64_t 存储到期时间。
7. **系统时间跳变影响定时器**：NTP 校时导致时间回拨，基于绝对时间的定时器全部异常。用 CLOCK_MONOTONIC（单调时钟）而非 CLOCK_REALTIME。
8. **回调中 add 新定时器导致迭代器失效**：tick 遍历槽链表时，回调中 add 到同一槽可能修改链表。先把到期节点移出再执行回调（本文实现已处理）。
9. **多线程共享一个定时器未加锁**：add/cancel/tick 并发导致链表损坏。每线程独立定时器，或加锁/无锁队列。
10. **时间轮圈数计算错误**：ticks < slot_count 时 rounds=0，但槽位计算用 `(current + ticks) % count`，注意 ticks=0 时应至少等 1 tick。
