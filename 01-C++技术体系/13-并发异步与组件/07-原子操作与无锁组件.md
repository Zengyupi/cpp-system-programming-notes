## 1. 概述

### 1.1 锁的问题

| 问题 | 一句话 |
|---|---|
| 竞争自旋/上下文切换 | 抢不到锁的线程在 futex 上休眠唤醒，来回切换微秒级 |
| 持锁者被切走 | 其他核空转等锁（convoy 护送效应），吞吐坍塌 |
| 优先级反转 | 低优先级持锁，高优先级被反压（Mars Pathfinder 事故） |

### 1.2 前进性保证分级【高频】

| 级别 | 定义 | 示例 |
|---|---|---|
| blocking | 持锁线程被挂起时，其他线程可能永远无法前进 | mutex 临界区 |
| lock-free | 系统整体**至少一个**线程有限步内前进（允许个别饿） | CAS 循环栈、rte_ring |
| wait-free | **每个**线程都有限步内前进，无饥饿 | fetch_add 计数器 |

## 2. CPU 缓存与 MESI【高频】

### 2.1 缓存层次

```text
 CPU0[L1d 32K|L2 256K]──┐                  ┌──CPU1[...]
                        ├──── L3 共享数MB ──┤
                        └─────── 内存 ──────┘
```

| 层级 | 典型延迟 | 说明 |
|---|---|---|
| L1 | ~1ns | 每核私有 |
| L2 | ~4ns | 每核私有 |
| L3 | ~40ns | 全核共享 |
| 内存 | ~100ns | 跨 NUMA 更久 |
| 跨核一致性传输 | ~几十 ns | MESI 消息往返 |

### 2.2 缓存行与伪共享

缓存以**缓存行（x86/ARM 通用 64 字节）**为单位加载与失效。两个线程频繁写**同一缓存行上的相邻变量**，每次写都让对方核该行失效，缓存行在核间乒乓——伪共享，性能掉数倍。

```cpp
// 反例: 相邻 atomic 成员大概率同落一个 64B 缓存行, 各线程写各的也乒乓
// 正解: 按缓存行对齐, 每计数器独占一行
// (C++17 亦可用 alignas(std::hardware_destructive_interference_size))
struct alignas(64) PaddedCounter { std::atomic<uint64_t> v; };
PaddedCounter counters[8];
```

| 项 | 说明 |
|---|---|
| 定位 | perf c2c / cache-misses 采样；吞吐远低于理论值即怀疑 |
| 本质 | "变量不相干"≠"缓存行不相干"，硬件同步粒度是行 |

### 2.3 MESI 四状态【必背】

| 状态 | 全名 | 含义 | 其他核有副本 |
|---|---|---|---|
| M | Modified | 脏，与内存不一致，**仅本核持有** | 无 |
| E | Exclusive | 干净，**仅本核持有** | 无 |
| S | Shared | 干净，多核可能共享 | 可能有 |
| I | Invalid | 本核副本失效 | —— |

关键转换：

| 事件 | 转换 | 总线动作 |
|---|---|---|
| 本核读命中 S/E | 保持不变 | 无 |
| 本核读 miss（I 行） | 无他核副本 → **E**；有 → S（M 持有者先写回） | BusRd |
| 本核写 E 行 | → M（独占，无需总线事务） | 无 |
| 本核写 S 行 | → M，广播 Invalidate，他核 → I | BusRdX |
| 他核读我的 M 行 | 我写回内存，双方 → S | writeback + BusRd |
| 他核写（我持 M/E/S） | 我 → I | 收 Invalidate |

可见性来源一句话：写方通过 Invalidate 消息让他人副本失效，他人再读必然 miss 而取到新值——可见性由**缓存一致性协议**保证，与语言层内存序（管重排）是两件事。store buffer / invalidate queue 一句话：核先把写放进 store buffer 就继续跑、失效方也先缓存失效消息稍后处理——性能优化的代价是**读写可能重排**，所以需要内存屏障强制刷出/处理。

## 3. 原子操作与 CAS

### 3.1 CAS 语义与循环范式

atomic 工具速查（load/store、fetch_add/sub、compare_exchange、fence）见 `../04-并发与多线程编程/01-并发编程与线程同步.md`。

```cpp
// 语义: if (expected == *this) { *this = desired; return true; }
//       else { expected = *this; return false; }  ← 失败时回填当前值
bool compare_exchange_strong(T& expected, T desired, ...) noexcept;
// weak 允许"伪失败"(值相等也返回 false): 更快, 必须放循环里;
// strong 判定确定, 适合不在循环内的场景

// 范式1: fetch_add 天然 wait-free (计数器)
std::atomic<uint64_t> g_count{0};
g_count.fetch_add(1, std::memory_order_relaxed);   // 只需原子性

// 范式2: 无锁栈 push (经典 CAS 循环, lock-free)
struct Node { Node* next; int val; };
std::atomic<Node*> head{nullptr};
void push(int v) {
    Node* n = new Node{nullptr, v};
    Node* old = head.load(std::memory_order_relaxed);
    do {
        n->next = old;                          // 先接好旧链
    } while (!head.compare_exchange_weak(old, n,   // 失败则 old 已被回填
             std::memory_order_release, std::memory_order_relaxed));
}
```

### 3.2 ABA 问题【高频】

场景：无锁栈 pop 用 CAS 比较 head——线程 1 读到 head=A；线程 2 弹出 A、弹出 B、又把 **A 压回**（释放后新分配复用同地址）；线程 1 CAS 见 head 仍是 A，判定"没变"成功摘链——但 A 的 next 早已指向别处，链错乱。

| 解法 | 思路 | 一句话 |
|---|---|---|
| tagged pointer | 指针+版本号打包，每次修改版本+1 | 最常用，需双宽 CAS |
| 双长度 CAS | 硬件一次原子比较两处（x86 CMPXCHG16B） | 平台相关 |
| hazard pointer | 每线程声明"正在读的节点"，回收方延迟释放 | 读多写少最优 |
| epoch/RCU | 分代回收，宽限期内不释放旧节点 | 内核 RCU 思路 |

### 3.3 六种内存序工程选择速查

| 内存序 | 语义 | 工程场景 |
|---|---|---|
| relaxed | 只保证单变量原子，无顺序约束 | 统计计数、发号 |
| consume | 依赖序（实践不推荐） | 别用 |
| acquire | 本读之后的访问不会重排到它前面 | 读端：读标志→读数据 |
| release | 本写之前的访问不会重排到它后面 | 写端：写数据→写标志 |
| acq_rel | RMW 兼具两者 | fetch_sub 释放引用 |
| seq_cst | 全局全序，最贵 | 默认；多变量需全局一致序 |

## 4. 手撕 shared_ptr【核心】

### 4.1 设计

```text
MySharedPtr<T>                          MyWeakPtr<T>
 +----------------+                     +----------------+
 | T* ptr         |   +------------+    | T* ptr (仅观察) |
 | ctrl ----------+-->| ControlBlock|<---+ ctrl ----------+  (不动 strong)
 +----------------+   |  T* ptr     |    +----------------+
                      |  strong     |     strong==0 → 析构对象
                      |  weak       |     weak==0   → 释放控制块
                      |  deleter    |
                      +------------+
```

| 部件 | 说明 |
|---|---|
| 对象指针 | 每份句柄直接持有，解引用零间接 |
| 控制块 | 堆上一次分配：强/弱两个原子计数 + 删除器 |
| 强计数 | MySharedPtr 拷贝 +1、析构 -1；归零析构对象 |
| 弱计数 | 初值 1 是"强引用方"对控制块的占用；MyWeakPtr 各 +1；归零释放控制块 |

### 4.2 引用计数的原子要点【高频】

| 操作 | 内存序 | 为什么 |
|---|---|---|
| 拷贝 fetch_add | **relaxed** | 只需原子自增，新持有者不依赖他人此前的写 |
| 析构 fetch_sub | **acq_rel** | 见下 |

**为什么 dec 必须 acquire**：每个持有者的 fetch_sub 带 release（对对象的写在减计数之前）；最后减到 0 的线程带 acquire，与之前所有 release 构成 happens-before 链——析构对象时必然看到全部持有者的写。若用 relaxed，可能读到未完成的写入，析构即 UB。

### 4.3 完整代码（C++11）

```cpp
// my_shared_ptr.h  手撕 shared_ptr 核心路径
#pragma once
#include <atomic>
#include <utility>

template <class T>
struct ControlBlock {
    T* ptr;
    void (*deleter)(T*);
    std::atomic<long> strong;   // 强引用计数
    std::atomic<long> weak;     // 初值 1: 强引用方对控制块的占用

    explicit ControlBlock(T* p, void (*d)(T*) = nullptr)
        : ptr(p), deleter(d ? d : [](T* q) { delete q; }),
          strong(1), weak(1) {}

    void release_strong() {
        if (strong.fetch_sub(1, std::memory_order_acq_rel) == 1) {
            deleter(ptr);        // 最后一份强引用: 只析构对象一次
            release_weak();      // 归还强引用方占用的 weak 份额
        }
    }
    void release_weak() {
        if (weak.fetch_sub(1, std::memory_order_acq_rel) == 1)
            delete this;         // 无人观察: 释放控制块
    }
};

template <class T>
class MySharedPtr {
public:
    MySharedPtr() = default;
    explicit MySharedPtr(T* p)
        : ptr_(p), ctrl_(p ? new ControlBlock<T>(p) : nullptr) {}

    MySharedPtr(const MySharedPtr& o) : ptr_(o.ptr_), ctrl_(o.ctrl_) {
        if (ctrl_) ctrl_->strong.fetch_add(1, std::memory_order_relaxed);
    }
    MySharedPtr(MySharedPtr&& o) noexcept : ptr_(o.ptr_), ctrl_(o.ctrl_) {
        o.ptr_ = nullptr; o.ctrl_ = nullptr;        // 移动: 计数不动
    }
    MySharedPtr& operator=(MySharedPtr o) noexcept { // 传值统一拷贝/移动
        swap(o); return *this;                      // o 析构带走旧引用
    }
    ~MySharedPtr() { if (ctrl_) ctrl_->release_strong(); }

    T& operator*()  const { return *ptr_; }
    T* operator->() const { return ptr_; }
    T* get()        const { return ptr_; }
    explicit operator bool() const { return ptr_ != nullptr; }
    long use_count() const {
        return ctrl_ ? ctrl_->strong.load(std::memory_order_relaxed) : 0;
    }
    void swap(MySharedPtr& o) noexcept {
        std::swap(ptr_, o.ptr_); std::swap(ctrl_, o.ctrl_);
    }
private:
    template <class U> friend class MyWeakPtr;
    T* ptr_ = nullptr;
    ControlBlock<T>* ctrl_ = nullptr;
};

template <class T>
class MyWeakPtr {
public:
    MyWeakPtr() = default;
    MyWeakPtr(const MySharedPtr<T>& s) : ptr_(s.ptr_), ctrl_(s.ctrl_) {
        if (ctrl_) ctrl_->weak.fetch_add(1, std::memory_order_relaxed);
    }
    MyWeakPtr(const MyWeakPtr& o) : ptr_(o.ptr_), ctrl_(o.ctrl_) {
        if (ctrl_) ctrl_->weak.fetch_add(1, std::memory_order_relaxed);
    }
    ~MyWeakPtr() { if (ctrl_) ctrl_->release_weak(); }

    MySharedPtr<T> lock() const {        // 强引用仍存活则升级
        MySharedPtr<T> res;
        if (ctrl_) {
            long c = ctrl_->strong.load(std::memory_order_relaxed);
            while (c != 0 && !ctrl_->strong.compare_exchange_weak(
                       c, c + 1, std::memory_order_acquire,   // 升级成功需 acquire
                       std::memory_order_relaxed)) {}          // weak 伪失败重试
            if (c != 0) { res.ptr_ = ptr_; res.ctrl_ = ctrl_; }
        }
        return res;                      // c==0: 对象已析构, 返回空
    }
private:
    T* ptr_ = nullptr;
    ControlBlock<T>* ctrl_ = nullptr;
};
```

要点：移动不碰计数；赋值用"传值+swap"天然防自赋值；析构 fetch_sub(acq_rel) 归零才析构对象再释放控制块；lock() 用 CAS 循环把 strong 从 c>0 抬到 c+1，防"检查后升级前"对象已死，升级成功带 acquire 以同步前持有者的写。enable_shared_from_this 思路一句话：对象内嵌 MyWeakPtr，`shared_from_this()` 即其 `lock()`。

### 4.4 与 std::shared_ptr 的差距清单

| 特性 | std | 本实现 |
|---|---|---|
| make_shared | 对象与控制块一次分配（省一次 malloc；代价：weak 存活则对象内存不还） | 不支持 |
| 别名构造 / 原子 free 函数 | shared_ptr<U>(sp, U*) / atomic_load 系列 | 不支持 |
| 删除器类型擦除 | 完整（支持捕获状态） | 简化函数指针 |

## 5. volatile 与内存屏障【高频】

### 5.1 volatile 三不管

| volatile 不管 | 说明 |
|---|---|
| 不管原子性 | volatile int64_t 在 32 位平台仍可撕裂 |
| 不管顺序性 | 不插屏障，编译器/CPU 仍可重排周围访问 |
| 不管跨核即时可见 | 可见性由 MESI 保证；它不强制刷 store buffer |
| 它管什么 | **阻止编译器**优化掉/合并读写——每次访问都真实发生 |

正确用途：MMIO 寄存器（读有副作用必须真读）、signal 标志（`volatile sig_atomic_t`）。错误用途：线程间同步（应改 atomic/mutex）。

### 5.2 内存屏障分类

| 屏障 | x86 指令 | 内核宏 | C++ 对应语素 |
|---|---|---|---|
| 编译器屏障 | （无指令） | `asm volatile("" ::: "memory")` | atomic 访问隐含 |
| 读屏障 | lfence | smp_rmb() | load(acquire) 效果 |
| 写屏障 | sfence | smp_wmb() | store(release) 效果 |
| 全屏障 | mfence | smp_mb() | seq_cst / fence(seq_cst) |

对应关系：`store(release)` ≈ 写数据 + 写屏障 + 发布；`load(acquire)` ≈ 读发布 + 读屏障 + 读数据。x86 是 TSO 强序，acquire/release 基本免费；ARM 上真实生成屏障指令。

### 5.3 DCLP 单例为什么需要屏障

```cpp
// 错误版: 双检查 + 锁, 但 p 是普通指针
static Singleton* instance() {
    if (p == nullptr) {                    // 第一次检查(无锁)
        std::lock_guard<std::mutex> g(mtx);
        if (p == nullptr)
            p = new Singleton();  // 可分解为 1)分配 2)构造 3)赋值p
                                 // 重排成 1)→3)→2) 后:
    }                              // 其他线程第一次检查见 p 非空,
    return p;                      // 直接使用【未构造完】的对象!
}
// C++11 正解: magic static, 编译器保证初始化线程安全
static Singleton& instance() {
    static Singleton inst;
    return inst;
}
// 手写版则需 atomic<Singleton*>: 外层 load(acquire),
// 内层构造完成后 store(release) 发布; 详见 ../01-C++语言核心/08-设计模式与典型实现.md
```

## 6. DPDK rte_ring 源码要点

### 6.1 结构

```c
struct rte_ring {
    char name[32];
    uint32_t size;              // 容量, 恒为 2 的幂
    uint32_t mask;              // size-1: idx & mask 代替取模
    uint32_t prod_head, prod_tail;  // 生产者抢占/完成索引, 缓存行对齐
    uint32_t cons_head, cons_tail;  // 消费者同构
    void *ring[] __rte_cache_aligned;
};
// 空判: prod.tail == cons.tail;  满判: prod.tail - cons.tail == size
```

| 设计点 | 说明 |
|---|---|
| head/tail 分离 | head 抢到位，tail 才是"已写完"；消费者只看 tail |
| 2^n + mask | 位运算取模，免除法 |
| 缓存行对齐 | prod/cons 索引各占一行，防伪共享 |
| 槽存 void* | 只搬指针不搬数据，配合 mbuf 池零拷贝 |

### 6.2 单生产者入队

读 head=H → CAS(prod.head: H→H+n) 抢占槽位 → 写 ring[(H+i)&mask] → 写屏障后 prod.tail=H+n 发布给消费者。

### 6.3 多生产者入队两阶段【高频】

```text
初始: prod.head=prod.tail=H; A、B 各入队 2 个
阶段1(抢位): A CAS 成功 head: H→H+2 (得槽 H,H+1)
             B 读新 head 再 CAS: H+2→H+4 (得槽 H+2,H+3); 失败者重读重试
阶段2(填数): A 写 ring[H],ring[H+1]; B 写 ring[H+2],ring[H+3]
             —— 各写各槽, 乱序完成也安全
阶段3(推进): tail 必须按抢位顺序前进!
             B 先写完, 但 prod.tail != 自己起点 H+2 → 自旋等待
             A 写完, prod.tail == 自己起点 H → 写屏障, tail=H+2
             B 等待解除 → 写屏障, tail=H+4
             消费者只消费下标 < prod.tail 的槽 → 读不到未完成的写入
```

| 问题 | 答案 |
|---|---|
| 为什么两阶段 | 槽位写入无序（各核速度不同），tail 推进必须有序——等前驱就是给写入排序 |
| 第二次更新为何不用 CAS | 等待条件成立时只有"rightful 后继"会写 tail，顺序已由自旋保证 |
| 退化点 | 前驱被抢占时，后继与消费者都自旋等它——MP 模式固有代价 |

四种变体：SPSC 最快无 CAS（线程间管道）；MPSC 快（多核汇聚单线程，如日志）；SPMC（任务分发）；MPMC 最慢两阶段全开（通用工作队列）。

## 7. 手撕 MPSCQueue【核心】

### 7.1 模型与实现

```text
 producer1 ─┐
 producer2 ─┼─fetch_add 领号─→ [slot0|slot1|...|slotN-1] ─→ 唯一消费者顺序 pop
 producer3 ─┘                  (写完置 published 标志)
```

| 设计 | 说明 |
|---|---|
| 分配 | `tail.fetch_add(1)` 原子领号，各写各的槽互不冲突 |
| 发布 | 写完槽 `published=true`（release），消费者 acquire 见标志才取数 |
| 有界满载 | 领号超前 head 太多则自旋等消费者放位（消费者独立推进，不死锁） |

```cpp
// mpsc_queue.h  多生产者单消费者环形队列 (C++11)
#pragma once
#include <array>
#include <atomic>
#include <cstddef>
#include <thread>

template <typename T, size_t N>          // N 必须是 2 的幂
class MPSCQueue {
    static_assert((N & (N - 1)) == 0, "N must be power of 2");
    static constexpr size_t kMask = N - 1;
public:
    MPSCQueue() {
        for (auto& p : published_) p.store(false, std::memory_order_relaxed);
    }
    MPSCQueue(const MPSCQueue&) = delete;
    MPSCQueue& operator=(const MPSCQueue&) = delete;

    bool push(const T& v) {              // 生产者: 多线程并发
        size_t idx = tail_.fetch_add(1, std::memory_order_relaxed); // 领号
        while (idx - head_.load(std::memory_order_acquire) >= N)
            std::this_thread::yield();   // 满载等放位(见坑表)
        slots_[idx & kMask] = v;         // 写自己的槽
        published_[idx & kMask].store(true, std::memory_order_release); // 发布
        return true;
    }

    bool pop(T& out) {                   // 消费者: 仅单线程调用!
        size_t idx = head_.load(std::memory_order_relaxed);
        if (!published_[idx & kMask].load(std::memory_order_acquire))
            return false;                // 空或前一个生产者尚未写完
        out = slots_[idx & kMask];
        published_[idx & kMask].store(false, std::memory_order_relaxed);
        head_.store(idx + 1, std::memory_order_release);  // 放位给生产者
        return true;
    }
private:
    std::array<T, N> slots_;
    std::array<std::atomic<bool>, N> published_;
    alignas(64) std::atomic<size_t> tail_;   // 生产者领号(多写)
    alignas(64) std::atomic<size_t> head_;   // 消费者游标(单写)
};
```

| 位置 | 内存序 | 理由 |
|---|---|---|
| fetch_add 领号 | relaxed | 只求唯一编号 |
| 置 published | release | 槽内数据先于标志可见 |
| pop 读标志 | acquire | 与 release 配对 |
| head 推进 | release | 等位生产者看到新边界后才复用槽 |

适用场景：日志落盘队列（多业务线程 push、单 flush 线程 pop）、采样上报、DPDK 多核收包汇聚到协议栈核。

### 7.2 与 MPMC（rte_ring）取舍

| 维度 | MPSC | MPMC |
|---|---|---|
| 生产端 | fetch_add 领号，几乎无竞争 | 两阶段 CAS，高竞争自旋 |
| 消费端 | 单线程免同步 | 多消费者 CAS 抢占 |
| 限制 | 消费者必须唯一 | 任意 |
| 选择 | 能单线程消费就 MPSC | 确需多消费者才 MPMC |

## 8. 网络缓冲区设计【核心】

### 8.1 三种方案对比

| 方案 | 结构 | 优 | 劣/满了怎么办 |
|---|---|---|---|
| ① RingBuffer 定长环形 | 定长数组+读写索引 | 空间恒定、实现简单 | 定长：扩容(变长化)/覆盖旧数据/阻塞 三策略 |
| ② fixed buffer 定长数组 | 一次性分配裸数组 | 最简单、零元数据 | 上限固定：丢弃/报错 |
| ③ ChainBuffer 链式块 | 多块 malloc 链成链表 | 动态增长、块可回收 | 指针跳转管理复杂：追加新块 |
| 配合技巧 | ChainBuffer + writev | 多块一次系统调用聚集发送（免拼接拷贝） | —— |

### 8.2 手撕 Buffer（muduo 风格完整代码）

muduo 方案：`vector<char>` 连续内存 + 读写双索引，**头部预留 prepend 空间**，已读空间可被写复用。

```text
+-------------------+------------------+------------------+
| prependable bytes |  readable bytes  |  writable bytes  |
+-------------------+------------------+------------------+
0 <=   readerIndex    <=    writerIndex   <=    size()
   (存长度头)      peek()从这里读        beginWrite()从这里写
```

```cpp
// buffer.h  muduo 风格网络缓冲区 (C++11)
#pragma once
#include <sys/uio.h>
#include <unistd.h>
#include <algorithm>
#include <cassert>
#include <cerrno>
#include <cstring>
#include <string>
#include <vector>

class Buffer {
public:
    static constexpr size_t kCheapPrepend = 8;     // 预留: 前置长度头
    static constexpr size_t kInitialSize = 1024;
    static constexpr size_t kExtraBufSize = 65536; // readFd 栈上备用块

    explicit Buffer(size_t init = kInitialSize)
        : buffer_(kCheapPrepend + init),
          readerIndex_(kCheapPrepend), writerIndex_(kCheapPrepend) {}

    size_t readableBytes()    const { return writerIndex_ - readerIndex_; }
    size_t writableBytes()    const { return buffer_.size() - writerIndex_; }
    size_t prependableBytes() const { return readerIndex_; }
    const char* peek()       const { return begin() + readerIndex_; }

    // ---------- 读侧 ----------
    void retrieve(size_t n) {                 // 读指针前移 n
        if (n < readableBytes()) readerIndex_ += n;
        else retrieveAll();
    }
    void retrieveAll() { readerIndex_ = writerIndex_ = kCheapPrepend; }
    std::string retrieveAsString(size_t n) {  // 取出并消费
        std::string s(peek(), n);
        retrieve(n);
        return s;
    }

    // ---------- 写侧 ----------
    void append(const char* data, size_t len) {
        ensureWritable(len);
        std::copy(data, data + len, beginWrite());
        writerIndex_ += len;
    }
    void ensureWritable(size_t len) {
        if (writableBytes() < len) makeSpace(len);
    }
    char* beginWrite() { return begin() + writerIndex_; }

    void prepend(const void* data, size_t len) {  // 前置写入: 长度头
        assert(len <= prependableBytes());
        readerIndex_ -= len;
        const char* d = static_cast<const char*>(data);
        std::copy(d, d + len, begin() + readerIndex_);
    }

    // ---------- 核心: readv 一次读全 ----------
    ssize_t readFd(int fd, int* savedErrno) {
        char extrabuf[kExtraBufSize];              // 64KB 栈上备用块
        struct iovec vec[2];
        const size_t writable = writableBytes();
        vec[0].iov_base = beginWrite();            // 目的地1: 缓冲区可写区
        vec[0].iov_len  = writable;
        vec[1].iov_base = extrabuf;                // 目的地2: 栈上备用
        vec[1].iov_len  = sizeof(extrabuf);
        // 可写区比备用块还大时, 一个 iov 就够
        const int iovcnt = (writable < sizeof(extrabuf)) ? 2 : 1;
        const ssize_t n = ::readv(fd, vec, iovcnt);
        if (n < 0) {
            *savedErrno = errno;
        } else if (static_cast<size_t>(n) <= writable) {
            writerIndex_ += n;                     // 数据全落缓冲区
        } else {
            writerIndex_ = buffer_.size();         // 缓冲区写满
            append(extrabuf, n - writable);        // 溢出部分追加(触发扩容)
        }
        return n;
    }

    // 可读数据零拷贝发送: [peek, peek+readable) 直接交给 write
    ssize_t sendFd(int fd) {
        ssize_t n = ::write(fd, peek(), readableBytes());
        if (n > 0) retrieve(n);                    // 发多少收多少
        return n;                                  // <0 由上层看 EAGAIN
    }
private:
    char* begin() { return buffer_.data(); }
    const char* begin() const { return buffer_.data(); }

    void makeSpace(size_t len) {
        // 前部空闲+可写足够 → 平移数据到头部, 不扩容
        if (prependableBytes() + writableBytes() < len + kCheapPrepend) {
            buffer_.resize(writerIndex_ + len);    // 只能整体扩容
        } else {
            const size_t readable = readableBytes();
            std::copy(begin() + readerIndex_, begin() + writerIndex_,
                      begin() + kCheapPrepend);
            readerIndex_ = kCheapPrepend;
            writerIndex_ = readerIndex_ + readable;
        }
    }

    std::vector<char> buffer_;
    size_t readerIndex_;
    size_t writerIndex_;
};
```

### 8.3 设计要点

| 要点 | 说明 |
|---|---|
| readv + 栈上 64KB 备用块 | 一次系统调用把"装不下的部分"也读走：够则直接落缓冲区，不够先落栈上块再 append（此时才扩容）。避免"先扩容再读"的浪费——多数时候包不大，栈上块用完即弃 |
| prepend 意义 | 长度前导协议（4B len + body）：先 append body 再 `prepend(&len,4)`，免为加头整体 memmove |
| 平移优先于扩容 | makeSpace 先回收已读区（O(readable) 平移），不够才 resize |
| 与 02-Reactor 的衔接 | EPOLLIN → readFd 一次收全 → 业务 append 响应 → sendFd 直发；写不完注册 EPOLLOUT 续发——即 Reactor 的 OutputBuffer |

## 9. 定时器方案【高频】

### 9.1 场景与结构对比

场景：心跳保活（每 30s 查活跃度）、请求超时、重传 RTO、延迟任务（定时开抢/缓存过期）。

| 方案 | 插入 | 取最近 | 删除任意 | 用户 |
|---|---|---|---|---|
| 红黑树 | O(log n) | O(1) 最左 | O(log n) | 内核高精度、nginx |
| 最小堆 | O(log n) | O(1) 堆顶 | 难（需辅助索引） | muduo、libevent |
| 时间轮 | **O(1)** 入槽 | O(1) | O(1) | skynet、Kafka、内核低精度 |
| 层级时间轮 | O(1)~O(层) | O(1) | O(1)，覆盖大跨度 | Kafka(20ms×512×3 层到天级) |

触发机制：①`nextTimeout()` 喂给 epoll_wait，返回后 `tick()`（零额外线程，推荐）；②timerfd 并入 epoll 统一事件源；③独立线程 `sleep(next)` 循环（多线程多锁，最次）。

### 9.2 手撕最小堆定时器（完整代码）

```cpp
// timer_queue.h  最小堆定时器 (C++11)
#pragma once
#include <chrono>
#include <cstdint>
#include <functional>
#include <queue>
#include <unordered_set>
#include <utility>
#include <vector>

using TimerCallback = std::function<void()>;
using Timestamp = uint64_t;                       // 毫秒

struct Timer {
    uint64_t id;                                  // 全局自增, 取消去重
    Timestamp when;                               // 绝对到期时刻
    uint64_t interval;                            // 周期, 0=一次性
    TimerCallback cb;
};

class TimerQueue {
public:
    static Timestamp nowMs() {
        return std::chrono::duration_cast<std::chrono::milliseconds>(
            std::chrono::steady_clock::now().time_since_epoch()).count();
    }
    uint64_t addTimer(TimerCallback cb, uint64_t delay_ms,
                      uint64_t interval = 0) {
        Timer t{++next_id_, nowMs() + delay_ms, interval, std::move(cb)};
        heap_.push(t);
        return t.id;
    }
    void cancel(uint64_t id) { cancelled_.insert(id); }   // 惰性删除

    int nextTimeout() const {          // 下一轮 epoll_wait 的 timeout(-1=无)
        if (heap_.empty()) return -1;
        Timestamp now = nowMs();
        return heap_.top().when > now
             ? static_cast<int>(heap_.top().when - now) : 0;
    }
    void tick() {                      // 每轮事件循环调用
        Timestamp now = nowMs();
        while (!heap_.empty() && heap_.top().when <= now) {
            Timer t = heap_.top();
            heap_.pop();
            if (cancelled_.count(t.id)) { cancelled_.erase(t.id); continue; }
            if (t.cb) t.cb();                          // 执行回调
            if (t.interval > 0) {                      // 周期任务重排
                t.when = now + t.interval;
                heap_.push(t);
            }
        }
    }
private:
    struct HeapGreater {               // priority_queue 默认大根堆→反转
        bool operator()(const Timer& a, const Timer& b) const {
            return a.when > b.when;                    // when 小者在堆顶
        }
    };
    std::priority_queue<Timer, std::vector<Timer>, HeapGreater> heap_;
    std::unordered_set<uint64_t> cancelled_;           // 取消集合
    uint64_t next_id_ = 0;
};
```

| 设计点 | 说明 |
|---|---|
| 惰性删除 | 堆删任意 O(n)，改为打标，到期弹出时跳过 |
| nextTimeout | 最近到期翻译成 epoll_wait 超时，定时与 IO 共用一个循环 |
| 周期重排 | 执行后 `when=now+interval`，避免累积漂移 |

### 9.3 时间轮原理

```text
单层时间轮(槽数 N=8, 每 tick 走一格):
   slot:  0    1    2    3    4    5    6    7
       +----+----+----+----+----+----+----+----+
       |    | T1 |    |    |    |    |    |    |  ← 指针 current=1
       +----+----+----+----+----+----+----+----+
              │ 槽内链表, 节点带轮数 round
              T1{round=2, cb}: 指针第 3 次转到此槽才触发

插入: slot = (current + delay) % N
      round = (delay - 1) / N     ← 注意减一(见自检)
指针每 tick: current=(current+1)%N, 处理新指向槽:
      round==0 → 触发并摘除; 否则 round-- 留在槽内
```

槽计算自检【易错】：设指针在 current，`slot=(current+delay)%N`，指针 1..N tick 后到达某槽；若 `delay%N==0`，slot 恰为 current，需转满一圈（N tick）才"到达"。故 round 必须取 `(delay-1)/N` 而非 `delay/N`：delay=8、N=8 时期望 8 tick 触发，`(8-1)/8=0` → 指针到槽即触发（对）；用 `8/8=1` 会多等一整圈变 16 tick（错一倍）。delay=13、N=8：`(13-1)/8=1` → 第一次到达（第 5 tick）不减尽、第二次（第 13 tick）触发（对）。

| 特性 | 说明 |
|---|---|
| 插入/删除 O(1) | 哈希入槽 + 链表摘挂 |
| 精度 | 只能到 tick 粒度；tick=100ms 表达不了 50ms |
| 长定时 | 单层靠大 round 空转；层级轮多层粒度递增到期降层——Kafka(20ms×512×3)、内核低精度(tv1 256 槽 + tv2~tv5 各 64) |
| 并发 | 到期与插入线程分离时，槽链表加锁或经 MPSC 队列过渡 |

## 11. 常见问题与坑

| 坑 | 现象 | 正解 |
|---|---|---|
| 用 volatile 做线程同步 | 偶发旧值/撕裂值 | 换 atomic 或锁；volatile 只留给 MMIO/sig_atomic_t |
| CAS 忘 ABA | 无锁结构偶发链损坏 | 版本号指针或 hazard pointer |
| fetch_sub 用 relaxed 释放引用 | 析构者读到未完成写 | 减计数用 acq_rel |
| 伪共享不处理 | 多线程计数吞吐只剩 1/N | alignas(64) 隔离热变量 |
| compare_exchange 忽略失败回填 | 循环用旧值死循环 | 失败时 expected 已更新，直接重试 |
| MPSC 多线程 pop / 满载自旋 | 数据错乱 / 烧 CPU | pop 仅单线程；高水位改阻塞/丢弃 |
| Buffer 读后忘 retrieve | readableBytes 恒增爆内存 | 处理完必须推进读指针 |
| readFd 不用备用块 / sendFd 忽略 EAGAIN | 多次扩容 / 丢数据 | readv 双目的地一次收全；EAGAIN 注册 EPOLLOUT 续发 |
| 时间轮 round 用 delay/N / 精度不匹配 | 晚一圈 / 表达不了小延迟 | round=(delay-1)/N；精度=粒度，大跨度用层级轮 |
| 定时器回调里重活 / shared_ptr 移动后用源 | tick 饿死 / 空指针 | 回调轻量化抛线程池；移动即交权 |
