## 1. 概述

### 1.1 协程存在的 3 个原因

| 原因 | 展开说 |
|---|---|
| ① 同步写法获得异步性能 | epoll+回调（异步）吞吐高但代码碎成一地回调；阻塞式代码可读但一连接一线程开销大。协程 = **看起来阻塞、实际挂起**：写 `recv()` 的顺序代码，底层被改造成"非阻塞 + epoll + 挂起/恢复" |
| ② 消灭回调地狱 | 回调把一次业务流程拆进 N 个函数，局部变量、错误处理、跳转全部碎片化；协程把流程还原成顺序逻辑，栈帧原地保留 |
| ③ 切换成本极低 | 协程切换 = 保存/恢复少量寄存器（用户态几十条指令）；线程切换要陷入内核走调度器（还要可能刷 TLB） |

### 1.2 进程 / 线程 / 协程切换开销对比【高频】

| 维度 | 进程切换 | 线程切换 | 协程切换 |
|---|---|---|---|
| 切换什么 | 页表（CR3）+ 全套寄存器 + 内核调度 | 寄存器 + 内核调度（同进程不切页表） | **只切 callee-saved 寄存器 + 栈指针** |
| 发生位置 | 内核态 | 内核态 | 用户态（不陷入内核） |
| 数量级 | 1~10 μs | 0.5~2 μs | **10~100 ns** |
| 切换时机 | 内核抢占/系统调用 | 内核抢占 | **用户代码主动让出**（协作式） |
| 栈 | 独立（8MB 级） | 独立（默认 8MB） | 独立小栈（128KB 级）或共享栈 |
| 并发量级 | 数百 | 数千~数万 | **十万~百万** |

（数量级为经验值，随内核版本/CPU 微架构浮动；结论稳定：协程切换约为线程的 1/10~1/100。）

### 1.3 协程 vs 线程大表

| 对比项 | 线程 | 协程 |
|---|---|---|
| 调度方 | 内核，**抢占式**（时间片到/优先级） | 用户态调度器，**协作式**（不让出就一直跑） |
| 阻塞语义 | 阻塞只挂起本线程 | "阻塞"若未改造会把**整个线程**卡住（见第 6 章 hook 的必要性） |
| 栈 | 独立 8MB（虚拟内存） | 128KB 独立栈或共享栈 |
| 数据竞争 | 天然存在，需锁 | 单线程内协程间**切换点之间**才可能竞争 |
| 数量上限 | ~万 | ~十万以上 |
| 多核利用 | 天然多核 | 一个调度器绑一个线程，多核要多实例（见 7.2） |
| 编程模型 | 同步顺序 | 同步顺序（这是卖点） |

### 1.4 与 Go goroutine 对照

| 项 | Go goroutine | NtyCo/本篇 |
|---|---|---|
| GMP 一句话 | G(goroutine) 挂在 P(逻辑处理器)的本地队列，P 绑定 M(内核线程)执行；M 阻塞时 P 会被搬到别的 M 继续跑 | 调度器实例直接绑死一个线程 |
| 栈 | 有栈：初始 2KB 连续栈，按需扩容（拷贝迁移） | 有栈：固定 128KB 独立栈（或共享栈） |
| 抢占 | 1.14 起基于信号的异步抢占 | 纯协作式 |
| 阻塞 API | runtime 全套接管（netpoller） | 靠 hook 改造 POSIX 函数 |

有栈 vs 无栈：有栈协程有真实栈帧（本篇/libco/go）；无栈协程把函数编译成状态机（asio coroutine、Rust async、C# async/await），切换即状态迁移，但不能在任意深处让出、局部变量受限。

## 2. 协程原语与结构体

### 2.1 四原语语义表

| 原语 | 语义 | 谁调用 |
|---|---|---|
| create | 创建协程对象+分配栈+布置首次启动现场，入就绪队列 | 用户 |
| switch | 底层上下文切换（保存 from、恢复 to），不含任何调度逻辑 | 调度器/hook 内部 |
| resume | 调度器把某个 SUSPEND/READY 协程切上 CPU | 调度器 |
| yield | 运行中的协程主动让出 CPU，回到调度器（可能同时挂入就绪/等待/睡眠集合） | 协程（用户代码） |

### 2.2 协程结构体（C）

```c
#include <stdint.h>
#include <stddef.h>

typedef void *(*co_func_t)(void *);

typedef enum {
    CO_READY = 0,      /* 新建: 还没上过 CPU */
    CO_RUNNING,        /* 正在运行 */
    CO_SUSPEND,        /* 已让出: 等待 io/睡眠/自愿让出 */
    CO_DONE            /* 已执行完, 待回收 */
} co_state;

typedef struct _coroutine {
    co_state    state;
    co_func_t   fn;              /* 协程入口函数 */
    void       *arg;             /* 入口参数 */

    /* ---- 上下文与栈 ---- */
    ctx_t       ctx;             /* regs: rsp,rbx,rbp,r12~r15 (见 3.3) */
    char       *stack;           /* 栈基址(独立栈: malloc/mmap) */
    size_t      stack_size;      /* 经验值 128KB */

    /* ---- 调度挂载信息 ---- */
    struct _sched *sched;
    uint64_t    sleep_until;     /* 睡眠到期时刻(ms), 供最小堆比较 */
    int         wait_fd;         /* 等待的 fd; -1 = 不在等 io */
    uint32_t    wait_events;     /* EPOLLIN / EPOLLOUT */
    int         timed_out;       /* 超时标志(调度器置位) */
    struct _coroutine *ready_next; /* 就绪队列链表节点 */
} coroutine_t;
```

### 2.3 调度器结构体

```c
typedef struct _sched {
    ctx_t         main_ctx;              /* 调度器自己的上下文 */
    coroutine_t  *running;               /* 当前占用 CPU 的协程 */

    coroutine_t  *ready_head;            /* 就绪队列: FIFO 链表 */
    coroutine_t  *ready_tail;
    minheap_t     sleep_heap;            /* 睡眠集合: 按 sleep_until 的最小堆 */
    hashmap_t     wait_map;              /* io 等待集合: fd → coroutine */

    int           epfd;                  /* 事件驱动之源 */
    int           nco_alive;             /* 未 DONE 的协程计数 */
} sched_t;
```

| 集合 | 结构 | 为什么 |
|---|---|---|
| 就绪 | FIFO 链表 | 公平轮转、O(1) |
| 睡眠 | 最小堆（键=sleep_until） | 每轮只看堆顶是否到期，O(log n) |
| 等 io | hash（键=fd） | epoll 事件回来按 fd 反查协程，O(1) |

## 3. 三种切换实现方式对比【高频】

### 3.1 setjmp / longjmp：为什么不能做协程

| 问题 | 说明 |
|---|---|
| 不能切栈 | setjmp 保存的是**调用时刻的 rsp**；longjmp 恢复它后只会"回到原来的栈"。协程要切换到**另一块栈**（新建协程栈），setjmp/longjmp 语义上只支持同栈回跳 |
| 首次启动无解 | 新协程从未 setjmp 过，没有 jmp_buf 可跳；伪造 jmp_buf 需要写 rsp/rip |
| jmp_buf 加密 | glibc 对 jmp_buf 中的指针做 PTR_MANGLE（与 TLS guard 异或+旋转），手改即崩，且不可移植 |
| 本质错位 | 它是非局部跳转（错误处理），不是可反复双向切换的调度原语 |

### 3.2 ucontext：四函数完整示例

| 函数 | 语义 | 关键细节 |
|---|---|---|
| getcontext(ucp) | 把**当前**上下文存入 ucp，返回 0 | 后续被 setcontext 回切时会在本行之后继续 |
| makecontext(ucp, func, argc, ...) | **改造** ucp：激活时从 func 开始跑 | 必须先 getcontext 初始化；uc_stack 要先设好；参数按 **int** 传递 |
| setcontext(ucp) | 切换到 ucp，不返回 | —— |
| swapcontext(oucp, ucp) | 保存当前到 oucp，激活 ucp | 当别人切回 oucp 时，本次调用"返回 0"（两次进入语义） |

```c
/* ucontext 协程最小示例: 编译 gcc -o uctx uctx.c */
#include <stdio.h>
#include <ucontext.h>
#include <string.h>

static ucontext_t main_ctx, co_ctx;
static char co_stack[64 * 1024];

static void co_fun(int x) {
    printf("coroutine start, x=%d\n", x);
    swapcontext(&co_ctx, &main_ctx);        /* 主动让出: 回到 main */
    printf("coroutine resume, then return\n");
}                                           /* 返回后 uc_link 生效: 自动切回 main */

int main(void) {
    getcontext(&co_ctx);                    /* 1. 初始化模板(必须先做) */
    co_ctx.uc_stack.ss_sp   = co_stack;     /* 2. 指定协程自己的栈 */
    co_ctx.uc_stack.ss_size = sizeof(co_stack);
    co_ctx.uc_link = &main_ctx;             /* 3. 函数 return 后切回 main_ctx */
    makecontext(&co_ctx, (void (*)(void))co_fun, 1, 42); /* 4. 改造入口 */

    swapcontext(&main_ctx, &co_ctx);        /* 5. 进入协程 */
    printf("main: after first switch\n");
    swapcontext(&main_ctx, &co_ctx);        /* 6. 恢复协程(它会 return) */
    printf("main: co returned, via uc_link back here\n");
    return 0;
}
```

ucontext 的缺点：glibc 封装有系统调用级开销（sigprocmask 处理信号掩码）；Windows 没有；makecontext 的 int 参数在 64 位下传指针不可移植（经典坑）。

### 3.3 汇编实现【核心】

协程切换的本质（x86_64 System V ABI）：

- **caller-saved 寄存器**（rax/rcx/rdx/rsi/rdi/r8~r11）：函数调用约定保证"调用者自己保存"，切换函数可以随便踩——**不用保存**；
- **callee-saved 寄存器**（rbx/rbp/r12/r13/r14/r15）：被调函数承诺保持原样——切换时要**手动保存/恢复**；
- 加上**栈指针 rsp** 与返回地址，共 6+1 个字，这就是上下文的全部。

```c
/* ctx.h: 上下文结构(与汇编布局一一对应) */
typedef struct _ctx {
    void *regs[7];   /* [0]=rsp [1]=rbx [2]=rbp [3]=r12 [4]=r13 [5]=r14 [6]=r15 */
} ctx_t;
extern void ctx_switch(ctx_t *from, ctx_t *to);
```

```asm
# ctx_switch.S —— x86_64, AT&T 语法, gcc -c ctx_switch.S
# 原型: void ctx_switch(ctx_t *from, ctx_t *to);
#       rdi = from(保存现场到这里)  rsi = to(从这里恢复)
    .text
    .globl ctx_switch
    .type  ctx_switch, @function
ctx_switch:
    # ---------- 保存当前协程: 6 个 callee-saved + rsp ----------
    # rdi/rsi 本身是 caller-saved, 可放心作地址基址
    movq %rsp,  0(%rdi)     # regs[0] = rsp  (栈指针, 命门)
    movq %rbx,  8(%rdi)     # regs[1] = rbx
    movq %rbp, 16(%rdi)     # regs[2] = rbp
    movq %r12, 24(%rdi)     # regs[3] = r12
    movq %r13, 32(%rdi)     # regs[4] = r13
    movq %r14, 40(%rdi)     # regs[5] = r14
    movq %r15, 48(%rdi)     # regs[6] = r15

    # ---------- 恢复目标协程 ----------
    movq 48(%rsi), %r15
    movq 40(%rsi), %r14
    movq 32(%rsi), %r13
    movq 24(%rsi), %r12
    movq 16(%rsi), %rbp
    movq  8(%rsi), %rbx
    movq  0(%rsi), %rsp     # 栈切到目标协程的栈
    ret                     # 弹出目标栈顶的返回地址 → 跳到目标上次停下的地方
    .size ctx_switch, .-ctx_switch
```

**ret 的两种含义**：①目标是老协程：它的栈顶存着"当年调用 ctx_switch 的返回地址"，ret 正常返回；②目标是新协程：它的栈顶被我们**预先布置**成跳板地址（下文）。

**首次启动技巧**：新协程没跑过、没有"上次的返回地址"，所以初始化时手工布置它的栈：

```text
新协程栈(从高地址向低地址生长, top 先 16 字节对齐):

     top ─┬─────────────────────────────────┐
          │  [参数: coroutine_t* co]        │ ← popq %rdi 弹出
          │  [真正入口: co_main 地址]        │ ← popq %rax 弹出
  rsp ──▶ │  [跳板: co_entry_stub 地址]     │ ← ctx_switch 的 ret 弹出, 跳进跳板
          └─────────────────────────────────┘
```

```asm
# 协程入口跳板: 负责把参数装进 rdi、对齐栈、调用入口、收尾
    .text
    .globl co_entry_stub
co_entry_stub:
    popq  %rax        # 1. 真正的 C 入口(co_main)
    popq  %rdi        # 2. 参数 co (coroutine_t*)
    pushq %rdi        # 3. 备份参数(入口返回后还要用)
    subq  $8, %rsp    # 4. 对齐填充: 保证 call 前 rsp 16 字节对齐
    callq *%rax       # 5. 调用 co_main(co)
    addq  $8, %rsp    # 6. 撤销对齐填充
    popq  %rdi        # 7. 恢复参数
    callq co_exit     # 8. co_exit(co): 标记 DONE 并切回调度器, 永不返回
    hlt               #    保险: 不应到这
```

```c
/* C 侧: 新协程栈布置 + 入口 + 收尾 */
void co_main(coroutine_t *co) {
    co->fn(co->arg);               /* 跑用户函数, 同步写法 */
}   /* 返回 → 回到跳板 → co_exit */

void co_exit(coroutine_t *co) {
    co->state = CO_DONE;           /* 收尾 */
    sched_t *s = co->sched;
    s->running = NULL;
    ctx_switch(&co->ctx, &s->main_ctx);   /* 切回调度器; 本协程不会再被恢复 */
}

static void co_init_stack(coroutine_t *co) {
    char *top = co->stack + co->stack_size;
    top = (char *)((uintptr_t)top & ~(uintptr_t)15);  /* 16字节对齐 */
    void **sp = (void **)top;
    *--sp = (void *)co;                    /* [参数] */
    *--sp = (void *)co_main;               /* [入口] */
    *--sp = (void *)co_entry_stub;         /* [ret 目标] */
    co->ctx.regs[0] = (void *)sp;          /* 首次切换时的 rsp */
}
```

对齐说明：ABI 要求 call 指令执行前 rsp 为 16 的倍数（函数入口处 rsp%16==8）。跳板里 pushq+subq $8 的组合就是为此服务——少这一步，用到 SSE 指令（memcpy/浮点）时直接段错误。

### 3.4 三方式优劣对比

| 方式 | 切栈 | 性能 | 可移植性 | 结论 |
|---|---|---|---|---|
| setjmp/longjmp | ✗（只能回原栈） | 快 | 好 | **不可用**：语义错位+jmp_buf 加密 |
| ucontext | ✓ | 慢（封装开销，含信号掩码操作） | POSIX（无 Windows） | 原型验证/教学首选 |
| 汇编 | ✓ | 最快（几十 ns） | 每种架构一份（x86_64/arm64...） | 生产选择（libco/boost.context 同路线） |

## 4. 栈管理

### 4.1 独立栈 vs 共享栈

```text
独立栈: 每协程一块                       共享栈: 所有协程共用一块
 ┌────┐┌────┐┌────┐┌────┐               ┌──────────────┐
 │co1 ││co2 ││co3 ││coN │               │ 共享栈 1MB    │← 当前只有 co3 在用
 │128K││128K││128K││128K│               └──────────────┘
 └────┘└────┘└────┘└────┘                 co1/co2 的栈内容被拷到各自保存区
 10 万协程 = 12.8GB 虚拟内存(按需驻留)      切换: memcpy 栈内容(几十μs 级)
```

| 对比项 | 独立栈 | 共享栈 |
|---|---|---|
| 切换成本 | 只切寄存器（几十 ns） | + memcpy 已用栈段（与栈深成正比） |
| 内存 | 虚拟内存大；实际只驻留触碰过的页 | 极省（一整块） |
| 实现难度 | 简单 | 需记录每协程"已用栈大小"，切换时拷进拷出 |
| 局部变量地址 | 稳定（各在各栈） | 恢复后仍在共享栈同一位置：**把局部变量地址传出去保存=悬垂** |
| 适用 | 通用（libco 默认、NtyCo 默认） | 海量协程内存敏感场景（libco 可选、go 早期分段栈思想类似） |

### 4.2 栈溢出检测与栈大小经验值

| 项 | 做法/经验 |
|---|---|
| guard page | 栈底放一页 `mmap(PROT_NONE)`；踩到立即 SIGSEGV，把"爆栈"变成可定位的崩溃（配合打日志看崩溃地址是否落在 guard 区） |
| 栈大小 | 默认 128KB；业务有深递归/大局部数组（如 `char buf[65536]`）按 512KB~1MB 配；过大浪费虚拟内存 |
| Go 对照 | goroutine 初始 2KB 连续栈，不够时 2 倍扩容并把栈整体拷贝迁移（记录指针重定向）——"小起步+可增长"是最优解但实现复杂 |

## 5. 调度器实现【核心】

### 5.1 调度主循环

```text
co_sched_run(s):
  while (s->nco_alive > 0):
      1. timeout = 堆顶到期时间 - now()   # 堆空取 1000ms; 已过期取 0
      2. n = epoll_wait(s->epfd, evs, timeout)        # 事件驱动之魂
      3. for ev in evs:                              # io 就绪 → 唤醒
             co = s->wait_map[ev.data.fd]
             从 wait_map 摘除; co->timed_out = 0
             若 co 还挂在睡眠堆(带超时等待) → 从堆中摘除
             就绪队列.push(co)
      4. while 睡眠堆顶.sleep_until <= now:           # 超时到期 → 唤醒
             co = 堆.pop(); co->timed_out = 1
             若 co 还挂在 wait_map → 摘除
             就绪队列.push(co)
      5. while co = 就绪队列.pop():                   # 恢复协程
             s->running = co; co->state = CO_RUNNING
             ctx_switch(&s->main_ctx, &co->ctx)       # 进协程
             s->running = NULL                        # 回到这: 它 yield 或结束了
             if co->state == CO_DONE: co_destroy(co)  # 回收栈与对象
```

```c
/* 主循环骨架(外围结构体/堆/hash 从略, 见 2.3 与 01 篇) */
void co_sched_run(sched_t *s) {
    struct epoll_event evs[128];
    while (s->nco_alive > 0) {
        int timeout = heap_empty(&s->sleep_heap) ? 1000
                    : (int)(heap_top_due(&s->sleep_heap) - now_ms());
        if (timeout < 0) timeout = 0;

        int n = epoll_wait(s->epfd, evs, 128, timeout);
        for (int i = 0; i < n; i++) {
            coroutine_t *co = wait_map_get(s, evs[i].data.fd);
            if (co) wait_map_del(s, co->wait_fd), ready_push(s, co);
        }
        uint64_t now = now_ms();
        while (!heap_empty(&s->sleep_heap)
               && heap_top_due(&s->sleep_heap) <= now)
            ready_push(s, heap_pop(&s->sleep_heap));

        coroutine_t *co;
        while ((co = ready_pop(s)) != NULL) {
            s->running = co;  co->state = CO_RUNNING;
            ctx_switch(&s->main_ctx, &co->ctx);   /* 进去 */
            s->running = NULL;                    /* 出来 */
            if (co->state == CO_DONE) { co_destroy(s, co); s->nco_alive--; }
        }
    }
}
```

### 5.2 三个集合与让出时机

| 集合 | 进入条件 | 离开条件 |
|---|---|---|
| 就绪队列 | create / 事件到达 / 睡眠到期 / 纯 yield | 被调度器 resume |
| 睡眠堆 | co_sleep(ms) / 带 timeout 的 io 等待 | 到期（或等待的 io 先到被摘除） |
| wait_map | 等 fd 事件（hook 的"阻塞"调用） | epoll 事件到达（或超时先到被摘除） |

协程让出时机 = 调用任何被 hook 的"阻塞"API（connect/recv/send/read/write/poll/sleep）或显式 `co_yield()`：

```c
/* 让出的统一收尾: 切回调度器 */
static void co_switch_back(coroutine_t *co) {
    co->sched->running = NULL;
    ctx_switch(&co->ctx, &co->sched->main_ctx);
}

void co_yield(coroutine_t *co) {          /* 自愿让出: 挂回就绪队尾 */
    co->state = CO_SUSPEND;
    ready_push(co->sched, co);
    co_switch_back(co);
}
void co_sleep(coroutine_t *co, uint64_t ms) {  /* 睡眠: 挂睡眠堆 */
    co->state = CO_SUSPEND;
    co->sleep_until = now_ms() + ms;
    heap_push(&co->sched->sleep_heap, co);
    co_switch_back(co);
}
```

## 6. 接口与 hook

### 6.1 协程 API 设计

| API | 语义 |
|---|---|
| co_create(fn, arg) | 建协程对象、分栈、co_init_stack 布置首次现场、入就绪队列 |
| co_kill(co) | 标记销毁（安全做法：置标志，调度器在其未运行时回收） |
| co_sleep(ms) | 当前协程睡 ms 毫秒（挂睡眠堆+让出） |
| co_yield() | 让出 CPU 但留在就绪队列 |
| co_sched_run() | 调度主循环，跑完所有协程返回 |

### 6.2 异步流程实现（阻塞调用的改造模板）

```text
同步阻塞:  recv(fd)  ──没数据──▶ 线程睡觉等内核唤醒
协程改造:  recv(fd)  ──EAGAIN──▶ ①fd 已非阻塞
                                ②epoll 注册 EPOLLIN, wait_map[fd]=co
                                ③yield 切回调度器(线程去跑别的协程)
                                ④事件到达 → 调度器把 co 挂回就绪 → resume
                                ⑤回到 recv 调用点之后, 像什么都没发生
```

```c
/* 等待 fd 事件(带超时): 所有 hook 函数的公共底座 */
int co_wait_io(int fd, uint32_t events, int timeout_ms) {
    sched_t *s = get_sched();             /* 本线程调度器实例 */
    coroutine_t *co = s->running;

    struct epoll_event ev;                 /* 注册关注 */
    ev.events = events; ev.data.fd = fd;
    epoll_ctl(s->epfd, EPOLL_CTL_ADD, fd, &ev);

    co->wait_fd = fd; co->wait_events = events;
    co->timed_out = 0;
    wait_map_put(s, fd, co);
    if (timeout_ms > 0) {                  /* 超时同时挂睡眠堆 */
        co->sleep_until = now_ms() + timeout_ms;
        heap_push(&s->sleep_heap, co);
    }
    co->state = CO_SUSPEND;
    ctx_switch(&co->ctx, &s->main_ctx);    /* ★ 让出, 醒来从这继续 */

    /* 恢复点: 清理另一半注册(事件到→摘睡眠堆; 超时到→摘wait_map+DEL) */
    epoll_ctl(s->epfd, EPOLL_CTL_DEL, fd, NULL);
    wait_map_del(s, fd);
    if (timeout_ms > 0 && !co->timed_out) heap_remove(&s->sleep_heap, co);
    return co->timed_out ? -1 : 0;         /* -1=超时 */
}
```

### 6.3 hook 钩子实现【高频】

原理：用 `dlsym(RTLD_NEXT, "connect")` 拿到 libc 里的**原函数**，再定义同名 `connect` 覆盖之；链接期（`gcc myhook.c -ldl` 编进程序）或运行期（`LD_PRELOAD=./hook.so ./app`）生效。

```c
#define _GNU_SOURCE
#include <dlfcn.h>
#include <errno.h>
#include <fcntl.h>
#include <unistd.h>
#include <sys/epoll.h>
#include <sys/socket.h>

typedef int (*connect_fn)(int, const struct sockaddr *, socklen_t);
static connect_fn real_connect = NULL;

static void hook_init(void) __attribute__((constructor)); /* so 加载即执行 */
static void hook_init(void) {
    real_connect = (connect_fn)dlsym(RTLD_NEXT, "connect");
    /* RTLD_NEXT: 从"下一个"库(即真正的 libc)里找, 跳过我们自己 */
}

extern int co_wait_io(int fd, uint32_t events, int timeout_ms);

int connect(int fd, const struct sockaddr *addr, socklen_t len) {
    if (!real_connect) hook_init();

    /* 1. 先转非阻塞 */
    int fl = fcntl(fd, F_GETFL, 0);
    fcntl(fd, F_SETFL, fl | O_NONBLOCK);

    /* 2. 调原函数: 发出 SYN */
    int ret = real_connect(fd, addr, len);
    if (ret == 0) { fcntl(fd, F_SETFL, fl); return 0; }   /* 立即成功 */
    if (errno != EINPROGRESS) return ret;    /* 真错误; EINPROGRESS=握手中 */

    /* 3. 挂起协程等"可写"(握手完成 fd 变可写), 超时按业务配(示例 3s) */
    if (co_wait_io(fd, EPOLLOUT, 3000) < 0) {
        fcntl(fd, F_SETFL, fl);
        errno = ETIMEDOUT;
        return -1;
    }

    /* 4. 恢复后取握手结果 */
    int err = 0; socklen_t elen = sizeof(err);
    getsockopt(fd, SOL_SOCKET, SO_ERROR, &err, &elen);
    fcntl(fd, F_SETFL, fl);                  /* 恢复原阻塞属性(可选) */
    if (err) { errno = err; return -1; }
    return 0;
}
```

| hook 对象 | 改造要点 |
|---|---|
| connect | 非阻塞 + 等 EPOLLOUT + SO_ERROR 判结果（上面完整版） |
| recv/read | 非阻塞收；EAGAIN → 等 EPOLLIN → resume 后重试收 |
| send/write | 尽力写；EAGAIN → 等 EPOLLOUT → resume 续写 |
| poll/epoll_wait | 把"等事件"本身翻译成对多个 fd 的 co_wait_io 聚合 |
| sleep/usleep | 直接转 co_sleep（挂睡眠堆） |

### 6.4 为什么 hook 后同步代码无需重写

第三方库（mysql_real_query、redis 客户端、curl...）内部最终都落到 connect/read/write/poll 这几个 POSIX 函数。hook 掉它们 = **整个调用链被透明地异步化**：

| 角度 | 说明 |
|---|---|
| 业务代码 | 一行不改，仍是顺序同步写法 |
| 第三方库 | 无需重新编译（LD_PRELOAD 运行期生效） |
| 线程模型 | 一条线程跑几万协程，任何一个"阻塞点"都只是挂起协程 |
| 边界 | 未被 hook 的函数（fopen 系 stdio 缓冲、pthread 锁、ioctl）依然真阻塞——见第 9 章坑表 |

## 7. 实战与多核

### 7.1 协程版 MySQL 请求流程

```text
co_mysql_query(co, sql):
  mysql_real_connect(...)   ← 内部 connect 被 hook: 挂起等握手
  mysql_real_query(sql)     ← 内部 send/recv 被 hook: 发出后挂起等 EPOLLIN
  mysql_store_result(...)   ← 数据分批到达, 每批之间协程挂起
  业务处理(同步代码)
整个过程中: 调度器线程在 epoll_wait 上, 几万协程共享这一个线程
对比线程池版: 1 万并发查询 = 1 万线程(内存/切换爆炸)
```

### 7.2 多核方案

单调度器只占一个核。多核扩展（参考 muduo one loop per thread + go GMP 思想）：

```text
主线程(acceptor)          worker-1          worker-2         worker-N
 accept → connfd ──分发──▶ sched 实例        sched 实例        sched 实例
 (轮询/最少负载)           独立 epoll         独立 epoll        独立 epoll
                          独立就绪/睡眠堆    ...               ...
分发: 无锁队列 + eventfd 唤醒目标线程(见 13-原子操作与无锁组件.md)
关键: 一个协程从生到死只属于一个 sched → 集合结构无锁
```

| 要点 | 说明 |
|---|---|
| 每线程独立调度器 | 避免全局锁竞争；协程不跨线程迁移 |
| 任务分发 | 新连接/新任务 round-robin 投给 worker；用无锁队列 + eventfd 唤醒 |
| 反面案例 | 多线程共享一个 epoll + 一个就绪队列 → 锁竞争吃掉协程收益 |

### 7.3 性能测试方法

| 项 | 做法 |
|---|---|
| 对象 | 同一 echo/短 SQL 业务：①每连接一线程+阻塞 IO ②epoll Reactor ③协程版 |
| 指标 | QPS、P99 延迟、CPU 利用率、RSS 内存 |
| 工具 | wrk / 自写 epoll 压测客户端（两端都调 fd，见 `04-百万并发与TCP栈优化.md`） |

## 9. 常见问题与坑

| 坑 | 现象 | 正解 |
|---|---|---|
| 协程内调 pthread_mutex 阻塞锁 | 整个线程卡死，几万协程陪葬 | 用协程锁（拿不到就挂起让出）或改无锁结构；临界区极短可用自旋 |
| 认为"单线程协程无并发" | yield 后共享数据被其他协程改掉 | 切换点=潜在并发点；跨 yield 的共享状态照样要同步 |
| 栈 128KB 不够用（深递归/大局部数组） | 落在 guard page 段错误或悄悄踩内存 | 按业务测最大栈深配 512KB~1MB；上 guard page 定位 |
| hook 未覆盖的 API | fopen/fgets(带 stdio 缓冲)、sleep、ioctl、pthread cond 仍真阻塞 | 全链路排查依赖；stdio 换 read/write 系 |
| 多线程直接 resume 别的线程的协程 | 调度器数据结构竞争，偶发崩溃 | 协程归属唯一线程；跨线程用任务投递（无锁队列+eventfd 唤醒） |
| 共享栈下把局部变量地址传出去 | 切换后指向共享栈同位置，内容被别的协程覆盖 | 共享栈模式禁止地址逃逸；或换独立栈 |
| makecontext 传指针参数 | 64 位指针被按 int 截断，读到垃圾 | 参数只用 int；指针经全局/上下文结构传递 |
| DONE 协程仍被引用 | 就绪队列/等待表残留指针 → use-after-free | co_exit 里从所有集合摘除；销毁只发生在调度循环手里 |
| 两个协程等同一个 fd | wait_map[fd] 互相覆盖，先挂的永远等不到 | fd 归属唯一协程；多路等待要专门聚合结构 |
| 协程内 fork/信号处理函数里切协程 | 子进程调度器状态混乱、信号上下文不可切换 | fork 后子进程重建调度器；信号回调只置标志 |
| 忘处理超时清理 | 事件与超时同时到，协程被 resume 两次 | timed_out 标志 + 恢复点统一摘除另一侧注册 |
| 跳板没做 16 字节对齐 | 一进 SSE/memcpy 就段错误 | pushq+subq $8 组合保证 call 前 rsp%16==0 |
| 调度循环空转 | 无协程时 epoll_wait timeout=0 死循环烧 CPU | 无存活协程且堆空时退出或用较长 timeout |
| 期望协程提升纯计算业务 | 测下来没提升 | 协程优化的是 IO 等待与切换成本，CPU 密集型无解 |
