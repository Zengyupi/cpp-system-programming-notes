## 1. 概述

嵌入式开发是对**嵌入式系统**（Embedded System）——软硬件结合、面向特定用途的专用计算机系统——进行开发的过程，覆盖物联网、汽车电子、工业控制、消费电子、医疗、航空航天。

### 1.1 核心特点

| 特点 | 说明 |
| --- | --- |
| **资源受限** | CPU 主频低、RAM 小（KB~MB）、Flash 有限，要精打细算每一字节 |
| **实时性** | 硬实时（错过截止期即事故，如安全气囊/电机控制）vs 软实时（偶尔超时可容忍，如 UI） |
| **功耗敏感** | 电池设备需在 Sleep/Stop/Standby 间动态切换 |
| **软硬件强耦合** | 直接操作寄存器、外设、时序，需读得懂原理图与数据手册（Datasheet/Reference Manual） |
| **交叉编译** | 在 x86 主机上编译，在 ARM/RISC-V 目标板运行 |
| **固化长期运行** | 烧录到 Flash，要求 7×24 稳定、可自恢复（看门狗）、可远程升级（OTA） |

### 1.2 三条技术路线

```text
裸机 Bare-Metal  ──功能变复杂──►  RTOS（FreeRTOS/RT-Thread/Zephyr）  ──要网络/UI/多核──►  嵌入式 Linux
   寄存器/中断         任务调度/IPC/驱动框架              内核/设备树/根文件系统/用户态
   Cortex-M 小 MCU     Cortex-M 中大型 MCU               Cortex-A MPU
   KB 级资源           几十~几百 KB RAM                   MB~GB RAM
```

| 路线 | 典型资源 | 实时性 | 典型芯片 |
| --- | --- | --- | --- |
| 裸机 | Flash<64K，RAM<16K | 最好（无调度开销） | STM32F0/F1、CH32V003 |
| RTOS | Flash 64K~1M，RAM 32K~512K | 强（优先级抢占） | STM32F4/H7、ESP32、nRF52 |
| 嵌入式 Linux | RAM≥32M，Flash≥64M | 弱（内核调度，需 RT 补丁/Xenomai） | i.MX6/8、RK3568、全志 H3 |

## 2. 嵌入式系统分层架构

```text
┌─────────────────────────────────────────────────────────────┐
│                    应用层 (Application)                      │
│        业务逻辑 / 协议栈 / 状态机 / AI 推理                    │
├─────────────────────────────────────────────────────────────┤
│              框架/OS 层 (RTOS / Linux Kernel)                │
│     任务调度、IPC、文件系统、网络栈、设备驱动模型              │
├─────────────────────────────────────────────────────────────┤
│                驱动/BSP 层 (Driver / HAL)                    │
│   UART/I2C/SPI/CAN/GPIO/DMA/Timer 驱动、板级初始化           │
├─────────────────────────────────────────────────────────────┤
│                   硬件层 (Hardware)                          │
│     CPU 核 + 总线矩阵 + 外设 + RAM/Flash + 引脚              │
└─────────────────────────────────────────────────────────────┘
```

> HAL（硬件抽象层，如 STM32 HAL/LL、ESP-IDF driver）把寄存器操作封装成 API；LL/寄存器层更接近硬件、效率更高，HAL 可移植性好但有额外开销。性能关键路径用 LL/寄存器，通用业务用 HAL。

## 3. 嵌入式硬件基础

### 3.1 MCU 与 MPU 的区别

| 特性 | MCU（微控制器） | MPU（微处理器） |
| --- | --- | --- |
| 典型芯片 | STM32、ESP32、AVR、CH32V | Cortex-A、RK/i.MX、x86 |
| 内存 | 片内 Flash + SRAM（KB~MB） | 外接 DDR（MB~GB）+ eMMC/SD |
| 运行系统 | 裸机 / RTOS | Linux / Android |
| 启动 | 上电直接执行 Flash 代码（XIP） | 需要 Bootloader 引导、加载内核 |
| 成本/功耗 | 低（$0.1~10）、mW 级 | 高（$5~100+）、W 级 |
| 确定性 | 中断响应确定（几 μs） | 受 MMU/缓存/调度影响 |

### 3.2 CPU 架构谱系

| 架构 | 定位 | 典型 |
| --- | --- | --- |
| ARM **Cortex-M**（M0/M0+/M3/M4/M7/M33/M55） | MCU 主流；M4 起带 FPU/DSP，M33/M55 带 TrustZone-M | STM32、nRF52、GD32 |
| ARM **Cortex-R**（R5/R8） | 实时、锁步双核、功能安全 | 汽车 ECU、存储主控 |
| ARM **Cortex-A**（A7/A53/A55/A76） | 应用处理器，带 MMU 跑 Linux | i.MX、RK、骁龙 |
| **RISC-V** | 开源免授权，可裁剪（RV32I/M/A/C/F/D） | ESP32-C3/C6、CH32V、GD32V |
| Xtensa LX | 可配置、指令可扩展 | ESP32/S3 |

> Cortex-M 关键概念：Thumb-2 指令集、NVIC 中断控制器、SysTick 系统滴答定时器、MPU（内存保护单元，非 MMU）、FPU。RISC-V 用 CLINT/PLIC 管定时器与外部中断，等价于 ARM 的 SysTick/NVIC。

### 3.3 常用外设接口速览

| 接口 | 线数/方式 | 速率量级 | 典型用途 |
| --- | --- | --- | --- |
| GPIO | 1 线，输入/输出 | — | LED、按键、片选、模拟协议 |
| UART | 2~5 线异步 | 9600~3Mbps | 调试串口、GPS、4G 模块 |
| I2C | 2 线同步多主多从 | 100K/400K/1M/3.4M | 传感器、EEPROM、触摸屏 |
| SPI | 4 线全双工单主多从 | 10M~100M+ | LCD、NOR Flash、SD 卡 |
| I2S/PCM | 3~5 线 | 音频采样率级 | 音频 Codec、麦克风 |
| CAN/CAN-FD | 2 线差分 | 1M / 8Mbps | 汽车、工业现场 |
| RS-485 | 2 线差分（基于 UART） | 同 UART | 工业 Modbus 总线 |
| USB | 差分 D+/D- | 12M/480M/5G/10G | 大容量、虚拟串口 |
| Ethernet | RMII/MII | 100M/1G | 网关、工业网关 |
| ADC/DAC | 模拟 | 采样率×分辨率 | 电压/温度采集、波形 |
| PWM/定时器 | 输出/输入捕获 | 时基驱动 | 电机调速、调光、测频 |

## 4. 快速参考卡片

### 技术路线选型决策表

| 判据 | 选裸机 | 选 RTOS | 选嵌入式 Linux |
| --- | --- | --- | --- |
| RAM/Flash 量级 | KB 级 | 几十~几百 KB | MB 级以上 |
| 是否需要 TCP/IP、文件系统、UI | 否 | 轻量网络栈可，重否 | 是 |
| 实时性要求 | 硬实时、确定中断 | 硬实时（优先级抢占） | 弱实时（需 RT 补丁/Xenomai） |
| 任务数量 | 1~2 个 | 多任务、有优先级 | 复杂业务、进程隔离 |
| 典型芯片 | Cortex-M0/M3、RISC-V RV32 | Cortex-M4/M7、ESP32、nRF52 | Cortex-A、RK、i.MX |

### MCU vs MPU 速查

| 维度 | MCU | MPU |
| --- | --- | --- |
| 内存 | 片内 SRAM/Flash（XIP） | 外接 DDR + eMMC/SD |
| MMU | 无（有 MPU 内存保护单元） | 有，跑 Linux |
| 启动 | 上电直接跑 Flash | Bootloader 引导内核 |
| 功耗/成本 | mW 级 / 几毛~几美元 | W 级 / 数美元起 |

## 5. 常见坑

1. **把 MPU 当 MCU 用**：选了 Cortex-A 做微秒级硬实时，忽视 Linux 内核调度、缓存、MMU TLB miss 带来的抖动；硬实时场景应选 Cortex-R/M 或加 PREEMPT_RT/Xenomai。
2. **资源估算只看"能跑"**：按代码占用估 Flash/RAM，漏掉 RTOS 内核、TCP/IP 协议栈、文件系统、堆与中断栈余量，量产时 OOM 或栈溢出。预留 20%~30% 余量。
3. **混淆两个"MPU"**：ARM Cortex-M 的 MPU 是 Memory Protection Unit（内存保护单元），用于隔离任务内存；与 MPU（MicroProcessor Unit，微处理器）同名不同物，读手册时需按上下文区分。
4. **外设接口选型脱离场景**：I2C/SPI 是板内短距离总线，强干扰/长距离工业现场误用会丢包，应选 CAN/RS-485；板内上拉电阻、终端电阻不接也会导致总线异常。
5. **忽视交叉编译与工具链版本**：在主机 x86 上编译却链接了错误架构的库，或 libc 版本与目标板不一致，运行时才暴露段错误；须用统一交叉工具链与 sysroot。
6. **XIP 性能误判**：代码直接在 Flash 执行时，取指受 Flash 等待状态（wait state）影响，与 SRAM 内执行差距明显；性能关键代码应拷贝到 RAM 执行，而非假设"上电即快"。
