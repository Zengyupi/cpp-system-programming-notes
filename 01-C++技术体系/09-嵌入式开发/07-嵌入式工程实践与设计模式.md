### 1.1 编译器、调试器与二进制工具

| 工具 | 作用 |
| --- | --- |
| `arm-none-eabi-gcc` / `arm-linux-gnueabihf-gcc` | 裸机 / Linux 交叉编译器 |
| `*-gdb` + OpenOCD | 配合 J-Link/ST-Link/DAP-Link 做源码级在线调试 |
| `objcopy -O binary/-O ihex` | elf → bin/hex（烧录用） |
| `objdump -d/-S` | 反汇编、混排源码看生成指令 |
| `size` | 看 text/data/bss 占用（评估 Flash/RAM） |
| `nm` | 列符号及地址（查变量/函数落在哪、有多大） |
| `addr2line` | 崩溃 PC 地址 → 源码行（HardFault 定位） |
| `readelf`/`map 文件` | 段布局、库依赖、内存用量细目 |

```bash
arm-none-eabi-gcc -mcpu=cortex-m4 -mthumb -mfpu=fpv4-sp-d16 -mfloat-abi=hard \
                  -g -O2 -ffunction-sections -fdata-sections main.c -o app.elf \
                  -T stm32f407.ld -Wl,--gc-sections -Wl,-Map=app.map
# -ffunction/data-sections + --gc-sections：把每个函数/数据独立成段，链接时丢弃未引用段以省 Flash
arm-none-eabi-objcopy -O binary app.elf app.bin
arm-none-eabi-size app.elf            # text+data 占 Flash，data+bss 占 RAM
```

## 3. 嵌入式经典设计模式

### 3.1 状态机（FSM）

裸机/协议解析最常用。简单分支用 switch，状态多用**表驱动**（状态×事件→处理函数/下一状态），避免 switch 爆炸：

```c
// 表驱动状态机：新增状态/事件只改表，不改主逻辑
typedef enum { ST_IDLE, ST_RECV, ST_SEND, ST_ERR } State;
typedef enum { EV_DATA, EV_DONE, EV_TIMEOUT, EV_MAX } Event;
typedef struct { State next; void (*action)(void); } Trans;

static Trans table[ST_ERR+1][EV_MAX] = {
  [ST_IDLE][EV_DATA]    = { ST_RECV, act_open   },
  [ST_RECV][EV_DONE]    = { ST_SEND, act_reply  },
  [ST_RECV][EV_TIMEOUT] = { ST_ERR,  act_error  },
  // ...
};

void fsm_dispatch(State *s, Event e) {
    Trans t = table[*s][e];
    if (t.action) t.action();
    *s = t.next;
}
```

## 4. 常见问题与坑

| 问题 | 根因 | 解决 |
| --- | --- | --- |
| HardFault | 野指针/越界、非对齐(M0)、除零、栈溢出、函数指针跑飞 | CFSR+栈帧 PC 定位（见《06-低功耗可靠性与OTA升级.md》1.3）；开栈检测 |
| 栈溢出 | 大局部数组、深递归、printf、中断嵌套 | 大数组 static/全局；估栈+水位线；减递归 |
| 全局变量被"莫名"改 | 缺 volatile 被优化 / 与 ISR 竞态 | 加 volatile；复合操作进临界区 |
| 外设完全不工作 | **忘了开外设/GPIO 时钟**、引脚没配复用 | 先查 RCC 时钟使能、AF 复用、数据手册时序 |
| I2C 卡死（SDA 被从机拉低） | 异常复位时从机停在应答态 | 主机手动补 9 个时钟释放总线；加超时复位 |
| UART 偶发丢字节 | 中断处理太慢、未清 ORE、无流控 | DMA+IDLE+环形缓冲；清 ORE；降波特率或加流控 |
| SPI 数据错乱 | 主从 CPOL/CPHA 不一致、位序/速率过高 | 对齐模式 0~3、MSB/LSB、降速看波形 |
| RTOS 任务"不动" | 优先级低于持续运行的任务、忘了阻塞/延时让出 CPU | 等待处必须阻塞或 vTaskDelay；同优先级开时间片 |
| 优先级反转 | 低优先级持锁、中优先级插队 | 用带优先级继承的 Mutex（非二值信号量） |
| 中断里调 API 崩 | 用了非 FromISR 版本/优先级高于系统调用阈值 | 一律 FromISR 并正确分组优先级 |
| 看门狗频繁复位 | 某任务死循环、ISR 太长 | 单点喂狗；查各任务耗时与阻塞点 |
| 浮点 printf 卡死/变大 | 没开硬浮点 ABI、newlib-nano 不支持 %f | -mfloat-abi=hard；或定点化避免 %f |
| 全局/静态初值不对 | .data 没从 Flash 拷贝、.bss 没清零 | 检查启动文件与 ld 的 _sdata/_sbss 符号 |
| DMA 收不到/数据旧 | 未使能外设 DMA、循环模式 NDTR、cache 一致性(M7) | M7 需 cache clean/invalidate 或放非 cache 区 |
| 低功耗下串口漏数据 | Stop 模式外设时钟停 | 用能在低功耗工作的 LSE/LSI、唤醒后重配 |
| Flash 写不进 | 没先擦除、写时读阻塞、跨扇区 | 严格按 擦→写；擦写期间不能取指（等就绪） |
| 堆内存越用越碎 | 运行期频繁 malloc/free | 内存池/静态分配，或 heap_4 合并 |

## 6. 快速参考卡片

```text
内存：Flash=0x08000000(.text/.rodata，XIP)  RAM=0x20000000(.data/.bss/heap↑/stack↓)
启动：向量表[MSP,Reset,...] → Reset_Handler(拷.data/清.bss/SystemInit) → main
段：.data 初值在 Flash 运行在 RAM；.bss 启动清零；const 进 Flash 省 RAM
volatile：硬件寄存器 / ISR 共享变量 / DMA 共享缓冲（不保证原子与顺序）
位操作：置|=  清&=~  翻^=  读改写字段先清后或；GPIO 用 BSRR 原子置位
临界区：尽量短；裸机关中断(BASEPRI)，RTOS 用 taskENTER_CRITICAL，ISR 用 FromISR
环形缓冲：SPSC 无锁，head 生产者改、tail 消费者改，容量取 2 的幂，判满牺牲一格
UART：起始位+数据+校验+停止，波特率误差<2%；不定长用 DMA 循环+IDLE 中断
I2C：开漏+上拉，SCL 高时 SDA 高→低=START、低→高=STOP，8 位后 ACK
SPI：CPOL 空闲电平 × CPHA 采样沿 = 模式0~3，主从必须一致；CS 低有效
CAN：显性0/隐性1，ID 小优先的非破坏性仲裁，CRC+ACK+错误帧，硬件滤波
ISR：短、快、不阻塞、不 printf/malloc；只入队+通知，重活给任务（顶/底半部）
DMA：正常/循环/双缓冲；M7 注意 D-Cache 一致性（clean/invalidate）
RTOS：高优先级抢占+同级时间片；Mutex 带优先级继承，二值信号量不带；栈单位是字
低功耗：Sleep/Stop/Standby + WFI；RTC 唤醒，占空比决定平均功耗
看门狗：只在主循环单点喂；IWDG 独立时钟兜底，WWDG 窗口查跑飞
HardFault：CFSR 看原因、栈帧里 PC 定位、addr2line -e app.elf <PC>
OTA：Bootloader+A/B 双区，下载备份区→CRC/签名校验→切换，失败回滚，永不覆盖唯一可用固件
Linux：BootROM→SPL→U-Boot→zImage+dtb→rootfs/init；设备树靠 compatible 匹配驱动
设备驱动：alloc_chrdev_region→cdev_add→class/device_create，file_operations 接 read/write
rootfs：快速用 Buildroot，量产用 Yocto；BusyBox 提供命令，libc 选 glibc/musl
```

## 7. 嵌入式 GUI 开发

嵌入式 GUI 是带屏设备（智能家居面板、工业 HMI、可穿戴、车载仪表）的核心。与桌面/移动 GUI 不同，嵌入式 GUI 必须在有限 RAM/Flash、低主频 CPU 上实现流畅渲染。

### 7.1 LVGL 架构与核心概念

LVGL（Light and Versatile Graphics Library）是目前最流行的开源嵌入式 GUI 库，纯 C 编写，MIT 许可，最小占用 ~64KB Flash、~16KB RAM。

#### 架构分层

```text
┌──────────────────────────────────────────────┐
│  应用层：你的 UI 代码（创建控件、设置回调、业务逻辑）│
├──────────────────────────────────────────────┤
│  LVGL 核心层                                    │
│  ┌──────────────────────────────────────────┐ │
│  │ 控件库（Widgets）：Button/Label/Slider/   │ │
│  │  Chart/List/Table/Keyboard/Textarea ...  │ │
│  ├──────────────────────────────────────────┤ │
│  │ 核心对象系统：lv_obj（所有控件基类）、       │ │
│  │ 样式系统（lv_style）、布局（Flex/Grid）、  │ │
│  │ 事件系统（lv_event）、动画（lv_anim）      │ │
│  ├──────────────────────────────────────────┤ │
│  │ 渲染引擎：脏矩形（dirty rect）只重绘变化区域、│ │
│  │ 颜色格式（RGB565/RGB888/ARGB8888）、抗锯齿  │ │
│  ├──────────────────────────────────────────┤ │
│  │ 显示驱动接口：lv_display_t → flush_cb     │ │
│  │ 输入驱动接口：lv_indev_t → read_cb        │ │
│  └──────────────────────────────────────────┘ │
├──────────────────────────────────────────────┤
│  硬件抽象层（用户实现）：                          │
│  flush_cb → SPI/LCD 控制器写帧缓冲                │
│  read_cb  → 触摸屏/按键/编码器读取输入             │
├──────────────────────────────────────────────┤
│  硬件：LCD 显示屏（SPI/RGB/MIPI）+ 触摸控制器     │
└──────────────────────────────────────────────┘
```

#### 核心概念

| 概念 | 说明 |
| --- | --- |
| **lv_obj（对象）** | 所有控件的基类，有位置、大小、样式、父对象；屏幕（lv_screen）也是对象，构成对象树 |
| **样式（Style）** | 类似 CSS，可设置背景色、边框、圆角、阴影、字体、状态（默认/按下/禁用）；样式可继承和级联 |
| **布局（Layout）** | Flex（弹性布局，类似 CSS Flexbox）和 Grid（网格布局），自动排列子控件，无需手动计算坐标 |
| **事件（Event）** | 控件状态变化触发事件（CLICK/VALUE_CHANGED/PRESS/RELEASE），注册回调函数处理 |
| **脏矩形渲染** | 只重绘变化的区域（dirty rect），而非整屏刷新，大幅减少 SPI/LCD 带宽 |
| **部分渲染（Partial Render）** | 用一小块行缓冲（line buffer，如 1/10 屏高）逐行渲染，不需要完整帧缓冲，RAM 占用极低 |
| **显示驱动 flush_cb** | LVGL 渲染好一块区域后调用 flush_cb，用户把数据通过 SPI/DMA 写到 LCD；写完调 `lv_display_flush_ready` |
| **输入驱动 read_cb** | 周期性调用，读取触摸屏坐标/按键状态，返回给 LVGL |

#### LVGL 最小示例

```c
#include "lvgl.h"

// 显示驱动：把渲染好的区域刷到 LCD（用户实现，对接 SPI/DMA）
static void flush_cb(lv_display_t *disp, const lv_area_t *area, uint8_t *px_map) {
    uint32_t w = lv_area_get_width(area);
    uint32_t h = lv_area_get_height(area);
    // 通过 SPI DMA 发送 px_map 到 LCD 的 (area->x1, area->y1) 区域
    lcd_send_area(area->x1, area->y1, area->x2, area->y2, px_map, w * h * 2);
    // DMA 完成中断中调用 lv_display_flush_ready(disp)
}

// 输入驱动：读取触摸屏
static void read_cb(lv_indev_t *indev, lv_indev_data_t *data) {
    uint16_t x, y;
    bool pressed = touch_read(&x, &y);
    data->point.x = x; data->point.y = y;
    data->state = pressed ? LV_INDEV_STATE_PRESSED : LV_INDEV_STATE_RELEASED;
}

void ui_init(void) {
    lv_init();

    // 创建显示设备：320x240，RGB565
    lv_display_t *disp = lv_display_create(320, 240);
    static uint8_t buf1[320 * 10 * 2];  // 10 行的部分渲染缓冲（RGB565=2字节/像素）
    static uint8_t buf2[320 * 10 * 2];  // 双缓冲：渲染一个时刷另一个
    lv_display_set_buffers(disp, buf1, buf2, sizeof(buf1), LV_DISPLAY_RENDER_MODE_PARTIAL);
    lv_display_set_flush_cb(disp, flush_cb);

    // 创建输入设备（触摸屏）
    lv_indev_t *indev = lv_indev_create();
    lv_indev_set_type(indev, LV_INDEV_TYPE_POINTER);
    lv_indev_set_read_cb(indev, read_cb);

    // 创建 UI：屏幕 + 标签 + 按钮
    lv_obj_t *screen = lv_screen_active();
    lv_obj_t *label = lv_label_create(screen);
    lv_label_set_text(label, "Hello LVGL");
    lv_obj_align(label, LV_ALIGN_TOP_MID, 0, 20);

    lv_obj_t *btn = lv_button_create(screen);
    lv_obj_set_size(btn, 120, 50);
    lv_obj_align(btn, LV_ALIGN_CENTER, 0, 0);
    lv_obj_t *btn_label = lv_label_create(btn);
    lv_label_set_text(btn_label, "Click Me");
    lv_obj_center(btn_label);
    // 注册点击事件回调
    lv_obj_add_event_cb(btn, btn_click_cb, LV_EVENT_CLICKED, NULL);
}

static void btn_click_cb(lv_event_t *e) {
    static int count = 0;
    lv_obj_t *btn = lv_event_get_target(e);
    lv_obj_t *label = lv_obj_get_child(btn, 0);
    count++;
    lv_label_set_text_fmt(label, "Clicked %d", count);
}

// 主循环中周期性调用（建议 5~30ms 一次，或用定时器）
while (1) {
    lv_timer_handler();  // 处理 LVGL 内部定时器、动画、输入、渲染
    vTaskDelay(pdMS_TO_TICKS(5));
}
```

### 7.2 TouchGFX 概览

TouchGFX 是 ST 推出的商业级嵌入式 GUI 框架，专为 STM32 优化，C++ 编写，免费使用（ST 芯片上）。

| 特点 | 说明 |
| --- | --- |
| **架构** | Model-View-Presenter（MVP）架构，UI 与业务逻辑分离 |
| **渲染** | 基于 DMA2D（Chrom-ART 硬件 2D 加速）+ LTDC/RGB 接口，硬件加速渲染 |
| **工具链** | TouchGFX Designer（可视化拖拽 UI 设计器）+ TouchGFX Generator（CubeMX 集成） |
| **性能** | 针对 STM32 深度优化，支持 60fps 动画、平滑滚动、Alpha 混合 |
| **资源** | 图片/字体自动转换为内部格式（位图压缩、字体子集化），Flash 占用优化 |
| **许可** | 免费（仅限 STM32 芯片），源码可见 |

TouchGFX 的典型工作流：在 TouchGFX Designer 中拖拽设计 UI → 生成 C++ 代码 → 在 CubeMX 中配置硬件（LTDC/DMA2D/触摸屏）→ 编写业务逻辑（Model 层）→ 编译烧录。

### 7.3 LVGL vs TouchGFX 对比

| 维度 | LVGL | TouchGFX |
| --- | --- | --- |
| **语言** | 纯 C | C++ |
| **许可** | MIT（完全免费，任意芯片） | 免费（仅限 STM32 芯片） |
| **芯片支持** | 任意 MCU/MPU（STM32/ESP32/nRF5/i.MX/RK…） | 仅 STM32 |
| **硬件加速** | 可选（DMA2D/PXP/GPU 需自行对接 flush_cb） | 原生支持 STM32 DMA2D/Chrom-ART |
| **可视化设计器** | 有（LVGL SquareLine Studio，部分功能付费） | 有（TouchGFX Designer，免费完整） |
| **最小 Flash/RAM** | ~64KB Flash / ~16KB RAM | ~128KB Flash / ~32KB RAM（含框架） |
| **架构模式** | 灵活（无强制模式，可自行组织） | MVP（强制分层，适合大型项目） |
| **控件丰富度** | 丰富（30+ 控件，含 Chart/Table/Keyboard） | 丰富（开箱即用，动画效果更精致） |
| **学习曲线** | 中等（C 语言，API 直观） | 中等（C++ + MVP + Designer，概念多） |
| **社区/生态** | 极大（GitHub 15k+ star，多平台活跃） | 较大（ST 官方支持，STM32 社区） |
| **适用场景** | 跨芯片项目、资源极紧设备、开源偏好、快速原型 | STM32 项目、需要精致动画、量产产品、团队偏好 C++ |

> **选型建议**：① 芯片不是 STM32 → 只能选 LVGL；② STM32 + 需要最精致的动画效果 + 团队熟悉 C++ → TouchGFX；③ STM32 + 团队偏好 C + 希望代码可控 → LVGL；④ 资源极紧（<128KB Flash）→ LVGL（TouchGFX 最小占用更大）；⑤ 需要跨平台/未来可能换芯片 → LVGL。
