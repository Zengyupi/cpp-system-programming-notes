## 1. 系统全景与自动驾驶分级

### 1.1 一条完整数据链路

```text
传感器(摄像头/激光LiDAR/毫米波雷达/超声波/IMU/GNSS/轮速)
  → 传感器驱动 + 时间同步(PTP/gPTP) + 外参标定
  → 感知(检测/分割/跟踪/车道线/可行驶区域) ┐
  → 多传感器融合(前/后/深度融合)           ├→ 世界模型(障碍物列表 + 语义地图)
  → 定位(高精地图匹配 / SLAM / 组合导航)    ┘
  → 预测(他车/行人未来轨迹)
  → 规划：全局路由 → 行为决策(变道/跟车/绕行) → 运动规划(平滑轨迹)
  → 控制：纵向(油门/刹车 ACC) + 横向(转向 LKA)
  → 线控执行(底盘 CAN/以太网)，全程功能安全兜底(降级/MRC 最小风险策略)
```

### 1.2 SAE 自动驾驶分级（J3016，面试常问）

| 级别 | 名称 | 谁监控环境/负责 | 典型 |
| --- | --- | --- | --- |
| L0 | 无自动化 | 人 | 仅报警(FCW/BSD) |
| L1 | 驾驶员辅助 | 人，系统做一项 | 定速巡航/车道保持单项 |
| L2 | 部分自动化 | **人全程负责**，系统同时做纵横向 | NOA 之前的 ACC+LKA（当前量产主流 L2++） |
| L3 | 有条件自动化 | **ODD 内系统负责**，人需接管 | 拥堵领航、高速 L3（脱手脱眼，要接管冗余） |
| L4 | 高度自动化 | ODD 内无人 | Robotaxi、限定园区物流 |
| L5 | 完全自动化 | 全场景无人 | 尚无量产 |

> ODD（设计运行域）：天气/车速/区域/光照等系统被设计能工作的范围；**MRC（最小风险策略）**：系统搞不定时自动靠边停车/双闪，而不是直接撒手。

## 2. 感知：从 2D 检测到 BEV 大模型

### 2.1 各传感器优劣与互补

| 传感器 | 优势 | 短板 | 用途 |
| --- | --- | --- | --- |
| 摄像头 | 语义丰富（认颜色/文字/类别）、便宜 | 受光照/雨雾影响、无直接深度、测距靠估计 | 检测、车道线、红绿灯、语义分割 |
| 激光雷达 LiDAR | 精确三维点云、夜间可用 | 贵、雨雪衰减、无颜色语义 | 测距、障碍物、点云检测/SLAM |
| 毫米波雷达 | 测速准(多普勒)、穿透雨雾、便宜 | 角分辨率低、静止物识别弱 | ACC、AEB、变道盲区 |
| 超声波 | 近距便宜可靠 | 距离极短 | 泊车、低速 UPA/APA |
| IMU | 高频(数百~kHz)、不依赖外部 | 积分漂移 | 组合导航、帧间运动补偿 |
| GNSS/RTK | 全局定位 | 遮挡/多径、更新慢 | 全局基准 |

**融合为什么必要**：没有任何单一传感器全天候可靠——摄像头怕逆光、LiDAR 怕大雨、雷达认不清静止物。融合是用冗余换安全。

### 2.2 融合的三个层级（演进方向）

| 层级 | 做法 | 特点 |
| --- | --- | --- |
| 后融合（目标级） | 各传感器先各自出目标框，再融合目标列表 | 工程简单、算力低，但丢原始信息 |
| 前融合（特征级） | 把多传感器特征在网络中间对齐融合 | 信息保留多，是当前主流 |
| **BEV/Occupancy（数据级/鸟瞰统一空间）** | 多路相机/雷达投影到统一鸟瞰 BEV 网格，甚至体素占据 Occupancy | 跨视角统一、能识别异形障碍/通用障碍物，Transformer 时代方案 |

### 2.3 为什么行业转向 BEV + Transformer

- 传统多视角 2D 检测要在图像空间分别检测再投影回 3D，跨相机目标被截断、重叠难处理；
- **BEV**：用视角变换把多相机特征"抬到车辆俯视坐标系"，在统一空间里做检测/车道/融合，天然支持多相机拼接和时序融合（带历史帧的 BEV 队列）；
- **Occupancy Network（占据网格）**：不依赖"先验类别"，直接预测每个三维体素是否被占据及语义/流场，能处理掉落轮胎、侧翻货车这类**没见过的异形障碍物**（这是纯目标检测的盲区）；
- 再往上是**端到端 / 世界模型**（感知到规控一个网络，如 UniAD 思路），是研究热点，量产仍以模块化为主。

### 2.4 经典感知任务与算法

| 任务 | 传统/经典 | 深度方案 |
| --- | --- | --- |
| 2D 检测 | HOG+SVM | YOLO 系列、Faster R-CNN、DETR |
| 3D/点云检测 | 聚类、地面分割(RANSAC) | PointPillars、CenterPoint、PV-RCNN |
| 语义/实例分割 | 分水岭、区域生长 | U-Net、Mask R-CNN、SegFormer |
| 多目标跟踪 | 卡尔曼滤波 + 匈牙利匹配 | SORT/DeepSORT、3D 跟踪(AB3DMOT) |

## 3. 定位：我在哪

| 方案 | 原理 | 适用/问题 |
| --- | --- | --- |
| GNSS + RTK | 卫星差分，厘米级 | 开阔好，隧道/城市峡谷失效 |
| **组合导航(INS)** | IMU 高频递推 + GNSS 低频校正，卡尔曼/误差状态 EKF 融合 | 主力方案，短时遮挡靠 IMU 顶住 |
| LiDAR 定位 | 实时点云和高精地图配准（**NDT/ICP**） | 精度高，依赖高精地图和特征 |
| 视觉 SLAM/VIO | 相机 + IMU 建图定位（ORB-SLAM3、VINS-Fusion） | 无图方案、室内机器人 |
| 重感知/无图方案 | 不依赖提前建高精地图，靠实时感知车道/地标 | 降本、覆盖广，是量产趋势（轻地图/无图 NOA） |

**SLAM 三要素**：前端里程计（相邻帧运动估计）+ 后端优化（位姿图/因子图，g2o、GTSAM、Ceres）+ 回环检测（词袋 BoW/场景识别，消除累积漂移）。激光系：LOAM、LIO-SAM、FAST-LIO2；视觉系：ORB-SLAM、VINS。

## 4. 预测：他接下来要往哪走（最容易被忽略的一环）

感知回答"现在周围有什么"，**预测回答"接下来几秒它们会怎样"**，是规划的前提：
- **物理模型**：恒速/恒加速度/卡尔曼外推，适合短时；
- **机动/意图识别**：分类（直行/左转/并线/刹车），结合地图车道拓扑算概率；
- **轨迹预测**：输出多模态未来轨迹 + 概率（如 PGP、MTR、Transformer 轨迹网络），必须是**多模态**的（一辆车可能直行也可能并线，不能只给一条）；
- 交互建模：路口人车博弈，用博弈论/图神经网络建模互相影响。

## 5. 规划：分三层，别混

```text
全局路由 Routing（A* 在高精地图路网找"走哪条路"，分钟级，类似导航）
   └→ 行为决策 Behavior（跟车/超车/变道/让行/停车，状态机或学习策略，秒级）
        └→ 运动规划 Motion（生成一条平滑、舒适、无碰撞、满足动力学的轨迹，百毫秒级）
```

| 层 | 代表方法 |
| --- | --- |
| 路由 | Dijkstra、A*（在有向图路网） |
| 行为决策 | 有限状态机 FSM、决策树、POMDP、强化学习（量产仍以规则 FSM 为主，可解释、安全） |
| 运动规划 | 采样类 RRT*/Lattice、搜索类 Hybrid A*、优化类 EM Planner、QP/样条曲线（贝塞尔/B 样条/五次多项式） |
| 机器人局部避障 | DWA 动态窗口、TEB 时间弹性带 |

好轨迹的标准：**无碰撞、满足车辆运动学（阿克曼转向，不能横移）、曲率连续、舒适（加加速度 jerk 小）、离参考线近**。

## 6. 控制：让车跟上轨迹

| 算法 | 说明 | 场景 |
| --- | --- | --- |
| PID | 比例-积分-微分，不依赖模型、最常用 | 纵向速度、简单横向 |
| LQR | 线性二次型调节器，最优反馈、需线性模型 | 横向控制（前轮转角） |
| **MPC 模型预测控制** | 建车辆动力学模型，**滚动优化未来 N 步**并显式处理约束（转角/加速度上限） | 中高阶横纵向一体，自动驾驶主流 |
| 纯追踪 Pure Pursuit | 几何法追前视点 | 简单横向、机器人 |

```cpp
// PID 位置式（离散）：err 积分消静差，微分项抑制超调
double pid(double target, double cur, double dt) {
    double err = target - cur;
    integral = clamp(integral + err * dt, -I, I);     // 积分本身限幅，防止积分饱和(windup)
    double deriv = (err - prevErr) / dt;
    prevErr = err;
    return Kp * err + Ki * integral + Kd * deriv;
}
// MPC 思路：在每个控制周期，用模型预测未来 N 步轨迹，解一个带约束的二次规划(QP)，
//          只执行第一步，下一周期重新解（滚动时域），因此能处理约束和模型误差。
```

## 7. ROS / ROS2：机器人与自动驾驶的"操作系统"

### 7.1 核心概念

| 概念 | 说明 |
| --- | --- |
| 节点 Node | 一个独立进程/功能单元（感知节点、规划节点） |
| 话题 Topic | **发布/订阅**、异步、多对多，适合数据流 |
| 服务 Service | 请求/响应、同步、一对一，适合偶发命令 |
| 动作 Action | 带反馈、可取消的长任务（导航到某点） |
| 参数 Parameter | 运行时可调配置 |
| TF 坐标变换树 | 统一管理各传感器/底盘坐标系（base_link/lidar/map/odom） |
| launch/包 | 启动编排、功能包管理 |

```cpp
// ROS2 C++ 发布/订阅（rclcpp）
auto pub = node->create_publisher<std_msgs::msg::String>("topic", 10);
pub->publish(msg);
auto sub = node->create_subscription<std_msgs::msg::String>(
    "topic", 10, [](const std_msgs::msg::String::SharedPtr m){ /*回调*/ });
```

### 7.2 ROS1 vs ROS2（面试高频，也是车载化的关键）

| 维度 | ROS1 | ROS2 |
| --- | --- | --- |
| 中间件 | 自研 TCP/UDP（roscore 单点） | **基于 DDS**（可换 FastDDS/Cyclone） |
| 实时性 | 弱、无 QoS 保障 | **QoS 策略**（可靠性/历史深度/截止期）、支持实时 |
| 去中心化 | 依赖 master，单点故障 | 无 master，自动发现（discovery） |
| 多机/安全 | 弱 | 原生多机、DDS-Security 加密认证 |
| 生命周期 | 无 | Lifecycle 受管节点（可控初始化/激活/关停） |
| 语言/平台 | C++/Python、主要 Linux | C++/Python，支持实时 OS、Windows/嵌入式 |

> **DDS 正是车载 SOA 中间件之一**（和 SOME/IP 并列，见《01-汽车软件与智能驾驶方向.md》）。ROS2 用 DDS 说明机器人和车载中间件在收敛：都是"去中心化发现 + 发布订阅 + QoS + 零拷贝"。高性能场景用 **shared memory 零拷贝传输**（iceoryx、FastDDS SHM），避免大数据（点云/图像）反复拷贝——和后台的零拷贝是同一思想。

| 领域 | 常用库/工具 |
| --- | --- |
| 线性代数/几何 | Eigen（必备）、Sophus（李群李代数）、tf2 |
| 点云 | PCL、libpointmatcher；GPU 用 CUDA-PointPillars |

| 构建/部署 | colcon、CMake、交叉编译、Docker、实时内核 PREEMPT_RT |

工程要点（C++ 后台经验直接用得上）：
- **实时性**：热点路径避免动态内存（预分配/内存池）、避免系统调用阻塞、关键线程绑核 + 高优先级、用无锁队列，见《../04-并发编程/01-线程基础与生命周期.md》《../13-并发异步与组件/06-无锁编程基础.md》；
- **时间同步**：多传感器必须硬件时钟同步（PTP/gPTP），并对运动中的点云/图像做**运动补偿（去畸变）**，否则融合错位；
- **坐标系**：严格管理 TF 树与外参，单位/坐标系（车体/雷达/世界）搞错是最常见 bug；
- **确定性与可复现**：固定随机种子、记录 rosbag 回放回归。

## 11. 常见问题与坑

1. **多传感器时间戳没硬件同步**：融合时各帧对不上，运动中尤其明显——必须 PTP 同步 + 点云去畸变。
2. **坐标系/外参混乱**：base_link/lidar/camera/map 变换错，目标位置整体偏移；统一走 TF 树并标定外参。
3. 只做单条轨迹预测：他车意图是多模态的，单条轨迹在路口必然失真。
4. 规划轨迹曲率不连续/忽略车辆运动学：车不是全向轮，不能横移，跟踪时画龙。
5. PID 积分不限位导致 windup，或参数不整定造成震荡/迟滞。
6. ROS 话题消息过大、频率过高导致丢帧/延迟：用零拷贝共享内存、压缩、降频或换 DDS QoS。
7. SLAM 无回环检测，长时间运行累积漂移；动态物体没剔除污染地图。
8. 仿真表现好、实车不行：没建模传感器噪声、通信延迟、执行器滞后——重视实车在环与 rosbag 回归。
9. 一上来追求端到端大模型：量产要可解释、功能安全，模块化仍是主力，先把管线工程做扎实。
