## 1. 渲染管线（Rendering Pipeline）

渲染管线是 GPU 将 3D 顶点数据转化为 2D 像素图像的固定流程，分为**应用阶段（CPU）→ 几何阶段（GPU 顶点处理）→ 光栅化阶段（GPU 片元处理）**：

```text
应用阶段(CPU)          几何阶段(GPU)                    光栅化阶段(GPU)
┌──────────────┐   ┌──────────────────────┐   ┌──────────────────────────┐
│ 场景数据准备   │   │ 顶点着色器            │   │ 图元装配(三角形)          │
│ 视锥剔除      │──→│ (模型视图投影变换)    │──→│ 光栅化(片元生成)          │──→ 帧缓冲
│ 绘制调用提交  │   │ 曲面细分/几何着色器(可选)│   │ 片元着色器(光照/纹理采样) │   (屏幕)
│ 状态设置      │   │ 裁剪/透视除法/屏幕映射 │   │ 深度测试/模板测试/混合     │
└──────────────┘   └──────────────────────┘   └──────────────────────────┘
```

| 阶段 | 说明 | 可编程性 |
| --- | --- | --- |
| 顶点着色器 Vertex Shader | 逐顶点执行，坐标变换（MVP）、法线变换、UV 传递 | **完全可编程** |
| 曲面细分 Tessellation | 将低模曲面细分为高模（Hull + Domain Shader） | 可选，可编程 |
| 几何着色器 Geometry Shader | 逐图元执行，可增删顶点（如生成公告板） | 可选，可编程 |
| 图元装配 Assembly | 顶点组装为点/线/三角形 | 固定功能 |
| 光栅化 Rasterization | 三角形覆盖哪些像素，生成片元（Fragment） | 固定功能 |
| 片元着色器 Fragment Shader | 逐片元执行，计算颜色（光照、纹理、法线贴图） | **完全可编程** |
| 输出合并 Output Merger | 深度测试、模板测试、Alpha 混合 | 固定功能（状态可配） |

### 1.1 一个最小 GLSL 顶点+片元着色器

```glsl
// 顶点着色器
#version 330 core
layout(location = 0) in vec3 aPos;
layout(location = 1) in vec3 aNormal;
layout(location = 2) in vec2 aTexCoord;

uniform mat4 model;
uniform mat4 view;
uniform mat4 projection;

out vec3 FragPos;
out vec3 Normal;
out vec2 TexCoord;

void main() {
    FragPos = vec3(model * vec4(aPos, 1.0));
    Normal = mat3(transpose(inverse(model))) * aNormal;  // 法线矩阵
    TexCoord = aTexCoord;
    gl_Position = projection * view * model * vec4(aPos, 1.0);
}
```

```glsl
// 片元着色器（Blinn-Phong + 纹理）
#version 330 core
in vec3 FragPos;
in vec3 Normal;
in vec2 TexCoord;

uniform vec3 lightPos;
uniform vec3 viewPos;
uniform sampler2D texture_diffuse;

out vec4 FragColor;

void main() {
    vec3 norm = normalize(Normal);
    vec3 lightDir = normalize(lightPos - FragPos);
    vec3 viewDir = normalize(viewPos - FragPos);
    vec3 halfwayDir = normalize(lightDir + viewDir);

    vec3 ambient = 0.1 * texture(texture_diffuse, TexCoord).rgb;
    float diff = max(dot(norm, lightDir), 0.0);
    vec3 diffuse = diff * texture(texture_diffuse, TexCoord).rgb;
    float spec = pow(max(dot(norm, halfwayDir), 0.0), 32.0);
    vec3 specular = 0.5 * spec * vec3(1.0);

    FragColor = vec4(ambient + diffuse + specular, 1.0);
}
```

## 2. 坐标变换：从模型空间到屏幕空间

```text
模型空间(Local)  →(Model矩阵)→  世界空间(World)  →(View矩阵)→  观察空间(View/Eye)
  →(Projection矩阵)→  裁剪空间(Clip)  →(透视除法)→  NDC  →(视口变换)→  屏幕空间(Screen)
```

- **MVP 矩阵** = Projection × View × Model（列主序下右乘，注意乘法顺序）；
- **透视投影**：近大远小，用 `glm::perspective(fov, aspect, near, far)`；
- **正交投影**：等比例，无透视变形，用于 2D/UI/CAD；
- **法线变换**：法线不能直接用 Model 矩阵（非均匀缩放会变形），需用 `transpose(inverse(model))` 的左上 3×3。

```cpp
// glm 计算 MVP（C++）
glm::mat4 model = glm::mat4(1.0f);
model = glm::rotate(model, glm::radians(angle), glm::vec3(0, 1, 0));
glm::mat4 view = glm::lookAt(cameraPos, target, up);
glm::mat4 proj = glm::perspective(glm::radians(45.0f), aspect, 0.1f, 100.0f);
glm::mat4 mvp = proj * view * model;  // 列主序：proj * view * model
```

## 3. 图形 API 对比

| 维度 | OpenGL | Vulkan | DirectX 12 | Metal |
| --- | --- | --- | --- | --- |
| 抽象层次 | 高（驱动帮你管状态/内存） | 低（显式控制一切） | 低（显式） | 低（显式） |
| 性能 | 好 | **更好（多线程、低驱动开销）** | 好 | 好 |
| 复杂度 | 低 | **高（样板代码多，需手动管同步/内存）** | 中高 | 中 |
| 跨平台 | 全平台（含移动端 ES） | 全平台（Android/Windows/Linux） | Windows/Xbox | Apple 全系 |
| 状态管理 | 隐式全局状态机 | 显式管线状态对象(PSO) | PSO | PSO |
| 学习曲线 | 平缓 | 陡峭 | 中 | 中 |

> 选型建议：学习入门用 OpenGL（概念清晰、代码少）；追求高性能/跨平台用 Vulkan；Windows/Xbox 生态用 DirectX 12；Apple 平台用 Metal。现代引擎通常封装一层 RHI（Rendering Hardware Interface）屏蔽 API 差异。

## 4. 光照模型

| 模型 | 组成 | 特点 |
| --- | --- | --- |
| 环境光 Ambient | 恒定基底光照 | 模拟间接光，避免全黑 |
| 漫反射 Diffuse | Lambert：`max(N·L, 0)` | 与视角无关，粗糙表面 |
| 镜面反射 Specular | Phong / Blinn-Phong | 高光，Blinn-Phong 用半程向量更高效稳定 |
| **PBR（基于物理渲染）** | 金属度(Metallic) + 粗糙度(Roughness) + Fresnel + 微表面分布 | 物理正确，材质参数直观，现代游戏/引擎主流 |

### 4.1 PBR 核心思想

PBR 基于微表面理论（Microfacet Theory）：
- **BRDF（双向反射分布函数）**：描述光线如何在表面反射，常用 Cook-Torrance 模型；
- **金属度 Metallic**：0=电介质（非金属），1=金属；金属没有漫反射，反射颜色 = 基础色；
- **粗糙度 Roughness**：0=镜面光滑，1=完全漫反射；微表面法线分布越集中高光越锐利；
- **Fresnel 效应**：掠射角反射率升高（Schlick 近似）；
- **能量守恒**：反射光 ≤ 入射光，漫反射 + 镜面反射 ≤ 1。

```glsl
// PBR 片元着色器核心（简化版 Cook-Torrance）
float DistributionGGX(vec3 N, vec3 H, float roughness) {
    float a = roughness * roughness;
    float a2 = a * a;
    float NdotH = max(dot(N, H), 0.0);
    float denom = (NdotH * NdotH * (a2 - 1.0) + 1.0);
    return a2 / (3.14159 * denom * denom);
}
float GeometrySchlickGGX(float NdotV, float roughness) {
    float r = roughness + 1.0;
    float k = (r * r) / 8.0;
    return NdotV / (NdotV * (1.0 - k) + k);
}
vec3 fresnelSchlick(float cosTheta, vec3 F0) {
    return F0 + (1.0 - F0) * pow(clamp(1.0 - cosTheta, 0.0, 1.0), 5.0);
}
```

## 5. 纹理与贴图技术

| 技术 | 说明 |
| --- | --- |
| UV 映射 | 2D 纹理坐标映射到 3D 表面，顶点属性传入 |
| 法线贴图 Normal Map | 用 RGB 纹理存储切线空间法线，模拟凹凸细节，不增加顶点 |
| 高度贴图/视差贴图 | 用高度图模拟深度，视差遮蔽映射(POM)更真实 |
| Mipmap | 多级缩小纹理，远距离采样避免闪烁/锯齿，三线性插值 |
| 各向异性过滤 Anisotropic | 斜视角下纹理更清晰（1x~16x） |
| 阴影贴图 Shadow Map | 从光源视角渲染深度图，比较深度判断是否在阴影中 |
| 环境贴图 IBL | 用 CubeMap 存储环境光，PBR 中做漫反射辐照 + 镜面预过滤 |
| 纹理压缩 | BCn/ASTC/ETC2，减少显存带宽和占用 |

### 5.1 阴影贴图进阶

- **PCF（Percentage Closer Filtering）**：对深度比较结果做滤波，软化阴影边缘；
- **CSM（Cascaded Shadow Maps，级联阴影）**：视锥体分多个层级，每层独立阴影图，解决远处阴影精度不足；
- **PCSS（Percentage Closer Soft Shadows）**：模拟软阴影，遮挡物越近阴影越锐利；
- **VSM/EVSM**：用方差阴影图减少锯齿，但有漏光问题。

## 6. 高级渲染技术

| 技术 | 说明 | 适用场景 |
| --- | --- | --- |
| **前向渲染 Forward** | 逐物体×逐光源计算，简单直接 | 光源少（<100）、移动端 |
| **延迟渲染 Deferred** | 先渲染 G-Buffer（位置/法线/反照率/材质），再逐光源全屏 Pass | 大量动态光源（上千）、3A 游戏 |
| **集群前向渲染 Clustered Forward** | 视锥体分簇，每簇关联光源，兼顾前向透明物体和大量光源 | 现代引擎主流（UE5、Unity HDRP） |
| **SSR（屏幕空间反射）** | 在屏幕空间做光线步进，模拟反射 | 实时反射补充，有屏幕外信息丢失问题 |
| **SSAO（屏幕空间环境光遮蔽）** | 用深度图计算角落遮蔽，增强立体感 | 几乎所有现代游戏 |
| **Bloom 泛光** | 提取高亮区域模糊后叠加，模拟光晕 | HDR 渲染、氛围 |
| **TAA（时间性抗锯齿）** | 利用历史帧累积，低采样高质量抗锯齿 | 现代游戏标配 |
| **Motion Blur 运动模糊** | 利用速度矢量模糊运动物体 | 增强速度感 |
| **Tone Mapping 色调映射** | HDR → LDR，常用 ACES 曲线 | HDR 渲染管线 |
| **光线追踪 Ray Tracing** | 追踪光线真实反射/折射/阴影，DXR/Vulkan Ray Tracing | 高端 GPU、3A 游戏 |

### 6.1 延迟渲染 G-Buffer 布局示例

```text
RT0: RGBA8   → 反照率 Albedo (RGB) + 遮罩 (A)
RT1: RGBA16F → 法线 Normal (RGB) + 粗糙度 (A)
RT2: RGBA16F → 位置 Position (RGB) + 金属度 (A)
深度缓冲: D32F → 深度值
```
光照 Pass 全屏四边形，从 G-Buffer 采样属性，逐光源计算光照。优点是光源数量与 draw call 解耦；缺点是不透明物体才能写入 G-Buffer，透明物体需前向 pass 补充。

## 7. 游戏引擎架构

```text
┌─────────────────────────────────────────────┐
│ 游戏逻辑层（脚本/业务：C#/Lua/蓝图/行为树）    │
├─────────────────────────────────────────────┤
│ 引擎功能层                                   │
│ 渲染器 · 物理 · 动画 · 音频 · AI · 输入 · UI  │
├─────────────────────────────────────────────┤
│ 核心层（Foundation）                          │
│ 内存管理 · 线程/任务系统 · 资源管理 · 数学库   │
│ 容器 · 序列化 · 日志 · 事件系统               │
├─────────────────────────────────────────────┤
│ 平台层（Platform Abstraction）                │
│ 窗口 · 文件IO · 时间 · 线程 · 图形API抽象(RHI) │
└─────────────────────────────────────────────┘
```

### 7.1 ECS（实体组件系统）

现代引擎（Unity DOTS、Bevy、自研）常用 ECS 替代传统 OOP 继承树：
- **Entity（实体）**：仅一个 ID，不含数据和行为；
- **Component（组件）**：纯数据结构体（Position、Velocity、MeshRenderer）；
- **System（系统）**：处理具有特定组件组合的所有实体，逐组件数组连续遍历，缓存友好；
- 优势：数据导向设计（DOD），内存连续、易并行、组合优于继承。

### 7.2 核心子系统

| 子系统 | 职责 | 关键技术 |
| --- | --- | --- |
| 渲染器 | 场景剔除、绘制排序、管线执行 | 视锥剔除、遮挡剔除、批次合并、Instancing |
| 物理 | 碰撞检测、刚体模拟、角色控制 | 碰撞体(BVTree/AABB/OBB)、约束求解、连续碰撞检测 |
| 动画 | 骨骼动画、状态机、混合树、IK | 蒙皮(Skinning)、Animation Compression、Runtime IK |
| 音频 | 3D 音效、混音、流式加载 | FMOD/Wwise、HRTF、音频线程 |
| 资源管理 | 加载/卸载/热重载 | 引用计数、句柄、异步加载、资源打包 |
| 场景管理 | 空间划分、可见性 | 八叉树/BVH/Portal、LOD |

## 8. 游戏主循环与时间步

```cpp
while (running) {
    processInput();           // 采集输入
    // 固定时间步更新物理/逻辑（与帧率解耦）
    accumulator += dt;
    while (accumulator >= FIXED_DT) {
        update(FIXED_DT);     // 物理、AI、游戏逻辑
        accumulator -= FIXED_DT;
    }
    render(alpha);            // 渲染，alpha 用于插值
    swapBuffers();            // 交换前后缓冲（避免撕裂）
    limitFPS();               // 可选帧率限制
}
```

- **固定时间步**：物理模拟用固定 dt（如 1/60s），保证不同帧率下物理一致；
- **插值**：渲染时用 accumulator/FIXED_DT 做位置插值，避免卡顿；
- **双缓冲/三缓冲**：避免画面撕裂，三缓冲可降低输入延迟。

## 12. 常见问题与坑

1. **未做深度测试或深度缓冲未清除**：渲染错乱，物体前后关系不对，确保 `glEnable(GL_DEPTH_TEST)` 且每帧 `glClear(GL_DEPTH_BUFFER_BIT)`。
2. **纹理坐标与顶点数据不匹配**：贴图拉伸/错位，检查 VAO 顶点属性布局和 VBO 数据步长。
3. **MVP 矩阵乘法顺序错误**：列主序下应为 `proj * view * model`，写反会导致物体不可见或变形。
4. **每帧频繁创建/销毁 GPU 资源**：性能暴跌，资源应在加载阶段创建，运行时复用。
5. **逻辑帧率与渲染帧率耦合**：不同设备表现不一致，用固定时间步解耦物理和渲染。
6. **法线用 Model 矩阵直接变换**：非均匀缩放导致法线不再垂直表面，必须用法线矩阵 `transpose(inverse(model))`。
7. **阴影失真（Shadow Acne）**：深度精度问题，加深度偏移(bias)或用 PCF 滤波。
8. **延迟渲染透明物体丢失**：透明物体不写 G-Buffer，需额外前向 pass 渲染透明物体。
9. **Draw Call 过多**：CPU 瓶颈，用 Instancing、静态合批、减少状态切换。
10. **显存泄漏**：GPU 资源（纹理/缓冲/Shader）未释放，长期运行显存增长，用渲染doc/NSight 排查。
