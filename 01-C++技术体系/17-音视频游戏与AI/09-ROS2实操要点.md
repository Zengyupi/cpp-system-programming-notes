## 1. ROS2 架构概述

### 1.1 DDS 中间件

ROS2 底层基于 **DDS**（Data Distribution Service），这是 OMG 标准化的分布式实时通信中间件，广泛用于国防、航空、工业自动化。

```text
┌─────────────────────────────────────────────────────┐
│                  ROS2 应用层                         │
│  rclcpp / rclpy（ROS Client Library）                │
├─────────────────────────────────────────────────────┤
│                  ROS 中间件层（RMW）                  │
│  rmw_fastrtps / rmw_cyclonedds / rmw_connextdds     │
├─────────────────────────────────────────────────────┤
│                  DDS 实现层                          │
│  Fast-DDS / Cyclone DDS / RTI Connext DDS           │
├─────────────────────────────────────────────────────┤
│                  传输层（UDP/TCP/Shared Memory）      │
└─────────────────────────────────────────────────────┘
```

| DDS 实现 | 开发商 | 特点 |
| --- | --- | --- |
| **Fast-DDS** | eProsima | ROS2 默认，开源，轻量 |
| **Cyclone DDS** | Eclipse | 开源，低延迟，适合嵌入式 |
| **RTI Connext** | RTI | 商业版，功能最全，认证级 |

DDS 核心概念：
- **Domain Participant**：DDS 域参与者，对应一个 ROS2 Node
- **Topic**：数据主题，发布订阅的通道
- **DataWriter/DataReader**：发布者/订阅者
- **QoS**：服务质量策略，控制可靠性、持久性等
- **Discovery**：自动发现，无需中心化 master

### 1.2 Node/Topic/Service/Action/Parameter

| 通信机制 | 模式 | 适用场景 | 特点 |
| --- | --- | --- | --- |
| **Topic** | 发布/订阅（异步） | 传感器数据、状态广播 | 一对多，持续流数据 |
| **Service** | 请求/响应（同步） | 触发计算、查询状态 | 一对一，一次性 |
| **Action** | 目标/反馈/结果（异步） | 导航、机械臂运动 | 可取消、可反馈进度 |
| **Parameter** | 键值配置 | 节点参数配置 | 可动态修改 |
| **Lifecycle** | 状态机管理 | 节点生命周期 | 配置/激活/停用/清理 |

```text
Topic（数据流）：
  Node A ──publish──> /camera/image ──subscribe──> Node B
                                      ──subscribe──> Node C

Service（请求响应）：
  Node A ──request──> /add_two_ints ──response──> Node B（唯一 Server）

Action（长任务）：
  Node A ──send goal──> /navigate_to_pose
  Node A <──feedback─── Node B（进度：50%）
  Node A <──result───── Node B（成功到达）
  Node A ──cancel goal─> Node B（可取消）
```

## 2. 话题通信

### 2.1 发布订阅实现

C++ 发布者：

```cpp
#include <rclcpp/rclcpp.hpp>
#include <std_msgs/msg/string.hpp>

class MinimalPublisher : public rclcpp::Node {
public:
    MinimalPublisher() : Node("minimal_publisher"), count_(0) {
        publisher_ = this->create_publisher<std_msgs::msg::String>("topic", 10);
        timer_ = this->create_wall_timer(
            std::chrono::milliseconds(500),
            std::bind(&MinimalPublisher::timer_callback, this));
    }
private:
    void timer_callback() {
        auto message = std_msgs::msg::String();
        message.data = "Hello, ROS2! " + std::to_string(count_++);
        RCLCPP_INFO(this->get_logger(), "Publishing: '%s'", message.data.c_str());
        publisher_->publish(message);
    }
    rclcpp::Publisher<std_msgs::msg::String>::SharedPtr publisher_;
    rclcpp::TimerBase::SharedPtr timer_;
    size_t count_;
};

int main(int argc, char *argv[]) {
    rclcpp::init(argc, argv);
    rclcpp::spin(std::make_shared<MinimalPublisher>());
    rclcpp::shutdown();
    return 0;
}
```

C++ 订阅者：

```cpp
#include <rclcpp/rclcpp.hpp>
#include <std_msgs/msg/string.hpp>

class MinimalSubscriber : public rclcpp::Node {
public:
    MinimalSubscriber() : Node("minimal_subscriber") {
        subscription_ = this->create_subscription<std_msgs::msg::String>(
            "topic", 10,
            std::bind(&MinimalSubscriber::topic_callback, this, std::placeholders::_1));
    }
private:
    void topic_callback(const std_msgs::msg::String::SharedPtr msg) const {
        RCLCPP_INFO(this->get_logger(), "I heard: '%s'", msg->data.c_str());
    }
    rclcpp::Subscription<std_msgs::msg::String>::SharedPtr subscription_;
};
```

### 2.2 QoS 策略详解

QoS（Quality of Service）是 ROS2 相比 ROS1 的核心改进，通过 DDS QoS 控制通信质量。

```cpp
#include <rclcpp/qos.hpp>

// 自定义 QoS
rclcpp::QoS custom_qos(rclcpp::KeepLast(10));
custom_qos.reliability(RMW_QOS_POLICY_RELIABILITY_RELIABLE);
custom_qos.durability(RMW_QOS_POLICY_DURABILITY_TRANSIENT_LOCAL);
custom_qos.history(RMW_QOS_POLICY_HISTORY_KEEP_LAST);
custom_qos.deadline(std::chrono::milliseconds(100));
custom_qos.lifespan(std::chrono::seconds(5));

auto pub = node->create_publisher<std_msgs::msg::String>("topic", custom_qos);
```

| QoS 策略 | 可选值 | 说明 |
| --- | --- | --- |
| **Reliability** | `RELIABLE` / `BEST_EFFORT` | 可靠（重传）vs 尽力而为（不重传） |
| **Durability** | `VOLATILE` / `TRANSIENT_LOCAL` | 临时 vs 持久（晚加入的订阅者能收到最后一条） |
| **History** | `KEEP_LAST` / `KEEP_ALL` | 保留最近 N 条 vs 保留全部 |
| **Depth** | 整数 | KEEP_LAST 时的队列深度 |
| **Deadline** | 时间 | 期望的消息最大间隔，超时触发事件 |
| **Lifespan** | 时间 | 消息过期时间 |
| **Liveliness** | `AUTOMATIC` / `MANUAL_BY_TOPIC` | 存活检测方式 |

**QoS 兼容性规则**：发布者和订阅者的 QoS 必须兼容才能通信：
- Reliability：发布者 RELIABLE，订阅者可 RELIABLE 或 BEST_EFFORT；发布者 BEST_EFFORT，订阅者只能 BEST_EFFORT
- Durability：发布者 TRANSIENT_LOCAL，订阅者可 TRANSIENT_LOCAL 或 VOLATILE

常用预设：
- `rclcpp::SensorDataQoS()`：BEST_EFFORT + KeepLast(5)，适合传感器（激光雷达、相机）
- `rclcpp::ParametersQoS()`：RELIABLE + TRANSIENT_LOCAL，适合参数
- `rclcpp::SystemDefaultsQoS()`：默认配置

## 3. 服务与参数

### 3.1 服务通信（请求响应）

服务定义（`srv/AddTwoInts.srv`）：

```text
int64 a
int64 b
---
int64 sum
```

服务端：

```cpp
#include <rclcpp/rclcpp.hpp>
#include <example_interfaces/srv/add_two_ints.hpp>

class AddTwoIntsServer : public rclcpp::Node {
public:
    AddTwoIntsServer() : Node("add_two_ints_server") {
        service_ = this->create_service<example_interfaces::srv::AddTwoInts>(
            "add_two_ints",
            std::bind(&AddTwoIntsServer::handle_service, this,
                      std::placeholders::_1, std::placeholders::_2));
    }
private:
    void handle_service(
        const std::shared_ptr<example_interfaces::srv::AddTwoInts::Request> request,
        std::shared_ptr<example_interfaces::srv::AddTwoInts::Response> response) {
        response->sum = request->a + request->b;
        RCLCPP_INFO(this->get_logger(), "Incoming request: %ld + %ld", request->a, request->b);
    }
    rclcpp::Service<example_interfaces::srv::AddTwoInts>::SharedPtr service_;
};
```

客户端：

```cpp
auto client = node->create_client<example_interfaces::srv::AddTwoInts>("add_two_ints");
while (!client->wait_for_service(std::chrono::seconds(1))) {
    RCLCPP_INFO(node->get_logger(), "等待服务上线...");
}
auto request = std::make_shared<example_interfaces::srv::AddTwoInts::Request>();
request->a = 40;
request->b = 2;
auto future = client->async_send_request(request);
// 等待响应（在 executor 中 spin）
```

### 3.2 参数服务器

ROS2 参数是节点级的，每个节点维护自己的参数（不同于 ROS1 的全局参数服务器）。

```cpp
// 声明参数
this->declare_parameter<std::string>("robot_name", "turtlebot");
this->declare_parameter<int>("max_speed", 5);
this->declare_parameter<double>("kp", 1.5);

// 读取参数
std::string robot_name = this->get_parameter("robot_name").as_string();
int max_speed = this->get_parameter("max_speed").as_int();

// 动态修改参数回调
auto param_callback = this->add_on_set_parameters_callback(
    [](const std::vector<rclcpp::Parameter> &params) {
        auto result = rcl_interfaces::msg::SetParametersResult();
        result.successful = true;
        for (const auto &p : params) {
            if (p.get_name() == "max_speed" && p.as_int() > 10) {
                result.successful = false;
                result.reason = "max_speed 不能超过 10";
            }
        }
        return result;
    });
```

命令行操作参数：

```bash
ros2 param list /my_node                    # 列出参数
ros2 param get /my_node max_speed           # 获取参数
ros2 param set /my_node max_speed 8         # 设置参数
ros2 param dump /my_node                    # 导出所有参数到 YAML
ros2 run my_pkg my_node --ros-args -p max_speed:=8  # 启动时传参
```

## 4. 开发环境与构建

### 4.1 colcon 构建系统

colcon 是 ROS2 的官方构建工具，替代 ROS1 的 catkin_make/catkin build。

```bash
# 创建工作空间
mkdir -p ~/ros2_ws/src
cd ~/ros2_ws

# 构建（首次或修改 CMakeLists 后）
colcon build

# 只构建指定包
colcon build --packages-select my_pkg

# 增量编译（只编译改动的文件，加快速度）
colcon build --symlink-install

# 清理
rm -rf build/ install/ log/

# 运行测试
colcon test --packages-select my_pkg
colcon test-result --verbose
```

`package.xml` 关键依赖声明：

```xml
<buildtool_depend>ament_cmake</buildtool_depend>
<depend>rclcpp</depend>
<depend>std_msgs</depend>
<depend>sensor_msgs</depend>
<test_depend>ament_lint_auto</test_depend>
<test_depend>ament_lint_common</test_depend>
```

### 4.2 ament 与工作空间

ament 是 ROS2 的构建系统元工具，提供：
- `ament_cmake`：CMake 封装
- `ament_python`：Python 构建
- `ament_lint`：代码检查（cpplint、flake8 等）

工作空间叠加（overlay）：

```bash
# 底层：ROS2 安装目录
source /opt/ros/humble/setup.bash

# 上层：自定义工作空间
source ~/ros2_ws/install/setup.bash

# 多个工作空间叠加（后 source 的优先级高）
source ~/ros2_ws/install/setup.bash
source ~/my_project/install/setup.bash
```

目录结构：

```text
ros2_ws/
├── src/
│   ├── my_pkg/
│   │   ├── CMakeLists.txt
│   │   ├── package.xml
│   │   ├── include/my_pkg/
│   │   ├── src/
│   │   ├── msg/
│   │   ├── srv/
│   │   ├── action/
│   │   ├── launch/
│   │   └── config/
│   └── another_pkg/
├── build/      # 编译中间产物
├── install/    # 安装结果（可执行文件、库、消息头文件）
└── log/        # 构建日志
```

## 5. Nav2 导航系统

Nav2（Navigation2）是 ROS2 的官方导航框架，替代 ROS1 的 navigation stack。

```text
┌─────────────────────────────────────────────────────┐
│                  行为树（BT Navigator）               │
│  NavigateToPose → 规划 → 控制 → 到达/失败             │
├──────────┬──────────┬──────────┬───────────────────┤
│ 全局规划器 │ 局部规划器 │ 控制器   │ 行为服务器         │
│ NavFn/   │ DWB/     │ DWB      │ ComputePathToPose │
│ Smac     │ Teb      │ Local    │ FollowPath        │
│ Planner  │ Planner  │ Planner  │ Spin/BackUp/Wait  │
├──────────┴──────────┴──────────┴───────────────────┤
│              代价地图（Costmap 2D）                   │
│  全局代价地图（静态地图+膨胀层）  局部代价地图（障碍物）  │
├─────────────────────────────────────────────────────┤
│              AMCL 定位（粒子滤波）                    │
├─────────────────────────────────────────────────────┤
│              传感器：激光雷达 / 深度相机 / IMU        │
└─────────────────────────────────────────────────────┘
```

### 5.1 AMCL 定位

AMCL（Adaptive Monte Carlo Localization）使用粒子滤波实现 2D 激光雷达定位。

```bash
# 启动 AMCL
ros2 launch nav2_bringup localization_launch.py \
    map:=./maps/my_map.yaml \
    use_sim_time:=true

# 参数配置（amcl_params.yaml）
amcl:
  ros__parameters:
    use_sim_time: true
    alpha1: 0.2      # 旋转噪声
    alpha2: 0.2      # 平移引起的旋转噪声
    alpha3: 0.2      # 平移噪声
    alpha4: 0.2      # 旋转引起的平移噪声
    max_particles: 2000
    min_particles: 500
    update_min_d: 0.2   # 平移 0.2m 更新一次
    update_min_a: 0.2   # 旋转 0.2rad 更新一次
    laser_model_type: "likelihood_field"
```

初始位姿设置：

```bash
# 在 RViz 中用 "2D Pose Estimate" 工具设置初始位姿
# 或命令行发布
ros2 topic pub /initialpose geometry_msgs/msg/PoseWithCovarianceStamped "{
    header: {frame_id: map},
    pose: {pose: {position: {x: 1.0, y: 1.0}, orientation: {w: 1.0}}}
}" -1
```

### 5.2 代价地图

代价地图将环境信息转换为机器人可通行的代价网格（0~254）。

| 层 | 说明 |
| --- | --- |
| **Static Layer** | 加载静态地图，障碍物=254，自由空间=0 |
| **Obstacle Layer** | 实时传感器数据标记障碍物 |
| **Inflation Layer** | 障碍物膨胀，机器人半径内代价递增 |
| **Voxel Layer** | 3D 体素障碍物（用于3D导航） |

```yaml
global_costmap:
  global_costmap:
    ros__parameters:
      update_frequency: 1.0
      publish_frequency: 1.0
      global_frame: map
      robot_base_frame: base_link
      resolution: 0.05
      plugins: ["static_layer", "inflation_layer"]
      static_layer:
        plugin: "nav2_costmap_2d::StaticLayer"
      inflation_layer:
        plugin: "nav2_costmap_2d::InflationLayer"
        inflation_radius: 0.55
        cost_scaling_factor: 3.0

local_costmap:
  local_costmap:
    ros__parameters:
      update_frequency: 5.0
      publish_frequency: 5.0
      global_frame: odom
      robot_base_frame: base_link
      rolling_window: true
      width: 3
      height: 3
      resolution: 0.05
      plugins: ["obstacle_layer", "inflation_layer"]
```

### 5.3 全局/局部规划器

| 规划器 | 类型 | 特点 |
| --- | --- | --- |
| **NavFn** | 全局 | Dijkstra/A*，经典，稳定 |
| **Smac Planner** | 全局 | 状态栅格 A*，支持非完整约束（差速/阿克曼） |
| **DWB** | 局部 | 动态窗口法，预测轨迹评分 |
| **TEB** | 局部 | 时间弹性带，优化轨迹时间和空间 |

发送导航目标：

```bash
ros2 action send_goal /navigate_to_pose nav2_msgs/action/NavigateToPose "{
    pose: {
        header: {frame_id: map},
        pose: {position: {x: 5.0, y: 3.0}, orientation: {w: 1.0}}
    }
}"
```

### 5.4 行为树（Behavior Tree）

Nav2 用行为树（BehaviorTree.CPP）编排导航任务，支持自定义复杂逻辑。

```xml
<!-- 简化的导航行为树 -->
<root main_tree_to_execute="MainTree">
  <BehaviorTree ID="MainTree">
    <PipelineSequence name="NavigateWithReplanning">
      <RateController hz="1.0">
        <ComputePathToPose goal="{goal}" path="{path}" planner_id="GridBased"/>
      </RateController>
      <FollowPath path="{path}" controller_id="FollowPath"/>
    </PipelineSequence>
  </BehaviorTree>
</root>
```

行为树节点类型：
- **Sequence**：顺序执行，一个失败则整体失败
- **Fallback**：依次尝试，一个成功则整体成功
- **Decorator**：修饰子节点（RateController、Retry 等）
- **Action**：实际执行动作（ComputePathToPose、FollowPath）

## 6. SLAM 建图

### 6.1 slam_toolbox

slam_toolbox 是 ROS2 推荐的 2D SLAM 工具包，基于 Karto SLAM，支持在线建图和地图合并。

```bash
# 安装
sudo apt install ros-humble-slam-toolbox

# 在线建图（同步模式）
ros2 launch slam_toolbox online_sync_launch.py \
    use_sim_time:=true

# 异步模式（适合高频率传感器）
ros2 launch slam_toolbox online_async_launch.py
```

关键参数：

```yaml
slam_toolbox:
  ros__parameters:
    use_sim_time: true
    # 激光雷达话题
    scan_topic: /scan
    # 里程计话题
    odom_frame: odom
    base_frame: base_footprint
    map_frame: map
    # 建图分辨率
    resolution: 0.05
    # 最大激光距离
    max_laser_range: 20.0
    # 回环检测
    loop_search_maximum_distance: 3.0
    # 最小扫描匹配得分
    minimum_travel_distance: 0.5
    minimum_travel_heading: 0.5
```

### 6.2 Cartographer

Cartographer 是 Google 开源的 SLAM 系统，支持 2D/3D，精度高，资源消耗大。


Cartographer 核心概念：
- **Local SLAM**：前端扫描匹配，实时构建子图（submap）
- **Global SLAM**：后端回环检测，优化位姿图（pose graph）
- **SPA（Sparse Pose Adjustment）**：稀疏位姿调整优化

## 8. ROS1 与 ROS2 对比

| 维度 | ROS1（Noetic） | ROS2（Humble/Iron/Rolling） |
| --- | --- | --- |
| **底层通信** | 自定义 TCPROS/UDPROS | DDS（工业级标准） |
| **中心化** | ROS Master（单点故障） | 无中心，DDS 自动发现 |
| **实时性** | 不支持硬实时 | 支持实时内核（PREEMPT_RT） |
| **QoS** | 无 | 完整 DDS QoS 策略 |
| **生命周期** | 无 | Lifecycle Node（配置/激活/停用/清理/错误） |
| **组件容器** | nodelet（进程内） | Component（ComposableNode，零拷贝） |
| **构建系统** | catkin（catkin_make/build） | colcon + ament |
| **语言支持** | C++03/Python2 | C++17/Python3 |
| **多机器人** | 需多 master 或 rosbridge | 原生支持（DDS Domain ID 隔离） |
| **安全** | 无 | DDS-Security（认证/加密/访问控制） |
| **参数** | 全局参数服务器 | 节点级参数 + 参数服务 |
| **Action** | 自定义 actionlib | 原生 Action（goal/feedback/result/cancel） |
| **Windows 支持** | 实验性 | 官方支持 |
| **长期支持** | Noetic 支持到 2025 | Humble 支持到 2027 |

ROS2 关键改进：
1. **DDS 中间件**：工业级可靠性，自动发现，无单点故障
2. **生命周期节点**：节点状态机管理，便于系统启动/停止/错误恢复
3. **组件容器**：进程内零拷贝通信，降低延迟
4. **QoS 策略**：灵活控制通信质量，适配不同传感器
5. **实时性**：支持 PREEMPT_RT 内核，适合硬实时场景
6. **安全性**：DDS-Security 提供认证和加密

```text
ROS2 命令速查：
  ros2 run <pkg> <node>              运行节点
  ros2 launch <pkg> <file.launch.py> 启动 launch 文件
  ros2 node list / info <node>       列出/查看节点
  ros2 topic list / echo <topic>     列出/监听话题
  ros2 topic pub <topic> <type> <msg> 发布消息
  ros2 topic hz <topic>              查看话题频率
  ros2 service list / call <srv>     列出/调用服务
  ros2 action list / send_goal <act> 列出/发送 action 目标
  ros2 param list / get / set <node>  参数管理
  ros2 bag record <topics>           录制 rosbag
  ros2 bag play <bag_file>           回放 rosbag
  ros2 interface show <msg_type>     查看消息定义
  ros2 doctor                        系统诊断
  ros2 wtf                           问题排查

QoS 策略表：
  Reliability:  RELIABLE(可靠重传) / BEST_EFFORT(尽力而为)
  Durability:   VOLATILE(临时) / TRANSIENT_LOCAL(持久,晚加入收最后一条)
  History:      KEEP_LAST(N) / KEEP_ALL
  传感器用 SensorDataQoS(): BEST_EFFORT + KeepLast(5)
  参数用 ParametersQoS(): RELIABLE + TRANSIENT_LOCAL

Nav2 组件图：
  行为树(BT) → 全局规划器(NavFn/Smac) → 局部规划器(DWB/TEB)
  → 代价地图(静态层+障碍层+膨胀层) → AMCL定位 → 传感器
```

## 10. 常见问题与坑

1. **QoS 不兼容导致收不到消息**：发布者 RELIABLE，订阅者 BEST_EFFORT 可以；反过来不行。解决：用 `ros2 topic info -v <topic>` 检查两端 QoS，统一配置。
2. **DDS 发现失败**：多机器通信时防火墙阻止 DDS 发现包（UDP 7400+）。解决：关闭防火墙或配置 DDS 初始节点（initial peers），用 `ROS_DOMAIN_ID` 隔离。
3. **colcon 编译找不到头文件**：CMakeLists.txt 中 `ament_target_dependencies` 未声明依赖。解决：确保 `find_package` 和 `ament_target_dependencies` 包含所有依赖包。
4. **AMCL 定位漂移**：粒子滤波在对称环境（长走廊）中容易丢失。解决：增加激光特征，设置合理的 `update_min_d/a`，必要时重新初始化位姿。
5. **导航时机器人抖动**：局部规划器参数不当或代价地图更新频率低。解决：提高 `local_costmap update_frequency`，调整 DWB 的 `vx/yaw_vel` 采样参数。
6. **Gazebo 中机器人漂移**：物理参数不当或摩擦力设置错误。解决：调整 URDF 中的 `mu1/mu2` 摩擦系数，确保 `inertia` 矩阵正确。
7. **TF 变换超时**：传感器 frame 到 base_link 的 TF 未发布或延迟。解决：用 `ros2 run tf2_ros tf2_monitor` 检查 TF 树，确保所有 frame 连通。
8. **rosbag 回放时间不同步**：未使用 sim_time。解决：回放时 `ros2 bag play --clock`，节点启动加 `use_sim_time:=true`。
9. **自定义消息编译后找不到头文件**：未在 CMakeLists 中添加 `rosidl_generate_interfaces` 的依赖。解决：检查 `DEPENDENCIES` 列表，重新 `colcon build`。
10. **大消息（点云）延迟高**：默认 RELIABLE QoS 导致重传累积。解决：用 BEST_EFFORT QoS，或使用零拷贝（iceoryx/Shared Memory）传输。
