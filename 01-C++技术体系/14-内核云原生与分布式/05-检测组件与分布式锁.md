## 1. 概述

### 1.1 事后排查 vs 运行时主动检测

| 维度 | 事后排查（gdb / valgrind） | 运行时主动检测（本篇组件） |
| --- | --- | --- |
| 介入时机 | 问题已发生，挂工具再复现 | 随进程常驻，边跑边查 |
| 性能开销 | valgrind 慢 10~50 倍，生产不可用 | 低到能常驻（1~2 倍内） |
| 定位能力 | 精确到指令/内存块 | 粗粒度（死锁环路径 / 泄漏调用栈） |
| 改业务代码 | 不需要 | 不需要（hook 系统函数） |

**事后排查用于根因分析，运行时检测用于线上巡检**，互补。工具用法见 `../06-工程化与工具链/08-GDB程序调试.md`、`../06-工程化与工具链/09-Valgrind内存检测.md`。

### 1.2 共同底座：dlsym 动态符号拦截

死锁检测拦 `pthread_mutex_lock`，泄漏检测拦 `malloc/free`，手段一致：

| 概念 | 说明 | 示例 |
| --- | --- | --- |
| dlsym(RTLD_NEXT, "malloc") | 在**当前 so 之后**的查找链上取下一个同名符号，即"真正的原函数" | `real_malloc = dlsym(RTLD_NEXT, "malloc")` |
| RTLD_NEXT 语义 | 从"调用者 so 的下一个链接对象"开始查；hook 库必须用它，RTLD_DEFAULT 可能又找到自己 → 死递归 | LD_PRELOAD 的 so 用它拿 libc 实现 |
| 返回值检查 | 找不到返回 NULL，必须检查 | `if (!real_malloc) dlerror();` |
| LD_PRELOAD 注入 | 链接器按 可执行文件→LD_PRELOAD 库→依赖库 建全局符号表，先出现者遮蔽后到者 | `LD_PRELOAD=./hook.so ./app` |
| 符号决议 | 调用走 PLT/GOT 懒绑定（`../02-计算机底层原理/02-编译链接与加载原理.md`） | hook 的 malloc 抢先进 GOT |
| 构造函数时机 | `__attribute__((constructor))` 在 so 加载后、main 前执行，动态链接器已初始化，**在这里 dlsym 安全** | 构造函数取 real 指针 + 起检测线程 |

```text
        LD_PRELOAD=./hook.so ./app
   ┌────────────────────────────────────────┐
   │ app 调 malloc ──► PLT ──► GOT 查符号   │
   │  查找顺序: hook.so(先) > libc(后)       │
   │  ⇒ 调进 hook 的 malloc                 │
   │  hook: real=dlsym(RTLD_NEXT) 拿真函数  │
   │  ⇒ 记账 + 转调 real                    │
   └────────────────────────────────────────┘
```

编译：`gcc -shared -fPIC -o hook.so hook.c -ldl -lpthread`（glibc 2.34+ 已把 dl 合入 libc，保留 -ldl 兼容旧系统）。

## 2. 死锁检测组件【核心】

### 2.1 死锁现象与四个必要条件

现象：多个线程互相持有对方想要的锁，全部阻塞，进程"活着但不动"。四个必要条件（破坏任意一个即可预防，详见 `../04-并发与多线程编程/01-并发编程与线程同步.md` 4.1）：

| 条件 | 说明 | 破坏手段 |
| --- | --- | --- |
| 互斥 | 资源同一时刻只归一个线程 | 无法破坏（锁的本质） |
| 请求与保持 | 拿着 A 又去要 B | 一次性申请全部资源 |
| 不可剥夺 | 别人不能抢走已持有的锁 | trylock 失败就释放重来 |
| 循环等待 | 等待关系成环 | **全局锁排序**（最实用） |

组件的本质：**运行时实时发现"循环等待"成立了**。

### 2.2 hook 框架

用 `dlsym(RTLD_NEXT)` 包装 `pthread_mutex_lock/unlock`（完整代码在 2.6）：

```c
static int (*real_lock)(pthread_mutex_t *);    // 原函数指针
__attribute__((constructor))
static void hook_init(void) {                  // so 加载后、main 前执行
    real_lock = dlsym(RTLD_NEXT, "pthread_mutex_lock");   // 取 libc 真实现
}
int pthread_mutex_lock(pthread_mutex_t *m) {   // 与 libc 同名同签名 → 覆盖之
    lock_before(pthread_self(), (unsigned long)m);  // ① 记录申请意图
    int r = real_lock(m);                           // ② 原函数（可能阻塞在这）
    lock_after(pthread_self(), (unsigned long)m);   // ③ 获得锁，登记持有
    return r;
}
```

关键：`lock_before` 在**阻塞前**记录申请意图，即使线程随后卡死在第②步，图上已留下证据。

### 2.3 有向图建模：两种方式对比

| 建模方式 | 节点 | 边 | 死锁判定 | 评价 |
| --- | --- | --- | --- | --- |
| **锁等待图（本组件采用）** | 只有锁 | "已持锁→申请锁"：持 A 申请 B 则画 A→B | 图中出现**环** | 节点少、边语义单一、一次 DFS |
| 线程资源图（资源分配图） | 线程+锁两类 | 申请边 T→L、分配边 L→T | 单实例资源下出现环 | 直观（能看出"谁等谁"），节点翻倍 |

互斥锁单持有者前提下两者等价（A→B 即"A 的持有者正在等 B"），选锁等待图：

```text
线程T1: 持A 申请B ──► 边 A→B      ┌──────┐
线程T2: 持B 申请A ──► 边 B→A  ──► │ A→B  │  出现环 A→B→A
                                  │ B→A  │  ⇒ 死锁！
                                  └──────┘
```

### 2.4 三个原语操作表

| 原语 | 调用时机 | 对图的操作 | 备注 |
| --- | --- | --- | --- |
| `lock_before(tid, lock)` | 调原 lock **之前** | 为 tid 已持有的**每把锁** L 建意图边 L→lock | 持 0 把锁则不建边 |
| `lock_after(tid, lock)` | 原 lock **返回后** | **只删 tid 自己**的锁指向 lock 的意图边；把 lock 登记进 held[tid] | 别人的等待边必须保留 |
| `unlock_after(tid, lock)` | 原 unlock **之后** | 把 lock 移出 held[tid]；防御性清理 lock 残留出边 | 正常出边在 lock_after 已清空 |

### 2.5 有向图 DFS 判环（三色标记）

| 颜色 | 含义 | 遇到时的动作 |
| --- | --- | --- |
| 白（0） | 未访问 | 入递归栈继续深搜 |
| 灰（1） | 在当前 DFS 路径上 | **灰遇灰 = 找到环**（指回当前路径） |
| 黑（2） | 子树已探明无环 | 回溯标黑，不再访问 |

为什么"灰遇灰"而不是"访问过就有环"：黑色点属于已探明无环的子树，指向它只是汇聚不成环；只有指回**当前路径**（灰色）才构成回路。实现见 2.6 的 `dfs()`。

### 2.6 完整组件框架代码

数据结构全部静态数组——hook 路径里**禁止**再调用可能被 hook 的分配函数：

```c
// deadlock_detector.c —— gcc -shared -fPIC -o dd.so deadlock_detector.c -ldl -lpthread
#define _GNU_SOURCE
#include <dlfcn.h>
#include <pthread.h>
#include <stdio.h>
#include <string.h>
#include <unistd.h>

#define MAX_NODE 1024
#define MAX_EDGE 8192
#define MAX_THREAD 256
#define MAX_HELD  64
#define DETECT_MS 1000

typedef struct { int from, to; } edge_t;
typedef struct {                       // 每线程持有锁集合
    unsigned long tid;
    int held[MAX_HELD], nheld;
} tinfo_t;

static unsigned long g_nodes[MAX_NODE];        // 节点=锁地址
static int  g_nnode;
static edge_t g_edges[MAX_EDGE];
static int  g_nedge;
static int  g_color[MAX_NODE], g_path[MAX_NODE];
static tinfo_t g_threads[MAX_THREAD];
static int  g_nthread;
static pthread_mutex_t g_mu = PTHREAD_MUTEX_INITIALIZER;     // 保护图
static int (*real_lock)(pthread_mutex_t *), (*real_unlock)(pthread_mutex_t *);

static int find_or_add_node(unsigned long lock) {           // 查/建锁节点
    for (int i = 0; i < g_nnode; i++) if (g_nodes[i] == lock) return i;
    return g_nnode < MAX_NODE ? (g_nodes[g_nnode] = lock, g_nnode++) : -1;
}
static tinfo_t *find_or_add_thread(unsigned long tid) {     // 查/建线程（省略上限判断）
    for (int i = 0; i < g_nthread; i++) if (g_threads[i].tid == tid) return &g_threads[i];
    g_threads[g_nthread].tid = tid;
    return &g_threads[g_nthread++];
}
static int has_edge(int f, int t) {
    for (int i = 0; i < g_nedge; i++)
        if (g_edges[i].from == f && g_edges[i].to == t) return 1;
    return 0;
}
static void add_edge(int f, int t) {          // 建边（带去重）
    if (f < 0 || t < 0 || g_nedge >= MAX_EDGE || has_edge(f, t)) return;
    g_edges[g_nedge].from = f; g_edges[g_nedge].to = t; g_nedge++;
}
static void del_edge(int f, int t) {          // 删边（尾元素补位 O(1)）
    for (int i = 0; i < g_nedge; i++)
        if (g_edges[i].from == f && g_edges[i].to == t) { g_edges[i] = g_edges[--g_nedge]; return; }
}

// ---------- 三个原语：★ 图锁用 real_lock 直调绕开自己的 hook，防自递归 ----------
static void lock_before(unsigned long tid, unsigned long lock) {
    real_lock(&g_mu);
    tinfo_t *t = find_or_add_thread(tid);
    int dst = find_or_add_node(lock);
    if (t && dst >= 0)
        for (int i = 0; i < t->nheld; i++) add_edge(t->held[i], dst);  // 已持锁→申请锁
    real_unlock(&g_mu);
}
static void lock_after(unsigned long tid, unsigned long lock) {
    real_lock(&g_mu);
    tinfo_t *t = find_or_add_thread(tid);
    int idx = find_or_add_node(lock);
    if (t && idx >= 0) {
        for (int i = 0; i < t->nheld; i++) del_edge(t->held[i], idx);  // ★只删自己的意图边
        if (t->nheld < MAX_HELD) t->held[t->nheld++] = idx;           // 登记持有
    }
    real_unlock(&g_mu);
}
static void unlock_after(unsigned long tid, unsigned long lock) {
    real_lock(&g_mu);
    tinfo_t *t = find_or_add_thread(tid);
    int idx = find_or_add_node(lock);
    if (t && idx >= 0) {
        for (int i = 0; i < t->nheld; i++)
            if (t->held[i] == idx) { t->held[i] = t->held[--t->nheld]; break; }
        for (int i = 0; i < g_nedge; i++)     // 防御：清本锁残留出边
            if (g_edges[i].from == idx) { g_edges[i] = g_edges[--g_nedge]; i--; }
    }
    real_unlock(&g_mu);
}

// ---------- 环检测与汇报 ----------
static void report_cycle(int meet, int depth) {         // 沿 path 回溯打印环
    char msg[512]; int off = snprintf(msg, sizeof(msg), "[deadlock] ");
    int st = depth;
    while (st > 0 && g_path[st] != meet) st--;          // 找环入口
    for (int i = st; i <= depth; i++)
        off += snprintf(msg + off, sizeof(msg) - off, "%lx%s",
                        g_nodes[g_path[i]], i < depth ? " -> " : "");
    snprintf(msg + off, sizeof(msg) - off, "\n");
    write(STDERR_FILENO, msg, strlen(msg));             // hook 环境用 write 直写
}
static int dfs(int u, int depth) {                      // 三色：0白 1灰 2黑
    g_color[u] = 1; g_path[depth] = u;
    for (int v = 0; v < g_nnode; v++) {
        if (!has_edge(u, v)) continue;
        if (g_color[v] == 1) { report_cycle(v, depth); return 1; }   // 灰遇灰=环
        if (g_color[v] == 0 && dfs(v, depth + 1)) return 1;
    }
    g_color[u] = 2;
    return 0;
}
static void *detect_thread(void *arg) {                 // 周期检测线程
    (void)arg;
    for (;;) {
        usleep(DETECT_MS * 1000);
        real_lock(&g_mu);                               // 拿一致的快照
        memset(g_color, 0, sizeof(g_color));
        int found = 0;
        for (int i = 0; i < g_nnode && !found; i++)
            if (g_color[i] == 0) found = dfs(i, 0);
        real_unlock(&g_mu);
        // 进阶：发现环后 pthread_kill 环中线程，在信号处理器里 backtrace 栈帧
    }
    return NULL;
}

// ---------- hook 入口 + 初始化 ----------
int pthread_mutex_lock(pthread_mutex_t *m) {
    if (!real_lock) return 0;                           // 未初始化兜底
    lock_before(pthread_self(), (unsigned long)m);      // ① 申请意图
    int r = real_lock(m);                               // ② 原函数（可能阻塞）
    lock_after(pthread_self(), (unsigned long)m);       // ③ 登记持有
    return r;
}
int pthread_mutex_unlock(pthread_mutex_t *m) {
    if (!real_unlock) return 0;
    int r = real_unlock(m);
    unlock_after(pthread_self(), (unsigned long)m);
    return r;
}
__attribute__((constructor))
static void dd_init(void) {                             // 取原函数 + 起检测线程
    real_lock   = dlsym(RTLD_NEXT, "pthread_mutex_lock");
    real_unlock = dlsym(RTLD_NEXT, "pthread_mutex_unlock");
    pthread_t t;
    pthread_create(&t, NULL, detect_thread, NULL);
}
```

```text
# 运行时注入（推荐，不用重编业务）：
LD_PRELOAD=./dd.so ./deadlock_app
# 链接期替换：把 dd.so 链进业务，-Wl,--whole-archive 保证符号被引出
```

验证：T1 先 A 后 B，T2 先 B 后 A → 1 秒内打印 `[deadlock] addrA -> addrB -> addrA`。

### 2.7 局限

| 局限 | 说明 |
| --- | --- |
| 只检测单进程 | 图在进程内，跨进程死锁（各自持 DB 行锁互等）看不到；改进：共享内存放全局图 |
| 只覆盖普通互斥锁 | trylock/读写锁/条件变量未 hook；改进：补 hook（trylock 成功才调 lock_after） |
| 依赖动态链接 | 静态编译程序无法注入；改进：链接期替换 |

## 3. 内存泄漏检测组件【核心】

### 3.1 泄漏现象与两类场景

| 场景 | 特征 | 策略 |
| --- | --- | --- |
| 第三方库泄漏 | 无源码不能改 | 只能 hook malloc/free 在外面记账 |
| 自身代码泄漏 | 有源码 | RAII/智能指针（`../01-C++语言核心/04-内存管理与智能指针.md`）+ 日志定位；本组件兜底巡检 |

### 3.2 防重入——本组件最大的坑

hook 了 malloc 后，**hook 自己的路径里再出现 malloc 就无限递归**直到栈溢出：

```text
malloc → record_alloc → backtrace()/printf → 内部又调 malloc
   ▲                                            │
   └────────────────────────────────────────────┘   递归死循环
```

| 措施 | 解决什么 | 实现要点 |
| --- | --- | --- |
| 线程局部 `g_in_hook` 标志 | hook 内部（backtrace/格式化）再进 malloc 时**跳过记账**直走 real 函数 | `__thread int g_in_hook;` 进 hook 置 1；副作用：这些内部分配不被记录（可接受的漏报） |
| 引导期静态缓冲 | 构造函数调 dlsym，glibc 的 dlsym 内部调 **calloc** → real_calloc 还没拿到 → 递归 | 静态 char 数组做 bump 分配器，初始化期分配全从这出，永不 free |
| 输出用 write 直写 | printf 内部可能 malloc 且持 stdio 锁，hook 路径里调用可能死锁 | `snprintf`（写栈缓冲，不分配）+ `write(STDERR_FILENO, ...)` |

### 3.3 检测策略与应用场景

| 步骤/场景 | 时机 | 动作 |
| --- | --- | --- |
| 记录 | malloc 返回后 | `{ptr, size, 调用栈}` 存全局哈希表（`backtrace` 取栈） |
| 删除 | free 调用时 | 按 ptr 从表中删除 |
| 报告 | atexit / 周期 dump | 遍历表，仍存活的指针按调用栈聚类输出 |
| 长跑服务嵌入式检测 | 常驻 | 周期 dump 只报"存活超 N 分钟"的指针，过滤短命分配 |
| CI 冒烟 | 用例跑完 | atexit dump 非空即失败，把泄漏挡在合入前 |

`backtrace(void**, int)` 取返回地址数组（`#include <execinfo.h>`），`backtrace_symbols` 转字符串；首帧是 malloc 本身，从第 2 帧起展示。**backtrace 首次调用可能 dlopen libgcc 触发 malloc——必须被 g_in_hook 挡住**。

### 3.4 完整代码框架

```c
// leak_detector.c —— gcc -shared -fPIC -o leak.so leak_detector.c -ldl -lpthread
#define _GNU_SOURCE
#include <dlfcn.h>
#include <execinfo.h>
#include <pthread.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <unistd.h>

#define HASH_SZ  (1 << 16)        // 哈希桶数，2 的幂
#define MAX_FRAME 12              // 记录栈深
#define BOOT_SZ  (1 << 20)        // 1MB 引导缓冲

typedef struct {
    void  *ptr;
    size_t size;
    void  *frame[MAX_FRAME];      // 分配时调用栈
    int    depth;
} rec_t;

static rec_t  g_tab[HASH_SZ];
static size_t g_live_bytes, g_live_cnt;
static __thread int g_in_hook;    // ★ 线程局部防重入标志
static int g_booting;
static char g_boot[BOOT_SZ] __attribute__((aligned(16)));
static size_t g_boot_used;

static void *(*real_malloc)(size_t);
static void  (*real_free)(void *);
static void *(*real_calloc)(size_t, size_t);

static void *boot_alloc(size_t n) {         // 引导期分配器：只加指针，永不释放
    n = (n + 15) & ~(size_t)15;             // 16 字节对齐
    if (g_boot_used + n > BOOT_SZ) return NULL;
    void *p = g_boot + g_boot_used; g_boot_used += n;
    return p;
}
static int in_boot(void *p) { return (char *)p >= g_boot && (char *)p < g_boot + BOOT_SZ; }

static void hook_init(void) {
    g_booting = 1;                          // dlsym 内部 calloc → 走 boot_alloc
    real_malloc = dlsym(RTLD_NEXT, "malloc");
    real_free   = dlsym(RTLD_NEXT, "free");
    real_calloc = dlsym(RTLD_NEXT, "calloc");
    g_booting = 0;
}

static size_t find_slot(void *p) {          // 开放寻址线性探测
    size_t i = ((size_t)p >> 4) & (HASH_SZ - 1);
    while (g_tab[i].ptr && g_tab[i].ptr != p) i = (i + 1) & (HASH_SZ - 1);
    return i;
}
static void record_alloc(void *p, size_t sz) {
    size_t i = find_slot(p);
    g_tab[i].ptr = p; g_tab[i].size = sz;
    g_tab[i].depth = backtrace(g_tab[i].frame, MAX_FRAME);   // 内部 malloc 被挡
    __sync_fetch_and_add(&g_live_bytes, sz);
    __sync_fetch_and_add(&g_live_cnt, 1);
}
static void record_free(void *p) {
    size_t i = find_slot(p);
    if (g_tab[i].ptr == p) {                // 找不到（hook 前分配的）直接放过
        __sync_fetch_and_sub(&g_live_bytes, g_tab[i].size);
        __sync_fetch_and_sub(&g_live_cnt, 1);
        g_tab[i].ptr = NULL; g_tab[i].size = 0;
    }
}

// ---------- hook 函数族：核心是"防重入三连" ----------
void *malloc(size_t sz) {
    if (!real_malloc) hook_init();
    void *p = real_malloc(sz);
    if (p && !g_in_hook && !g_booting) { g_in_hook = 1; record_alloc(p, sz); g_in_hook = 0; }
    return p;
}
void *calloc(size_t n, size_t sz) {
    if (!real_calloc) return boot_alloc(n * sz);   // ★ dlsym 递归点：走引导缓冲
    void *p = real_calloc(n, sz);
    if (p && !g_in_hook && !g_booting) { g_in_hook = 1; record_alloc(p, n * sz); g_in_hook = 0; }
    return p;
}
void free(void *p) {
    if (!p) return;
    if (!real_free) hook_init();
    if (in_boot(p)) return;                  // ★ 引导区指针不能交给真 free
    if (!g_in_hook && !g_booting) { g_in_hook = 1; record_free(p); g_in_hook = 0; }
    real_free(p);
}
// realloc 同理：real_realloc 转调 + record_free(旧) + record_alloc(新)，篇幅略

// ---------- dump：atexit 时机不在 hook 路径，可用 backtrace_symbols ----------
static void dump_leaks(void) {
    char msg[256];
    int off = snprintf(msg, sizeof(msg), "\n[leak] live=%zu blocks, %zu bytes\n",
                       g_live_cnt, g_live_bytes);
    write(STDERR_FILENO, msg, off);
    g_in_hook = 1;                           // dump 自身的分配不记账
    for (size_t i = 0; i < HASH_SZ; i++) {
        if (!g_tab[i].ptr) continue;
        snprintf(msg, sizeof(msg), "[leak] ptr=%p size=%zu\n",
                 g_tab[i].ptr, g_tab[i].size);
        write(STDERR_FILENO, msg, strlen(msg));
        char **syms = backtrace_symbols(g_tab[i].frame, g_tab[i].depth);
        if (syms) {
            for (int f = 1; f < g_tab[i].depth; f++)   // 第 0 帧是 malloc 自己
                write(STDERR_FILENO, syms[f], strlen(syms[f])),
                write(STDERR_FILENO, "\n", 1);
            free(syms);                      // backtrace_symbols 返回值要 free
        }
    }
    g_in_hook = 0;
}
__attribute__((constructor))
static void leak_init(void) {
    hook_init();                             // 提前初始化避免首条路径踩坑
    atexit(dump_leaks);
}
```

使用：`LD_PRELOAD=./leak.so ./app`。等价于一个只看"分配/释放配对"的极简 memcheck。

### 3.5 与 valgrind / ASan 对比【高频】

| 维度 | 本组件（hook 记账） | valgrind memcheck（`../06-工程化与工具链/09-Valgrind内存检测.md`） | AddressSanitizer |
| --- | --- | --- | --- |
| 原理 | LD_PRELOAD hook + 调用栈记账 | 动态二进制翻译 + 影子内存 | 编译器插桩 + 影子内存 |
| 能查什么 | 只能查"未释放" | 泄漏 + 越界 + UAF + 未初始化读 | 泄漏 + 越界 + UAF |
| 开销 | 1~2 倍（backtrace 较贵） | 慢 10~50 倍、内存 2 倍+ | 约 2 倍、内存 3 倍 |
| 要重编译 | 不需要 | 不需要 | **需要**（-fsanitize=address） |
| 生产可用 | 可常驻低开销巡检 | 不可 | 谨慎（可只开 leak 检测） |

面试话术：泄漏开发期首选 ASan、生产期用本组件；越界/UAF 只能 valgrind/ASan——hook 层面看不到"读写越过了分配边界"。

## 4. 分布式锁【高频】

### 4.1 使用场景与单机锁为什么失效

典型场景：库存扣减（多实例防超卖）、定时任务多实例只跑一份、多副本选主。

`std::mutex` 一句话原理：**futex——无竞争时纯用户态原子 CAS 不进内核；有竞争才 futex(FUTEX_WAIT) 陷入内核排队**。所以快，但也**只管得住一个进程地址空间内的线程**。

```text
        单机锁失效：两个进程各自本地加锁，全部成功
 ┌───────── 进程A ─────────┐      ┌───────── 进程B ─────────┐
 │ lock(mtx_A) ✓ 本地独立  │      │ lock(mtx_B) ✓ 本地独立  │
 │ UPDATE stock=stock-1    │      │ UPDATE stock=stock-1    │
 └────────────┬────────────┘      └────────────┬────────────┘
              └────────────┬───────────────────┘
                           ▼
              共享 MySQL：stock = stock - 2（超卖）
   ⇒ 锁必须放到所有进程都看得见的地方：redis / MySQL / zookeeper
```

### 4.2 分布式锁的三大异常【高频】

| 异常 | 场景 | 后果 | 对策 |
| --- | --- | --- | --- |
| 持有者宕机 | 加锁后进程崩溃，解锁永远不执行 | 锁永不过期，其他实例拿不到 → 业务全停 | **必须带过期时间**（redis EX / MySQL 时间戳） |
| 锁超时业务未完成 | 业务 > TTL，锁过期被抢走，原持有者处理完执行 DEL | **误删他人锁** | value 存唯一 uuid，解锁校验"自己的锁才删"（Lua 原子化）；看门狗续期 |
| 网络分区/主从切换 | redis 主写锁未同步到从即宕机，从提升为主 | 锁丢失，两客户端同时持锁（脑裂双主） | 单实例 redis 无法根除：Redlock 多数派，或换 zookeeper/etcd（CP） |

### 4.3 基于 Redis 的实现【核心】

概念（SETNX+EXPIRE 不原子问题、Redlock 争议）见 `../05-数据库与序列化/02-Redis设计与数据结构.md` 第 9 章，这里补 C++ 实现。三条军规：

| 军规 | 命令/做法 | 原因 |
| --- | --- | --- |
| 加锁必须原子 | `SET key uuid NX PX 10000` | SETNX 与 EXPIRE 两条命令间宕机 → 死锁 |
| 解锁必须校验+原子 | Lua：GET 比对 uuid 相等才 DEL | 先 GET 后 DEL 两步间锁易主 → 误删 |
| 长任务要续期 | 看门狗每 TTL/3 执行 PEXPIRE | 业务没完成锁先过期 → 并发进入临界区 |

```cpp
// redis_dist_lock.cc —— g++ -std=c++17 lock.cc -o lock -lhiredis -lpthread
#include <hiredis/hiredis.h>
#include <atomic>
#include <chrono>
#include <cstdio>
#include <cstring>
#include <random>
#include <string>
#include <thread>

class RedisDistLock {
public:
    RedisDistLock(const std::string &host, int port) {
        ctx_ = redisConnect(host.c_str(), port);
        if (!ctx_ || ctx_->err) fprintf(stderr, "redis connect fail\n");
    }
    ~RedisDistLock() { stop_watchdog(); if (ctx_) redisFree(ctx_); }

    // 加锁：SET key uuid NX PX ttl —— 一条原子命令
    bool lock(const std::string &key, int ttl_ms = 10000) {
        uuid_ = gen_uuid();                    // 唯一值标识"这把锁是我加的"
        redisReply *r = (redisReply *)redisCommand(
            ctx_, "SET %s %s NX PX %d", key.c_str(), uuid_.c_str(), ttl_ms);
        bool ok = r && r->type == REDIS_REPLY_STATUS && strcmp(r->str, "OK") == 0;
        if (r) freeReplyObject(r);
        if (ok) { key_ = key; ttl_ms_ = ttl_ms; start_watchdog(); }
        return ok;                             // 失败=被别人持有，重试或放弃
    }

    // 解锁：Lua 校验 uuid 相同才 DEL（GET+DEL 原子化，防误删他人锁）
    bool unlock() {
        stop_watchdog();
        static const char *LUA =
            "if redis.call('GET', KEYS[1]) == ARGV[1] then "
            "  return redis.call('DEL', KEYS[1]) else return 0 end";
        redisReply *r = (redisReply *)redisCommand(
            ctx_, "EVAL %s 1 %s %s", LUA, key_.c_str(), uuid_.c_str());
        bool ok = r && r->type == REDIS_REPLY_INTEGER && r->integer == 1;
        if (r) freeReplyObject(r);
        return ok;
    }

private:
    static std::string gen_uuid() {            // 生产建议 机器ID+时间戳+随机数
        static thread_local std::mt19937_64 rng(std::random_device{}());
        char buf[40];
        snprintf(buf, sizeof(buf), "%llx-%llx",
                 (unsigned long long)rng(), (unsigned long long)rng());
        return buf;
    }
    // 看门狗：每 ttl/3 续期；只有"仍是我的锁"才续，防止把别人的 TTL 顶长
    void start_watchdog() {
        holding_ = true;
        watchdog_ = std::thread([this] {
            static const char *LUA =
                "if redis.call('GET', KEYS[1]) == ARGV[1] then "
                "  return redis.call('PEXPIRE', KEYS[1], ARGV[2]) "
                "else return 0 end";
            while (holding_.load()) {
                std::this_thread::sleep_for(std::chrono::milliseconds(ttl_ms_ / 3));
                if (!holding_.load()) break;
                redisReply *r = (redisReply *)redisCommand(
                    ctx_, "EVAL %s 1 %s %s %d", LUA,
                    key_.c_str(), uuid_.c_str(), ttl_ms_);
                if (!r || r->type != REDIS_REPLY_INTEGER || r->integer == 0)
                    fprintf(stderr, "[watchdog] renew fail / lock lost\n");
                if (r) freeReplyObject(r);
            }
        });
    }
    void stop_watchdog() {
        holding_ = false;
        if (watchdog_.joinable()) watchdog_.join();
    }

    redisContext *ctx_ = nullptr;
    std::string key_, uuid_;
    int ttl_ms_ = 10000;
    std::atomic<bool> holding_{false};
    std::thread watchdog_;
};

// 用法：if (lock.lock("stock:lock:1001")) { deduct_stock(); lock.unlock(); }
```

### 4.4 基于 MySQL 的实现

| 方案 | 思路 | 优缺点 |
| --- | --- | --- |
| 方案一：唯一索引插入 | 主键冲突天然互斥；`expire_at` 实现"宕机后可抢占" | 简单、强一致（单机事务）；性能差（百 QPS 级），适合低频任务防重 |
| 方案二：乐观锁版本号 | 抢锁 = CAS 更新 version，改不动 = 被别人持有 | 无插入冲突开销，但自旋重试打 DB；适合共享数据被多方频繁更新 |

```sql
-- 方案一：唯一索引插入
CREATE TABLE dist_lock (
  lock_name VARCHAR(64) PRIMARY KEY,     -- 主键冲突 = 别人持有
  owner     VARCHAR(64) NOT NULL,        -- 持有者标识（uuid）
  expire_at BIGINT NOT NULL              -- 过期时间戳（毫秒）
);
-- 加锁：冲突即失败
INSERT INTO dist_lock(lock_name, owner, expire_at)
VALUES ('job:daily', 'uuid-A', 1730000000000 + 10000);
-- 冲突后抢占（持有者已过期）。必须用条件 UPDATE 的原子性（先 SELECT 再 UPDATE 有竞态）：
UPDATE dist_lock SET owner='uuid-A', expire_at=1730000000000 + 10000
 WHERE lock_name='job:daily' AND expire_at < 1730000000000;   -- 影响行数=1 才算抢到
-- 解锁（校验 owner 防误删）：
DELETE FROM dist_lock WHERE lock_name='job:daily' AND owner='uuid-A';

-- 方案二：乐观锁版本号（version 作 CAS 依据）
CREATE TABLE dist_lock2 (
  lock_name VARCHAR(64) PRIMARY KEY, owner VARCHAR(64) NOT NULL,
  version BIGINT NOT NULL DEFAULT 0, expire_at BIGINT NOT NULL
);
-- 抢锁：version 没被动过才能改成功（affected rows = 1 即获得锁）
UPDATE dist_lock2 SET owner='uuid-A', version=version+1,
       expire_at=1730000000000 + 10000
 WHERE lock_name='job:daily' AND version=5;
```

注意：以上 UPDATE 都命中主键索引只锁单行；条件不走索引会升级成范围锁，DB 并发急剧恶化（详见 `../05-数据库与序列化/01-MySQL数据库精要.md` 锁章节）。

### 4.5 三种实现对比与选型【高频】

| 维度 | Redis | MySQL | ZooKeeper |
| --- | --- | --- | --- |
| 一致性语义 | AP：主从异步复制，切换瞬间可能丢锁 | 强一致（单机事务） | CP：ZAB 过半提交 |
| 性能 | 高（内存，单机 10w QPS 级） | 差（磁盘事务，百 QPS 级） | 中等（写要过半投票，千 QPS 级） |
| 可靠性 | 主从切换锁丢失（脑裂风险） | 高（事务日志） | 高：会话断开**临时节点自动删除** |
| 过期/释放 | 自己管 TTL + Lua 校验删除 | 自己管 expire_at | 临时节点随会话自动删，watch 通知等待者 |
| 适用场景 | 高并发短临界区（秒杀扣减） | 已有 DB、低频定时任务防重 | 选主、要求绝不双写的场景 |

选型一句话：**性能优先选 redis（接受极小概率双持有），强可靠选 zookeeper，不想引新组件选 MySQL**。

## 6. 常见问题与坑

| 坑 | 现象 | 规避 |
| --- | --- | --- |
| hook 内部递归 | backtrace/printf 内部 malloc → 栈溢出 | `g_in_hook` 线程局部标志；输出改 write 直写 |
| dlsym 内部 calloc 递归 | 初始化死循环 | 引导期静态 bump 分配器，real 拿到前 calloc 走 boot |
| 检测组件自己死锁 | hook 的 lock 里再 lock 全局图锁 → 自递归 | 图锁用 `real_lock(&g_mu)` 直调原函数绕开 hook |
| 死锁误报 | 按序加锁明明安全却报环 | 检查实现：lock_after 是否只删自己的意图边、unlock 是否清残留出边、trylock/递归锁是否绕过记账、检测线程是否拿 g_mu 取一致快照。算法在"全量 hook+非递归锁+快照一致"前提下本身无假阳性 |
| trylock/递归锁绕过 hook | 持有集不完整 → 漏报误报甚至图错乱；递归锁重入被画成自环 | 补 hook：trylock 成功才调 lock_after；递归锁按锁类型过滤（pthread_mutexattr_gettype） |
| 泄漏误报（静态对象） | 全局单例/缓存在 dump 之后才释放，或进程生命周期不释放，被当泄漏 | 只报"存活超 N 秒"的分配；对照 valgrind 的 still reachable 语义过滤 |
| 引导缓冲指针被真 free | dlsym 的内存交给 real_free → 堆损坏 | free hook 里 `in_boot(p)` 检查，引导区指针直接忽略 |
| 看门狗与业务超时不匹配 | 业务跑 5 分钟、锁 TTL 10 秒且看门狗挂了 → 中途失锁双写 | 续期失败必须立刻中断业务回滚；TTL 取业务 P99 的 3 倍以上 |
| redis 主从切换丢锁 | 异步复制未到从节点，failover 后新主无锁 → 双持有 | 重要场景 Redlock 多数派或 zookeeper；DB 层加 fencing token（版本号）兜底 |
| MySQL 锁行长期持有 | 拿锁的 SQL 里做慢操作，行锁持有放大死锁概率 | 拿锁用独立短事务（autocommit），别把业务处理包进同一事务 |
| 误删他人锁 | 解锁只 DEL 不校验 value | 解锁一律走 Lua（GET 比对 uuid + DEL 原子） |
