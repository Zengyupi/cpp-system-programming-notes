## 1. 进程与线程

### 1.1 对比

| 维度 | 进程 | 线程 |
| -- | --------- | -------- |
| 定义 | 资源分配的基本单位（独立地址空间） | CPU 调度的基本单位，进程内的执行流 |
| 资源 | 独立地址空间、独立 fd 表、内存映射 | 共享所属进程的代码/堆/全局区/文件，**私有栈和寄存器** |
| 开销 | 创建/切换需切页表、刷 TLB，开销大 | 只切栈与寄存器，开销小 |
| 通信 | IPC（管道/消息/共享内存/socket） | 共享内存变量（需同步） |
| 崩溃 | 进程间隔离，一个崩溃不影响其他 | 一个线程崩溃（非法内存）通常拖垮整个进程 |
| 表示 | PCB（task_struct） | TCB（Linux 里线程也是 task_struct，共享 mm） |

### 1.2 进程状态（五状态模型）

```text
        创建 new
          │ 接纳
          ▼
      ┌────────┐  调度/时间片到   ┌────────┐
      │ Ready  │◄──────────────►│Running │
      │ 就绪   │─────调度──────►│ 运行   │
      └────────┘                └───┬────┘
          ▲                         │ 等待事件(IO/信号量)
          │ 事件到达/唤醒            ▼
          │                    ┌────────┐
          └────────────────────│ Blocked│
                               │ 阻塞   │
                               └────────┘
          运行 ──退出──► Terminated 终止
```

- 就绪→运行：被调度器选中；运行→就绪：时间片用完/被高优先级抢占；运行→阻塞：主动等资源；阻塞→就绪：资源就绪（**不能直接回到运行**）。
- Linux 实际用更细的状态：R/S/D/T/Z（运行、可中断睡眠、**不可中断睡眠 D（等磁盘 IO，kill 不掉）**、停止、僵尸）。

### 1.3 线程的三种实现模型

| 模型 | 映射 | 特点 |
| --- | --- | --- |
| 用户级线程（多对一） | 多个用户线程映射一个内核线程 | 切换不进内核、极快；但一个阻塞全阻塞（如早期绿色线程、协程） |
| 内核级线程（一对一） | 每个用户线程一个内核线程 | 一个阻塞不影响其他，Linux/NPTL、Windows 采用；切换进内核有开销 |
| 两级（多对多） | M 个用户线程映射 N 个内核线程 | 折中，Go 的 GMP 属此类思想 |

> **协程（coroutine）**：用户态协作式调度，主动让出（co_await/yield）才切换，无内核切换与抢占开销；但一个协程阻塞会卡住线程内其他协程，所以协程网络库必须配非阻塞 IO + 事件循环（见《../13-并发异步与组件/01-协程框架原理与实现.md》）。

### 1.4 上下文切换开销从哪来

保存/恢复寄存器与程序计数器、切栈、切页表（进程切换才刷 TLB，同进程线程切换不刷）、调度器选下一个任务、缓存变冷。减少切换手段：线程池、协程、批量处理、绑核。`vmstat` 的 `cs` 列即每秒上下文切换次数，异常高说明线程过多/锁竞争。

## 2. 进程通信（IPC）

| 方式 | 特点 | 适用 |
| --------- | -------- | ----- |
| 匿名管道 pipe | 半双工、内存中、仅限有亲缘（父子）进程；`|` 就是它 | 简单数据流、shell 管线 |
| 命名管道 FIFO | 有文件路径，无亲缘进程也可连 | 持久命名通道 |
| 信号 signal | 异步、只带编号（SIGKILL/SIGTERM/SIGCHLD…） | 事件通知，不适合传数据 |
| 信号量 semaphore | 内核维护的计数器 | 同步/互斥，不传数据 |
| 共享内存 shm | 同一块物理页映射到多进程地址空间，**零拷贝、最快** | 大数据量，必须配信号量/互斥 |
| 消息队列 | 内核链表，按消息为单位、有类型 | 结构化消息（现已少用） |
| Socket | 可跨主机、也可本地（Unix Domain Socket） | 网络/本机服务通信 |

```cpp
// 共享内存：最快的 IPC，配合信号量同步
int shmid = shmget(key, size, IPC_CREAT | 0666);
char* p = (char*)shmat(shmid, NULL, 0);   // 挂接到本进程地址空间
// 读写 p（无拷贝，直接操作同一物理页）...
shmdt(p);                                 // 脱接；shmctl 删除
```

> 速度排序：共享内存（无拷贝）> 管道/UDS（内核拷贝）> socket（跨网络还要走协议栈）。共享内存快在数据不经内核中转，但同步仍需信号量/futex。

## 3. 线程同步

| 机制 | 说明 |
| ------------ | ------- |
| 互斥量 mutex | 二值，互斥进入临界区 |
| 条件变量 cond | "等待某条件成立"，必须配合 mutex 与**循环判断**（防虚假唤醒） |
| 信号量 sem | 计数，控制 N 个并发资源；初值 1 即互斥锁 |
| 读写锁 rwlock | 读共享、写独占，读多写少 |
| 自旋锁 spinlock | 忙等不睡眠，临界区极短且不可睡眠时用（内核常用） |

### 3.1 生产者-消费者（条件变量标准写法）

```cpp
#include <mutex>
#include <condition_variable>
#include <queue>

template <class T>
class BlockingQueue {
    std::queue<T> q_;
    std::mutex m_;
    std::condition_variable not_empty_, not_full_;
    size_t cap_;
public:
    explicit BlockingQueue(size_t cap) : cap_(cap) {}
    void push(T v) {
        std::unique_lock<std::mutex> lk(m_);
        not_full_.wait(lk, [&]{ return q_.size() < cap_; });  // 满了等；谓词防虚假唤醒
        q_.push(std::move(v));
        not_empty_.notify_one();                               // 唤醒一个消费者
    }
    T pop() {
        std::unique_lock<std::mutex> lk(m_);
        not_empty_.wait(lk, [&]{ return !q_.empty(); });       // 空了等
        T v = std::move(q_.front()); q_.pop();
        not_full_.notify_one();
        return v;
    }
};
```

要点：**wait 必带谓词**（等价 `while(!cond) wait`）；先持锁改状态再通知；消费者和生产者用两个条件变量避免惊群。C++ 完整并发原语见《../04-并发编程/03-条件变量与异步任务.md》。

### 3.2 信号量 vs 互斥量

互斥量是"加锁-解锁"且**谁加谁解**、二值；信号量是计数、可由一个线程 V、另一个线程 P（适合"发放许可/事件计数"）。初值为 1 的信号量在互斥语义上接近锁，但没有属主概念。

## 4. 死锁

### 4.1 四个必要条件（缺一不可，同时成立才可能死锁）

| 条件 | 说明 | 破坏方法 |
| ----- | ---------- | ---------- |
| 互斥 | 资源同一时刻只能一个占用 | 一般无法破坏（资源本性） |
| 占有并等待 | 持着 A 再等 B | 一次性申请全部资源 |
| 不可剥夺 | 未用完不能强抢 | `trylock` + 失败全放重试 |
| 循环等待 | 等待关系成环 | **固定全局加锁顺序**（最实用） |

### 4.2 经典 ABBA 与处理策略

```text
线程1：lock(A) → lock(B)        线程2：lock(B) → lock(A)   → 互相等待成环
```

| 策略 | 说明 |
| -- | ------------------- |
| 预防 | 破坏四条件之一（固定顺序、一次申请） |
| 避免 | **银行家算法**：分配前先模拟，只有分配后系统仍"安全"才分 |
| 检测与解除 | 资源分配图找环，然后终止/回滚进程 |
| 鸵鸟策略 | 不理会（多数通用 OS/业务系统，靠超时与重启兜底） |

### 4.3 银行家算法（安全序列判定）

```cpp
#include <vector>
// available：各类可用资源数；max/need/allocation：进程的最大需求/尚需/已占
// 返回是否存在一个让所有进程都能依次完成的安全序列
bool isSafe(std::vector<int> avail,
            const std::vector<std::vector<int>>& need,
            const std::vector<std::vector<int>>& alloc) {
    int n = need.size(), m = avail.size();
    std::vector<bool> finish(n, false);
    std::vector<int> work = avail;
    for (int k = 0; k < n; ++k) {                       // 最多找 n 轮
        bool progressed = false;
        for (int i = 0; i < n; ++i) {
            if (finish[i]) continue;
            bool canRun = true;
            for (int j = 0; j < m; ++j)
                if (need[i][j] > work[j]) { canRun = false; break; }
            if (canRun) {                               // i 能跑完，释放其占用
                for (int j = 0; j < m; ++j) work[j] += alloc[i][j];
                finish[i] = true; progressed = true;
            }
        }
        if (!progressed) break;                         // 这轮没人能跑，必死锁
    }
    for (bool f : finish) if (!f) return false;         // 有进程永远轮不到 → 不安全
    return true;
}
```

### 4.4 工程实践

- **固定加锁顺序**：所有线程按同一顺序（如按锁地址排序）加锁；C++ 用 `std::scoped_lock lk(a,b)` 让库做免死锁加锁。
- **活锁**：线程没阻塞但都在"谦让重试"导致谁都无法推进（加随机退避）；**饥饿**：某线程长期抢不到资源（老化/公平锁）。这两者不是死锁但同样要避免。

## 5. 虚拟内存

### 5.1 为什么要虚拟内存

每个进程拥有**独立、连续的虚拟地址空间**，经页表映射到离散物理页。带来：进程隔离与保护、内存"超卖"（换页到磁盘，看似比物理内存大）、共享库/共享内存、简化链接与加载（固定起始地址）。

### 5.2 分页、分段与多级页表

| 机制 | 说明 |
| --- | --- |
| 分段 | 按逻辑段（代码/数据/栈）映射，长度可变；会产生**外部碎片** |
| 分页 | 固定大小页（x86 通常 4KB），产生内部碎片但无外部碎片，现代主流 |
| 多级页表 | 页表本身分级（x86-64 四级：PML4→PDPT→PD→PT），用不到的层级不分配，省内存 |
| TLB | 页表缓存（在 MMU 里），缓存"虚拟页→物理页帧"，miss 要走多级页表（~多次访存），大页可降低 miss |

### 5.3 缺页与写时复制

| 概念 | 说明 |
| --- | --- |
| 缺页异常 page fault | 访问的页不在物理内存，陷入内核处理：**次缺页**（页在内存但没建映射，如刚 mmap/共享页，快）vs **主缺页**（要从磁盘读，慢，~ms） |
| 写时复制 COW | `fork()` 后父子共享同一物理页并标只读；谁写就触发缺页、**复制一份**再写。fork 因此极快 |
| swap | 冷页换出到磁盘，用到再换入；频繁换入换出叫**抖动 thrashing**，系统卡死 |
| mmap | 把文件/匿名内存映射进地址空间，按需缺页加载，避免 read 的一次拷贝 |
| 零拷贝 | sendfile/mmap/splice 减少"内核↔用户"拷贝，高并发网络常用（见《../03-网络编程/02-IO多路复用与Reactor模型.md》） |

### 5.4 页面置换算法

| 算法 | 说明 | 特点 |
| ----- | -------- | ------------ |
| OPT 最佳 | 淘汰"将来最久才用"的页 | 理论最优，需预知未来，只作上界对照 |
| FIFO | 淘汰最早进入的 | 简单；有 **Belady 异常**（帧数增多缺页反而增多） |
| LRU | 淘汰最久未使用 | 局部性好、效果好；精确实现需每次访问更新，开销大 |
| Clock/NRU | LRU 的近似：访问位 + 环形指针扫描 | 硬件友好，OS 实际采用这类近似 |
| LFU | 淘汰访问次数最少 | 能抗突发但旧高频难淘汰 |

### 5.5 LRU 的 O(1) 实现（哈希表 + 双向链表）

```cpp
#include <list>
#include <unordered_map>
#include <utility>

class LRUCache {
    int cap_;
    std::list<std::pair<int,int>> list_;                      // 头=最近，尾=最久
    std::unordered_map<int, std::list<std::pair<int,int>>::iterator> map_;
public:
    explicit LRUCache(int cap) : cap_(cap) {}
    int get(int key) {
        auto it = map_.find(key);
        if (it == map_.end()) return -1;
        list_.splice(list_.begin(), list_, it->second);       // 提到最前
        return it->second->second;
    }
    void put(int key, int val) {
        auto it = map_.find(key);
        if (it != map_.end()) { it->second->second = val;
                               list_.splice(list_.begin(), list_, it->second); return; }
        if ((int)list_.size() == cap_) {                      // 满了淘汰尾部
            map_.erase(list_.back().first); list_.pop_back();
        }
        list_.emplace_front(key, val);
        map_[key] = list_.begin();
    }
};
```

## 6. 进程调度算法

| 算法 | 说明 | 特点 |
| -------- | ---------- | ----------- |
| FCFS 先来先服务 | 按到达顺序，非抢占 | 简单；护航效应，长任务堵短任务 |
| SJF/SPN 最短作业优先 | 选预计运行最短的 | 平均等待最短；需预知时长；长任务可能饥饿 |
| 优先级调度 | 高优先级先（抢占/非抢占） | 灵活；低优先级可能饥饿，用**老化（aging）**解决 |
| RR 时间片轮转 | 每任务跑一个时间片后排队 | 公平、响应快，适合交互；时间片太小切换频繁、太大退化为 FCFS |
| 多级反馈队列 MLFQ | 多优先级队列 + 动态升降级 | 兼顾长短任务，通用 OS 主流思想 |

### Linux 的实际调度器

| 调度类 | 面向 | 策略 |
| --- | --- | --- |
| CFS（完全公平调度） | 普通进程（SCHED_NORMAL） | 用红黑树按 **vruntime（虚拟运行时间）** 选最小者，nice 值映射权重，时间片动态 |
| RT 实时类（FIFO/RR） | 实时进程 | 优先级高于 CFS，SCHED_FIFO 跑到阻塞/让出，SCHED_RR 同优先级轮转 |
| Deadline | 硬实时 | 按截止期调度（EDF 思想） |

> 计算密集型任务 nice/优先级影响有限，真正决定吞吐的是核数、缓存与调度域；低延迟场景用 `chrt`、绑核（taskset/cgroup cpuset）减少迁移。

## 7. I/O 模型（与网络编程衔接）

| 模型 | 是否阻塞等待数据 | 是否阻塞在拷贝 | 典型 |
| --- | --- | --- | --- |
| 阻塞 IO | 是 | 是 | 默认 read |
| 非阻塞 IO | 否（轮询返回 EAGAIN） | 是 | O_NONBLOCK |
| IO 多路复用 | select/poll/epoll 等一批 fd | 是 | Reactor 基石 |
| 信号驱动 IO | 否（SIGIO 通知） | 是 | 少用 |
| 异步 IO（AIO/io_uring） | 否 | **否（内核拷完才回调）** | Proactor、io_uring |

> 五种模型的内核差异、select/poll/epoll 演进、Reactor/Proactor 详见《../03-网络编程/02-IO多路复用与Reactor模型.md》；用户态协议栈/DPDK 见《../13-并发异步与组件/03-用户态协议栈与DPDK.md》。

## 8. 快速参考卡片

```text
进程=资源单位（独立地址空间），线程=调度单位（共享进程、私有栈）
状态：就绪⇄运行→阻塞→就绪；Linux R/S/D/T/Z，D 是不可中断睡眠
协程=用户态协作式，必须配非阻塞IO+事件循环
IPC 速度：共享内存(零拷贝) > 管道/UDS > socket；同步用信号量
条件变量：unique_lock + wait(谓词)，先改状态再 notify
死锁四条件：互斥+占有等待+不可剥夺+循环等待；固定加锁顺序/scoped_lock 破环
银行家：分配后仍存在安全序列才分配
虚拟内存：多级页表+TLB；缺页(主/次)；fork 用 COW；抖动=频繁换入换出
置换：OPT(理论)/FIFO(Belady)/LRU(哈希+双向链表O(1))/Clock(近似)
调度：FCFS/SJF/优先级/RR/MLFQ；Linux CFS 按 vruntime 选最小
IO 模型：阻塞/非阻塞/多路复用/信号驱动/异步；epoll→Reactor，AIO→Proactor
```

## 9. 常见问题与坑

1. 加锁顺序不一致导致死锁，且难复现——统一顺序或 `scoped_lock`。
2. 共享内存忘记同步导致数据竞争——共享内存只解决"传"，不解决"同步"。
3. 条件变量用裸 `wait` 不带谓词，遇虚假唤醒/丢失唤醒出错——永远 `wait(lk, pred)`。
4. 混淆互斥量与信号量：互斥量有属主、谁加谁解；信号量是许可计数。
5. 以为多线程一定快：上下文切换、TLB/缓存失效、锁竞争、内存带宽都会反噬。
6. 把"缺页"都当慢操作：次缺页（COW、已在内存）很便宜，主缺页（读盘）才是毫秒级。
7. LRU 只讲思路不会写：哈希表 + 双向链表，访问/插入都 O(1)。
8. kill 不掉某进程：它处于 D 状态（不可中断，卡在磁盘 IO），只能等 IO 返回或排查存储。
9. 以为 fork 会完整拷贝内存：现代靠 COW 共享，写时才复制。
