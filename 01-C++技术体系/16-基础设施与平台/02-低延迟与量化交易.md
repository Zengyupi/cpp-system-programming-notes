## 1. 延迟层级与来源

### 1.1 延迟数量级认知

| 操作 | 典型延迟 | 说明 |
| --- | --- | --- |
| L1 缓存访问 | ~1 ns | 最快的片上存储 |
| L2 缓存访问 | ~4 ns | 片上，容量更大 |
| L3 缓存访问 | ~12 ns | 多核共享 |
| 主存访问 | ~80~100 ns | DRAM，比缓存慢一个数量级 |
| 系统调用 | ~100~300 ns | 陷入内核，上下文切换 |
| 互斥锁加解锁 | ~20~50 ns | 无竞争时；有竞争可达微秒级 |
| 网络包处理（内核栈） | ~5~20 μs | 从网卡到用户态 |
| 同机房网络往返 | ~50~200 μs | 取决于距离和交换机 |
| 跨城市网络往返 | ~1~10 ms | 光速限制 |

> 关键认知：在纳秒/微秒级优化中，**一次系统调用、一次缓存未命中、一次锁竞争都可能是致命的**。低延迟优化的本质是减少"不可预测的延迟来源"，而不仅仅是降低平均延迟。

### 1.2 延迟构成分解

```text
行情到达 → 网卡硬件 → 网卡驱动 → 内核协议栈 → 系统调用 → 用户态
  → 行情解码 → 策略计算 → 风控 → 下单编码 → 系统调用 → 内核协议栈
  → 网卡驱动 → 网卡硬件 → 网络发出
```

延迟来源：
- **网络传输延迟**：物理距离（光速限制）、交换机排队、带宽；
- **协议栈处理延迟**：内核网络栈处理、中断、软中断；
- **上下文切换延迟**：用户态/内核态切换、线程调度切换；
- **锁竞争延迟**：自旋等待、阻塞睡眠、唤醒；
- **内存分配延迟**：malloc/free、缺页中断、TLB miss；
- **缓存未命中延迟**：L1/L2/L3/主存层级延迟差异。

## 2. 内核旁路（Kernel Bypass）

内核协议栈是低延迟系统的主要瓶颈之一：中断处理、软中断、系统调用、锁、内存拷贝都引入不可预测延迟。内核旁路技术让用户态直接操作网卡。

### 2.1 DPDK（Data Plane Development Kit）

| 特性 | 说明 |
| --- | --- |
| **UIO/VFIO** | 将网卡寄存器映射到用户态，绕过内核驱动 |
| **轮询模式驱动 PMD** | 不用中断，主动轮询网卡收包队列，避免中断延迟和抖动 |
| **大页内存 HugePage** | 预分配大页（2MB/1GB），减少 TLB miss |
| **无锁环形队列 rte_ring** | 多生产者多消费者无锁队列，核间通信 |
| **CPU 亲和** | 每个核绑定一个收包/处理线程，避免调度迁移 |

```text
传统路径：网卡→中断→软中断→内核协议栈→socket→用户态（多次拷贝+上下文切换）
DPDK路径：网卡→用户态轮询→直接处理（零拷贝、无中断、无系统调用）
```

### 2.2 其他内核旁路方案

| 方案 | 说明 |
| --- | --- |
| **Solarflare Onload / Exablaze** | 商用网卡+用户态驱动，延迟极低（<1μs），高频交易常用 |
| **AF_XDP** | Linux 内核方案，XDP(eBPF)在网卡驱动层处理包，可重定向到用户态，无需特殊硬件 |
| **XDP(eBPF)** | 在内核网卡驱动层直接过滤/转发/修改包，性能接近 DPDK 但更安全 |
| **RDMA** | 远程直接内存访问，绕过 CPU 和内核，网卡直接读写远端内存，延迟 <1μs |
| **FPGA** | 可编程硬件，把行情解码/策略逻辑烧到 FPGA，亚微秒级延迟 |

### 2.3 RDMA（Remote Direct Memory Access）

RDMA 让一台机器的网卡直接读写另一台机器的内存，无需 CPU 和内核参与：
- **Verbs API**：ibv_post_send/ibv_poll_cq，编程模型类似异步 IO；
- **RoCEv2**：基于以太网的 RDMA，数据中心常用；
- **InfiniBand**：专用网络，延迟最低但成本高；
- 适用场景：交易所行情分发、交易系统内部进程间超低延迟通信。

## 3. 零拷贝（Zero-Copy）

传统 `read()+write()` 路径有 4 次拷贝和 4 次上下文切换：
```text
磁盘→内核缓冲区→用户缓冲区→内核socket缓冲区→网卡（4次拷贝）
```

### 3.1 sendfile

```cpp
// sendfile：文件数据直接从内核页缓存到 socket，不经用户态
#include <sys/sendfile.h>
ssize_t sendfile(int out_fd, int in_fd, off_t* offset, size_t count);
```
减少 2 次拷贝（省去用户态缓冲），但仍有内核内拷贝。带 DMA 收集（`splice` + `sendfile`）可实现真正零拷贝。

### 3.2 mmap

```cpp
// mmap：文件映射到进程地址空间，读写如内存，缺页时内核自动加载
void* addr = mmap(NULL, size, PROT_READ, MAP_SHARED | MAP_POPULATE, fd, 0);
// MAP_POPULATE 预缺页，避免运行时缺页中断
```
适用：大文件随机访问、共享内存 IPC。注意 mmap 有缺页中断开销，低延迟场景需预缺页或锁定内存（`mlock`）。

### 3.3 splice / vmsplice

```cpp
// splice：在两个文件描述符间移动数据，不需用户态拷贝（内核管道中转）
ssize_t splice(int fd_in, loff_t* off_in, int fd_out, loff_t* off_out,
               size_t len, unsigned int flags);
// vmsplice：用户态内存直接"拼"到管道，配合 splice 实现真零拷贝
```

### 3.4 io_uring

Linux 5.1+ 的异步 IO 框架，用共享内存环形队列提交/完成 IO，**一次系统调用可批量提交多个 IO**，大幅减少系统调用开销：
```cpp
// 概念：提交队列(SQ)和完成队列(CQ)在用户态和内核间共享
// io_uring_enter 批量提交，轮询 CQ 取结果，无需每个 IO 都系统调用
```
io_uring 是传统异步 IO（libaio）的现代替代，支持网络、文件、管道等多种 fd。

## 4. CPU 亲和与实时调度

### 4.1 隔离核心（isolcpus）

```bash
# 内核启动参数：隔离 CPU 2,3，内核调度器不会把普通线程调度到这些核上
isolcpus=2,3 nohz_full=2,3 rcu_nocbs=2,3
# nohz_full：完全无时钟中断（dyntick-idle），减少抖动
# rcu_nocbs：RCU 回调不在这些核上执行
```

### 4.2 线程绑核

```cpp
#include <sched.h>
cpu_set_t cpuset;
CPU_ZERO(&cpuset);
CPU_SET(2, &cpuset);                    // 绑定到核 2
pthread_setaffinity_np(pthread_self(), sizeof(cpuset), &cpuset);

// 关闭该核的中断均衡，将中断绑到其他核
// echo 1 > /proc/irq/<n>/smp_affinity（把中断绑到核0）
```

### 4.3 实时调度策略

```cpp
#include <sched.h>
struct sched_param param;
param.sched_priority = 99;              // 实时优先级 1~99
pthread_setschedparam(pthread_self(), SCHED_FIFO, &param);
// SCHED_FIFO：先入先出实时策略，高优先级抢占低优先级
// SCHED_RR：时间片轮转实时策略
```
注意：实时进程如果不释放 CPU（死循环）会饿死其他进程，必须谨慎使用。

### 4.4 其他减少抖动的手段

| 手段 | 说明 |
| --- | --- |
| 关闭超线程 SMT | 避免同核两个线程争抢执行单元和缓存 |
| 关闭 CPU 节能（C-state/P-state） | 避免频率切换和睡眠唤醒延迟 |
| `mlockall(MCL_CURRENT\|MCL_FUTURE)` | 锁定进程内存，防止换出和缺页 |
| 预分配大页内存 | 避免运行时 malloc 和缺页 |
| 关闭 ASLR | 地址随机化导致缓存布局不确定（安全权衡） |

## 5. 无锁编程与内存池

### 5.1 无锁队列（SPSC 单生产者单消费者）

低延迟系统中，锁竞争是抖动的主要来源。SPSC 环形队列用原子操作实现无锁：

```cpp
template<typename T, size_t N>
class SPSCQueue {
    std::array<T, N> buf_;
    std::atomic<size_t> head_{0}, tail_{0};
public:
    bool push(const T& val) {
        size_t tail = tail_.load(std::memory_order_relaxed);
        size_t next = (tail + 1) % N;
        if (next == head_.load(std::memory_order_acquire)) return false; // 满
        buf_[tail] = val;
        tail_.store(next, std::memory_order_release);
        return true;
    }
    bool pop(T& out) {
        size_t head = head_.load(std::memory_order_relaxed);
        if (head == tail_.load(std::memory_order_acquire)) return false; // 空
        out = buf_[head];
        head_.store((head + 1) % N, std::memory_order_release);
        return true;
    }
};
```
- MPMC（多生产者多消费者）更复杂，需用 CAS 循环或每线程分桶；
- 内存序选择：生产者用 release，消费者用 acquire，建立 happens-before。

### 5.2 内存池

热路径上 `malloc/free` 不可接受（加锁、brk/mmap 系统调用、碎片）：
```cpp
// 固定大小内存池：预分配一大块，用 free list 管理
template<typename T, size_t N>
class ObjectPool {
    std::array<T, N> pool_;
    std::array<size_t, N> free_list_;
    size_t free_head_;
public:
    ObjectPool() : free_head_(0) { for (size_t i = 0; i < N; ++i) free_list_[i] = i; }
    T* alloc() { return &pool_[free_list_[free_head_++]]; }  // O(1)，无锁
    void free(T* p) { free_list_[--free_head_] = p - pool_.data(); }
};
```
- 消息/对象全部预分配，运行时无动态分配；
- 环形缓冲 + 内存池是低延迟系统的标准组合。

## 6. 共享内存 IPC

进程间通信用共享内存（零拷贝）+ 无锁队列，比 socket/管道快一个数量级：

```cpp
#include <sys/mman.h>
#include <fcntl.h>
// 创建共享内存对象
int fd = shm_open("/latency_shm", O_CREAT | O_RDWR, 0666);
ftruncate(fd, sizeof(SharedData));
SharedData* data = (SharedData*)mmap(NULL, sizeof(SharedData),
    PROT_READ | PROT_WRITE, MAP_SHARED, fd, 0);
// data 内放 SPSC 环形队列，进程 A 写、进程 B 读，无需内核参与
```
- `shm_open` + `mmap` 是 POSIX 共享内存；
- 也可用 `mmap` 映射普通文件（需 `msync` 持久化）；
- 同步用原子变量或 futex（比信号量快）。

## 7. 低延迟交易系统架构

```text
┌──────────────────────────────────────────────────────────┐
│ 行情源（交易所组播/点对点）                                │
├──────────────────────────────────────────────────────────┤
│ 接入层：DPDK/FPGA 低延迟收包 → 行情解码（FIX/ITCH/二进制） │
├──────────────────────────────────────────────────────────┤
│ 行情分发：共享内存 + SPSC 无锁队列 → 多策略进程            │
├──────────────────────────────────────────────────────────┤
│ 策略引擎：事件驱动、内存计算、信号生成                     │
├──────────────────────────────────────────────────────────┤
│ 风控层：预交易风控（持仓/资金/频率/价格限制）               │
├──────────────────────────────────────────────────────────┤
│ 订单通道：编码(FIX/二进制) → DPDK/内核旁路 → 交易所        │
└──────────────────────────────────────────────────────────┘
```

### 7.1 设计原则

| 原则 | 说明 |
| --- | --- |
| **每核一个角色** | 收包核、解码核、策略核、下单核分离，通过共享内存队列通信 |
| **无锁无系统调用** | 热路径上不调用 malloc、不获取锁、不做系统调用 |
| **忙轮询 Busy-Wait** | 用 `while(queue.empty()) _mm_pause();` 轮询，避免条件变量的唤醒延迟 |
| **内存预分配** | 所有对象/消息在启动时分配，运行时零分配 |
| **无共享数据竞争** | 数据所有权明确传递（队列转移所有权），而非多线程共享修改 |
| **抖动隔离** | 关键线程在隔离核上，非关键线程（日志、监控）在其他核 |

### 7.2 行情解码优化

- 行情协议（如 NASDAQ ITCH、上交所 Binary）通常是组播 UDP，需处理丢包重传；
- 解码用查表/偏移直接读取，避免内存拷贝；
- 用 `__builtin_prefetch` 预取下一条消息到缓存。

## 8. 性能测量与抖动分析

### 8.1 精确计时

```cpp
// rdtsc：读取 CPU 时间戳计数器，纳秒级精度（需校准频率）
static inline uint64_t rdtsc() {
    uint32_t lo, hi;
    __asm__ __volatile__("rdtsc" : "=a"(lo), "=d"(hi));
    return ((uint64_t)hi << 32) | lo;
}
// 或用 clock_gettime(CLOCK_MONOTONIC_RAW)，不受 NTP 调整影响
```

### 8.2 关键指标

| 指标 | 说明 | 关注点 |
| --- | --- | --- |
| **平均延迟** | 所有样本均值 | 参考价值有限，可能被极端值掩盖 |
| **P50/P99/P99.9/P99.99** | 百分位延迟 | **尾部延迟是低延迟系统的核心指标** |
| **抖动 Jitter** | 延迟的标准差/最大-最小 | 抖动比均值更重要，不可预测的延迟最危险 |
| **吞吐** | 每秒消息/订单数 | 延迟和吞吐需平衡 |
| **缓存命中率** | L1/L2/L3 hit rate | 缓存未命中是主要延迟来源 |
| **上下文切换次数** | `pidstat -w` | 关键线程应为 0 |

### 8.3 测量工具

```bash
perf stat -e cache-misses,cache-references,cycles,instructions ./app  # 性能计数
perf record -g ./app && perf report                                   # 火焰图
lat_ctx --num-runs 10000 ./app                                        # 延迟分布
cyclictest -t1 -p 99 -n -i 1000 -l 10000                              # 内核延迟测试
bpftrace/ftrace                                                        # 内核追踪
```


## 10. 常见问题与坑

1. **过度优化忽略业务正确性**：先测量再优化，低延迟不能以牺牲正确性为代价。
2. **热路径动态内存分配**：malloc 引入不可控延迟，必须预分配内存池。
3. **未绑定 CPU 核心**：线程迁移导致缓存失效，关键线程必须绑核+隔离核。
4. **锁粒度过大或自旋锁竞争**：延迟抖动严重，用无锁队列或细粒度锁，关键路径无锁。
5. **只看平均延迟**：均值掩盖尾部问题，必须统计 P99/P99.9 和抖动。
6. **条件变量等待/唤醒**：唤醒延迟可达数十微秒，低延迟用忙轮询（busy-wait）。
7. **中断处理在关键核上**：将网卡中断绑到非关键核，关键核关中断均衡。
8. **大页内存未预分配**：运行时缺页中断导致抖动，启动时预分配并 mlock。
9. **日志/监控在热路径**：日志写入引入 IO 和锁，用无锁环形缓冲异步写日志。
10. **忽略缓存行伪共享（False Sharing）**：多线程变量在同一缓存行导致频繁失效，用 `alignas(64)` 填充隔离。
