## 2. 红黑树

### 2.1 五条性质【高频】

红黑树是每个节点带颜色（红/黑）的二叉搜索树，用"颜色约束"换取"近似平衡"（最长路径 ≤ 2×最短路径）：

| 序号 | 性质 | 违反后果 |
|---|---|---|
| 1 | 每个节点非红即黑 | —— |
| 2 | 根节点是黑色 | 可在 fixup 末尾强制染黑 |
| 3 | 每个叶子（NIL 哨兵）是黑色 | 实现上用一个共享黑色哨兵代替所有 NULL |
| 4 | 红节点的两个孩子必须是黑（不存在连续红） | 插入后可能违反 → 插入 fixup 的唯一目标 |
| 5 | 任一节点到其所有后代叶子的路径含相同数量黑节点（黑高相同） | 删除后可能违反 → 删除 fixup 的目标 |

推论（面试加分点）：n 个内部节点的红黑树高度 ≤ 2·log₂(n+1)（因为黑高为 bh 的子树至少含 2^bh − 1 个节点）——"最坏 O(log n)"的来源；也因此插删只需局部变色/旋转，不像 AVL 要回溯调整全路径。

### 2.2 旋转：唯一改变结构的操作

```text
左旋(支点x): 右孩子y上位, x降为y的左孩子
      x                y
       \              / \
        y    ==>     x   β
       / \            \
      α   β            α

右旋(支点x): 左孩子y上位, x降为y的右孩子（镜像）
```

旋转只动 3 根指针 + 2 个 parent 回指，O(1)，且**不破坏二叉搜索树性质**（α 子树所有键仍在 x、y 之间正确位置）。

完整可用的旋转代码（哨兵 nil 版本，epoll 内核同款思路）：

```c
#include <stdio.h>
#include <stdlib.h>

typedef int KEY_TYPE;
#define RED   0
#define BLACK 1

typedef struct _rbtree_node {
    KEY_TYPE key;
    struct _rbtree_node *left, *right, *parent;
    int color;
    void *value;                  // 关联数据（epoll 里就是 epitem）
} rbtree_node;

typedef struct _rbtree {
    rbtree_node *root;
    rbtree_node *nil;             // 黑色哨兵：所有叶子和根的 parent
} rbtree;

/* 左旋：x 为支点 */
void rbtree_left_rotate(rbtree *T, rbtree_node *x) {
    rbtree_node *y = x->right;

    x->right = y->left;                        // 1. y 的左子树挂到 x 右边
    if (y->left != T->nil) y->left->parent = x;

    y->parent = x->parent;                     // 2. y 接管 x 的父亲
    if (x == T->root)                T->root = y;
    else if (x == x->parent->left)   x->parent->left  = y;
    else                             x->parent->right = y;

    y->left   = x;                             // 3. x 变成 y 的左孩子
    x->parent = y;
}

/* 右旋：镜像，把 left/right 互换即可 */
void rbtree_right_rotate(rbtree *T, rbtree_node *x) {
    rbtree_node *y = x->left;

    x->left = y->right;
    if (y->right != T->nil) y->right->parent = x;

    y->parent = x->parent;
    if (x == T->root)                T->root = y;
    else if (x == x->parent->right)  x->parent->right = y;
    else                             x->parent->left  = y;

    y->right  = x;
    x->parent = y;
}
```

### 2.3 插入：3 种情况【高频】

新节点 z 染**红**（不破坏黑高，只可能违反性质 4"连续红"），沿树向上修复。判断只看两个颜色：**父亲**与**叔叔**：

| 情况 | 条件（父在祖父左侧） | 处理 | 复杂度 |
|---|---|---|---|
| 1 | 父红、叔红 | 父叔变黑、祖父变红，z 上移到祖父继续 | 变色，最多 O(log n) 次 |
| 2 | 父红、叔黑、z 是父的右孩子（LR 型） | 绕父左旋 → 转成情况 3 | 1 次旋转 |
| 3 | 父红、叔黑、z 是父的左孩子（LL 型） | 父变黑、祖父变红、绕祖父右旋 | 1 次旋转，结束 |

插入 fixup 框架（完整可编译的核心逻辑）：

```c
void rbtree_insert_fixup(rbtree *T, rbtree_node *z) {
    while (z->parent->color == RED) {                  // 违反性质4才动
        if (z->parent == z->parent->parent->left) {    // 父在祖父左侧
            rbtree_node *u = z->parent->parent->right; // 叔叔
            if (u->color == RED) {                     // 情况1：叔红
                z->parent->color = BLACK;
                u->color = BLACK;
                z->parent->parent->color = RED;
                z = z->parent->parent;                 // 上移两级
            } else {
                if (z == z->parent->right) {           // 情况2：LR
                    z = z->parent;
                    rbtree_left_rotate(T, z);          // 转成 LL
                }
                z->parent->color = BLACK;              // 情况3：LL
                z->parent->parent->color = RED;
                rbtree_right_rotate(T, z->parent->parent);
            }
        } else {                                       // 镜像：父在右侧
            rbtree_node *u = z->parent->parent->left;
            if (u->color == RED) {
                z->parent->color = BLACK;
                u->color = BLACK;
                z->parent->parent->color = RED;
                z = z->parent->parent;
            } else {
                if (z == z->parent->left) {
                    z = z->parent;
                    rbtree_right_rotate(T, z);
                }
                z->parent->color = BLACK;
                z->parent->parent->color = RED;
                rbtree_left_rotate(T, z->parent->parent);
            }
        }
    }
    T->root->color = BLACK;                            // 性质2兜底
}

/* 外层 rbtree_insert：常规 BST 定位插入点（parent 接好、左右指向哨兵）、
   新节点染红，最后调用 rbtree_insert_fixup(T, z)。定位与普通 BST 相同，略 */
```

### 2.4 删除：4 种情况分析

删除按 BST 方式先摘节点（至多 1 个孩子），被"移走颜色"的路径若少了黑色，则产生**双重黑**节点 x，靠兄弟 w 修复。设 x 是父的左孩子，w 是右兄弟（右侧镜像对称）：

| 情况 | 兄弟/侄子颜色组合 | 处理 | 走向 |
|---|---|---|---|
| 1 | w 红（侄子必黑） | w 变黑、父变红、绕父左旋；新 w 必黑 | 转入 2/3/4 |
| 2 | w 黑，w 两个孩子全黑 | w 变红，双重黑上移给父（父红则直接染黑终止） | 可能继续循环 |
| 3 | w 黑，近侄红、远侄黑 | 近侄变黑、w 变红、绕 w 右旋 | 转成情况 4 |
| 4 | w 黑，远侄红 | w 染成父色、父变黑、远侄变黑、绕父左旋 | 双重黑消除，结束 |

代码与插入 fixup 同构：`while (x != T->root && x->color == BLACK)` 循环 + 四分支；插入最多 2 次旋转、删除最多 3 次旋转，变色可能 O(log n) 次。面试口述：摘的是黑节点才 fixup → 双重黑概念 → 按上表四情况推进。

### 2.5 红黑树 vs AVL 对比【高频】

| 对比项 | AVL | 红黑树 |
|---|---|---|
| 平衡严格度 | 严格：左右子树高差 ≤ 1 | 近似：最长 ≤ 2×最短 |
| 查询性能 | 更快（更矮更匀） | 略慢（同量级） |
| 插入旋转 | 最多 2 次（LL/RR/LR/RL） | 最多 2 次 |
| 删除旋转 | 最坏回溯到根，O(log n) 次旋转 | 最多 3 次 |
| 写多场景 | 差（频繁重平衡） | 好 |
| 典型使用 | 只读/读极多数据库内存索引 | 内核（epoll/CFS）、STL map、nginx timer |

为什么 STL/内核选红黑树：插入删除的**旋转次数有常数上限**，树高只差一个常数因子，综合读写性价比更高；AVL 的严格平衡在写频繁时代价大。

### 2.6 线程安全的做法

读多写少用**读写锁**；读极多写极少用 **RCU**（读侧零开销裸读，写侧复制 + 宽限期延迟回收，内核 VMA/路由表同款）；写并发高用**分片锁**（按 key 分片到多棵小树）；数据库索引用**不可变树**（写时复制整条路径，读永远无锁）。

手撕自测：随机插入后中序有序 + 递归校验 5 条性质（黑高一致）；哨兵 nil 让 fixup 无需判空。

## 3. B 树与 B+ 树

### 3.1 磁盘页与 IO 次数 = 树高

机械盘一次随机 IO 约 10ms（寻道+旋转），SSD 约 100μs，而内存访问约 100ns——差 4~6 个数量级。所以磁盘数据结构的设计目标只有一个：**把树压矮，一次节点读取尽可能多数据**。

```text
二叉树: 100万数据 → 高约 20 → 20 次磁盘IO
B+树:   节点=16KB页, 每页放 ~200 个键(扇出200)
        100万数据 → 高约 3 → 3 次磁盘IO（根常驻内存则 2 次）
```

| 概念 | 说明 | 示例 |
|---|---|---|
| 磁盘页/块 | 磁盘与内存交换的最小单位，OS 4KB，InnoDB 页 16KB | 节点大小 = 页大小 → 读一个节点 = 1 次 IO |
| 扇出(fanout) | 一个节点的孩子数，阶越高扇出越大，树越矮 | 16KB / (键+指针约 14B) ≈ 1000+ |
| 局部性 | B+ 树叶子物理连续（预读），范围扫描顺序读 | `order by id limit 100` |

### 3.2 B 树的定义（阶 m）

一棵 m 阶 B 树（m 叉搜索树）满足：

| 约束 | 规则 | 目的 |
|---|---|---|
| 节点关键字数 | 最多 m−1，最少 ⌈m/2⌉−1（根除外） | 至少半满，保证树矮 |
| 节点孩子数 | 最多 m，最少 ⌈m/2⌉（根除外，根最少 2） | 与关键字数 = 孩子数−1 对应 |
| 有序性 | 节点内关键字升序；child[i] 的键都 < keys[i] 且 > keys[i−1] | 二分定位 |
| 叶子同层 | 所有叶子在同一深度 | 绝对平衡（从底部长高，不是从顶部长） |

3 阶 B 树就是 2-3 树，4 阶就是 2-3-4 树。

### 3.3 插入：两种分裂

插入永远发生在叶子，满了就**从中间劈开**：

```text
1. 叶分裂: 4阶节点已有3个键, 插入第4个 → 取中间键上移给父亲
   [10 20 30] + 15  →  临时[10 15 20 30] → 上移15
   父亲:      [15]
            /      \
      [10]          [20 30]

2. 根分裂: 上移到根也溢出 → 根分裂, 产生新根, 树整体长高一层
   （B 树从底部长高的唯一方式, 所有叶子仍保持同层;
     叶分裂=中间键上移父节点本节点一分为二; 根分裂=新建只含1键的新根）
```

### 3.4 删除：兄弟借位与节点合并

删除后节点关键字数低于 ⌈m/2⌉−1 时先看兄弟：

| 场景 | 条件 | 操作 |
|---|---|---|
| 直接删 | 节点仍 ≥ 最少键数 | 删掉即可 |
| 兄弟借位 | 相邻兄弟 > 最少键数（富余） | 父亲下移一个键到本节点，兄弟上移一个键给父亲（旋转） |
| 节点合并 | 兄弟也刚好最少 | 本节点 + 父亲分隔键 + 兄弟 三合一，父亲少一个键，可能连锁向上合并；根被合并空则树高 −1（根收缩） |
| 删内部节点键 | —— | 用前驱/后继（叶子里的最近键）替换后转为叶子删除 |

### 3.5 B+ 树定义与叶子链表

| 特性 | B+ 树规则 |
|---|---|
| 非叶节点 | 只存**键（索引）**不存数据，键是孩子节点键的副本（最大/最小键上浮） |
| 叶子节点 | 存**全部键 + 数据（或数据地址）** |
| 孩子数 | 非叶：n 个键 → n+1 个孩子（B 树是 n 键 n+1 孩子但键也带数据） |
| 叶子链表 | 所有叶子用前后指针串成**有序双向/单向链表** |
| 查找 | 每次都要走到叶子（键相等也不停在非叶） |

```text
                     [ 50 ]
                    /      \
            [20 35]          [70 85]           ← 非叶：只有索引键
           /   |   \        /   |   \
  [5 10 20]→[25 30 35]→[40 45 50]→[60 65 70]   ← 叶子：全部键+数据, 链表串联
```

InnoDB 中：主键索引（聚簇）叶子放整行数据；二级索引叶子放主键值（回表）。

### 3.6 B 树 vs B+ 树对比【高频】

| 对比项 | B 树 | B+ 树 |
|---|---|---|
| 非叶节点存数据 | 存（键+数据） | 不存（纯索引） |
| 单键扇出 | 小（数据占空间） | 大（同样 16KB 能放更多键）→ 树更矮 |
| 树高（同数据量） | 更高 | 更低 → IO 更少 |
| 查询稳定性 | 可能中途命中，快慢不一 | 必到叶子，稳定 O(树高) |
| 范围查询/排序 | 中序遍历回溯，差 | 叶子链表顺序扫，极好 |
| 全表扫描 | 遍历所有节点（含内部） | 只扫叶子链表 |
| 典型使用 | 文件系统（如 ext4 的 htree 是 B 树变体）、MongoDB(MMAPv1) | MySQL InnoDB、PostgreSQL、大部分数据库 |

一句话回答面试："MySQL 选 B+ 不选 B 树：非叶不存数据 → 扇出大 → 树矮 IO 少；叶子链表 → 范围查询顺序读；查询路径等长 → 性能稳定。"

### 3.7 并发控制：latch crabbing

B+ 树并发用**锁耦合（latch crabbing / 锁蟹行）**：自顶向下拿到孩子的锁就立刻释放父亲的锁（如蟹行交替），避免整棵树被锁死；读操作可乐观无锁、冲突再重走。一句话记住即可。

### 3.8 手撕 B 树核心代码

完整可编译（插入含分裂、查找、中序遍历；删除按 3.4 分析实现，此处从略）：

```c
#include <stdio.h>
#include <stdlib.h>

#define M 4                     /* 阶：最多 M 个孩子、M-1 个键 */

typedef struct _btree_node {
    int keys[M];                /* 多留 1 格：溢出时临时存放第 M 个键 */
    struct _btree_node *child[M + 1];
    int n;                      /* 当前键数 */
    int leaf;                   /* 1=叶子 */
} btree_node;

typedef struct _btree {
    btree_node *root;
} btree;

static btree_node *bt_new_node(int leaf) {
    btree_node *p = calloc(1, sizeof(btree_node));
    p->leaf = leaf;
    return p;
}

/* 递归插入；返回 1 表示节点分裂，up_key/up_child 交给父节点 */
static int bt_insert_rec(btree_node *node, int key,
                         int *up_key, btree_node **up_child) {
    int i = 0;
    while (i < node->n && key > node->keys[i]) i++;   /* 定位 */

    if (node->leaf) {
        for (int j = node->n; j > i; j--)             /* 叶子：腾位插入 */
            node->keys[j] = node->keys[j - 1];
        node->keys[i] = key;
        node->n++;
    } else {
        int ckey; btree_node *cchild = NULL;
        if (bt_insert_rec(node->child[i], key, &ckey, &cchild)) {
            /* 孩子分裂了：把上来的键与新孩子插入本节点 */
            for (int j = node->n; j > i; j--)
                node->keys[j] = node->keys[j - 1];
            for (int j = node->n; j > i; j--)
                node->child[j + 1] = node->child[j];
            node->keys[i] = ckey;
            node->child[i + 1] = cchild;
            node->n++;
        }
    }

    if (node->n <= M - 1) return 0;                   /* 未溢出 */

    /* 溢出：node 现有 M 个键，从中间劈开 */
    int mid = (M - 1) / 2;                            /* 上移键下标 */
    btree_node *right = bt_new_node(node->leaf);
    right->n = M - 1 - mid;                           /* 右半键数 */
    for (int j = 0; j < right->n; j++)
        right->keys[j] = node->keys[mid + 1 + j];
    if (!node->leaf)
        for (int j = 0; j <= right->n; j++)           /* 孩子跟着走 */
            right->child[j] = node->child[mid + 1 + j];
    node->n = mid;                                    /* 左半保留 */
    *up_key = node->keys[mid];
    *up_child = right;
    return 1;
}

void bt_insert(btree *t, int key) {
    if (!t->root) {                                   /* 空树 */
        t->root = bt_new_node(1);
        t->root->keys[0] = key; t->root->n = 1;
        return;
    }
    int up_key; btree_node *up_child = NULL;
    if (bt_insert_rec(t->root, key, &up_key, &up_child)) {
        btree_node *r = bt_new_node(0);               /* 根分裂：树高+1 */
        r->keys[0] = up_key; r->n = 1;
        r->child[0] = t->root;
        r->child[1] = up_child;
        t->root = r;
    }
}

/* 查找：返回所在节点并把下标写入 *idx，失败返回 NULL */
btree_node *bt_search(btree *t, int key, int *idx) {
    btree_node *node = t->root;
    while (node) {
        int i = 0;
        while (i < node->n && key > node->keys[i]) i++;
        if (i < node->n && key == node->keys[i]) { *idx = i; return node; }
        if (node->leaf) return NULL;
        node = node->child[i];                        /* 下潜 */
    }
    return NULL;
}

/* 中序遍历：孩子i → 键i → …… → 最右孩子 */
void bt_inorder(btree_node *node) {
    if (!node) return;
    for (int i = 0; i < node->n; i++) {
        bt_inorder(node->child[i]);
        printf("%d ", node->keys[i]);
    }
    bt_inorder(node->child[node->n]);
}

int main(void) {                                      /* 自测: 应输出升序 */
    btree t = {0};
    int a[] = {10, 20, 5, 30, 15, 25, 35, 40, 1, 8, 22, 28};
    for (unsigned i = 0; i < sizeof(a) / sizeof(a[0]); i++) bt_insert(&t, a[i]);
    bt_inorder(t.root); printf("\n");
    int idx;
    printf("find 25: %s\n", bt_search(&t, 25, &idx) ? "yes" : "no");
    return 0;
}
```

自测：中序输出必须有序；把 M 改成 3、5 验证分裂逻辑的通用性。

## 4. Hash

### 4.1 hash 函数实现

| 函数 | 思路 | 代码/定位 |
|---|---|---|
| 除留余数 | `h(k) = k % m`，m 取**不接近 2 的幂的质数** | 最简单，整数键 |
| BKDR | 字符串按 seed 加权累积 | 见下，经典字符串 hash |
| MurmurHash | 乘法+移位混合，非加密、快、分布均匀 | Guava/Cassandra 默认；Redis 用 SipHash 抗碰撞攻击；std::hash 只保证同进程一致，勿跨进程 |

```c
/* BKDR 字符串哈希：seed 经验值 31 131 1313 13131 ... */
unsigned int bkdr_hash(const char *str) {
    unsigned int seed = 131, h = 0;
    while (*str) h = h * seed + (unsigned char)*str++;
    return h;
}
```

好 hash 的标准：**均匀**（输出等概率）、**稳定**（同输入同输出）、**雪崩**（输入 1 bit 变化输出平均变一半位）。

### 4.2 冲突解决对比

| 方案 | 思路 | 优点 | 缺点 |
|---|---|---|---|
| 链地址法 | 每桶挂链表（或小数组） | 负载因子可 >1；删除容易；扩容可渐进 | 指针跳转缓存不友好；每节点额外指针 |
| 开放寻址-线性探测 | 冲突则看下一个槽 | 缓存友好（同 cache line） | 一次聚集：连续占用区越来越长 |
| 开放寻址-二次探测 | 偏移 1²,2²,3²… | 缓解一次聚集 | 二次聚集；表长有讲究 |
| 开放寻址-双重散列 | 偏移 i·h₂(k) | 基本消除聚集，最优 OA | 需第二个独立 hash；要求 h₂ 与 m 互质 |
| 删除（OA） | 不能直接清空，放**墓碑标记** | 保持探测链不断 | 墓碑堆积，需定期重建 |

选型：内存敏感/嵌入式/小对象 → 开放寻址（如 Python dict、rust hashmap）；需要稳定遍历、删除多、负载高 → 链地址（Redis dict、Java HashMap）。

### 4.3 负载因子与 rehash

| 概念 | 说明 | 经验值 |
|---|---|---|
| 负载因子 α | α = 元素数 / 桶数；链地址 α≈1，OA α≤0.75 | Java HashMap 0.75 扩容翻倍 |
| rehash 代价 | 一次性重建 O(n)，期间可用性骤降 | 大表要避免尖刺 |
| 渐进式 rehash | 双表 + 每次操作顺带迁移 1 桶 + 定时器兜底；期间读先旧后新、写只进新表 | Redis dict 方案，详见 `../05-数据库与序列化/02-Redis设计与数据结构.md` |

面试高频："Redis 为什么渐进式 rehash？"——单线程模型下一次性 rehash 百万键会卡死主线程，故把 O(n) 摊到每次操作里。

### 4.4 一致性 hash【高频】

普通取模 `node = hash(key) % N` 的问题：N 变化（扩容/宕机）时**几乎全部数据重新映射**（N 台 → N+1 台，约 N/(N+1) 的 key 换节点）。

一致性 hash 把哈希空间围成环（0 ~ 2³²−1），节点与 key 都哈希到环上，**key 归属顺时针遇到的第一个节点**：

```text
        0/2^32 ─────●N1─────○V(N2)─────●N2─────○V(N1)───── (环回到起点)
                     ↑                   ↑
                   key1→N1             key2→N2
        ●=物理节点  ○=虚拟节点(每个物理节点配 100~200 个)
```

| 要点 | 说明 | 迁移量对比 |
|---|---|---|
| 节点增删 | 只影响**新节点与其前驱之间**的 key，其余不动 | ≈ 1/(N+1) |
| 倾斜问题 | 节点少时环上分布不均（3 个节点可能管 80% 区间） | —— |
| 虚拟节点 | 每物理节点哈希出成百上千个虚拟点打散到环上；节点权重用虚拟点数量表达 | 同时解决倾斜 |
| 实现 | 节点哈希值放**有序数组**，二分找第一个 ≥ hash(key) 的位置（比真环结构简单） | —— |

| 方案 | 10 台扩到 11 台迁移量 |
|---|---|
| 普通取模 | ≈ 10/11 ≈ 91%（几乎全迁） |
| 一致性 hash | ≈ 1/11 ≈ 9% |

```c
/* 一致性 hash 核心：虚拟节点 + 二分查找 */
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

typedef struct { unsigned int hv; char node[32]; } vnode_t;
static vnode_t g_ring[4096];                 /* 虚拟节点环（有序数组） */
static int g_cnt;

static unsigned int fnv(const char *s) {     /* 简易 hash */
    unsigned int h = 2166136261u;
    while (*s) { h ^= (unsigned char)*s++; h *= 16777619u; }
    return h;
}

void chash_add_node(const char *node, int vnum) {
    char buf[64];
    for (int i = 0; i < vnum; i++) {         /* 每个物理节点挂 vnum 个虚拟点 */
        snprintf(buf, sizeof(buf), "%s#%d", node, i);
        g_ring[g_cnt].hv = fnv(buf);
        strncpy(g_ring[g_cnt].node, node, 31);
        g_cnt++;
    }
    /* 按 hash 值排序成"环" */
    for (int i = 1; i < g_cnt; i++) {        /* 插入排序即可(节点总量小) */
        vnode_t t = g_ring[i]; int j = i - 1;
        while (j >= 0 && g_ring[j].hv > t.hv) { g_ring[j+1] = g_ring[j]; j--; }
        g_ring[j+1] = t;
    }
}

const char *chash_lookup(const char *key) {  /* 二分找顺时针第一个节点 */
    unsigned int h = fnv(key);
    int lo = 0, hi = g_cnt - 1;
    while (lo <= hi) {                       /* 第一个 hv >= h */
        int mid = (lo + hi) / 2;
        if (g_ring[mid].hv < h) lo = mid + 1;
        else hi = mid - 1;
    }
    return g_ring[lo % g_cnt].node;          /* 回绕到环首 */
}
```

## 5. 海量数据去重

### 5.1 bitmap 原理与实现

一个整数存在/不存在只需要 1 bit。10 亿个 int（值域 0~10⁹）：

| 存储 | 内存 |
|---|---|
| int 数组 40 亿（32 位值域） | 16 GB |
| bitmap（40 亿 bit） | 40×10⁸ / 8 = **500 MB** |
| bitmap（值域 10 亿） | 10⁹ / 8 ≈ **125 MB** |

| 操作 | 位运算 |
|---|---|
| 置位 set(v) | `bm[v >> 3] |=  (1u << (v & 7))` |
| 清位 clr(v) | `bm[v >> 3] &= ~(1u << (v & 7))` |
| 测试 test(v) | `bm[v >> 3] &   (1u << (v & 7))` |
| 负数处理 | 值域 [min, max] 映射为 `v - min` 再按上式（偏移法） |

```c
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

typedef struct { unsigned char *bits; long min, max; } bitmap_t;

bitmap_t *bm_create(long min, long max) {      /* 支持负数：偏移 min */
    bitmap_t *bm = malloc(sizeof(bitmap_t));
    bm->min = min; bm->max = max;
    long n = max - min + 1;                    /* 值域大小 */
    bm->bits = calloc((n + 7) / 8, 1);         /* 向上取整字节 */
    return bm;
}
void bm_set(bitmap_t *bm, long v)  { long i = v - bm->min; bm->bits[i >> 3] |=  (unsigned char)(1u << (i & 7)); }
void bm_clr(bitmap_t *bm, long v)  { long i = v - bm->min; bm->bits[i >> 3] &= ~(unsigned char)(1u << (i & 7)); }
int  bm_test(bitmap_t *bm, long v) { long i = v - bm->min; return (bm->bits[i >> 3] >> (i & 7)) & 1; }
/* 用法: bm_test(bm, v) 判存在; bm_set(bm, v) 插入; 值域含负数靠 min 偏移解决 */
```

bitmap 适合：值域已知且密集的整数（判存在、排序、去重、统计）；不适合稀疏大值域（如 int64 手机号直接开数组不现实——改用先 hash 压缩或分段）。

### 5.2 布隆过滤器原理

bitmap 只能处理小整数。海量**字符串/任意对象**的"是否见过"用布隆过滤器：一个 m 位的位数组 + k 个独立 hash 函数。

```text
插入 x:  对 x 计算 k 个 hash → 置位 k 个 bit
查询 x:  对 x 计算 k 个 hash →
          任一位为 0  →  一定不存在（100% 确定）
          全部为 1   →  可能存在（有误判率 p）
```

| 特性 | 说明 |
|---|---|
| 不漏报 | 判"不存在"绝对正确（没插入过不可能置位） |
| 会误报 | 判"存在"可能错误（位被别的元素踩过），误判率可控 |
| 不支持删除 | 清一位可能影响其他元素；要删除用计数布隆（每位换成计数器，内存×4） |

### 5.3 数学推导【高频】

设数组 m 位、插入 n 个元素、k 个 hash 函数、hash 均匀：

1. 插入一个元素后某特定位仍为 0 的概率：`1 − 1/m`；
2. 插入 n 个元素（共 kn 次置位）后该位仍为 0：`(1 − 1/m)^{kn} ≈ e^{−kn/m}`；
3. 查询一个**未插入**的元素，误判 = k 个位置全为 1：

```text
p ≈ (1 − e^{−kn/m})^k
```

4. 对 k 求导取极值（令 x = e^{−kn/m}，ln p = k·ln(1−x)，注意 k = −(m/n)ln x 代入后求导），得最优条件 **e^{−kn/m} = 1/2**，即平均每个 bit 恰有一半概率被置位，此时：

```text
k* = (m/n)·ln2
此时 p = (1/2)^k = (0.6185)^{m/n}
```

5. 反解：给定元素数 n 与目标误判率 p，最优内存与函数个数：

```text
m = −n·ln p / (ln2)²          （每元素约 9.6 bit 即达 1% 误判）
k = −ln p / ln2 ≈ 7           （1% 误判对应 7 个 hash）
```

| 目标误判率 p | m/n（bit/元素） | 最优 k |
|---|---|---|
| 10% | 4.8 | 5 |
| 1% | 9.6 | 7 |
| 0.1% | 14.4 | 10 |

### 5.4 手撕布隆过滤器（含最优参数计算）

```c
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <stdint.h>
#include <math.h>

typedef struct {
    uint8_t *bits;
    size_t   m;      /* 位数 */
    int      k;      /* hash 函数个数 */
} bloom_t;

/* 双重哈希模拟 k 个函数: h_i(x) = h1(x) + i*h2(x)（Kirsch–Mitzenmacher 定理）
   只需 2 个好 hash 即可近似 k 个独立 hash 的效果 */
static uint64_t h1(const char *s) {             /* FNV-1a 64 */
    uint64_t h = 1469598103934665603ULL;
    while (*s) { h ^= (uint8_t)*s++; h *= 1099511628211ULL; }
    return h;
}
static uint64_t h2(const char *s) {             /* BKDR 变体 */
    uint64_t h = 1125899906842597ULL;
    while (*s) h = 31 * h + (uint8_t)*s++;
    return h | 1ULL;                            /* 保证奇数 */
}

bloom_t *bloom_create(size_t n, double p) {     /* n=预计元素数 p=目标误判率 */
    bloom_t *bf = calloc(1, sizeof(bloom_t));
    bf->m = (size_t)(-n * log(p) / (M_LN2 * M_LN2));   /* 最优 m */
    bf->k = (int)(0.5 + (double)bf->m / n * M_LN2);    /* 最优 k, 四舍五入 */
    bf->bits = calloc(bf->m / 8 + 1, 1);
    printf("bloom: n=%zu p=%g -> m=%zu bits (%.1fMB), k=%d\n",
           n, p, bf->m, bf->m / 8.0 / 1048576, bf->k);
    return bf;
}

void bloom_add(bloom_t *bf, const char *s) {
    uint64_t a = h1(s), b = h2(s);
    for (int i = 0; i < bf->k; i++) {
        uint64_t pos = (a + (uint64_t)i * b) % bf->m;
        bf->bits[pos >> 3] |= (uint8_t)(1u << (pos & 7));
    }
}

int bloom_may_contain(bloom_t *bf, const char *s) {
    uint64_t a = h1(s), b = h2(s);
    for (int i = 0; i < bf->k; i++) {
        uint64_t pos = (a + (uint64_t)i * b) % bf->m;
        if (!(bf->bits[pos >> 3] & (1u << (pos & 7)))) return 0; /* 有0位→必不存在 */
    }
    return 1;                                   /* 全1 → 可能存在 */
}

int main(void) {
    bloom_t *bf = bloom_create(1000000, 0.01);   /* 百万元素, 1% 误判 → ~1.2MB, k=7 */
    bloom_add(bf, "user:10086");
    printf("%d %d\n", bloom_may_contain(bf, "user:10086"),  /* 1 */
                      bloom_may_contain(bf, "user:99999")); /* 0(大概率) */
    return 0;
}
```

### 5.5 三种去重方案对比

| 方案 | 内存（百万元素） | 误差 | 支持删除 | 支持枚举 | 适用 |
|---|---|---|---|---|---|
| hash set（精确） | 数百 MB（键+指针+桶） | 0 | 是 | 是 | 元素量可控、要精确语义 |
| bitmap | 值域/8（整数 125MB/10 亿） | 0 | 是 | 可按位扫描 | 小整数、值域密集 |
| 布隆过滤器 | ≈1.2 MB（1% 误判） | 有 p | 否（需计数版） | 否 | 海量、允许误判的预过滤 |

典型链路：**布隆先挡（判不存在直接返回）→ 命中再查精确结构**。缓存穿透防御：请求先过布隆，不存在的 key 不打数据库。

### 5.6 经典海量题速查【高频】

| 题型 | 套路 | 复杂度/内存 |
|---|---|---|
| 10 亿整数找最大的 100 个（top-K） | 维护**小顶堆**（容量 K），比堆顶大则替换并下沉 | O(n log K)，内存 O(K) |
| 10 亿整数找最小的 100 个 | 同上用**大顶堆** | 同上 |
| 两个各 1 亿 URL 的文件求交集 | hash(x) % 1000 分片成小文件对，同一元素必落同号文件，逐对求交（hash 分治） | 内存按 1/1000 缩 |
| 10 亿 QQ 号统计在线人数/判存在 | bitmap | 40 亿值域 500MB |
| 海量字符串判"是否出现过" | 布隆过滤器 | ~1.2MB/百万@1% |
| 40 亿 int 出现次数最多的数 | hash 分片 → 各片哈希计数 → 归并 top1 | 分治 |

通用三板斧：**分而治之（hash 分片）+ 位图/布隆（压缩状态）+ 堆（top-K）**。

## 6. 快速参考卡片

| 要点 | 一句话 |
|---|---|
| 红黑树 5 性质 | 非红即黑；根黑；叶(NIL)黑；无连续红；黑高相同；高度 ≤ 2·log₂(n+1) |
| 插入 fixup | 新节点染红；叔红变色上移；叔黑 LR 先旋成 LL 再旋收尾；最多 2 次旋转 |
| 删除 fixup | 双重黑 + 看兄弟：兄红造机会 / 侄全黑甩锅上移 / 近红对齐 / 远红收割，最多 3 次旋转 |
| RB vs AVL | AVL 严格平衡查询快、维护贵；RB 旋转次数有常数上限，写多选 RB |
| B 树阶 m | 最多 m 孩子 m−1 键，最少 ⌈m/2⌉ 孩子（根除外），叶子同层 |
| B 树分裂 | 溢出取中间键上移；根分裂则树高 +1（自底向上长高） |
| B 树删除 | 先问兄弟借（富余才借得动），借不到就合并，可能连锁收缩根 |
| B+ vs B | 非叶不存数据（扇出大树矮）；叶子链表（范围查询）；查询必到叶（稳定） |
| MySQL 选 B+ | 16KB 页 + 高扇出 → 千万行 3~4 层；范围/排序走叶子链表 |
| latch crabbing | 拿到孩子的锁就放父亲的锁，自顶向下"蟹行" |
| 负载因子 | 元素/桶；链地址 ~1 扩容，OA ≤0.75；Redis 渐进式 rehash 双表迁移 |
| 一致性 hash | 环 + 顺时针归属 + 虚拟节点打散；节点增删只迁 ~1/N |
| bitmap 三运算 | set `\|=`、clr `&=~`、test `&`，下标 v>>3 / 位 v&7，负数减 min 偏移 |
| 布隆三公式 | p≈(1−e^(−kn/m))^k；k*=(m/n)ln2；m*=−n·ln p/(ln2)²；1% 误判→9.6bit/元素、k=7 |
| 布隆语义 | 一定不存在（不漏报）/ 可能存在（有误判）/ 不支持删除 |
| top-K | 求"最大 K"用小顶堆；内存 O(K)；海量题先 hash 分片 |

## 7. 常见问题与坑

| 坑 | 现象 | 正解 |
|---|---|---|
| 红黑树插入忘染红/忘把 root 染黑 | 性质 4/2 被破坏，后续查找错乱 | 新节点固定 RED，fixup 末尾 `T->root->color = BLACK` 兜底 |
| 只写插入不写 fixup 或 fixup 少镜像分支 | 一半数据是坏树 | 插入/删除 fixup 必须写全父在左/父在右两个镜像 |
| 删除时直接 free 节点没处理孩子 | 树断链、野指针 | 先按 BST 规则用后继/孩子顶替，再 fixup |
| B 树删除只删不合并 | 节点亏空，性质（最少 ⌈m/2⌉−1 键）被破坏 | 借位优先，借不到合并，向上连锁；根空了要收缩降高 |
| B 树把根分裂写成叶分裂 | 树高不变、出现四叉节点 | 根分裂必须新建只含 1 键的新根，两个旧半部做孩子 |
| 手撕 B+ 树时非叶仍存数据 | 扇出上不去，退化成 B 树 | 非叶只留键与指针，数据全下沉叶子 |
| 一致性 hash 不加虚拟节点 | 3 个节点时负载严重倾斜 | 每节点 100+ 虚拟点；环用有序数组+二分实现 |
| bitmap 直接下标负数 | 越界崩溃 | 先 `v - min` 偏移，或值域统一加偏置 |
| bitmap 处理 int64 稀疏值域 | 内存爆掉 | 分段 bitmap / 先 hash 缩域 / 换布隆 |
| 布隆支持删除（清位） | 误删别人的位，误判率暴涨 | 换计数布隆（每位 4 bit 计数）或定期重建 |
| 布隆参数拍脑袋（m、k 随便设） | 误判率失控 | 用公式：m=−n ln p/(ln2)²、k=(m/n)ln2 |
| 布隆误判当精确结果用 | 已存在的 key 被漏处理 | 语义只能是"预过滤"，命中后必须查精确结构 |
| 开放寻址直接置空删除槽 | 探测链断裂，后继元素"消失" | 用墓碑（DELETED 标记），负载高时重建 |
