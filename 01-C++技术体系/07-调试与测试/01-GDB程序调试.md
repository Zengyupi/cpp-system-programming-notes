## 1. 概述

GDB（GNU Debugger）是 Linux 下最常用的调试器，用于调试 C/C++、Go、Rust 等编译型语言程序。支持设置断点、单步执行、查看变量、分析 core dump 等功能。

**基本调用格式：**

```bash
gdb [选项] [程序] [core文件]
```

**常用启动方式：**

```bash
gdb ./program                    # 直接调试程序
gdb ./program core               # 调试 core dump 文件
gdb -p <PID>                     # 附加到正在运行的进程（程序名自动从 /proc 获取）
gdb ./program <PID>              # 也可以：程序名 + 进程号（PID 作为第二个参数）
gdb --args ./program arg1 arg2   # 调试程序并向其传参
gdb -tui ./program               # 使用 TUI 文本界面模式
```

## 2. 启动与控制选项

| 选项                             | 说明                                      |
| -------------------------------- | ----------------------------------------- |
| `-p <PID>` / `--pid=<PID>`       | 附加到正在运行的进程（附加他人进程需 root） |
| `-c <文件>` / `--core=<文件>`    | 指定 core dump 文件                       |
| `-x <文件>` / `--command=<文件>` | 启动时自动执行文件中的 GDB 命令           |
| `-ex <命令>`                     | 启动时自动执行一条 GDB 命令（可多次使用） |
| `-tui` / `--tui`                 | 启动文本用户界面（源码 + 命令窗口）       |
| `-q` / `--quiet`                 | 安静模式，不显示版权信息                  |
| `--args <程序> <参数...>`        | 将后面的所有参数传递给被调试程序          |
| `--directory=<路径>` / `-d`      | 添加源码搜索路径                          |

## 3. 程序执行与退出控制

| GDB 内部命令     | 说明                               | 简写          |
| ---------------- | ---------------------------------- | ------------- |
| `run` / `r`      | 启动或重新启动程序                 | `r`           |
| `run <参数>`     | 带参数启动程序                     | `r arg1 arg2` |
| `start`          | 启动程序并在 `main` 入口处暂停     | -             |
| `starti`         | 启动程序并在第一条指令处暂停       | -             |
| `continue` / `c` | 继续执行到下一个断点               | `c`           |
| `step` / `s`     | 单步进入（会进入函数内部）         | `s`           |
| `next` / `n`     | 单步跳过（不进入函数内部）         | `n`           |
| `stepi` / `si`   | 单步一条机器指令（进入）           | `si`          |
| `nexti` / `ni`   | 单步一条机器指令（跳过）           | `ni`          |
| `finish`         | 执行完当前函数并返回               | -             |
| `until` / `u`    | 执行到指定行号或当前循环结束       | `u`           |
| `return`         | 强制从当前函数返回（可指定返回值） | -             |
| `quit` / `q`     | 退出 GDB                           | `q`           |
| `kill`           | 终止被调试的程序                   | -             |

## 4. 断点管理

### 4.1 设置断点

| GDB 内部命令            | 说明                                            | 示例                            |
| ----------------------- | ----------------------------------------------- | ------------------------------- |
| `break <位置>` / `b`    | 在指定位置设置断点                              | `b main`、`b 42`、`b main.c:42` |
| `break <函数>`          | 在函数入口设置断点                              | `b my_function`                 |
| `break <文件名>:<行号>` | 在指定文件行号设置断点                          | `b main.c:42`                   |
| `break <文件>:<函数>`   | 在指定文件的函数设置断点                        | `b main.c:main`                 |
| `break *<地址>`         | 在内存地址设置断点                              | `b *0x4005a3`                   |
| `tbreak <位置>`         | 设置一次性断点（触发后自动删除）                | `tbreak main`                   |
| `rbreak <正则表达式>`   | 在所有匹配正则表达式的函数设置断点              | `rbreak ^my_`                   |
| `watch <表达式>`        | 数据断点：当表达式值变化时触发                  | `watch x`                       |
| `rwatch <表达式>`       | 数据断点：当表达式被读取时触发                  | `rwatch x`                      |
| `awatch <表达式>`       | 数据断点：当表达式被读写时触发                  | `awatch x`                      |
| `catch <事件>`          | 捕获系统事件（如 `fork`、`exec`、`syscall` 等） | `catch syscall`                 |

### 4.2 断点管理

| GDB 内部命令                | 说明                                          |
| --------------------------- | --------------------------------------------- |
| `info breakpoints` / `i b`  | 列出所有断点/观察点                           |
| `delete <编号>` / `d`       | 删除指定断点（不加编号则删除所有）            |
| `disable <编号>`            | 禁用指定断点（断点保留但无效）                |
| `enable <编号>`             | 启用指定断点                                  |
| `enable once <编号>`        | 启用断点，触发一次后自动禁用                  |
| `enable delete <编号>`      | 启用断点，触发一次后自动删除                  |
| `condition <编号> <表达式>` | 为断点添加条件（条件满足时才触发）            |
| `commands <编号>`           | 断点触发时自动执行的命令列表（以 `end` 结束） |
| `ignore <编号> <次数>`      | 忽略断点指定的触发次数                        |

### 4.3 断点示例

```bash
# 在 main 函数设置断点
(gdb) b main

# 在第 42 行设置条件断点（仅当 count > 10 时触发）
(gdb) b 42 if count > 10

# 设置数据断点，监控指针指向的内容
(gdb) watch *ptr

# 断点触发时自动打印变量值
(gdb) commands 1
> p x
> p y
> c
> end
```

## 5. 查看数据

### 5.1 打印变量与表达式

| GDB 内部命令                     | 说明                                                         | 示例                        |
| -------------------------------- | ------------------------------------------------------------ | --------------------------- |
| `print <表达式>` / `p`           | 打印表达式的值                                               | `p x`、`p *ptr`、`p arr[2]` |
| `print /<格式> <表达式>`         | 按指定格式打印（`x`十六进制、`d`十进制、`t`二进制、`c`字符、`s`字符串） | `p/x x`                     |
| `display <表达式>`               | 每次暂停时自动打印表达式的值                                 | `display x`                 |
| `undisplay <编号>`               | 取消自动打印                                                 | `undisplay 1`               |
| `printf "<格式串>", <表达式...>` | 格式化打印（类似 C 的 printf）                               | `printf "x=%d\n", x`        |
| `whatis <变量>`                  | 显示变量的类型                                               | `whatis x`                  |
| `ptype <变量>`                   | 显示变量的详细类型（包括结构体定义）                         | `ptype mystruct`            |
| `print *<指针>@<长度>`           | 打印指针指向的连续多个元素                                   | `p *arr@10`                 |
| `print <变量> = <值>`            | 在调试中直接修改变量值                                       | `p x = 5`                   |

### 5.2 查看内存

| GDB 内部命令       | 说明                                             | 示例             |
| ------------------ | ------------------------------------------------ | ---------------- |
| `x /<格式> <地址>` | 查看内存内容（格式：`x/<重复次数><格式><大小>`） | 见下表说明       |
| `x/s <地址>`       | 以字符串形式查看内存                             | `x/s 0x7fff1234` |
| `x/10x <地址>`     | 以十六进制显示 10 个单位                         | `x/10x buf`      |
| `x/10i <地址>`     | 反汇编 10 条指令                                 | `x/10i main`     |

**`x` 命令格式说明：** `x/<重复次数><格式><大小> <地址>`

| 格式 | 说明     | 大小字母 | 说明           |
| ---- | -------- | -------- | -------------- |
| `x`  | 十六进制 | `b`      | 1 字节         |
| `d`  | 十进制   | `h`      | 2 字节（半字） |
| `t`  | 二进制   | `w`      | 4 字节（字）   |
| `o`  | 八进制   | `g`      | 8 字节（巨字） |
| `c`  | 字符     |          |                |
| `s`  | 字符串   |          |                |
| `i`  | 汇编指令 |          |                |

```bash
# 示例：从 buf 地址开始，以十六进制显示 20 个字节
(gdb) x/20xb buf

# 示例：查看当前指令指针（RIP）处的 5 条汇编指令
(gdb) x/5i $rip
```

### 5.3 寄存器与反汇编

| GDB 内部命令              | 说明                                       | 示例                 |
| ------------------------- | ------------------------------------------ | -------------------- |
| `info registers` / `i r`  | 显示所有寄存器的值                         | `i r`                |
| `info registers <名称>`   | 显示指定寄存器                             | `i r rip rsp`        |
| `print $<寄存器>`         | 打印单个寄存器（可参与运算）               | `p/x $rsp + 8`       |
| `disassemble` / `disas`   | 反汇编当前函数                             | `disas`              |
| `disassemble <函数>`      | 反汇编指定函数                             | `disas main`         |
| `disassemble <起>,<止>`   | 反汇编指定地址区间                         | `disas 0x4005a3,0x4005d0` |
| `disassemble /r <函数>`   | 反汇编并显示机器码字节                     | `disas /r main`      |
| `set disassembly-flavor`  | 设置汇编风格（x86：`att` 默认 / `intel`）  | `set disassembly-flavor intel` |

```bash
# 常见寄存器（x86_64）：rip 指令指针、rsp 栈指针、rbp 帧指针、rax 返回值
(gdb) p/x $rip
(gdb) x/i $rip      # 查看即将执行的指令
```

| GDB 内部命令         | 说明                             | 简写      |
| -------------------- | -------------------------------- | --------- |
| `backtrace` / `bt`   | 显示当前调用栈（所有函数调用链） | `bt`      |

| `frame <编号>` / `f` | 切换到指定栈帧（编号来自 `bt`）  | `f 2`     |

| `info frame` / `i f` | 显示当前栈帧的详细信息           | `i f`     |
| `info locals`        | 显示当前栈帧的所有局部变量       | -         |
| `info args`          | 显示当前栈帧的函数参数           | -         |

### 6.2 源文件查看

| GDB 内部命令            | 说明                                 |
| ----------------------- | ------------------------------------ |
| `list` / `l`            | 显示当前行附近的源代码（默认 10 行） |
| `list <行号>`           | 显示指定行附近的代码                 |
| `list <函数>`           | 显示指定函数的代码                   |
| `list <文件名>:<行号>`  | 显示指定文件的行号附近代码           |
| `search <正则>`         | 在当前文件向前搜索                   |
| `reverse-search <正则>` | 在当前文件向后搜索                   |
| `info source`           | 显示当前源文件信息                   |
| `info sources`          | 显示所有已加载的源文件               |
| `directory <路径>`      | 添加源码搜索路径                     |

## 7. 多线程调试

| GDB 内部命令                   | 说明                                                         | 简写                   |
| ------------------------------ | ------------------------------------------------------------ | ---------------------- |
| `info threads` / `i th`        | 显示所有线程                                                 | `i th`                 |
| `thread <编号>`                | 切换到指定线程                                               | `th 2`                 |
| `thread apply <编号> <命令>`   | 对指定线程执行命令                                           | `thread apply 2 bt`    |
| `thread apply all <命令>`      | 对所有线程执行命令                                           | `th apply all bt full` |
| `thread name <名称>`           | 给当前线程命名（便于识别）                                   | `thread name worker`   |
| `break <位置> thread <编号>`   | 仅为指定线程设置断点                                         | `b 42 thread 3`        |
| `set scheduler-locking <模式>` | 调度锁定模式：`off`（默认）、`on`（只运行当前线程）、`step`（单步时锁住） | -                      |
| `handle <信号> <动作>`         | 控制信号处理（`stop`/`print`/`pass`/`ignore`）               | -                      |

```bash
# 切换线程并查看其调用栈
(gdb) info threads
(gdb) thread 3
(gdb) bt

# 打印所有线程的调用栈
(gdb) thread apply all bt
```

## 11. Core Dump 分析

### 11.1 启用 core dump（前置条件）

```bash
# 临时开启：不限制 core 文件大小（默认为 0，即不生成）
ulimit -c unlimited

# 永久开启：在 /etc/security/limits.conf 中添加
# * soft core unlimited

# 查看 core 文件的保存位置和命名规则
cat /proc/sys/kernel/core_pattern
# 常见值 "core" 表示在程序运行目录下生成名为 core 的文件
# 修改示例（含 PID，便于区分）：
echo "core.%p" > /proc/sys/kernel/core_pattern

# 编译时加 -g 才能看到函数名和行号
gcc -g -O0 program.c -o program
```

### 11.2 分析步骤

| 使用场景                      | 命令                        |
| ----------------------------- | --------------------------- |
| 加载 core 文件                | `gdb ./program core`        |
| 查看崩溃时的调用栈            | `(gdb) bt`                  |
| 查看崩溃时的寄存器值          | `(gdb) info registers`      |
| 查看崩溃时的局部变量          | `(gdb) info locals`         |
| 查看崩溃时的函数参数          | `(gdb) info args`           |
| 查看崩溃地址的汇编指令        | `(gdb) x/10i $rip`          |
| 切换到崩溃线程（多线程 core） | `(gdb) thread apply all bt` |

> 提示：若 `bt` 显示 `No symbol`，通常是程序编译时未加 `-g`，或运行环境与编译环境的库版本不一致。

## 14. 常见坑与易错点

| 现象 | 根因 | 对策 |
|---|---|---|
| `bt` 全是 `??`，或 `p var` 报 No symbol "var" in current context | 编译时漏加 `-g`，可执行文件不带调试信息（或跑的是 strip 后的发布版） | 编译加 `-g`（调试建议 `-g -O0`），确认调试用的是带符号的二进制而非发布版 |
| `p x` 显示 `<optimized out>`，或 `list` 行号与源码对不上、单步乱跳 | `-O2` 等优化把变量优化掉、指令重排/内联，行号表失真 | 调试用 `-O0`（或 `-Og`）重编；必须在优化版上查时改用看汇编/寄存器，勿轻信源码行号 |
| `attach <pid>` 报 `ptrace: Operation not permitted` | Linux Yama 默认 `ptrace_scope=1`，只允许调试子进程 | 临时 `sudo gdb -p <pid>`；或 `echo 0 | sudo tee /proc/sys/kernel/yama/ptrace_scope`；长期用 gdbserver 远程附加 |
| 任意线程一命中断点所有线程都停；`step` 时其他线程仍在跑导致状态抖动 | GDB 默认暂停所有线程，非当前线程事件照常推进 | 单线程聚焦时 `set scheduler-locking on`（只跑当前线程），单步场景用 `step` 模式，看完恢复 `off`；看现场用 `thread apply all bt` |
| 程序崩溃后目录里找不到 core 文件 | `ulimit -c` 默认 0（不生成）；或 `core_pattern` 指向 systemd-coredump 管道/无写权限目录 | `ulimit -c unlimited`（临时）并写进 limits.conf；`cat /proc/sys/kernel/core_pattern` 确认落点，必要时 `echo "core.%p" > /proc/sys/kernel/core_pattern` 指回工作目录 |
