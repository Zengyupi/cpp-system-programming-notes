## 1. 概述

### 1.1 Qt 是什么

Qt 是**跨平台 C++ 应用程序开发框架**：既是一套 GUI 库（窗口/控件/绘图/事件），也是完整的应用框架（网络/数据库/多线程/国际化/单元测试）。同一份 C++ 源码在 Windows/Linux/macOS 上编译为原生程序（"Write once, compile anywhere"），无虚拟机开销。

| 入口类 | 模块 | 适用程序 |
|---|---|---|
| QCoreApplication | QtCore | 无界面控制台程序（仍可用信号槽/线程/网络） |
| QGuiApplication | QtGui | 有窗口不用控件（QWindow/QML/OpenGL） |
| QApplication | QtWidgets | 传统桌面控件程序（本手册 1~10 章主角） |

### 1.2 模块划分表

| 模块 | 职责 | 代表类 |
|---|---|---|
| QtCore | 对象模型、事件循环、容器、字符串、线程、正则 | QObject、QString、QList、QThread、QTimer |
| QtGui | 窗口系统集成、事件类型、2D 绘图、字体图标 | QWindow、QPainter、QPixmap、QColor、QAction（Qt6 起） |
| QtWidgets | 完整桌面控件库（基于 QWidget） | QWidget、QPushButton、QMainWindow、QTableWidget |
| QtNetwork | TCP/UDP/HTTP 异步网络 | QTcpServer、QTcpSocket、QUdpSocket、QNetworkAccessManager |
| QtSql | 数据库连接与 SQL（衔接《../05-存储与序列化/01-MySQL数据库精要.md》） | QSqlDatabase、QSqlQuery、QSqlTableModel |
| QtConcurrent | 高层并发（线程池 + 函数式接口） | QtConcurrent::run/map、QFuture、QThreadPool |
| QtSvg | SVG 显示与生成 | QSvgWidget、QSvgRenderer |
| QtMultimedia | 音视频播放与采集 | QMediaPlayer、QMediaRecorder、QAudioOutput |
| Qt5Compat（仅 Qt6） | 承接移出核心的旧 API | QRegExp、QTextCodec、QStringRef |
| QtQuick/Qml | 声明式 UI（《05-Qt综合实战.md》第 11 章起） | QQuickView、QQmlEngine |

### 1.3 版本与支持表

| 版本 | 类型 | 发布 | 现状与备注 |
|---|---|---|---|
| Qt 5.12 | LTS | 2018-12 | 开源支持已结束；工控/车机/嵌入式存量项目大量存在 |
| Qt 5.15 | LTS | 2020-05 | **最后一个 Qt5 版本**，存量桌面项目主力；开源版停维护，商业版延长支持 |
| Qt 6.2 | LTS | 2021-09 | 首个 Qt6 LTS |
| Qt 6.5 | LTS | 2023-03 | Qt Graphs 等新模块 |
| Qt 6.8 | LTS | 2024-10 | 截至本手册编写时的主力 LTS；此后非 LTS 小版本约半年一发 |

**双协议一句话**：开源协议（LGPLv3/GPL，可免费商用但须满足动态链接等义务）+ 商业协议（付费、无开源义务、官方支持）二选一；闭源静态链接商用需买商业版。

### 1.4 Qt5 → Qt6 迁移要点总表【高频】

| 差异点 | Qt 5 | Qt 6 |
|---|---|---|
| 高 DPI 缩放 | 需在创建 QApplication 前手动 `setAttribute(Qt::AA_EnableHighDpiScaling)` | **默认启用**，该属性已废弃（设置无效但无害） |
| 正则 | QRegExp（QtCore） | QRegExp 废弃移入 Qt5Compat；一律改用 QRegularExpression |
| 字符编码 | QTextCodec | 移入 Qt5Compat；新代码用 QStringConverter/QStringDecoder |
| 字符串视图 | QStringRef | 移除（Qt5Compat），改 QStringView |
| 容器 | QVector 与 QList 并存 | **QVector 成为 QList 的别名**（合并实现） |
| QString::split 枚举 | `QString::SkipEmptyParts`（≤5.13）/ `Qt::SkipEmptyParts`（5.14+） | 只认 `Qt::SkipEmptyParts`；空分隔符行为见下 |
| QComboBox 信号 | currentIndexChanged 有 int 与 QString 两重载（QString 5.15 起废弃） | 只剩 `currentIndexChanged(int)`（currentTextChanged 保留） |
| QButtonGroup 信号 | buttonClicked(int) 等 | 已移除，改 idClicked(int)/idToggled(int)（5.15 起可用） |
| socket 错误信号 | `error(QAbstractSocket::SocketError)` | 改名 `errorOccurred(...)`（5.15 引入，Qt6 仅有它） |
| 鼠标坐标 | QMouseEvent::pos()/x()/y() | 推荐 position()/globalPosition()（pos() 过时但可用） |
| QAction 归属 | QtWidgets | 移到 QtGui（include 不变，CMake 目标不同） |
| QTextStream 编码 | `stream.setCodec("UTF-8")` | setCodec 移除；默认 UTF-8，可 setEncoding(QStringConverter::Utf8) |
| C++ 标准 | 要求 C++11（推荐 17） | **强制 C++17 起**；不再提供 32 位 Windows 官方二进制 |
| CMake | `Qt5::Widgets`、add_executable | `Qt6::Widgets`、qt_add_executable（见 1.5） |

```cpp
// split 坑 1：枚举命名空间迁移（跨版本编译报错最常见处）
QString s = "a,,b";
s.split(',', Qt::SkipEmptyParts);           // Qt 5.14+ / Qt6 正确写法
// s.split(',', QString::SkipEmptyParts);  // Qt ≤5.13 旧写法，Qt6 编译失败
// 两版本默认值均为 KeepEmptyParts（保留空段），跨版本代码显式写参数最安全

// split 坑 2：空分隔符行为不一致，不要依赖
// Qt6 文档：分隔符为空时结果是【空串+每个字符+空串】，"abc".split("") → ("","a","b","c","")
// Qt 5.13 及更早的实现结果与之不同。需要逐字符处理请显式遍历：
for (const QChar &ch : s) { /* ... */ }
```

### 1.5 环境搭建速查：qmake 与 CMake

```pro
# ---------- hello.pro（qmake 最小工程） ----------
QT      += core gui widgets        # 引入模块
CONFIG  += c++17
TARGET   = hello
SOURCES += main.cpp mainwindow.cpp
HEADERS += mainwindow.h             # 带 Q_OBJECT 的 .h 必须列出，moc 才会处理
# RESOURCES += resources.qrc        # 资源文件（《03-Qt界面组件与布局.md》第 9 章）
# FORMS     += dialog.ui            # Designer 界面文件（《03-Qt界面组件与布局.md》第 8 章）
```

```cmake
# ---------- CMakeLists.txt（Qt6 写法；Qt5 把 6 换成 5 即可） ----------
cmake_minimum_required(VERSION 3.16)
project(HelloQt VERSION 1.0 LANGUAGES CXX)
set(CMAKE_CXX_STANDARD 17)
set(CMAKE_CXX_STANDARD_REQUIRED ON)
set(CMAKE_AUTOMOC ON)               # 自动跑 moc（Q_OBJECT 必需）；AUTOUIC/AUTORCC 同理
find_package(Qt6 6.2 REQUIRED COMPONENTS Widgets)   # Qt5: find_package(Qt5 5.15 REQUIRED COMPONENTS Widgets)
qt_add_executable(hello main.cpp mainwindow.cpp mainwindow.h)   # Qt5 可用 add_executable
target_link_libraries(hello PRIVATE Qt6::Widgets)   # Qt5: Qt5::Widgets
```

```bash
qmake -v                 # 确认 qmake 与 Qt 版本（用的是哪套 Kit）
qmake hello.pro && make -j8     # 生成 Makefile 并编译；MSVC 用 nmake/jom
cmake -B build -DCMAKE_PREFIX_PATH="C:/Qt/6.8.0/msvc2022_64"    # Qt 不在默认路径时必须指定
cmake --build build --config Release
```

## 2. 对象模型与内存管理【核心】

### 2.1 QObject 树形所有权

每个 QObject 可有 parent：父对象析构时**自动 delete 所有子对象**并级联到整棵子树——挂进父子树的控件基本不需要手动 delete。

```text
QMainWindow（父）
 ├── centralWidget : QWidget        ← 构造时传 parent
 │    ├── nameEdit : QLineEdit      ← parent = centralWidget
 │    └── formLay  : QFormLayout    ← 布局对象也在 QObject 树里
 ├── menuBar()
 └── statusBar()

delete 主窗口 ──► ~QObject() 遍历 children ──► 级联 delete 全部子孙
```

| 函数 | 说明 | 示例 |
|---|---|---|
| 构造参数 parent | 建立父子并纳入所有权 | `new QPushButton("OK", this)` |
| setParent(obj) | 运行期换父（自动 reparent） | `label->setParent(box)` |
| parent() / children() | 查询 | `w->parentWidget()` |
| findChild\<T\>(name) / findChildren\<T\>() | 按类型+对象名递归查找 | `findChild<QLineEdit*>("nameEdit")` |

### 2.2 堆 vs 栈：创建位置规则表【高频】

| 场景 | 推荐写法 | 原因 |
|---|---|---|
| main() 里的主窗口 | 栈上（`MainWindow w; w.show();`） | 生命周期覆盖 `a.exec()` |
| 普通函数/槽函数里弹出的**独立窗口** | 必须堆上 new | 栈对象函数返回即析构，窗口一闪而过：show() 只是排队显示，不延长生命周期 |
| 任何**有 parent** 的子控件 | 必须堆上 new + 传 parent | parent 析构时会 delete 它；栈对象会二次析构崩溃 |
| 无 parent 的临时 QObject | 堆上 + 智能指针/deleteLater | 没人替你释放 |

```cpp
void MainWindow::onClicked() {
    // 错误：函数返回即析构，窗口闪现后消失
    // SubWindow sub; sub.show();
    auto *sub = new SubWindow;                  // 独立窗口：堆上、无 parent
    sub->setAttribute(Qt::WA_DeleteOnClose);    // 关闭自动销毁，防泄漏
    sub->show();                                // 非模态：立即返回
}
```

### 2.3 deleteLater() 与事件循环【高频】

`obj->deleteLater()` 不是立即析构，而是**向对象所属线程的事件队列投递 DeferredDelete 事件**，等控制权回到该线程事件循环后才真正 delete。

比直接 delete 安全的原因：信号槽执行期间调用栈里可能正持有该对象的 this（例如槽里发出的信号又回到该对象），此时 delete 后的任何成员访问都是悬垂崩溃；deleteLater 保证析构发生在"当前调用栈完全展开、回到事件循环"之后。典型使用：`disconnected` 里删 socket、用完释放 QNetworkReply、非模态对话框关闭。

```cpp
connect(sock, &QTcpSocket::disconnected, sock, [sock] {
    sock->deleteLater();       // 等本次信号分发结束后再析构
});
```

注意：它依赖事件循环——在没有事件循环的线程里调用可能永不执行。

### 2.4 QPointer 与智能指针

衔接《../01-语言基础/04-内存管理与智能指针.md》：Qt 的父子所有权与 std 智能指针是**两套并行机制，不要混管同一对象**（既被 parent 管又被 shared_ptr 管，必然双重释放）。

| 类 | 作用 | 与 std 的关系 |
|---|---|---|
| QPointer\<T\> | 守卫裸指针：所指 QObject 析构后**自动置空** | 无对应物（只支持 QObject 系，比 weak_ptr 轻） |
| QSharedPointer\<T\> | 引用计数共享，支持自定义删除器 | ≈ std::shared_ptr（C++11 前的替代品，新代码建议 std 版） |
| QWeakPointer\<T\> | 观察 QSharedPointer，lock() 提升 | ≈ std::weak_ptr |
| QScopedPointer\<T\> | 独占不可转移 | ≈ std::unique_ptr（功能更弱） |
| std::shared_ptr/unique_ptr | 标准库 | 可管 QObject，但必须放弃 parent 所有权 |

```cpp
QPointer<QNetworkReply> reply = nam->get(req);
// ... 异步回调里：
if (reply) reply->readAll();     // 若期间被删除，reply 已自动为 nullptr
```

### 2.5 Q_OBJECT 宏与 moc【高频】

- `Q_OBJECT` 为类注入 `metaObject()/qt_metacall()` 等成员并声明信号；**moc（元对象编译器）**扫描头文件生成 `moc_xxx.cpp`，提供信号槽所需元信息与信号函数体。
- 没有它：自定义信号槽失效、qobject_cast 失效、tr() 国际化失效。继承 QObject 且要**自定义信号**或用 qobject_cast 时必须写。
- 头号链接报错【高频】：`undefined reference to 'vtable for MainWindow'`——moc 没生成/没编译，Q_OBJECT 展开的虚函数无实现。排查顺序：① .h 没加进 HEADERS/目标源文件；② 没开 `CMAKE_AUTOMOC`；③ **在 .h 新增 Q_OBJECT/signals 后没重新 qmake/cmake**（删 build 目录重来）；④ 类声明语法错误导致 moc 失败。
- 另一经典坑：类写在 .cpp 里且带 Q_OBJECT 时，必须在文件末尾 `#include "文件名.moc"`（5.6 示例有演示）。
