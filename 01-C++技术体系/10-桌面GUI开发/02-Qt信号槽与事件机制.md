## 3. 信号与槽【高频·最重要章节】

### 3.1 本质：框架级观察者模式

信号槽是《../01-语言基础/08-设计模式与典型实现.md》观察者模式的框架化实现：信号≈Subject 的通知，槽≈Observer 的更新，QObject 内部连接表≈观察者列表；增强点：多对多、任一方析构自动断开、跨线程自动投递、（新语法）编译期类型检查。

```text
   emit valueChanged(42)                    发射方（被观察者）
         │
         ▼  查询该对象的连接表
 ┌────────────────────────────────┐
 │ valueChanged → A::onValue      │──► A::onValue(42)    观察者（槽）
 │ valueChanged → B::sig2         │──► B::sig2(42)       信号转发
 │ valueChanged → lambda(this)    │──► lambda(42)        闭包观察者
 └────────────────────────────────┘
```

### 3.2 connect 四种写法对比【高频】

| # | 写法 | 一行示例 | 检查时机 | 评价 |
|---|---|---|---|---|
| ① | Qt4 宏 | `connect(btn, SIGNAL(clicked()), this, SLOT(onClick()));` | 运行时字符串匹配 | 不推荐：拼错签名只在运行时报 No such signal/slot |
| ② | 函数指针（Qt5+） | `connect(btn, &QPushButton::clicked, this, &W::onClick);` | **编译期** | 【推荐】签名不符直接编译失败 |
| ③ | lambda 无上下文 | `connect(btn, &QPushButton::clicked, [this]{ ... });` | 编译期 | 危险：this 析构不断开，槽内访问成员即悬垂 |
| ④ | 函数/lambda + 上下文 | `connect(btn, &QPushButton::clicked, this, [this]{ ... });` | 编译期 | 【推荐】this 既作接收者又作上下文：析构自动断开，且决定执行线程 |

```cpp
// 信号有重载时需指明版本（Qt5 的 QComboBox；Qt6 只剩 int 版无需处理）
connect(box, qOverload<int>(&QComboBox::currentIndexChanged), this, &MainWindow::onIndex);
// 等价：static_cast<void(QComboBox::*)(int)>(&QComboBox::currentIndexChanged)
```

```cpp
// 常用重载（Qt5.4+）：仿函数形式，第五参为连接类型
QMetaObject::Connection c = connect(sender, &Sender::sig, context, functor, Qt::QueuedConnection);
```

| 参数 | 说明 |
|---|---|
| sender / signal | 发射者与信号（函数指针或 SIGNAL 宏字符串） |
| receiver / context | 接收者兼上下文：析构自动断连；仿函数形式下决定其执行线程 |
| slot / functor | 槽函数、普通函数、lambda，或另一个信号（转发） |
| type | 连接类型，默认 AutoConnection（见 3.4） |
| 返回值 | QMetaObject::Connection，保存后可精确 disconnect |

### 3.3 自定义信号

```cpp
class Worker : public QObject {
    Q_OBJECT
signals:                              // 只需声明，moc 负责实现
    void progress(int percent);       // 可带参数；返回值必须是 void
    void finished();
public slots:
    void doWork() {
        emit progress(50);            // emit 是可读性宏（展开为空），本质就是调用
        emit finished();
    }
};
```

规则：信号在 `signals:` 区**只声明不实现**；`signals` 在 Qt5/Qt6 展开为 public，谁都能连；**槽参数可少于信号**（从左往右匹配），反之不行；信号可直接连另一个信号做跨层转发。

### 3.4 连接类型（第五参数）【高频】

| 类型 | 行为 | 注意 |
|---|---|---|
| AutoConnection（默认） | 发射瞬间判断双方线程：同线程→直连，跨线程→队列 | 99% 场景用它，天然线程安全 |
| DirectConnection | 槽在**发射者线程**立即执行（等价直接调用） | 子线程发射 + 槽里操作控件 → 崩溃 |
| QueuedConnection | 槽在**接收者所属线程**的事件循环里执行，参数被拷贝 | 自定义类型须注册元类型（见下）；拿不到槽返回值 |
| BlockingQueuedConnection | 同队列连接，但发射线程阻塞等槽执行完 | **收发同线程必死锁**（自己等自己）【高频坑】 |
| UniqueConnection | 重复连接去重 | **仅对 SIGNAL/SLOT 宏写法生效**，函数指针语法当普通连接处理 |

```cpp
// 队列连接的自定义类型【高频坑】
struct LogMsg { QString file; int line; QString text; };
Q_DECLARE_METATYPE(LogMsg)          // 头文件：进入元对象系统
qRegisterMetaType<LogMsg>("LogMsg");// main() 里、建立连接之前注册
```

Qt 内建类型（int/QString/QByteArray/QVariant 等）已自动注册。

### 3.5 disconnect 与执行顺序

| 用法 | 效果 |
|---|---|
| `disconnect(sender, &S::sig, receiver, &R::slot)` | 断开指定连接 |
| `disconnect(conn)`（保存的 Connection） | 精确断开某一次连接 |
| `sender->disconnect(receiver)` / `obj->disconnect()` | 断开与某接收者的全部 / 该对象全部收发 |
| 任一方析构 | 自动断开 |

执行顺序：一信号连多槽，**同线程内按 connect 先后依次调用**；跨线程队列连接各自在自己线程排队，无全局顺序。多信号连一槽完全合法。

### 3.6 信号槽 vs 回调函数

| 维度 | 原始回调（函数指针） | 信号槽 |
|---|---|---|
| 类型安全 | 无（常退化 void* + 强转） | 函数指针语法编译期检查 |
| 耦合 | 双方需知道对方头文件与签名 | 双方只需都是 QObject，互相不知情 |
| 多对多 | 手工维护回调列表 | 框架内建 |
| 跨线程 | 手写锁+队列+投递 | Queued 自动 |
| 生命周期 | 回调悬垂自己防 | 析构自动断开 |
| 开销 | 一次间接调用 | 直连≈函数指针；队列连接有序列化开销 |

lambda 捕获 this 的悬垂风险（呼应 3.2 的 ③④）：

```cpp
connect(timer, &QTimer::timeout, [this]{ refresh(); });      // 危险：无上下文
connect(timer, &QTimer::timeout, this, [this]{ refresh(); });// 安全：析构自动断开
```

### 3.7 完整示例：两窗口通过自定义信号传递数据

```cpp
// ================= subwindow.h =================
#pragma once
#include <QWidget>

class QLineEdit;

class SubWindow : public QWidget {
    Q_OBJECT                              // 自定义信号必须
public:
    explicit SubWindow(QWidget *parent = nullptr);
signals:
    void sendText(const QString &text);   // 带参数的自定义信号
private slots:
    void onSendClicked();
private:
    QLineEdit *m_edit;
};

// ================= subwindow.cpp =================
#include "subwindow.h"
#include <QLineEdit>
#include <QPushButton>
#include <QVBoxLayout>

SubWindow::SubWindow(QWidget *parent) : QWidget(parent) {
    setWindowTitle("子窗口");
    resize(300, 120);
    m_edit = new QLineEdit(this);
    m_edit->setPlaceholderText("输入要发送的内容");
    auto *btn = new QPushButton("发送到主窗口", this);
    auto *lay = new QVBoxLayout(this);
    lay->addWidget(m_edit);
    lay->addWidget(btn);
    connect(btn, &QPushButton::clicked, this, &SubWindow::onSendClicked);
}

void SubWindow::onSendClicked() {
    emit sendText(m_edit->text());        // 发射信号
}

// ================= mainwindow.h =================
#pragma once
#include <QMainWindow>

class QLabel;
class SubWindow;

class MainWindow : public QMainWindow {
    Q_OBJECT
public:
    explicit MainWindow(QWidget *parent = nullptr);
protected:
    void closeEvent(QCloseEvent *event) override;  // 关主窗口时关子窗口
private slots:
    void onOpenSub();
    void onTextReceived(const QString &text);
private:
    QLabel *m_label;
    SubWindow *m_sub = nullptr;           // 独立窗口：堆上、无 parent
};

// ================= mainwindow.cpp =================
#include "mainwindow.h"
#include "subwindow.h"
#include <QLabel>
#include <QPushButton>
#include <QVBoxLayout>
#include <QCloseEvent>
#include <QDateTime>

MainWindow::MainWindow(QWidget *parent) : QMainWindow(parent) {
    setWindowTitle("主窗口");
    resize(500, 300);
    auto *cw = new QWidget(this);
    setCentralWidget(cw);
    m_label = new QLabel("等待子窗口数据...", cw);
    m_label->setAlignment(Qt::AlignCenter);
    auto *openBtn = new QPushButton("打开子窗口", cw);
    auto *lay = new QVBoxLayout(cw);
    lay->addWidget(m_label, 1);
    lay->addWidget(openBtn);
    connect(openBtn, &QPushButton::clicked, this, &MainWindow::onOpenSub);
}

void MainWindow::onOpenSub() {
    if (!m_sub) {
        m_sub = new SubWindow;
        // 自定义信号→主窗口槽：函数指针语法，编译期检查【推荐】
        connect(m_sub, &SubWindow::sendText, this, &MainWindow::onTextReceived);
        // 子窗口销毁时置空指针（防悬垂）
        connect(m_sub, &SubWindow::destroyed, this, [this] { m_sub = nullptr; });
    }
    m_sub->show();      // 非模态：立即返回，两窗口同时可用
    m_sub->raise();
}

void MainWindow::onTextReceived(const QString &text) {
    m_label->setText(QString("[%1] 收到：%2")
                     .arg(QDateTime::currentDateTime().toString("hh:mm:ss"), text));
}

void MainWindow::closeEvent(QCloseEvent *event) {
    if (m_sub) m_sub->close();
    event->accept();
}

// ================= main.cpp =================
#include <QApplication>
#include "mainwindow.h"

int main(int argc, char *argv[]) {
    QApplication a(argc, argv);
    MainWindow w;
    w.show();
    return a.exec();
}
```

## 4. 事件系统

### 4.1 事件循环：a.exec() 做了什么

`a.exec()` 启动事件循环（近似 while）：阻塞等待事件源（窗口系统消息、socket 活动通知、定时器、postEvent 投递），取出后 `QCoreApplication::sendEvent()` 分发给目标对象的 `event()`，再派发给具体 `xxxEvent()` 虚函数；直到 `quit()/exit(code)` 才返回，exec 的返回值即 main 的返回值。

```text
int main() { QApplication a; w.show(); return a.exec(); }
                                  │
                                  ▼
 ┌──────────── a.exec()（近似伪代码）──────────────┐
 │  while (!quit_flag) {                          │
 │      event = 阻塞等待并取出队列头;              │
 │      sendEvent(接收者, event);                  │
 │        └─► event() ─► xxxEvent() 虚函数         │
 │      顺带处理 deleteLater、到期定时器等;         │
 │  }                                             │
 │  return exit_code;                             │
 └────────────────────────────────────────────────┘
```

| 函数 | 说明 | 示例 |
|---|---|---|
| exec() | 进入事件循环直到退出 | `return a.exec();` |
| quit() / exit(int) | 退出循环（quit≡exit(0)），可跨线程调用 | `QTimer::singleShot(3000, &a, &QCoreApplication::quit);` |
| processEvents() | 长任务里手动处理一次积压事件（慎用） | `QCoreApplication::processEvents();` |

### 4.2 事件处理的三个层次【高频】

| 层次 | 手段 | 适用 |
|---|---|---|
| ① 重写事件虚函数 | keyPressEvent / paintEvent / mousePressEvent 等 | 只关心某类事件，最常用 |
| ② 重写 event() | `bool event(QEvent *e)` 统一入口，返回 true=不再分发 | 拦截到不了 xxxEvent 的事件：经典是 **Tab 键**（默认在 event() 层被焦点切换消费，到不了 keyPressEvent） |
| ③ 事件过滤器 | `target->installEventFilter(this)` + 重写自己的 eventFilter | **目标类不可/不想继承时**【高频】 |

```cpp
// 经典：让输入框忽略鼠标滚轮（避免误改数字）
m_spinBox->installEventFilter(this);          // 装在目标控件上

bool MainWindow::eventFilter(QObject *watched, QEvent *event) {
    if (watched == m_spinBox && event->type() == QEvent::Wheel)
        return true;                          // 吞掉该事件
    return QMainWindow::eventFilter(watched, event);   // 其余交回基类
}
```

### 4.3 常见事件类型表

| 事件类 | 对应虚函数 | 触发时机与常用成员 |
|---|---|---|
| QMouseEvent | mousePressEvent / mouseReleaseEvent / mouseMoveEvent / mouseDoubleClickEvent | `button()` 判断键位；坐标 Qt5 用 pos()，Qt6 推荐 position().toPoint()；跟踪移动需 setMouseTracking(true) |
| QKeyEvent | keyPressEvent / keyReleaseEvent | `key()`（Qt::Key_Return 等）；`modifiers()` 判断 Ctrl/Shift |
| QPaintEvent | paintEvent | 控件需重绘（见《03-Qt界面组件与布局.md》第 9 章） |
| QResizeEvent | resizeEvent | `size()` / `oldSize()`，自绘控件重算几何 |
| QCloseEvent | closeEvent | 关闭前拦截：accept() 放行 / ignore() 取消 |
| QTimerEvent | timerEvent | `startTimer(ms)` 返回 id，`event->timerId()` 区分，killTimer(id) 停止 |
| QWheelEvent | wheelEvent | `angleDelta().y()` 正负判断方向 |
| QFocusEvent | focusInEvent / focusOutEvent | 聚焦高亮等 |
| QShowEvent/QHideEvent | showEvent / hideEvent | 首次显示做一次性初始化 |
| QDragEnterEvent/QDropEvent | dragEnterEvent / dropEvent | 拖放接收（需 setAcceptDrops(true)） |

### 4.4 postEvent vs sendEvent；QTimer

| | sendEvent（同步） | postEvent（异步） |
|---|---|---|
| 行为 | 立即调用目标 event()，返回处理结果 | 事件入队，控制权回事件循环才处理 |
| 事件所有权 | 调用者持有（栈上构造即可） | 必须 new，队列接管并负责删除 |
| 典型用途 | 测试中模拟事件 | 跨对象/跨线程投递事件 |

```cpp
QCloseEvent e;  QApplication::sendEvent(&w, &e);          // 同步
QApplication::postEvent(this, new QEvent(QEvent::User));  // 异步
```

QTimer 速查（startTimer 的信号槽化封装）：

| 函数/信号 | 说明 | 示例 |
|---|---|---|
| start(int ms) | 启动/重启并设周期 | `timer->start(1000);` |
| setInterval / setSingleShot | 周期 / 单次触发 | `timer->setSingleShot(true);` |
| stop() / isActive() | 停止 / 是否运行 | |
| timeout() 信号 | 每次到时发射【核心】 | `connect(timer, &QTimer::timeout, ...)` |
| QTimer::singleShot(ms, ctx, functor) | 静态：延迟执行一次 | `QTimer::singleShot(3000, this, [this]{ close(); });` |

### 4.5 event() 返回值与 accept()/ignore()

`event()` 返回 true：事件到此为止不再分发；accept()/ignore() 针对部分事件（键盘、关闭）的"是否接收"语义，ignore() 后事件继续向父控件传播，事件默认处于 accepted 状态。

closeEvent 拦截关闭的经典写法【高频】：

```cpp
void MainWindow::closeEvent(QCloseEvent *event) {
    if (m_modified) {
        auto ret = QMessageBox::warning(this, "提示", "尚未保存，是否退出？",
                                        QMessageBox::Yes | QMessageBox::No);
        if (ret == QMessageBox::No) { event->ignore(); return; }   // 拦截：不关
    }
    event->accept();   // 放行：正常关闭
}
```
