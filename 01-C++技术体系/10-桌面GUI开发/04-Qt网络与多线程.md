## 10. 网络与多线程【高频】

网络模块：qmake `QT += network`；CMake `find_package(Qt6 COMPONENTS Network)` + 链接 `Qt6::Network`（Qt5 换前缀）。

### 10.1 QTcpServer / QTcpSocket

本质（衔接《../03-网络编程/02-IO多路复用与Reactor模型.md》）：二者是对 BSD socket 的 C++ 封装，并把"非阻塞 + I/O 多路复用"隐藏进事件循环——可读/可写/出错都转成信号，不需要手写 select/epoll 循环。

信号速查表：

| 对象 | 信号 | 触发时机 |
|---|---|---|
| QTcpServer | newConnection() | 有新连接待接收（接着调 nextPendingConnection 取走） |
| QTcpSocket | connected() | connectToHost 三次握手成功 |
| QTcpSocket | disconnected() | 连接断开 |
| QTcpSocket | readyRead() | **有新数据到达可读**【核心】 |
| QTcpSocket | errorOccurred(QAbstractSocket::SocketError) | 出错；Qt 5.15 前叫 error(...)，Qt6 仅有 errorOccurred |
| QTcpSocket | stateChanged(SocketState) | 状态迁移 |
| QTcpSocket | bytesWritten(qint64) | 数据真正写出（内核缓冲腾出） |

常用函数表：

| 对象 | 函数 | 说明 |
|---|---|---|
| QTcpServer | listen(QHostAddress::Any, port) | 开始监听，返回是否成功 |
| QTcpServer | hasPendingConnections() / nextPendingConnection() | 有无排队连接 / 取出（返回 QTcpSocket*，所有权归调用者） |
| QTcpServer | close() / errorString() / serverPort() | 停止监听 / 错误信息 / 实际端口 |
| QTcpSocket | connectToHost(host, port) / disconnectFromHost() | 发起 / 断开连接 |
| QTcpSocket | write(data) / readAll() / read(buf, max) | 写入发送缓冲 / 尽量读走 |
| QTcpSocket | bytesAvailable() / flush() | 可读字节数 / 立即发出缓冲数据 |
| QTcpSocket | peerAddress() / peerPort() / state() / abort() | 对端信息 / 当前状态 / 立即丢弃缓冲断开 |

简易 TCP echo 服务端（窗口 + 日志，约 50 行）：

```cpp
// echoserver.h
#pragma once
#include <QWidget>
#include <QTcpServer>
#include <QTcpSocket>

class QPlainTextEdit;
class QSpinBox;

class EchoServer : public QWidget {
    Q_OBJECT
public:
    explicit EchoServer(QWidget *parent = nullptr);
private slots:
    void startListen();
private:
    void log(const QString &msg) { m_log->appendPlainText(msg); }
    QTcpServer m_server;                  // 随窗口析构
    QPlainTextEdit *m_log = nullptr;
    QSpinBox *m_port = nullptr;
};

// echoserver.cpp
#include "echoserver.h"
#include <QPlainTextEdit>
#include <QSpinBox>
#include <QPushButton>
#include <QLabel>
#include <QHBoxLayout>
#include <QVBoxLayout>

EchoServer::EchoServer(QWidget *parent) : QWidget(parent) {
    setWindowTitle("TCP Echo 服务端");
    resize(520, 380);
    m_log = new QPlainTextEdit;  m_log->setReadOnly(true);
    m_port = new QSpinBox;      m_port->setRange(1, 65535);  m_port->setValue(9000);
    auto *btn = new QPushButton("开始监听");
    auto *top = new QHBoxLayout;
    top->addWidget(new QLabel("端口："));
    top->addWidget(m_port);
    top->addWidget(btn);
    top->addStretch();

    auto *lay = new QVBoxLayout(this);
    lay->addLayout(top);
    lay->addWidget(m_log);

    connect(btn, &QPushButton::clicked, this, &EchoServer::startListen);

    // 新连接 → 逐个取出并接线
    connect(&m_server, &QTcpServer::newConnection, this, [this] {
        while (QTcpSocket *c = m_server.nextPendingConnection()) {
            log("新客户端：" + c->peerAddress().toString());
            // 数据到达 → 原样回写（echo）
            connect(c, &QTcpSocket::readyRead, this, [this, c] {
                const QByteArray data = c->readAll();
                c->write(data);
                log("收到: " + QString::fromUtf8(data));
            });
            // 断开 → deleteLater 安全回收（见《01-Qt框架与界面开发.md》第 2 章）
            connect(c, &QTcpSocket::disconnected, c, [this, c] {
                log("客户端断开");
                c->deleteLater();
            });
        }
    });
}

void EchoServer::startListen() {
    if (m_server.listen(QHostAddress::Any, m_port->value()))   // 监听所有网卡
        log(QString("监听成功，端口 %1").arg(m_server.serverPort()));
    else
        log("监听失败：" + m_server.errorString());
}
```

一对一客户端连接示例：

```cpp
auto *sock = new QTcpSocket(this);          // parent=this，窗口析构自动清理
connect(sock, &QTcpSocket::connected, this, [this, sock] {
    sock->write("hello server\n");
});
connect(sock, &QTcpSocket::readyRead, this, [this, sock] {
    log("服务器回复: " + QString::fromUtf8(sock->readAll()));
});
connect(sock, &QTcpSocket::errorOccurred, this, [this](QAbstractSocket::SocketError e) {
    log("连接出错: " + QString::number(int(e)));   // errorOccurred：Qt6/Qt5.15+
});
sock->connectToHost("127.0.0.1", 9000);     // 异步：结果经 connected 信号通知
```

提示：无事件循环的控制台程序可用阻塞式 `waitForConnected()/waitForReadyRead()` 过渡；GUI 程序一律用信号槽。

### 10.2 QNetworkAccessManager（HTTP）

异步三步曲：`get(QNetworkRequest)` 立即返回 `QNetworkReply*` → 完成时发 finished 信号 → 槽里 `readAll()` 并 **手动 deleteLater()**【高频坑：reply 不会自动释放，忘写必泄漏】。

```cpp
// GET（Qt5/Qt6 通用）
auto *nam = new QNetworkAccessManager(this);      // 整个程序一个实例即可
connect(nam, &QNetworkAccessManager::finished, this, [this](QNetworkReply *reply) {
    reply->deleteLater();                         // 【必写】防泄漏
    if (reply->error() != QNetworkReply::NoError) {
        m_label->setText("请求失败: " + reply->errorString());
        return;
    }
    m_label->setText(QString::fromUtf8(reply->readAll()));
});
nam->get(QNetworkRequest(QUrl("https://example.com/")));

// POST JSON
QNetworkRequest req(QUrl("https://example.com/api"));
req.setHeader(QNetworkRequest::ContentTypeHeader, "application/json");
nam->post(req, QByteArray(R"({"name":"qt"})"));
// 上传文件：QHttpMultiPart 组装 multipart/form-data 后 nam->post(req, multiPart)
```

| 配置项 | 说明 |
|---|---|
| req.setTransferTimeout(ms) | 传输超时（Qt 5.15+/Qt6） |
| req.setRawHeader(name, value) | 自定义请求头 |
| nam->setProxy(QNetworkProxy) | 代理 |
| req.setSslConfiguration(QSslConfiguration) | SSL 证书/协议配置（QtNetwork） |
| reply->attribute(QNetworkRequest::HttpStatusCodeAttribute) | HTTP 状态码 |
| reply->header(QNetworkRequest::LocationHeader) | 响应头（如重定向地址） |

### 10.3 QThread 两种用法【面试高频】

先纠正最常见误解：**QThread 对象本身住在创建它的线程里**，它只是新线程的"遥控器"。

```text
  主线程                               新线程（OS 线程）
  ┌────────────────────┐             ┌────────────────────────────┐
  │ QThread 对象 this   │   start()  │ run() 函数体（子类化写法）    │
  │ 它自己的槽默认仍在   │ ─────────► │ 或：被 moveToThread 进来的  │
  │ 主线程执行！         │             │ worker 的槽函数             │
  └────────────────────┘             └────────────────────────────┘
```

| 维度 | 法一：子类化 QThread 重写 run() | 法二：moveToThread 工作对象【官方推荐】 |
|---|---|---|
| 谁在新线程执行 | 只有 run() 函数体 | worker 的**所有槽**（经队列连接投递过去） |
| 对象线程归属 | QThread 对象仍在创建线程（易误解） | worker 整体搬入新线程 |
| 事件循环 | run() 默认不跑事件循环（除非手动 exec()），线程内 QTimer/队列槽不可用 | 新线程自带事件循环，QTimer、队列信号槽正常 |
| 控制粒度 | 单一入口，任务多时 run() 膨胀 | 多个槽=多个任务入口，粒度细 |
| 典型场景 | 简单一次性后台循环 | 多任务调度、需定时器/复杂交互 |
| 历史 | Qt4 时代唯一写法 | Qt5 起官方文档推荐【高频】 |

法一：子类化 QThread（注意"run 里的代码在新线程、对象的槽在原线程"）：

```cpp
class RenderThread : public QThread {
    Q_OBJECT
public:
    void stop() { m_stop = true; }            // 跨线程只写原子标志，安全
signals:
    void progress(int percent);
protected:
    void run() override {                     // run() 内代码运行在新线程
        m_stop = false;
        for (int i = 0; i <= 100 && !m_stop; ++i) {
            QThread::msleep(50);
            emit progress(i);                 // 跨线程信号自动变 Queued
        }
    }
private:
    std::atomic_bool m_stop{false};
};
```

法二：worker + moveToThread（完整代码，含停止标志与收尾）：

```cpp
// worker.h
#pragma once
#include <QObject>
#include <QThread>
#include <atomic>

class Worker : public QObject {
    Q_OBJECT
public slots:
    void doWork() {                           // 运行在新线程（started 信号投递过来）
        for (int i = 1; i <= 100 && !m_stop; ++i) {
            QThread::msleep(50);
            emit progress(i);
        }
        emit workFinished();
    }
    void stop() { m_stop = true; }            // 也设计成槽：主线程发信号安全触发
signals:
    void progress(int percent);
    void workFinished();
private:
    std::atomic_bool m_stop{false};
};

// 主窗口里启动（MainWindow 摘要）：
void MainWindow::startWork() {
    auto *thread = new QThread(this);         // 线程对象归主窗口管
    auto *worker = new Worker;                // 注意：worker 不能有 parent，否则 move 失败
    worker->moveToThread(thread);

    connect(thread, &QThread::started,     worker, &Worker::doWork);        // 启动即开工
    connect(worker, &Worker::workFinished, thread, &QThread::quit);         // 干完退线程
    connect(worker, &Worker::progress,     this,   &MainWindow::onProgress);// 回主线程刷 UI
    connect(thread, &QThread::finished,    worker, &QObject::deleteLater);  // 线程结束清 worker
    connect(this,   &MainWindow::stopRequested, worker, &Worker::stop);     // 跨线程自动排队
    thread->start();
}
// 关闭窗口时收尾（放 closeEvent）：
//   thread->quit();    // 请求事件循环退出
//   thread->wait();    // 阻塞等线程真正结束，避免析构中的崩溃警告
```

### 10.4 线程同步与安全清单

同步原语（衔接《../04-并发编程/01-线程基础与生命周期.md》，Qt 版与 std 版可混用，风格统一即可）：

| 工具 | 用法 | 说明 |
|---|---|---|
| QMutex + QMutexLocker | `QMutexLocker locker(&m_mutex);` | RAII 加解锁，首选；QRecursiveMutex 可重入 |
| QReadWriteLock | `QReadLocker l(&m_lock);` / `QWriteLocker l(&m_lock);` | 读多写少场景 |
| QWaitCondition / QSemaphore | 配合 QMutex | 生产者消费者 / 资源计数 |
| QAtomicInteger / std::atomic | `m_stop = true;` | 标志位等原子操作 |

线程安全红线清单【一票否决】：

| 规则 | 原因与替代做法 |
|---|---|
| **控件、QPixmap 等所有 GUI 类只能在主线程创建/操作** | GUI 类非重入；子线程更新界面 → emit 信号连主线程对象的槽（自动 Queued） |
| QTimer 只能在"自己所属线程"start | moveToThread 后应在 worker 槽里 new QTimer/start；主线程建的定时器拿到别的线程 start 属未定义行为 |
| 不在持锁时做跨线程 BlockingQueued 调用 | 双方互等即死锁 |
| 跨线程信号槽参数需要元类型 | 自定义类型：头文件 `Q_DECLARE_METATYPE(T)` + 连接前 `qRegisterMetaType<T>("T")`【高频坑】 |
| 不用 terminate() 杀线程 | 强杀时机不可控，用原子停止标志 + quit/wait |

高层封装一句话表：

| 工具 | 一句话用法 |
|---|---|
| QThreadPool + QRunnable | 派生 QRunnable 重写 run()，`QThreadPool::globalInstance()->start(runnable)`；runnable 默认执行完自动删除 |
| QtConcurrent::run | `auto f = QtConcurrent::run([](int n){ return n * n; }, 8);` 立即返回 QFuture，f.result() 取值（阻塞） |
| QtConcurrent::map / mapped / filter | 对整个容器并行映射/过滤；Qt6 的 QFuture 支持 `then()/onFailed()` 链式续接 |

## 15. 模型视图与 C++ 交互【重点·高频】

### 15.1 模型 / 委托 / 视图三概念

与《../01-语言基础/03-STL容器与算法.md》"容器 + 算法"分离思想一脉相承：**视图不拥有数据**，只管展示与滚动；**delegate 是模板不是实例**，视图按可视区需要实例化/回收它。

| 概念 | 职责 | QML 侧对应 |
|---|---|---|
| Model（模型） | 持有数据、提供角色（role）、发变更信号 | ListModel / JS 数组 / 整数 / C++ QAbstractListModel |
| Delegate（委托） | 单条数据的 UI 模板 | `delegate: Item {...}` |
| View（视图） | 布局实例、滚动、复用 | ListView / GridView / TableView |

```text
   ┌────────────┐  count/roleNames/   ┌──────────────┐  按需实例化  ┌─────────────┐
   │   Model    │ ── data(role) ────▶ │  Delegate    │ ◀────────── │    View     │
   │  (数据层)  │     提供 role 值     │ (每项UI模板) │  可视区外回收│ (滚动/布局) │
   └────────────┘                     └──────────────┘             └─────────────┘
        ▲                                  │ 复用/回收
        │ dataChanged/insertRows 信号驱动  └────────────────────────────┘
   C++ QAbstractListModel / ListModel / JS 数组 / 整数
```

### 15.2 ListView 核心属性

| 属性 | 说明 |
|---|---|
| `model` / `delegate` | 数据源（四种，见 15.3）/ 每项 UI 模板 |
| `spacing` / `clip: true` | 项间距 / 裁剪溢出内容【不设常见"内容飘出边界"】 |
| `orientation` | `ListView.Vertical` / `Horizontal` |
| `header` / `footer` | 头/尾（footer 自动贴底，常用"加载更多"指示） |
| `section.property` / `section.delegate` | 按角色分组显示小标题 |
| `cacheBuffer` | 可视区外预实例化像素量，加大消滚动白屏【性能一句话】 |
| `ScrollBar.vertical: ScrollBar {}` | 附加垂直滚动条 |
| `currentIndex` / `currentItem` / `highlight` | 当前项与高亮（点击默认不改 currentIndex，需手动 `listView.currentIndex = index`） |
| `populate` / `add` / `move` / `displaced` | 各场景 Transition 动画 |
| `reuseItems: true` | Qt5.15+ 开启 delegate 复用池（提性能，注意状态残留，见《05-Qt综合实战.md》第 17 章） |

### 15.3 数据源四种方式

| 数据源 | 写法 | 修改后自动刷新？ |
|---|---|---|
| ① ListModel + ListElement | 声明式；元素属性即 role | 是：`append` `insert` `set` `setProperty` `remove` `move` `clear` 全部即时刷新【推荐】 |
| ② 整数 | `model: 10` | 否（静态，仅提供 `index`） |
| ③ JS 数组 | `model: someArray` | **否**【坑】`push/splice` 原地修改不触发；整体**重新赋值**才刷新绑定 |
| ④ C++ 模型 | `QAbstractListModel` 派生 | 是：`dataChanged`/`insertRows` 等信号驱动【生产推荐】 |

```qml
ListView {
    model: ListModel {
        ListElement { name: "张三"; age: 28 }      // 定义 role: name、age
        ListElement { name: "李四"; age: 35 }
    }
    delegate: ItemDelegate {
        required property string name              // Qt6【推荐】声明需要的 role
        required property int age
        text: name + "（" + age + "岁）"
        onClicked: console.log("点击", name)
    }
    ScrollBar.vertical: ScrollBar { }
}
```

### 15.4 delegate 编写规范【Qt5/Qt6 差异重点】

| 写法 | 版本 | 说明 |
|---|---|---|
| `required property string name` | **Qt5.15 引入，Qt6 官方推荐** | 声明依赖 role 自动注入；模型缺 role 显式报错（早失败），qmllint 可静态检查 |
| `model.name` / `model.index` | Qt5 传统 | 访问 model 对象 role；未声明 required 时 Qt6 给弃用警告 |
| `modelData` | 通用 | 数据源是纯值（整数/字符串数组）时的单一角色名：`text: modelData` |

**复用状态残留坑**：滚动/复用（尤其 `reuseItems: true`）时同一 delegate 实例被填充不同数据，若把选中/展开等状态存在 delegate 自定义属性里，滚动回来就"串数据"。正确做法：UI 状态**绑定**模型数据（`checked: model.selected`），或 `ListView.onReused`（Qt5.15+ 附加信号）中重置；Qt5.15 起 `ListView.onAdd/onRemove` 已废弃，改用 `add`/`remove` Transition。

| 视图 | 特点 | 适用 |
|---|---|---|
| `ListView` | 一维、滚动、按需实例化 | 任意长列表 |
| `GridView` | 网格：`cellWidth`/`cellHeight`、`flow` | 相册、九宫格 |
| `TableView`（Qt6） | 表格；模型 QAbstractTableModel；`columnWidthProvider`/`rowHeightProvider` 定尺寸；delegate 同样用 required property（如 `required property var value`） | 大数据表格 |
| `Repeater` | **不是视图**：立即实例化全部项，无滚动无复用 | 少量项（工具栏/菜单），放 Row/Column/Grid/Flow 内 |

### 15.5 C++ ↔ QML 交互大图【面试高频】

```text
┌────────────────────────── C++ 世界 ──────────────────────────┐
│  class Backend : public QObject                              │
│    Q_PROPERTY(userName READ/WRITE/NOTIFY)   ← 数据绑定源      │
│    Q_INVOKABLE login(...)                   ← 可调方法       │
│    signals: result(...)                     → 通知 QML       │
│        ▲                                                    │
│        │ ①engine.rootContext()->setContextProperty("backend",&b)│
│        │ ②qmlRegisterType<T>("MyApp",1,0,"T")      QML 中创建实例│
│        │ ③qmlRegisterSingletonInstance("MyApp",1,0,"Svc",&s)  单例│
│        │ ④QML_ELEMENT + qt_add_qml_module           自动注册(Qt6)│
├──────────────────────────────────────────────────────────────┤
│  QQmlApplicationEngine（QML 引擎）                           │
│      └─ rootObjects() ─ findChild<QObject*>("objectName")    │
│              └─ setProperty() / QMetaObject::invokeMethod()  │
├──────────────────────────────────────────────────────────────┤
│  QML 世界：backend.userName / MyClass { } / onResult: {...}  │
└──────────────────────────────────────────────────────────────┘
```

**四种暴露方式对比大表【面试高频】**：

| 方式 | 典型调用 | 语义 | 生命周期 | 适用 |
|---|---|---|---|---|
| ① 上下文属性 | `engine.rootContext()->setContextProperty("backend", &obj);` | 全局名字注入，QML 直接 `backend.xxx` | C++ 拥有 | 最快上手，原型与全局后台对象 |
| ② 注册类型 | `qmlRegisterType<MyClass>("MyApp", 1, 0, "MyClass");` | QML 中 `MyClass { }` **创建实例** | QML/引擎（按所有权规则） | 每处需要独立实例的类型 |
| ③ 注册单例实例 | `qmlRegisterSingletonInstance("MyApp", 1, 0, "Svc", &obj);`（**Qt5.14+ / Qt6**） | 把**已存在**的 C++ 对象暴露为 QML 单例 | C++ 拥有；engine 不接管，对象须活得比 QML 引用久 | 全局服务【推荐】 |
| ④ QML_ELEMENT + qt_add_qml_module（Qt6） | 类内 `QML_ELEMENT` 宏 + CMake | 声明式自动注册进模块（同②；另有 `QML_SINGLETON`、`QML_UNCREATABLE("理由")` 等宏） | 同② | Qt6 现代工程【官方推荐】 |

> ③与①的区别：单例方式是正式的 QML 类型系统成员（可 import、可设版本），①只是引擎级全局变量；新代码优先③/④。

### 15.6 Q_PROPERTY / Q_INVOKABLE / 信号

```cpp
class Backend : public QObject
{
    Q_OBJECT
    // 三要素 READ/WRITE/NOTIFY【头号坑：缺 NOTIFY，QML 绑定只在创建时求值一次，之后永远不刷新】
    Q_PROPERTY(QString userName READ userName WRITE setUserName NOTIFY userNameChanged)
    // 构造后确实永不变化的属性可用 CONSTANT 替代 NOTIFY（此时不得有 setter）
public:
    Q_INVOKABLE void login(const QString &password);   // Q_INVOKABLE：QML 可直接调
public slots:
    void refresh();                        // public slots 同样可被 QML 调用
signals:
    void userNameChanged();
    void result(bool ok, const QString &message);  // QML 中处理器为 onResult
};
```

| 要素 | 作用 | 缺失后果 |
|---|---|---|
| `READ xxx` | 读访问器（必需） | 无法注册 |
| `WRITE setXxx` | 写访问器 | 属性只读（QML 赋值报错） |
| `NOTIFY xxxChanged` | 变更通知信号 | **QML 绑定不刷新**【头号坑】；setter 中必须 emit，值相同应跳过 emit 防绑定风暴 |

C++ 信号 → QML 处理器：信号 `result(bool, QString)` 在 QML 中 `Backend { onResult: (ok, message) => tip.text = message }`（Qt5.15+ 写法；Qt5 传统写法 `onResult: { tip.text = message }` 参数隐式注入，已废弃）。

**元类型映射表**：

| C++ 类型 | QML / JS 侧 |
|---|---|
| `bool` / `int` / `double` | `boolean` / `number` |
| `QString` | `string` |
| `QVariantList` / `QVariantMap` | JS 数组 / JS 对象 `{k: v}` |
| `QDateTime` / `QDate` / `QTime` | `Date` |
| `QUrl` / `QColor` | `url` / `color`（`"#RRGGBB"`） |
| `QImage`/`QPixmap` | 不能直接传；用 `QQuickImageProvider` 或转存文件传 url |
| `QObject*` 派生指针 | 对象引用（可继续读其属性） |

### 15.8 完整综合示例（C++ 后端 + QML 登录页，可编译）

```cpp
// backend.h —— Q_PROPERTY + NOTIFY + Q_INVOKABLE + 业务信号
#pragma once
#include <QObject>
#include <QString>

class Backend : public QObject
{
    Q_OBJECT
    Q_PROPERTY(QString userName READ userName WRITE setUserName NOTIFY userNameChanged)
public:
    explicit Backend(QObject *parent = nullptr) : QObject(parent) {}

    QString userName() const { return m_userName; }
    void setUserName(const QString &name) {
        if (m_userName == name) return;   // 【必须】值未变不发信号，避免绑定风暴
        m_userName = name;
        emit userNameChanged();           // 通知所有 QML 绑定刷新
    }

    Q_INVOKABLE void login(const QString &password) {   // QML 可直接调用
        // 真实项目把耗时校验放线程池，完成后回主线程发信号
        const bool ok = (password.length() >= 6);
        emit result(ok, ok ? QStringLiteral("登录成功")
                           : QStringLiteral("密码至少 6 位"));
    }

signals:
    void userNameChanged();
    void result(bool ok, const QString &message);   // 驱动 QML 界面更新

private:
    QString m_userName;
};
```

```cpp
// main.cpp —— 注入对象 + 加载模块 + 失败退出
#include <QGuiApplication>
#include <QQmlApplicationEngine>
#include "backend.h"

int main(int argc, char *argv[])
{
    QGuiApplication app(argc, argv);

    Backend backend;                                 // 栈上对象：活得比 QML 引用久

    QQmlApplicationEngine engine;
    // 方式①上下文属性注入（最快）；生产可换 qmlRegisterSingletonInstance（Qt5.14+）
    engine.rootContext()->setContextProperty("backend", &backend);

    engine.loadFromModule("QmlDemo", "Main");        // Qt6.5+；Qt6.0~6.4 用
    if (engine.rootObjects().isEmpty())              // engine.load(QUrl("qrc:/qt/qml/QmlDemo/Main.qml"))
        return -1;
    return app.exec();
}
```
