## 1. 概述

泛型编程的核心思想：**把算法与它操作的具体类型解耦**——算法只描述"需要什么操作"，而不关心操作的对象是 `int` 还是 `std::string`。

| 维度 | 面向对象多态 | 泛型（模板）多态 |
| --- | --- | --- |
| 绑定时机 | 运行期（vtable） | 编译期（实例化） |
| 对类型的要求 | 公共基类接口 | 满足语法约束即可（duck typing） |
| 性能 | 间接调用 | 可内联、可深度优化 |
| 代价 | 每对象一个 vptr | 代码膨胀、编译变慢、报错难读 |

模板不只是"类型参数化的函数/类"——它是**图灵完备的编译期语言**：模板实例化在编译期递归展开，配合特化即可做编译期计算与类型运算（见第 10 节）。代价是实例化深度与编译时间。

## 2. 函数模板

### 2.1 定义与调用

```cpp
template <typename T>              // typename 与 class 等价，推荐 typename
T my_max(const T& a, const T& b) {
    return a < b ? b : a;          // 只要求 T 支持 operator<
}

int main() {
    my_max(1, 2);                  // 模板实参推导：T = int
    my_max<double>(1, 2.5);        // 显式指定：两个参数类型不同时必须显式
}
```

### 2.2 模板实参推导表（重点）

传值、传引用、传 const 引用对 `T` 的推导差异：

| 形参形式 | 传入实参 | 推导出的 T | 说明 |
| --- | --- | --- | --- |
| `T x`（传值） | `int i` | `int` | 顶层 const、引用都被剥离 |
| `T x`（传值） | `const int ci` | `int` | 拷贝，const 剥离 |
| `T x`（传值） | `int& r` | `int` | 引用性被忽略 |
| `T x`（传值） | `"hi"`（`const char[3]`） | `const char*` | **数组/函数退化**为指针 |
| `T& x`（传引用） | `int i` | `int` | 推导为引用 |
| `T& x`（传引用） | `const int ci` | `const int` | const 会被吸收进 T |
| `T& x`（传引用） | `"hi"` | `const char[3]` | **数组不退化**（保留数组类型） |
| `const T& x` | `int i` / `const int ci` | `int` | 形参 const 在外，T 不带 const |
| `const T& x` | `"hi"` | `char[3]` | 数组不退化，数组元素是 char |
| `T&& x`（模板中） | `int` 右值 | `int` | 转发引用（见第 7 节） |
| `T&& x`（模板中） | `int` 左值 | `int&` | 引用折叠：`int& && → int&` |

> 由此产生经典坑：`template<class T> void f(T x)` 传数组会退化为指针，`sizeof(x)` 是指针大小；想保留数组长度要传 `T&`。

### 2.3 显式指定模板实参

```text
my_max<double>(1, 2.5);          // 指定 T = double
my_max<int>('a', 'b');           // 强制按 int 比较
```

显式指定后模板形参从左往右固定，其余继续推导；也可用 `my_max<>`（空尖括号）强制走推导。

## 3. 类模板

```cpp
template <typename T>
class Stack {
public:
    void push(T v) { data_.push_back(std::move(v)); }
    T pop() { T v = std::move(data_.back()); data_.pop_back(); return v; }
    bool empty() const { return data_.empty(); }
private:
    std::vector<T> data_;
};

int main() {
    Stack<int> s;                 // C++17 之前必须写 <int>
    Stack<double> d;              // 每种 T 生成一份独立代码（实例）
}
```

### 3.1 CTAD 类模板实参推导（C++17）

```cpp
std::pair p(1, 2.5);              // C++17：推导出 std::pair<int, double>
std::vector v{1, 2, 3};           // std::vector<int>
template <typename T> struct Box { T value; };
Box b{42};                        // Box<int>（C++20 起聚合也获得隐式推导指引）
Stack s2{std::vector<int>{}};     // 有构造函数即可参与推导
```

### 3.2 成员函数延迟实例化

类模板的成员函数**只有被实际调用时才实例化**。这可以当作"伪约束"：

```cpp
template <typename T>
class DebugPrinter {
public:
    explicit DebugPrinter(T t) : t_(std::move(t)) {}
    void print() const { std::cout << t_; }   // T 没有operator<< 时，只有调用 print 才报错
private:
    T t_;
};
```

| 特性 | 后果 |
| --- | --- |
| 未调用的成员函数不实例化 | 模板类可以容纳"只支持部分操作"的类型 |
| 报错发生在使用点 | 错误信息出现得很晚（Concepts 时代已可前置约束） |

## 4. 模板参数种类

| 种类 | 语法 | 示例 | 说明 |
| --- | --- | --- | --- |
| 类型参数 | `typename T` / `class T` | `std::vector<int>` | 最常用 |
| 非类型参数 NTTP（整型） | `int N`、`std::size_t N` | `std::array<int, 4>` | 编译期常量，参与类型 |
| 非类型参数 `auto`（C++17） | `auto V` | `template<auto V> void f();` | 由实参推导值的类型 |
| 非类型参数（浮点/类类型，C++20） | `double D`、字面类类型 | `template<double D>` | C++20 起允许；类类型需满足 structural 要求 |
| 模板模板参数 | `template<class> class C` | `template<template<class> class Container> ...` | 参数本身是模板（C++17 起可用 `typename` 代替 `class`） |

```cpp
template <typename T, std::size_t N>          // NTTP：数组长度参与类型
class RingBuffer { T buf_[N]; std::size_t idx_ = 0; /* ... */ };

template <template <typename, typename> class Container, typename T>  // 模板模板参数
using IntBox = Container<T, std::allocator<T>>;
IntBox<std::vector, int> v;                   // std::vector<int>
```

## 5. 特化与偏特化

### 5.1 语法与选择规则

| 形式 | 语法 | 选择规则 |
| --- | --- | --- |
| 主模板 | `template<class T> struct X {...};` | 兜底 |
| 全特化 | `template<> struct X<int> {...};` | 实参完全匹配 `X<int>` 时优先于主模板 |
| 偏特化 | `template<class T> struct X<T*> {...};` | 实参匹配某个"模式"（仅类模板支持；函数模板只能重载不能偏特化） |

```cpp
template <typename T> struct IsPointer          { static constexpr bool value = false; };
template <typename T> struct IsPointer<T*>      { static constexpr bool value = true;  };  // 偏特化
template <>           struct IsPointer<void>    { static constexpr bool value = false; };  // 全特化
```

### 5.2 traits 惯用法

```cpp
// 简化版 is_pointer：真版请用标准库 <type_traits>
template <typename T> struct remove_ref      { using type = T; };
template <typename T> struct remove_ref<T&>  { using type = T; };
template <typename T> struct remove_ref<T&&> { using type = T; };

template <typename T> using remove_ref_t = typename remove_ref<T>::type;  // C++14 别名模板

static_assert(remove_ref_t<int&>{} + 1 == 1);   // int
```

### 5.3 SFINAE：替换失败不是错误

在**重载解析的模板实参替换阶段**，把无效类型代入签名失败只会让该候选退出重载集，而不是编译错误：

```cpp
#include <iostream>
#include <type_traits>

// #1：仅当 T 为整数类型时，这个签名才有效（enable_if_t 在替换失败时被移除）
template <typename T,
          std::enable_if_t<std::is_integral_v<T>, int> = 0>
void describe(T) { std::cout << "整数\n"; }

// #2：仅当 T 为浮点类型时有效
template <typename T,
          std::enable_if_t<std::is_floating_point_v<T>, int> = 0>
void describe(T) { std::cout << "浮点\n"; }

int main() {
    describe(42);      // 选 #1
    describe(3.14);    // 选 #2
    // describe("hi"); // 无可用重载 → 编译错误（不是 SFINAE，是所有候选都被淘汰）
}
```

| SFINAE 要点 | 说明 |
| --- | --- |
| 适用位置 | 模板签名（返回类型、形参类型、默认模板实参）中的"立即上下文"替换 |
| 不适用 | 函数**体内**写错不是 SFINAE，是硬错误 |
| 工具 | `std::enable_if` / `enable_if_t`、返回类型上的 `decltype(...)`、`void_t` 惯用法 |
| 现状 | C++20 Concepts 出现后，新代码应优先 Concepts（见第 8 节） |

## 6. 可变参数模板（C++11）

### 6.1 参数包与展开

| 语法 | 含义 |
| --- | --- |
| `typename... Args` | 声明模板参数包 |
| `const Args&... args` | 声明函数参数包 |
| `args...` | 把包展开为逗号分隔的实参列表 |
| `sizeof...(args)` | 包中元素个数（编译期常量） |

### 6.2 递归展开（C++11）与折叠表达式（C++17）

```cpp
#include <iostream>

// C++11：递归展开 + 终止重载
void print() { std::cout << '\n'; }                      // 终止条件
template <typename T, typename... Rest>
void print(const T& first, const Rest&... rest) {
    std::cout << first << ' ';
    print(rest...);                                      // 每层剥掉一个参数
}

// C++17：折叠表达式，一行搞定
template <typename... Args>
void print2(const Args&... args) {
    ((std::cout << args << ' '), ...);                   // 一元右折叠
    std::cout << '\n';
}
```

四种折叠形式（C++17）：

| 形式 | 名称 | 展开为（E1..EN） |
| --- | --- | --- |
| `(pack op ...)` | 一元右折叠 | `E1 op (E2 op (... op EN))` |
| `(... op pack)` | 一元左折叠 | `((E1 op E2) op ...) op EN` |
| `(pack op ... op init)` | 二元右折叠 | `E1 op (E2 op (... op (EN op init)))` |
| `(init op ... op pack)` | 二元左折叠 | `(((init op E1) op E2) op ...) op EN` |

> 空包规则：一元折叠仅 `&&`（得 `true`）、`||`（得 `false`）、`,`（得 `void()`）合法；其他运算符空包是编译错误。给求和写 `(args + ... + 0)` 正是为了空包时有初值。

### 6.3 安全打印与完美转发任意参数

```cpp
#include <cstdio>
#include <utility>

// printf 风格安全打印：类型由编译器检查，参数个数由模板包约束
template <typename... Args>
void log_line(const char* fmt, Args&&... args) {
    std::printf(fmt, std::forward<Args>(args)...);   // 完美转发所有参数
    std::putchar('\n');
}
```

## 7. 完美转发

### 7.1 转发引用 vs 右值引用

| 写法 | 身份 | 推导行为 |
| --- | --- | --- |
| `void f(Widget&& w)`（具体类型） | **右值引用** | 只能绑定 Widget 右值 |
| `template<class T> void f(T&& x)` | **转发引用** | 左值 → `T=Widget&`；右值 → `T=Widget` |
| `auto&& x = expr;` | 转发引用 | 同上（auto 推导） |
| `template<class T> void f(std::vector<T>&& v)` | 右值引用 | `vector<T>` 是具体类型，非转发引用 |
| `const T&&` | 右值引用（加了 const 不再转发） | 只能绑定右值 |

### 7.2 引用折叠规则

| 组合 | 结果 |
| --- | --- |
| `X& &` | `X&` |
| `X& &&` | `X&` |
| `X&& &` | `X&` |
| `X&& &&` | `X&&` |

口诀：**出现左值引用就折叠成左值引用；只有右值+右值才是右值引用**。

### 7.3 std::forward 原理与工厂示例

```cpp
// std::forward 的核心（简化）：利用 T&& 的折叠把值类别还原回去
template <typename T>
constexpr T&& forward(std::remove_reference_t<T>& t) noexcept {
    return static_cast<T&&>(t);
}
// T = Widget&  时：static_cast<Widget&> → 返回左值引用
// T = Widget   时：static_cast<Widget&&> → 返回右值引用
```

```cpp
#include <memory>
#include <string>

// make_unique 风格工厂：Args&&... 保住实参的值类别
template <typename T, typename... Args>
std::unique_ptr<T> make(Args&&... args) {
    return std::unique_ptr<T>(new T(std::forward<Args>(args)...));
}

struct Msg {
    Msg(const std::string& s, int n);   // #1
    Msg(std::string&& s, int n);        // #2
};
auto m = make<Msg>("hello", 1);         // "hello" 是右值 → 走 #2，避免多余拷贝
```

| 转发写法 | 结果 |
| --- | --- |
| 直接 `f(args...)` | 全部变左值，丢失移动机会 |
| `f(std::move(args)...)` | 全部变右值，左值被错误掏空 |
| `f(std::forward<Args>(args)...)` | **值类别原样保留**（正确做法） |

## 8. C++20 Concepts（现代首选）

### 8.1 定义与两种 requires

```cpp
#include <concepts>

// concept 定义：requires 表达式产出 bool
template <typename T>
concept Addable = requires(T a, T b) {
    a + b;                        // 要求表达式合法
    { a + b } -> std::convertible_to<T>;   // 要求结果可转换为 T
};

// 用法一：requires 子句（约束整个模板）
template <typename T> requires Addable<T>
T sum(T a, T b) { return a + b; }

// 用法二：直接约束模板参数
template <Addable T>
T sum2(T a, T b) { return a + b; }

// 用法三：约束 auto 参数（简写）
Addable auto sum3(Addable auto a, Addable auto b) { return a + b; }
```

| 语法 | 位置 | 作用 |
| --- | --- | --- |
| requires **表达式** `requires (形参) { 要求; }` | 可出现在任何常量表达式处 | 描述"满足什么条件"，求值为 bool |
| requires **子句** `template<class T> requires C<T>` | 紧跟模板形参列表或函数声明后 | 把概念挂到模板上参与重载决策 |
| 约定型形参 `template<C T>` | 模板形参处 | 最简洁的写法 |

### 8.2 比 SFINAE 的优势

| 维度 | SFINAE（enable_if） | Concepts（C++20） |
| --- | --- | --- |
| 报错信息 | 几十行模板实例化堆栈 | 一行：`constraints not satisfied: Addable<X>` |
| 约束组合 | 嵌套 enable_if，难以阅读 | `requires A<T> && B<T>` 直接逻辑组合 |
| 约束 auto 参数 | 做不到 | `Sortable auto x` 直接可用 |
| 重载排序 | 需要手工制造"更特化" | 约束之间可比较包含关系，自动选更受约束者 |
| 意图表达 | 隐藏在签名细节里 | 概念有名字、可复用、可文档化 |

### 8.3 常用标准库 concepts（`<concepts>`）

| 概念 | 要求 | 典型用途 |
| --- | --- | --- |
| `std::integral` / `std::floating_point` | 整型 / 浮点 | 数值算法分流 |
| `std::same_as<T, U>` | 同一类型 | 精确类型约束 |
| `std::convertible_to<F, T>` | 可转换 | 接口收窄 |
| `std::equality_comparable` / `std::totally_ordered` | `==` / `<` 全套 | 容器、排序 |
| `std::invocable<F, Args...>` | 可调用 | 回调/任务参数 |
| `std::default_initializable` / `std::movable` / `std::copyable` | 对应语义 | 容器元素约束 |
| `std::regular` / `std::semiregular` | 值语义全家桶 | 通用容器元素 |

## 9. CRTP（奇异递归模板模式）

```cpp
#include <cstddef>

// 基类以"派生类自身"为模板参数：编译期就知道最终类型
template <typename Derived>
struct Shape {
    double area() const {                       // 静态多态：无 vptr、可内联
        return static_cast<const Derived&>(*this).area_impl();
    }
};

struct Circle : Shape<Circle> {
    explicit Circle(double r) : r_(r) {}
    double area_impl() const { return 3.14159265358979 * r_ * r_; }
private:
    double r_;
};

Circle c{2};
c.area();        // 直接调用（编译期绑定），内联后常量传播可算成编译期结果
```

计数器 mixin（另一种典型用法）：

```cpp
template <typename T>
class Counter {
public:
    Counter() { ++count_; }
    ~Counter() { --count_; }
    static std::size_t count() { return count_; }
private:
    inline static std::size_t count_ = 0;   // C++17 inline 变量：每个 T 一份
};

struct Widget : Counter<Widget> {};
```

CRTP 与虚函数对比：

| 维度 | 虚函数 | CRTP |
| --- | --- | --- |
| 分发方式 | 运行期 vtable | 编译期 static_cast |
| 每对象开销 | vptr（8 字节） | 无 |
| 可内联 | 基本不可 | 可以 |
| 类型何时确定 | 运行期 | 编译期（不能装进统一容器做异构多态，除非再包一层） |
| 代码体积 | 每类一份 vtable+函数 | 每个派生类实例化一份基类代码（**代码膨胀**） |
| 与第三方类型协作 | 直接继承即可 | 需要侵入式修改类型定义 |

C++23 的显式对象形参（deducing this）可少写一层 CRTP：

```cpp
struct Shape2 {
    template <typename Self>                  // C++23：Self 由编译器推导为最终类型
    double area(this const Self& self) { return self.area_impl(); }
};
```

## 10. 模板元编程入门

### 10.1 编译期计算：constexpr vs 模板特化

```cpp
// C++14 起：constexpr 函数写法（推荐）
constexpr unsigned long long fact(unsigned n) {
    unsigned long long r = 1;
    for (unsigned i = 2; i <= n; ++i) r *= i;   // C++14 起允许循环与局部变量
    return r;
}
static_assert(fact(10) == 3628800ULL);          // 编译期验证

// 传统 TMP 写法：模板递归 + 特化终止（了解即可）
template <unsigned N> struct Fact {
    static constexpr unsigned long long value = N * Fact<N - 1>::value;
};
template <> struct Fact<0> {
    static constexpr unsigned long long value = 1;
};
static_assert(Fact<10>::value == 3628800ULL);
```

演进趋势表：

| 时代 | 手段 | 状态 |
| --- | --- | --- |
| C++98/03 | 模板特化 + 枚举递归 | 已淘汰，仅读旧代码需要 |
| C++11 | `constexpr` 函数（单 return） | 可用但受限 |
| C++14/17 | constexpr 放开循环/分支；`if constexpr` | 大部分编译期计算的首选 |
| C++20 | `consteval`（强制编译期）、concepts | 现代写法 |
| 持续 | 类型运算仍靠 traits/特化 | `remove_reference` 等仍是特化实现 |

### 10.2 常用 type traits 清单（`<type_traits>`）

| Trait | 作用 | 备注 |
| --- | --- | --- |
| `std::is_same<A, B>` | 类型是否相同 | 注意顶层 const/引用 |
| `std::is_pointer<T>` / `is_integral` / `is_class` | 类型分类 | 均有 `_v` 变量模板（C++14） |
| `std::remove_reference<T>::type` | 去引用 | C++14 起 `remove_reference_t` |
| `std::remove_const` / `decay` | 去 const / 模拟按值传参的退化 | `decay` = 去引用+顶层 const+数组函数退化 |
| `std::conditional<B, T, F>::type` | 编译期三元 | 选类型 |
| `std::enable_if<B, T>` | 条件启用签名 | SFINAE 主力 |
| `std::is_constructible<T, Args...>` | 可否构造 | 接口约束 |
| `std::invoke_result<F, Args...>` | 调用返回类型 | 替代 `result_of`（已废弃） |

## 11. 工程实践

### 11.1 模板为什么必须放头文件

| 原因 | 说明 |
| --- | --- |
| 隐式实例化 | 调用方需要看到完整定义才能生成 `max<int>` 的代码；只给声明会链接错误（undefined reference） |
| 两阶段查找 | 第一阶段（定义时）检查不依赖模板参数的名字；第二阶段（实例化时）才检查依赖名字。定义不可见时依赖名字无法解析 |
| 例外 | 可在 .cpp 中**显式实例化**（`template class Stack<int>;`）供其他翻译单元链接 |

```cpp
// stack.h：模板定义必须在这里
template <typename T> class Stack { /* 全部实现 */ };

// stack.cpp：为常用类型显式实例化，别的文件只链接不重复生成
#include "stack.h"
template class Stack<int>;
template class Stack<double>;
```

`extern template`（C++11）用于抑制隐式实例化、加快编译：

```cpp
#include "stack.h"
extern template class Stack<int>;   // 声明"别处已实例化"，本文件不再生成
Stack<int> s;                       // 链接到 stack.cpp 里的那份
```

### 11.2 报错信息阅读与编译建议

| 技巧 | 说明 |
| --- | --- |
| 从最内层看起 | 模板错误通常先打印一大串实例化历史，**最底部的 error 才是真正原因** |
| `static_assert` 前置 | 在模板开头 `static_assert(concept_v<T>, "T 必须支持 operator<")`，把 50 行报错变 1 行中文提示 |
| 用 Concepts | C++20 起 constraints 的报错直接指名概念 |
| 只编译不链接 | `g++ -fsyntax-only -std=c++20 a.cpp` 快速验证语法（衔接《../06-构建与版本控制/01-构建工具GCC与CMake.md》） |
| 阅读工具 | `clang++ -frewrite-instances` 或 STLFilt 可简化报错；gdb 里 `ptype` 查看实例化后的真实类型 |

### 11.3 代码膨胀与编译时间控制

| 手段 | 效果 |
| --- | --- |
| 类型擦除（`std::function`、`void*` + 函数指针封装） | 一份代码服务所有类型，代价是间接调用 |
| 公共非模板基类 | 模板派生类把不变部分上提到非模板基类 |
| `extern template` 显式管理实例化点 | 减少重复实例化 |
| 减少头文件里的重模板（`<iostream>` 换 `<cstdio>`） | 显著缩短编译时间 |
| 概念/约束失败早暴露 | 避免深递归实例化到很晚才炸 |

## 12. 快速参考卡片

按"我想约束/实现 XX"组织：

| 我想…… | 用什么 |
| --- | --- |
| 约束模板参数（C++20） | `template<Addable T>` 或 `requires` 子句 |
| 约束 auto 参数 | `Sortable auto x` |
| 编译期判断类型 | `<type_traits>`：`is_integral_v<T>` 等 |
| 编译期改类型 | `remove_reference_t` / `decay_t` / `conditional_t` |
| 按类型选择重载（C++17） | `if constexpr (std::is_integral_v<T>) {...} else {...}` |
| 按类型选择重载（C++11） | `enable_if_t` SFINAE |
| 接收任意数量参数 | `template<class... Args> f(Args&&... args)` |
| 保持实参值类别转发 | `std::forward<Args>(args)...` |
| 编译期计算 | `constexpr` 函数（强制编译期用 `consteval`，C++20） |
| 静态多态（免 vtable） | CRTP（C++23 可用 deducing this） |
| 对不同类型给不同实现 | 偏特化（类）/ 重载（函数，函数模板不能偏特化） |
| 看实例化后的类型 | gdb `ptype` / 报错信息最内层 |

折叠与转发速记：

| 需求 | 写法 |
| --- | --- |
| 对所有参数求和（允许空包） | `(args + ... + 0)` |
| 逐个执行调用 | `(f(args), ...)` |
| 全部满足返回 true | `(pred(args) && ...)` |
| 转发参数包 | `target(std::forward<Args>(args)...)` |

## 13. 常见问题与坑

| 问题 | 原因与解决方案 |
| --- | --- |
| 模板声明放头文件、定义放 .cpp，链接报 undefined reference | 实例化点看不到定义。解决：定义放头文件；或 .cpp 里显式实例化用到的类型 |
| 把模板里的 `T&&` 当成右值引用，左值传进去被当成右值掏空 | 模板推导中的 `T&&` 是**转发引用**，左值使 `T=U&`。解决：配 `std::forward<T>` 转发 |
| 想偏特化函数模板发现不生效 | 函数模板不支持偏特化。解决：改用重载；或委托给可偏特化的类模板 |
| 全特化与重载并存时选了"没想到的那个" | 全特化不参与重载解析：先按主模板+重载选函数，再看有无匹配全特化。解决：能用重载就别写全特化（`std::swap` 惯用法同理） |
| 访问模板基类的成员编译报"未声明" | 两阶段查找：依赖基类的名字默认不去基类里找。解决：写 `this->member` 或 `using Base<T>::member;` |
| 依赖类型前忘写 `typename` 报一堆错 | `Base<T>::iterator` 在实例化前不知道是类型。解决：`typename Base<T>::iterator`；C++20 起多数场景可省 |
| 空包时 `args + ...` 编译失败 | 一元折叠仅 `&&`/`||`/`,` 允许空包。解决：二元折叠给初值 `(args + ... + 0)` |
| `sizeof` 模板传值形参得到 8 而不是数组长度 | 传值导致数组退化为指针。解决：形参改 `T&` 或 `const T&`（不退化） |
| `std::forward` 忘写 `()` 后的模板实参 | `std::forward(args)` 推导 `T` 为左值，转发退化。解决：必须 `std::forward<Args>(args)...` 显式给 T |
| CTAD 对聚合类不生效 | C++17 聚合没有隐式推导指引。解决：手写推导指引 `Box() -> Box<T>` 或升级 C++20 |
| 特化与主模板声明在不同头文件/命名空间 | 全特化必须与主模板同命名空间。解决：特化写在主模板所在命名空间 |
| 模板代码编译极慢 | 深度实例化+热门头文件。解决：extern template、前置声明、`<iosfwd>`、把重头模板隔离到单独 TU |
