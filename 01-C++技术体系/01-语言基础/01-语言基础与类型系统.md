## 1. 概述

C++ 是一门多范式语言：既可以像 C 一样面向过程贴近硬件，也支持面向对象、泛型编程和函数式风格。它的两条设计哲学贯穿始终：

1. **零开销抽象**：不为你没使用的特性付出运行时代价。
2. **直接映射硬件**：类型大小、内存布局、指针运算都贴近机器模型。

因此，理解类型系统是理解一切 C++ 高级特性的前提。同时 C++ 又是一门"活的语言"，每 3 年更新一次标准，很多概念必须标注"它是哪个标准引入的"——本文所有特性都会标注版本。

### 1.1 C++ 标准版本时间线

| 标准 | 发布年份 | 里程碑特性 | 定位 |
|---|---|---|---|
| C++98 | 1998 | STL、模板、异常、RTTI、string/stream、locale | 第一版正式标准 |
| C++03 | 2003 | 值初始化语义澄清、缺陷修订 | 维护性小版本 |
| C++11 | 2011 | auto、lambda、右值引用/移动语义、智能指针、constexpr、范围 for、线程库、nullptr、enum class | "Modern C++" 起点 |
| C++14 | 2014 | 泛型 lambda、返回类型推导、make_unique、变量模板 | 对 11 的补全 |
| C++17 | 2017 | 结构化绑定、if constexpr、optional/variant/string_view、并行算法 | 实用性大增 |

| 维度 | C | C++ |

## 2. 基本内置类型

### 2.1 类型大小与取值范围

**关键认知：标准只保证"最小大小"和大小关系，实际大小由平台（编译器 + ABI）决定。**

| 类型 | 标准保证 | 典型大小（64 位平台） | 典型范围/精度 | 备注 |
|---|---|---|---|---|
| `bool` | — | 1 字节 | true / false | 大小由实现定义，通常是 1 |
| `char` | 1 字节（≥8 位） | 1 字节 | 字符 / -128~127 或 0~255 | **符号性由实现定义**！ |
| `signed char` | 1 字节 | 1 字节 | -128 ~ 127 | 显式有符号 |
| `unsigned char` | 1 字节 | 1 字节 | 0 ~ 255 | 处理原始字节首选 |
| `short` | ≥16 位 | 2 字节 | -32768 ~ 32767 | |
| `unsigned short` | ≥16 位 | 2 字节 | 0 ~ 65535 | |
| `int` | ≥16 位 | 4 字节 | 约 ±21.4 亿 | 16 位 MCU 上只有 2 字节！ |
| `unsigned int` | ≥16 位 | 4 字节 | 0 ~ 4294967295 | |
| `long` | ≥32 位 | Linux: 8 / Win: 4 | — | **跨平台最著名的坑** |
| `long long` (C++11) | ≥64 位 | 8 字节 | 约 ±9.2×10^18 | |
| `float` | — | 4 字节 | IEEE 754，约 7 位有效数字 | |
| `double` | — | 8 字节 | 约 15~16 位有效数字 | |
| `long double` | — | Linux: 16 / MSVC: 8 | x87 扩展精度（视实现而定） | Windows 上与 double 相同 |
| `void` | — | 无大小 | — | 不能 `sizeof(void)` |

大小关系链（标准保证）：`sizeof(char) ≤ sizeof(short) ≤ sizeof(int) ≤ sizeof(long) ≤ sizeof(long long)`。

### 2.2 数据模型：LP64 与 LLP64 —— 跨平台第一坑

同样是"64 位平台"，Linux/macOS 用 **LP64**（long 和指针都是 64 位），Windows 用 **LLP64**（long long 和指针是 64 位，long 仍是 32 位）。

| 类型 | Linux/macOS 64 位（LP64） | Windows 64 位（LLP64） | 32 位平台（ILP32） |
|---|---|---|---|
| `char` / `short` / `int` | 1 / 2 / 4 | 1 / 2 / 4 | 1 / 2 / 4 |
| `long` | **8** | **4** | 4 |
| `long long` | 8 | 8 | 8（C++11） |
| 指针 | 8 | 8 | 4 |

```cpp
// 经典移植性 bug：在 Windows 上 long 只有 32 位
long timestamp_ms = 1735689600123;   // Windows: 溢出/截断（值 > 21 亿）
// 正确做法：跨平台的"精确宽度"整数一律用 <cstdint>
std::int64_t timestamp_ms = 1735689600123;   // 所有平台 8 字节
```

**结论：涉及宽度敏感的代码（协议、文件格式、序列化）永远用固定宽度类型；`long` 只在 POSIX API 边界使用。**

### 2.3 `<cstdint>` 固定宽度类型（C++11）

| 类型组 | 示例 | 含义 | 使用场景 |
|---|---|---|---|
| 精确宽度 | `std::int32_t` / `std::uint64_t` | 恰好 N 位 | 协议、序列化（若平台支持则必有） |
| 最快类型 | `std::int_fast32_t` | 至少 N 位且对该平台最快 | 循环计数（嵌入式常用） |
| 最小类型 | `std::int_least16_t` | 至少 N 位且最小 | 内存极度受限 |
| 指针宽度 | `std::intptr_t` / `std::uintptr_t` | 能装下指针的整数 | 指针 ↔ 整数转换 |
| 最大类型 | `std::intmax_t` | 平台最大整数 | 通用极值 |

```cpp
#include <cstdint>

std::uint32_t crc = 0xDEADBEEFu;   // 无歧义
std::int64_t  ns   = 1'000'000'000; // C++14 数字分隔符
```

### 2.4 sizeof 的规则

| 规则 | 说明 |
|---|---|
| `sizeof(char)` 恒为 1 | 以字节为单位的最小单位 |
| 操作数不求值 | `sizeof(f())` 不会调用 f（可放心用于未初始化对象） |
| 结果类型是 `size_t` | 无符号整数，打印用 `%zu` |
| 引用 | `sizeof(引用)` = 被引用类型的大小 |
| 数组 | `sizeof(数组名)` = 全部字节数（仅在数组所在作用域成立） |
| 函数参数数组 | 传参后退化成指针，`sizeof` = 指针大小 |
| 空类 | `sizeof(空类) == 1`（保证不同对象地址不同；含虚函数则至少多一个 vptr） |
| 位域/不完整类型/函数类型 | 不能 `sizeof`，编译错误 |

```cpp
int arr[10];
sizeof(arr);                    // 40：整个数组
sizeof(arr) / sizeof(arr[0]);   // 10：经典元素个数写法

void f(int a[10]);              // 语法糖，实际是 void f(int* a)
// 函数内 sizeof(a) == 8（64 位平台）

// 模板里数组不退化（引用/数组形参保留长度信息）
template <typename T, size_t N>
constexpr size_t len(T (&)[N]) { return N; }   // C++17 起可直接 std::size(arr)
```

### 2.5 字面量与后缀

| 后缀/前缀 | 含义 | 示例 | 引入版本 |
|---|---|---|---|
| `u` / `U` | unsigned | `42u` | C++98 |
| `l` / `L` | long | `42L` | C++98 |
| `ll` / `LL` | long long | `42LL` | C++11 |
| 组合 | 无符号长整型 | `42ULL`、`0xFFuLL` | C++11 |
| `f` / `F` | float | `3.14f` | C++98 |
| 无后缀小数 | double | `3.14` | — |
| `l` / `L`（浮点） | long double | `3.14L` | C++98 |
| `0x` / `0X` | 十六进制 | `0xFF` | C++98 |
| `0` 前缀 | 八进制 | `010` == 8 | C（易踩坑） |
| `0b` / `0B` | 二进制 | `0b1010` | C++14 |
| `'` 分隔符 | 数字分隔 | `1'000'000` | C++14 |
| `""s` | std::string 字面量 | `"abc"s` | C++14 |
| `""sv` | std::string_view 字面量 | `"abc"sv` | C++17 |
| `u8"..."` | UTF-8 字符串 | `u8"你好"` | C++11（C++20 起类型为 char8_t） |

## 3. const 家族

### 3.1 const 变量与 const 指针

`const` 表示"运行期只读承诺"：被修饰的对象不能通过该名字修改，但值可以在运行期才确定。

```cpp
const int size = getSize();   // OK：运行期才确定，之后只读
int arr[size];                // 错误！不是常量表达式（C 里 VLA 不存在于标准 C++）

const int* p1;                // 指向 const int 的指针：指向物只读
int* const p2 = nullptr;      // 指向 int 的 const 指针：指针本身只读
```

### 3.2 顶层 const 与底层 const（必考）

| 术语 | 含义 | 判别方法 |
|---|---|---|
| 顶层 const（top-level） | 对象**本身**是 const | const 修饰"最外层对象" |
| 底层 const（low-level） | 指针/引用**指向的对象**是 const | const 出现在 `*` 左侧 |

**判别口诀：`*` 右边的 const 修饰指针本身（顶层），`*` 左边的 const 修饰指向物（底层）。**

```cpp
int v = 0, w = 0;

const int* p1 = &v;       // 底层 const：不能通过 p1 改 v
int* const p2 = &v;       // 顶层 const：p2 不能再指向别处
const int* const p3 = &v; // 顶层 + 底层都有

p1 = &w;                  // OK：p1 本身可变
// *p1 = 1;               // 错误：指向物只读
// p2 = &w;               // 错误：p2 本身只读
*p2 = 1;                  // OK：指向物可写

int* p4 = p1;             // 错误：拷贝时不能丢弃底层 const
const int* p5 = p2;       // OK：增加底层 const 没问题
```

**拷贝规则：顶层 const 在拷贝时被忽略；底层 const 必须两边兼容。**

### 3.3 constexpr（C++11）：编译期常量

`const` 是"运行期只读"，`constexpr` 是"编译期可知"。两者的本质区别：

| | const | constexpr |
|---|---|---|
| 语义 | 运行期只读 | 编译期常量表达式 |
| 能否用于数组大小/模板实参 | 不能（除非恰好是编译期值） | 能 |
| 函数能否用 | 修饰成员函数（this 为 const） | 修饰函数使其可用于常量表达式 |

```cpp
constexpr int kSize = 100;        // 编译期常量
int arr[kSize];                   // OK

// constexpr 函数的演进：
// C++11：函数体只允许一条 return（但允许递归）
constexpr int factorial(int n) { return n <= 1 ? 1 : n * factorial(n - 1); }

// C++14：允许循环、局部变量、多语句
constexpr int fact2(int n) {
    int r = 1;
    for (int i = 2; i <= n; ++i) r *= i;
    return r;
}
static_assert(factorial(5) == 120, "编译期即验证");

// 注意：constexpr 函数传运行期参数时，退化为普通函数照常在运行期执行
int x; std::cin >> x;
int y = fact2(x);                 // OK：运行期调用
```

### 3.4 consteval 与 constinit（C++20）

| 关键字 | 版本 | 语义 | 与 constexpr 的区别 |
|---|---|---|---|
| `consteval` | C++20 | 立即函数：**每次调用必须**在编译期完成，否则编译错误 | constexpr 允许运行期调用，consteval 不允许 |
| `constinit` | C++20 | 保证静态/线程存储期对象**静态初始化**（编译期完成初始化），但对象本身**不是 const** | constexpr 变量不可改，constinit 变量可改 |

```cpp
consteval int square(int n) { return n * n; }
constexpr int a = square(5);     // OK：编译期求值
int x = std::cin.get();
// int b = square(x);            // 错误：x 不是常量表达式

constinit int cfg = computeDefault();  // 若 computeDefault 不能常量求值则报错
cfg = 42;                              // OK：之后可以修改
```

`constinit` 的价值：杜绝"静态初始化顺序惨案"（不同编译单元全局对象的初始化顺序未定义）。

### 3.5 const 家族对比总表

| 关键字/用法 | 版本 | 语义 | 典型用途 |
|---|---|---|---|
| `const T x` | C++98 | 运行期只读 | 接口参数 `const std::string&` |
| `const T* / T* const` | C++98 | 底层/顶层 const | C API 交互 |
| `constexpr T x` | C++11 | 编译期常量 | 数组大小、模板实参、static_assert |
| `constexpr` 函数 | C++11/14 | 可用于常量表达式 | 数学常量、查表 |
| `consteval` | C++20 | 强制编译期调用 | 编译期校验、编译期生成数据 |
| `constinit` | C++20 | 强制静态初始化、可变 | 全局配置、消除初始化顺序问题 |

## 4. 指针与引用

### 4.1 基本用法

```cpp
int x = 10;
int& rx = x;      // 引用：rx 是 x 的别名
rx = 20;          // 修改的就是 x 本体
int* p = &x;      // 指针：p 存储 x 的地址
*p = 30;          // 通过地址间接修改

int y = 5;
p = &y;           // 指针可以重绑定（改指别人）
rx = y;           // 注意！这不是重绑定，而是"把 y 的值赋给 x"
```

### 4.2 全面对比表

| 维度 | 指针 `T*` | 引用 `T&` |
|---|---|---|
| 能否为空 | 可以（NULL/nullptr） | 语言规则不允许（不得绑定到空） |
| 能否重绑定（改指向） | 可以 | **不能**，一生只绑定一次 |
| 初始化要求 | 可以不初始化（危险） | **必须**在声明时初始化 |
| sizeof 结果 | 指针本身大小（4/8 字节） | 被引用对象的大小 |
| 多级支持 | `int**` 合法 | 无"引用的引用"、无"指向引用的指针"（语法禁止） |
| 指针算术 | `p + 1` 合法 | 不存在引用算术 |
| 使用形式 | `*p`、`p->` | 直接当对象用 |
| 数组支持 | 指针数组、数组指针都合法 | 引用数组非法（`int& a[3]` 编译错） |
| 可测试性 | `if (p)` 常见 | 无判空一说（空引用即 UB） |
| 典型场景 | 可能缺省、需要重指、C 接口、数据结构链 | 函数参数、返回值、range-for、运算符重载 |

### 4.3 引用的本质

- 语义上：引用就是**别名**，标准从不要求它占用存储。
- 实现上：主流编译器通常把引用实现为"自动解引用的常量指针"（视实现而定），作为类成员时通常占用一个指针大小。
- 证据：`sizeof(rx) == sizeof(int)`；`&rx` 取到的是 `&x`，无法取得"引用自身的地址"。

```cpp
int i = 0;
int& r = i;
static_assert(sizeof(r) == sizeof(int));   // 引用的大小 = 被引类型
// &r 与 &i 相同；不存在"引用的地址"这一概念
```

**一个重要推论**：函数返回 `T&` 比返回 `T*` 表达了更强的契约——"我保证返回一个有效对象"。标准库容器 `operator[]` 返回引用正是如此。

### 4.4 右值引用简述（C++11）

```cpp
int&& rr = 42;          // 右值引用：只能绑定右值（临时值、字面量）
const int& cr = 42;     // const 左值引用：也能绑定右值（历史遗留方案，延长临时生命周期）
```

右值引用是移动语义与完美转发的基石，完整讨论见《06-现代C++新特性.md》第 3 章。本篇只需记住：`T&&` 是为"可以掏空的对象（将亡值）"准备的。

## 5. 类型转换

### 5.1 C 风格转换的问题

```cpp
Derived* d = (Derived*)basePtr;   // 这一行到底干了什么？
```

C 风格转换 `(T)expr` 会**依次尝试**以下组合，取第一个可行的：`const_cast` → `static_cast` → `static_cast + const_cast` → `reinterpret_cast` → `reinterpret_cast + const_cast`。问题：

1. 它可能悄悄退化成最危险的 `reinterpret_cast`（例如基类指针转不相关类型）。
2. 它可能悄悄丢掉 const（写 `const char*` → `char*` 编译器一声不吭）。
3. 无法被 grep 检索（`(int)` 与括号表达式无法区分），代码评审困难。

**结论：C++ 代码中禁用 C 风格转换，四种命名 cast 让转换意图显式化。**

### 5.2 四种 cast 对比表

| 转换 | 用途 | 安全性 | 运行时开销 | 典型场景 |
|---|---|---|---|---|
| `static_cast` | 数值转换、相关类型（有/无符号、上下行转换、显式调用转换构造） | 无运行时检查，下行转换（基→派生）不安全 | 无 | `double→int`、`void*→T*`、`enum→int` |
| `dynamic_cast` | 多态类型的安全下行/侧向转换 | 有 RTTI 检查，失败有明确信号 | **有**（查询 RTTI、字符串比较类名，视实现而定） | 基类指针 → 派生类指针 |
| `const_cast` | 增/删 const、volatile | 修改"真 const 对象"是 UB | 无 | 与老 C API 交互（接口没标 const） |
| `reinterpret_cast` | 位模式重新解释 | 极不安全，违反严格别名即 UB | 无 | 指针↔整数、查看位模式（配合 memcpy） |

### 5.3 各 cast 示例

```cpp
// static_cast：相关类型的显式转换
double d = 3.9;
int i = static_cast<int>(d);              // 3：截断，意图明确
void* vp = &i;
int* ip = static_cast<int*>(vp);          // void* 必须显式转回（C++ 与 C 的差异！）

// dynamic_cast：需要基类至少有一个虚函数（多态类型）
struct Base { virtual ~Base() = default; };
struct Derived : Base { void hello() {} };

void f(Base* b) {
    if (Derived* d = dynamic_cast<Derived*>(b)) {   // 失败返回 nullptr
        d->hello();
    }
}
void g(Base& b) {
    try {
        Derived& d = dynamic_cast<Derived&>(b);     // 引用形式失败抛 std::bad_cast
        d.hello();
    } catch (const std::bad_cast&) { /* 处理 */ }
}

// const_cast：与 C API 交互
void legacyPrint(char* s);                      // 老接口，忘了写 const
std::string msg = "hi";
legacyPrint(const_cast<char*>(msg.c_str()));    // 只有确认函数不改内容才安全
// 注意：对"定义为 const 的对象"去掉 const 再写入 → UB

// reinterpret_cast：看 float 的位模式（必须绕道 memcpy，不能直接解引用）
float f = 1.0f;
std::uint32_t bits;
std::memcpy(&bits, &f, sizeof bits);            // 正确：类型双关的合法方式
// int wrong = *reinterpret_cast<int*>(&f);     // UB：违反严格别名规则
```

### 5.4 隐式转换与整型提升（编译器默默干的危险事）

| 隐式行为 | 规则 | 风险 |
|---|---|---|
| 整型提升 | `char`/`short` 先提升为 `int` 再运算 | `char + char` 结果是 int |
| 有符号↔无符号混算 | **两侧都转成无符号** | `-1 < 1u` 为 **false**！ |
| 整型→浮点 | 小整数精确，大整数丢精度 | `int → float` 可能失真 |
| 浮点→整型 | 截断小数；超出范围是 **UB** | `(int)1e100` 崩溃 |
| 数组→指针 | 传参时退化 | sizeof 变了、丢失长度 |
| bool 转换 | 任何指针/数值可转 bool | if (n = 0) 手滑赋值 |

```cpp
// 有符号/无符号陷阱的完整推演
std::vector<int> v;
for (int i = 0; i < v.size() - 1; ++i) {}   // v 为空时：0-1 = -1 → 转 size_t 巨大值 → 越界！
for (std::size_t i = 0; i + 1 < v.size(); ++i) {}   // 正确写法
```

## 6. auto 与 decltype 类型推导

### 6.1 auto 推导规则

`auto` 的推导规则与函数模板按值传参完全一致：**丢弃引用、丢弃顶层 const，保留底层 const**。

```cpp
int i = 0;
const int ci = i;
const int& cri = i;

auto a = i;      // int
auto b = ci;     // int！顶层 const 被丢弃
auto c = cri;    // int！引用与 const 都被丢弃（发生一次拷贝）
const auto d = ci;      // const int：需要时显式加回
auto& e = cri;   // const int&：通过引用形式保留了 const
auto* p = &ci;   // const int*：指针的底层 const 保留
```

| 声明形式 | 推导规则 | 适用场景 |
|---|---|---|
| `auto x = e` | 去引用、去顶层 const，得到值拷贝 | 想要副本时 |
| `auto& x = e` | 保留 const，左值引用，需要可绑定左值 | 只读或读写遍历 |
| `const auto& x = e` | const 左值引用，**可绑定临时值** | 大对象只读遍历（避免拷贝） |
| `auto&& x = e` | 万能引用 + 引用折叠：左值→T&，右值→T&& | 泛型代码/范围 for |
| `auto* x = &e` | 指针形式，要求 e 可取地址 | 强调"我在要指针" |

### 6.2 范围 for 的正确姿势

```cpp
std::vector<Widget> v(1000);

for (auto w : v) {}          // 每轮拷贝一个 Widget！性能灾难
for (auto& w : v) {}         // 读写：引用
for (const auto& w : v) {}   // 只读：最常用、最安全
for (auto&& w : v) {}        // 泛型：无论容器返回什么都正确（代理容器必需）
```

### 6.3 decltype 与 `decltype((x))` 的坑

`decltype(实体)` 给出**声明时的类型**；`decltype(表达式)` 按**值类别**推导：左值表达式得 `T&`，纯右值得 `T`。

```cpp
int i = 0;
decltype(i) a;        // int：i 是变量名（实体）
decltype((i)) b = i;  // int&！(i) 是左值表达式 → 加括号就变引用

int&& rr = 42;
decltype(rr) c = 0;    // int&&：按实体的声明类型
decltype((rr)) d = rr; // int&：左值表达式 → 折叠成左值引用
```

**记忆：给 decltype 的变量加不加括号结果不同——`(x)` 是表达式，左值表达式推导出引用。** 这个坑在 `decltype(auto)` 返回值推导中最常见（详见《06-现代C++新特性.md》）。

### 6.4 C++14：auto 返回类型

```cpp
// C++11：尾置返回类型
auto add(int a, int b) -> int { return a + b; }

// C++14：直接 auto，按 return 推导
auto add(int a, int b) { return a + b; }        // int
auto& first(std::vector<int>& v) { return v[0]; }   // int&：正确保留引用

// decltype(auto)：严格按 decltype 规则推导（想要引用时用）
decltype(auto) elem(std::vector<int>& v, size_t i) { return v[i]; }  // int&（operator[] 返回引用）
```

## 7. 作用域与生命周期

### 7.1 四种存储期（storage duration）

| 存储期 | 获得方式 | 生命周期 | 存储位置 |
|---|---|---|---|
| 自动（automatic） | 局部变量、函数参数 | 作用域结束即销毁 | 栈 |
| 静态（static） | 全局变量、`static` 变量、namespace 变量 | 整个程序期间 | .data（已初始化）/ .bss（未初始化） |
| 动态（dynamic） | `new` 表达式 | 直到 `delete` | 堆 |
| 线程（thread） | `thread_local`（C++11） | 所在线程整个生命周期 | 每线程一份，TLS 区 |

```cpp
int g_counter;              // 静态存储期，零初始化（.bss），extern 可见
int g_init = 42;            // 静态存储期（.data）
static int file_local = 1;  // 静态存储期，仅本编译单元可见（内部链接）
thread_local int tls_count; // C++11：每个线程独立副本

void demo() {
    int a;                  // 自动存储期：值未初始化！读取是 UB
    int b{};                // 值初始化为 0：好习惯
    static int calls = 0;   // 静态存储期：函数第一次执行时初始化一次
    ++calls;
}
```

### 7.2 进程内存布局示意

```text
高地址
+---------------------------+
|  命令行参数 / 环境变量       |
+---------------------------+
|  栈 stack                  |  自动存储期，向低地址增长
|  |    ...                 |  （大小受限：Linux 默认 8MB，
|  v    局部变量、函数帧       |   超出即 stack overflow）
|                           |
|  ^    堆 heap              |  new/malloc 分配，向高地址增长
|  |    动态分配的对象         |  （受碎片影响，管理成本高）
+---------------------------+
|  .bss   未初始化静态数据     |  静态存储期，程序加载时清零
|  .data  已初始化静态数据     |  静态存储期，值在可执行文件中
+---------------------------+
|  .rodata 常量与字符串字面量   |  只读，写入段错误
|  .text   机器代码           |  只读+可执行
+---------------------------+
低地址
```

（进程运行时布局可用 `cat /proc/<pid>/maps` 查看，命令见《../08-网络与系统工具/01-Linux命令行速查.md》；段（.text/.data/.bss）的来龙去脉见《../02-系统原理/02-编译链接与加载原理.md》第 4 章；堆区详解见《04-内存管理与智能指针.md》。）

### 7.3 静态局部变量与 magic statics（C++11）

```cpp
Widget& instance() {
    static Widget w;     // C++11 起标准保证：并发首次调用也只初始化一次
    return w;            //      （GCC/Clang 用 guard 变量实现，MSVC 2015+ 同样支持）
}
```

这是"C++11 起局部静态变量初始化线程安全（常称 magic statics）"的标准条款 [stmt.dcl]/4。C++03 时代需要双检锁或 pthread_once——那套代码如今可以全部删掉。该性质也是《08-设计模式与典型实现.md》中 Meyers 单例的基础。

注意两个附带规则：初始化抛异常会向上传播且下次进入会**再次尝试**初始化；析构发生在 main 返回后（与注册顺序相反，详见 atexit 语义）。

## 8. 其他基础要点

### 8.1 enum class（C++11 强类型枚举）

```cpp
enum class Color : std::uint8_t { Red, Green, Blue };   // 可指定底层类型

Color c = Color::Red;
// int n = c;                    // 错误：不隐式转 int（老 enum 会）
int n = static_cast<int>(c);     // 显式转换 OK

enum OldColor { OLD_RED, OLD_GREEN };   // 无作用域枚举（老式）
int x = OLD_RED;                        // 隐式转 int：命名空间污染 + 类型不安全
```

| 优势 | 说明 |
|---|---|
| 作用域 | 枚举名封装在 `Color::` 内，不再污染外层命名空间 |
| 类型安全 | 不隐式转 int，switch 之外的误用编译期拦截 |
| 底层类型可控 | `: std::uint8_t` 精确控制大小（嵌入式协议字段必备） |
| 前置声明友好 | 不指定底层类型也能前向声明（老枚举必须知道大小） |

### 8.2 nullptr（C++11）

```cpp
void f(int);
void f(char*);

f(NULL);      // NULL 是 0（或 0L）→ 调用 f(int)！语义完全错了
f(nullptr);   // nullptr 类型是 std::nullptr_t → 精确调用 f(char*)
```

| 对比 | NULL | nullptr |
|---|---|---|
| 本质 | 宏，整数 0 | 关键字，独立类型 `std::nullptr_t` |
| 重载决议 | 会被当成 int | 只匹配指针/可空类型 |
| 模板推导 | 推导为整数类型 | 推导为 nullptr_t，可转任意指针 |
| C++11 后 | 不要再写 | 唯一正确的空指针写法 |

### 8.3 using 与 typedef

```cpp
typedef std::vector<int> IntVec;          // 老写法
using IntVec2 = std::vector<int>;         // C++11：等价但更清晰（名字在左边）

template <typename T>
using Vec = std::vector<T>;               // 别名模板：typedef 做不到
Vec<int> v;                               // 直接可用

// typedef 想做模板必须借助嵌套 struct 绕路：
template <typename T> struct VecHelper { typedef std::vector<T> type; };
typename VecHelper<int>::type v2;         // 又臭又长
```

### 8.4 初始化方式与 narrowing 检查

```cpp
int a = 3.5;    // 拷贝初始化：OK，隐式截断为 3（多数编译器给告警）
int b(3.5);     // 直接初始化：OK，同样截断
int c{3.5};     // 列表初始化（C++11）：编译错误！narrowing
char d{300};    // 编译错误！300 超出 char 范围（8 位 char 平台）
int e{};        // 值初始化：0（推荐替代 int e; 的未初始化状态）

std::vector<int> v1(3, 1);   // (构造语义)：3 个 1 → {1,1,1}
std::vector<int> v2{3, 1};   // (列表语义)：2 个元素 → {3,1}  ← 注意区分！
```

| 方式 | 语法 | narrowing | 建议 |
|---|---|---|---|
| 拷贝初始化 | `T x = e` | 允许（截断） | 简单变量可用 |
| 直接初始化 | `T x(e)` | 允许 | 调用显式构造函数 |
| 列表初始化 | `T x{e}` | **禁止（编译错误）** | 默认首选：安全、统一 |
| 值初始化 | `T x{}` | — | 防未初始化 |

## 10. 常见问题与坑

| 问题 | 原因与解决方案 |
|---|---|
| 读取未初始化的局部变量结果随机 | 自动存储期内置类型不初始化，读取是 UB。定义即初始化：`int x{};`；开 `-Wuninitialized` + ASan 辅助 |
| `sizeof(数组)` 传进函数后变小 | 数组传参退化成指针。传 `std::span`/`std::array`/vector，或额外传长度 |
| `for (int i=0; i<v.size(); ++i)` 空容器时越界狂奔 | `i` 与无符号 `size_t` 比较，i 被转为无符号，-1 变巨大值。用 `size_t`、范围 for 或 `ssize()`（C++20） |
| `INT_MAX + 1` 变成负数/崩溃 | **有符号整数溢出是 UB**（优化器可能删掉你的检查）。用更大类型、无符号回绕语义或前置判断 |
| 无符号减法得到巨大正数 | 无符号运算按模 2^n 回绕。混用前先想清楚，或用 `-Wsign-conversion` |
| `if (a == 0.1)` 判定失败 | 二进制无法精确表示 0.1。用 `fabs(a-b) < eps`（绝对/相对误差）或整数定点 |
| `const char* s = str;` 编译不过 | `std::string` **没有**到 `const char*` 的隐式转换（只有反向隐式构造）。用 `str.c_str()`，注意返回指针随 str 修改/析构失效 |
| `int arr[n]`（n 是 const 变量）编译错 | const ≠ 常量表达式。用 `constexpr` |
| `dynamic_cast` 编译报"源类型不是多态类型" | 基类没有任何虚函数。至少给基类一个虚析构（多态类型的要求） |
| 对 const 对象去掉 const 后修改崩溃 | 真 const 对象可能位于只读段（.rodata）。const_cast 只用于"对象本身可变但接口签名缺失 const"的场景 |
| `char` 到底有没有符号？ | 由实现定义（ARM/x86 Linux 通常有符号）。明确写 `signed char` / `unsigned char` |
| `sizeof(空类) == 1` 感到奇怪 | 标准保证不同对象地址不同。多个空基类可被优化（EBO，视实现而定） |
