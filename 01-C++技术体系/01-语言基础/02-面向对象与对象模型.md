## 1. 概述

C++ 面向对象的三大支柱：

| 支柱 | 解决的问题 | C++ 语法载体 | 运行期代价 |
| --- | --- | --- | --- |
| 封装 | 隐藏实现，约束访问路径 | `class` + 访问控制符 | 无（纯编译期检查） |
| 继承 | 复用与抽象分类（is-a） | 派生列表 | 可能增加对象体积与间接跳转 |
| 多态 | 同一接口、不同行为 | 虚函数（运行期）；重载/模板（编译期） | vtable 间接调用 |

C++ 的"多态"实际是两套机制，初学者常混为一谈：

| 维度 | 编译期多态（静态） | 运行期多态（动态） |
| --- | --- | --- |
| 机制 | 函数重载、运算符重载、模板 | 虚函数 |
| 绑定时机 | 编译期 | 运行期（按对象实际类型） |
| 性能 | 可内联，接近零开销 | 间接调用，难内联 |
| 灵活性 | 类型编译期必须已知 | 运行期才确定类型也可用 |
| 典型例子 | `max<int>` / `max<double>` | `Shape* p; p->draw();` |

## 2. 类与对象基础

### 2.1 访问控制

| 访问符 | 类内 | 派生类 | 类外 |
| --- | --- | --- | --- |
| `public` | 可访问 | 可访问 | 可访问 |
| `protected` | 可访问 | 可访问 | 不可访问 |
| `private` | 可访问 | 不可访问 | 不可访问 |

三种继承方式下，基类成员在派生类中的可见性变化：

| 基类成员 | `public` 继承 | `protected` 继承 | `private` 继承 |
| --- | --- | --- | --- |
| `public` 成员 | 在派生类中仍是 `public` | 变为 `protected` | 变为 `private` |
| `protected` 成员 | 仍是 `protected` | 仍是 `protected` | 变为 `private` |
| `private` 成员 | 存在但不可直接访问 | 存在但不可直接访问 | 存在但不可直接访问 |
| 语义 | is-a（公开继承才表达"是一种"） | "按实现继承"（少见） | "用……来实现"（等价于组合，优先用组合） |

> 实践准则：99% 的继承都应是 `public` 继承；`private` 继承表达 has-a，能用成员组合就不要用它。

### 2.2 struct 与 class

| 维度 | `struct` | `class` |
| --- | --- | --- |
| 默认成员访问 | `public` | `private` |
| 默认继承方式 | `public` 继承 | `private` 继承 |
| 其余能力 | 完全相同（构造/虚函数/模板……） | 完全相同 |

唯一的默认差异就是上表两条。惯用法：纯数据聚合用 `struct`，有行为和不变量的用 `class`。

### 2.3 友元

| 特性 | 说明 | 示例 |
| --- | --- | --- |
| `friend` 函数 | 授权某个函数访问私有成员 | `friend std::ostream& operator<<(std::ostream&, const X&);` |
| `friend` 类 | 授权整个类访问 | `friend class Builder;` |
| 单向性 | A 声明 B 为友元，B 不自动把 A 当友元 | — |
| 不传递 | 友元的友元不是友元 | — |
| 不继承 | 基类的友元访问不了派生类新增的私有成员；派生类的友元也访问不了基类私有成员 | — |

```cpp
class Matrix {
    friend Matrix operator*(const Matrix& a, const Matrix& b);  // 运算符需要访问内部数据
public:
    // ...
private:
    double data_[4][4];
};
```

## 3. 构造与析构

### 3.1 构造与析构顺序

构造顺序（从外到内）：

```text
构造 D 对象：
  ① 虚基类（按最深、声明序）      D 的构造函数初始化列表开始执行
  ② 直接基类（按派生列表声明序）
  ③ 非静态数据成员（按类内声明序，与初始化列表书写顺序无关！）
  ④ 构造函数体

析构顺序：完全逆序（④③②①）
```

### 3.2 初始化列表的顺序坑

成员初始化顺序由**声明顺序**决定，初始化列表只决定"用什么值"，不决定顺序：

```cpp
#include <cstddef>
#include <vector>

struct Widget {
    std::vector<int> data;   // ① 先声明，先初始化
    std::size_t n;           // ② 后初始化
    Widget(std::size_t n_) : n(n_), data(n, 0) {}  // 陷阱：实际先执行 data(n,0)，
                                                   // 此时 n 尚未初始化，读未初始化值是未定义行为
};
// 正确做法：调整成员声明顺序，让 n 在 data 之前
```

启用 `-Wall -Wextra` 时 GCC/Clang 会对这种顺序不一致给出 `-Wreorder` 警告。

### 3.3 委托构造（C++11）与 explicit

```cpp
class Timer {
public:
    Timer() : Timer(60) {}               // C++11 委托构造：转给另一个构造函数
    explicit Timer(int seconds) : sec_(seconds) {}
private:
    int sec_;
};
```

`explicit` 的作用：

| 写法 | 效果 |
| --- | --- |
| `Meters(double)` | 允许 `paint(3.0)` 隐式构造临时对象，容易出 bug |
| `explicit Meters(double)` | 禁止隐式转换，必须 `paint(Meters(3.0))` |
| `explicit operator bool()` | 允许 `if (obj)` 但禁止 `int x = obj;`（惯用法） |

> 准则：单参数构造函数默认加 `explicit`，确实想要隐式转换再显式去掉。

### 3.4 聚合初始化

```cpp
struct Point { int x; int y; };        // 聚合类：无用户声明构造函数、无私有非静态成员、无虚函数、无基类（C++17 起可有 public 基类）
Point p{1, 2};                         // 聚合初始化
Point q{.x = 1, .y = 2};               // C++20 指定初始化器
```

## 4. 虚函数机制（核心）

### 4.1 vtable 与 vptr

> **重要声明：C++ 标准没有规定虚函数的实现方式**，只规定了行为（按动态类型派发）。以下描述的是 **Itanium C++ ABI（GCC/Clang 在 Linux 上的典型实现）**；MSVC 的布局细节不同，但思想一致。具体布局视实现而定。

每个**含虚函数的类**有一张虚函数表（vtable，编译期生成，通常放只读数据段）；每个**对象**头部有一个指针（vptr）指向其动态类型的 vtable。

```text
  Derived d;                        vtable（每个类仅一份，只读段）
  +--------------+
  | vptr (8B)    | ─────────────►  +-----------------------------+
  +--------------+                 | [0] &Derived::print()       |
  | int  x       |                 | [1] &Derived::scale(double) |
  +--------------+                 | [2] &Derived::~Derived()    |
  | double y      |                | ...                         |
  +--------------+                 +-----------------------------+
        ▲                          （Itanium ABI 中表前还有 typeinfo 指针、
        │                             offset-to-top 等辅助项）
  Base* p = &d;   // 静态类型 Base*，动态类型 Derived；指向同一地址
```

派生类的 vtable 中：重写了的槽位换成派生类函数地址；没重写的沿用基类地址；新增虚函数追加在后面。

### 4.2 一次虚函数调用的完整步骤

```text
p->print();    // 编译成三步（伪代码 (*p->vptr[0])(p)）：
```

```text
1) 取对象首部 vptr            mov   rax, [rdi]        ; 第一次解引用
2) 按槽位取函数地址           call  [rax + 8*n]       ; 第二次解引用 + 间接调用
3) this 指针已在 rdi          （n 是该虚函数在表中的下标，编译期已知）
```

### 4.3 虚调用成本分析

| 维度 | 直接调用 `f(x)` | 虚调用 `p->f()` |
| --- | --- | --- |
| 指令形态 | 相对 `call`（目标编译期已知） | 两次内存加载 + 间接 `call` |
| 内联 | 可以内联，进而触发常量传播等连锁优化 | 基本无法内联，**连锁损失**：函数体进不了调用者，后续优化全部丢失 |
| 分支预测 | 无压力 | 间接跳转依赖预测器（类层次多时可能 miss） |
| 去虚化 | — | 编译器有时能证明唯一类型（如 `final`、局部对象直接调用）而退化为直接调用 |

> 真正的成本不只是"多两条指令"，而是**阻断内联**带来的连锁效应。热点路径上可用 `final`、CRTP（见《05-模板与泛型编程.md》）或手工分支替代。

## 5. 对象内存布局进阶

### 5.1 空类与 EBO

```cpp
struct Empty {};
sizeof(Empty);              // == 1：保证两个不同对象地址不同（数组元素不能重叠）
struct HasMember { Empty e; int x; };
sizeof(HasMember);          // == 8：成员 Empty 必须占独立地址（对齐后 1+填充+4）
struct HasBase : Empty { int x; };
sizeof(HasBase);            // == 4：空基类优化 EBO，基类子对象可与派生类成员共享偏移 0
```

| 现象 | 原因 |
| --- | --- |
| 空类 `sizeof == 1` | C++ 要求不同完整对象地址不同，必须占 1 字节 |
| 空类作为**成员**使体积膨胀 | 成员子对象不能与其他成员同地址（视实现的对齐规则） |
| 空类作为**基类**零开销 | 标准允许空基类优化（EBO），GCC/Clang/MSVC 均实现 |

### 5.2 多继承布局

```cpp
class A { int a; public: virtual void fa(); };
class B { int b; public: virtual void fb(); };
class C : public A, public B { int c; };
```

```text
C 对象（GCC/Clang，Itanium ABI）
+--------------------+
| vptr_A             | ──► C 中 A 子对象的 vtable（含 fb 调整 thunk）
+--------------------+
| int a              |
+--------------------+   ← B* 指向这里（偏移 +16）：static_cast<B*>(pc) 会做指针调整
| vptr_B             | ──► C 中 B 子对象的 vtable
+--------------------+
| int b              |
+--------------------+
| int c              |
+--------------------+
```

多继承的代价表：

| 代价 | 说明 |
| --- | --- |
| 多个 vptr | 每多一个含虚函数的基类，对象多一个指针 |
| 指针调整 | `B* p = &c;` 得到的地址和 `&c` 不同；比较/转换有额外开销 |
| this 调整 thunk | 通过 B 子对象调用 C 的重写函数时需把 this 加回偏移 |

### 5.3 虚继承与菱形问题

| 方案 | 基类子对象份数 | 体积 | 访问共享基类成员 | 二义性 |
| --- | --- | --- | --- | --- |
| 普通继承（菱形） | 2 份（两条路径各一份） | 较小 | 必须写 `obj->Printer::id` 指明路径 | 有 |
| 虚继承 | 1 份（共享） | 增大（视实现而定，Itanium ABI 下通常经 vtable 中的 vbase offset 间接寻址） | 直接访问 | 消除 |

## 6. 多继承与接口

### 6.1 接口类惯用法

```cpp
#include <string>

class Serializable {                    // 纯虚接口惯用法
public:
    virtual ~Serializable() = default;  // 虚析构：见第 8 节
    virtual std::string to_json() const = 0;
protected:
    Serializable() = default;           // 只允许派生类构造
};
```

### 6.2 菱形继承完整演示

```cpp
#include <iostream>

struct Device { int id = 0; };
struct Printer : Device { int dpi = 600; };
struct Scanner : Device { int dpi = 1200; };      // 演示二义性：故意重名
struct MFP : Printer, Scanner {};

int main() {
    MFP m;
    // m.id = 1;                 // 编译错误：ambiguous，两份 Device::id
    m.Printer::id = 1;           // 必须显式指明路径
    m.Scanner::id = 2;           // 与上面那份互不相干！
    // m.dpi = 100;              // 编译错误：Printer::dpi / Scanner::dpi 二义
    std::cout << m.Printer::id << ' ' << m.Scanner::id << '\n';
    // sizeof(m) 通常含两份 Device 子对象（视实现与对齐而定）
}
```

用虚继承消除重复：

```cpp
struct Printer : virtual Device { int dpi = 600; };
struct Scanner : virtual Device { int dpi = 1200; };
struct MFP : Printer, Scanner { };
// MFP 中只有一份 Device；id 只有一份，无二义
// 注意：最派生类 MFP 负责初始化虚基类 Device（虚基类由最终派生类直接初始化）
```

## 7. 对象切片（slicing）

```cpp
#include <memory>
#include <vector>

struct Shape { virtual double area() const { return 0; } virtual ~Shape() = default; };
struct Circle : Shape { double r; explicit Circle(double r) : r(r) {}
                        double area() const override { return 3.14159 * r * r; } };

int main() {
    std::vector<Shape> wrong;            // 反例：按值存基类
    wrong.push_back(Circle{5});          // 切片！Circle 部分被丢弃，只剩 Shape 子对象
    wrong[0].area();                     // 永远返回 0，多态已丢失

    std::vector<std::unique_ptr<Shape>> ok;      // 正确做法 1：多态指针容器
    ok.push_back(std::make_unique<Circle>(5));
    ok[0]->area();                       // 78.5397...

    std::vector<std::shared_ptr<Shape>> shared;  // 正确做法 2：需要共享所有权时
}
```

| 做法 | 结果 |
| --- | --- |
| `std::vector<Shape>` 存派生对象 | 切片：派生部分丢失，虚调用退化为基类版本 |
| `std::vector<Shape*>` / `unique_ptr<Shape>` | 保持多态 |
| 函数形参 `void f(Shape s)` 按值传派生对象 | 切片（同理） |
| 形参 `const Shape&` / `Shape*` | 保持多态 |

## 8. 虚析构函数（重点）

### 8.1 反例：UB

```cpp
#include <vector>

struct Base {
    ~Base() {}                 // 非虚析构
};
struct Derived : Base {
    std::vector<int> big;      // 派生类新增资源
};

int main() {
    Base* p = new Derived;
    delete p;                  // 未定义行为：编译器按静态类型只调用 ~Base，
}                              // big 的内存泄漏（析构未运行），标准不保证任何行为
```

### 8.2 判定准则

| 场景 | 析构函数应当 |
| --- | --- |
| 类会被 `delete`，且可能通过基类指针 | 必须 `virtual` |
| 不作为基类使用（可加 `final` 类） | 非 virtual（保持默认），零开销 |
| 基类只供派生类内部使用，绝不经基类指针 delete | `protected` 非 virtual 析构惯用法：阻止外部经基类指针删除 |
| 有虚函数的类 | 几乎必然会被多态使用 → 析构也应 virtual（有虚函数却非虚析构是强烈的设计坏味道） |

```cpp
class UtilityBase {                 // protected 非虚析构惯用法
protected:
    ~UtilityBase() = default;       // 派生类析构时能调用；外部不能 delete UtilityBase*
};
```

## 9. override 与 final（C++11）

### 9.1 override 检查表

| 基类声明 | 派生类写了 | 有 `override` 时 | 无 `override` 时 |
| --- | --- | --- | --- |
| `virtual void f() const;` | `void f()` | 编译错误（漏 const） | 静默变成**隐藏**，运行期仍调基类版本 |
| `virtual void f(int&);` | `void f(int)` | 编译错误（引用≠值） | 同上，静默隐藏 |
| `virtual void f();` | `void f() const` | 编译错误 | 静默隐藏 |
| `virtual void f();` | `virtual void f()` | 正常重写 | 正常重写（但基类日后改签名将不再报警） |

> 结论：**所有重写一律写 `override`**，把签名错误从运行期 bug 变成编译错误。

### 9.2 隐藏（hiding）与重写（overriding）

| 维度 | 重写 overriding | 隐藏 hiding |
| --- | --- | --- |
| 发生条件 | 基类 virtual 且签名/const/引用限定完全一致 | 派生类声明了同名函数（签名可不同） |
| 绑定方式 | 动态绑定（按对象实际类型） | 静态绑定（按静态类型） |
| 影响范围 | 单个函数 | **整个同名重载集都被隐藏** |

```cpp
struct Base {
    virtual void run(int);
    virtual void run(double);
};
struct Derived : Base {
    void run(int) override;   // 只重写了一个；run(double) 在派生类作用域中被隐藏
    using Base::run;          // 解法：把基类重载集引入派生类作用域
};
```

### 9.3 final

| 用法 | 含义 |
| --- | --- |
| `void f() override final;` | 该函数不允许再被下层重写（帮助编译器去虚化） |
| `class X final {};` | 类不可被继承 |

## 10. RTTI（运行期类型信息）

| 工具 | 失败时的行为 | 典型用法 |
| --- | --- | --- |
| `dynamic_cast<Derived*>(p)` | 返回 `nullptr` | 指针转换 + 判空 |
| `dynamic_cast<Derived&>(*p)` | 抛出 `std::bad_cast` | 引用转换（引用无空值可表达失败） |
| `typeid(*p)` | 解引用空指针的多态类型抛 `std::bad_typeid` | 取 `type_info` 比较 |
| `typeid(T)` / `typeid(expr)` | 不失败（静态） | 编译期/表达式类型名 |

```cpp
#include <typeinfo>

struct Base { virtual ~Base() = default; };
struct Derived : Base { void only_in_derived(); };

void f(Base* p) {
    if (auto* d = dynamic_cast<Derived*>(p))   // 常用惯用法：判空即分支
        d->only_in_derived();
    // typeid(p) 是 Base* 的静态类型；typeid(*p) 才是动态类型（要求多态类型）
}
```

| RTTI 相关 | 说明 |
| --- | --- |
| 开销来源 | 每个多态类一份 `type_info` 对象、vtable 中的指针、`dynamic_cast` 的运行期类型树遍历（视实现而定） |
| 编译选项 | `-fno-rtti` 关闭（嵌入式/体积敏感场景）；关闭后 `dynamic_cast` 多态转换与 `typeid(*p)` 不可用 |
| 滥用信号 | 大量 `if (dynamic_cast<D*>...) if-else 链` = 忘了写虚函数 |

## 11. 继承设计准则

| 维度 | 组合（has-a） | 继承（is-a） |
| --- | --- | --- |
| 语义 | "X 有一个 Y" | "X 是一种 Y"（仅 public 继承成立） |
| 耦合度 | 低：只依赖 Y 的公开接口 | 高：继承还隐式耦合内存布局与 protected 成员 |
| 灵活性 | 运行期可替换成员对象 | 关系编译期固定 |
| 测试/复用 | 容易单独测试、按件复用 | 基类改动波及整棵继承树 |
| 适用 | 默认选择 | 存在真实接口抽象（框架回调、插件接口）时 |

> 经验法则：**优先组合，仅在需要运行期多态替换或复用框架钩子时使用 public 继承**；`private` 继承表达"以……实现"，能换成员组合就换。

## 12. 快速参考卡片

| 我想…… | 用法 |
| --- | --- |
| 声明可重写接口 | `virtual void f() = 0;` + 虚析构 + protected 构造 |
| 安全重写 | 派生类写 `void f() override`（永远带 override） |
| 通过基类指针 delete | 基类析构 `virtual ~Base() = default;` |
| 派生类引入基类重载集 | `using Base::run;` |
| 向下转换（保守判空） | `if (auto* d = dynamic_cast<D*>(p))` |
| 多态容器 | `std::vector<std::unique_ptr<Shape>>`，绝不按值存基类 |
| 禁止隐式单参转换 | 构造函数加 `explicit` |
| 禁止进一步继承/重写 | `class X final` / `void f() override final` |
| 共享菱形基类 | 中间层 `virtual` 继承 + 最派生类初始化虚基类 |
| 判断"用继承还是组合" | 能说通 "X 是一种 Y" 才用 public 继承，否则组合 |

内存速查（GCC/Clang x86-64，Itanium ABI，具体视实现而定）：

| 对象 | 典型 sizeof | 说明 |
| --- | --- | --- |
| `struct Empty {}` | 1 | 保证地址唯一 |
| `struct X : Empty { int i; }` | 4 | EBO |
| 含 1 个虚函数的类（另有 2 个 int） | 16 | vptr(8) + 8（对齐填充后） |
| 多继承两个含虚函数基类 | 至少 2 个 vptr | 每个"多态基类子对象"一个 |

## 13. 常见问题与坑

| 问题 | 原因与解决方案 |
| --- | --- |
| 基类析构非虚，`delete basePtr` 泄漏/崩溃 | 通过基类指针删除派生对象是 UB。解决：多态基类一律 `virtual ~Base() = default;` |
| 构造/析构函数里调用虚函数没派发到派生类 | 构造基类子对象时对象"还是基类"，虚调用退化为静态绑定。解决：构造期不要指望多态，用两段式 `init()` 或工厂 |
| 对象切片：容器按值存基类，虚函数全调基类版本 | `vector<Shape>` 拷贝时切掉派生部分。解决：存 `unique_ptr<Shape>`/`shared_ptr<Shape>` |
| 初始化列表顺序与声明顺序不一致，读到未初始化成员 | 初始化按**声明顺序**执行。解决：调整成员声明顺序；开 `-Wreorder` 警告 |
| 派生类重写基类某个重载后，其余重载"消失" | 隐藏整个同名重载集。解决：`using Base::run;` |
| 纯虚析构函数链接报错 | 纯虚析构也必须提供定义（派生类析构链会调用它）：类内声明 `virtual ~Interface() = 0;`，定义必须放在类外 `Interface::~Interface() = default;` |
| `dynamic_cast` 引用版本没判失败直接崩 | 引用失败抛 `std::bad_cast` 而非返回空。解决：能判空就用指针版本 |
| 漏写 `const` 导致"以为重写了其实没重写" | 签名不一致变成隐藏。解决：所有重写加 `override` |
| 菱形继承访问基类成员报 ambiguous | 两条路径各一份基类子对象。解决：中间类 `virtual` 继承；或改用组合/单接口 |
| `struct` 继承默认是 public 而 `class` 默认 private，混用导致成员可见性意外 | 记住两种关键字默认差异；继承方式显式写出来 |
| 虚函数放在构造函数初始化列表里调用 | 同"构造中调用虚函数"，静态绑定。解决：移到构造函数体之后由使用者显式调用 |
| `delete` 后通过悬垂基类指针继续调用 | 与虚析构无关的悬垂指针 UB。解决：`delete` 后置空或用智能指针管理所有权 |
