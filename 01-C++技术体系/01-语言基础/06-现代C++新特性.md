## 1. 概述：版本演进总览

| 版本 | 定位 | 核心主题 | GCC 基本完整支持 | 编译开关 |
|---|---|---|---|---|
| C++11 | 现代起点 | auto、lambda、移动语义、智能指针、constexpr、线程 | 4.8.1 | `-std=c++11` |
| C++14 | 完善 | 泛型 lambda、返回推导、make_unique | 5 | `-std=c++14` |
| C++17 | 实用化 | 结构化绑定、optional/variant/string_view、if constexpr | 7~8 | `-std=c++17` |
| C++20 | 四大件 | concepts、ranges、coroutines、modules | 12~13（modules 支持仍滞后，视实现而定） | `-std=c++20` |
| C++23 | 补强 | print、expected、mdspan、deducing this | 14（print/format 需 14+） | `-std=c++23` |

> GCC 各小版本的特性矩阵可用 `g++ -std=c++20 -Q --help=c++` 查看已启用项；MSVC 用 `/std:c++20`；Clang 用 `-std=c++20`。构建系统集成见《../06-构建与版本控制/01-构建工具GCC与CMake.md》。具体某特性是否可用，最终以你的编译器实测为准（支持度随版本演进，本文标注为"典型可用版本"）。

学习优先级建议：**移动语义 > lambda + auto > C++17 工具库 > ranges/concepts**。前者每天都用，后者渐进采用。

```cpp

public:
    Widget() = default;                          // 用编译器默认实现
    Widget(const Widget&) = delete;              // 禁止拷贝（编译期报错）
    Widget& operator=(const Widget&) = delete;
    virtual ~Widget() = default;
    void draw() const override;                  // 检查：确实是虚函数重写

struct NoInherit final {};                       // final：禁止继承
```

### 2.2 lambda 详解

```cpp
auto add = [](int a, int b) { return a + b; };       // 完整形式
int add3(int x) { return x + 3; }
auto f = add3;                                       // 函数指针
// 语法骨架：[capture](params) -> ret { body }，返回类型 ret 常可省略
```

**捕获方式表：**

| 语法 | 含义 | 风险与备注 |
|---|---|---|
| `[]` | 不捕获（只能用全局/静态和形参） | 最安全 |
| `[=]` | 按值捕获所有被用到的变量 | 每个都拷贝；**this 仍按引用**（见下） |
| `[&]` | 按引用捕获所有 | **悬垂高危**：lambda 活得比捕获变量久即 UB |
| `[x]` / `[&x]` | 指名按值/按引用 | 显式，推荐 |
| `[=, &big]` / `[&, tiny]` | 混合 | 默认 + 例外 |
| `[this]` | 捕获 this 指针（可访问成员） | 对象销毁后调用 = 悬垂 |
| `[*this]`（C++17） | **拷贝整个对象**进闭包 | 异步回调安全，要求可拷贝 |
| `[v = std::move(big)]`（C++14） | 初始化捕获：把对象**移动**进闭包 | 捕获 unique_ptr 的唯一方式 |
| `[i = 0]`（C++14） | 初始化捕获新变量 | 闭包内计数器等 |

```cpp
// mutable：允许修改按值捕获的副本（不影响外部原件）
int counter = 0;
auto inc = [counter]() mutable { return ++counter; };  // 修改闭包内的副本
inc(); inc();
// counter 仍是 0

// 捕获 this 的悬垂陷阱：
class Session {
    void startAsync() {
        post([this] { handle(); });       // 危险：回调执行时 Session 可能已析构
        post([self = shared_from_this()] { self->handle(); });   // 正确：保活（见内存管理篇）
        // C++17 也可以 [*this]（若可拷贝）
    }
    void handle();
};

// 无捕获 lambda 可转函数指针（C 接口回调桥）：
using Cb = void(*)(int);
Cb cb = [](int x) { std::printf("%d\n", x); };
```

**lambda 的本质**：编译器生成一个匿名类，捕获的变量成为其成员，`operator()` 默认 `const`（mutable 去掉 const）。理解这一点，"闭包按值捕获的是快照、按引用捕获的是外部本体"就自然成立。

## 3. 移动语义（本篇核心）

### 3.1 值类别：左值、右值、将亡值

| 类别 | 通俗理解 | 能否取地址 | 例子 |
|---|---|---|---|
| 左值（lvalue） | 有名字、可反复引用的对象 | 能 | `x`、`*p`、`arr[i]` |
| 纯右值（prvalue） | 字面量、临时计算结果 | 不能 | `42`、`x+1`、`Widget{}` |
| 将亡值（xvalue） | "可以被掏空"的资源持有者 | 不能 | `std::move(x)`、返回 `T&&` |

（C++17 起的精确分类为 lvalue/prvalue/xvalue 三类，prvalue 含"未实质化"概念；工程上记"能不能取地址 + 还要不要用它"足够。）

**判定口诀：能出现在赋值号左边、能取地址的是左值；`std::move(x)` 之后 x 名字还在、还是左值，但被标记为"可掏空"。**

### 3.2 std::move 的本质：它不移动任何东西

```cpp
// std::move 的实现近似（就是一次 static_cast）：
template <typename T>
constexpr std::remove_reference_t<T>&& my_move(T&& t) noexcept {
    return static_cast<std::remove_reference_t<T>&&>(t);
}
```

`std::move(x)` 只做一件事：**把 x 转换成右值引用（类型层面的标记）**，从而让重载决议选中移动构造/移动赋值。真正的"移动"发生在移动构造函数里。因此：

- 对没有移动构造的类型，`std::move` 之后照常走拷贝（比如某些老类）。
- `std::move` 本身零运行时开销，但移动构造是否有意义取决于类怎么写。
- `const` 对象上的 `std::move` 会退化成拷贝（见第 10 章坑表）。

### 3.3 移动构造 / 移动赋值示例

```cpp
#include <algorithm>
#include <cstddef>
#include <utility>

class Buffer {
public:
    explicit Buffer(std::size_t n) : size_(n), data_(new int[n]) {}
    ~Buffer() { delete[] data_; }

    // --- 拷贝语义：深拷贝（贵） ---
    Buffer(const Buffer& o) : size_(o.size_), data_(new int[o.size_]) {
        std::copy(o.data_, o.data_ + o.size_, data_);
    }
    Buffer& operator=(const Buffer& o) {
        if (this != &o) {
            int* p = new int[o.size_];                    // 先分配再释放：异常安全
            std::copy(o.data_, o.data_ + o.size_, p);
            delete[] data_;
            data_ = p; size_ = o.size_;
        }
        return *this;
    }

    // --- 移动语义：窃取资源（便宜，标记 noexcept 极重要） ---
    Buffer(Buffer&& o) noexcept : size_(o.size_), data_(o.data_) {
        o.data_ = nullptr;                                // 置空来源，防止双重释放
        o.size_ = 0;
    }
    Buffer& operator=(Buffer&& o) noexcept {
        if (this != &o) {
            delete[] data_;
            data_ = std::exchange(o.data_, nullptr);      // C++14 <utility>
            size_ = std::exchange(o.size_, 0);
        }
        return *this;
    }

private:
    std::size_t size_;
    int* data_;
};

Buffer a(1024);
Buffer b = a;              // 拷贝构造：分配 + 逐元素复制
Buffer c = std::move(a);   // 移动构造：三个指针赋值，a 进入"有效但未指定"状态
```

**移动后来源对象的状态：标准规定为"有效但未指定（valid but unspecified）"**——可以析构、可以赋新值，但别假设它的内容。

### 3.4 rule of five

一旦你为类手写了**任何一个**（析构/拷贝构造/拷贝赋值），就该考虑全套五个是否都要写：

| 成员函数 | 默认行为 | 何时需要手写 |
|---|---|---|
| 析构函数 | 逐成员析构 | 持有裸资源（new/fopen）时 |
| 拷贝构造 | 逐成员拷贝 | 裸指针成员 → 需深拷贝 |
| 拷贝赋值 | 逐成员拷贝 | 同上 + 自赋值/异常安全 |
| 移动构造 | 逐成员移动 | 想掏空资源 + noexcept |
| 移动赋值 | 逐成员移动 | 同上 |

更现代的忠告（rule of zero）：**类里不放裸资源、成员全用 string/vector/unique_ptr，五个函数一个都不写**——编译器生成的默认行为全部正确。

### 3.5 noexcept 移动与 vector 扩容（高频考点）

```cpp
std::vector<Buffer> v;
v.push_back(Buffer(1024));     // 临时对象 → 移动构造进容器
v.push_back(Buffer(1024));     // 触发扩容：搬移旧元素
```

扩容搬移时 vector 面临选择：逐个**移动**（快，但移动构造若中途抛异常，无法回滚已破坏的元素）还是逐个**拷贝**（慢，但出错可回滚）。标准的选择是 `std::move_if_noexcept`：**移动构造标了 noexcept 才用移动，否则退回拷贝**。

> 忘写 noexcept 的后果：vector 扩容悄悄退化为深拷贝，性能掉一个数量级且没有任何告警。这是"移动语义没生效"的第一嫌疑人。

### 3.6 右值引用延长临时生命周期

```cpp
const std::string& s1 = std::string("tmp");   // const 左值引用：延长临时寿命到 s1 离开作用域
std::string&& s2 = std::string("tmp");        // 右值引用：同样延长
// C++11 起还有生命周期陷阱：
std::string&& bad = std::move(local_str);     // local_str 是左值！move 后仍在原处，bad 只是别名
```

### 3.7 std::forward 完美转发（简述）

```cpp
template <typename T, typename... Args>
std::unique_ptr<T> my_make(Args&&... args) {          // 万能引用：转发引用
    return std::unique_ptr<T>(new T(std::forward<Args>(args)...));   // 保持实参的左右值属性
}
// my_make<Widget>(a)      → Args=Widget& → 拷贝构造
// my_make<Widget>(std::move(a)) → Args=Widget → 移动构造
```

**引用折叠规则**：`T& &`、`T& &&`、`T&& &` 都折叠为 `T&`，只有 `T&& &&` 是 `T&&`。`T&&` 在模板推导中遇到左值实参时 `T = U&`，折叠后参数类型是 `U&`——这就是万能引用能同时接住左值和右值的机制。

`std::move` = 无条件转右值；`std::forward<T>` = **有条件**转发（原来是左值就保持左值）。前者用于"我确定要掏空"，后者用于"我只是通道"。

## 5. C++17：实用主义大爆发

### 5.1 结构化绑定

```cpp
std::map<std::string, int> ages{{"tom", 18}, {"jerry", 20}};

for (const auto& [name, age] : ages)              // map 遍历最佳形态
    std::cout << name << ": " << age << '\n';

struct Point { double x, y; };
Point p{1.0, 2.0};
auto [x, y] = p;                                   // 解构聚合

int arr[3] = {1, 2, 3};
auto [a, b, c] = arr;                              // 原生数组也能解
// 限制：不能嵌套、不能在同一作用域重复绑定同名、绑定的不是新变量而是引用
```

### 5.2 if / switch 带初始化器

```cpp
// 把"临时变量"关进 if 的作用域，命名清晰且不外泄
if (auto it = cache.find(key); it != cache.end()) {
    return it->second;                 // it 只在本分支可见
}
return compute(key);

switch (auto code = parse());          // switch 同样支持
```

### 5.3 if constexpr：编译期分支

```cpp
template <typename T>
auto strip(T t) {
    if constexpr (std::is_pointer_v<T>)       // 编译期裁剪：未选中的分支根本不实例化
        return *t;
    else
        return t;
}
// 与普通 if 的本质区别：else 分支里可以写"只对某些 T 合法"的代码，
// 因为未命中的分支在编译期被丢弃——模板元编程的复杂度大幅下降
```

### 5.4 std::optional：消灭魔法值

```cpp
#include <optional>

std::optional<int> find_user_id(const std::string& name);   // 找不到 ≠ 返回 -1

if (auto id = find_user_id("tom")) {       // 有值时为 true（语境转换）
    use(*id);                              // 解引用取值
}
int id_or_guest = find_user_id(name).value_or(-1);   // 带默认值
auto id2 = find_user_id(name).value();     // 无值时抛 std::bad_optional_access

// 旧时代写法：返回 int + 出参 bool；或约定 -1 表示无效——两种都是坑
```

**vs 异常**：异常表达"不可预期的错误"；optional 表达"预期内可能没有结果"。查缓存、查配置、解析失败，用 optional。

### 5.5 std::variant：类型安全的联合体

```cpp
#include <variant>
#include <string>

std::variant<int, std::string> v = 42;

int n = std::get<int>(v);                  // 类型不对抛 std::bad_variant_access
if (auto p = std::get_if<int>(&v))         // 指针形式不抛异常
    use(*p);

// visit + overloaded 惯用法：穷举所有分支（编译器保证不漏）
template <typename... Ts> struct overloaded : Ts... { using Ts::operator()...; };
template <typename... Ts> overloaded(Ts...) -> overloaded<Ts...>;   // C++17 推导指引

std::visit(overloaded{
    [](int i)              { std::cout << "int: " << i << '\n'; },
    [](const std::string& s) { std::cout << "str: " << s << '\n'; },
}, v);
```

与 union 的区别：union 不知道当前存的是哪个成员（用错即 UB）；variant 记录当前类型并做检查。**variant + visit 是"访问者模式"的现代形态**（呼应《08-设计模式与典型实现.md》第 4 章）。

### 5.6 std::string_view：只读字符串切片

```cpp
#include <string_view>

void log_msg(std::string_view sv);          // 接口首选：接收 const char*/string 都零拷贝

std::string url = "https://example.com/path";
auto host = url.substr(0, 18);              // string::substr → 拷贝（分配）
std::string_view sv(url);
auto host2 = sv.substr(0, 18);              // string_view::substr → O(1)，零拷贝
```

| 优点 | 风险 |
|---|---|
| 传参零拷贝、substr O(1) | **不拥有数据：所指字符串销毁后悬垂** |
| 替代 `const std::string&` 参数避免隐式构造 | 不保证 NUL 结尾，传给 C API 前须确认 |
| 轻量（指针+长度） | 存成成员变量 = 埋雷（生命周期不明） |

## 6. C++20：四大件与其他

### 6.1 concepts：带约束的模板

```cpp
#include <concepts>

template <typename T>
concept Number = std::integral<T> || std::floating_point<T>;

template <Number T>                 // 用法1：直接约束模板参数
T twice(T x) { return x + x; }

template <typename T> requires Number<T>    // 用法2：requires 子句
T thrice(T x) { return x * 3; }

void f(Number auto x);              // 用法3：缩写形式（C++20 简写函数模板）

// 报错信息从"嵌套替换失败"变为人话：
// "constraint not satisfied: std::integral<double> evaluated to false"
```

价值：模板报错可读、约束可复用（`std::ranges::range`、`std::convertible_to`）、替代 SFINAE/enable_if 的所有黑魔法。

### 6.2 ranges：管道化的惰性视图

```cpp
#include <ranges>
#include <vector>

std::vector<int> v{1, 2, 3, 4, 5, 6};
auto result = v | std::views::filter([](int x) { return x % 2 == 0; })
                | std::views::transform([](int x) { return x * x; });
for (int x : result) std::cout << x << ' ';        // 输出 4 16 36

// 惰性求值：不产生中间容器，遍历时才计算
// C++23 起还能 to<std::vector>() 物化结果
auto first = *std::ranges::max_element(v);
auto [min, max] = std::ranges::minmax(v);
```

ranges 同时统一了"算法直接吃容器"（`std::ranges::sort(v)`，不用再写 begin/end）与投影（`std::ranges::sort(people, {}, &Person::age)`）。

### 6.3 coroutines：概念级认识

```cpp
// 关键字：co_await（挂起等待）、co_yield（产出一个值）、co_return（结束）
// 形态（示意，非完整代码）：
generator<int> iota() {
    for (int i = 0;; ++i)
        co_yield i;                  // 每次产出一个值后挂起，调用方取值时恢复
}
```

适用场景：异步 IO 的同步写法、生成器/无限序列、状态机、协作式调度。**不深入的原因**：C++20 只提供了底层机制（promise_type、awaiter），日常使用依赖库（cppcoro 等）封装；初学阶段只需认识关键字与"函数可挂起恢复"的模型。

### 6.4 modules：现状与预期

```cpp
// math.ixx（模块接口单元）
export module math;
export int add(int a, int b) { return a + b; }

// main.cpp
import math;
int main() { return add(1, 2); }
```

| 现状 | 说明 |
|---|---|
| 目标 | 替代头文件：告别 include 依赖地狱、更快编译 |
| 编译器支持 | 不均衡：MSVC 较成熟，GCC 14+/Clang 17+ 基本可用（视实现而定） |
| 生态 | 标准库模块（`import std;`）C++23 才标准化；大量第三方库尚未模块化 |
| 建议 | 新项目可实验；存量项目短期继续头文件 |

### 6.5 其他 C++20 要点

```cpp
// 三路比较：一次 default 生成全套比较
struct Version {
    int major, minor, patch;
    auto operator<=>(const Version&) const = default;   // 生成 < <= > >=
    bool operator==(const Version&) const = default;    // == 需单独 default（注意！）
};

// std::span：连续内存的统一视图（数组/vector/指针+长度 通吃）
#include <span>
void process(std::span<const int> data);
int a[4]{1,2,3,4};  std::vector<int> v{1,2,3};
process(a);  process(v);                                 // 都能传，零拷贝

// std::format：类型安全的格式化（思路接近 Python 的 str.format）
#include <format>
std::string s = std::format("{:>8.2f} ({})", 3.14159, "PI");

// 指定初始化器：字段按名初始化（必须按声明顺序！）
struct Point { int x = 0; int y = 0; int tag = 0; };
Point p{.x = 1, .y = 2};          // 跳过 tag 用默认值；写 .y 在 .x 前是编译错误
```

### 8.1 渐进式升级项目标准

| 步骤 | 做法 |
|---|---|
| 1. 评估 | 用编译器 `-std=c++17` 试编译现有代码，统计报错量（多数老代码可直接过） |
| 2. 定门槛 | CMake 里 `set(CMAKE_CXX_STANDARD 17)` + `CXX_STANDARD_REQUIRED ON`（见《../06-构建与版本控制/01-构建工具GCC与CMake.md》） |
| 3. 双编译 CI | 同一 CI 矩阵里新旧两个标准各编一次，防止隐式依赖 |
| 4. 小步替换 | 按模块把裸 new 改智能指针、把出参改 optional、把宏改 constexpr |
| 5. 开 sanitizer | 升级期间常开 ASan/UBSan，移动语义的坑（移动后使用）靠它抓 |
| 6. 注意 ABI | 同一进程混用不同 -std 编译的库要小心 libstdc++ 的双 ABI（`_GLIBCXX_USE_CXX11_ABI`） |

### 8.2 面试高频考点表

| 考点 | 一句话答案 |
|---|---|
| std::move 原理 | static_cast 到右值引用的类型转换，本身零开销，不移动任何东西 |
| 移动后对象状态 | "有效但未指定"：可析构可赋值，不可假设内容 |
| 为什么移动构造要 noexcept | vector 扩容用 move_if_noexcept，非 noexcept 退化为拷贝 |
| 完美转发 | 模板 `T&&` + 引用折叠 + std::forward 保持实参值类别 |
| move vs forward | move 无条件转右值（我要掏空）；forward 有条件保持（我只是通道） |
| optional vs 异常 | optional=预期内的"可能没有"；异常=不可预期的故障 |
| lambda 捕获 this 的坑 | 捕获的是指针，对象析构后回调悬垂；用 [*this] 或 shared_from_this |
| 左值/右值判定 | 能取地址、有名字的是左值；move(x) 是将亡值表达式但 x 本身还是左值 |

## 10. 常见问题与坑

| 问题 | 原因与解决方案 |
|---|---|
| 对 const 对象 `std::move` 后发现还是发生了深拷贝 | `const T&&` 无法绑定移动构造的 `T&&` 形参，重载决议退回拷贝构造。去掉来源的 const 或检查形参 |
| lambda 按引用捕获，异步线程里使用时崩溃 | 捕获的引用指向已销毁的栈变量。改按值捕获 / `[*this]`（17）/ shared_from_this 保活 |
| `std::string_view sv = std::string("tmp");` 之后用 sv 崩溃 | 临时 string 在该语句末析构，sv 悬垂。需要拥有数据就拷成 string |
| `auto b = v[0];`（vector<bool>）得到怪异类型 | 代理类型 `vector<bool>::reference`，非 bool。显式写 `bool b = v[0];` 或换容器 |
| 结构化绑定想写 `auto [a, [b, c]] = ...` | 语法不支持嵌套解构。分两步绑定 |
| `std::move(a)` 之后继续用 a 的内容 | 移动后是"有效但未指定"状态，内容不可预测。move 之后只允许析构或重新赋值 |
| 类写了移动构造但没标 noexcept，vector 扩容性能暴跌 | move_if_noexcept 退回拷贝。移动构造/移动赋值一律 `noexcept` |
| 移动构造里忘了置空来源指针 → 双重释放 | 移动是"窃取+置空"，置空是义务不是可选 |
| 范围 for 写 `for (auto x : bigContainer)` 全量拷贝 | 改 `const auto&`；代理容器用 `auto&&` |
| C++20 指定初始化器报"顺序错误" | 必须按成员声明顺序书写 `.x` `.y`，不能跳跃倒序 |
| `operator<=> = default` 后 `==` 行为疑惑 | defaulted `<=>` 不自动合成 `==`，需要另写 `bool operator==(const T&) const = default;` |
| if constexpr 里写的"另一分支"代码仍然报错 | 只有依赖模板参数的分支会被丢弃；不依赖的分支照常检查语法 |
| 结构化绑定后 `auto [a,b] = p; a = 5;` 发现没改到 p | 绑定的是"引用别名"，但 `auto` 决定了底层拷贝。要修改原对象用 `auto& [a, b] = p;` |
| unordered 容器用 enum class 做 key | C++20 起标准提供 `std::hash<enum>`；旧标准需自己写 hash 或 static_cast |
