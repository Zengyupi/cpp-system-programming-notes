## 1. 识别 AI 生成代码的"幻觉"与错误

大模型会**自信地编造**不存在或张冠李戴的 API，C++ 尤其多（版本/平台碎片化）。重点排查：

| 坑类型 | 表现 | 验证方式 |
| --- | --- | --- |
| 虚构 API/头文件 | `std::xxx`、某库方法根本不存在 | 查 cppreference / 实际头文件 |
| 版本错配 | 用了 C++20 却按 C++14 编译；OpenSSL 1.1 与 3.x API 混用 | 对编译标准和库版本 |
| 未定义行为 UB | 有符号溢出、越界、序列点、悬垂引用、数据竞争 | 开 `-Wall -Wextra -Wpedantic` + UBSan/TSan |
| 看似合理的魔数/算法 | CRC 多项式、协议常量、复杂度分析是编的 | 查协议手册/独立计算 |
| 吞异常/错误处理缺失 | `catch(...)` 后什么都不做、忽略返回值 | 人工审查错误路径 |
| 多余依赖/过度设计 | 小问题引大库、滥用设计模式 | 问"没有它行不行" |

### 1.1 强制验证三连（任何 AI 代码合入前）

```text
1. 编译：-Wall -Wextra -Werror 干净通过，交叉编译目标也过
2. 跑：单元测试 + ASAN/UBSAN 跑过，关键路径压测
3. 读懂：能逐行讲清为什么对，讲不清的部分查资料或要求 AI 解释到懂
```

## 2. 用 AI 做 Code Review（双向）

### 2.1 让 AI 审查同事/自身代码

```text
以严格的 C++ code reviewer 视角审查下面代码，按严重程度分级（阻断/建议/风格）：
- 内存与生命周期：泄漏、悬垂、双重释放、所有权
- 并发：数据竞争、死锁、锁粒度、原子内存序
- 异常安全：RAII、异常路径资源、noexcept 是否恰当
- 边界与整数：溢出、off-by-one、有/无符号比较
- 性能：无谓拷贝、大对象按值传参、频繁分配、算法复杂度
- 安全：注入、越界、敏感信息、未校验外部输入
每条给出：问题、后果、修复建议。代码：<粘贴>
```

### 2.2 审查 AI 自己产出的代码（自检提示词）

```text
忘掉你刚写的代码，以挑刺者身份重新审查：列出至少 5 个可能出错的点，
尤其是并发、生命周期、边界输入；对每个点判断是否真实存在并修正。
```

> AI 自审不能替代人审，但能快速捞出低级问题；**最终责任在人**。

## 3. 代码安全与保密红线（公司项目必读）

1. **不上传**：未公开规约实现、密钥/证书/口令、客户与现场配置、内网拓扑、带真实业务数据的日志。
2. 必须用云端工具时先**脱敏**：标识符改名、删 IP/密钥、用占位数据替换真实数据。
3. 遵守公司制度：很多企业对代码外发有明确规定，未经授权不要自行其是。
4. 警惕 AI 生成代码引入**开源协议风险**：它可能"默写"GPL 代码片段，商业闭源产品要谨慎，关键模块做来源核查。
5. 不要把生成的加密/安全算法直接用于生产（密码学要用成熟库，见《../01-C++技术体系/03-网络编程/03-网络安全与加密编程.md》）。

## 4. 本地化 / 内网部署（企业内网与信创场景）

目标：模型和代码都不出本机/内网。最小可用方案：**Ollama（跑模型）+ Continue/Cline（VSCode 插件）+ 代码模型**。

### 4.1 架构

```text
VSCode / CLion
   └─ Continue / Cline 插件（HTTP 调本地模型）
          └─ Ollama（本机 11434 端口提供推理）
                 └─ Qwen2.5-Coder / DeepSeek-Coder（本地权重，离线）
团队内网：一台带 GPU/大内存的服务器部署 Ollama 或 vLLM/openai 兼容接口，
          其他人插件指向内网地址，代码全程不出内网
```

### 4.2 本机快速起步（x86 开发机）

```bash
# 1) 安装 Ollama（Linux/macOS/Windows），官网 https://ollama.com
ollama pull qwen2.5-coder:7b        # 代码模型，7B 对内存/显存友好
ollama run qwen2.5-coder:7b         # 先在命令行验证可用
# 2) VSCode 安装 Continue 插件，配置模型 Provider 选 Ollama、模型名 qwen2.5-coder:7b
# 3) 离线环境：在能联网机器 ollama pull 后 ollama export 拷贝到内网 ollama import
```

### 4.3 硬件与模型选择（经验值，以实际为准）

| 模型规模 | 内存/显存建议 | 适用 |
| --- | --- | --- |
| 1.5B–3B | 8GB 内存，纯 CPU 可跑 | 行内补全、轻量 |
| **7B** | 16GB 内存 / 8GB 显存较顺 | 个人主力，补全+问答平衡 |
| 14B–32B | 32GB+ 内存或更强 GPU | 复杂重构/多文件，接近云端中小模型 |

- 代码任务优先选**带 Coder 后缀**的模型（代码专项训练）；
- 纯 CPU 可用但慢，量化版（Q4）省内存；
- 信创 ARM（鲲鹏/飞腾）+ 麒麟/统信部署需确认有对应架构构建，必要时用 vLLM/llama.cpp 方案，参考《../01-C++技术体系/02-系统原理/04-信创国产化技术栈.md》《../01-C++技术体系/17-音视频游戏与AI/03-端侧AI推理部署.md》。

### 4.4 本地模型的能力边界（别期望过高）

- 本地 7B 在**行内补全、局部函数、解释、写小脚本**上够用；
- **跨多文件大改造、复杂架构、追新框架**仍明显弱于云端旗舰模型；内网敏感代码用本地，非敏感复杂问题脱敏后用云端，是常见折中。

## 5. 日常工作流 SOP（可直接照做）

```text
写新功能
  先让 AI 出方案/接口设计 → 人定架构 → AI 分块生成 → 编译+ASAN+单测 → 人审合入
改 bug
  采证(堆栈/日志) → AI 帮列假设 → 实验定位根因 → 修复 → 让 AI 补回归测试
读源码
  给目录树要架构图 → 按调用链逐文件提问 → 让它出 quiz 考掌握程度
提交前
  AI 跑一遍 Review 清单 → 处理阻断项 → 生成 commit message → 自查 diff
学习/求职
  让它按简历项目出追问、模拟面试、把八股结合项目讲（见《../01-C++技术体系/18-面试与求职/02-简历撰写与项目表达.md》）
```

## 6. 快速参考卡片

```text
幻觉排查：虚构API、版本错配、UB、编的常量、吞异常、过度设计
合入三连：-Wall -Werror 编译过 / 测试+ASAN 过 / 逐行能讲清
保密：规约/密钥/客户数据不外传；脱敏；防 GPL 默写；加密用成熟库
本地化：Ollama + Continue/Cline + Qwen/DeepSeek-Coder；7B/16G 主力；内网用 vLLM
边界：本地模型擅长补全/局部，复杂多文件仍需云端旗舰(脱敏)
```

## 7. 常见问题与坑

| 问题 | 对策 |
| --- | --- |
| 过度信任 AI 代码导致线上 bug | 合入三连不可省，核心并发/安全代码必须人审 |
| 本地模型又慢又笨 | 选 Coder 模型、用量化版、换更小模型做补全、复杂问题交云端 |
| 内网装不上 | 用可联网机拉取模型/依赖后离线导入；确认 CPU 架构与 glibc |
| AI 默写的代码有许可证风险 | 关键模块核查来源，不盲目照抄大段输出 |
| 团队各用各的、提示词不沉淀 | 建团队共享的提示词/规则库（.rules、编码规范喂给工具） |
| 离开 AI 就不会写 | 先自己想方案再让 AI 补，刻意保持独立排错能力，别让基本功退化 |
