## 1. 所有权模型：栈、堆与 move 语义

### 1.1 栈与堆的本质区别

理解所有权的前提是理解栈与堆的内存管理差异：

| 维度 | 栈 (Stack) | 堆 (Heap) |
|---|---|---|
| 分配方式 | 编译器自动分配/释放 | 运行时手动申请/释放 |
| 分配速度 | 极快（移动栈指针） | 较慢（搜索空闲块、可能缺页） |
| 大小要求 | 编译期已知、固定 | 运行时可变 |
| 生命周期 | 随作用域自动结束 | 需手动管理（或 GC/RAII） |
| 访问方式 | 直接访问 | 通过指针间接访问 |
| 典型数据 | 标量、元组、数组、引用 | String、Vec、Box、闭包 |

```rust
fn main() {
    // 栈上数据：固定大小，作用域结束自动释放
    let x = 5;              // i32，4 字节，栈
    let arr = [1, 2, 3];   // [i32; 3]，12 字节，栈

    // 堆上数据：指针在栈，数据在堆
    let s = String::from("hello");
    // 栈上：String 结构体（指针 ptr + 长度 len + 容量 capacity，共 24 字节）
    // 堆上："hello" 的实际字节数据（无末尾 \0，String 不存储空终止符）

    let v = vec![1, 2, 3];
    // 栈上：Vec 结构体（ptr + len + cap，24 字节）
    // 堆上：[1, 2, 3] 的实际数据
}
```

C++ 中栈/堆的区分与 Rust 一致，但 C++ 堆内存需要 `new`/`delete` 手动管理（或依赖智能指针），而 Rust 通过所有权系统在编译期确定释放时机。

### 1.2 所有权三规则

Rust 所有权的核心是三条规则：

1. **每个值有且仅有一个所有者（owner）**
2. **同一时刻只能有一个所有者**
3. **当所有者离开作用域时，值被丢弃（drop），内存自动释放**

```rust
fn main() {
    {                      // s 作用域开始
        let s = String::from("hello"); // s 是 "hello" 的所有者
        // 使用 s
    }                      // s 作用域结束，drop(s) 自动调用，堆内存释放
    // println!("{}", s); // 编译错误：s 已离开作用域
}
```

`drop` 的调用顺序与变量声明顺序相反（栈式 LIFO）：

```rust
fn main() {
    let a = String::from("a");  // 先声明
    let b = String::from("b");  // 后声明
    // 作用域结束时：先 drop(b)，再 drop(a)
}
```

> **对照 C++**：这与 C++ 的 RAII（Resource Acquisition Is Initialization）完全一致——对象离开作用域时析构函数自动调用。但 C++ 的 RAII 只保证"析构函数会被调用"，不保证"资源只有一个所有者"（可以有多个 `shared_ptr`，也可以有裸指针别名）。Rust 的所有权规则在编译期强制单一所有者，从根本上杜绝了 double-free 和 use-after-free。

### 1.3 move 语义与变量失效

对于堆上的数据（非 Copy 类型），赋值或传参时发生 **move**——所有权转移，原变量失效：

```rust
fn main() {
    let s1 = String::from("hello");
    let s2 = s1;  // move：s1 的所有权转移给 s2

    // println!("{}", s1); // 编译错误：value borrowed here after move
    println!("{}", s2);    // OK，s2 是所有者
}
```

内存示意：

```text
move 前：
  栈: s1 { ptr → 堆["hello"], len:5, cap:5 }

move 后：
  栈: s1 { 已失效（编译器标记为未初始化） }
      s2 { ptr → 堆["hello"], len:5, cap:5 }
```

注意：move 只复制栈上的元数据（ptr/len/cap，24 字节的浅拷贝），不复制堆上的数据。这与 C++ 的移动构造函数语义一致，但 Rust 的 move 是**语言级强制**的，且 move 后原变量**编译期不可用**（C++ 中移动后原对象处于"有效但未指定"状态，仍可使用，容易出错）。

```rust
fn main() {
    // 元组中包含非 Copy 类型时，部分 move
    let t = (String::from("hello"), 42);
    let s = t.0;  // move t.0，t.0 失效
    // println!("{}", t.0); // 编译错误
    println!("{}", t.1);    // OK，t.1 是 i32（Copy），未被 move
    // println!("{:?}", t);  // 编译错误：t 部分 move 后不能整体使用
}
```

### 1.4 函数传参与返回值的所有权转移

```rust
fn take_ownership(s: String) -> String {
    println!("took: {}", s);
    s  // 返回所有权
}

fn main() {
    let s1 = String::from("hello");
    let s2 = take_ownership(s1);  // s1 move 进函数，函数返回 s2
    // println!("{}", s1); // 编译错误：s1 已 move
    println!("{}", s2);    // OK
}
```

每次函数调用都要手动转移所有权非常繁琐，这正是**借用（引用）**要解决的问题——允许使用值而不获取所有权。

## 2. Copy 与 Clone：复制的边界

不是所有类型都发生 move。实现了 `Copy` trait 的类型在赋值时发生**位拷贝**（浅拷贝），原变量仍然可用：

```rust
fn main() {
    let x = 5;      // i32 实现了 Copy
    let y = x;      // 位拷贝，x 仍然有效
    println!("x = {}, y = {}", x, y); // 都可用

    let s1 = String::from("hello"); // String 没有实现 Copy
    // let s2 = s1; // move，s1 失效
}
```

**Copy 类型**：所有标量类型（整数、浮点、布尔、字符）、只包含 Copy 类型的元组和数组。`Copy` 是隐式的，不能重载。

**Clone 类型**：显式调用 `.clone()` 进行深拷贝（复制堆数据）。`Clone` 是 `Copy` 的超集（实现 `Copy` 的类型必须实现 `Clone`，且 `Clone` 实现就是位拷贝）。

```rust
fn main() {
    let s1 = String::from("hello");
    let s2 = s1.clone();  // 深拷贝：堆上数据也被复制
    println!("s1 = {}, s2 = {}", s1, s2); // 都可用，各自独立

    // Copy 类型的 clone 等价于位拷贝
    let x = 5;
    let y = x.clone();  // 等价于 let y = x;
}
```

| 特性 | Copy | Clone |
|---|---|---|
| 触发方式 | 隐式（赋值/传参自动） | 显式调用 `.clone()` |
| 行为 | 位拷贝（浅拷贝） | 深拷贝（自定义实现） |
| 性能 | 极快（寄存器/栈拷贝） | 可能慢（堆分配、数据复制） |
| 原变量 | 保持有效 | 保持有效 |
| 实现条件 | 类型及其所有字段都是 Copy | 几乎所有类型都可实现 |
| C++ 对应 | 平凡拷贝（trivial copy） | 拷贝构造函数（深拷贝） |

> **关键判断**：如果一个类型包含堆分配数据（String、Vec、Box 等），它**不能**实现 Copy，因为 Copy 意味着位拷贝后两个变量指向同一块堆内存，会导致 double-free。C++ 中可以通过拷贝构造函数实现深拷贝来"复制"包含堆数据的对象，但这是隐式的、可能昂贵的，Rust 要求显式 `.clone()` 来提醒程序员"这里有性能开销"。

## 3. 借用：引用与借用规则

### 3.1 不可变引用与可变引用

借用（borrowing）通过引用（reference）实现，允许使用值而不获取所有权：

```rust
fn calculate_length(s: &String) -> usize {  // 不可变引用
    s.len()
}  // s 离开作用域，但因为不拥有所有权，不会 drop 引用的值

fn main() {
    let s1 = String::from("hello");
    let len = calculate_length(&s1);  // 借用 s1，不转移所有权
    println!("The length of '{}' is {}.", s1, len); // s1 仍然可用
}
```

可变引用允许修改借用的值：

```rust
fn append_world(s: &mut String) {
    s.push_str(", world");
}

fn main() {
    let mut s = String::from("hello");
    append_world(&mut s);
    println!("{}", s); // "hello, world"
}
```

引用的解引用：Rust 有自动解引用（deref coercion），大多数情况下不需要手动 `*`：

```rust
fn main() {
    let mut x = 5;
    let r = &x;
    println!("{}", *r);  // 手动解引用，5
    println!("{}", r);   // 自动解引用（通过 Deref），5

    let mr = &mut x;
    *mr += 1;  // 修改需要手动解引用
    println!("{}", x); // 6
}
```

### 3.2 借用三规则

借用检查器（borrow checker）强制执行三条规则：

1. **同一时刻，可以有任意多个不可变引用（`&T`），或者只能有一个可变引用（`&mut T`），二者不可同时存在**
2. **引用必须始终有效（不能悬垂）**
3. **可变引用在使用期间，原变量和其他引用都不能使用**

```rust
fn main() {
    let mut s = String::from("hello");

    // 规则1：多个不可变引用 OK
    let r1 = &s;
    let r2 = &s;
    println!("{} and {}", r1, r2);

    // 规则1：可变引用 + 不可变引用同时存在 → 编译错误
    // let r3 = &mut s;  // 编译错误：cannot borrow `s` as mutable
    //                   // because it is also borrowed as immutable

    // 正确：不可变引用使用完毕后，再创建可变引用（NLL 帮助）
    let r3 = &mut s;
    r3.push_str("!");
    println!("{}", r3);
}
```

> **设计哲学**：这条规则的本质是"读多写一"并发控制的编译期实现。多个读者（不可变引用）不会互相干扰，但写者（可变引用）必须独占，否则会产生数据竞争。C++ 中这完全依赖程序员自觉（`const` 引用和非 `const` 引用可以同时存在），数据竞争是运行时 bug。Rust 在编译期杜绝了这一类问题。

### 3.3 NLL：非词法生命周期

早期 Rust（2015 edition）的借用检查是词法的（lexical lifetime）——引用的生命周期持续到作用域结束。Rust 2018 引入 NLL（Non-Lexical Lifetimes），引用的生命周期只持续到**最后一次使用**：

```rust
fn main() {
    let mut s = String::from("hello");

    let r1 = &s;        // 不可变借用开始
    println!("{}", r1); // r1 最后一次使用
    // NLL：r1 的生命周期在此结束（不是到作用域结束）

    let r2 = &mut s;    // 可变借用 OK，因为 r1 已不再使用
    r2.push_str("!");
    println!("{}", r2);
}
```

如果没有 NLL（词法生命周期），上面的代码会编译错误，因为 `r1` 的生命周期持续到 `}`。NLL 大幅减少了"明明没问题但编译器报错"的情况，是 Rust 可用性的重大改进。

```rust
fn main() {
    // NLL 仍无法处理的情况：引用在后续条件分支中使用
    let mut s = String::from("hello");
    let r1 = &s;
    let r2 = &mut s;     // 编译错误
    // if some_condition {
    //     println!("{}", r1); // r1 在这里可能被使用，所以生命周期不能提前结束
    // }
}
```

### 3.4 悬垂引用防范

C++ 中最常见的 bug 之一是悬垂引用（dangling reference）——引用指向已被释放的内存。Rust 借用检查器在编译期杜绝：

```rust
fn dangle() -> &String {  // 编译错误：missing lifetime specifier
    let s = String::from("hello");
    &s  // 返回对局部变量的引用
}      // s 在此 drop，引用悬垂！

fn main() {
    let reference_to_nothing = dangle();
}
```

编译器直接拒绝返回局部变量引用的函数。正确做法是直接返回所有权（`String`），让调用者决定生命周期：

```rust
fn no_dangle() -> String {
    let s = String::from("hello");
    s  // 返回所有权，不返回引用
}
```

## 4. 生命周期标注

### 4.1 为什么需要生命周期标注

生命周期（lifetime）是引用的有效期。大多数情况下编译器能自动推导，但当函数返回引用、或结构体包含引用时，编译器需要程序员显式标注来明确引用之间的关系：

```rust
// 编译错误：编译器不知道返回的引用指向 x 还是 y
// fn longest(x: &str, y: &str) -> &str {
//     if x.len() > y.len() { x } else { y }
// }

// 正确：生命周期标注 'a 表示 x、y 和返回值有相同的生命周期
fn longest<'a>(x: &'a str, y: &'a str) -> &'a str {
    if x.len() > y.len() { x } else { y }
}
```

生命周期标注不改变引用的实际生命周期，只是**描述引用之间的关系**，帮助编译器验证引用的有效性。

### 4.2 函数签名中的生命周期

```rust
// 单生命周期：所有引用共享同一生命周期
fn first_word<'a>(s: &'a str) -> &'a str {
    // 返回值的生命周期与参数 s 相同
    s.split_whitespace().next().unwrap_or("")
}

// 多生命周期：不同参数有不同生命周期
fn pick<'a, 'b>(x: &'a str, y: &'b str, use_x: bool) -> &'a str {
    // 返回值只与 x 的生命周期相关
    if use_x { x } else { "default" }
}

// 生命周期约束：'b 至少和 'a 一样长（'b: 'a）
fn select<'a, 'b>(x: &'a str, y: &'b str) -> &'a str
where
    'b: 'a,  // 'b 活得比 'a 长或相等
{
    if x.len() > y.len() { x } else { y }
}
```

### 4.3 结构体中的生命周期

结构体包含引用时，必须标注生命周期：

```rust
// 结构体持有一个字符串切片引用
struct ImportantExcerpt<'a> {
    part: &'a str,  // part 引用的数据必须比结构体活得长
}

fn main() {
    let novel = String::from("Call me Ishmael. Some years ago...");
    let first_sentence = novel.split('.').next().expect("Could not find a '.'");
    let excerpt = ImportantExcerpt {
        part: first_sentence,  // 引用 novel 的一部分
    };
    println!("{}", excerpt.part);
}  // excerpt 先 drop，然后 novel drop，顺序正确
```

如果结构体引用的数据比结构体先释放，编译器会报错：

```rust
fn main() {
    let excerpt;
    {
        let novel = String::from("Call me Ishmael.");
        excerpt = ImportantExcerpt { part: &novel };
    }  // novel 在此 drop
    // println!("{}", excerpt.part); // 编译错误：novel does not live long enough
}
```

### 4.4 impl 块中的生命周期

```rust
struct ImportantExcerpt<'a> {
    part: &'a str,
}

// impl 块必须声明生命周期参数
impl<'a> ImportantExcerpt<'a> {
    // 方法返回 &self 的引用时，生命周期自动与 self 关联（省略规则）
    fn part(&self) -> &str {
        self.part
    }

    // 显式标注
    fn announce_and_return_part(&self, announcement: &str) -> &str {
        println!("Attention please: {}", announcement);
        self.part
    }
}
```

### 4.5 三条省略规则 elision

编译器在以下情况可以自动推导生命周期，无需显式标注（称为 lifetime elision）：

1. **每个引用参数都获得独立的生命周期**：`fn foo(x: &T, y: &U)` → `fn foo<'a, 'b>(x: &'a T, y: &'b U)`
2. **如果只有一个输入生命周期，它被赋给所有输出生命周期**：`fn foo(x: &T) -> &U` → `fn foo<'a>(x: &'a T) -> &'a U`
3. **如果有多个输入生命周期，但其中一个是 `&self` 或 `&mut self`（方法），则 self 的生命周期被赋给所有输出生命周期**

```rust
// 规则1+2：单输入引用，输出生命周期自动匹配
fn first_word(s: &str) -> &str {  // 等价于 fn first_word<'a>(s: &'a str) -> &'a str
    s.split_whitespace().next().unwrap_or("")
}

// 规则3：方法，输出生命周期匹配 self
impl<'a> ImportantExcerpt<'a> {
    fn get_part(&self) -> &str {  // 等价于 fn get_part<'b>(&'b self) -> &'b str
        self.part
    }
}

// 不能省略的情况：多个输入引用且返回引用，编译器无法确定关系
// fn longest(x: &str, y: &str) -> &str { ... } // 编译错误，必须显式标注
```

### 4.6 'static 的双重含义

`'static` 是 Rust 中最容易混淆的生命周期，它有两种含义：

1. **作为生命周期标注**：引用的数据在整个程序运行期间都有效
2. **作为 trait bound**：类型不包含任何非 'static 引用（可以安全地跨线程传递）

```rust
// 含义1：'static 生命周期引用
fn main() {
    let s: &'static str = "hello";  // 字符串字面量存储在只读数据段，整个程序有效
    // 等价于 C++ 的 static const char*
}

// 含义2：'static trait bound
fn print_type<T: 'static>(t: T) {
    // T 不包含任何短生命周期的引用，可以安全存储/跨线程
    println!("type is static");
}

fn main() {
    print_type(42);              // OK，i32 是 'static
    print_type(String::from("x")); // OK，String 拥有数据，是 'static

    let s = String::from("hello");
    // print_type(&s);  // 编译错误：&s 有非 'static 生命周期
}
```

> **常见误解**：`'static` 不等于"永远不释放"。作为 trait bound，`T: 'static` 只表示 T 内部没有借用外部数据的引用，T 本身可以被正常 drop。`String` 是 `'static`（因为它拥有堆数据，不借用任何东西），但 `String` 离开作用域时会被正常释放。

## 5. 综合示例：链表节点与借用

```rust
use std::collections::HashMap;

// 结构体包含引用，需要生命周期标注
struct Config<'a> {
    name: &'a str,
    values: &'a [i32],
}

impl<'a> Config<'a> {
    fn new(name: &'a str, values: &'a [i32]) -> Self {
        Config { name, values }
    }

    fn sum(&self) -> i32 {
        self.values.iter().sum()
    }
}

// 函数返回引用，需要生命周期
fn find_max<'a>(items: &'a [i32]) -> Option<&'a i32> {
    items.iter().max()
}

// 借用规则综合运用
fn process_data() {
    let mut data = vec![1, 2, 3, 4, 5];

    // 多个不可变借用
    let r1 = &data[0..2];
    let r2 = &data[2..4];
    println!("r1: {:?}, r2: {:?}", r1, r2);
    // r1, r2 最后一次使用，NLL 结束它们的生命周期

    // 可变借用
    data.push(6);
    println!("data: {:?}", data);

    // 可变引用使用期间不能访问原变量
    let mref = &mut data;
    mref.push(7);
    // println!("{:?}", data); // 编译错误：data 被可变借用
    println!("{:?}", mref);   // OK，通过 mref 访问
}

fn main() {
    let values = [10, 20, 30];
    let config = Config::new("test", &values);
    println!("{} sum = {}", config.name, config.sum());

    if let Some(max) = find_max(&values) {
        println!("max = {}", max);
    }

    process_data();
}
```

## 6. 12 个常见编译错误全解

### 错误 1：value used here after move

```text
error[E0382]: borrow of moved value: `s1`
 --> src/main.rs:4:20
  |
2 |     let s1 = String::from("hello");
  |         -- move occurs because `s1` has type `String`, which does not implement the `Copy` trait
3 |     let s2 = s1;
  |              -- value moved here
4 |     println!("{}", s1);
  |                    ^^ value borrowed here after move
```
**原因**：非 Copy 类型赋值发生 move，原变量失效。
**修复**：使用 `clone()` 深拷贝，或重新设计避免需要两个所有者。
```rust
let s1 = String::from("hello");
let s2 = s1.clone();  // 深拷贝
println!("{}", s1);   // OK
```

### 错误 2：cannot borrow as mutable because it is also borrowed as immutable

```text
error[E0502]: cannot borrow `s` as mutable because it is also borrowed as immutable
 --> src/main.rs:5:14
  |
4 |     let r1 = &s;
  |              -- immutable borrow occurs here
5 |     let r2 = &mut s;
  |              ^^^^^^^^ mutable borrow occurs here
6 |     println!("{}", r1);
  |                    -- immutable borrow later used here
```
**原因**：不可变引用和可变引用同时存在（且不可变引用后续仍被使用）。
**修复**：确保不可变引用使用完毕后再创建可变引用（NLL 会帮助），或用独立作用域隔离。
```rust
let r1 = &s;
println!("{}", r1);  // r1 最后一次使用
let r2 = &mut s;     // OK，NLL 后 r1 生命周期已结束
r2.push_str("!");
```

### 错误 3：cannot assign to immutable variable

```text
error[E0384]: cannot assign twice to immutable variable `x`
```
**原因**：`let x` 默认不可变。**修复**：`let mut x = 5;`

### 错误 4：missing lifetime specifier

```text
error[E0106]: missing lifetime specifier
 --> src/main.rs:1:23
  |
1 | fn longest(x: &str, y: &str) -> &str {
  |                       ^     ^     ^ expected named lifetime parameter
  |
  = help: this function's return type contains a borrowed value, but the signature does not say whether it is borrowed from `x` or `y`
```
**原因**：函数返回引用但有多个输入引用，编译器无法确定返回值与哪个参数关联。
**修复**：添加生命周期标注。
```rust
fn longest<'a>(x: &'a str, y: &'a str) -> &'a str {
    if x.len() > y.len() { x } else { y }
}
```

### 错误 5：does not live long enough

```text
error[E0597]: `s` does not live long enough
 --> src/main.rs:3:17
  |
2 |     let r;
3 |     let s = String::from("hello");
  |         - binding `s` declared here
4 |     r = &s;
  |         ^^ borrowed value does not live long enough
5 | }
  | - `s` dropped here while still borrowed
```
**原因**：引用的数据比引用先释放（悬垂引用）。
**修复**：调整变量声明顺序，确保被引用者活得更久，或直接返回所有权。
```rust
let s = String::from("hello");  // 先声明（活得更久）
let r = &s;                       // 后声明
println!("{}", r);
```

### 错误 6：cannot move out of borrowed content

```text
error[E0507]: cannot move out of a shared reference
 --> src/main.rs:3:18
  |
3 |     let s = r.0;
  |                  ^^^^^ move occurs because value has type `String`, which does not implement the `Copy` trait
```
**原因**：试图从引用中 move 出非 Copy 类型的数据。
**修复**：使用 `clone()`，或解构引用，或重新设计。
```rust
let t = (String::from("hello"), 42);
let r = &t;
let s = r.0.clone();  // clone 而非 move
```

### 错误 7：temporary value dropped while borrowed

```text
error[E0716]: temporary value dropped while borrowed
 --> src/main.rs:2:13
  |
2 |     let s = &String::from("hello");
  |             ^^^^^^^^^^^^^^^^^^^^^^^ creates a temporary value which is freed while still in use
3 |     println!("{}", s);
4 | }
  | - temporary value is freed at the end of this statement
```
**原因**：引用指向一个临时值（表达式创建的未命名值），临时值在语句结束后 drop。
**修复**：将临时值绑定到变量，延长其生命周期。
```rust
let s = String::from("hello");  // 绑定到变量
let r = &s;
println!("{}", r);
```

### 错误 8：cannot borrow `*self` as mutable more than once at a time

```text
error[E0499]: cannot borrow `*self` as mutable more than once at a time
```
**原因**：方法中同时存在多个对 `self` 的可变借用（常见于同时调用两个 `&mut self` 方法）。
**修复**：拆分操作，先计算需要的值再调用第二个方法，或使用 std::mem::replace。
```rust
// 错误写法
// self.push(self.pop().unwrap());

// 正确写法：先取出值，结束第一个借用，再 push
let val = self.pop().unwrap();
self.push(val);
```

### 错误 9：the trait `Copy` is not implemented

```text
error[E0277]: the trait bound `MyStruct: Copy` is not satisfied
```
**原因**：试图对非 Copy 类型进行隐式拷贝（如在需要 Copy 的上下文中使用）。
**修复**：如果类型适合 Copy，派生 `Copy` 和 `Clone`；否则使用 `clone()` 或 move。
```rust
#[derive(Clone, Copy)]
struct Point { x: i32, y: i32 }
```

### 错误 10：lifetime may not live long enough

```text
error[E0597]: `x` does not live long enough
```
**原因**：函数或结构体要求某个引用的生命周期满足特定约束，但实际引用不够长。
**修复**：调整生命周期标注，或延长被引用数据的生命周期。

### 错误 11：cannot return reference to local variable

```text
error[E0515]: cannot return reference to local variable `s`
 --> src/main.rs:2:5
  |
2 |     &s
  |     ^^ returns a reference to data owned by the current function
```
**原因**：函数返回对局部变量的引用，局部变量在函数返回时 drop。
**修复**：返回拥有所有权的类型（String 而非 &str），或让调用者传入缓冲区。
```rust
fn make_string() -> String {
    String::from("hello")  // 返回所有权
}
```

### 错误 12：second mutable borrow occurs here

```text
error[E0499]: cannot borrow `v` as mutable more than once at a time
 --> src/main.rs:4:14
  |
3 |     let first = &mut v[0];
  |                  --------- first mutable borrow occurs here
4 |     let second = &mut v[1];
  |                  ^^^^^^^^^^ second mutable borrow occurs here
```
**原因**：对同一个 Vec 的不同元素同时可变借用，编译器保守地认为是对整个 Vec 的借用。
**修复**：使用 `split_at_mut` 安全地拆分可变切片，或重构代码。
```rust
let (left, right) = v.split_at_mut(1);
let first = &mut left[0];
let second = &mut right[0];
```

## 7. 对照 C++：RAII / 智能指针 / 引用

| 维度 | Rust | C++ |
|---|---|---|
| 内存管理 | 所有权系统（编译期） | RAII + 智能指针（约定+运行时） |
| 单一所有者 | 编译期强制（move 后原变量失效） | `unique_ptr`（约定，可被 `release`/`reset` 绕过） |
| 共享所有权 | `Rc<T>`/`Arc<T>`（引用计数） | `shared_ptr<T>`（引用计数，线程安全） |
| 循环引用 | `Weak<T>` 打破，无自动回收 | `weak_ptr<T>` 打破，无自动回收 |
| 不可变引用 | `&T`（编译期 enforce 不可变） | `const T&`（可被 const_cast 去除） |
| 可变引用 | `&mut T`（独占，编译期 enforce） | `T&`（可同时存在多个，无独占约束） |
| 悬垂引用 | 编译期杜绝 | 运行时 bug（最常见的内存错误之一） |
| double-free | 编译期杜绝（单一所有者） | 运行时 bug（多个 delete 同一指针） |
| use-after-free | 编译期杜绝 | 运行时 bug |
| 数据竞争 | 编译期杜绝（Send/Sync + 借用规则） | 运行时 bug（需 mutex 等同步） |
| 移动语义 | 语言级强制，move 后原变量编译期不可用 | 移动构造/赋值，移动后原对象"有效但未指定" |
| 拷贝 | Copy（隐式位拷贝）/ Clone（显式深拷贝） | 拷贝构造（隐式，可能深拷贝） |
| 生命周期 | 显式标注 + 省略规则，编译期验证 | 无对应概念，依赖程序员管理 |

> **核心差异总结**：C++ 的内存安全是"约定 + 工具"（RAII 约定、智能指针、valgrind/ASan 检测），而 Rust 的内存安全是"语言 + 编译器"（所有权规则、借用检查器、生命周期标注）。C++ 中"正确使用智能指针"需要程序员自觉，而 Rust 中"不正确使用"根本无法通过编译。这就是 Rust 承诺"零成本抽象 + 内存安全"的核心机制。

可进一步对照《08-智能指针与内存模型.md》和《../../01-C++技术体系/04-并发编程/04-原子操作与C++内存模型.md》理解跨语言内存模型差异。

| 结构体存引用 | 必须标注：`struct Parser<'a> { src: &'a str }` |
| 高频错误码 | E0382 move 后用、E0499 两次可变借用、E0502 可变+不可变、E0505、E0106 缺标注、E0515 返回局部引用 |

## 9. 本节小结

- **所有权**：每个值有唯一所有者，所有者离开作用域时值 drop。非 Copy 类型赋值/传参发生 move，原变量编译期失效。这从根本上杜绝了 double-free。
- **Copy/Clone**：Copy 类型（标量、全 Copy 字段的复合类型）隐式位拷贝，原变量保持有效；非 Copy 类型需显式 `.clone()` 深拷贝。这一区分提醒程序员注意拷贝开销。
- **借用规则**：同一时刻要么多个不可变引用，要么一个可变引用，二者不可共存。这是"读多写一"并发控制的编译期实现，杜绝数据竞争。
- **NLL**：非词法生命周期让引用只持续到最后一次使用，大幅减少了误报，是 Rust 2018 的关键改进。
- **悬垂引用**：借用检查器在编译期验证所有引用始终有效，杜绝了 C++ 中最常见的 use-after-free。
- **生命周期标注**：描述引用之间的关系，不改变实际生命周期。三条省略规则覆盖了大多数常见模式，无需处处标注。
- **'static**：双重含义——作为生命周期表示整个程序有效，作为 trait bound 表示类型不含短生命周期引用。
- **12 个常见编译错误**：每个都有明确的错误信息、原因和修复方案，是学习所有权系统的最佳练习素材。
- **与 C++ 对照**：Rust 将 C++ 中依赖约定和运行时检测的内存安全问题，提升为编译期强制保证，代价是学习曲线和某些编程模式的限制。
