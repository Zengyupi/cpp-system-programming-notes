## 1. 智能指针概览

智能指针（smart pointer）是一类在指针语义基础上增加额外功能的类型。Rust 中智能指针的共同特征是实现了 `Deref` 和 `Drop` trait：

- `Deref`：允许智能指针像引用一样使用（自动解引用）
- `Drop`：在智能指针离开作用域时自动执行清理逻辑（释放内存等）

| 智能指针 | 功能 | 线程安全 | C++ 对应 |
|---|---|---|---|
| `Box<T>` | 堆分配，单一所有权 | 是 | `std::unique_ptr<T>` |
| `Rc<T>` | 单线程引用计数 | 否 | 无直接对应（`std::shared_ptr` 是线程安全的） |
| `Arc<T>` | 多线程引用计数 | 是 | `std::shared_ptr<T>` |
| `Weak<T>` | 弱引用，不增加计数 | 是/否（对应 Arc/Rc） | `std::weak_ptr<T>` |
| `RefCell<T>` | 运行时借用检查，内部可变性 | 否 | 无直接对应 |
| `Cell<T>` | Copy 类型内部可变性 | 否 | 无直接对应 |
| `Cow<T>` | 写时克隆 | 是 | 无直接对应 |

## 2. Box：堆分配与递归类型

### 2.1 基本用法与内存布局

`Box<T>` 是最简单的智能指针，在堆上分配内存并拥有唯一所有权：

```rust
fn main() {
    // 栈分配
    let a = 5;  // i32，栈上 4 字节

    // 堆分配：Box 在栈上（8 字节指针），数据在堆上
    let b = Box::new(5);  // Box<i32>
    println!("b = {}", b);  // 自动解引用，输出 5

    // 解引用
    println!("*b = {}", *b);  // 5

    // Box 实现了 Deref，可以像 &T 一样使用
    fn print_i32(x: &i32) { println!("{}", x); }
    print_i32(&b);  // &Box<i32> → &i32（Deref coercion）

    // 消费 Box，获取堆数据的所有权
    let b = Box::new(String::from("hello"));
    let s: String = *b;  // 解引用 move 出数据（String 不是 Copy）
    // println!("{}", b); // 编译错误：b 已被 move（部分 move）
    println!("{}", s);    // hello
}
```

内存布局（64 位平台）：

```text
栈: b (8 字节，指针) ──→ 堆: 5 (4 字节，i32)
```

`Box<T>` 本身在栈上只有一个指针（8 字节），数据在堆上。当 `Box` 离开作用域时，`drop` 被调用，释放堆内存。

### 2.2 递归类型与 DST

`Box` 的关键用途是定义递归类型（大小在编译期无法确定）：

```rust
// 编译错误：recursive type `List` has infinite size
// enum List {
//     Cons(i32, List),  // List 包含 List，大小无限
//     Nil,
// }

// 正确：用 Box 间接递归（Box 是固定大小的指针）
#[derive(Debug)]
enum List {
    Cons(i32, Box<List>),
    Nil,
}

fn main() {
    use List::{Cons, Nil};

    let list = Cons(1, Box::new(Cons(2, Box::new(Cons(3, Box::new(Nil))))));
    println!("{:?}", list);
}
```

递归类型必须用 `Box`（或其他指针）间接，因为编译器需要在编译期知道类型大小。直接递归会导致无限大小。

### 2.3 Box 的特殊能力

```rust
fn main() {
    // Box::leak：泄漏 Box，返回 &'static mut T
    // 适用于需要整个程序生命周期的配置等
    let config: &'static mut String = Box::leak(Box::new(String::from("config")));
    config.push_str("!");
    println!("{}", config);

    // Box::into_raw / Box::from_raw：与裸指针互转（FFI 常用）
    let b = Box::new(42);
    let ptr = Box::into_raw(b);  // *mut i32
    unsafe {
        println!("{}", *ptr);  // 42
        let b = Box::from_raw(ptr);  // 重新获得 Box（负责释放）
    }

    // 零大小类型的 Box：不实际分配堆内存
    let zero = Box::new(());
    println!("size of Box<()>: {}", std::mem::size_of_val(&zero));  // 8（指针大小）
}
```

## 3. Rc：单线程引用计数

### 3.1 基本用法与引用计数

`Rc<T>`（Reference Counted）允许在单线程中共享所有权，通过引用计数管理内存：

```rust
use std::rc::Rc;

fn main() {
    let a = Rc::new(String::from("hello"));
    println!("a count = {}", Rc::strong_count(&a));  // 1

    {
        let b = Rc::clone(&a);  // 克隆引用，增加计数（不深拷贝数据）
        println!("a count = {}", Rc::strong_count(&a));  // 2
        println!("b count = {}", Rc::strong_count(&b));  // 2
        println!("b = {}", b);  // hello
    }  // b drop，计数减 1

    println!("a count = {}", Rc::strong_count(&a));  // 1
}  // a drop，计数减到 0，释放堆内存
```

关键特性：
- `Rc::clone()` 只增加引用计数（O(1)），不深拷贝数据
- 最后一个 `Rc` drop 时，引用计数为 0，释放数据
- `Rc` 只能用于单线程（引用计数不是原子操作，无 `Send`）
- `Rc` 中的数据是不可变的（需要可变性用 `RefCell`）

### 3.2 Rc::strong_count 与 Weak

`Rc` 有两种引用计数：
- **强引用（strong count）**：拥有所有权，计数为 0 时释放数据
- **弱引用（weak count）**：不拥有所有权，不阻止数据释放

```rust
use std::rc::{Rc, Weak};

fn main() {
    let strong = Rc::new(42);
    let weak = Rc::downgrade(&strong);  // 创建弱引用

    println!("strong count = {}", Rc::strong_count(&strong));  // 1
    println!("weak count = {}", Rc::weak_count(&strong));      // 1

    // 弱引用升级为强引用（数据可能已释放，返回 Option）
    if let Some(strong2) = weak.upgrade() {
        println!("upgraded: {}", strong2);  // 42
    }

    // 释放所有强引用
    drop(strong);
    // drop(strong2);  // 如果上面升级了，这里也要 drop

    // 弱引用无法升级（数据已释放）
    println!("upgrade after drop: {:?}", weak.upgrade());  // None
}
```

### 3.3 内部可变性：Rc<RefCell<T>>

`Rc` 中的数据默认不可变。需要共享可变数据时，组合 `Rc<RefCell<T>>`：

```rust
use std::rc::Rc;
use std::cell::RefCell;

fn main() {
    let shared = Rc::new(RefCell::new(vec![1, 2, 3]));

    let shared1 = Rc::clone(&shared);
    let shared2 = Rc::clone(&shared);

    // 通过 RefCell 可变借用修改
    shared1.borrow_mut().push(4);
    shared2.borrow_mut().push(5);

    println!("{:?}", shared.borrow());  // [1, 2, 3, 4, 5]
}
```

这是 Rust 中实现"共享可变状态"的常见模式，详见后续 RefCell 章节。

## 4. Arc：多线程引用计数

### 4.1 与 Rc 的区别

`Arc<T>`（Atomic Reference Counted）是 `Rc` 的线程安全版本，引用计数使用原子操作：

```rust
use std::sync::Arc;
use std::thread;

fn main() {
    let data = Arc::new(vec![1, 2, 3]);
    let mut handles = vec![];

    for _ in 0..3 {
        let data = Arc::clone(&data);  // 原子增加引用计数
        let handle = thread::spawn(move || {
            println!("{:?}", data);
        });
        handles.push(handle);
    }

    for h in handles {
        h.join().unwrap();
    }
}
```

| 特性 | Rc<T> | Arc<T> |
|---|---|---|
| 引用计数 | 普通整数（非原子） | 原子整数（AtomicUsize） |
| 线程安全 | 否（!Send, !Sync） | 是（Send, Sync） |
| 性能 | 快（无原子开销） | 稍慢（原子操作开销） |
| 适用场景 | 单线程共享所有权 | 多线程共享所有权 |
| C++ 对应 | 无 | `std::shared_ptr<T>` |

> **选择原则**：单线程用 `Rc`（性能更好），跨线程用 `Arc`。编译器会阻止将 `Rc` 传递到另一个线程（因为 `Rc: !Send`），所以不会出错。

### 4.2 Arc<Mutex<T>> 组合

与 `Rc<RefCell<T>>` 类似，多线程共享可变数据用 `Arc<Mutex<T>>`：

```rust
use std::sync::{Arc, Mutex};
use std::thread;

fn main() {
    let counter = Arc::new(Mutex::new(0));
    let mut handles = vec![];

    for _ in 0..10 {
        let counter = Arc::clone(&counter);
        let handle = thread::spawn(move || {
            let mut num = counter.lock().unwrap();
            *num += 1;
        });
        handles.push(handle);
    }

    for h in handles {
        h.join().unwrap();
    }

    println!("Result: {}", *counter.lock().unwrap());  // 10
}
```

`Arc<Mutex<T>>` 是 Rust 多线程共享可变状态的经典组合，可对照《../../01-C++技术体系/04-并发编程/02-互斥锁与死锁.md》理解。

## 5. RefCell 与 Cell：运行时借用与内部可变性

### 5.1 Cell：Copy 类型的内部可变性

`Cell<T>` 适用于 `Copy` 类型，提供内部可变性（通过 `get`/`set`）：

```rust
use std::cell::Cell;

fn main() {
    let x = Cell::new(5);  // x 不可变绑定
    x.set(10);              // 但可以修改内部值（内部可变性）
    println!("x = {}", x.get());  // 10

    // Cell 在结构体中的应用：不可变结构体中的可变字段
    struct Counter {
        count: Cell<u32>,
    }

    impl Counter {
        fn new() -> Self {
            Counter { count: Cell::new(0) }
        }

        fn increment(&self) {  // &self（不可变借用），但可以修改 count
            self.count.set(self.count.get() + 1);
        }
    }

    let counter = Counter::new();  // 不可变绑定
    counter.increment();            // 可以调用（内部可变性）
    counter.increment();
    println!("count = {}", counter.count.get());  // 2
}
```

`Cell` 的特点：
- 只适用于 `Copy` 类型（`get` 返回值的拷贝）
- 无运行时借用检查（因为每次 `get`/`set` 都是值拷贝，不存在引用别名）
- 性能开销极小（就是一个普通的 `UnsafeCell` 包装）

### 5.2 RefCell：运行时借用检查

`RefCell<T>` 适用于非 `Copy` 类型，在运行时执行借用检查：

```rust
use std::cell::RefCell;

fn main() {
    let data = RefCell::new(vec![1, 2, 3]);

    // 不可变借用（可以有多个）
    let r1 = data.borrow();
    let r2 = data.borrow();
    println!("r1: {:?}, r2: {:?}", r1, r2);
    // r1, r2 在此之后不再使用（NLL 对 RefCell 不适用，需要手动 drop）

    // 必须显式结束不可变借用，才能可变借用
    drop(r1);
    drop(r2);

    // 可变借用（只能有一个）
    let mut r3 = data.borrow_mut();
    r3.push(4);
    println!("r3: {:?}", r3);
    drop(r3);

    println!("final: {:?}", data.borrow());  // [1, 2, 3, 4]
}
```

运行时借用违反会 panic（不是编译错误）：

```rust
use std::cell::RefCell;

fn main() {
    let data = RefCell::new(5);

    let r1 = data.borrow();       // 不可变借用
    // let r2 = data.borrow_mut(); // panic: already borrowed
    // thread 'main' panicked at 'already borrowed: BorrowMutError'
}
```

`RefCell` 的方法：
- `borrow()`：不可变借用，返回 `Ref<T>`（智能指针），已有可变借用则 panic
- `borrow_mut()`：可变借用，返回 `RefMut<T>`，已有任何借用则 panic
- `try_borrow()`/`try_borrow_mut()`：不 panic，返回 `Result`

### 5.3 编译期 vs 运行时借用检查

| 维度 | 编译期检查（普通引用） | 运行时检查（RefCell） |
|---|---|---|
| 检查时机 | 编译期 | 运行时 |
| 错误处理 | 编译错误 | panic（或 Result） |
| 性能开销 | 零 | 微小（借用计数器） |
| 内部可变性 | 不支持 | 支持 |
| NLL | 支持 | 不支持（需手动 drop） |
| 适用场景 | 大多数情况 | 需要内部可变性、编译期无法证明安全时 |

> **设计哲学**：Rust 的借用检查器是保守的——有些实际上安全的模式无法通过编译期检查（如多个对象互相引用、观察者模式）。`RefCell` 将检查推迟到运行时，在这些场景下提供了"逃生舱"。代价是运行时 panic 的风险，所以 `RefCell` 应该谨慎使用，优先尝试重构代码通过编译期检查。

## 6. Weak：打破引用循环

`Rc`/`Arc` 的引用计数机制无法自动回收循环引用。`Weak`（弱引用）不增加强引用计数，用于打破循环：

```rust
use std::rc::{Rc, Weak};
use std::cell::RefCell;

#[derive(Debug)]
struct Node {
    value: i32,
    parent: RefCell<Weak<Node>>,   // 弱引用：不阻止 parent 释放
    children: RefCell<Vec<Rc<Node>>>, // 强引用：拥有 children
}

fn main() {
    let leaf = Rc::new(Node {
        value: 3,
        parent: RefCell::new(Weak::new()),
        children: RefCell::new(vec![]),
    });

    let branch = Rc::new(Node {
        value: 5,
        parent: RefCell::new(Weak::new()),
        children: RefCell::new(vec![Rc::clone(&leaf)]),
    });

    // leaf 的 parent 指向 branch（弱引用）
    *leaf.parent.borrow_mut() = Rc::downgrade(&branch);

    // 通过弱引用访问 parent
    if let Some(parent) = leaf.parent.borrow().upgrade() {
        println!("leaf parent value = {}", parent.value);  // 5
    }

    // 引用计数
    println!("branch strong = {}", Rc::strong_count(&branch));  // 1
    println!("leaf strong = {}", Rc::strong_count(&leaf));      // 2（branch.children + leaf 本身）
}
```

如果用 `Rc` 而非 `Weak` 做 parent 指针，会形成循环引用（branch → leaf → branch），引用计数永远不为 0，内存泄漏。`Weak` 不增加强引用计数，打破了循环。

> **对照 C++**：这与 C++ 的 `shared_ptr`/`weak_ptr` 完全一致。C++ 中也需要用 `weak_ptr` 打破 `shared_ptr` 的循环引用。Rust 的 `Weak` 升级返回 `Option<Rc<T>>`（数据可能已释放），C++ 的 `weak_ptr::lock()` 返回 `shared_ptr<T>`（空表示已释放），语义一致。

## 7. Deref 强转链

`Deref` trait 是智能指针的核心，允许自动解引用：

```rust
use std::ops::Deref;

struct MyBox<T>(T);

impl<T> MyBox<T> {
    fn new(x: T) -> Self { MyBox(x) }
}

impl<T> Deref for MyBox<T> {
    type Target = T;
    fn deref(&self) -> &Self::Target {
        &self.0
    }
}

fn main() {
    let b = MyBox::new(String::from("hello"));

    // 手动解引用
    println!("{}", *b);  // *(b.deref()) = "hello"

    // Deref coercion：函数参数自动解引用
    fn print_str(s: &str) { println!("{}", s); }
    print_str(&b);  // &MyBox<String> → &String → &str（链式解引用）

    // 方法调用自动解引用
    println!("length = {}", b.len());  // b.deref().len() = String::len
}
```

Deref coercion 规则：
- 当 `T: Deref<Target=U>` 时，`&T` 自动转换为 `&U`
- 可以链式发生：`&Box<String>` → `&String` → `&str`
- 只在函数/方法参数和赋值时发生，不在比较运算中发生

标准库中的 Deref 实现：
- `Box<T>` → `T`
- `Rc<T>` → `T`
- `Arc<T>` → `T`
- `String` → `str`
- `Vec<T>` → `[T]`
- `&T` → `T`（如果 T: Deref）

## 8. Drop 顺序与主动释放

`Drop` trait 定义值离开作用域时的清理逻辑：

```rust
struct CustomSmartPointer {
    data: String,
}

impl Drop for CustomSmartPointer {
    fn drop(&mut self) {
        println!("Dropping CustomSmartPointer with data `{}`!", self.data);
    }
}

fn main() {
    let c = CustomSmartPointer { data: String::from("my stuff") };
    let d = CustomSmartPointer { data: String::from("other stuff") };
    println!("CustomSmartPointers created.");

    // 主动释放（不能直接调用 c.drop()，会被编译器阻止）
    drop(c);  // std::mem::drop，提前释放
    println!("CustomSmartPointer c dropped before end of main.");
}
// 输出：
// CustomSmartPointers created.
// Dropping CustomSmartPointer with data `my stuff`!
// CustomSmartPointer c dropped before end of main.
// Dropping CustomSmartPointer with data `other stuff`!
```

Drop 顺序规则：
- 局部变量按声明的**逆序** drop（LIFO，栈式）
- 结构体字段按声明**顺序** drop（与局部变量相反）
- 元组/数组元素按顺序 drop
- `Box`/`Rc`/`Arc` drop 时先 drop 指针本身，然后 drop 指向的数据（如果计数为 0）

```rust
fn main() {
    // 局部变量逆序 drop
    let a = String::from("a");  // 先声明
    let b = String::from("b");  // 后声明
    // drop 顺序：b → a
}

struct Foo {
    x: String,  // 先声明
    y: String,  // 后声明
}
// Foo drop 顺序：x → y（字段顺序，与局部变量相反）
```

## 9. 内存模型：Sized / ?Sized / DST / fat pointer

### 9.1 Sized 与 ?Sized

`Sized` 是一个标记 trait，表示类型在编译期大小已知。Rust 中几乎所有类型都自动实现 `Sized`：

```rust
// 这些都是 Sized
let x: i32 = 5;           // 4 字节
let s: String = String::new();  // 24 字节（ptr + len + cap）
let v: Vec<i32> = vec![];      // 24 字节

// 这些不是 Sized（DST）
// let s: str = "hello";  // 编译错误：str doesn't have a size known at compile-time
// let v: [i32] = [1, 2]; // 编译错误
```

泛型参数默认有隐式 `Sized` 约束。需要允许 DST 时用 `?Sized`：

```rust
// 默认：T: Sized
fn foo<T>(t: T) {}

// 允许 DST：T: ?Sized（只能通过引用/指针使用）
fn foo_unsized<T: ?Sized>(t: &T) {}

// 标准库中的 ?Sized 例子
// impl<T: ?Sized> Deref for Box<T> { ... }  // Box 可以包装 DST
```

### 9.2 DST：动态大小类型

DST（Dynamically Sized Type）是编译期大小未知的类型，只能通过引用或指针使用：

- `str`：字符串切片，大小 = 字符字节数（运行时确定）
- `[T]`：数组切片，大小 = 元素数 × sizeof(T)（运行时确定）
- `dyn Trait`：trait 对象，大小 = 具体类型大小（运行时确定）

DST 不能直接存储在栈上，必须通过引用（`&str`、`&[T]`、`&dyn Trait`）或指针（`Box<str>`、`Box<dyn Trait>`）使用。

### 9.3 fat pointer：胖指针

指向 DST 的引用/指针是**胖指针**（fat pointer），包含两个机器字：

| DST 引用 | 组成 | 大小（64位） |
|---|---|---|
| `&str` | 数据指针 + 长度 | 16 字节 |
| `&[T]` | 数据指针 + 长度 | 16 字节 |
| `&dyn Trait` | 数据指针 + vtable 指针 | 16 字节 |

```rust
fn main() {
    // 普通引用（thin pointer）：8 字节
    let x = 5;
    let r = &x;
    println!("size of &i32 = {}", std::mem::size_of_val(&r));  // 8

    // 切片引用（fat pointer）：16 字节
    let v = vec![1, 2, 3];
    let s: &[i32] = &v;
    println!("size of &[i32] = {}", std::mem::size_of_val(&s));  // 16

    // 字符串引用（fat pointer）：16 字节
    let s: &str = "hello";
    println!("size of &str = {}", std::mem::size_of_val(&s));  // 16

    // trait 对象引用（fat pointer）：16 字节
    use std::fmt::Display;
    let x: &dyn Display = &5;
    println!("size of &dyn Display = {}", std::mem::size_of_val(&x));  // 16
}
```

### 9.4 常见 DST 类型

```rust
fn main() {
    // str：通过 &str 或 Box<str> 使用
    let s: &str = "hello";
    let boxed: Box<str> = "hello".into();

    // [T]：通过 &[T] 或 Box<[T]> 使用
    let v = vec![1, 2, 3];
    let slice: &[i32] = &v;
    let boxed_slice: Box<[i32]> = vec![1, 2, 3].into_boxed_slice();

    // dyn Trait：通过 &dyn Trait 或 Box<dyn Trait> 使用
    use std::fmt::Display;
    let x: &dyn Display = &42;
    let boxed: Box<dyn Display> = Box::new(42);
}
```

## 10. 内存布局与 repr 属性

Rust 默认的内存布局（`repr(Rust)`）不保证字段顺序和对齐，编译器可以重排字段以优化大小。需要控制布局时使用 `repr` 属性：

```rust
// 默认布局（repr(Rust)）：编译器可重排字段
struct Foo {
    a: u8,   // 1 字节
    b: u32,  // 4 字节
    c: u8,   // 1 字节
}
// 实际布局可能是：b(4) + a(1) + c(1) + padding(2) = 8（编译器重排减少填充）
// 或：a(1) + padding(3) + b(4) + c(1) + padding(3) = 12（声明顺序）

// repr(C)：C 兼容布局，字段顺序固定，对齐规则与 C 一致
#[repr(C)]
struct FooC {
    a: u8,   // 1 + 3 padding
    b: u32,  // 4
    c: u8,   // 1 + 3 padding
}
// 大小 = 12 字节（固定顺序，不重排）

// repr(transparent)：透明布局，新类型与内部类型布局相同
#[repr(transparent)]
struct Meters(f64);  // 与 f64 布局完全相同（8 字节）

// repr(align(N))：指定对齐
#[repr(align(64))]
struct CacheLineAligned {
    data: [u8; 64],
}

// repr(packed)：取消对齐填充（谨慎使用，可能导致未对齐访问）
#[repr(packed)]
struct Packed {
    a: u8,
    b: u32,  // 不对齐，直接跟在 a 后面
}
// 大小 = 5 字节（无填充）
```

> **对照 C++**：C++ 的结构体布局由 ABI 规定（通常是 C 兼容布局，字段顺序固定），Rust 默认允许编译器重排字段。需要 FFI 互操作时必须用 `#[repr(C)]` 保证布局一致。C++ 的 `alignas` 对应 Rust 的 `#[repr(align(N))]`，C++ 的 `#pragma pack` 对应 `#[repr(packed)]`。

## 11. 对照 C++：unique_ptr / shared_ptr / weak_ptr

| 维度 | Rust Box<T> | C++ unique_ptr<T> |
|---|---|---|
| 所有权 | 单一所有权 | 单一所有权 |
| 拷贝 | 不可拷贝（move only） | 不可拷贝（move only） |
| 自定义删除器 | 通过 trait（较复杂） | 模板参数（`unique_ptr<T, Deleter>`） |
| 空指针 | 无（Box 始终非空） | `nullptr`（可空） |
| 数组 | `Box<[T]>` | `unique_ptr<T[]>` |
| 释放时机 | 离开作用域（drop） | 离开作用域（析构） |
| 性能 | 零开销（与裸指针相同） | 零开销（与裸指针相同） |

| 维度 | Rust Arc<T> | C++ shared_ptr<T> |
|---|---|---|
| 引用计数 | 原子操作 | 原子操作 |
| 线程安全 | 是 | 是 |
| 控制块 | 单独分配（与数据分开） | 单独分配（`make_shared` 可合并） |
| 弱引用 | `Weak<T>` | `weak_ptr<T>` |
| 循环引用 | 需 `Weak` 打破 | 需 `weak_ptr` 打破 |
| 数据可变性 | 默认不可变（需 `Mutex`/`RwLock`） | 默认可变（无编译期保护） |
| 别名构造 | 不支持 | 支持（`shared_ptr<T>(shared_ptr<U>, T*)`） |

| 维度 | Rust RefCell<T> | C++ 对应 |
|---|---|---|
| 内部可变性 | 支持 | `mutable` 关键字 |
| 借用检查 | 运行时（panic on violation） | 无（完全依赖程序员） |
| 不可变/可变借用 | 运行时 enforce 一可变多不可变 | 无约束 |
| 线程安全 | 否（单线程） | `mutable` 可用于多线程（但不安全） |
| 性能开销 | 微小（借用计数器） | 零 |

> **核心差异总结**：
> 1. **可空性**：Rust 的 `Box` 不可空（没有 null 指针），C++ 的 `unique_ptr` 可空。Rust 用 `Option<Box<T>>` 表示可空。
> 2. **可变性**：Rust 的 `Rc`/`Arc` 默认不可变，需要可变性时组合 `RefCell`/`Mutex`（编译期或运行时 enforce）。C++ 的 `shared_ptr` 默认可变，没有任何保护。
> 3. **借用检查**：Rust 的 `RefCell` 在运行时 enforce 借用规则（一可变多不可变），违反则 panic。C++ 没有对应机制，完全依赖程序员自觉。
> 4. **自定义删除器**：C++ 的 `unique_ptr`/`shared_ptr` 通过模板参数支持自定义删除器，Rust 通过 `Drop` trait 实现（更统一但不够灵活）。

## 12. 综合示例：图结构与引用循环

```rust
use std::rc::{Rc, Weak};
use std::cell::RefCell;

#[derive(Debug)]
struct Vertex {
    name: char,
    edges: RefCell<Vec<Rc<Vertex>>>,  // 强引用：指向相邻顶点
}

impl Vertex {
    fn new(name: char) -> Rc<Self> {
        Rc::new(Vertex {
            name,
            edges: RefCell::new(vec![]),
        })
    }

    fn add_edge(&self, other: Rc<Vertex>) {
        self.edges.borrow_mut().push(other);
    }

    fn neighbors(&self) -> Vec<char> {
        self.edges.borrow().iter().map(|v| v.name).collect()
    }
}

// 有向图：A → B, A → C, B → C
fn main() {
    let a = Vertex::new('A');
    let b = Vertex::new('B');
    let c = Vertex::new('C');

    a.add_edge(Rc::clone(&b));
    a.add_edge(Rc::clone(&c));
    b.add_edge(Rc::clone(&c));

    println!("A neighbors: {:?}", a.neighbors());  // ['B', 'C']
    println!("B neighbors: {:?}", b.neighbors());  // ['C']
    println!("C neighbors: {:?}", c.neighbors());  // []

    // 引用计数
    println!("A strong count = {}", Rc::strong_count(&a));  // 1
    println!("B strong count = {}", Rc::strong_count(&b));  // 2（a.edges + b 本身）
    println!("C strong count = {}", Rc::strong_count(&c));  // 3（a.edges + b.edges + c 本身）

    // 注意：这个图没有循环引用（有向无环图），可以正常释放
    // 如果需要循环图（如无向图），需要用 Weak 打破循环
}

// 无向图：用 Weak 存储反向边，避免循环引用
#[derive(Debug)]
struct UndirectedVertex {
    name: char,
    // 强引用：出边
    outgoing: RefCell<Vec<Rc<UndirectedVertex>>>,
    // 弱引用：入边（不阻止释放）
    incoming: RefCell<Vec<Weak<UndirectedVertex>>>,
}

impl UndirectedVertex {
    fn new(name: char) -> Rc<Self> {
        Rc::new(UndirectedVertex {
            name,
            outgoing: RefCell::new(vec![]),
            incoming: RefCell::new(vec![]),
        })
    }

    fn connect(a: Rc<Self>, b: Rc<Self>) {
        // a → b（强引用）
        a.outgoing.borrow_mut().push(Rc::clone(&b));
        // b → a（弱引用，避免循环）
        b.incoming.borrow_mut().push(Rc::downgrade(&a));
    }
}
```

## 13. 常见坑与编译错误

### 错误 1：cannot move out of an `Rc`

```text
error[E0507]: cannot move out of an `Rc`
```
**原因**：试图从 `Rc` 中 move 出数据（但可能有其他引用）。**修复**：使用 `clone()` 深拷贝，或 `Rc::try_unwrap()` 获取唯一所有权，或用 `RefCell` 内部修改。

### 错误 2：already borrowed: BorrowMutError

```text
thread 'main' panicked at 'already borrowed: BorrowMutError'
```
**原因**：`RefCell` 同时存在不可变和可变借用（运行时检查失败）。**修复**：确保在可变借用前 drop 所有不可变借用，缩小借用作用域。

### 错误 3：`Rc<...>` cannot be sent between threads safely

```text
error[E0277]: `Rc<i32>` cannot be sent between threads safely
```
**原因**：将 `Rc` 传递到另一个线程（`Rc: !Send`）。**修复**：改用 `Arc`（原子引用计数，线程安全）。

### 错误 4：the size for values of type `str` cannot be known at compilation time

```text
error[E0277]: the size for values of type `str` cannot be known at compilation time
```
**原因**：试图直接使用 DST（如 `str`、`[T]`）而非通过引用/指针。**修复**：使用 `&str`、`Box<str>`、`&[T]` 等引用/指针类型。

### 错误 5：recursive type has infinite size

```text
error[E0072]: recursive type `Node` has infinite size
```
**原因**：递归类型直接包含自身（大小无限）。**修复**：用 `Box<T>`、`Rc<T>` 或 `Arc<T>` 间接递归。

## 14. 本节小结

- **Box<T>**：堆分配、单一所有权，等价于 C++ `unique_ptr`。关键用途是递归类型、DST 包装、转移大对象所有权。
- **Rc<T>**：单线程引用计数，`clone()` 只增加计数不深拷贝。最后一个引用 drop 时释放数据。不能跨线程。
- **Arc<T>**：`Rc` 的线程安全版本，引用计数用原子操作。跨线程共享所有权的标准选择。
- **RefCell<T>**：运行时借用检查，提供内部可变性。违反借用规则时 panic（而非编译错误）。适用于编译期无法证明安全的场景。
- **Cell<T>**：Copy 类型的内部可变性，无运行时借用检查（值拷贝无别名问题）。性能优于 RefCell。
- **Weak<T>**：弱引用，不增加强引用计数，不阻止数据释放。用于打破 `Rc`/`Arc` 的循环引用，升级返回 `Option`。
- **Deref 强转链**：`Deref` trait 允许自动解引用，可链式发生（`&Box<String>` → `&String` → `&str`）。智能指针像引用一样透明使用。
- **Drop 顺序**：局部变量逆序 drop（LIFO），结构体字段顺序 drop。`std::mem::drop()` 主动释放。
- **内存模型**：`Sized`（编译期大小已知）vs `?Sized`（可能是 DST）。DST（`str`、`[T]`、`dyn Trait`）只能通过胖指针使用，胖指针 = 数据指针 + 元数据（长度/vtable），16 字节（64位）。
- **内存布局**：默认 `repr(Rust)` 允许编译器重排字段，`repr(C)` 保证 C 兼容布局（FFI 必需），`repr(transparent)` 新类型透明，`repr(align)`/`repr(packed)` 控制对齐。
- **与 C++ 对照**：Box↔unique_ptr、Arc↔shared_ptr、Weak↔weak_ptr。关键差异：Rust 指针不可空（用 Option）、默认不可变（需 RefCell/Mutex）、RefCell 运行时 enforce 借用规则。
