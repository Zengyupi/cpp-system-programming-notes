## 1. 生命周期子类型与 variance

生命周期在 Rust 中构成一个**子类型关系**：如果 `'long: 'short`（`'long` 至少和 `'short` 一样长），那么 `&'long T` 是 `&'short T` 的子类型。这意味着长生命周期的引用可以安全地用在需要短生命周期引用的地方。

variance 描述的是：当泛型参数 `T` 是 `U` 的子类型时，容器 `C<T>` 是否也是 `C<U>` 的子类型。

### 1.1 协变、逆变、不变的定义

| variance | 含义 | 典型类型 |
|----------|------|----------|
| 协变 (covariant) | `T <: U` ⇒ `C<T> <: C<U>` | `&'a T`, `Vec<T>`, `Box<T>` |
| 逆变 (contravariant) | `T <: U` ⇒ `C<U> <: C<T>` | `fn(T)` 的参数位置 |
| 不变 (invariant) | 无任何子类型关系 | `&'a mut T`, `Cell<T>`, `UnsafeCell<T>` |

对照 C++：C++没有生命周期子类型，但模板参数的协变/逆变概念出现在函数指针和智能指针中。`std::shared_ptr<Derived>` 可以隐式转换为 `std::shared_ptr<Base>`，这是协变；但 C++不检查这种转换的安全性，完全依赖程序员。

```rust
// 协变示例：长生命周期引用可以缩短
fn need_short<'a>(_x: &'a i32) {}

let long_val = 42;
static LONG_VAL: i32 = 100; // 必须是 static 才能获得 &'static
let long_ref: &'static i32 = &LONG_VAL;
need_short(long_ref); // OK：协变允许缩短生命周期
```

逆变出现在函数参数中：

```rust
// 逆变：接受更宽泛参数的函数，可以用在需要更具体参数的位置
fn take_any(_x: &dyn std::fmt::Display) {}
fn take_int(_x: &i32) {}

// fn(&i32) 是 fn(&dyn Display) 的子类型吗？
// 参数位置是逆变的：如果 &i32 <: &dyn Display，那么 fn(&dyn Display) <: fn(&i32)
let f: fn(&i32) = take_any; // OK：take_any能接受任何Display，自然能接受i32
```

### 1.2 标准库类型的 variance 表

| 类型 | 对 T 的 variance | 对'a 的 variance |
|------|---------------|----------------|
| `&'a T` | 协变 | 协变 |
| `&'a mut T` | 不变 | 协变 |
| `*const T` | 协变 | - |
| `*mut T` | 不变 | - |
| `Vec<T>` | 协变 | - |
| `Box<T>` | 协变 | - |
| `Cell<T>` | 不变 | - |
| `RefCell<T>` | 不变 | - |
| `UnsafeCell<T>` | 不变 | - |
| `fn(T) -> U` | T 逆变，U 协变 | - |
| `PhantomData<T>` | 与 T 相同 | - |
| `PhantomData<fn(T)>` | 逆变 | - |
| `PhantomData<Cell<T>>` | 不变 | - |

### 1.3 内存示意：为什么 Cell 是不变

`Cell<T>` 提供内部可变性：通过 `&Cell<T>`（不可变引用）可以修改内部值。如果 `Cell<T>` 是协变的，就会出现以下安全漏洞：

```text
内存布局示意：

  &Cell<&'long str>          Cell<&'short str>
  ┌─────────────────┐         ┌─────────────────┐
  │ ptr → Cell      │  协变?  │ ptr → Cell      │
  │     ┌───────┐  │ ──────→ │     ┌───────┐  │
  │     │&'long │  │         │     │&'short│  │
  │     │  str  │  │         │     │  str  │  │
  │     └───────┘  │         │     └───────┘  │
  └─────────────────┘         └─────────────────┘

如果允许协变缩短：
1. 有一个 Cell<&'long str>，里面存着长生命周期引用
2. 把它当作 Cell<&'short str> 使用
3. 通过 &Cell<&'short str>.set() 写入一个短生命周期引用
4. 原来的长生命周期引用被覆盖成了悬空指针！
```

因此 `Cell<T>` 必须是**不变**的，阻止任何生命周期的缩短或延长。

对照 C++：C++的 `const` 不提供内部可变性的区分，`const std::shared_ptr<T>` 不能修改指针但可以修改指向的值，这种语义模糊导致 C++无法在类型系统中表达 variance，只能靠约定。

## 2. PhantomData 的用途

`PhantomData<T>` 是一个零大小类型（ZST），不占内存，但在类型系统中告诉编译器"这个结构体逻辑上拥有/借用了 T"。

### 2.1 标记所有权与 drop 检查

```rust
use std::marker::PhantomData;

// 自定义智能指针：裸指针 + PhantomData标记所有权
struct MyBox<T> {
    ptr: *mut T,
    _marker: PhantomData<T>, // 告诉编译器：MyBox逻辑上拥有T
}

impl<T> Drop for MyBox<T> {
    fn drop(&mut self) {
        unsafe {
            // 因为PhantomData<T>标记了所有权，编译器知道drop时需要销毁T
            std::ptr::drop_in_place(self.ptr);
            let layout = std::alloc::Layout::new::<T>();
            std::alloc::dealloc(self.ptr as *mut u8, layout);
        }
    }
}
```

如果没有 `PhantomData<T>`，编译器会认为 `MyBox<T>` 不包含 `T`，drop 检查器可能允许 `T` 在 `MyBox` 之前被销毁，导致 use-after-free。

### 2.2 控制 variance

通过选择不同的 `PhantomData` 变体，可以精确控制自定义类型的 variance：

```rust
use std::marker::PhantomData;

// 协变：像&'a T
struct Covariant<'a, T> {
    raw: *const T,
    _marker: PhantomData<&'a T>, // 协变
}

// 不变：像&'a mut T或Cell<T>
struct Invariant<'a, T> {
    raw: *mut T,
    _marker: PhantomData<Cell<T>>, // 不变
}

// 逆变：像fn(T)
struct Contravariant<T> {
    func: *const (),
    _marker: PhantomData<fn(T)>, // 逆变
}
```

### 2.3 标记 Send/Sync

裸指针默认是 `!Send + !Sync` 的。如果自定义容器确实是线程安全的，需要手动实现：

```rust
use std::marker::PhantomData;

struct AtomicPtrWrapper<T> {
    ptr: *mut T,
    _marker: PhantomData<T>,
}

// 手动声明线程安全（前提是内部确实用了原子操作保护）
unsafe impl<T: Send> Send for AtomicPtrWrapper<T> {}
unsafe impl<T: Sync> Sync for AtomicPtrWrapper<T> {}
```

对照 C++：C++没有 Send/Sync 概念，线程安全完全是文档约定。Rust 通过 `PhantomData` 和自动 trait 实现，把"这个类型是否可跨线程传递"变成了编译期检查。

## 3. HRTB 高阶生命周期约束

HRTB（Higher-Ranked Trait Bounds）允许 trait 约束对**所有**生命周期成立，而不是某个特定的生命周期。

### 3.1 for<'a>语法

```rust
// 普通约束：F需要对某个特定的'a实现Fn(&'a i32)
fn call_with_ref<'a, F>(f: F, x: &'a i32)
where
    F: Fn(&'a i32),
{
    f(x);
}

// HRTB约束：F需要对任意可能的'a实现Fn(&'a i32)
fn call_with_any_ref<F>(f: F)
where
    F: for<'a> Fn(&'a i32),
{
    let x = 42;
    f(&x); // 这里的'a是函数内部的局部生命周期
    let y = 100;
    f(&y); // 另一个不同的'a
}
```

关键区别：普通约束中，调用者决定 `'a`；HRTB 中，被调用者内部可以产生任意生命周期的引用并传给闭包。

### 3.2 闭包与 HRTB

闭包的类型中，引用参数的生命周期通常是高阶的。这就是为什么下面的代码可以工作：

```rust
let print_any = |x: &i32| println!("{}", x);

// 闭包 print_any 自动满足 for<'a> Fn(&'a i32)
call_with_any_ref(print_any);
```

但如果闭包返回一个引用，情况就复杂了：

```rust
// 这个闭包的类型是 for<'a> Fn(&'a i32) -> &'a i32
// 生命周期省略规则自动推导
let identity = |x: &i32| x;
```

### 3.3 对比 C++模板模板参数

C++中没有直接对应的 HRTB 概念。最接近的是模板模板参数（template template parameter），但那是关于类型构造器的多态，不是生命周期的多态。

```cpp
// C++模板模板参数：接受一个模板作为参数
template <template <typename> class Container>
struct Wrapper {
    Container<int> data;
};

// 这与Rust的HRTB完全不同：HRTB是对生命周期的全称量化
// Rust中没有"模板模板参数"，因为生命周期不是类型
```

Rust 的 HRTB 本质上是 System Fω中的全称类型（∀类型），而 C++模板更接近宏展开，没有统一的类型论基础。

## 4. impl 块生命周期约束

### 4.1 impl<'a>与方法级生命周期

```rust
struct Parser<'a> {
    input: &'a str,
}

// impl块上声明生命周期'a
impl<'a> Parser<'a> {
    // 方法可以使用impl块的'a
    fn parse(&self) -> &'a str {
        &self.input[..1]
    }

    // 方法也可以引入自己的生命周期
    fn parse_sub<'b>(&self, range: &'b str) -> (&'a str, &'b str) {
        (&self.input[..1], range)
    }

    // 生命周期约束：'b必须不短于'a
    fn extend<'b: 'a>(&self, other: &'b str) -> &'b str {
        other
    }
}
```

### 4.2 生命周期约束的传播

```rust
struct Container<'a, T: 'a> {
    // T: 'a 表示T中所有引用的生命周期都不短于'a
    data: &'a T,
}

impl<'a, T: 'a> Container<'a, T> {
    fn get(&self) -> &'a T {
        self.data
    }
}
```

`T: 'a` 约束的含义是：类型 `T` 中包含的所有引用都必须活得至少和 `'a` 一样长。这是存储 `&'a T` 的必要条件——如果 `T` 内部有一个比 `'a` 短的引用，那么 `&'a T` 就可能悬空。

对照 C++：C++没有这种约束传播。`std::vector<const std::string&>` 在 C++中是非法的（引用不能存储在容器中），但 `std::vector<boost::reference_wrapper<const std::string>>` 不会检查被引用字符串的生命周期，完全靠程序员保证。

## 5. 生命周期与 trait object

### 5.1 dyn Trait + 'a 的含义

```rust
// trait object默认有一个'static生命周期约束
// dyn Trait 等价于 dyn Trait + 'static
fn make_static() -> Box<dyn std::fmt::Display> {
    Box::new(42) // OK：i32是'static的
}

// 非'static的trait object必须显式标注
fn make_with_lifetime<'a>(s: &'a str) -> Box<dyn std::fmt::Display + 'a> {
    Box::new(s) // &'a str不是'static，所以trait object必须是+'a
}
```

`dyn Trait + 'a` 的含义是：这个 trait object 内部包含的所有引用的生命周期都不短于 `'a`。换句话说，这个 trait object 至少能活到 `'a` 结束。

### 5.2 生命周期省略与 trait object

函数返回 trait object 时，生命周期省略规则：

```rust
// 省略写法：返回Box<dyn Trait>
// 等价于 Box<dyn Trait + 'static>
fn returns_static() -> Box<dyn std::fmt::Display> {
    Box::new(String::from("hello"))
}

// 如果参数中有引用，返回的trait object生命周期与参数关联
fn returns_from_input<'a>(s: &'a str) -> Box<dyn std::fmt::Display + 'a> {
    Box::new(s)
}

// 多个引用参数时必须显式标注
fn ambiguous<'a, 'b>(x: &'a str, y: &'b str) -> Box<dyn std::fmt::Display + 'a> {
    Box::new(x)
}
```

常见错误：

```rust
// 编译错误：返回的trait object是'static的，但s不是
fn broken(s: &str) -> Box<dyn std::fmt::Display> {
    Box::new(s) // 错误：s的生命周期不够长
}
```

## 6. 'static 约束陷阱

### 6.1 'static 生命周期 vs 'static 约束

这两个概念经常混淆：

| 概念 | 含义 | 示例 |
|------|------|------|
| `'static` 生命周期 | 引用指向的数据活在整个程序期间 | `let s: &'static str = "hello";` |
| `T: 'static` 约束 | 类型 T 中不包含任何短于'static 的引用 | `fn foo<T: 'static>(x: T) {}` |

```rust
// 'static生命周期：字符串字面量
const MESSAGE: &str = "constant"; // &'static str

// 'static约束：T可以是任何不包含短引用的类型
fn spawn_thread<F: FnOnce() + Send + 'static>(f: F) {
    std::thread::spawn(f);
}

// String满足'static约束（它不包含引用）
spawn_thread(|| {
    let s = String::from("owned");
    println!("{}", s);
});

// &String不满足'static约束（它是一个引用）
let local = String::from("local");
// spawn_thread(|| println!("{}", local)); // 错误：local不是'static
```

### 6.2 线程与'static 的常见误解

**误解 1**：`'static` 约束意味着数据必须是编译期常量。

**事实**：`'static` 约束只要求类型不包含短生命周期引用。`String`、`Vec<T>`、`i32` 等所有拥有所有权的类型都满足 `'static` 约束，即使它们是在运行时创建的。

```rust
// 运行时创建的String满足'static约束
let runtime_string = String::from("created at runtime");
std::thread::spawn(move || {
    println!("{}", runtime_string); // OK：move转移了所有权
});
```

**误解 2**：`&'static T` 和 `T: 'static` 是一回事。

**事实**：`&'static T` 是一个具体的引用类型，指向活整个程序的数据；`T: 'static` 是一个约束，说 T 这个类型不包含短引用。`Box<dyn Trait>` 满足 `'static` 约束但不是 `&'static` 引用。

对照 C++：C++的 `static` 关键字含义完全不同——它表示静态存储期或内部链接，没有"类型不包含悬空引用"的约束概念。Rust 的 `'static` 约束更接近 C++中"这个对象不持有任何外部引用"的文档约定，但 Rust 是编译期强制的。

## 7. 典型案例：自引用结构体与租赁类型

自引用结构体是 Rust 中最棘手的生命周期问题之一：结构体的一个字段引用了另一个字段。

```rust
// 直接写法：编译失败
// struct SelfRef {
//     data: String,
//     ref_to_data: &str, // 引用data字段，但无法表达这个生命周期
// }
```

### 方案 1：unsafe + 裸指针（ouroboros 库的思路）

```rust
use std::marker::PhantomData;

struct SelfRef {
    data: String,
    // 裸指针指向data的内部，不参与生命周期检查
    ref_ptr: *const str,
    _marker: PhantomData<&'static str>,
}

impl SelfRef {
    fn new(data: String) -> Self {
        let ref_ptr = data.as_str() as *const str;
        Self {
            data,
            ref_ptr,
            _marker: PhantomData,
        }
    }

    fn get_ref(&self) -> &str {
        // 安全：ref_ptr始终指向self.data的内部
        // 只要self活着，data就活着，ref_ptr就有效
        unsafe { &*self.ref_ptr }
    }
}

// 注意：SelfRef不能实现移动语义的安全移动
// 因为移动后data的地址变了，ref_ptr会悬空
// 实际项目中使用ouroboros或self_cell库处理
```

### 方案 2：租赁类型（rental pattern）

将引用和数据分离，引用的生命周期绑定到一个守卫对象：

```rust
struct Data {
    payload: String,
}

struct View<'a> {
    part: &'a str,
}

impl Data {
    fn view(&self) -> View<'_> {
        View {
            part: &self.payload[..2],
        }
    }
}

fn main() {
    let data = Data {
        payload: String::from("hello"),
    };
    let view = data.view(); // view的生命周期绑定到data
    println!("{}", view.part);
}
```

这种模式在 C++中对应"视图类持有指向所有者的指针/引用"，但 C++不检查生命周期，容易出现悬空视图。Rust 通过生命周期绑定，在编译期保证视图不会比数据活得久。

## 8. 快速参考卡片

| 查询点 | 速答 |
| --- | --- |
| 三种 variance | `&'a T` 对 T **协变**；`&'a mut T` 对 T **不变**；`Cell<T>`/`RefCell<T>` **不变**（内部可变必须不变） |
| 为什么可变引用不变 | 若 `&mut &'long T` 可当 `&mut &'short T` 用，就能把短引用写进长引用 → 悬垂 |
| PhantomData 三用途 | ① 标记"逻辑上拥有 T"（drop check 与自动 trait） ② 控制 variance ③ 影响 Send/Sync 推导 |
| HRTB 何时需要 | 函数/闭包参数含引用且要对"任意生命周期"成立：`fn f<F>(g: F) where F: for<'a> Fn(&'a str)` |
| trait object 生命周期 | `Box<dyn Trait>` 默认 `+ 'static`；借用数据时显式写 `Box<dyn Trait + 'a>` |
| `'static` 两种用法 | 类型标注（字面量、`&'static str`）vs 约束 `T: 'static`（不含短借用，值不必永生） |
| 生命周期约束传播 | `impl<'a> Foo<'a> { fn get(&self) -> &'a str }`：返回的生命周期绑在结构体参数上而非 self |
| 自引用结构体 | 语言不直接支持；方案：`ouroboros`/`Pin + unsafe`，或拆成"索引 + 容器"设计 |
| 高频错误码 | E0621 需显式标注、E0310/E0311 `'static` 约束、E0597 does not live long enough |

---

## 9. 本节小结

- **variance**是生命周期子类型在泛型容器中的传播规则：协变允许缩短、逆变出现在函数参数、不变阻止任何变化。内部可变性类型（`Cell`、`RefCell`、`UnsafeCell`）必须是不变的。
- **PhantomData**是零大小标记类型，用于告诉编译器结构体逻辑上拥有/借用了某个类型，控制 drop 检查、variance 和 Send/Sync 自动实现。
- **HRTB**（`for<'a>`）表达"对所有生命周期成立"的约束，是闭包引用参数的默认行为，也是高阶函数的必要工具。
- **impl 块生命周期**在 `impl<'a>` 上声明，方法可以引入额外生命周期和约束（`'b: 'a`）。`T: 'a` 表示 T 中所有引用不短于'a。
- **trait object**默认是 `'static` 的，非'static 必须写 `dyn Trait + 'a`。返回 trait object 时注意生命周期省略规则。
- **'static 约束**不等于"编译期常量"，所有拥有所有权的类型都满足 `'static` 约束。`&'static T` 和 `T: 'static` 是不同概念。
- 自引用结构体需要 `unsafe` 或第三方库（ouroboros/self_cell），租赁类型是更安全的替代方案。对照 C++的异常安全机制（《../../01-C++技术体系/01-语言基础/07-异常处理与异常安全.md》），Rust 的生命周期在编译期保证内存安全，C++依赖 RAII 和运行时约定。
