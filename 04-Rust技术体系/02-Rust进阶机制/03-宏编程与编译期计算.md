## 1. macro_rules!声明宏

`macro_rules!` 是 Rust 的声明宏系统，基于模式匹配工作。它在编译期展开为 AST 节点，不是文本替换。

### 1.1 基本语法与匹配器

```rust
// 最简单的宏：无参数
macro_rules! hello {
    () => {
        println!("Hello, macro!");
    };
}

// 带表达式参数
macro_rules! double {
    ($x:expr) => {
        $x * 2
    };
}

// 多个分支
macro_rules! calculate {
    ($x:expr, add, $y:expr) => { $x + $y };
    ($x:expr, mul, $y:expr) => { $x * $y };
}

fn main() {
    hello!();
    println!("{}", double!(5)); // 10
    println!("{}", calculate!(3, add, 4)); // 7
    println!("{}", calculate!(3, mul, 4)); // 12
}
```

匹配器片段类型（fragment specifier）：

| 片段类型 | 匹配内容 | 后续分隔符限制 |
|----------|----------|----------------|
| `expr` | 表达式 | `=> , ;` |
| `ty` | 类型 | `=> , ; = \|` |
| `pat` | 模式 | `=> , ; = \| if in` |
| `stmt` | 语句 | 无特殊限制 |
| `block` | 代码块 | 无特殊限制 |
| `item` | 条目（函数、结构体等） | 无特殊限制 |
| `meta` | 属性内容 | 无特殊限制 |
| `tt` | 单个 token 树 | 无特殊限制 |
| `ident` | 标识符 | 无特殊限制 |
| `path` | 路径 | `=> , ; = \|` |
| `vis` | 可见性修饰符 | 无特殊限制 |
| `lifetime` | 生命周期 | 无特殊限制 |

### 1.2 重复匹配

重复匹配是声明宏最强大的功能，使用 `$(...),*` 或 `$(...),+` 语法。

```rust
// vec!宏的简化实现
macro_rules! my_vec {
    ($($x:expr),* $(,)?) => {{
        let mut temp_vec = Vec::new();
        $(
            temp_vec.push($x);
        )*
        temp_vec
    }};
}

fn main() {
    let v = my_vec![1, 2, 3, 4];
    println!("{:?}", v); // [1, 2, 3, 4]

    // 尾部逗号可选
    let v2 = my_vec![1, 2, 3,];
    println!("{:?}", v2); // [1, 2, 3]
}
```

重复语法详解：

```rust
macro_rules! repeat_demo {
    // $(...),* ：逗号分隔的零个或多个
    ($($x:expr),*) => { ... };

    // $(...),+ ：逗号分隔的一个或多个
    ($($x:expr),+) => { ... };

    // $(...);* ：分号分隔
    ($($x:expr);*) => { ... };

    // $(...)? ：零个或一个（可选）
    ($($x:expr)?) => { ... };

    // 嵌套重复
    ($([$($x:expr),*]),*) => { ... };
}
```

更复杂的例子：为多个类型实现 trait

```rust
macro_rules! impl_display {
    ($($t:ty),*) => {
        $(
            impl std::fmt::Display for $t {
                fn fmt(&self, f: &mut std::fmt::Formatter<'_>) -> std::fmt::Result {
                    write!(f, "{:?}", self)
                }
            }
        )*
    };
}

// 为多个类型同时实现Display
impl_display!(i32, u32, f32, bool);
```

### 1.3 卫生性（hygiene）

Rust 的声明宏是**卫生的**（hygienic）：宏内部定义的变量不会与外部变量冲突。

```rust
macro_rules! hygienic_demo {
    ($x:expr) => {{
        let internal = 42; // 宏内部的变量
        $x + internal
    }};
}

fn main() {
    let internal = 100; // 外部同名变量
    let result = hygienic_demo!(internal);
    println!("{}", result); // 142：宏内部的internal=42，外部的internal=100
}
```

展开后的等价代码：

```rust
fn main() {
    let internal = 100;
    let result = {
        let internal = 42; // 这是宏的internal，有独立的语法上下文
        internal + internal // 第一个internal是外部传入的(值100)，第二个是宏内部的(值42)
    };
    // 实际展开更复杂，但核心是：宏定义的标识符有独立的语法上下文
}
```

对照 C++：C++的预处理器宏是**不卫生的**，纯文本替换会导致变量名冲突。

```cpp
// C++宏的卫生性问题
#define SQUARE(x) ({ int _tmp = (x); _tmp * _tmp; })

int main() {
    int _tmp = 100;
    int result = SQUARE(_tmp); // 宏内部的_tmp与外部冲突！
    // 展开为：({ int _tmp = (_tmp); _tmp * _tmp; })
    // 外部_tmp被宏内部的_tmp遮蔽，结果不是10000
}
```

### 1.4 递归宏

声明宏可以递归调用自身，用于处理变长参数列表。

```rust
// 计算参数个数
macro_rules! count_args {
    () => { 0usize };
    ($head:expr $(, $tail:expr)*) => {
        1usize + count_args!($($tail),*)
    };
}

fn main() {
    println!("{}", count_args!());       // 0
    println!("{}", count_args!(1));      // 1
    println!("{}", count_args!(1, 2, 3)); // 3
}
```

递归展开过程（以 `count_args!(1, 2, 3)` 为例）：

```text
count_args!(1, 2, 3)
→ 1 + count_args!(2, 3)
→ 1 + (1 + count_args!(3))
→ 1 + (1 + (1 + count_args!()))
→ 1 + (1 + (1 + 0))
→ 3
```

注意：声明宏的递归深度有限制（默认 64 层），可以通过 `#![recursion_limit = "256"]` 调整。

## 2. 过程宏

过程宏（Procedural Macros）是在编译期运行的 Rust 函数，接收 TokenStream 输入，返回 TokenStream 输出。比声明宏更强大，但也更复杂。

### 2.1 三类过程宏概览

| 类型 | 语法 | 用途 | 输入 |
|------|------|------|------|
| derive 宏 | `#[derive(MyTrait)]` | 为类型自动实现 trait | 结构体/枚举的 TokenStream |
| 属性宏 | `#[my_attribute]` | 转换或注解条目 | 属性参数 + 被注解条目的 TokenStream |
| 函数式宏 | `my_macro!(...)` | 类似声明宏但用 Rust 代码处理 | 括号内的 TokenStream |

过程宏必须放在单独的 crate 中，crate 类型为 `proc-macro`：

```toml
[package]
name = "my_proc_macros"
version = "0.1.0"
edition = "2021"

[lib]
proc-macro = true

[dependencies]
syn = { version = "2", features = ["full"] }
quote = "1"
proc-macro2 = "1"
```

（以上 crate 版本以 crates.io 最新稳定版为准）

### 2.2 derive 宏最小实例

实现一个 `#[derive(Hello)]` 宏，自动为类型生成 `hello()` 方法：

```rust
// my_proc_macros/src/lib.rs
use proc_macro::TokenStream;
use quote::quote;
use syn::{parse_macro_input, DeriveInput};

#[proc_macro_derive(Hello)]
pub fn derive_hello(input: TokenStream) -> TokenStream {
    // 解析输入为DeriveInput（结构体或枚举的AST）
    let input = parse_macro_input!(input as DeriveInput);

    // 获取类型名称
    let name = &input.ident;

    // 生成实现代码
    let expanded = quote! {
        impl #name {
            pub fn hello(&self) {
                println!("Hello from {}!", stringify!(#name));
            }
        }
    };

    // 返回生成的TokenStream
    TokenStream::from(expanded)
}
```

使用这个宏：

```rust
use my_proc_macros::Hello;

#[derive(Hello)]
struct MyStruct {
    value: i32,
}

#[derive(Hello)]
enum MyEnum {
    A,
    B,
}

fn main() {
    let s = MyStruct { value: 42 };
    s.hello(); // 输出 "Hello from MyStruct!"

    let e = MyEnum::A;
    e.hello(); // 输出 "Hello from MyEnum!"
}
```

更实用的例子：自动实现 `From<T>` 转换

```rust
use proc_macro::TokenStream;
use quote::quote;
use syn::{parse_macro_input, DeriveInput, Fields};

#[proc_macro_derive(IntoInner)]
pub fn derive_into_inner(input: TokenStream) -> TokenStream {
    let input = parse_macro_input!(input as DeriveInput);
    let name = &input.ident;

    // 只处理单字段元组结构体（newtype模式）
    let inner_type = match &input.data {
        syn::Data::Struct(data) => match &data.fields {
            Fields::Unnamed(fields) if fields.unnamed.len() == 1 => {
                &fields.unnamed.first().unwrap().ty
            }
            _ => panic!("IntoInner can only be derived for single-field tuple structs"),
        },
        _ => panic!("IntoInner can only be derived for structs"),
    };

    let expanded = quote! {
        impl #name {
            pub fn into_inner(self) -> #inner_type {
                self.0
            }
        }
    };

    TokenStream::from(expanded)
}
```

### 2.3 属性宏与函数式宏

**属性宏**可以修改被注解的条目：

```rust
#[proc_macro_attribute]
pub fn log_calls(attr: TokenStream, item: TokenStream) -> TokenStream {
    // attr是属性参数，item是被注解的函数
    let input = parse_macro_input!(item as syn::ItemFn);
    let fn_name = &input.sig.ident;
    let body = &input.block;
    let vis = &input.vis;
    let sig = &input.sig;

    let expanded = quote! {
        #vis #sig {
            println!("entering {}", stringify!(#fn_name));
            let result = (|| #body)();
            println!("leaving {}", stringify!(#fn_name));
            result
        }
    };

    TokenStream::from(expanded)
}

// 使用
#[log_calls]
fn add(a: i32, b: i32) -> i32 {
    a + b
}
```

**函数式宏**类似声明宏，但用 Rust 代码处理 TokenStream：

```rust
#[proc_macro]
pub fn sql(input: TokenStream) -> TokenStream {
    // 解析SQL语句，在编译期验证语法，生成预编译的查询代码
    let query = input.to_string();
    // ... 验证和生成 ...
    let expanded = quote! {
        Query::new(#query)
    };
    TokenStream::from(expanded)
}

// 使用
let query = sql!(SELECT * FROM users WHERE id = ?);
```

## 3. const fn 与编译期求值

`const fn` 是可以在编译期执行的函数，其返回值可以用于常量上下文。

### 3.1 const fn 的能力边界

```rust
// 基本的const fn
const fn square(x: i32) -> i32 {
    x * x
}

const RESULT: i32 = square(5); // 编译期计算，值为25

// const fn中可以使用的操作（stable Rust）
const fn complex_calc(n: usize) -> usize {
    let mut sum = 0;
    let mut i = 0;
    while i < n {
        sum += i * i;
        i += 1;
    }
    sum
}

const VALUE: usize = complex_calc(10); // 编译期计算

fn main() {
    println!("{}", RESULT); // 25
    println!("{}", VALUE);  // 285

    // const fn也可以在运行时调用
    let runtime_val = square(10);
    println!("{}", runtime_val); // 100
}
```

const fn 的限制（stable Rust）：
- 不能使用 `let mut` 以外的复杂控制流（目前已支持循环和条件）
- 不能调用非 const 函数
- 不能使用堆分配（`Box`、`Vec` 等）
- 不能使用 `&mut` 引用（const mut 引用正在稳定化中）
- 不能使用 trait 方法（除非是 const trait）

### 3.2 const 泛型

const 泛型允许用常量值作为泛型参数：

```rust
// 固定大小数组的泛型封装
struct Array<T, const N: usize> {
    data: [T; N],
}

impl<T, const N: usize> Array<T, N> {
    const fn new(data: [T; N]) -> Self {
        Array { data }
    }

    const fn len(&self) -> usize {
        N
    }

    const fn is_empty(&self) -> bool {
        N == 0
    }
}

// const泛型表达式（需要#![feature(generic_const_exprs)]，目前在nightly）
// struct Buffer<T, const N: usize>
// where
//     [T; N * 2]: Sized, // 常量表达式作为数组大小
// {
//     data: [T; N],
// }

fn main() {
    let arr = Array::new([1, 2, 3, 4, 5]);
    println!("len: {}, empty: {}", arr.len(), arr.is_empty());
}
```

### 3.3 编译期计算实战

编译期计算哈希值（避免运行时开销）：

```rust
// FNV-1a哈希的const实现
const fn fnv1a_hash(bytes: &[u8]) -> u64 {
    let mut hash: u64 = 0xcbf29ce484222325;
    let mut i = 0;
    while i < bytes.len() {
        hash ^= bytes[i] as u64;
        hash = hash.wrapping_mul(0x100000001b3);
        i += 1;
    }
    hash
}

// 编译期计算的哈希常量
const HELLO_HASH: u64 = fnv1a_hash(b"hello");
const WORLD_HASH: u64 = fnv1a_hash(b"world");

fn main() {
    println!("{:016x}", HELLO_HASH); // 编译期已计算好
    println!("{:016x}", WORLD_HASH);

    // 运行时验证
    assert_eq!(fnv1a_hash(b"hello"), HELLO_HASH);
}
```

编译期验证（类型状态的编译期检查）：

```rust
/// 编译期验证字符串长度不超过MAX_LEN
const fn assert_len(s: &str, max_len: usize) -> &str {
    assert!(s.len() <= max_len, "string too long");
    s
}

// 编译期检查：如果超过长度限制，编译失败
const SHORT_NAME: &str = assert_len("hello", 10); // OK
// const LONG_NAME: &str = assert_len("this is way too long", 10); // 编译错误

fn main() {
    println!("{}", SHORT_NAME);
}
```

## 4. 对比 C++模板元编程与宏缺陷

### 4.1 C++预处理器宏的缺陷

C++的 `#define` 宏是纯文本替换，存在大量问题：

| 缺陷 | C++示例 | Rust 对应方案 |
|------|---------|-------------|
| 不卫生 | `#define MAX(a,b) ((a)>(b)?(a):(b))` 变量名冲突 | 声明宏天然卫生 |
| 无类型检查 | 宏参数可以是任何文本 | 片段类型（expr/ty/ident） |
| 无作用域 | 宏全局生效，无法命名空间隔离 | 宏可以 mod/path 限定 |
| 调试困难 | 展开后才能看到错误 | 过程宏有 Span 信息 |
| 无法递归限制 | 宏递归可能无限展开 | 递归限制 64 层，可配置 |

```cpp
// C++宏的经典错误
#define SQUARE(x) x * x

int main() {
    int result = SQUARE(2 + 3); // 展开为 2 + 3 * 2 + 3 = 11，不是25！
    // 正确写法需要括号：#define SQUARE(x) ((x) * (x))
    // 但即使加了括号，SQUARE(i++)也会导致i被自增两次
}
```

Rust 的声明宏基于 AST 匹配，不会有这种问题：

```rust
macro_rules! square {
    ($x:expr) => { $x * $x };
}

fn main() {
    let result = square!(2 + 3); // 正确：(2+3) * (2+3) = 25
    println!("{}", result);
}
```

### 4.2 C++模板元编程 vs Rust 编译期计算

C++模板元编程（TMP）是在编译期执行计算的技术，但它的语法极其晦涩：

```cpp
// C++模板元编程：编译期阶乘
template<int N>
struct Factorial {
    static const int value = N * Factorial<N - 1>::value;
};

template<>
struct Factorial<0> {
    static const int value = 1;
};

// 使用
constexpr int result = Factorial<5>::value; // 120
```

Rust 的 const fn 等价实现，语法与普通函数完全一致：

```rust
const fn factorial(n: u64) -> u64 {
    let mut result = 1;
    let mut i = 1;
    while i <= n {
        result *= i;
        i += 1;
    }
    result
}

const RESULT: u64 = factorial(5); // 120
```

| 特性 | C++模板元编程 | Rust const fn |
|------|---------------|---------------|
| 语法 | 模板特化，类 Prolog | 普通函数语法 |
| 调试 | 错误信息极难阅读 | 普通编译错误 |
| 递归 | 无硬性限制（编译器内存限制） | 默认 64 层，可配置 |
| 条件 | 模板特化/`std::conditional` | `if`/`match` |
| 循环 | 递归模拟 | `loop`/`while` |
| 变量 | 无（用类型代替值） | `let`（包括 `let mut`） |
| 与运行时共享 | 模板代码不能直接运行时调用 | const fn 可运行时调用 |

C++20 引入了 `constexpr` 函数和 `consteval`，缩小了与 Rust 的差距，但 C++的 `constexpr` 仍然有更多限制（不能使用动态分配、异常等），且与模板元编程是两套独立的系统。

## 5. 快速参考卡片

| 查询点 | 速答 |
| --- | --- |
| 定义声明宏 | `macro_rules! name { ($x:expr) => { ... }; }`，可多分支，按顺序匹配 |
| 片段符速查 | `expr`（表达式）`ident`（标识符）`ty`（类型）`pat`（模式）`path` `tt`（token 树）`block` `item` `literal` `meta` |
| 重复展开 | `$( $e:expr ),*` 配合 `$( ... )*`；分隔符可用 `,` `;` 或空格 |
| 卫生性 | 宏内 `let x` 与调用方 `x` 互不干扰；例外：从 `tt` 传入的标识符保持调用方身份 |
| 过程宏三类 | `#[derive(MyDerive)]`、属性宏 `#[my_attr]`、函数式宏 `my_macro!{...}` |
| 过程宏工程 | 独立 crate + `[lib] proc-macro = true`；`syn` 解析、`quote!` 生成、`proc-macro2` 兼容 |
| 调试手段 | `cargo expand` 看展开结果；nightly 用 `-Z macro-backtrace` |
| 编译期计算 | `const fn`、`const generics`（`const N: usize`）、`build.rs` 生成代码 |
| 选型建议 | 能用函数/泛型/trait 就不要用宏；宏适合消除样板与语法扩展 |

## 6. 常见坑与最佳实践

### 坑 1：声明宏的片段类型后续限制

```rust
// 编译错误：expr后面不能直接跟另一个expr
// macro_rules! bad {
//     ($a:expr $b:expr) => { $a + $b };
// }

// 正确：用逗号分隔
macro_rules! good {
    ($a:expr, $b:expr) => { $a + $b };
}
```

### 坑 2：过程宏中的 Span 丢失

使用 `quote!` 时，生成代码的 Span 默认是 `Span::call_site()`，这会导致错误信息指向宏调用位置而不是生成代码位置。对于 derive 宏，通常希望错误指向被 derive 的类型。

```rust
// 使用spanned API保留Span信息
use quote::ToTokens;

let name_span = name.span();
let expanded = quote_spanned! {name_span=>
    impl #name { ... }
};
```

### 坑 3：const fn 中的浮点运算

```rust
// 目前stable Rust中，const fn不支持浮点比较和部分浮点运算
// const fn approx_eq(a: f64, b: f64) -> bool {
//     (a - b).abs() < 1e-9 // 编译错误：f64的方法不是const
// }

// 变通方案：用整数运算模拟
const fn approx_eq_int(a: i64, b: i64, tolerance: i64) -> bool {
    (a - b).abs() < tolerance
}
```

### 最佳实践

1. **优先使用声明宏**：只有声明宏无法满足需求时才用过程宏
2. **过程宏保持简单**：复杂逻辑放在运行时库中，过程宏只做代码生成
3. **const fn 优先于宏**：编译期计算能用 const fn 就不用宏
4. **为宏编写测试**：使用 `trybuild` crate 测试宏的编译错误
5. **文档化宏的使用方式**：宏的错误信息通常不直观，文档很重要

## 7. 本节小结

- **声明宏**`macro_rules!` 基于 AST 模式匹配，支持重复匹配 `$(...),*`、递归和卫生性。片段类型（expr/ty/ident 等）提供基本的类型检查。卫生性保证宏内部变量不与外部冲突，这是 C++预处理器宏完全不具备的。
- **过程宏**是编译期运行的 Rust 函数，分三类：derive 宏（`#[derive(Trait)]`）、属性宏（`#[attr]`）、函数式宏（`macro!()`）。使用 `syn` 解析 TokenStream 为 AST，`quote` 生成代码。过程宏必须放在独立的 `proc-macro` crate 中。
- **const fn**可以在编译期执行，语法与普通函数一致，支持循环、条件、可变变量。const 泛型允许常量值作为泛型参数（`struct Array<T, const N: usize>`）。编译期计算可用于哈希预计算、常量验证等场景。
- **对比 C++**：C++预处理器宏是纯文本替换，不卫生、无类型检查、调试困难；C++模板元编程语法晦涩，用类型模拟值计算。Rust 的声明宏+过程宏+const fn 提供了更安全、更易用的编译期编程体系，将错误从运行时（对照《../../01-C++技术体系/01-语言基础/07-异常处理与异常安全.md》）提前到编译期。
- 常见坑：片段类型后续分隔符限制、过程宏 Span 丢失、const fn 浮点运算限制。最佳实践：优先声明宏、过程宏保持简单、const fn 优先于宏。
