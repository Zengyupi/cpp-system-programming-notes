## 1. 工程场景：Python需要类型注解吗

C++/Rust工程师最不适应Python的**没有编译期类型检查**。函数期望`bytes`，调用方传了`str`，要到运行时才在`data[0]`处报`TypeError`。几百行的一次性脚本不是问题——跑一遍就发现了。但团队维护的工具项目（几千行、多人协作、CI自动运行），类型错误会在最不方便的时候爆发。

Python 3.5+引入类型注解，3.9+支持内置泛型（`list[int]`），3.10+支持`X | None`联合类型。类型注解是**可选的、渐进的**——可以只给关键函数加，也可以全项目严格检查。

## 2. 类型注解基础

```python
# 变量注解
name: str = "device-01"
port: int = 8080

# 函数注解：参数和返回值
def connect(host: str, port: int, timeout: float = 5.0) -> bool:
    return True

# 类属性注解
class Packet:
    length: int
    data: bytes
    def __init__(self, data: bytes) -> None:
        self.data = data
        self.length = len(data)
```

**类型注解不影响运行**——这是与C++/Rust最本质的区别。注解在运行时被忽略，不做检查，不影响性能。类型检查由外部工具（mypy/pyright）在开发时/CI时执行。

```python
def add(a: int, b: int) -> int:
    return a + b

print(add("hello", " world"))  # "hello world" —— 注解被完全忽略，运行不报错
```

C++的类型在编译期检查并影响代码生成，Rust同理。Python的类型注解更像是**结构化注释+外部lint**，与运行时完全解耦。

## 3. typing常用类型

### 3.1 Optional与容器类型

`Optional[X]`表示`X`或`None`，Python 3.10+推荐写成`X | None`。

```python
def find_device(name: str) -> dict | None:
    devices = {"GW-01": {"ip": "192.168.1.1"}}
    return devices.get(name)

device = find_device("GW-02")
if device is not None:   # 必须检查None
    print(device["ip"])
```

类型检查器会提醒忘记检查None的情况（对应C++空指针解引用、Rust`Option<T>`必须处理）。

Python 3.9+支持内置泛型语法，不需要从`typing`导入`List/Dict/Set/Tuple`：

```python
ports: list[int] = [8080, 8443]
config: dict[str, int] = {"timeout": 5, "retries": 3}
allowed: set[str] = {"192.168.1.1"}
point: tuple[int, int] = (10, 20)
values: tuple[int, ...] = (1, 2, 3)  # 可变长度tuple

def filter_ports(ports: list[int], min_port: int) -> list[int]:
    return [p for p in ports if p >= min_port]
```

C++对照：`list[int]`→`std::vector<int>`，`dict[str,int]`→`std::unordered_map<std::string,int>`。Rust对应`Vec<i32>`、`HashMap<String,i32>`。

### 3.2 Callable与TypeVar

`Callable[[参数类型...], 返回类型]`描述函数类型，用于回调、高阶函数、装饰器。

```python
from typing import Callable

Parser = Callable[[bytes], dict]

def parse_with(data: bytes, parser: Parser) -> dict:
    return parser(data)

def tcp_parser(data: bytes) -> dict:
    return {"proto": "TCP", "length": len(data)}

result = parse_with(b"\x01\x02", tcp_parser)
```

`Callable[..., ReturnType]`中的`...`表示任意参数。C++对照`std::function<R(Args...)>`，Rust对照`Fn(Args)->R` trait。

`TypeVar`定义类型变量，用于泛型函数：

```python
from typing import TypeVar

T = TypeVar("T")

def first_item(items: list[T]) -> T | None:
    return items[0] if items else None

# 类型检查器推断返回类型
first: int | None = first_item([1, 2, 3])    # 推断为int | None
first_str: str | None = first_item(["a", "b"])  # 推断为str | None

# 带约束的TypeVar：只能是指定类型
Number = TypeVar("Number", int, float)
def double(x: Number) -> Number:
    return x * 2
```

C++对照模板`template<typename T>`，Rust对照泛型`fn first_item<T>(Vec<T>)->Option<T>`。Python的TypeVar是类型检查器层面的泛型，运行时不特化。

### 3.3 Protocol与TypedDict

`Protocol`定义结构化接口——只要对象有指定方法/属性就符合，不需要显式继承（鸭子类型）。

```python
from typing import Protocol

class Closable(Protocol):
    def close(self) -> None: ...

def safe_close(resource: Closable) -> None:
    try:
        resource.close()
    except Exception as e:
        print(f"关闭失败: {e}")

# 文件对象有close()，符合Closable
# 自定义类只要有close()就符合，不需要继承
class SocketWrapper:
    def close(self) -> None:
        print("socket已关闭")

safe_close(SocketWrapper())  # OK
```

C++对照C++20 `concept`，Rust对照`trait`（但Rust需显式`impl`）。Python的Protocol完全隐式。

`TypedDict`给字典指定键名和值类型，用于描述结构化字典（JSON解析结果、配置字典）。

```python
from typing import TypedDict

class DeviceConfig(TypedDict):
    name: str
    ip: str
    port: int
    enabled: bool

config: DeviceConfig = {
    "name": "GW-01", "ip": "192.168.1.1",
    "port": 8080, "enabled": True,
}
# 类型检查器验证：缺少必须字段→错误，键名拼写错误→错误，值类型不匹配→错误
```

可选字段用`total=False`。比普通`dict[str, object]`精确得多。

## 4. 类型检查工具：mypy/pyright/ruff

| 工具 | 定位 | 速度 | 推荐场景 |
|------|------|------|---------|
| mypy | 类型检查参考实现，规则最严格 | 中 | CI类型检查 |
| pyright | 类型检查+语言服务，VSCode Pylance底层 | 快 | 日常开发实时检查 |
| ruff | lint+format（不做类型检查），Rust编写 | 极快 | 代码风格、导入排序、常见bug |

**mypy配置**（`pyproject.toml`）：

```toml
[tool.mypy]
python_version = "3.11"
strict = false
warn_return_any = true
disallow_untyped_defs = false  # 渐进式：不强制所有函数有注解
ignore_missing_imports = true   # 忽略无类型存根的第三方库
```

**pyright配置**：VSCode安装Pylance扩展后实时显示类型错误（红色波浪线），最常用的方式。

**ruff配置**：

```toml
[tool.ruff]
line-length = 100
target-version = "py311"

[tool.ruff.lint]
select = ["E", "W", "F", "I", "UP", "B", "ANN"]
# E/W: pycodestyle, F: pyflakes, I: isort, UP: pyupgrade, B: bugbear, ANN: 注解缺失
```

**推荐组合**：日常开发用VSCode+Pylance（pyright）实时检查+ruff保存时格式化；CI用`ruff check`+`mypy`+`pytest`。所有配置统一放`pyproject.toml`。

## 5. 渐进式注解策略

不要追求一步到位，推荐三阶段：

**阶段一：零注解起步**
- 新写的函数加参数和返回值注解
- mypy非严格模式，只检查有注解的函数

**阶段二：核心模块注解（1-2周）**
- 给数据结构（dataclass、TypedDict）加完整注解
- 给公共API函数（被其他模块调用的）加注解
- 开启`disallow_untyped_defs`但排除特定目录

**阶段三：全项目严格（长期）**
- 所有函数都有注解，mypy `--strict`通过
- CI中类型检查失败阻止合并

**性价比判断**：
- 值得加：团队维护的核心模块、公共API、数据结构、复杂算法
- 不值得加：一次性脚本、50行以内小工具、原型验证代码、频繁变动的探索性代码

**实用技巧**：用运行时类型收集工具（如monkeytype、pyannotate）自动生成注解草稿再人工修正；不要用`Any`逃避检查（`Any`会传染使类型检查失效）。

## 6. 对照C++/Rust静态类型

| 维度 | C++ | Rust | Python（类型注解） |
|------|-----|------|-------------------|
| 检查时机 | 编译期 | 编译期 | 外部工具，运行时不检查 |
| 影响运行 | 是（代码生成、重载） | 是（单态化、trait分发） | 否（注解被忽略，零开销） |
| 空值表示 | 指针/nullptr（无编译期保护） | `Option<T>`（必须处理） | `None`+`Optional[T]`（检查器提醒） |
| 错误处理 | 异常/返回码 | `Result<T,E>`（必须处理） | 异常（检查器不强制） |
| 泛型 | 模板（编译期特化） | 泛型（单态化/trait对象） | TypeVar（检查器层面，运行时不特化） |
| 接口 | 抽象类/虚函数 | trait（显式impl） | Protocol（结构化，隐式符合） |
| 注解可选性 | 否 | 否（局部变量可推断） | 是（完全可选，渐进式） |

**核心差异**：C++/Rust的类型是运行时的一部分（决定内存布局、调用约定、代码生成）；Python的类型注解只是开发时工具（文档+静态检查）。这意味着Python类型系统更灵活但更弱——不能保证运行时类型安全。

**系统程序员的正确心态**：不要期望Python类型注解达到C++/Rust的编译期保证。把它当成**高级文档+bug预防工具**——能在提交前捕获30%的类型相关bug，就已经值回票价。

## 7. 完整示例：带类型注解的报文解析器

```python
"""带完整类型注解的报文解析器。"""
from dataclasses import dataclass
from enum import Enum, auto
from typing import Callable, Iterator, Protocol, TypedDict

class PacketType(Enum):
    DATA = auto()
    HEARTBEAT = auto()
    CONTROL = auto()

@dataclass(frozen=True)
class Packet:
    pkt_type: PacketType
    seq: int
    payload: bytes

class PacketHandler(Protocol):
    """报文处理器协议：只要有handle方法就符合。"""
    def handle(self, packet: Packet) -> None: ...

class ParseResult(TypedDict):
    total: int
    by_type: dict[str, int]
    errors: list[str]

def parse_stream(data: bytes) -> Iterator[Packet]:
    """从字节流解析报文，逐产出（生成器）。"""
    pos = 0
    while pos + 4 <= len(data):
        try:
            pkt_type = PacketType(data[pos])
        except ValueError:
            pos += 1
            continue
        seq = int.from_bytes(data[pos + 1:pos + 3], "big")
        length = data[pos + 3]
        if pos + 4 + length > len(data):
            break
        payload = bytes(data[pos + 4:pos + 4 + length])
        yield Packet(pkt_type, seq, payload)
        pos += 4 + length

def process_packets(
    packets: Iterator[Packet],
    handler: PacketHandler,
    filter_fn: Callable[[Packet], bool] | None = None,
) -> ParseResult:
    """处理报文流，返回统计结果。"""
    total = 0
    by_type: dict[str, int] = {}
    errors: list[str] = []
    for packet in packets:
        if filter_fn and not filter_fn(packet):
            continue
        try:
            handler.handle(packet)
            total += 1
            name = packet.pkt_type.name
            by_type[name] = by_type.get(name, 0) + 1
        except Exception as e:
            errors.append(f"seq={packet.seq}: {e}")
    return {"total": total, "by_type": by_type, "errors": errors}

class CountingHandler:
    def __init__(self) -> None:
        self.count = 0
    def handle(self, packet: Packet) -> None:
        self.count += 1

if __name__ == "__main__":
    stream = bytes([1, 0, 1, 3, 0xAA, 0xBB, 0xCC, 2, 0, 2, 0])
    handler = CountingHandler()
    result = process_packets(
        parse_stream(stream), handler,
        filter_fn=lambda p: p.pkt_type != PacketType.HEARTBEAT,
    )
    print(f"处理完成: {result['total']} 个报文, {len(result['errors'])} 个错误")
```

## 8. 快速参考卡片

| 需求 | 做法 |
| --- | --- |
| 基本注解 | `def f(x: int, s: str = "") -> list[str]:` |
| 常用类型 | `list[int]`、`dict[str, int]`、`tuple[int, ...]`、`set[str]`（3.9+ 内置泛型） |
| 可选与联合 | `Optional[int]` / `int \| None`（3.10+）、`Union[A, B]` / `A \| B` |
| 可调用 | `Callable[[int, str], bool]`；`Iterable[T]`、`Iterator[T]`、`Sequence[T]` |
| 前向引用 | `from __future__ import annotations` 或字符串 `"Node"` |
| 只涉及类型 | `if TYPE_CHECKING:` 内导入，避免运行期循环依赖 |
| 静态检查 | `mypy --strict` / `pyright`；CI 里加 `--warn-unused-ignores` |
| 运行时校验 | `@dataclass` + `pydantic.BaseModel`（解析外部数据时用） |
| 渐进式策略 | 新代码全标注 → 公共接口优先 → 用 `Any` 兜底并逐步收紧 |
| 与 C++ 对照 | 注解不改变运行行为（无性能收益），价值在 IDE 提示与 CI 拦截 |

## 9. 常见坑

**坑1：用Any逃避类型检查**
```python
from typing import Any

def process(data: Any) -> Any:  # 等于没加注解
    return data["value"]
# Any会传染，调用方所有操作都不检查
```
尽量精确标注，只有真正无法确定时才用`Any`并加注释。

**坑2：可变默认参数的类型注解**
类型注解正确但运行时有坑（见《03-函数模块与包.md》）。用`None`做哨兵，注解为`list[str] | None`。ruff的B006规则可检测。

**坑3：第三方库没有类型存根**
```python
import some_library  # 无类型存根
result = some_library.parse(data)  # result被推断为Any
```
解决：`ignore_missing_imports = true`，或安装`types-xxx`存根包，或自己写`.pyi`存根。

**坑4：类型注解与运行时行为不一致**
```python
def get_config() -> dict[str, int]:
    return {"timeout": "5"}  # 注解说是int，实际是str
```
mypy会报错但运行时不报错。CI中必须运行类型检查，不能只靠编辑器提示。

## 10. 本节小结

- **类型注解是可选的**：运行时被忽略，不影响性能，由外部工具检查。可渐进式添加，不会破坏现有代码。
- **常用类型**：`Optional[X]`/`X | None`（可空）、`list/dict/set/tuple`泛型（3.9+内置语法）、`Callable`（函数类型）、`TypeVar`（泛型）、`Protocol`（结构化接口）、`TypedDict`（字典结构描述）。
- **工具选型**：pyright（VSCode实时检查）+ ruff（lint+format）+ mypy（CI严格检查）。配置统一放`pyproject.toml`。
- **渐进式策略**：先给新函数和数据结构加注解，再扩展到核心模块，最后全项目严格。一次性脚本和小工具不值得加注解。
- **与C++/Rust的本质差异**：C++/Rust类型是运行时的一部分，Python类型注解只是开发时工具。不要期望编译期保证，把它当成高级文档+bug预防工具。
