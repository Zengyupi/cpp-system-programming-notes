## 1. 工程场景：大日志与横切关注点

系统程序员日常面对两个典型问题：

**大日志分析**：生产日志动辄几个GB，`open().readlines()`一次性加载会爆内存。C++用`std::ifstream`逐行读，Python的最佳方案是**生成器（yield）**——逐行产出，内存占用恒定。

**横切关注点**：网络请求需要重试、函数需要计时、重复计算需要缓存、插件需要自动注册——这些逻辑散布在各函数中，直接写导致代码重复。C++用RAII类或模板元编程，Python的优雅方案是**装饰器**。

## 2. 可迭代协议与生成器

### 2.1 可迭代对象与迭代器

`for`循环的底层是可迭代协议：
- **可迭代对象**：实现`__iter__()`返回迭代器。如list、dict、str、文件对象。
- **迭代器**：实现`__iter__()`（返回自身）和`__next__()`（返回下一个元素，耗尽时raise `StopIteration`）。

```python
# for循环的底层等价
lst = [1, 2, 3]
it = iter(lst)        # 调用__iter__()
while True:
    try:
        item = next(it)  # 调用__next__()
        print(item)
    except StopIteration:
        break
```

迭代器是**惰性**的——只在`next()`时计算，可表示无限序列，内存恒定。

```python
class InfiniteCounter:
    def __init__(self, start: int = 0) -> None:
        self.current = start
    def __iter__(self) -> "InfiniteCounter":
        return self
    def __next__(self) -> int:
        value = self.current
        self.current += 1
        return value

from itertools import islice
print(list(islice(InfiniteCounter(0), 5)))  # [0,1,2,3,4]
```

C++对照：迭代器对应C++输入迭代器（Input Iterator），可迭代对象对应有`begin()`/`end()`的容器。Rust对应`Iterator` trait。

### 2.2 yield基础与生成器表达式

含`yield`的函数是生成器函数，调用时返回生成器对象（迭代器），不执行函数体。每次`next()`执行到下一个`yield`，暂停并返回值，下次从暂停处继续。

```python
def count_up_to(n: int):
    count = 0
    while count < n:
        yield count      # 暂停，返回count
        count += 1       # 下次next()从这里继续

for i in count_up_to(3):
    print(i)  # 0 1 2
```

关键特性：惰性求值、状态保持、内存高效。C++对照C++20协程`co_yield`，Rust无直接对应。

**生成器表达式**：推导式的惰性版本，用圆括号。

```python
# list推导式：立即生成，占内存
squares_list = [x**2 for x in range(1000000)]

# 生成器表达式：惰性，内存恒定
squares_gen = (x**2 for x in range(1000000))
for sq in squares_gen:
    if sq > 100: break
```

工程规则：只遍历一次且数据量大时用生成器表达式；需要多次访问/索引/数据量小时用list推导式。

### 2.3 流式处理大日志实战

生成器最有价值的工程场景。GB级日志逐行处理，内存占用恒定。

```python
from pathlib import Path
from typing import Iterator

def read_lines(filepath: Path) -> Iterator[str]:
    """逐行读取，内存恒定。"""
    with open(filepath, "r", encoding="utf-8", errors="replace") as f:
        for line in f:           # 文件对象本身就是迭代器
            yield line.rstrip("\n")

def filter_errors(lines: Iterator[str]) -> Iterator[str]:
    for line in lines:
        if "ERROR" in line:
            yield line

def count_by_minute(lines: Iterator[str]) -> dict[str, int]:
    counts: dict[str, int] = {}
    for line in lines:
        parts = line.split(maxsplit=2)
        minute = parts[1][:16] if len(parts) >= 2 else "?"
        counts[minute] = counts.get(minute, 0) + 1
    return counts

# 流式管道：文件→逐行→过滤→统计
# 整个过程内存中只有当前行和统计结果
lines = read_lines(Path("app.log"))    # 还没开始读
errors = filter_errors(lines)            # 还没开始过滤
stats = count_by_minute(errors)          # 触发执行，逐行流过管道
```

内存分析：`read_lines`每次只保留一行；`filter_errors`每次处理一行；`count_by_minute`只保留统计dict。即使日志10GB，内存占用几MB。

## 3. 装饰器：横切关注点的优雅解

### 3.1 装饰器原理与带参数装饰器

装饰器本质是**接收函数、返回新函数的高阶函数**。`@decorator`等价于`func = decorator(func)`。

```python
import time
from functools import wraps

def timer(func):
    @wraps(func)  # 保留原函数元信息（名称、文档）
    def wrapper(*args, **kwargs):
        start = time.perf_counter()
        result = func(*args, **kwargs)
        print(f"[{func.__name__}] 耗时: {(time.perf_counter()-start)*1000:.2f}ms")
        return result
    return wrapper

@timer
def process(data: bytes) -> int:
    return len(data)

# 等价于：process = timer(process)
process(b"hello")
```

关键点：装饰器在函数定义时执行（不是调用时）；`wrapper`用`*args/**kwargs`透传参数；`@wraps`保留元信息；装饰器可以叠加。

**带参数的装饰器**：多一层嵌套，外层接收参数返回真正的装饰器。执行顺序：`retry(...)`返回`decorator`，`decorator(func)`返回`wrapper`，`func = wrapper`。完整的重试装饰器实现见3.2节。

### 3.2 工程四件套之一：重试retry

不稳定操作（网络请求、设备连接、文件锁）需要重试。

```python
def retry(max_attempts: int = 3, delay: float = 1.0, backoff: float = 2.0,
          exceptions: tuple[type[Exception], ...] = (Exception,)):
    """重试装饰器：指数退避，指定异常类型。"""
    def decorator(func):
        @wraps(func)
        def wrapper(*args, **kwargs):
            current_delay = delay
            for attempt in range(1, max_attempts + 1):
                try:
                    return func(*args, **kwargs)
                except exceptions as e:
                    if attempt == max_attempts: raise
                    print(f"[{func.__name__}] 第{attempt}/{max_attempts}次失败: {e}，"
                          f"{current_delay:.1f}s后重试")
                    time.sleep(current_delay)
                    current_delay *= backoff
        return wrapper
    return decorator

@retry(max_attempts=3, delay=0.5, backoff=2.0, exceptions=(ConnectionError, TimeoutError))
def send_command(ip: str, port: int, cmd: str) -> str: ...
```

工程要点：指数退避避免打爆服务端；只重试可恢复异常（连接错误/超时），不重试编程错误。

### 3.3 工程四件套之二：计时timer

见3.1的基础实现。用`time.perf_counter()`（单调时钟，高精度）而非`time.time()`。也可以用上下文管理器计时代码块：

```python
class Timer:
    def __init__(self, label: str = "代码块") -> None:
        self.label = label
    def __enter__(self) -> "Timer":
        self.start = time.perf_counter()
        return self
    def __exit__(self, *args) -> None:
        print(f"[{self.label}] 耗时: {(time.perf_counter()-self.start)*1000:.2f}ms")

with Timer("日志统计"):
    total = sum(1 for _ in open("app.log", encoding="utf-8", errors="replace"))
```

### 3.4 工程四件套之三：lru_cache

`functools.lru_cache`是标准库内置缓存装饰器，缓存函数返回值。

```python
from functools import lru_cache

@lru_cache(maxsize=128)
def parse_header(data: bytes) -> dict:
    """解析协议头，相同报文头直接返回缓存。"""
    return {"version": data[0], "type": data[1], "length": int.from_bytes(data[2:4], "big")}

r1 = parse_header(b"\x01\x02\x00\x64")  # 计算并缓存
r2 = parse_header(b"\x01\x02\x00\x64")  # 直接返回缓存
print(parse_header.cache_info())  # CacheInfo(hits=1, misses=1, maxsize=128, currsize=1)
```

**重要限制**：
- 参数必须**可哈希**（int/str/tuple/bytes），不能是list/dict
- `maxsize=None`不限制大小可能内存泄漏，建议设上限
- 缓存返回值的引用，外部修改会污染缓存
- 函数不能有副作用（修改全局状态、写文件）

适用场景：纯函数+计算密集+重复调用。不适用：有副作用、参数不可哈希、返回值可能被修改。

### 3.5 工程四件套之四：插件注册器

装饰器自动注册插件/处理器，避免手动维护注册表。

```python
from collections.abc import Callable

protocol_handlers: dict[str, Callable] = {}

def register_protocol(name: str):
    def decorator(func):
        protocol_handlers[name] = func
        return func  # 返回原函数，不包装
    return decorator

@register_protocol("TCP")
def handle_tcp(data: bytes) -> dict:
    return {"proto": "TCP", "src_port": int.from_bytes(data[0:2], "big")}

@register_protocol("UDP")
def handle_udp(data: bytes) -> dict:
    return {"proto": "UDP", "length": int.from_bytes(data[4:6], "big")}

def dispatch(proto_name: str, data: bytes) -> dict:
    handler = protocol_handlers.get(proto_name)
    if handler is None:
        raise ValueError(f"未知协议: {proto_name}")
    return handler(data)

print(f"已注册: {list(protocol_handlers.keys())}")  # ['TCP', 'UDP']
```

工程价值：新增处理器只需写函数+加装饰器，不需修改分发代码。可配合`importlib`动态加载实现真正的插件化。C++对应工厂模式+自动注册，Rust对应`inventory` crate。

## 4. with上下文管理器与RAII对照

### 4.1 上下文管理器协议与C++ RAII对照

上下文管理器实现`__enter__`（获取资源）和`__exit__`（释放资源），`with`保证`__exit__`一定执行（即使异常）。

```python
class FileHandler:
    def __init__(self, path: str, mode: str = "r") -> None:
        self.path = path
        self.mode = mode
        self._file = None
    def __enter__(self):
        self._file = open(self.path, self.mode, encoding="utf-8")
        return self._file
    def __exit__(self, exc_type, exc_val, exc_tb):
        if self._file: self._file.close()
        return False

with FileHandler("app.log") as f:
    content = f.read()
# 自动关闭，即使read()抛异常
```

**C++ RAII对照**：

| C++ RAII | Python上下文管理器 |
|----------|-------------------|
| 构造函数 | `__enter__` |
| 析构函数 | `__exit__` |
| 栈对象作用域 | `with`块 |
| 异常时自动析构 | 异常时自动调用`__exit__` |
| `std::lock_guard` | `threading.Lock`的with用法 |
| `std::ifstream` | `open()`的with用法 |

关键差异：C++析构函数在对象离开作用域时自动调用（确定性销毁）；Python普通对象销毁由GC决定（不确定），但`with`块的`__exit__`是确定性的。Python必须用`with`保证资源释放，C++只要是栈对象就自动释放。

标准库中文件对象、`threading.Lock`、`socket.socket`、`subprocess.Popen`都是上下文管理器。

### 4.2 contextlib简化

`contextlib.contextmanager`用生成器语法写上下文管理器，不需要定义类。

```python
from contextlib import contextmanager
import time

@contextmanager
def timer_context(label: str = "代码块"):
    """用生成器语法实现计时上下文管理器。"""
    start = time.perf_counter()   # __enter__部分
    try:
        yield                      # 暂停，with块代码在这里执行
    finally:
        elapsed = time.perf_counter() - start  # __exit__部分
        print(f"[{label}] 耗时: {elapsed*1000:.2f}ms")

with timer_context("日志解析"):
    total = sum(1 for _ in open("app.log", encoding="utf-8", errors="replace"))
    print(f"总行数: {total}")
```

规则：`yield`之前是`__enter__`，之后是`__exit__`；必须用`try/finally`包裹`yield`确保异常时清理也执行；`yield`后可跟返回值绑定到`as`变量。

其他常用工具：
- `contextlib.closing(obj)`：将有`close()`但无`__enter__`/`__exit__`的对象包装成上下文管理器
- `contextlib.suppress(*exceptions)`：忽略指定异常

```python
from contextlib import suppress, closing

with suppress(FileNotFoundError):
    open("不存在的文件.txt").read()  # 忽略异常

with closing(MyResource()):  # 自动调用close()
    print("使用资源")
```

## 5. 完整示例：流式日志分析管道

结合生成器、装饰器、上下文管理器：

```python
"""流式日志分析管道：生成器+装饰器+上下文管理器综合示例。"""
import re
import time
from collections import Counter
from contextlib import contextmanager
from functools import lru_cache, wraps
from pathlib import Path
from typing import Iterator

def timer(func):
    @wraps(func)
    def wrapper(*args, **kwargs):
        start = time.perf_counter()
        result = func(*args, **kwargs)
        print(f"[{func.__name__}] 耗时: {time.perf_counter()-start:.2f}s")
        return result
    return wrapper

def read_lines(filepath: Path) -> Iterator[str]:
    with open(filepath, "r", encoding="utf-8", errors="replace") as f:
        for line in f:
            yield line.rstrip("\n")

LOG_PATTERN = re.compile(r"^(\d{4}-\d{2}-\d{2} \d{2}:\d{2}:\d{2})\s+(\w+)\s+(.*)$")

@lru_cache(maxsize=1024)
def parse_line(line: str) -> tuple[str, str, str] | None:
    m = LOG_PATTERN.match(line)
    return (m.group(1), m.group(2), m.group(3)) if m else None

def filter_level(lines: Iterator[str], level: str) -> Iterator[tuple[str, str, str]]:
    order = {"DEBUG":10, "INFO":20, "WARN":30, "ERROR":40}
    threshold = order.get(level, 0)
    for line in lines:
        parsed = parse_line(line)
        if parsed and order.get(parsed[1], 0) >= threshold:
            yield parsed

@timer
def analyze_log(filepath: Path, min_level: str = "ERROR") -> None:
    records = filter_level(read_lines(filepath), min_level)
    minute_counts: Counter[str] = Counter()
    error_msgs: Counter[str] = Counter()
    for ts, level, msg in records:
        minute_counts[ts[:16]] += 1
        error_msgs[" ".join(msg.split()[:3])] += 1
    print(f"\n按分钟错误分布:")
    for minute, count in sorted(minute_counts.items()):
        print(f"  {minute}: {count}")
    print(f"\nTop 5错误类型:")
    for msg, count in error_msgs.most_common(5):
        print(f"  {count}x: {msg}")

if __name__ == "__main__":
    analyze_log(Path("app.log"))
```

## 6. 常见坑

**坑1：生成器只能遍历一次**
```python
gen = (x for x in range(3))
print(list(gen))  # [0,1,2]
print(list(gen))  # [] —— 已耗尽！需要多次遍历时用list或重新创建
```

**坑2：lru_cache缓存可变返回值**
```python
@lru_cache(maxsize=10)
def get_config() -> dict:
    return {"timeout": 5}
cfg = get_config()
cfg["timeout"] = 999
print(get_config())  # {'timeout': 999} —— 缓存被污染！
# 解决：返回不可变对象，或声明不要修改返回值
```

**坑3：装饰器丢失函数元信息**
```python
def bad_decorator(func):
    def wrapper(*args, **kwargs): return func(*args, **kwargs)
    return wrapper  # 没有@wraps
@bad_decorator
def my_func():
    """我的函数。"""
print(my_func.__name__)  # wrapper —— 不是my_func！
# 解决：始终用@functools.wraps(func)
```

**坑4：在生成器中修改正在迭代的列表**
```python
# 错误：迭代时修改列表会跳过元素
# 解决：遍历副本，或用推导式创建新列表
def filter_even(lst): return [x for x in lst if x % 2 != 0]
```

**坑5：with中return导致__exit__不执行？**
不会。`with`保证`__exit__`一定执行，即使有`return`/`break`/异常。这是`with`的核心保证。

## 7. 本节小结

- **可迭代协议**：可迭代对象实现`__iter__`返回迭代器，迭代器实现`__next__`逐个产出。`for`循环底层是`iter()`+`next()`+`StopIteration`。
- **生成器（yield）**：Python最强大的流式处理工具。惰性求值、内存恒定、状态保持。GB级日志逐行处理的标准方案。生成器表达式`(x for x in ...)`是推导式的惰性版本。
- **装饰器四件套**：
  - `retry`：不稳定操作的自动重试+指数退避，只重试可恢复异常
  - `timer`：函数/代码块执行时间统计，用`time.perf_counter()`
  - `lru_cache`：纯函数结果缓存（参数必须可哈希、函数无副作用、注意缓存污染）
  - 插件注册器：自动注册处理器，实现开放-封闭原则
- **with上下文管理器**：对应C++ RAII。`__enter__`获取资源，`__exit__`释放资源，`with`块保证一定执行。`contextlib.contextmanager`用生成器语法简化实现。
- **组合使用**：生成器管道处理数据流，装饰器处理横切关注点，上下文管理器管理资源——三者结合是Python工具脚本的经典架构。
