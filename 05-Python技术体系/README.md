## 1. 模块定位：系统程序员的Python工具箱

本模块不是Python就业方向教程，不教Django/Flask全栈、不教数据分析与AI应用、不教游戏开发。它的唯一目标是：**让写C++/Rust的工程师，把Python当成一把高杠杆的瑞士军刀，嵌入日常系统开发工作流**。

C++/Rust的核心价值在于性能、内存安全与底层控制，但代价是开发周期长、编译慢、写一次性脚本的性价比极低。Python恰好补上这块短板：解释执行、语法简洁、标准库与第三方生态极其丰富，写一个50行的报文解析器或日志过滤器，Python的开发效率是C++的5到10倍。

典型的工作模式是：**核心路径用C++/Rust写，外围工具用Python写**。一个工业网关项目中，C++负责实时报文收发与协议处理，Python负责：批量生成测试报文、对拍C++编解码结果、分析core dump后的日志、自动化构建与回归测试、快速验证新协议字段的解析逻辑。

## 2. 场景地图：Python在系统工程中的六大用武之地

### 2.1 批处理自动化

批量重命名日志文件、批量转换编码、批量提取core dump中的堆栈、批量修改配置文件中的IP段。这类任务的特点是：一次性或周期性、逻辑简单但重复、用Shell写容易陷入引号地狱，用C++写要编译链接得不偿失。Python的`pathlib`、`re`、`subprocess`三件套足以覆盖90%的场景。

### 2.2 构建与CI集成

CMake的`execute_process`可以调Python脚本做代码生成（如根据协议描述文件自动生成C++结构体与编解码函数）；CI流水线中用Python脚本解析编译警告、统计代码覆盖率、生成变更报告。相比Shell脚本，Python在跨平台（Windows/Linux）一致性、JSON/XML解析、错误处理上有压倒性优势。相关构建脚本基础可参考《../01-C++技术体系/06-构建与版本控制/04-Shell脚本编程.md》。

### 2.3 测试对拍与数据生成

这是Python对C++/Rust项目最有价值的场景之一。用Python快速实现一个协议编解码器的"参考实现"，然后随机生成海量报文，对拍C++实现与Python参考实现的输出是否一致。Python的`random`、`struct`、`hypothesis`（以PyPI最新稳定版为准）能在几十行代码内完成模糊测试框架。并发场景下的测试数据生成可参考《../01-C++技术体系/04-并发编程/05-线程池与并发实战模式.md》中的对拍思路。

### 2.4 调试与日志分析

生产环境出问题时，日志动辄几个GB。用Python写流式分析脚本：按时间窗口聚合错误、提取特定会话ID的完整调用链、统计异常分布、生成时序图数据。生成器（yield）天然适合流式处理大文件，不需要把整个日志加载到内存。调试中的异常分析可参考《../01-C++技术体系/01-语言基础/07-异常处理与异常安全.md》。

### 2.5 网络与二进制工具

快速写一个TCP/UDP测试客户端、模拟设备上报报文、抓包后解析自定义二进制协议。Python的`socket`、`struct`、`scapy`（以PyPI最新稳定版为准）让网络工具开发变得极其轻量。`struct.pack/unpack`对应C语言的`memcpy`类型强转，但跨平台字节序安全。Rust侧的二进制处理可参考《../04-Rust技术体系/02-Rust进阶机制/02-Unsafe裸指针与FFI互操作.md》。

### 2.6 混合编程与原型验证

用Python快速验证算法逻辑（如路由表查找、CRC校验、状态机），确认正确后再移植到C++/Rust。或者通过`ctypes`/`cffi`/`pybind11`（以PyPI最新稳定版为准）直接调用C++动态库，在Python中做集成测试。异步原型验证可参考《../04-Rust技术体系/03-并发与异步编程/04-Tokio运行时与异步生态.md》。

## 3. C++/Rust工程师最小学习路径

对于已有C++/Rust基础的工程师，Python的学习曲线非常平缓，因为大部分编程概念（变量、函数、类、模块、异常）已经熟悉，需要学的主要是**语法差异和Python特有的惯用法**。

**第一阶段（1-2天）：能读能改**
- 阅读《01-Python语言速成/01-环境工具链与运行模型.md》，搭好环境，理解解释执行模型
- 阅读《01-Python语言速成/02-语法精要与CppRust对照.md》，掌握缩进、变量引用语义、常用容器、推导式
- 能读懂已有Python脚本并做小修改

**第二阶段（3-5天）：能写工具脚本**
- 阅读《01-Python语言速成/03-函数模块与包.md》，掌握参数模型与import机制
- 阅读《01-Python语言速成/04-面向对象够用篇.md》，知道何时用类、何时用函数式
- 阅读《01-Python语言速成/05-迭代器生成器与装饰器.md》，掌握流式处理与工程装饰器
- 独立写出100-300行的批处理/日志分析/报文生成脚本

**第三阶段（按需）：工程化与进阶**
- 阅读《01-Python语言速成/06-类型注解与检查工具.md》，给长期维护的脚本加类型注解
- 按需学习`subprocess`、`argparse`、`logging`、`json`、`pathlib`等标准库模块
- 按需学习`pybind11`混合编程、`pytest`测试框架、`ruff`代码检查

**核心原则：不要试图系统学完Python再用，而是带着具体工具需求边查边写。** C++/Rust工程师最容易犯的错误是用C++的思维写Python（比如过度设计类层次、手动管理资源），应该主动拥抱Python的"够用就好"哲学。

## 4. 本库刻意不讲的主题及原因

| 主题 | 不讲原因 |
|------|----------|
| 数据分析（pandas/numpy） | 属于数据科学职业栈，与系统工程日常关联弱；如需处理表格数据，标准库`csv`+`json`足够 |
| AI/机器学习应用 | 属于AI职业栈，模型训练与推理不是系统程序员的核心工作；如需调用AI API，`requests`即可 |
| Web全栈（Django/Flask/FastAPI） | 属于后端职业栈，系统程序员偶尔写个内部管理页面用Flask即可，不需要深入 |
| 游戏开发（Pygame等） | 与系统工程无关 |
| 桌面GUI（PyQt/Tkinter） | 系统工具以CLI为主，GUI需求极少；如需简单界面可用`tkinter`快速搭 |
| 异步编程（asyncio） | 系统程序员的异步需求在C++/Rust侧解决（epoll/io_uring/Tokio），Python侧写同步脚本更简单；仅在需要高并发网络工具时才涉及 |
| 元编程与高级魔法（metaclass/descriptor深度） | 工具脚本几乎用不到，属于框架开发者的领域 |
| 打包发布（PyInstaller/setuptools深度） | 内部工具直接`python script.py`运行即可，不需要打包成exe或发布到PyPI |

## 5. Python↔C++/Rust分工对照表

| 维度 | C++ | Rust | Python | 系统工程中的典型分工 |
|------|-----|------|--------|---------------------|
| 执行模型 | 编译为机器码，直接执行 | 编译为机器码，直接执行 | 解释执行（CPython字节码） | 核心路径C++/Rust，外围工具Python |
| 内存管理 | 手动/RAII/智能指针 | 所有权+借用检查 | GC（引用计数为主） | 不需要手动管理内存的脚本用Python |
| 类型系统 | 静态强类型，编译期检查 | 静态强类型，编译期检查 | 动态类型，可选注解 | 快速原型用Python，稳定后移植C++/Rust |
| 开发效率 | 低（编译慢、语法繁琐） | 中（编译慢但工具链好） | 高（解释执行、语法简洁） | 一次性脚本用Python |
| 运行性能 | 极高 | 极高 | 低（约C++的1/10-1/50） | 性能敏感路径必须C++/Rust |
| 并发模型 | 线程+锁/原子，易出bug | 线程+async，编译期防数据竞争 | GIL限制多线程，多进程为主 | 高并发在C++/Rust侧，Python做单线程脚本 |
| 跨平台 | 需处理平台差异（#ifdef） | cargo统一管理 | 标准库高度跨平台 | 跨平台构建脚本用Python |
| 生态 | 系统级库丰富 | 生态快速增长 | 第三方库极其丰富 | 快速调用成熟库（如解析各种格式）用Python |
| 调试 | gdb/lldb，core dump | rust-gdb，编译期错误多 | pdb，错误信息友好 | 快速验证逻辑用Python调试 |
