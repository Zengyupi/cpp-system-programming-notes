## 1. 工程场景：文本处理在系统编程中的位置

C++/Rust 项目的日常工作充满了半结构化文本：gcc/clang 的编译错误输出、gdb 的回溯栈、Valgrind 的内存报告、`compile_commands.json`、协议报文的十六进制 dump、设备日志。这些文本不是给人读的，而是需要被程序解析、归类、聚合、再生成新的文本（如报告、配置、代码）。

Python 的 `str` + `re` + 结构化文本库（csv/json/toml）+ Jinja2 模板，构成了完整的"文本进、结构化数据出、文本再出"流水线。典型场景：

- **编译错误提取**：从 `make 2>&1 | tee build.log` 中提取所有 `error:` 行，按文件归类去重，生成错误报告
- **gdb 调用栈提取**：从 `bt full` 输出中解析帧号、函数名、文件名、行号，生成调用栈 JSON
- **配置文件生成**：从 CSV 协议表生成 C++ 结构体定义和 CMakeLists 中的源文件列表

## 2. str 高频方法速查

### 2.1 分割与拼接

```python
# split：按分隔符分割，maxsplit 限制次数
"src/net/tcp.cpp".split("/")          # ['src', 'net', 'tcp.cpp']
"a,b,c,d".split(",", maxsplit=2)      # ['a', 'b', 'c,d']

# rsplit：从右往左分割
"src/net/tcp.cpp".rsplit("/", 1)      # ['src/net', 'tcp.cpp']

# splitlines：按换行符分割（自动处理 \r\n / \n / \r）
"line1\r\nline2\nline3".splitlines()  # ['line1', 'line2', 'line3']

# partition：分割成 (前, 分隔符, 后) 三元组，找不到时分隔符为空
"error: undefined reference".partition(":")  # ('error', ':', ' undefined reference')

# join：拼接
"/".join(["src", "net", "tcp.cpp"])   # 'src/net/tcp.cpp'
" ".join(["gcc", "-c", "main.cpp"])    # 'gcc -c main.cpp'
```

### 2.2 查找与替换

```python
s = "tcp_connection.cpp:42: error: 'foo' was not declared"

# find / rfind：返回索引，找不到返回 -1
s.find("error")        # 23
s.rfind(":")           # 28（最后一个冒号）

# startswith / endswith：支持元组多匹配
s.startswith("tcp_")   # True
s.endswith((".cpp", ".hpp"))  # False（以 'declared' 结尾）

# replace：替换所有或指定次数
s.replace("error", "ERROR")     # 替换所有
s.replace(":", "->", 1)         # 只替换第一个

# count：统计出现次数
s.count(":")          # 3
```

### 2.3 清洗与转换

```python
s = "  \t  Hello World  \n  "

s.strip()       # 'Hello World'（去两端空白）
s.lstrip()      # 'Hello World  \n  '
s.rstrip()      # '  \t  Hello World'
s.strip(" \t\n")  # 同上，显式指定字符

"hello".upper()         # 'HELLO'
"HELLO".lower()         # 'hello'
"hello world".title()   # 'Hello World'
"Hello".swapcase()      # 'hELLO'

"  hello  ".center(20, "-")   # '-------  hello  ------'
"42".zfill(5)                  # '00042'（补零）

# 字符串判断
"123".isdigit()       # True
"abc".isalpha()       # True
"abc123".isalnum()    # True
"  ".isspace()        # True
"Hello".istitle()     # True
```

## 3. re 正则全表

### 3.1 核心函数与模式

```python
import re

# 常用函数
re.match(pattern, text)       # 从开头匹配，返回 Match 或 None
re.search(pattern, text)      # 搜索第一个匹配
re.findall(pattern, text)     # 返回所有匹配的字符串列表
re.finditer(pattern, text)    # 返回 Match 对象迭代器（流式，推荐大文件）
re.sub(pattern, repl, text)   # 替换
re.split(pattern, text)       # 按正则分割
re.compile(pattern, flags)    # 预编译（多次使用时性能更好）

# 常用标志
re.IGNORECASE / re.I    # 忽略大小写
re.MULTILINE / re.M     # ^ 和 $ 匹配每行首尾
re.DOTALL / re.S        # . 匹配换行符
re.VERBOSE / re.X       # 允许模式中有空白和注释
re.ASCII / re.A         # 仅 ASCII 匹配（\w \d 等不匹配 Unicode）
```

### 3.2 贪婪与非贪婪

```python
text = '<div class="a">content</div><div class="b">more</div>'

# 贪婪：.* 尽可能多匹配
re.findall(r'<div class="(.*)">(.*)</div>', text)
# [('a">content</div><div class="b', 'more')]  ← 贪婪吞掉了中间部分

# 非贪婪：.*? 尽可能少匹配
re.findall(r'<div class="(.*?)">(.*?)</div>', text)
# [('a', 'content'), ('b', 'more')]  ← 正确
```

**工程场景**：从日志中提取引号内的字符串，必须用非贪婪，否则会跨多条日志匹配。

```python
log = 'msg="connect" level=INFO msg="disconnect" level=ERROR'
re.findall(r'msg="(.*?)"', log)   # ['connect', 'disconnect']
re.findall(r'msg="(.*)"', log)     # ['connect" level=INFO msg="disconnect']  ← 错误
```

### 3.3 分组与命名分组

```python
# 编号分组：从 1 开始，group(0) 是整个匹配
pattern = re.compile(r'(\w+)\.(\w+):(\d+):\s+(error|warning):\s+(.*)')
m = pattern.search("tcp_connection.cpp:42: error: 'foo' was not declared")
m.group(0)   # 整行
m.group(1)   # 'tcp_connection'
m.group(2)   # 'cpp'
m.group(3)   # '42'
m.group(4)   # 'error'
m.group(5)   # "'foo' was not declared"
m.groups()   # ('tcp_connection', 'cpp', '42', 'error', "'foo' was not declared")

# 命名分组：(?P<name>...)，可读性更好
pattern = re.compile(
    r'(?P<file>[\w./-]+):(?P<line>\d+):(?P<col>\d+):\s+'
    r'(?P<level>error|warning):\s+(?P<msg>.*)'
)
m = pattern.search("src/net/tcp.cpp:42:10: error: 'foo' was not declared")
m.groupdict()
# {'file': 'src/net/tcp.cpp', 'line': '42', 'col': '10',
#  'level': 'error', 'msg': "'foo' was not declared"}
```

### 3.4 零宽断言

零宽断言不消耗字符，只判断位置是否满足条件。

```python
# 正向先行断言 (?=...)：后面必须是
# 提取 .so 文件名中的版本号（后面必须是 .so）
re.findall(r'lib\w+(?=\.so)', "libcore.so libutil.so.1")  # ['libcore', 'libutil']

# 负向先行断言 (?!...)：后面不能是
# 匹配不是 .tmp 结尾的文件名
re.findall(r'\w+\.(?!tmp\b)\w+', "a.cpp b.tmp c.hpp")  # ['a.cpp', 'c.hpp']

# 正向后行断言 (?<=...)：前面必须是
# 提取 error: 后面的消息
re.findall(r'(?<=error: ).*', "error: segfault")  # ['segfault']

# 负向后行断言 (?<!...)：前面不能是
# 匹配不在 // 注释中的 TODO
re.findall(r'(?<!// )TODO', "TODO: fix this  // TODO: later")  # ['TODO']（只匹配第一个）
```

### 3.5 finditer 流式匹配大文件

`findall()` 把所有匹配加载到内存，GB 级日志会 OOM。`finditer()` 返回迭代器，逐行处理。

```python
import re

# 预编译模式
ERROR_PATTERN = re.compile(
    r'(?P<file>[\w./-]+):(?P<line>\d+):\s+(?P<level>error|warning):\s+(?P<msg>.*)'
)

def scan_errors(log_path: str):
    """流式扫描日志，逐行匹配，不加载整个文件。"""
    with open(log_path, "r", encoding="utf-8", errors="replace") as f:
        for line_no, line in enumerate(f, 1):
            m = ERROR_PATTERN.search(line)
            if m:
                yield {
                    "log_line": line_no,
                    **m.groupdict(),
                }

# 用法：边读边处理，内存占用恒定
for err in scan_errors("huge_build.log"):
    print(f"[{err['level']}] {err['file']}:{err['line']} {err['msg'][:60]}")
```

## 4. 实战：从编译日志提取错误

gcc/clang 的错误输出格式：`文件:行:列: 级别: 消息`，后续行可能是 `note:` 或代码上下文。需要提取所有 error/warning，按文件归类，去重。

```python
import re
from collections import defaultdict
from pathlib import Path

# 匹配 gcc/clang 诊断行
DIAG_PATTERN = re.compile(
    r'^(?P<file>[\w./\\-]+):(?P<line>\d+):(?P<col>\d+):\s+'
    r'(?P<level>error|warning|note):\s+(?P<msg>.*)$'
)

def parse_build_log(log_path: Path) -> dict:
    """解析编译日志，按文件归类错误和警告。"""
    issues = defaultdict(list)
    current_file = None

    with log_path.open("r", encoding="utf-8", errors="replace") as f:
        for line in f:
            m = DIAG_PATTERN.match(line.rstrip("\n"))
            if m:
                data = m.groupdict()
                data["line"] = int(data["line"])
                data["col"] = int(data["col"])
                issues[data["file"]].append(data)
                current_file = data["file"]
            elif current_file and line.startswith(" "):
                # 上下文行（代码片段或 ^ 标记），附加到最后一条
                if issues[current_file]:
                    last = issues[current_file][-1]
                    last.setdefault("context", []).append(line.rstrip("\n"))

    return dict(issues)

def deduplicate(issues: dict) -> dict:
    """同一文件同一行同一消息去重。"""
    result = {}
    for fname, item_list in issues.items():
        seen = set()
        unique = []
        for item in item_list:
            key = (item["line"], item["level"], item["msg"])
            if key not in seen:
                seen.add(key)
                unique.append(item)
        result[fname] = unique
    return result

def print_report(issues: dict):
    """打印错误报告。"""
    total_errors = sum(1 for items in issues.values() for i in items if i["level"] == "error")
    total_warnings = sum(1 for items in issues.values() for i in items if i["level"] == "warning")
    print(f"总计: {total_errors} errors, {total_warnings} warnings, {len(issues)} files")
    print("=" * 70)

    for fname in sorted(issues):
        items = issues[fname]
        errors = [i for i in items if i["level"] == "error"]
        warnings = [i for i in items if i["level"] == "warning"]
        print(f"\n{fname}  ({len(errors)} errors, {len(warnings)} warnings)")
        print("-" * 70)
        for item in sorted(items, key=lambda x: x["line"]):
            print(f"  L{item['line']}:{item['col']} [{item['level']}] {item['msg'][:80]}")

# 用法
issues = parse_build_log(Path("build.log"))
issues = deduplicate(issues)
print_report(issues)
```

## 5. 实战：从 gdb 输出提取调用栈

`gdb -batch -ex "bt full" -ex "quit" ./program core` 的输出包含帧号、函数名、参数、文件名、行号。解析后可生成 JSON 调用栈，用于批量分析 core 文件。

```python
import re
import json
from pathlib import Path

# 匹配帧行：#0  func (arg=val) at file:line
FRAME_PATTERN = re.compile(
    r'^#(?P<frame>\d+)\s+(?P<func>[\w:<>,~*&]+)\s*'
    r'\((?P<args>.*?)\)\s+at\s+(?P<file>[\w./-]+):(?P<line>\d+)'
)
# 匹配无调试信息的帧：#0  0x00007f... in func () from /lib/libc.so.6
FRAME_NO_DEBUG = re.compile(
    r'^#(?P<frame>\d+)\s+0x[0-9a-f]+ in (?P<func>[\w:<>,~*&]+)\s*'
    r'\((?P<args>.*?)\)\s+from\s+(?P<lib>[\w./-]+)'
)

def parse_gdb_bt(output: str) -> list:
    """解析 gdb bt 输出，返回帧列表。"""
    frames = []
    for line in output.splitlines():
        m = FRAME_PATTERN.match(line)
        if m:
            frames.append({
                "frame": int(m.group("frame")),
                "func": m.group("func"),
                "args": m.group("args"),
                "file": m.group("file"),
                "line": int(m.group("line")),
                "has_debug": True,
            })
            continue
        m = FRAME_NO_DEBUG.match(line)
        if m:
            frames.append({
                "frame": int(m.group("frame")),
                "func": m.group("func"),
                "args": m.group("args"),
                "lib": m.group("lib"),
                "has_debug": False,
            })
    return frames

# 用法：批量解析 core 文件的 gdb 输出
core_dir = Path("cores")
for core_file in sorted(core_dir.glob("core.*")):
    # 假设已经用 gdb 批量生成了 bt 输出
    bt_file = core_file.with_suffix(".bt")
    if bt_file.exists():
        frames = parse_gdb_bt(bt_file.read_text(encoding="utf-8"))
        print(f"{core_file.name}: {len(frames)} frames, top = {frames[0]['func'] if frames else 'N/A'}")
        # 保存 JSON
        core_file.with_suffix(".bt.json").write_text(
            json.dumps(frames, indent=2, ensure_ascii=False), encoding="utf-8"
        )
```

## 6. 结构化文本读写：csv/json/toml

### 6.1 csv 读写

CSV 常用于协议表、寄存器表、测试用例表。`csv` 模块处理引号、逗号转义。

```python
import csv
from pathlib import Path

# 读取 CSV（DictReader 返回字典）
with Path("protocol.csv").open("r", encoding="utf-8-sig") as f:
    reader = csv.DictReader(f)
    for row in reader:
        print(row["field_name"], row["offset"], row["type"])

# 写入 CSV
with Path("output.csv").open("w", encoding="utf-8", newline="") as f:
    writer = csv.DictWriter(f, fieldnames=["name", "offset", "size", "type"])
    writer.writeheader()
    writer.writerow({"name": "msg_type", "offset": 0, "size": 2, "type": "uint16"})
    writer.writerow({"name": "length", "offset": 2, "size": 2, "type": "uint16"})
```

**注意**：Windows 下写 CSV 必须设 `newline=""`，否则会出现空行。

### 6.2 json 读写

JSON 是 `compile_commands.json`、配置文件、API 响应的通用格式。

```python
import json
from pathlib import Path

# 读取
data = json.loads(Path("compile_commands.json").read_text(encoding="utf-8"))

# 写入（ensure_ascii=False 保留中文，indent=2 美化）
Path("output.json").write_text(
    json.dumps(data, indent=2, ensure_ascii=False),
    encoding="utf-8"
)

# 流式读取 JSON Lines（每行一个 JSON 对象，大日志常用）
with Path("events.jsonl").open("r", encoding="utf-8") as f:
    for line in f:
        obj = json.loads(line)
        process(obj)
```

### 6.3 toml 读写

TOML 是 Rust `Cargo.toml`、Python `pyproject.toml` 的配置格式。Python 3.11+ 标准库自带 `tomllib`（只读），写入需第三方库 `tomli_w`。

```python
import tomllib  # Python 3.11+，标准库只读
from pathlib import Path

# 读取 Cargo.toml
with Path("Cargo.toml").open("rb") as f:
    cargo = tomllib.load(f)

print(cargo["package"]["name"])
print(cargo["dependencies"].get("serde", {}).get("version"))

# 写入 TOML（需 tomli_w，pip install tomli_w）
import tomli_w
config = {
    "build": {"target": "x86_64-unknown-linux-gnu", "release": True},
    "features": ["tcp", "udp", "serial"],
}
Path("build.toml").write_bytes(tomli_w.dumps(config).encode("utf-8"))
```

## 7. Jinja2 最小用法：生成配置文件与 CMake 片段

Jinja2 是 Python 最流行的模板引擎（`pip install jinja2`），用于从数据生成文本文件。系统程序员常用它从协议表、配置数据生成 C++ 代码、CMakeLists、配置文件。

```python
from jinja2 import Template
from pathlib import Path

# 最小用法：字符串模板
template = Template("""\
#ifndef {{ guard|upper }}
#define {{ guard|upper }}

// 自动生成，请勿手动编辑
struct {{ struct_name }} {
{% for field in fields %}
    {{ field.cpp_type }} {{ field.name }};  // offset {{ field.offset }}
{% endfor %}
};

#endif // {{ guard|upper }}
""")

fields = [
    {"name": "msg_type", "cpp_type": "uint16_t", "offset": 0},
    {"name": "length", "cpp_type": "uint16_t", "offset": 2},
    {"name": "payload", "cpp_type": "uint8_t[256]", "offset": 4},
]

output = template.render(
    guard="PROTOCOL_MESSAGE_H",
    struct_name="ProtocolMessage",
    fields=fields,
)
Path("protocol_message.h").write_text(output, encoding="utf-8")
```

生成 CMakeLists 源文件列表：

```python
from jinja2 import Environment, FileSystemLoader

# 从文件加载模板（推荐项目中使用）
env = Environment(loader=FileSystemLoader("templates"))
template = env.get_template("CMakeLists.txt.j2")

sources = ["src/main.cpp", "src/net/tcp.cpp", "src/util/log.cpp"]
output = template.render(
    project_name="myapp",
    sources=sources,
    cxx_standard=17,
)
```

模板文件 `templates/CMakeLists.txt.j2`：

```cmake
cmake_minimum_required(VERSION 3.16)
project({{ project_name }} CXX)

set(CMAKE_CXX_STANDARD {{ cxx_standard }})
set(CMAKE_CXX_STANDARD_REQUIRED ON)

add_executable({{ project_name }}
{% for src in sources %}
    {{ src }}
{% endfor %}
)
```

Jinja2 核心语法速查：

| 语法 | 用途 |
|---|---|
| `{{ var }}` | 输出变量 |
| `{{ var \| filter }}` | 过滤器（upper/lower/trim/default） |
| `{% if cond %}...{% endif %}` | 条件 |
| `{% for x in list %}...{% endfor %}` | 循环 |
| `{% set var = value %}` | 变量赋值 |
| `{# comment #}` | 注释 |
| `{% macro name(args) %}...{% endmacro %}` | 宏（可复用片段） |

## 8. 常见坑与避坑指南

| 坑 | 现象 | 解决方案 |
|---|---|---|
| 正则贪婪匹配 | `.*` 吞掉跨多行内容 | 用 `.*?` 非贪婪，或用 `[^"]*` 排除字符类 |
| `.` 不匹配换行 | 跨行匹配失败 | 用 `re.DOTALL` 标志，或 `[\s\S]*` |
| `^$` 只匹配首尾 | 多行文本每行匹配失败 | 用 `re.MULTILINE` 标志 |
| 原始字符串遗漏 | `\d` 写成 `"\\d"` 或 `\d` 被转义 | 正则模式始终用 `r"..."` 原始字符串 |
| CSV Windows 空行 | 每行后多一个空行 | 写文件时设 `newline=""` |
| JSON 中文乱码 | `\u4e2d\u6587` 转义 | `json.dumps(ensure_ascii=False)` |
| re.match vs re.search | 模式不在开头时 match 返回 None | 从中间搜索用 `re.search()`，`re.match()` 只匹配开头 |
| 分组引用越界 | `IndexError: no such group` | 检查分组编号，命名分组用 `groupdict()` 更安全 |
| 大文件 findall OOM | 内存爆炸 | 用 `finditer()` 或逐行 `search()` |

## 9. 本节小结

- `str` 方法覆盖分割、查找、替换、清洗，是文本处理的基础层
- `re` 正则核心是命名分组 + `finditer` 流式匹配，贪婪/非贪婪和零宽断言是进阶必备
- 编译日志提取和 gdb 调用栈解析是系统程序员最常用的两个文本解析场景
- csv/json/toml 覆盖了协议表、构建配置、结构化日志的读写需求
- Jinja2 模板是从数据生成代码/配置的标准工具，配合 CSV/JSON 可实现"配置表→代码"流水线
