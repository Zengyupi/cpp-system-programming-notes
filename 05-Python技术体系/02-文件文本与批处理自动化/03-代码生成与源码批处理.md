## 1. 工程场景：为什么需要代码生成

C++/Rust 项目中存在大量"机械重复但必须精确"的代码：协议报文的结构体定义与序列化、枚举与字符串的双向映射、消息类型的注册分发、寄存器字段的读写封装。这些代码模式固定、数量庞大、手写易错，且一旦协议变更需要同步修改多处。

代码生成的核心价值：

- **单一数据源**：协议/枚举定义在 CSV/TOML/JSON 中，代码从定义生成，避免多处不一致
- **减少手写错误**：序列化代码的偏移量、字节序、字段大小由程序计算，不会算错
- **多语言同步**：同一份协议定义同时生成 C++ 和 Rust 代码，保证跨语言一致性
- **可审计**：生成器代码可 review，生成结果可 diff，比手写大段重复代码更可靠

典型场景：

- 通讯协议有 50 种消息类型，每种有 5-20 个字段，需要生成 C++ 结构体 + 序列化 + 消息注册
- 错误码表有 200 个条目，需要生成 C++ enum + `toString()` + Rust enum + `Display`
- 寄存器映射表有 100 个寄存器，需要生成读写函数和字段掩码

## 2. 代码生成方案选型

### 2.1 字符串拼接 vs Jinja2 模板

| 方案 | 适用场景 | 优点 | 缺点 |
|---|---|---|---|
| f-string 拼接 | 简单、短代码片段 | 无需依赖，直观 | 复杂模板可读性差，逻辑与输出混杂 |
| Jinja2 模板 | 复杂、多文件、有循环/条件 | 模板与逻辑分离，可复用，支持继承 | 需第三方库，模板语法有学习成本 |
| 专用代码生成库（如 Cog） | 嵌入现有源码中生成 | 生成代码与手写代码同文件 | 工具链侵入，调试困难 |

**经验法则**：生成代码超过 30 行或包含循环/条件，用 Jinja2；简单几行用 f-string。

### 2.2 生成代码的组织原则

1. **生成文件单独存放**：`generated/` 目录，不与手写代码混放，`.gitignore` 中可选择忽略或提交
2. **文件头标注自动生成**：`// AUTO-GENERATED by gen_protocol.py, DO NOT EDIT`
3. **幂等**：相同输入永远生成相同输出，避免无意义 diff
4. **可重入**：生成器可随时重跑，不依赖上次生成结果
5. **校验**：生成后编译验证，或用 AST 检查语法

### 3.2 生成 C++ enum + 字符串映射

```python
import csv
from pathlib import Path
from jinja2 import Template

CPP_TEMPLATE = Template("""\
// AUTO-GENERATED by gen_enum.py, DO NOT EDIT
#ifndef {{ guard|upper }}
#define {{ guard|upper }}

#include <cstdint>
#include <string>
#include <optional>

namespace {{ namespace }} {

enum class {{ enum_name }} : uint16_t {
{% for item in items %}
    {{ item.name }} = {{ item.value }},  // {{ item.description }}
{% endfor %}
};

inline const char* toString({{ enum_name }} v) {
    switch (v) {
{% for item in items %}
    case {{ enum_name }}::{{ item.name }}: return "{{ item.name }}";
{% endfor %}
    default: return "UNKNOWN";
    }
}

inline std::optional<{{ enum_name }}> fromString(const std::string& s) {
{% for item in items %}
    if (s == "{{ item.name }}") return {{ enum_name }}::{{ item.name }};
{% endfor %}
    return std::nullopt;
}

} // namespace {{ namespace }}

#endif // {{ guard|upper }}
""")

def gen_cpp_enum(csv_path: Path, out_path: Path, enum_name: str, namespace: str):
    with csv_path.open("r", encoding="utf-8-sig") as f:
        items = list(csv.DictReader(f))

    output = CPP_TEMPLATE.render(
        guard=f"{enum_name}_h",
        enum_name=enum_name,
        namespace=namespace,
        items=items,
    )
    out_path.parent.mkdir(parents=True, exist_ok=True)
    out_path.write_text(output, encoding="utf-8")
    print(f"生成: {out_path} ({len(items)} 个枚举值)")

# 用法
gen_cpp_enum(Path("msg_type.csv"), Path("generated/msg_type.hpp"),
             enum_name="MsgType", namespace="protocol")
```

### 3.3 生成 Rust enum + match

```python
RUST_TEMPLATE = Template("""\
// AUTO-GENERATED by gen_enum.py, DO NOT EDIT
use std::fmt;
use std::str::FromStr;

#[derive(Debug, Clone, Copy, PartialEq, Eq)]
#[repr(u16)]
pub enum {{ enum_name }} {
{% for item in items %}
    {{ item.rust_name }} = {{ item.value }},
{% endfor %}
}

impl fmt::Display for {{ enum_name }} {
    fn fmt(&self, f: &mut fmt::Formatter<'_>) -> fmt::Result {
        match self {
{% for item in items %}
            Self::{{ item.rust_name }} => write!(f, "{{ item.name }}"),
{% endfor %}
        }
    }
}

impl FromStr for {{ enum_name }} {
    type Err = String;
    fn from_str(s: &str) -> Result<Self, Self::Err> {
        match s {
{% for item in items %}
            "{{ item.name }}" => Ok(Self::{{ item.rust_name }}),
{% endfor %}
            _ => Err(format!("unknown {{ enum_name }}: {}", s)),
        }
    }
}

impl From<u16> for {{ enum_name }} {
    fn from(v: u16) -> Self {
        match v {
{% for item in items %}
            {{ item.value }} => Self::{{ item.rust_name }},
{% endfor %}
            _ => panic!("invalid {{ enum_name }} value: {}", v),
        }
    }
}
""")

def gen_rust_enum(csv_path: Path, out_path: Path, enum_name: str, prefix: str = "MSG_TYPE_"):
    with csv_path.open("r", encoding="utf-8-sig") as f:
        items = list(csv.DictReader(f))
    for item in items:
        item["rust_name"] = item["name"].removeprefix(prefix)

    output = RUST_TEMPLATE.render(
        enum_name=enum_name,
        prefix=prefix,
        items=items,
    )
    out_path.parent.mkdir(parents=True, exist_ok=True)
    out_path.write_text(output, encoding="utf-8")
    print(f"生成: {out_path} ({len(items)} 个枚举值)")
```

### 4.3 生成 Rust struct + encode/decode

```python
RUST_PROTO_TEMPLATE = Template("""\
// AUTO-GENERATED by gen_protocol.py, DO NOT EDIT
use std::mem::size_of;

#[repr(C, packed)]
#[derive(Debug, Clone, Copy)]
pub struct {{ struct_name }} {
{% for field in fields %}
    pub {{ field.name }}: {{ field.rust_type }},
{% endfor %}
}

impl {{ struct_name }} {
    pub const SIZE: usize = {{ total_size }};

    pub fn encode(&self) -> [u8; Self::SIZE] {
        unsafe { std::ptr::read(self as *const _ as *const [u8; Self::SIZE]) }
    }

    pub fn decode(data: &[u8]) -> Result<Self, &'static str> {
        if data.len() < Self::SIZE {
            return Err("buffer too short");
        }
        unsafe {
            Ok(std::ptr::read(data.as_ptr() as *const Self))
        }
    }
}
""")
```

**注意**：`#[repr(C, packed)]` 在 Rust 中可能导致未对齐访问，实际项目中应逐字段 `read_unaligned` 或使用 `byteorder`/`scroll` 库。此处仅为最小示例。

## 5. 生成注册代码与 switch 分支

消息分发是工业网关的核心：收到报文后根据 `msg_type` 调用对应的处理函数。手写 50 个 case 容易遗漏，用生成器保证完整。

```python
DISPATCH_TEMPLATE = Template("""\
// AUTO-GENERATED by gen_dispatcher.py, DO NOT EDIT
#include "handlers.hpp"
#include "msg_type.hpp"
#include <functional>
#include <unordered_map>

namespace {{ namespace }} {

using Handler = std::function<void(const uint8_t*, size_t)>;

const std::unordered_map<MsgType, Handler>& getHandlers() {
    static const std::unordered_map<MsgType, Handler> handlers = {
{% for item in items %}
        {MsgType::{{ item.name }}, handle{{ item.name | title | replace("_", "") }}},
{% endfor %}
    };
    return handlers;
}

bool dispatch(MsgType type, const uint8_t* data, size_t len) {
    auto& handlers = getHandlers();
    auto it = handlers.find(type);
    if (it == handlers.end()) return false;
    it->second(data, len);
    return true;
}

} // namespace {{ namespace }}
""")
```

生成的代码保证：CSV 中每一个消息类型都有对应的 handler 注册，新增消息类型只需在 CSV 加一行并重跑生成器。

## 6. 正则改代码：能力边界与风险

### 6.1 正则能做什么

- 批量重命名标识符（如 `oldName` → `newName`），但需排除字符串和注释
- 在固定模式的代码块前后插入代码（如每个 `TEST()` 宏后加日志）
- 提取函数签名、类名、include 列表
- 简单的格式化调整（如统一指针符号位置）

### 6.2 正则不能做什么

- 解析嵌套结构（括号、模板、命名空间）——正则不是语法分析器
- 区分上下文（如 `foo` 是变量名还是类型名还是字符串内容）
- 处理宏展开后的代码
- 保证改后代码仍然可编译——正则改代码没有语义理解

### 6.3 安全改代码的流程

```python
import re
from pathlib import Path

def safe_rename_in_source(file_path: Path, old: str, new: str):
    """安全重命名：只改标识符，不改字符串和注释。"""
    text = file_path.read_text(encoding="utf-8")
    lines = text.splitlines(keepends=True)
    result = []
    pattern = re.compile(r'\b' + re.escape(old) + r'\b')

    for line in lines:
        # 简单处理：去掉 // 注释和字符串后再匹配
        # 注意：这只是简化版，实际应处理多行注释、raw string 等
        code_part = line.split("//", 1)[0]  # 去掉行注释
        # 去掉字符串字面量（简化：不处理转义引号）
        code_no_str = re.sub(r'"[^"]*"', '""', code_part)

        if pattern.search(code_no_str):
            # 在整行中替换，但只替换代码部分
            result.append(pattern.sub(new, line))
        else:
            result.append(line)

    file_path.write_text("".join(result), encoding="utf-8")
```

**铁律**：正则改代码后必须编译验证 + git diff 人工审查，绝不能直接提交。

## 7. Python ast 模块：静态检查小工具

`ast` 模块将 Python 源码解析为抽象语法树，可用于做静态检查、代码分析、自动重构。对系统程序员来说，可用来检查项目中 Python 脚本的质量。

```python
import ast
from pathlib import Path

class FunctionLinter(ast.NodeVisitor):
    """检查函数是否过长、参数是否过多。"""

    def __init__(self, max_lines: int = 50, max_args: int = 6):
        self.max_lines = max_lines
        self.max_args = max_args
        self.issues = []

    def visit_FunctionDef(self, node):
        # 函数行数
        func_lines = node.end_lineno - node.lineno + 1
        if func_lines > self.max_lines:
            self.issues.append(
                f"{node.lineno}: 函数 {node.name} 过长 ({func_lines} 行 > {self.max_lines})"
            )

        # 参数数量（含 *args, **kwargs）
        args = node.args
        arg_count = (len(args.posonlyargs) + len(args.args) + len(args.kwonlyargs)
                     + (1 if args.vararg else 0) + (1 if args.kwarg else 0))
        if arg_count > self.max_args:
            self.issues.append(
                f"{node.lineno}: 函数 {node.name} 参数过多 ({arg_count} > {self.max_args})"
            )

        # 检查是否有 TODO 注释（通过 body 中的 Expr 常量）
        self.generic_visit(node)

    visit_AsyncFunctionDef = visit_FunctionDef

def lint_python_file(file_path: Path) -> list:
    tree = ast.parse(file_path.read_text(encoding="utf-8"), filename=str(file_path))
    linter = FunctionLinter()
    linter.visit(tree)
    return linter.issues

# 批量检查项目中所有 Python 脚本
for py_file in Path("scripts").rglob("*.py"):
    issues = lint_python_file(py_file)
    if issues:
        print(f"\n{py_file}:")
        for issue in issues:
            print(f"  {issue}")
```

`ast` 还可以做：提取所有函数签名生成文档、检查未使用的 import、统计代码复杂度、自动插入日志调用。

## 8. 完整实战：配置表→多语言代码生成器

整合以上能力，实现一个完整的代码生成器：从一个 TOML 配置文件定义协议，同时生成 C++ 和 Rust 的枚举、结构体、序列化代码。

输入 `protocol.toml`：

```toml
[meta]
namespace = "device_proto"
cpp_guard = "DEVICE_PROTOCOL_HPP"
rust_mod = "device_proto"

[[messages]]
name = "Heartbeat"
id = 0x0001
fields = [
    { name = "seq",       cpp_type = "uint16_t", rust_type = "u16",    size = 2 },
    { name = "timestamp", cpp_type = "uint32_t", rust_type = "u32",    size = 4 },
    { name = "status",    cpp_type = "uint8_t",  rust_type = "u8",     size = 1 },
]

[[messages]]
name = "DataReport"
id = 0x0010
fields = [
    { name = "seq",       cpp_type = "uint16_t", rust_type = "u16",    size = 2 },
    { name = "sensor_id", cpp_type = "uint16_t", rust_type = "u16",    size = 2 },
    { name = "value",     cpp_type = "float",    rust_type = "f32",    size = 4 },
    { name = "payload",   cpp_type = "uint8_t[32]", rust_type = "[u8; 32]", size = 32 },

```

生成器 `gen_protocol.py`：

```python
#!/usr/bin/env python3
"""配置表→多语言代码生成器。

用法: python gen_protocol.py protocol.toml --cpp-out generated/ --rust-out generated/
"""
import argparse
import tomllib
from pathlib import Path
from jinja2 import Template

CPP_HEADER = Template("""\
// AUTO-GENERATED by gen_protocol.py, DO NOT EDIT
#ifndef {{ meta.cpp_guard|upper }}
#define {{ meta.cpp_guard|upper }}

#include <cstdint>
#include <cstring>
#include <vector>
#include <stdexcept>

namespace {{ meta.namespace }} {

enum class MsgId : uint16_t {
{% for msg in messages %}
    {{ msg.name | upper }} = {{ "0x%04X" | format(msg.id) }},
{% endfor %}
};

{% for msg in messages %}
struct {{ msg.name }} {
    static constexpr MsgId ID = MsgId::{{ msg.name | upper }};
    static constexpr size_t SIZE = {{ msg.fields | sum(attribute="size") }};

{% for field in msg.fields %}
    {{ field.cpp_type }} {{ field.name }};
{% endfor %}

    std::vector<uint8_t> pack() const {
        std::vector<uint8_t> buf(SIZE);
        size_t off = 0;
{% for field in msg.fields %}
        std::memcpy(buf.data() + off, &{{ field.name }}, {{ field.size }}); off += {{ field.size }};
{% endfor %}
        return buf;
    }

    static {{ msg.name }} unpack(const uint8_t* data, size_t len) {
        if (len < SIZE) throw std::runtime_error("{{ msg.name }}: buffer too short");
        {{ msg.name }} s{};
        size_t off = 0;
{% for field in msg.fields %}
        std::memcpy(&s.{{ field.name }}, data + off, {{ field.size }}); off += {{ field.size }};
{% endfor %}
        return s;
    }
};

{% endfor %}
} // namespace {{ meta.namespace }}

#endif // {{ meta.cpp_guard|upper }}
""")

RUST_MOD = Template("""\
// AUTO-GENERATED by gen_protocol.py, DO NOT EDIT
#![allow(dead_code)]

#[repr(u16)]
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum MsgId {
{% for msg in messages %}
    {{ msg.name | upper }} = {{ msg.id }},
{% endfor %}
}

{% for msg in messages %}
#[repr(C, packed)]
#[derive(Debug, Clone, Copy)]
pub struct {{ msg.name }} {
{% for field in msg.fields %}
    pub {{ field.name }}: {{ field.rust_type }},
{% endfor %}
}

impl {{ msg.name }} {
    pub const ID: MsgId = MsgId::{{ msg.name | upper }};
    pub const SIZE: usize = {{ msg.fields | sum(attribute="size") }};

    pub fn encode(&self) -> Vec<u8> {
        let mut buf = Vec::with_capacity(Self::SIZE);
        unsafe {
            let ptr = self as *const Self as *const u8;
            buf.extend_from_slice(std::slice::from_raw_parts(ptr, Self::SIZE));
        }
        buf
    }

    pub fn decode(data: &[u8]) -> Result<Self, &'static str> {
        if data.len() < Self::SIZE {
            return Err("{{ msg.name }}: buffer too short");
        }
        unsafe {
            Ok(std::ptr::read_unaligned(data.as_ptr() as *const Self))
        }
    }
}

{% endfor %}
""")

def generate(config_path: Path, cpp_out: Path, rust_out: Path):
    with config_path.open("rb") as f:
        config = tomllib.load(f)

    meta = config["meta"]
    messages = config["messages"]

    # 生成 C++
    cpp_code = CPP_HEADER.render(meta=meta, messages=messages)
    cpp_path = cpp_out / f"{meta['namespace']}.hpp"
    cpp_path.parent.mkdir(parents=True, exist_ok=True)
    cpp_path.write_text(cpp_code, encoding="utf-8")
    print(f"[C++] {cpp_path} ({len(messages)} messages)")

    # 生成 Rust
    rust_code = RUST_MOD.render(meta=meta, messages=messages)
    rust_path = rust_out / f"{meta['rust_mod']}.rs"
    rust_path.parent.mkdir(parents=True, exist_ok=True)
    rust_path.write_text(rust_code, encoding="utf-8")
    print(f"[Rust] {rust_path} ({len(messages)} messages)")

def main():
    parser = argparse.ArgumentParser(description="配置表→多语言代码生成器")
    parser.add_argument("config", type=Path, help="TOML 配置文件")
    parser.add_argument("--cpp-out", type=Path, default=Path("generated"))
    parser.add_argument("--rust-out", type=Path, default=Path("generated"))
    args = parser.parse_args()
    generate(args.config, args.cpp_out, args.rust_out)

if __name__ == "__main__":
    main()
```

这个生成器的特点：

- **单一数据源**：TOML 配置定义所有协议，C++ 和 Rust 从同一份定义生成
- **偏移量自动计算**：`pack()`/`unpack()` 中用 `off += size` 自动维护偏移，不会算错
- **大小自动求和**：`SIZE` 常量由字段大小求和得出
- **可扩展**：新增消息类型只需在 TOML 加一个 `[[messages]]` 块，重跑生成器即可

## 9. 快速参考卡片

| 需求 | 做法 |
| --- | --- |
| 模板生成 | `string.Template`（`$name`）或 f-string；大模板用 `jinja2` |

| IDL/表驱动生成 | 读 CSV/JSON → 渲染结构体 + 序列化代码；生成物加"自动生成请勿手改"头 |
| 批量处理保留原文件 | 写 `*.bak` 或输出到新目录；`fileinput` 原地替换（`inplace=True`） |
| 编码/换行统一 | `newline="\n"` 写入，`encoding="utf-8"`；BOM 用 `utf-8-sig` |
| 幂等与可重入 | 生成前清目标目录或用标记块（`// BEGIN GENERATED`）替换 |
| 校验生成结果 | 生成后跑一次编译器/解析器做语法校验 |
| 与 C++ 对照 | 这类"配置 → 代码"工作 C++ 侧用宏/模板做会极难维护，Python 生成是行业惯例 |

## 10. 常见坑与避坑指南

| 坑 | 现象 | 解决方案 |
|---|---|---|
| 生成代码无幂等性 | 每次生成 diff 不同（如随机顺序） | 对输入排序，固定输出顺序 |
| 字节序未处理 | 跨平台通信数据错乱 | 生成代码中显式 `htons`/`ntohs` 或用 `byteorder` 库 |
| 结构体对齐问题 | C++ 和 Rust 结构体布局不一致 | C++ 用 `#pragma pack(push, 1)`，Rust 用 `#[repr(C, packed)]`，或逐字段序列化 |
| 生成文件被手动编辑 | 手动修改后被生成器覆盖 | 文件头标注 `DO NOT EDIT`，CI 中检查生成文件是否最新 |
| Jinja2 模板缩进混乱 | 生成代码缩进不对 | 模板中用 `{%- %}` 控制空白，或生成后用 `clang-format`/`rustfmt` 格式化 |
| CSV 编码问题 | 中文描述乱码 | 读取时用 `utf-8-sig`（Excel 导出的 CSV 带 BOM） |
| 枚举值重复 | 生成的 enum 编译报错 | 生成器中校验 value 唯一性 |
| 正则改代码破坏语法 | 改后编译失败 | 改后必须编译验证 + git diff，复杂重构用 AST 而非正则 |

## 11. 本节小结

- 代码生成的核心是"单一数据源 + 模板渲染"，CSV/TOML/JSON 定义 → Jinja2 模板 → C++/Rust 代码
- 枚举生成要同时产出 `enum` 定义、`toString()`/`fromString()` 双向映射，保证调试和配置解析可用
- 协议结构体生成要自动计算偏移量和总大小，避免手写算错
- 注册代码和 switch 分支生成保证完整性，新增类型只需改配置表
- 正则改代码能力有限，只能做简单模式替换，复杂重构用 AST；改后必须编译验证
- Python `ast` 模块可做静态检查、代码分析、自动重构，是检查项目中 Python 脚本质量的利器
- 完整生成器展示了从 TOML 配置同时生成 C++ 和 Rust 代码的端到端流程
