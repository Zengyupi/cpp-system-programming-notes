## 1. 工程场景：为什么用 Python 编排命令

写 C++/Rust 的日常工作中，需要频繁调用命令行工具：`cmake` 配置构建、`make`/`ninja` 编译、`cargo build` 构建 Rust 项目、`gdb` 调试、`git` 版本控制、`objdump`/`readelf` 分析二进制。shell 脚本可以串联这些命令，但一旦需要条件判断、错误分类、并行执行、结果汇总，shell 就变得难以维护。

Python 的 `subprocess` 模块提供了跨平台的进程控制能力，配合 `concurrent.futures` 可以实现批量并行。典型场景：

- **编译矩阵**：用 gcc/clang + debug/release + O0/O2 组合批量编译，收集所有错误
- **批量测试**：并行跑 100 个测试用例，收集通过/失败/超时
- **gdb 批处理**：对 50 个 core 文件批量跑 `bt`，提取调用栈并聚类
- **git 批量操作**：遍历 20 个子模块，批量 checkout、pull、统计提交

## 2. subprocess.run：最常用的接口

`subprocess.run()` 是 Python 3.5+ 推荐的高级接口，适用于"运行一个命令并等待完成"的场景。

### 2.1 基本用法与返回码

```python
import subprocess

# 最简单：命令用列表传递（推荐，避免 shell 注入）
result = subprocess.run(["g++", "--version"])
print(result.returncode)  # 0

# check=True：返回码非 0 时抛出 CalledProcessError
try:
    subprocess.run(["g++", "-c", "main.cpp", "-o", "main.o"], check=True)
except subprocess.CalledProcessError as e:
    print(f"编译失败，返回码: {e.returncode}")

# 不抛异常，手动检查返回码
result = subprocess.run(["git", "diff", "--name-only"])
if result.returncode != 0:
    print("git diff 失败")
```

### 2.2 捕获输出与编码

```python
# capture_output=True：捕获 stdout 和 stderr
result = subprocess.run(
    ["g++", "-c", "main.cpp"],
    capture_output=True,
    text=True,  # 等价于 universal_newlines=True，输出为 str 而非 bytes
)
print(result.stdout)
print(result.stderr)

# 分别重定向：stdout 到管道，stderr 合并到 stdout
result = subprocess.run(
    ["make", "-j4"],
    stdout=subprocess.PIPE,
    stderr=subprocess.STDOUT,
    text=True,
    encoding="utf-8",
    errors="replace",  # 遇到无法解码的字节时替换为 �
)

# 输出重定向到文件
with open("build.log", "w", encoding="utf-8") as f:
    subprocess.run(["make", "-j4"], stdout=f, stderr=subprocess.STDOUT)
```

### 2.3 超时、cwd 与环境变量

```python
import os

# timeout：超时后杀进程并抛 TimeoutExpired
try:
    result = subprocess.run(
        ["./myapp", "--stress"],
        capture_output=True, text=True,
        timeout=30,  # 30 秒
    )
except subprocess.TimeoutExpired:
    print("程序运行超时（>30秒），已终止")

# cwd：在指定目录下运行命令
subprocess.run(["cmake", "..", "-G", "Ninja"], cwd="build")

# env：传递环境变量（注意：默认继承当前进程环境，这里是完全替换）
my_env = os.environ.copy()
my_env["CC"] = "clang"
my_env["CXX"] = "clang++"
my_env["CFLAGS"] = "-O2 -Wall"
subprocess.run(["make", "-j4"], env=my_env)

# 只添加/修改环境变量（更安全的写法）
env = {**os.environ, "BUILD_TYPE": "release", "VERBOSE": "1"}
subprocess.run(["./build.sh"], env=env)
```

## 3. Popen：高级进程控制

`subprocess.Popen` 是底层接口，适用于需要实时交互、管道串联、非阻塞等待的场景。

### 3.1 实时读取输出

`run()` 要等进程结束才能拿到输出，`Popen` 可以边运行边读。

```python
import subprocess

def run_with_live_output(cmd: list, log_prefix: str = ""):
    """实时打印命令输出，并返回完整输出。"""
    proc = subprocess.Popen(
        cmd,
        stdout=subprocess.PIPE,
        stderr=subprocess.STDOUT,
        text=True,
        encoding="utf-8",
        errors="replace",
        bufsize=1,  # 行缓冲
    )

    full_output = []
    assert proc.stdout is not None
    for line in proc.stdout:
        print(f"{log_prefix}{line}", end="")
        full_output.append(line)

    proc.wait()
    return proc.returncode, "".join(full_output)

# 用法：编译时实时显示进度
code, output = run_with_live_output(["make", "-j4"], log_prefix="[build] ")
```

**注意**：如果同时需要 stdout 和 stderr 且不合并，必须用线程分别读取，否则可能死锁（管道缓冲区满导致进程阻塞）。

```python
import threading

def run_capture_both(cmd: list):
    """同时捕获 stdout 和 stderr，避免死锁。"""
    proc = subprocess.Popen(
        cmd,
        stdout=subprocess.PIPE,
        stderr=subprocess.PIPE,
        text=True,
    )

    stdout_lines = []
    stderr_lines = []

    def read_stdout():
        assert proc.stdout is not None
        for line in proc.stdout:
            stdout_lines.append(line)

    def read_stderr():
        assert proc.stderr is not None
        for line in proc.stderr:
            stderr_lines.append(line)

    t1 = threading.Thread(target=read_stdout)
    t2 = threading.Thread(target=read_stderr)
    t1.start()
    t2.start()
    t1.join()
    t2.join()
    proc.wait()

    return proc.returncode, "".join(stdout_lines), "".join(stderr_lines)
```

### 3.2 管道串联多个命令

用 `Popen` 实现 shell 管道 `cmd1 | cmd2 | cmd3`。

```python
# 等价于: git log --oneline | grep "fix" | wc -l
p1 = subprocess.Popen(["git", "log", "--oneline"], stdout=subprocess.PIPE, text=True)
p2 = subprocess.Popen(["grep", "fix"], stdin=p1.stdout, stdout=subprocess.PIPE, text=True)
p3 = subprocess.Popen(["wc", "-l"], stdin=p2.stdout, stdout=subprocess.PIPE, text=True)

# 允许 p1 收到 SIGPIPE 如果 p2 提前退出
p1.stdout.close()  # type: ignore
p2.stdout.close()  # type: ignore

output = p3.communicate()[0]
print(f"fix 相关提交数: {output.strip()}")
```

**更简单的替代**：大多数情况下，管道的后段可以用 Python 代码实现，不需要真的起子进程。

```python
# 用 Python 替代 grep | wc -l
result = subprocess.run(["git", "log", "--oneline"], capture_output=True, text=True)
fix_count = sum(1 for line in result.stdout.splitlines() if "fix" in line.lower())
print(f"fix 相关提交数: {fix_count}")
```

### 3.3 进程等待与终止

```python
import time
import signal

proc = subprocess.Popen(["./long_running_app"])

# 非阻塞检查是否结束
if proc.poll() is not None:
    print(f"已结束，返回码: {proc.returncode}")

# 等待指定时间
try:
    proc.wait(timeout=10)
except subprocess.TimeoutExpired:
    # 超时后优雅终止
    proc.terminate()  # 发 SIGTERM
    try:
        proc.wait(timeout=5)
    except subprocess.TimeoutExpired:
        proc.kill()  # 发 SIGKILL，强制杀
        proc.wait()

# Windows 下 terminate() 和 kill() 都调用 TerminateProcess
# POSIX 下可以发任意信号
proc.send_signal(signal.SIGINT)  # 等价于 Ctrl+C
```

## 4. shell=False 安全红线

`shell=True` 会通过 shell 解释命令字符串，存在命令注入风险。**系统程序员的铁律：永远用列表传参，永远设 `shell=False`（默认值）。**

```python
# 危险：shell=True + 字符串拼接，用户输入可注入
filename = "main.cpp; rm -rf /"  # 恶意输入
subprocess.run(f"g++ -c {filename}", shell=True)  # 会执行 rm -rf /

# 安全：列表传参，shell=False（默认）
filename = "main.cpp; rm -rf /"
subprocess.run(["g++", "-c", filename])  # 把整个字符串当作一个文件名，不会注入

# 如果必须用 shell 特性（如通配符、重定向），用 Python 替代
# 不要: subprocess.run("ls *.cpp", shell=True)
import glob
for f in glob.glob("*.cpp"):
    print(f)

# 不要: subprocess.run("cmd > out.txt 2>&1", shell=True)
with open("out.txt", "w") as f:
    subprocess.run(["cmd"], stdout=f, stderr=subprocess.STDOUT)
```

唯一可接受 `shell=True` 的场景：命令完全由程序内部构造、不含任何用户输入，且必须使用 shell 内建命令（如 `source`）。即便如此，也应优先考虑用 `bash -c` + 列表的方式。

## 5. 串联编译工具链

### 5.1 驱动 cmake 构建

```python
from pathlib import Path
import subprocess

def cmake_build(source_dir: Path, build_dir: Path, build_type: str = "Release",
                generator: str = "Ninja", jobs: int = 4) -> tuple[int, str]:
    """配置并构建 CMake 项目。"""
    build_dir.mkdir(parents=True, exist_ok=True)

    # 配置阶段
    configure_cmd = [
        "cmake",
        "-S", str(source_dir),
        "-B", str(build_dir),
        "-G", generator,
        f"-DCMAKE_BUILD_TYPE={build_type}",
    ]
    result = subprocess.run(configure_cmd, capture_output=True, text=True)
    if result.returncode != 0:
        return result.returncode, f"配置失败:\n{result.stderr}"

    # 构建阶段
    build_cmd = ["cmake", "--build", str(build_dir), "--parallel", str(jobs)]
    result = subprocess.run(build_cmd, capture_output=True, text=True)
    if result.returncode != 0:
        return result.returncode, f"构建失败:\n{result.stdout}\n{result.stderr}"

    return 0, "构建成功"
```

### 5.2 驱动 cargo 构建与测试

```python
def cargo_build(project_dir: Path, release: bool = False, target: str | None = None) -> tuple[int, str]:
    """构建 Rust 项目。"""
    cmd = ["cargo", "build"]
    if release:
        cmd.append("--release")
    if target:
        cmd.extend(["--target", target])

    result = subprocess.run(cmd, cwd=project_dir, capture_output=True, text=True)
    return result.returncode, result.stdout + result.stderr

def cargo_test(project_dir: Path, test_threads: int = 4) -> dict:
    """运行 Rust 测试并解析结果。"""
    cmd = ["cargo", "test", "--", "--test-threads", str(test_threads)]
    result = subprocess.run(cmd, cwd=project_dir, capture_output=True, text=True)

    # 解析测试结果
    passed = 0
    failed = 0
    failed_tests = []
    for line in result.stdout.splitlines():
        if "test result:" in line:
            # test result: ok. 42 passed; 0 failed; 0 ignored
            parts = line.split()
            passed += int(parts[3])
            failed += int(parts[5])
        elif line.startswith("test ") and "FAILED" in line:
            failed_tests.append(line.split()[1])

    return {
        "returncode": result.returncode,
        "passed": passed,
        "failed": failed,
        "failed_tests": failed_tests,
        "output": result.stdout + result.stderr,
    }
```

### 5.3 调用 gdb 批处理

```python
def gdb_batch(program: Path, core_file: Path | None = None,
              commands: list[str] | None = None) -> str:
    """用 gdb 批处理模式运行命令，返回输出。"""
    gdb_cmds = commands or ["bt full", "info registers", "quit"]
    cmd = ["gdb", "-batch", "-nx", str(program)]
    if core_file:
        cmd.extend([str(core_file)])
    for c in gdb_cmds:
        cmd.extend(["-ex", c])

    result = subprocess.run(cmd, capture_output=True, text=True, timeout=30)
    return result.stdout + result.stderr
```

## 6. 解析命令输出

很多命令输出是半结构化文本，需要用正则或字符串方法提取关键信息。

```python
import re

def parse_gcc_errors(output: str) -> list[dict]:
    """解析 gcc/clang 编译错误输出。"""
    pattern = re.compile(
        r'(?P<file>[\w./-]+):(?P<line>\d+):(?P<col>\d+):\s+'
        r'(?P<level>error|warning):\s+(?P<msg>.*)'
    )
    errors = []
    for line in output.splitlines():
        m = pattern.search(line)
        if m:
            errors.append(m.groupdict())
    return errors

def parse_git_log(output: str) -> list[dict]:
    """解析 git log --pretty=format 输出。"""
    commits = []
    for line in output.splitlines():
        parts = line.split("|", 3)
        if len(parts) == 4:
            commits.append({
                "hash": parts[0],
                "author": parts[1],
                "date": parts[2],
                "subject": parts[3],
            })
    return commits

# 用法：git log 用固定格式输出，便于解析
result = subprocess.run(
    ["git", "log", "--pretty=format:%H|%an|%ad|%s", "--date=short", "-n", "20"],
    capture_output=True, text=True,
)
commits = parse_git_log(result.stdout)
```

**经验**：调用命令时，优先选择机器可读的输出格式（`--format`、`--json`、`-x`），而不是解析人类可读的默认输出。例如 `git log --format` 比解析默认 `git log` 容易得多。

## 7. concurrent.futures：批量并行执行

`concurrent.futures` 提供了 `ThreadPoolExecutor` 和 `ProcessPoolExecutor`，是 Python 并行编程的高层接口。

### 7.1 线程池：IO 密集型任务

适用于：批量跑子进程（等待子进程是 IO 等待）、批量网络请求、批量文件读写。

```python
from concurrent.futures import ThreadPoolExecutor, as_completed
import subprocess

def compile_file(src: str) -> dict:
    """编译单个源文件。"""
    result = subprocess.run(
        ["g++", "-c", src, "-o", src.replace(".cpp", ".o"), "-O2", "-Wall"],
        capture_output=True, text=True,
    )
    return {"src": src, "returncode": result.returncode, "stderr": result.stderr}

sources = [f"src/module{i}.cpp" for i in range(20)]

# 线程池并行编译（子进程编译是 IO 等待，线程池合适）
with ThreadPoolExecutor(max_workers=8) as executor:
    futures = {executor.submit(compile_file, src): src for src in sources}

    results = []
    for future in as_completed(futures):
        src = futures[future]
        try:
            result = future.result()
            results.append(result)
            status = "OK" if result["returncode"] == 0 else "FAIL"
            print(f"[{status}] {src}")
        except Exception as e:
            print(f"[EXCEPTION] {src}: {e}")

failed = [r for r in results if r["returncode"] != 0]
print(f"\n完成: {len(results) - len(failed)}/{len(results)} 成功, {len(failed)} 失败")
```

### 7.2 进程池：CPU 密集型任务

适用于：批量数据处理、压缩/解压、密码学运算、大量正则匹配。进程池绕过 GIL，真正并行使用多核。

```python
from concurrent.futures import ProcessPoolExecutor
import gzip
from pathlib import Path

def compress_file(filepath: str) -> dict:
    """压缩单个文件（CPU 密集型）。"""
    src = Path(filepath)
    dst = src.with_suffix(src.suffix + ".gz")
    with open(src, "rb") as f_in, gzip.open(dst, "wb", compresslevel=6) as f_out:
        f_out.write(f_in.read())
    return {"src": filepath, "dst": str(dst), "size": dst.stat().st_size}

files = [str(p) for p in Path("logs").glob("*.log")]

# 进程池并行压缩
with ProcessPoolExecutor(max_workers=4) as executor:
    for result in executor.map(compress_file, files):
        print(f"压缩完成: {result['src']} -> {result['size']} bytes")
```

**进程池注意事项**：
- 传入函数和参数必须可 pickle（序列化）
- 每个进程有独立内存空间，无法共享变量（用 `multiprocessing.Manager` 或返回值传递）
- 进程启动开销大，任务粒度不能太细
- Windows 下必须用 `if __name__ == "__main__":` 保护

### 7.3 GIL 对 IO/CPU 任务的影响

GIL（Global Interpreter Lock）是 CPython 的全局解释器锁，保证同一时刻只有一个线程执行 Python 字节码。

| 任务类型 | GIL 影响 | 推荐方案 |
|---|---|---|
| IO 密集（等待子进程、网络、文件） | 等待时释放 GIL，多线程有效 | `ThreadPoolExecutor` |
| CPU 密集（纯 Python 计算） | GIL 导致多线程无法并行 | `ProcessPoolExecutor` |
| C 扩展计算（numpy、regex） | C 扩展可释放 GIL，多线程可能有效 | 视具体库而定 |
| 调用子进程（subprocess） | 子进程独立于 GIL，多线程有效 | `ThreadPoolExecutor` |

**关键结论**：用 Python 编排 C++/Rust 编译和测试时，主要工作在子进程中完成，Python 主线程只是等待，因此**线程池是最合适的并行方案**，不需要进程池。只有当 Python 自身在做大量 CPU 计算（如正则匹配 GB 级文本）时，才需要进程池。

## 8. 完整实战：批量编译矩阵脚本

整合以上能力，实现一个编译矩阵脚本：用多编译器 × 多构建类型 × 多优化级别组合批量编译，收集结果并生成报告。

```python
#!/usr/bin/env python3
"""批量编译矩阵脚本。

用法: python build_matrix.py <source_dir>
"""
import argparse
import json
import subprocess
import sys
from concurrent.futures import ThreadPoolExecutor, as_completed
from dataclasses import dataclass, asdict
from pathlib import Path
from datetime import datetime

@dataclass
class BuildConfig:
    compiler: str       # gcc, clang
    build_type: str     # Debug, Release, RelWithDebInfo
    opt_level: str      # O0, O1, O2, O3
    standard: str       # 17, 20, 23

    @property
    def name(self) -> str:
        return f"{self.compiler}-{self.build_type}-{self.opt_level}-c++{self.standard}"

    @property
    def build_dir(self) -> str:
        return f"build_matrix/{self.name}"

def run_build(source_dir: Path, config: BuildConfig) -> dict:
    """执行单次构建，返回结果。"""
    build_dir = Path(config.build_dir)
    build_dir.mkdir(parents=True, exist_ok=True)

    cxx = {"gcc": "g++", "clang": "clang++"}[config.compiler]
    cflags = f"-{config.opt_level} -Wall -Wextra -std=c++{config.standard}"

    # 配置
    configure_cmd = [
        "cmake",
        "-S", str(source_dir),
        "-B", str(build_dir),
        "-G", "Ninja",
        f"-DCMAKE_CXX_COMPILER={cxx}",
        f"-DCMAKE_BUILD_TYPE={config.build_type}",
        f"-DCMAKE_CXX_FLAGS={cflags}",
    ]
    result = subprocess.run(configure_cmd, capture_output=True, text=True, timeout=120)
    if result.returncode != 0:
        return {
            "config": asdict(config),
            "stage": "configure",
            "success": False,
            "output": result.stdout + result.stderr,
        }

    # 构建
    build_cmd = ["cmake", "--build", str(build_dir), "--parallel", "4"]
    result = subprocess.run(build_cmd, capture_output=True, text=True, timeout=300)

    return {
        "config": asdict(config),
        "stage": "build",
        "success": result.returncode == 0,
        "output": result.stdout + result.stderr,
    }

def generate_matrix() -> list[BuildConfig]:
    """生成编译矩阵。"""
    compilers = ["gcc", "clang"]
    build_types = ["Debug", "Release"]
    opt_levels = ["O0", "O2"]
    standards = ["17", "20"]

    configs = []
    for cc in compilers:
        for bt in build_types:
            for opt in opt_levels:
                for std in standards:
                    configs.append(BuildConfig(cc, bt, opt, std))
    return configs

def main():
    parser = argparse.ArgumentParser(description="批量编译矩阵")
    parser.add_argument("source_dir", type=Path)
    parser.add_argument("--workers", type=int, default=4)
    args = parser.parse_args()

    configs = generate_matrix()
    print(f"编译矩阵: {len(configs)} 个配置, {args.workers} 并发")

    results = []
    with ThreadPoolExecutor(max_workers=args.workers) as executor:
        futures = {executor.submit(run_build, args.source_dir, cfg): cfg for cfg in configs}
        for future in as_completed(futures):
            cfg = futures[future]
            try:
                result = future.result()
                results.append(result)
                status = "PASS" if result["success"] else "FAIL"
                print(f"[{status}] {cfg.name} ({result['stage']})")
            except Exception as e:
                print(f"[EXCEPTION] {cfg.name}: {e}")
                results.append({"config": asdict(cfg), "success": False, "error": str(e)})

    # 汇总
    passed = sum(1 for r in results if r.get("success"))
    failed = len(results) - passed
    print(f"\n{'='*60}")
    print(f"总计: {len(results)} 个配置, {passed} 通过, {failed} 失败")

    # 保存报告
    report = {
        "timestamp": datetime.now().isoformat(),
        "total": len(results),
        "passed": passed,
        "failed": failed,
        "results": results,
    }
    report_path = Path("build_matrix/report.json")
    report_path.parent.mkdir(parents=True, exist_ok=True)
    report_path.write_text(json.dumps(report, indent=2, ensure_ascii=False), encoding="utf-8")
    print(f"报告已保存: {report_path}")

    sys.exit(0 if failed == 0 else 1)

if __name__ == "__main__":
    main()
```

## 9. 常见坑与避坑指南

| 坑 | 现象 | 解决方案 |
|---|---|---|
| `shell=True` 注入 | 用户输入被当作命令执行 | 永远用列表传参，`shell=False` |
| 管道死锁 | 进程卡住不动 | 同时读 stdout/stderr 用线程，或合并为 `STDOUT` |
| 子进程不退出 | `wait()` 永远不返回 | 设 `timeout`，超时后 `terminate()` + `kill()` |
| Windows 编码问题 | 子进程输出乱码 | 设 `encoding="utf-8", errors="replace"`，或 `text=True` |
| 环境变量被替换 | `env=` 后命令找不到 | `env = os.environ.copy()` 后再修改，不要直接传新 dict |
| 进程池 Windows 报错 | `RuntimeError: An attempt has been made to start a new process` | 用 `if __name__ == "__main__":` 保护 |
| 线程池 CPU 任务慢 | 多线程反而比单线程慢 | CPU 密集型用进程池，IO 密集型用线程池 |
| `cwd` 相对路径 | 命令找不到文件 | `cwd` 用绝对路径，或命令中文件用绝对路径 |
| 超时杀不掉进程 | `terminate()` 后进程还在 | 先 `terminate()`，等几秒，再 `kill()`，最后 `wait()` |
| 大输出内存爆炸 | `capture_output=True` OOM | 用 `Popen` 流式读取，或重定向到文件 |

## 10. 本节小结

- `subprocess.run()` 是"运行并等待"的首选，支持 `capture_output`、`timeout`、`cwd`、`env`
- `subprocess.Popen` 用于实时输出、管道串联、非阻塞等待，注意避免管道死锁
- `shell=False` + 列表传参是安全红线，永远不要用字符串拼接命令
- 编译工具链（cmake/cargo/gdb/git）都可以用 Python 编排，优先选择机器可读的输出格式
- `ThreadPoolExecutor` 适用于 IO 密集型（等待子进程），`ProcessPoolExecutor` 适用于 CPU 密集型
- GIL 不影响子进程等待，因此编排编译/测试用线程池即可；只有 Python 自身做 CPU 计算时才需要进程池
- 编译矩阵脚本展示了多配置并行编译、结果收集、报告生成的端到端流程
