## 1. 工程场景：为什么用 Python 解析二进制

C++ 程序员日常接触大量二进制文件：固件镜像、core dump、内存快照、自定义协议报文、日志的二进制归档、编译产物。用 C++ 写解析器要处理编译、结构体对齐、跨平台，改一个字段就要重新编译。Python 的 `struct` 和 `ctypes` 可以在脚本里精确描述字节布局，几十行就能把一个二进制文件拆成可读字段。

典型场景：

- 设备固件升级失败，需要解析固件头确认版本号、魔数、CRC 是否正确。
- 线上抓了一段自定义协议报文，需要逐字段解析后重放。
- core dump 文件太大，先用 Python 提取 ELF 头和程序头，判断是哪个架构、哪个段。
- 二进制日志归档需要批量解析、过滤、转成文本。
- 验证 C++ 端序列化的字节布局是否与协议文档一致（对齐、大小端、位域）。

## 2. struct：格式化字节串

`struct` 是 Python 标准库，在 `bytes` 和 C 类型之间做转换。核心是**格式字符串**，每个字符对应一个 C 类型。

### 2.1 格式字符与大小端

| 格式字符 | C 类型 | Python 类型 | 标准大小 |
|---|---|---|---|
| `b` / `B` | signed/unsigned char | int | 1 字节 |
| `h` / `H` | signed/unsigned short | int | 2 字节 |
| `i` / `I` | signed/unsigned int | int | 4 字节 |
| `q` / `Q` | signed/unsigned long long | int | 8 字节 |
| `f` / `d` | float / double | float | 4/8 字节 |
| `s` | char[] | bytes | 定长 |
| `x` | 填充字节 | — | 1 字节 |

大小端由格式字符串的第一个字符控制：

- `>` 或 `!`：大端（网络字节序，`!` 等同于 `>`）
- `<`：小端
- `=`：本机原生字节序，标准大小
- `@`（默认）：本机原生字节序，原生对齐

```python
"""struct_basic.py — struct 打包解包基础"""
import struct

# 大端打包：2 字节无符号短整数 + 4 字节无符号整数 + 8 字节数据
packed = struct.pack(">HI8s", 0x1234, 0xDEADBEEF, b"abcdefgh")
print(packed.hex())  # 1234 deadbeef 6162636465666768

# 解包
a, b, c = struct.unpack(">HI8s", packed)
print(f"a=0x{a:04x}, b=0x{b:08x}, c={c}")

# 用 Struct 对象预编译，重复解析更高效
fmt = struct.Struct(">HI8s")
print(fmt.size)  # 2 + 4 + 8 = 14
a, b, c = fmt.unpack(packed)
```

从字节流中按偏移解析：

```python
"""struct_offset.py — 从大文件指定偏移解析"""
import struct

with open("firmware.bin", "rb") as f:
    # 读前 64 字节头
    header = f.read(64)

# 假设头布局：魔数(4) + 版本(2,大端) + 入口地址(4) + 保留(2) + 大小(4)
magic, version, entry, size = struct.unpack_from(">4sHI2xI", header, 0)
print(f"magic={magic}, version={version}, entry=0x{entry:08x}, size={size}")
```

`unpack_from(buffer, offset)` 从指定偏移开始解包，不需要切片。`2x` 表示跳过 2 字节填充。

### 2.2 对齐与填充

C 结构体有自然对齐，`struct` 默认（`@`）也会按本机规则插入填充。用 `<`、`>`、`!`、`=` 时**不插入填充**，按标准大小紧密排列。这对解析网络协议和文件格式至关重要——协议文档里的布局通常是紧密排列的。

```python
"""struct_align.py — 对齐对比"""
import struct

# C 结构体：struct { char a; int b; short c; };
# 原生对齐（@）：a(1) + 填充(3) + b(4) + c(2) + 填充(2) = 12
print(struct.calcsize("@bih"))   # 12（本机 64 位 Linux/Windows）

# 紧密排列（<）：a(1) + b(4) + c(2) = 7
print(struct.calcsize("<bih"))   # 7

# 如果协议文档要求按 4 字节对齐，手动加填充
print(struct.calcsize("<b3xih2x"))  # 1+3+4+2+2 = 12
```

验证 C++ 端序列化是否正确时，用 `@` 打包后与 C++ `memcpy` 的结果对比，可以发现对齐差异。

### 2.3 位域的处理

`struct` 不直接支持位域（C 的 `unsigned int flag:1`），需要手动移位和掩码：

```python
"""bitfield.py — 位域手动解析"""
import struct

# 假设 2 字节状态寄存器：
# bit 15:   power_on
# bit 14:   error
# bit 13-8: reserved
# bit 7-0:  temperature (uint8)
raw = struct.pack(">H", 0b10100000_00101000)  # power_on=1, error=0, temp=40
value = struct.unpack(">H", raw)[0]

power_on = (value >> 15) & 0x1
error    = (value >> 14) & 0x1
temp     = value & 0xFF

print(f"power_on={power_on}, error={error}, temp={temp}")
# 反向打包
value2 = (power_on << 15) | (error << 14) | (temp & 0xFF)
print(f"0x{value2:04x}")
```

如果位域较多，可以写一个辅助类或用 `ctypes` 的位域（见下节）。

## 3. ctypes：结构体与联合的字节级映射

`ctypes` 可以定义与 C 完全一致的结构体、联合、位域，并且支持原生对齐。当需要精确复刻 C 内存布局（包括位域和联合）时，`ctypes` 比 `struct` 更直观。

```python
"""ctypes_struct.py — ctypes 定义 C 结构体/联合/位域"""
import ctypes

class StatusReg(ctypes.BigEndianStructure):
    _pack_ = 1  # 1 字节对齐，等价于 #pragma pack(1)
    _fields_ = [
        ("power_on", ctypes.c_uint8, 1),   # 1 位
        ("error",    ctypes.c_uint8, 1),   # 1 位
        ("reserved", ctypes.c_uint8, 6),   # 6 位
        ("temp",     ctypes.c_uint8),       # 8 位
    ]

class FirmwareHeader(ctypes.BigEndianStructure):
    _pack_ = 1
    _fields_ = [
        ("magic",    ctypes.c_uint8 * 4),
        ("version",  ctypes.c_uint16),
        ("entry",    ctypes.c_uint32),
        ("status",   StatusReg),
        ("size",     ctypes.c_uint32),
    ]

# 从字节创建
data = b"\xAA\x55\x5A\xA5" + b"\x00\x02" + b"\x08\x04\x00\x00" + b"\x80\x28" + b"\x00\x01\x00\x00"
hdr = FirmwareHeader.from_buffer_copy(data)
print(f"magic={bytes(hdr.magic).hex()}")
print(f"version={hdr.version}")
print(f"entry=0x{hdr.entry:08x}")
print(f"status: power_on={hdr.status.power_on}, error={hdr.status.error}, temp={hdr.status.temp}")
print(f"size={hdr.size}")
print(f"total size={ctypes.sizeof(FirmwareHeader)}")

# 反向：修改字段后导出字节
hdr.version = 3
modified = bytes(hdr)
print(f"modified hex={modified.hex()}")
```

`ctypes.BigEndianStructure` / `LittleEndianStructure` 控制字节序，`_pack_` 控制对齐。`from_buffer_copy(data)` 从字节创建结构体副本，`bytes(hdr)` 导出。

联合的用法：

```python
"""ctypes_union.py — 联合映射"""
import ctypes

class DataUnion(ctypes.Union):
    _fields_ = [
        ("u32", ctypes.c_uint32),
        ("u16", ctypes.c_uint16 * 2),
        ("u8",  ctypes.c_uint8 * 4),
    ]

u = DataUnion()
u.u32 = 0x12345678
print(f"u16[0]=0x{u.u16[0]:04x}, u16[1]=0x{u.u16[1]:04x}")  # 小端机器
print(f"u8={[hex(b) for b in u.u8]}")
```

## 4. 解析自定义二进制格式

综合运用 `struct` 解析一个完整的自定义二进制日志文件。假设格式：

```text
文件头(16B): magic(4) + version(2) + entry_count(4) + reserved(6)
索引区: 每个 entry 12B: offset(4) + length(4) + timestamp(4)
数据区: 每条记录 = 长度头(2) + 类型(1) + payload
```

```python
"""custom_format.py — 完整自定义二进制格式解析器"""
import struct
from dataclasses import dataclass
from datetime import datetime

MAGIC = b"BLG\x01"
HEADER_FMT = struct.Struct(">4sHI6x")   # magic + version + count + reserved
INDEX_FMT = struct.Struct(">III")         # offset + length + timestamp
RECORD_FMT = struct.Struct(">HB")         # length + type

@dataclass
class Record:
    offset: int
    length: int
    timestamp: int
    rec_type: int
    payload: bytes

    @property
    def time_str(self) -> str:
        return datetime.fromtimestamp(self.timestamp).strftime("%Y-%m-%d %H:%M:%S")

def parse_binary_log(path: str) -> list[Record]:
    with open(path, "rb") as f:
        data = f.read()

    # 1. 解析文件头
    if len(data) < HEADER_FMT.size:
        raise ValueError("文件太小，不是有效的二进制日志")
    magic, version, count = HEADER_FMT.unpack_from(data, 0)
    if magic != MAGIC:
        raise ValueError(f"魔数不匹配: {magic.hex()}")
    print(f"[HEADER] version={version}, entries={count}")

    # 2. 解析索引区
    records = []
    idx_offset = HEADER_FMT.size
    for i in range(count):
        offset, length, ts = INDEX_FMT.unpack_from(data, idx_offset + i * INDEX_FMT.size)
        records.append(Record(offset=offset, length=length, timestamp=ts,
                               rec_type=0, payload=b""))

    # 3. 解析数据区
    for rec in records:
        if rec.offset + 3 > len(data):
            print(f"[WARN] entry offset={rec.offset} 越界")
            continue
        rec_len, rec_type = RECORD_FMT.unpack_from(data, rec.offset)
        payload_start = rec.offset + RECORD_FMT.size
        rec.rec_type = rec_type
        rec.payload = data[payload_start:payload_start + rec_len]

    return records

if __name__ == "__main__":
    records = parse_binary_log("device_log.bin")
    for r in records:
        print(f"[{r.time_str}] type=0x{r.rec_type:02x} len={r.length} "
              f"payload={r.payload.hex()}")
```

用 `dataclass` 承载解析结果，比裸元组更可读。`Struct` 对象预编译格式串，重复解析时性能更好。

## 5. 固件与 dump 文件分析

固件镜像通常有分段结构：头 + 代码段 + 数据段 + CRC。分析固件时常用的操作：

```python
"""firmware_analyze.py — 固件镜像基本分析"""
import struct
import os

def analyze_firmware(path: str):
    size = os.path.getsize(path)
    with open(path, "rb") as f:
        data = f.read()

    print(f"文件: {path}")
    print(f"大小: {size} 字节 ({size/1024:.1f} KB)")

    # 魔数检测：常见固件头
    magic_checks = [
        (b"\x7fELF", "ELF"),
        (b"MZ", "PE/DOS"),
        (b"\xAA\x55", "x86 MBR"),
        (b"BLG\x01", "自定义日志"),
    ]
    for magic, name in magic_checks:
        if data.startswith(magic):
            print(f"魔数: {name} ({magic.hex()})")
            break
    else:
        print(f"魔数: 未知 (前 8 字节: {data[:8].hex()})")

    # 熵分析：判断哪些区域是压缩/加密数据
    print("\n分段熵分析（每 4KB 一段）:")
    import math
    for i in range(0, min(len(data), 64 * 1024), 4096):
        block = data[i:i+4096]
        if not block:
            break
        freq = [0] * 256
        for b in block:
            freq[b] += 1
        entropy = -sum((c / len(block)) * math.log2(c / len(block))
                       for c in freq if c > 0)
        marker = " [压缩/加密?]" if entropy > 7.5 else (" [全零?]" if entropy < 0.1 else "")
        print(f"  0x{i:08x}-0x{i+len(block):08x}  熵={entropy:.2f}{marker}")

    # 字符串提取：ASCII 可打印序列 >= 4 字符
    print("\n可打印字符串（前 20 条）:")
    strings = []
    current = bytearray()
    for b in data:
        if 32 <= b < 127:
            current.append(b)
        else:
            if len(current) >= 4:
                strings.append(current.decode("ascii"))
            current = bytearray()
    for s in strings[:20]:
        print(f"  {s}")

if __name__ == "__main__":
    analyze_firmware("firmware_v2.bin")
```

熵分析可以快速定位压缩段或加密段（熵接近 8），全零段（熵接近 0）通常是未初始化的 BSS 或保留区。字符串提取可以找到版本号、编译时间、错误信息等线索。

## 6. 校验和与 CRC 实现

二进制文件和报文通常带校验和或 CRC。Python 标准库 `zlib` 提供 CRC32，自定义 CRC 可以用查表法实现。

```python
"""checksum.py — 校验和与 CRC 实现"""
import zlib

def checksum_8bit(data: bytes) -> int:
    """8 位累加和校验（取低 8 位）"""
    return sum(data) & 0xFF

def checksum_ip(data: bytes) -> int:
    """IP 头校验和：16 位反码求和"""
    if len(data) % 2 == 1:
        data += b"\x00"
    total = 0
    for i in range(0, len(data), 2):
        total += (data[i] << 8) + data[i + 1]
    while total >> 16:
        total = (total & 0xFFFF) + (total >> 16)
    return (~total) & 0xFFFF

def crc32_zlib(data: bytes) -> int:
    """zlib 提供的 CRC32（多项式 0xEDB88320）"""
    return zlib.crc32(data) & 0xFFFFFFFF

def crc16_ccitt(data: bytes, poly: int = 0x1021, init: int = 0xFFFF) -> int:
    """CRC-16/CCITT 查表法实现"""
    # 预计算 256 项表
    table = []
    for i in range(256):
        crc = i << 8
        for _ in range(8):
            if crc & 0x8000:
                crc = ((crc << 1) ^ poly) & 0xFFFF
            else:
                crc = (crc << 1) & 0xFFFF
        table.append(crc)
    crc = init
    for b in data:
        crc = ((crc << 8) & 0xFFFF) ^ table[(crc >> 8) ^ b]
    return crc

# 验证固件 CRC
if __name__ == "__main__":
    with open("firmware_v2.bin", "rb") as f:
        data = f.read()
    # 假设最后 4 字节是 CRC32，前面是数据
    payload = data[:-4]
    stored_crc = int.from_bytes(data[-4:], "little")
    calc_crc = crc32_zlib(payload)
    print(f"存储 CRC32: 0x{stored_crc:08x}")
    print(f"计算 CRC32: 0x{calc_crc:08x}")
    print(f"校验: {'通过' if stored_crc == calc_crc else '失败'}")
```

实现自定义 CRC 时，关键参数是：多项式（poly）、初始值（init）、输入反转（refin）、输出反转（refout）、最终异或（xorout）。上面的 `crc16_ccitt` 是不反转版本。如果协议文档要求反转，需要在处理每个字节时先反转位序。

## 7. hex 与 bin 互转

日常调试中经常需要在十六进制文本和二进制之间转换：

```python
"""hex_bin.py — hex 与 bin 互转"""
# bytes -> hex 字符串
data = b"\xAA\x55\x01\x00\x10\x20"
hex_str = data.hex()              # "aa5501001020"
hex_spaced = data.hex(" ")        # "aa 55 01 00 10 20"（Python 3.8+）
print(hex_str, hex_spaced)

# hex 字符串 -> bytes
back = bytes.fromhex("aa5501001020")
back2 = bytes.fromhex("aa 55 01 00 10 20")  # 自动忽略空格
print(back == back2 == data)

# 从文本文件读取 hex 转 bin
with open("packet.hex", "r") as f:
    hex_text = f.read().replace("\n", "").replace(" ", "")
binary = bytes.fromhex(hex_text)
with open("packet.bin", "wb") as f:
    f.write(binary)

# bin 转带偏移的 hex dump（类似 hexdump -C）
def hexdump(data: bytes, width: int = 16) -> str:
    lines = []
    for i in range(0, len(data), width):
        chunk = data[i:i+width]
        hex_part = " ".join(f"{b:02x}" for b in chunk)
        ascii_part = "".join(chr(b) if 32 <= b < 127 else "." for b in chunk)
        lines.append(f"{i:08x}  {hex_part:<{width*3-1}}  |{ascii_part}|")
    return "\n".join(lines)

print(hexdump(b"Hello, World! This is a binary test.\x00\x01\x02"))
```

`bytes.hex()` 和 `bytes.fromhex()` 是标准库内置，不需要额外库。`int.to_bytes()` / `int.from_bytes()` 处理整数与字节的转换，显式指定 `byteorder`。

## 8. ELF/PE 头解析入门

理解编译产物的格式对 C++ 程序员至关重要。用 `struct` 解析 ELF 和 PE 的头部，可以快速确认架构、字节序、段信息。更多编译链接原理参见《../../01-C++技术体系/02-系统原理/02-编译链接与加载原理.md》。

### 8.1 ELF 头解析

```python
"""elf_header.py — ELF 文件头解析"""
import struct

def parse_elf_header(path: str):
    with open(path, "rb") as f:
        data = f.read(64)  # ELF64 头 64 字节

    # e_ident: 16 字节
    magic = data[0:4]
    if magic != b"\x7fELF":
        raise ValueError("不是 ELF 文件")
    ei_class = data[4]      # 1=32位, 2=64位
    ei_data = data[5]       # 1=小端, 2=大端
    ei_version = data[6]
    ei_osabi = data[7]

    is_64 = (ei_class == 2)
    endian = "<" if ei_data == 1 else ">"

    if is_64:
        # ELF64 头：e_type(2) e_machine(2) e_version(4) e_entry(8)
        # e_phoff(8) e_shoff(8) e_flags(4) e_ehsize(2)
        # e_phentsize(2) e_phnum(2) e_shentsize(2) e_shnum(2) e_shstrndx(2)
        fmt = struct.Struct(f"{endian}HHIQQQIHHHHHH")
        e_type, e_machine, e_version, e_entry, e_phoff, e_shoff, \
            e_flags, e_ehsize, e_phentsize, e_phnum, e_shentsize, \
            e_shnum, e_shstrndx = fmt.unpack_from(data, 16)
    else:
        # ELF32 头
        fmt = struct.Struct(f"{endian}HHIIIIIHHHHHH")
        e_type, e_machine, e_version, e_entry, e_phoff, e_shoff, \
            e_flags, e_ehsize, e_phentsize, e_phnum, e_shentsize, \
            e_shnum, e_shstrndx = fmt.unpack_from(data, 16)

    machine_names = {0x03: "x86", 0x3E: "x86-64", 0x28: "ARM",
                     0xB7: "AArch64", 0xF3: "RISC-V"}
    type_names = {1: "REL (可重定位)", 2: "EXEC (可执行)",
                  3: "DYN (共享库/PIE)", 4: "CORE (core dump)"}

    print(f"ELF{'64' if is_64 else '32'}  {'小端' if ei_data==1 else '大端'}")
    print(f"类型: {type_names.get(e_type, f'0x{e_type:x}')}")
    print(f"架构: {machine_names.get(e_machine, f'0x{e_machine:x}')}")
    print(f"入口地址: 0x{e_entry:08x}")
    print(f"程序头: offset=0x{e_phoff:x} 数量={e_phnum} 大小={e_phentsize}")
    print(f"节头:   offset=0x{e_shoff:x} 数量={e_shnum} 大小={e_shentsize}")

if __name__ == "__main__":
    parse_elf_header("a.out")
```

### 8.2 PE 头解析（DOS 头 + PE 签名）

```python
"""pe_header.py — PE 文件头入门解析"""
import struct

def parse_pe_header(path: str):
    with open(path, "rb") as f:
        data = f.read(1024)

    # DOS 头：前 2 字节 "MZ"，e_lfanew 在 0x3C 处
    if data[0:2] != b"MZ":
        raise ValueError("不是 PE 文件")
    e_lfanew = struct.unpack_from("<I", data, 0x3C)[0]
    print(f"DOS 头: e_lfanew=0x{e_lfanew:x} (PE 头偏移)")

    # PE 签名: "PE\0\0"
    pe_sig = data[e_lfanew:e_lfanew+4]
    if pe_sig != b"PE\x00\x00":
        raise ValueError(f"PE 签名不匹配: {pe_sig}")

    # COFF 头（PE 签名后 20 字节）
    coff_offset = e_lfanew + 4
    machine, nsections, timestamp, _, _, opt_header_size, characteristics = \
        struct.unpack_from("<HHIIIHH", data, coff_offset)

    machine_names = {0x014C: "x86 (i386)", 0x8664: "x86-64",
                     0xAA64: "ARM64", 0x01C0: "ARM"}
    print(f"COFF 头:")
    print(f"  架构: {machine_names.get(machine, f'0x{machine:x}')}")
    print(f"  段数量: {nsections}")
    print(f"  时间戳: {timestamp}")
    print(f"  可选头大小: {opt_header_size}")
    print(f"  特征: 0x{characteristics:04x}")

    # 可选头魔数（判断 PE32 / PE32+）
    opt_offset = coff_offset + 20
    opt_magic = struct.unpack_from("<H", data, opt_offset)[0]
    pe_type = "PE32" if opt_magic == 0x10B else ("PE32+" if opt_magic == 0x20B else "未知")
    print(f"  可选头: {pe_type} (magic=0x{opt_magic:04x})")

if __name__ == "__main__":
    parse_pe_header("app.exe")
```

PE 解析到 DOS 头和 COFF 头就能确认架构和段数，进一步解析可选头和段表需要更多代码。实际工作中，Linux 用 `readelf`、Windows 用 `dumpbin` 更全面，但 Python 脚本可以批量处理、嵌入自动化流程。

## 10. 常见坑

**坑 1：大小端搞反。** `struct.pack("I", 0x12345678)` 默认用本机字节序（`@`），在 x86 上是小端。网络协议和大多数文件格式用大端，必须显式写 `">I"` 或 `"!I"`。

**坑 2：对齐导致偏移错位。** C 结构体默认自然对齐，`struct` 的 `@` 也对齐，但 `>`/`<` 不对齐。解析协议时如果用了 `>` 但协议本身有对齐填充，所有后续字段都会错位。解决方案：用 `ctypes` + `_pack_` 精确控制，或在 `struct` 格式串中手动加 `x` 填充。

**坑 3：`unpack` 返回元组顺序搞错。** 字段多时建议用 `dataclass` 或 `ctypes.Structure` 命名字段，不要靠位置索引。

**坑 4：位域字节序与位序混淆。** `ctypes.BigEndianStructure` 的位域从高位开始分配，但不同编译器的位域分配规则可能不同（MSVC 与 GCC 有差异）。跨平台解析位域时，手动移位掩码比依赖 ctypes 位域更可靠。

**坑 5：CRC 参数不匹配。** 同一个 CRC-16 名称下有多种变体（CCITT、MODBUS、XMODEM），多项式、初始值、反转、最终异或都可能不同。必须严格按协议文档的参数实现，用文档给出的测试向量验证。

**坑 6：读取大文件时 `f.read()` 全部加载。** 固件或 dump 可能几百 MB，`read()` 全部读入内存浪费。用 `f.seek(offset)` + `f.read(size)` 按需读取，或用 `mmap` 映射。

## 11. 本节小结

- `struct` 用格式字符串在 `bytes` 和 C 类型间转换，`>`/`<` 控制大小端，`x` 做填充，`Struct` 对象预编译提升性能。
- `ctypes` 可以定义与 C 完全一致的结构体、联合、位域，`_pack_` 控制对齐，`BigEndianStructure`/`LittleEndianStructure` 控制字节序，适合精确复刻 C 内存布局。
- 解析自定义二进制格式的标准流程：读文件头验证魔数 → 解析索引/目录 → 按偏移读数据区 → 用 `dataclass` 承载结果。
- 固件分析三件套：魔数检测、熵分析（定位压缩/加密段）、字符串提取（找版本号和错误信息）。
- 校验和用累加或反码求和，CRC 用 `zlib.crc32` 或查表法自定义，关键是参数与协议文档严格一致。
- ELF/PE 头解析可以快速确认架构、字节序、段数，Python 脚本适合批量处理和嵌入自动化。
