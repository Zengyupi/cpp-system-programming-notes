## 1. 工程场景：C++ 服务端的运维痛点

C++ 写的服务端部署到 Linux 后，日常运维需要：

- 进程挂了要能自动拉起，不能半夜靠人重启。
- 需要监控 CPU、内存、文件句柄数，在 OOM 前预警。
- 定时清理日志文件和 core dump，避免磁盘写满。
- 部署前检查环境：内核版本、glibc 版本、CPU 架构、端口占用、依赖库是否存在。
- 优雅关闭：收到 SIGTERM 后停止接收新连接、等待当前请求完成、再退出。

这些用 shell 脚本也能做，但 Python 在跨平台、字符串处理、JSON 输出、错误处理上更健壮，而且可以和已有的 Python 工具链整合。psutil 是系统监控的事实标准库（以PyPI最新稳定版为准），用统一 API 覆盖 Linux/macOS/Windows。

## 2. os/sys/platform：进程与环境基础

标准库提供最基础的进程和环境操作：

```python
"""sys_env.py — 进程与环境基础操作"""
import os
import sys
import platform

# 进程信息
print(f"PID: {os.getpid()}")
print(f"父 PID: {os.getppid()}")

# 环境变量
print(f"PATH: {os.environ.get('PATH', '(未设置)')}")
os.environ["MY_VAR"] = "value"  # 设置环境变量（仅当前进程及子进程）

# 命令行参数
print(f"脚本名: {sys.argv[0]}")
print(f"参数: {sys.argv[1:]}")

# 平台信息
print(f"系统: {platform.system()}")        # Linux / Windows / Darwin
print(f"发行版: {platform.platform()}")     # Linux-5.15.0-x86_64
print(f"架构: {platform.machine()}")        # x86_64 / aarch64
print(f"Python: {platform.python_version()}")
print(f"glibc: {platform.libc_ver()}")      # ('glibc', '2.35')

# 退出码
sys.exit(0)   # 正常退出
# sys.exit(1)  # 异常退出，非零码
```

`os` 模块的文件和目录操作是跨平台的，`sys` 模块管理解释器和进程，`platform` 提供系统信息。部署脚本中常用 `platform.system()` 判断操作系统，走不同的逻辑分支。

执行外部命令：

```python
"""run_cmd.py — 执行外部命令并捕获输出"""
import subprocess

# 简单执行，捕获输出
result = subprocess.run(
    ["ls", "-la", "/var/log"],
    capture_output=True,
    text=True,
    timeout=10,
)
print(f"返回码: {result.returncode}")
print(f"stdout: {result.stdout}")
print(f"stderr: {result.stderr}")

# 检查执行（非零返回码抛异常）
try:
    subprocess.run(["g++", "--version"], check=True, capture_output=True, text=True)
except subprocess.CalledProcessError as e:
    print(f"命令失败: {e.returncode}, {e.stderr}")

# 管道：等价于 ps aux | grep myserver
ps = subprocess.run(["ps", "aux"], capture_output=True, text=True)
grep = subprocess.run(["grep", "myserver"], input=ps.stdout, capture_output=True, text=True)
print(grep.stdout)
```

`subprocess.run` 是 Python 3.5+ 的统一接口，`capture_output=True` 捕获 stdout/stderr，`text=True` 返回字符串而非 bytes，`timeout` 防止命令挂死。

## 3. signal：信号处理

C++ 服务端的优雅关闭通常靠 SIGTERM/SIGINT 触发。Python 脚本作为看门狗或管理进程时，也需要处理信号：

```python
"""signal_handler.py — 信号处理与优雅关闭"""
import signal
import sys
import time
import threading

# 全局停止标志
stop_event = threading.Event()

def handle_signal(signum, frame):
    sig_name = signal.Signals(signum).name
    print(f"\n[信号] 收到 {sig_name} ({signum})，开始优雅关闭...")
    stop_event.set()

# 注册信号处理
signal.signal(signal.SIGINT, handle_signal)   # Ctrl+C
signal.signal(signal.SIGTERM, handle_signal)  # systemd stop / kill

# SIGUSR1 用于重新加载配置
def handle_reload(signum, frame):
    print("[信号] 收到 SIGUSR1，重新加载配置...")
    # reload_config()

signal.signal(signal.SIGUSR1, handle_reload)

def main_loop():
    print("[主循环] 启动，PID:", __import__("os").getpid())
    while not stop_event.is_set():
        # 模拟工作
        print("[工作] 处理中...")
        stop_event.wait(2.0)  # 可被信号中断的等待
    print("[主循环] 已停止，清理资源...")
    # 关闭连接、刷写日志、等待子进程
    time.sleep(0.5)
    print("[主循环] 退出完成")

if __name__ == "__main__":
    main_loop()
```

关键点：

- 信号处理函数中不要做复杂操作（不要加锁、不要分配大量内存），只设置标志位，主循环检测标志位后做清理。
- `signal.signal` 只能在主线程调用，子线程中调用会抛 `ValueError`。
- Windows 只支持 `SIGINT`、`SIGTERM`、`SIGBREAK`，不支持 `SIGUSR1`/`SIGKILL` 等。
- `SIGKILL`（kill -9）无法捕获，进程会被强制杀死，所以优雅关闭只能靠 SIGTERM。

## 4. psutil：系统指标采集

`psutil`（以PyPI最新稳定版为准）是跨平台系统监控库，API 统一，覆盖 CPU、内存、磁盘、网络、进程。安装：`pip install psutil`。

### 4.1 CPU 与内存

```python
"""psutil_basic.py — CPU、内存、磁盘、网络指标采集"""
import psutil
import time

# CPU
print(f"逻辑 CPU 数: {psutil.cpu_count()}")
print(f"物理 CPU 数: {psutil.cpu_count(logical=False)}")
# 单次采样（interval=None 返回自上次调用的百分比）
print(f"CPU 使用率: {psutil.cpu_percent(interval=1.0)}%")
# 每核使用率
per_cpu = psutil.cpu_percent(interval=1.0, percpu=True)
for i, p in enumerate(per_cpu):
    print(f"  CPU{i}: {p}%")

# 内存
mem = psutil.virtual_memory()
print(f"\n总内存: {mem.total / 1024**3:.1f} GB")
print(f"已用: {mem.used / 1024**3:.1f} GB ({mem.percent}%)")
print(f"可用: {mem.available / 1024**3:.1f} GB")

swap = psutil.swap_memory()
print(f"Swap: {swap.used / 1024**3:.1f}/{swap.total / 1024**3:.1f} GB")

# 磁盘
for part in psutil.disk_partitions():
    if "loop" in part.device or part.fstype == "":
        continue
    usage = psutil.disk_usage(part.mountpoint)
    print(f"\n磁盘 {part.device} ({part.mountpoint}):")
    print(f"  总: {usage.total/1024**3:.1f}G  已用: {usage.used/1024**3:.1f}G  "
          f"可用: {usage.free/1024**3:.1f}G  使用率: {usage.percent}%")

# 磁盘 IO
disk_io = psutil.disk_io_counters()
print(f"\n磁盘读: {disk_io.read_bytes / 1024**2:.1f} MB  写: {disk_io.write_bytes / 1024**2:.1f} MB")

# 网络
net_io = psutil.net_io_counters()
print(f"网络收: {net_io.bytes_recv / 1024**2:.1f} MB  发: {net_io.bytes_sent / 1024**2:.1f} MB")
```

### 4.2 进程详情：句柄、线程、连接

监控特定 C++ 服务进程时，需要看它的句柄数、线程数、打开的连接：

```python
"""psutil_process.py — 进程级监控"""
import psutil

def monitor_process(pid: int):
    try:
        p = psutil.Process(pid)
    except psutil.NoSuchProcess:
        print(f"进程 {pid} 不存在")
        return

    with p.oneshot():  # 批量获取，减少系统调用
        print(f"PID: {p.pid}")
        print(f"名称: {p.name()}")
        print(f"状态: {p.status()}")        # running / sleeping / zombie
        print(f"命令行: {' '.join(p.cmdline())}")
        print(f"工作目录: {p.cwd()}")
        print(f"创建时间: {p.create_time()}")

        # CPU
        print(f"CPU 使用率: {p.cpu_percent(interval=0.5)}%")
        print(f"CPU 时间: user={p.cpu_times().user:.1f}s sys={p.cpu_times().system:.1f}s")

        # 内存
        mem = p.memory_info()
        print(f"内存 RSS: {mem.rss / 1024**2:.1f} MB")
        print(f"内存 VMS: {mem.vms / 1024**2:.1f} MB")
        print(f"内存占比: {p.memory_percent():.2f}%")

        # 线程
        threads = p.threads()
        print(f"线程数: {len(threads)}")
        for t in threads[:5]:
            print(f"  线程 {t.id}: user={t.user_time:.2f}s sys={t.system_time:.2f}s")

        # 文件句柄（Linux）
        try:
            open_files = p.open_files()
            print(f"打开文件数: {len(open_files)}")
            for f in open_files[:5]:
                print(f"  {f.path} (fd={f.fd})")
        except (psutil.AccessDenied, psutil.NoSuchProcess):
            print("打开文件数: 无权限")

        # 网络连接
        connections = p.net_connections(kind="inet")
        print(f"网络连接数: {len(connections)}")
        for c in connections:
            local = f"{c.laddr.ip}:{c.laddr.port}" if c.laddr else "-"
            remote = f"{c.raddr.ip}:{c.raddr.port}" if c.raddr else "-"
            print(f"  {c.type.name} {local} -> {remote} [{c.status}]")

        # 子进程
        children = p.children(recursive=True)
        print(f"子进程数: {len(children)}")

if __name__ == "__main__":
    import sys
    pid = int(sys.argv[1]) if len(sys.argv) > 1 else psutil.Process().pid
    monitor_process(pid)
```

`p.oneshot()` 上下文管理器批量获取进程信息，减少多次系统调用的开销。句柄数泄漏排查时，`open_files()` 和 `net_connections()` 是关键——如果句柄数持续增长，看是文件没关还是连接没关。

按名称查找进程：

```python
"""find_process.py — 按名称查找进程"""
import psutil

def find_by_name(name: str) -> list[psutil.Process]:
    results = []
    for p in psutil.process_iter(["pid", "name", "cmdline"]):
        try:
            if name in (p.info["name"] or "") or \
               any(name in (c or "") for c in (p.info["cmdline"] or [])):
                results.append(p)
        except (psutil.NoSuchProcess, psutil.AccessDenied):
            pass
    return results

for p in find_by_name("myserver"):
    print(f"PID={p.pid} name={p.name()} cmd={' '.join(p.cmdline())}")
```

## 5. 看门狗与自动重启

C++ 服务进程意外退出后自动拉起。看门狗的核心是循环检测进程是否存活，不存活就重启：

```python
"""watchdog.py — 进程看门狗与自动重启"""
import subprocess
import time
import signal
import sys
import os
from datetime import datetime

class Watchdog:
    def __init__(self, cmd: list[str], restart_delay: float = 3.0,
                 max_restarts: int = 0, log_file: str = "watchdog.log"):
        self.cmd = cmd
        self.restart_delay = restart_delay
        self.max_restarts = max_restarts  # 0 = 无限重启
        self.restart_count = 0
        self.process: subprocess.Popen | None = None
        self.log_file = log_file
        self._stop = False

    def log(self, msg: str):
        line = f"[{datetime.now().strftime('%Y-%m-%d %H:%M:%S')}] {msg}"
        print(line)
        with open(self.log_file, "a", encoding="utf-8") as f:
            f.write(line + "\n")

    def start_process(self) -> bool:
        try:
            self.process = subprocess.Popen(
                self.cmd,
                stdout=subprocess.DEVNULL,
                stderr=subprocess.DEVNULL,
                # stdin 关闭，避免阻塞
            )
            self.log(f"启动进程 PID={self.process.pid}: {' '.join(self.cmd)}")
            return True
        except FileNotFoundError:
            self.log(f"错误：可执行文件不存在: {self.cmd[0]}")
            return False
        except Exception as e:
            self.log(f"启动失败: {e}")
            return False

    def stop(self, signum=None, frame=None):
        self._stop = True
        self.log("收到停止信号，正在终止子进程...")
        if self.process and self.process.poll() is None:
            self.process.terminate()
            try:
                self.process.wait(timeout=10)
            except subprocess.TimeoutExpired:
                self.process.kill()
        self.log("看门狗退出")

    def run(self):
        signal.signal(signal.SIGTERM, self.stop)
        signal.signal(signal.SIGINT, self.stop)

        if not self.start_process():
            sys.exit(1)

        while not self._stop:
            retcode = self.process.poll()
            if retcode is not None:
                # 进程退出了
                self.log(f"进程退出，返回码={retcode}")
                if self.max_restarts > 0 and self.restart_count >= self.max_restarts:
                    self.log(f"已达最大重启次数 {self.max_restarts}，看门狗退出")
                    break
                self.restart_count += 1
                self.log(f"{self.restart_delay}s 后第 {self.restart_count} 次重启...")
                time.sleep(self.restart_delay)
                if not self.start_process():
                    self.log("重启失败，退出")
                    break
            time.sleep(1.0)

if __name__ == "__main__":
    # 用法: python watchdog.py ./myserver --config /etc/myserver.conf
    if len(sys.argv) < 2:
        print("用法: python watchdog.py <命令> [参数...]")
        sys.exit(1)
    wd = Watchdog(cmd=sys.argv[1:], restart_delay=3.0, max_restarts=0)
    wd.run()
```

这个看门狗的特点：

- 用 `subprocess.Popen` 启动子进程，`poll()` 非阻塞检测退出状态。
- 记录重启次数，可选最大重启次数（防止崩溃循环）。
- 收到 SIGTERM/SIGINT 时先 `terminate()` 子进程，等待 10 秒后 `kill()`。
- 日志同时输出到控制台和文件。

生产环境中，systemd 的 `Restart=always` 已经能做自动重启，这个 Python 看门狗适合没有 systemd 的嵌入式环境，或者需要在重启前做额外清理（删临时文件、发告警）的场景。

## 6. 定时任务

Python 脚本内做定时任务有两种方式：标准库 `sched`/`threading.Timer`，或第三方库 `schedule`（以PyPI最新稳定版为准，API 最简洁）。

```python
"""scheduled_jobs.py — 定时任务"""
import schedule  # pip install schedule
import time
from datetime import datetime

def job_clean_logs():
    print(f"[{datetime.now()}] 清理日志...")
    # clean_old_logs("/var/log/myserver", days=7)

def job_check_health():
    print(f"[{datetime.now()}] 健康检查...")
    # check_service_health()

def job_backup():
    print(f"[{datetime.now()}] 备份配置...")
    # backup_config()

# 每 30 秒执行
schedule.every(30).seconds.do(job_check_health)
# 每分钟执行
schedule.every(1).minutes.do(job_clean_logs)
# 每天凌晨 2 点执行
schedule.every().day.at("02:00").do(job_backup)
# 每周一 9 点执行
schedule.every().monday.at("09:00").do(job_backup)

print("定时任务已启动，Ctrl+C 退出")
while True:
    schedule.run_pending()
    time.sleep(1)
```

`schedule` 库适合轻量级定时任务，但它是单线程阻塞的，如果任务执行时间长会影响后续任务。需要更精确的调度或多线程任务时，用 `APScheduler`（以PyPI最新稳定版为准），支持 cron 表达式、线程池/进程池执行器、持久化任务。

```python
"""apscheduler_example.py — APScheduler 高级定时"""
from apscheduler.schedulers.blocking import BlockingScheduler
from apscheduler.triggers.cron import CronTrigger

def job_every_minute():
    print("每分钟执行")

scheduler = BlockingScheduler()
# cron 表达式：每天 2:30 执行
scheduler.add_job(job_every_minute, CronTrigger(hour=2, minute=30))
# 间隔：每 5 分钟
scheduler.add_job(job_every_minute, "interval", minutes=5)
scheduler.start()
```

如果只是系统级的定时任务（如每天清理日志），直接用 Linux crontab 调用 Python 脚本更简单可靠，不需要在脚本内做调度。

## 7. systemd 用户服务

把 Python 看门狗或管理脚本注册为 systemd 用户服务，开机自启、崩溃自动重启、日志统一管理。

```ini
# ~/.config/systemd/user/myserver-watchdog.service
[Unit]
Description=MyServer Watchdog
After=network.target

[Service]
Type=simple
WorkingDirectory=/opt/myserver
ExecStart=/usr/bin/python3 /opt/myserver/watchdog.py /opt/myserver/myserver --config /etc/myserver.conf
Restart=always
RestartSec=3
StandardOutput=journal
StandardError=journal
Environment=PYTHONUNBUFFERED=1

[Install]
WantedBy=default.target
```

管理命令：

```bash
# 重新加载 systemd 配置
systemctl --user daemon-reload

# 启动 / 停止 / 重启
systemctl --user start myserver-watchdog
systemctl --user stop myserver-watchdog
systemctl --user restart myserver-watchdog

# 开机自启（用户登录时启动）
systemctl --user enable myserver-watchdog

# 查看状态和日志
systemctl --user status myserver-watchdog
journalctl --user -u myserver-watchdog -f   # 实时跟踪日志

# 允许用户服务在未登录时也运行（需要 root）
sudo loginctl enable-linger $USER
```

关键点：

- `Restart=always` + `RestartSec=3` 已经实现了自动重启，此时 Python 看门狗内部可以不再做重启逻辑，只做健康检查和告警。
- `PYTHONUNBUFFERED=1` 确保 Python 的 print 立即输出到 journal，不会因为缓冲导致日志延迟。
- 用户服务不需要 root 权限，但默认只在用户登录时运行；`loginctl enable-linger` 让服务在用户未登录时也运行。
- 如果需要系统级服务（所有用户共享），把文件放到 `/etc/systemd/system/`，用 `systemctl`（不带 `--user`）管理。

## 8. 磁盘清理与环境巡检

### 8.1 磁盘清理脚本

```python
"""disk_cleanup.py — 磁盘清理"""
import os
import time
import shutil
from pathlib import Path

def clean_old_files(directory: str, days: int, extensions: list[str] | None = None,
                    dry_run: bool = True) -> int:
    """删除指定目录下超过 N 天的文件"""
    cutoff = time.time() - days * 86400
    cleaned = 0
    for root, dirs, files in os.walk(directory):
        for fname in files:
            if extensions and not any(fname.endswith(ext) for ext in extensions):
                continue
            fpath = os.path.join(root, fname)
            try:
                mtime = os.path.getmtime(fpath)
                if mtime < cutoff:
                    size = os.path.getsize(fpath)
                    if dry_run:
                        print(f"[DRY] 将删除 {fpath} ({size/1024:.1f} KB)")
                    else:
                        os.remove(fpath)
                        print(f"[DEL] 已删除 {fpath} ({size/1024:.1f} KB)")
                    cleaned += 1
            except OSError as e:
                print(f"[ERR] {fpath}: {e}")
    return cleaned

def clean_core_dumps(directory: str = "/var/lib/systemd/coredump",
                      max_size_mb: int = 1024, dry_run: bool = True):
    """清理 core dump，保留最近的，总大小不超过阈值"""
    files = []
    for f in Path(directory).glob("core*"):
        if f.is_file():
            files.append((f.stat().st_mtime, f.stat().st_size, f))
    files.sort(reverse=True)  # 最新的在前

    total = 0
    for mtime, size, fpath in files:
        total += size
        if total > max_size_mb * 1024**2:
            if dry_run:
                print(f"[DRY] 将删除 core dump {fpath} ({size/1024**2:.1f} MB)")
            else:
                fpath.unlink()
                print(f"[DEL] 已删除 core dump {fpath}")

if __name__ == "__main__":
    print("=== 清理 7 天前的 .log 文件 ===")
    clean_old_files("/var/log/myserver", days=7, extensions=[".log"], dry_run=True)
    print("\n=== 清理 core dump（上限 1GB）===")
    clean_core_dumps(dry_run=True)
```

`dry_run=True` 先预览要删什么，确认后再改成 `False` 执行。这是运维脚本的安全惯例。

### 8.2 环境巡检脚本

部署前检查环境是否满足要求：

```python
"""env_check.py — 部署前环境巡检"""
import os
import sys
import shutil
import subprocess
import platform

def check_command(cmd: str) -> bool:
    """检查命令是否存在"""
    return shutil.which(cmd) is not None

def check_port_free(port: int) -> bool:
    """检查端口是否被占用"""
    import socket
    with socket.socket(socket.AF_INET, socket.SOCK_STREAM) as s:
        return s.connect_ex(("127.0.0.1", port)) != 0

def check_disk_space(path: str, min_gb: float) -> bool:
    """检查磁盘剩余空间"""
    stat = os.statvfs(path)
    free_gb = (stat.f_bavail * stat.f_frsize) / 1024**3
    return free_gb >= min_gb

def check_glibc_version(min_version: tuple[int, int]) -> bool:
    """检查 glibc 版本"""
    try:
        result = subprocess.run(["ldd", "--version"], capture_output=True, text=True)
        # 输出第一行: ldd (Ubuntu GLIBC 2.35-0ubuntu3) 2.35
        version_str = result.stdout.split("\n")[0].split()[-1]
        major, minor = map(int, version_str.split(".")[:2])
        return (major, minor) >= min_version
    except Exception:
        return False

def run_checks():
    checks = [
        ("操作系统为 Linux", platform.system() == "Linux"),
        ("架构为 x86_64", platform.machine() == "x86_64"),
        ("g++ 已安装", check_command("g++")),
        ("cmake 已安装", check_command("cmake")),
        ("python3 已安装", check_command("python3")),
        ("glibc >= 2.28", check_glibc_version((2, 28))),
        ("端口 8080 可用", check_port_free(8080)),
        ("端口 8443 可用", check_port_free(8443)),
        ("/opt 剩余 >= 5GB", check_disk_space("/opt", 5.0)),
        ("/var/log 剩余 >= 2GB", check_disk_space("/var/log", 2.0)),
    ]

    all_pass = True
    print("=== 环境巡检 ===")
    for name, passed in checks:
        status = "PASS" if passed else "FAIL"
        if not passed:
            all_pass = False
        print(f"  [{status}] {name}")

    print(f"\n结果: {'全部通过' if all_pass else '存在失败项，请检查'}")
    return all_pass

if __name__ == "__main__":
    sys.exit(0 if run_checks() else 1)
```

巡检脚本输出 PASS/FAIL，返回码 0 表示全部通过，可以直接嵌入 CI/CD 或部署脚本中做前置检查。

## 9. 常见坑

**坑 1：`subprocess.run` 不设 timeout。** 外部命令挂死会导致整个 Python 脚本挂死。始终设 `timeout`，或用 `Popen` + `wait(timeout)`。

**坑 2：用 `shell=True` 拼接命令。** `subprocess.run("ls " + path, shell=True)` 有命令注入风险，且跨平台兼容性差。用列表形式 `subprocess.run(["ls", path])`，参数自动转义。

**坑 3：信号处理函数中做复杂操作。** 信号处理函数是异步执行的，在里面加锁、分配内存、调用非可重入函数可能导致死锁或崩溃。只设置标志位，主循环处理。

**坑 4：psutil 遍历进程时遇到已退出的进程。** `process_iter` 遍历过程中进程可能退出，调用 `p.name()` 等方法会抛 `NoSuchProcess`。必须 `try/except` 包裹，或用 `process_iter(["attrs"])` 一次性获取属性。

**坑 5：看门狗无限重启导致崩溃循环。** 进程启动后立即崩溃，看门狗无限重启会刷爆日志和 CPU。加最大重启次数或退避延迟（每次重启间隔翻倍），或在重启次数过多时发告警并暂停。

**坑 6：`os.statvfs` 跨平台。** 这是 POSIX 接口，Windows 上没有。跨平台脚本用 `shutil.disk_usage(path)`，它返回 `(total, used, free)`，Windows/Linux/macOS 都支持。

**坑 7：systemd 用户服务不开机自启。** 用户服务默认只在用户登录时启动。需要 `loginctl enable-linger $USER` 让服务在未登录时也运行。

## 10. 本节小结

- `os`/`sys`/`platform` 提供进程、环境、平台信息的基础操作；`subprocess.run` 是执行外部命令的统一接口，必须设 `timeout`，用列表参数避免注入。
- `signal` 处理 SIGTERM/SIGINT 实现优雅关闭，处理函数只设标志位，主循环做清理；SIGKILL 无法捕获。
- `psutil` 是跨平台系统监控事实标准，`Process.oneshot()` 批量获取，`open_files()` 和 `net_connections()` 是句柄泄漏排查的关键。
- 看门狗用 `Popen` + `poll()` 检测进程退出，自动重启；生产环境优先用 systemd `Restart=always`，Python 看门狗适合嵌入式或需要额外清理的场景。
- 定时任务轻量用 `schedule`，高级用 `APScheduler`；系统级定时直接用 crontab 更可靠。
- systemd 用户服务实现开机自启和日志统一管理，`PYTHONUNBUFFERED=1` 避免日志缓冲延迟，`loginctl enable-linger` 让未登录时也运行。
- 磁盘清理和环境巡检脚本用 `dry_run` 先预览，巡检输出 PASS/FAIL + 非零退出码，可嵌入自动化流程。
