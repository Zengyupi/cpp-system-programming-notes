## 1. 工程场景：Python 在构建流程中的角色

C++/Rust 项目的构建流程通常不止是 `make` 或 `cargo build`：需要先检查依赖、生成版本头文件、配置 CMake、编译、运行测试、收集产物、打包发布。这些步骤用 shell 脚本可以写，但一旦涉及条件判断、错误分类、并行构建矩阵、跨平台兼容，shell 就变得难以维护。

Python 在构建流程中的定位是**编排层**：不替代 CMake/cargo 做实际编译，而是串联各个构建步骤、处理构建输出、管理构建配置。典型场景：

- **统一构建入口**：一个 `build.py` 替代 5 个 shell 脚本，支持 `--debug/--release`、`--clean`、`--test` 等选项
- **编译矩阵**：gcc/clang × debug/release × O0/O2 批量编译，收集所有错误并归类
- **版本头生成**：从 git 描述自动生成 `version.h`，包含 commit hash、构建时间、分支
- **交叉编译**：针对 arm-linux-gnueabihf、aarch64-linux-gnu 等多个 toolchain 编排构建
- **产物收集**：编译后把可执行文件、库、配置文件按平台分类打包

## 2. 驱动 CMake/Make/cargo 构建

### 2.1 CMake 完整构建流程

```python
import subprocess
from pathlib import Path

class CMakeBuilder:
    """CMake 构建封装。"""

    def __init__(self, source_dir: Path, build_dir: Path,
                 generator: str = "Ninja", build_type: str = "Release"):
        self.source_dir = source_dir.resolve()
        self.build_dir = build_dir.resolve()
        self.generator = generator
        self.build_type = build_type

    def configure(self, extra_args: list[str] | None = None) -> tuple[int, str]:
        """配置阶段：cmake -S . -B build。"""
        self.build_dir.mkdir(parents=True, exist_ok=True)
        cmd = [
            "cmake",
            "-S", str(self.source_dir),
            "-B", str(self.build_dir),
            "-G", self.generator,
            f"-DCMAKE_BUILD_TYPE={self.build_type}",
        ]
        if extra_args:
            cmd.extend(extra_args)

        result = subprocess.run(cmd, capture_output=True, text=True)
        return result.returncode, result.stdout + result.stderr

    def build(self, targets: list[str] | None = None, jobs: int = 4) -> tuple[int, str]:
        """构建阶段：cmake --build build。"""
        cmd = ["cmake", "--build", str(self.build_dir), "--parallel", str(jobs)]
        if targets:
            cmd.extend(["--target", *targets])

        result = subprocess.run(cmd, capture_output=True, text=True)
        return result.returncode, result.stdout + result.stderr

    def clean(self) -> tuple[int, str]:
        """清理构建目录。"""
        cmd = ["cmake", "--build", str(self.build_dir), "--target", "clean"]
        result = subprocess.run(cmd, capture_output=True, text=True)
        return result.returncode, result.stdout + result.stderr

    def run_tests(self, jobs: int = 4) -> tuple[int, str]:
        """运行 CTest。"""
        cmd = ["ctest", "--test-dir", str(self.build_dir), "-j", str(jobs), "--output-on-failure"]
        result = subprocess.run(cmd, capture_output=True, text=True)
        return result.returncode, result.stdout + result.stderr

# 用法
builder = CMakeBuilder(Path("."), Path("build/release"), build_type="Release")
code, output = builder.configure()
if code == 0:
    code, output = builder.build(jobs=8)
if code == 0:
    code, output = builder.run_tests()
```

### 2.2 Make 与 Ninja

```python
def make_build(build_dir: Path, target: str = "all", jobs: int = 4) -> tuple[int, str]:
    """调用 make。"""
    cmd = ["make", "-C", str(build_dir), "-j", str(jobs), target]
    result = subprocess.run(cmd, capture_output=True, text=True)
    return result.returncode, result.stdout + result.stderr

def ninja_build(build_dir: Path, target: str | None = None, jobs: int = 4) -> tuple[int, str]:
    """调用 ninja。"""
    cmd = ["ninja", "-C", str(build_dir), "-j", str(jobs)]
    if target:
        cmd.append(target)
    result = subprocess.run(cmd, capture_output=True, text=True)
    return result.returncode, result.stdout + result.stderr
```

Ninja 比 Make 快的原因：增量构建时依赖图计算更快，且默认并行。Python 编排时推荐用 Ninja 作为 CMake generator。

```python
import json

def cargo_build(project_dir: Path, release: bool = False,
                 target: str | None = None, features: list[str] | None = None) -> tuple[int, str]:
    """cargo build。"""
    cmd = ["cargo", "build"]
    if release:
        cmd.append("--release")
    if target:
        cmd.extend(["--target", target])
    if features:
        cmd.extend(["--features", ",".join(features)])

    result = subprocess.run(cmd, cwd=project_dir, capture_output=True, text=True)
    return result.returncode, result.stdout + result.stderr

def cargo_metadata(project_dir: Path) -> dict:
    """获取 cargo 项目元数据（JSON 格式，机器可读）。"""
    result = subprocess.run(
        ["cargo", "metadata", "--format-version", "1", "--no-deps"],
        cwd=project_dir, capture_output=True, text=True,
    )
    return json.loads(result.stdout)

# 用法：获取项目名和目标列表
meta = cargo_metadata(Path("."))
for pkg in meta["packages"]:
    print(f"包: {pkg['name']} v{pkg['version']}")
    for target in pkg["targets"]:
        print(f"  目标: {target['name']} ({', '.join(target['kind'])})")
```

## 3. 批量编译矩阵

编译矩阵是系统程序员的常用工具：验证代码在不同编译器、不同编译选项下都能正确编译。

```python
from concurrent.futures import ThreadPoolExecutor, as_completed
from dataclasses import dataclass

@dataclass
class BuildMatrixConfig:
    compiler: str       # gcc, clang
    build_type: str     # Debug, Release
    opt_level: str      # O0, O1, O2, O3, Os
    standard: str       # 14, 17, 20, 23

    @property
    def name(self) -> str:
        return f"{self.compiler}_{self.build_type}_{self.opt_level}_cxx{self.standard}"

    @property
    def build_dir(self) -> Path:
        return Path("build_matrix") / self.name

def run_matrix_build(source_dir: Path, config: BuildMatrixConfig) -> dict:
    """执行矩阵中的单次构建。"""
    cxx = {"gcc": "g++", "clang": "clang++"}[config.compiler]
    cc = {"gcc": "gcc", "clang": "clang"}[config.compiler]
    cxxflags = f"-{config.opt_level} -Wall -Wextra -Wpedantic -std=c++{config.standard}"

    builder = CMakeBuilder(
        source_dir, config.build_dir,
        build_type=config.build_type,
    )
    code, output = builder.configure(extra_args=[
        f"-DCMAKE_C_COMPILER={cc}",
        f"-DCMAKE_CXX_COMPILER={cxx}",
        f"-DCMAKE_CXX_FLAGS={cxxflags}",
    ])
    if code != 0:
        return {"config": config.__dict__, "stage": "configure", "success": False, "output": output}

    code, output = builder.build(jobs=4)
    return {
        "config": config.__dict__,
        "stage": "build",
        "success": code == 0,
        "output": output,
    }

def generate_matrix() -> list[BuildMatrixConfig]:
    """生成编译矩阵。"""
    configs = []
    for cc in ["gcc", "clang"]:
        for bt in ["Debug", "Release"]:
            for opt in ["O0", "O2"]:
                for std in ["17", "20"]:
                    configs.append(BuildMatrixConfig(cc, bt, opt, std))
    return configs

def run_matrix(source_dir: Path, workers: int = 4) -> list[dict]:
    """并行执行编译矩阵。"""
    configs = generate_matrix()
    print(f"编译矩阵: {len(configs)} 个配置, {workers} 并发")

    results = []
    with ThreadPoolExecutor(max_workers=workers) as executor:
        futures = {executor.submit(run_matrix_build, source_dir, cfg): cfg for cfg in configs}
        for future in as_completed(futures):
            cfg = futures[future]
            try:
                result = future.result()
                results.append(result)
                status = "PASS" if result["success"] else "FAIL"
                print(f"[{status}] {cfg.name}")
            except Exception as e:
                print(f"[EXCEPTION] {cfg.name}: {e}")
                results.append({"config": cfg.__dict__, "success": False, "error": str(e)})

    return results
```

## 4. 解析编译错误并归类去重

编译矩阵产生大量错误输出，需要归类去重后才能快速定位问题。

```python
import re
from collections import defaultdict

DIAG_PATTERN = re.compile(
    r'^(?P<file>[\w./\\-]+):(?P<line>\d+):(?P<col>\d+):\s+'
    r'(?P<level>error|warning|note):\s+(?P<msg>.*)$'
)

def classify_error(msg: str) -> str:
    """将错误消息归类为错误类型。"""
    if "undefined reference" in msg:
        return "undefined_reference"
    if "was not declared" in msg or "was not declared in this scope" in msg:
        return "not_declared"
    if "no matching function" in msg:
        return "no_matching_function"
    if "redefinition" in msg:
        return "redefinition"
    if "does not name a type" in msg:
        return "unknown_type"
    if "expected" in msg and "before" in msg:
        return "syntax_error"
    if "conversion" in msg and "could not convert" in msg:
        return "type_conversion"
    if "warning" in msg:
        return "warning"
    return "other"

def parse_and_dedupe(build_output: str) -> dict:
    """解析编译输出，归类去重。"""
    errors_by_type = defaultdict(list)
    errors_by_file = defaultdict(list)
    seen = set()

    for line in build_output.splitlines():
        m = DIAG_PATTERN.match(line)
        if not m:
            continue
        data = m.groupdict()
        if data["level"] not in ("error", "warning"):
            continue

        # 去重 key：文件 + 行 + 错误类型 + 消息前60字符
        error_type = classify_error(data["msg"])
        key = (data["file"], data["line"], error_type, data["msg"][:60])
        if key in seen:
            continue
        seen.add(key)

        entry = {**data, "error_type": error_type}
        errors_by_type[error_type].append(entry)
        errors_by_file[data["file"]].append(entry)

    return {
        "by_type": {k: len(v) for k, v in sorted(errors_by_type.items(), key=lambda x: -len(x[1]))},
        "by_file": {k: len(v) for k, v in sorted(errors_by_file.items(), key=lambda x: -len(x[1]))},
        "unique_errors": len(seen),
        "details": {k: v[:5] for k, v in errors_by_type.items()},  # 每类最多5条详情
    }
```

## 5. compile_commands.json 利用

`compile_commands.json` 是 CMake 生成的编译命令数据库（`-DCMAKE_EXPORT_COMPILE_COMMANDS=ON`），记录了每个源文件的编译命令。clangd、clang-tidy、include-what-you-use 等工具都依赖它。

```python
import json
from pathlib import Path

def load_compile_commands(build_dir: Path) -> list[dict]:
    """加载 compile_commands.json。"""
    path = build_dir / "compile_commands.json"
    if not path.exists():
        raise FileNotFoundError(f"未找到 {path}，请加 -DCMAKE_EXPORT_COMPILE_COMMANDS=ON")
    return json.loads(path.read_text(encoding="utf-8"))

def find_compile_command(commands: list[dict], source_file: str) -> dict | None:
    """查找指定源文件的编译命令。"""
    for cmd in commands:
        if cmd["file"].endswith(source_file):
            return cmd
    return None

def extract_include_paths(commands: list[dict]) -> list[str]:
    """从编译命令中提取所有 include 路径。"""
    import re
    includes = set()
    for cmd in commands:
        for match in re.finditer(r'-I\s*(\S+)', cmd["command"]):
            includes.add(match.group(1))
    return sorted(includes)

def extract_defines(commands: list[dict]) -> list[str]:
    """提取所有宏定义。"""
    import re
    defines = set()
    for cmd in commands:
        for match in re.finditer(r'-D\s*(\S+)', cmd["command"]):
            defines.add(match.group(1))
    return sorted(defines)

def run_clang_tidy(commands: list[dict], source_files: list[str],
                    checks: str = "bugprone-*,performance-*") -> dict:
    """对指定文件运行 clang-tidy。"""
    results = {}
    for src in source_files:
        cmd = ["clang-tidy", src, "-checks", checks, "-p", str(Path(commands[0]["directory"]))]
        result = subprocess.run(cmd, capture_output=True, text=True)
        results[src] = {"returncode": result.returncode, "output": result.stdout + result.stderr}
    return results
```

**典型用途**：
- 提取 include 路径和宏定义，用于配置 clangd 或其他静态分析工具
- 批量运行 clang-tidy/clang-analyzer
- 检查哪些文件没有被编译（源文件存在但不在 compile_commands 中）
- 生成 include 依赖图

## 6. 自动生成版本头文件

从 git 信息自动生成 `version.h`，避免手动维护版本号。

```python
import subprocess
from datetime import datetime
from pathlib import Path

def get_git_info() -> dict:
    """获取 git 版本信息。"""
    def run(cmd: list[str]) -> str:
        result = subprocess.run(cmd, capture_output=True, text=True)
        return result.stdout.strip()

    return {
        "commit": run(["git", "rev-parse", "HEAD"]),
        "short_commit": run(["git", "rev-parse", "--short", "HEAD"]),
        "branch": run(["git", "rev-parse", "--abbrev-ref", "HEAD"]),
        "tag": run(["git", "describe", "--tags", "--always", "--dirty"]),
        "is_dirty": run(["git", "status", "--porcelain"]) != "",
        "commit_time": run(["git", "log", "-1", "--format=%ci"]),
    }

def generate_version_header(output_path: Path, version_major: int, version_minor: int,
                             version_patch: int) -> None:
    """生成 version.h。"""
    git = get_git_info()
    build_time = datetime.now().strftime("%Y-%m-%d %H:%M:%S")

    content = f"""\
// AUTO-GENERATED by gen_version.py, DO NOT EDIT
#ifndef VERSION_H
#define VERSION_H

#define VERSION_MAJOR {version_major}
#define VERSION_MINOR {version_minor}
#define VERSION_PATCH {version_patch}
#define VERSION_STRING "{version_major}.{version_minor}.{version_patch}"

#define GIT_COMMIT "{git['commit']}"
#define GIT_SHORT_COMMIT "{git['short_commit']}"
#define GIT_BRANCH "{git['branch']}"
#define GIT_DESCRIBE "{git['tag']}"
#define GIT_DIRTY {'1' if git['is_dirty'] else '0'}

#define BUILD_TIME "{build_time}"

#endif // VERSION_H
"""
    output_path.parent.mkdir(parents=True, exist_ok=True)
    output_path.write_text(content, encoding="utf-8")
    print(f"生成: {output_path} (v{version_major}.{version_minor}.{version_patch}-{git['short_commit']})")

# 用法
generate_version_header(Path("src/version.h"), 1, 2, 3)
```

在 CMake 中集成：用 `add_custom_command` 在构建前调用 Python 脚本生成版本头。

```cmake
# CMakeLists.txt 中集成版本头生成
add_custom_command(
    OUTPUT ${CMAKE_BINARY_DIR}/generated/version.h
    COMMAND ${Python3_EXECUTABLE} ${CMAKE_SOURCE_DIR}/scripts/gen_version.py
            --output ${CMAKE_BINARY_DIR}/generated/version.h
            --major 1 --minor 2 --patch 3
    DEPENDS ${CMAKE_SOURCE_DIR}/scripts/gen_version.py
    COMMENT "Generating version.h"
)
```

## 7. 交叉编译编排

交叉编译是嵌入式/通讯设备开发的常态：同一套代码要针对 arm-linux-gnueabihf（32位 ARM）、aarch64-linux-gnu（64位 ARM）、mipsel-linux-gnu 等多个 toolchain 编译。

```python
from dataclasses import dataclass

@dataclass
class Toolchain:
    name: str
    cc: str
    cxx: str
    arch: str
    sysroot: str | None = None
    extra_flags: list[str] | None = None

# 预定义 toolchain 配置
TOOLCHAINS = {
    "x86_64-linux": Toolchain("x86_64-linux", "gcc", "g++", "x86_64"),
    "armhf-linux": Toolchain(
        "armhf-linux",
        "arm-linux-gnueabihf-gcc", "arm-linux-gnueabihf-g++",
        "armv7",
        extra_flags=["-march=armv7-a", "-mfpu=neon", "-mfloat-abi=hard"],
    ),
    "aarch64-linux": Toolchain(
        "aarch64-linux",
        "aarch64-linux-gnu-gcc", "aarch64-linux-gnu-g++",
        "aarch64",
    ),
}

def cross_compile(source_dir: Path, toolchain_name: str,
                  build_type: str = "Release") -> tuple[int, str]:
    """交叉编译。"""
    if toolchain_name not in TOOLCHAINS:
        raise ValueError(f"未知 toolchain: {toolchain_name}")

    tc = TOOLCHAINS[toolchain_name]
    build_dir = Path(f"build/{toolchain_name}/{build_type.lower()}")

    extra_args = [
        f"-DCMAKE_C_COMPILER={tc.cc}",
        f"-DCMAKE_CXX_COMPILER={tc.cxx}",
        f"-DCMAKE_SYSTEM_PROCESSOR={tc.arch}",
        "-DCMAKE_SYSTEM_NAME=Linux",
    ]
    if tc.sysroot:
        extra_args.append(f"-DCMAKE_SYSROOT={tc.sysroot}")
    if tc.extra_flags:
        flags = " ".join(tc.extra_flags)
        extra_args.append(f"-DCMAKE_C_FLAGS={flags}")
        extra_args.append(f"-DCMAKE_CXX_FLAGS={flags}")

    builder = CMakeBuilder(source_dir, build_dir, build_type=build_type)
    code, output = builder.configure(extra_args=extra_args)
    if code != 0:
        return code, output

    return builder.build(jobs=4)

def build_all_targets(source_dir: Path, targets: list[str] | None = None) -> dict:
    """针对所有平台编译。"""
    targets = targets or list(TOOLCHAINS.keys())
    results = {}
    for tc_name in targets:
        print(f"交叉编译: {tc_name}")
        code, output = cross_compile(source_dir, tc_name)
        results[tc_name] = {"success": code == 0, "output": output[-500:] if len(output) > 500 else output}
        status = "PASS" if code == 0 else "FAIL"
        print(f"  [{status}] {tc_name}")
    return results
```

## 8. 构建产物收集与发布

编译完成后，需要把可执行文件、库、配置文件、文档按平台分类收集并打包。

```python
import tarfile
import hashlib
import shutil
from pathlib import Path

def collect_artifacts(build_dir: Path, output_dir: Path, platform: str) -> dict:
    """收集构建产物到输出目录。"""
    bin_dir = output_dir / platform / "bin"
    lib_dir = output_dir / platform / "lib"
    bin_dir.mkdir(parents=True, exist_ok=True)
    lib_dir.mkdir(parents=True, exist_ok=True)

    artifacts = {"bin": [], "lib": []}

    for p in build_dir.rglob("*"):
        if not p.is_file():
            continue
        suffix = p.suffix.lower()
        name = p.name

        # 可执行文件（无扩展名且有执行权限，或 .exe）
        if suffix == ".exe" or (suffix == "" and p.stat().st_mode & 0o111):
            dst = bin_dir / name
            shutil.copy2(p, dst)
            artifacts["bin"].append({"name": name, "size": dst.stat().st_size})

        # 库文件
        elif suffix in (".a", ".so", ".dylib", ".lib", ".dll"):
            dst = lib_dir / name
            shutil.copy2(p, dst)
            artifacts["lib"].append({"name": name, "size": dst.stat().st_size})

    return artifacts

def create_package(source_dir: Path, output_path: Path, platform: str) -> Path:
    """创建发布包（tar.gz）。"""
    output_path.parent.mkdir(parents=True, exist_ok=True)
    with tarfile.open(output_path, "w:gz") as tar:
        tar.add(source_dir / platform, arcname=platform)
    return output_path

def compute_checksum(file_path: Path) -> str:
    """计算 SHA256 校验和。"""
    h = hashlib.sha256()
    with file_path.open("rb") as f:
        for chunk in iter(lambda: f.read(8192), b""):
            h.update(chunk)
    return h.hexdigest()

def release_package(artifacts_dir: Path, platform: str, version: str) -> dict:
    """打包并生成校验和。"""
    pkg_name = f"myapp-{version}-{platform}.tar.gz"
    pkg_path = artifacts_dir / pkg_name
    create_package(artifacts_dir, pkg_path, platform)

    checksum = compute_checksum(pkg_path)
    checksum_path = pkg_path.with_name(pkg_path.name + ".sha256")
    checksum_path.write_text(f"{checksum}  {pkg_name}\n", encoding="utf-8")

    return {
        "package": str(pkg_path),
        "size": pkg_path.stat().st_size,
        "sha256": checksum,
    }
```

## 9. 完整实战：统一构建入口脚本

整合以上能力，实现一个 `build.py` 统一构建入口，支持配置、编译、测试、打包全流程。

```python
#!/usr/bin/env python3
"""统一构建入口脚本。

用法:
  python build.py configure --release
  python build.py build --jobs 8
  python build.py test
  python build.py package --version 1.2.3
  python build.py all --release --jobs 8
"""
import argparse
import json
import shutil
import sys
from pathlib import Path

# 复用前面定义的 CMakeBuilder、generate_version_header、collect_artifacts 等

class BuildSystem:
    def __init__(self, source_dir: Path, build_type: str = "Debug", jobs: int = 4):
        self.source_dir = source_dir.resolve()
        self.build_type = build_type
        self.jobs = jobs
        self.build_dir = self.source_dir / "build" / build_type.lower()
        self.dist_dir = self.source_dir / "dist"

    def configure(self) -> bool:
        print(f"[configure] {self.build_type} -> {self.build_dir}")
        builder = CMakeBuilder(self.source_dir, self.build_dir, build_type=self.build_type)
        code, output = builder.configure(extra_args=[
            "-DCMAKE_EXPORT_COMPILE_COMMANDS=ON",
        ])
        if code != 0:
            print(output)
            return False
        print("  配置成功")
        return True

    def generate_version(self) -> bool:
        print("[version] 生成版本头文件")
        try:
            generate_version_header(
                self.build_dir / "generated" / "version.h",
                version_major=1, version_minor=0, version_patch=0,
            )
            return True
        except Exception as e:
            print(f"  版本头生成失败: {e}")
            return False

    def build(self) -> bool:
        print(f"[build] {self.build_type}, {self.jobs} 并行")
        builder = CMakeBuilder(self.source_dir, self.build_dir, build_type=self.build_type)
        code, output = builder.build(jobs=self.jobs)
        if code != 0:
            print(output[-2000:] if len(output) > 2000 else output)
            return False
        print("  构建成功")
        return True

    def test(self) -> bool:
        print("[test] 运行测试")
        builder = CMakeBuilder(self.source_dir, self.build_dir, build_type=self.build_type)
        code, output = builder.run_tests(jobs=self.jobs)
        if code != 0:
            print(output)
            return False
        print("  测试通过")
        return True

    def package(self, version: str) -> bool:
        print(f"[package] 打包 v{version}")
        import platform as pf
        plat = f"{pf.system().lower()}-{pf.machine().lower()}"
        artifacts = collect_artifacts(self.build_dir, self.dist_dir, plat)
        print(f"  收集: {len(artifacts['bin'])} 可执行, {len(artifacts['lib'])} 库")

        result = release_package(self.dist_dir, plat, version)
        print(f"  发布包: {result['package']} ({result['size'] / 1024:.1f} KB)")
        print(f"  SHA256: {result['sha256']}")
        return True

    def clean(self) -> bool:
        print("[clean] 清理构建目录")
        if self.build_dir.exists():
            shutil.rmtree(self.build_dir)
        print("  已清理")
        return True

def main():
    parser = argparse.ArgumentParser(description="统一构建入口")
    parser.add_argument("command", choices=["configure", "build", "test", "package", "clean", "all"])
    parser.add_argument("--release", action="store_true", help="Release 构建")
    parser.add_argument("--jobs", type=int, default=4, help="并行数")
    parser.add_argument("--version", type=str, default="0.0.0", help="版本号（package 用）")
    args = parser.parse_args()

    build_type = "Release" if args.release else "Debug"
    bs = BuildSystem(Path("."), build_type=build_type, jobs=args.jobs)

    if args.command == "configure":
        ok = bs.configure() and bs.generate_version()
    elif args.command == "build":
        ok = bs.build()
    elif args.command == "test":
        ok = bs.test()
    elif args.command == "package":
        ok = bs.package(args.version)
    elif args.command == "clean":
        ok = bs.clean()
    elif args.command == "all":
        ok = bs.configure() and bs.generate_version() and bs.build() and bs.test()
    else:
        ok = False

    sys.exit(0 if ok else 1)

if __name__ == "__main__":
    main()
```

## 10. 快速参考卡片

| 需求 | 做法 |
| --- | --- |
| 调 CMake | `subprocess.run(["cmake", "-S", ".", "-B", "build", "-DCMAKE_BUILD_TYPE=Release"], check=True)` |
| 增量构建 | `cmake --build build -j$(nproc)`（Windows `-j N`）；把 build 目录固定下来复用缓存 |
| 多配置矩阵 | 外层循环 Debug/Release × GCC/Clang，各自独立 build 目录 |
| 编译并行 | `-j` 值取 CPU 核数（`os.cpu_count()`）；内存小则适度降低 |
| 抓编译错误 | `capture_output=True` 后过滤 `error:`/`warning:` 行并汇总 |
| 编译数据库 | `-DCMAKE_EXPORT_COMPILE_COMMANDS=ON` 供 clang-tidy/clangd 使用 |
| 运行测试 | `ctest --test-dir build --output-on-failure` 或直接跑可执行文件 |
| 产物归档 | 打 tar/zip 并附 commit hash、构建时间、编译器版本 |
| 失败即中断 | 每步 `check=True`；汇总时报出第一步失败位置 |
| 与 CI 衔接 | 本地脚本先在 CI 复用（同一入口），避免"本地能过 CI 挂" |

## 11. 常见坑与避坑指南

| 坑 | 现象 | 解决方案 |
|---|---|---|
| CMake 缓存污染 | 修改编译选项后不生效 | 删除 build 目录或 `cmake . -DCMAKE_XXX=...` 后重新 configure |
| 并行编译 OOM | `-j` 太大导致内存耗尽 | 根据内存设置 `--parallel`，或用 `ninja -j $(nproc)` |
| 交叉编译工具链找不到 | `arm-linux-gnueabihf-gcc: command not found` | 检查 PATH，或用绝对路径，或用 CMake toolchain file |
| compile_commands.json 不存在 | clangd 无法工作 | 加 `-DCMAKE_EXPORT_COMPILE_COMMANDS=ON`，或软链到项目根目录 |
| 版本头重复生成 | 每次构建都重新生成导致增量编译失效 | 内容不变时不写文件（比较后再写） |
| 产物收集遗漏 | 可执行文件没有执行权限位被跳过 | 同时检查 `.exe` 扩展名和已知的可执行文件名列表 |
| Ninja 找不到 | `CMake Error: Could not find Ninja` | 安装 ninja，或用默认的 Unix Makefiles generator |
| 环境变量不一致 | 子进程编译时找不到编译器 | `env = {**os.environ, ...}` 继承当前环境 |

## 12. 本节小结

- Python 在构建流程中是编排层，用 `subprocess` 驱动 CMake/Make/Ninja/cargo，不替代构建系统本身
- 编译矩阵用 `ThreadPoolExecutor` 并行执行多编译器/多选项组合，结果用错误归类去重后输出
- `compile_commands.json` 是静态分析工具的数据源，可提取 include 路径、宏定义，批量运行 clang-tidy
- 版本头文件从 git 信息自动生成，通过 CMake `add_custom_command` 集成到构建流程
- 交叉编译用 toolchain 配置表管理多平台，每个平台独立 build 目录
- 构建产物收集按平台分类，打包后生成 SHA256 校验和
- 统一构建入口脚本整合了 configure → version → build → test → package 全流程
