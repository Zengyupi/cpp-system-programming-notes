## 1. tcpdump 常用过滤器（抓得准才看得清）

```bash
# 主机/端口/协议组合
tcpdump -i eth0 -nn -S host 192.168.1.10 and tcp port 502
tcpdump -nn 'tcp port 2404 or udp port 53'
tcpdump -nn tcp[tcpflags] & tcp-syn != 0          # 只看 SYN（握手）
tcpdump -nn 'tcp[tcpflags] & (tcp-fin|tcp-rst) != 0'   # 只看挥手/复位
tcpdump -nn icmp                                   # ping
tcpdump -nn 'ip[2:2] > 1500'                       # IP 总长>1500（疑似分片）
# -nn 不解析名字/端口 -X 同时hex+ASCII -w cap.pcap 存盘 -r 读盘 -c N 抓N个
tcpdump -i eth0 -nn -s0 -w /tmp/x.pcap            # 完整抓并存文件，再拖进 Wireshark
```

| 过滤类型 | 例子 |
| --- | --- |
| 主机/网络 | `host x`、`src host x`、`net 192.168.1.0/24` |
| 端口 | `port 502`、`src port / dst port`、`portrange 1000-2000` |
| 协议 | `tcp / udp / icmp / arp / ip6` |
| 字节偏移 | `ip[9]=6`（protocol=TCP）、`tcp[13] & 2 !=0`（SYN） |

更多见《../01-C++技术体系/08-网络与系统工具/02-tcpdump网络抓包.md》。

## 2. Wireshark 分析套路

1. **Follow → TCP Stream**：把一条双向流按顺序拼好，看完整请求/响应（分析 Modbus/104/HTTP 最快）；
2. **Statistics → Flow Graph / Conversations**：看握手挥手时序、谁主动关、重传；
3. 右键报文 **Decode As** 指定端口用某解析器（比如把 1502 当 Modbus）；
4. 着色规则：黑底红字=RST、重传/乱序会标色，是定位丢包的线索；
5. `tcp.analysis.retransmission`、`tcp.analysis.duplicate_ack` 等显示过滤器查异常；
6. 工业协议直接在 Packet Details 展开每个字段，与手写解析对照验证。

## 3. 校验和算法（IP/TCP/UDP 通用反码求和 + Modbus CRC16）

### 3.1 Internet 校验和（16 位反码求和）

IP 首部、TCP/UDP（后者加伪首部）都用它：把数据按 16 位字累加，进位回卷，最后取反。

```cpp
#include <cstdint>
#include <cstddef>
uint16_t inet_checksum(const uint8_t* data, size_t len) {
    uint32_t sum = 0;
    for (size_t i = 0; i + 1 < len; i += 2)        // 按 16 位大端累加
        sum += (uint32_t(data[i]) << 8) | data[i + 1];
    if (len & 1) sum += uint32_t(data[len - 1]) << 8;   // 奇数字节补0
    while (sum >> 16) sum = (sum & 0xFFFF) + (sum >> 16); // 回卷进位
    return uint16_t(~sum);                          // 取反
}
```

> TCP/UDP 校验要额外构造**伪首部**（源IP、目IP、协议号、TCP/UDP长度）参与计算；接收方对"首部+数据+校验字段本身"整体求和结果应为 0。

### 3.2 Modbus CRC16（多项式 0xA001，初值 0xFFFF，低字节在前）

```cpp
uint16_t modbus_crc16(const uint8_t* buf, size_t len) {
    uint16_t crc = 0xFFFF;
    for (size_t i = 0; i < len; ++i) {
        crc ^= buf[i];
        for (int b = 0; b < 8; ++b)
            crc = (crc & 1) ? (crc >> 1) ^ 0xA001 : (crc >> 1);
    }
    return crc;   // 在线上：先放低字节 (crc&0xFF)，再放高字节 (crc>>8)
}
```

## 4. 手写 Modbus TCP 解析器（C++20，安全、处理半包）

要点：**先判断够不够 MBAP 头(7B)，再按长度字段判断整包是否到齐，全程边界校验**。

```cpp
#include <cstdint>
#include <optional>
#include <span>
#include <vector>
#include <arpa/inet.h>

struct MbTcpFrame {
    uint16_t txnId, proto, length, unit, func;
    std::span<const uint8_t> data;   // PDU 数据（功能码之后）
};

// 返回值：=nullopt 数据不足需继续收；抛异常表示非法报文；成功返回消费的字节数
std::optional<size_t> try_parse(std::span<const uint8_t> buf, MbTcpFrame& out) {
    if (buf.size() < 7) return std::nullopt;                 // MBAP 头没收全(半包)
    uint16_t length = (uint16_t(buf[4]) << 8) | buf[5];      // MBAP 长度=大端
    if (buf[2] != 0 || buf[3] != 0) throw std::runtime_error("protocol must be 0");
    size_t total = 6 + length;                               // MBAP前6 + length(unit+PDU)
    if (length < 2) throw std::runtime_error("bad length");
    if (buf.size() < total) return std::nullopt;             // 整帧未到齐(半包)，继续等
    out.txnId  = (uint16_t(buf[0]) << 8) | buf[1];
    out.proto  = 0;
    out.length = length;
    out.unit   = buf[6];
    out.func   = buf[7];
    out.data   = buf.subspan(8, total - 8);
    return total;                                            // 调用方从缓冲区 erase 这么多字节
}
```

Python 等价（struct 大端，快速验证/造测试报文）：

```python
import struct
def parse_mbtcp(b: bytes):
    if len(b) < 7: return None                       # 半包
    txn, proto, length, unit = struct.unpack(">HHHB", b[:7])
    total = 6 + length
    if len(b) < total: return None                   # 半包
    func = b[7]
    return {"txn": txn, "unit": unit, "func": func,
            "data": b[8:total], "consume": total}
```

## 5. 粘包 / 半包（TCP 字节流的核心问题，必懂）

TCP 是**无边界字节流**：`send` 次数和 `recv` 次数没有对应关系。

```text
半包：一次 recv 只收到一个完整帧的一部分（帧被拆在两次收）
粘包：一次 recv 收到多个帧拼在一起（或一个半 + 下一个）
成因：Nagle、MSS分段、接收时机、应用读得慢——无法靠"多读几次"避免，必须按协议分帧
```

### 5.1 通用接收缓冲区模型（所有长度前缀协议通用）

```text
维护一个不断增长的接收缓冲区 rxBuf，循环：
  1) recv 到的字节 append 到 rxBuf 尾部
  2) while rxBuf 能按"协议定界规则"切出一个完整帧：
        解析该帧 → 投递业务 → 从 rxBuf 头部移除已消费字节
  3) 剩余不足一帧的部分留着，等下次 recv 拼上
定界规则：Modbus TCP/IEC104=长度字段；HTTP=Content-Length/chunked；分隔符协议=找 \n
```

C++ 缓冲区骨架（配合 Reactor 的可读事件）：

```cpp
std::vector<uint8_t> rxBuf;
void onReadable() {
    uint8_t tmp[4096];
    ssize_t n = ::read(fd, tmp, sizeof tmp);
    if (n <= 0) { /* 对端关闭/错误，见 03 篇挥手/RST */ return; }
    rxBuf.insert(rxBuf.end(), tmp, tmp + n);          // 追加
    while (true) {
        MbTcpFrame f;
        auto used = try_parse(rxBuf, f);
        if (!used) break;                             // 半包，等下次
        handleFrame(f);                               // 业务处理
        rxBuf.erase(rxBuf.begin(), rxBuf.begin() + *used); // 移除已消费
    }
}
```

> 生产实现用环形/可扩展缓冲区减少 erase 拷贝（见《../01-C++技术体系/13-并发异步与组件/04-内存池与池化技术.md》《../01-C++技术体系/12-网络与服务器架构/04-Reactor与高性能网络库.md》），但**分帧逻辑不变**。

### 5.2 IEC104 分帧（启动符 + 长度）

```cpp
// 规则：首字节必须 0x68；第二字节=后续长度(控制域4+ASDU)；总长 = 2 + length
std::optional<size_t> try_parse_104(std::span<const uint8_t> b) {
    if (b.size() < 2) return std::nullopt;
    if (b[0] != 0x68) throw std::runtime_error("expected 0x68");
    size_t total = 2 + b[1];
    if (b[1] < 4 || b[1] > 253) throw std::runtime_error("bad apdu len");
    if (b.size() < total) return std::nullopt;       // 半包
    return total;
}
```

## 6. 造测试报文（不依赖真实设备自测解析器）

```python
# 构造一个 Modbus TCP 读保持寄存器请求并验证自己的解析
import struct
def mbtcp(txn, unit, pdu: bytes):
    return struct.pack(">HHH", txn, 0, len(pdu)+1) + bytes([unit]) + pdu
req = mbtcp(1, 1, bytes([0x03,0x00,0x00,0x00,0x02]))
print(req.hex(" "))     # 00 01 00 00 00 06 01 03 00 00 00 02
# 再故意切成两段喂给解析器，验证半包处理；拼两条验证粘包
```

## 7. 端到端排查清单（工业现场通用）

```text
1) 物理/链路：网卡 up？网线/485？ip addr、ethtool 看链路
2) 二层：ARP 有对端/网关 MAC 吗？(ip neigh)，VLAN 对吗
3) 三层：ping 通吗？traceroute/mtr 哪一跳丢？(ping不通≠TCP不通)
4) 传输：端口在监听吗(ss -lntp)？握手完成吗(tcpdump 看 SYN/SYNACK/ACK)
5) 应用：报文格式/字节序/长度对吗(Wireshark 展开)？半包处理对吗
6) 状态：有没有大量 TIME_WAIT/CLOSE_WAIT/RST(ss -tan 状态统计)
```

## 8. 快速参考卡片

```text
tcpdump：-nn -S -X -w；组合 host/port/标志位；tcp[tcpflags]&tcp-syn
Wireshark：Follow Stream 看对话、Flow Graph 看时序、Decode As、重传过滤
校验和：16位反码求和+回卷+取反；TCP/UDP加伪首部；Modbus CRC16=0xA001/FFFF/低字节在前
分帧：先够不够定长头→按长度判断整帧→不够留着(半包)→一次多帧循环切(粘包)
  Modbus TCP: total=6+length；IEC104: 0x68,total=2+b[1]；HTTP: CL/chunked
自测：Python struct 造报文(含半/粘包) ↔ C++ 解析对拍
排查链：链路→ARP→IP/ICMP→TCP握手→应用报文→连接状态
```

## 9. 常见问题与坑

| 问题 | 解决 |
| --- | --- |
| 按 recv 次数切帧，偶发解析失败 | TCP 无边界，必须按长度/分隔符分帧 + 接收缓冲区 |
| 粘了两帧只解析第一帧 | while 循环切到不够一帧为止 |
| 长度字段算错导致错位 | 牢记各协议长度从哪起算（Modbus 从 Unit 起、104 不含 0x68 和自身） |
| 大小端读错 | 网络/Modbus 大端；104 序号小端且左移，逐字段核对 |
| 校验和总不对 | 漏伪首部、奇数字节没补 0、没回卷进位；CRC 字节序放反 |
| 抓不到握手包 | 连接早已建立；加 `-S`、在握手前开始抓或重连 |
| 生产不能装 Wireshark | tcpdump -w 存 pcap 拷回分析 |
| 解析器被畸形帧带崩 | 任何取字段前先校验剩余长度，非法帧断开连接而不是越界 |
